# Build

Act as Team Lead, not implementer or independent acceptor. Resolve
[project context](../../../docs/engineering/PROJECT_CONTEXT.md), target instructions/TASK/parents/Board and
[execution rules](../../../docs/engineering/EXECUTION.md). Follow the
[native workflow rule](../../../harness/pi/WORKFLOW_RULE.md). Fresh Pi contexts are not OS isolation.

## Bound one delivery

Accepted-work synchronization uses explicit [Sync](../sync/SKILL.md), not a shortened Build or an Engineer
promoted by prompt. Sync reuses this process launch/model/observation protocol and the same subject lock;
ordinary Build keeps Engineer → independent Review → applicable QA → Land for new implementation.

`/skill:build TASK-NNNNN` delegates Work, independent Review, applicable QA and Land, including owned commits,
non-force publication and suitable capture uploads. Do not ask again for these effects or ordinary task-owned
cleanup. Never approve/merge/force-push/release/deploy or continue to another TASK. Respect narrower invocation
authority. A TICKET selects only its sole unambiguous eligible TASK; otherwise ask, without decomposing it.

Verify cwd/origin/branch/base/status, blockers, existing PR and unrelated changes. Reuse the operator's selected
checkout; ask main versus worktree only when missing. Keep source in that selected checkout. Resolve canonical
base through Git; canonical Review/QA reports there remain authoritative. Read existing reports/ledger before
choosing a stage; resume current evidence, never reset repair usage or rebuild an accepted unchanged candidate.

Use a private `.runs/build/<TASK-ID>/<run>/` and exclusive `active` directory. Inspect existing ownership before
resume; release only your lock after children stop. One concise ledger holds authorization, project/subject,
checkout/base/head, pinned models, stage/attempt/report/PR locators, shared repairs and incomplete effects.
Keep active coordinator/session protected. No duplicate resource registry or permanent local source archive.
Use the target's resolved runtime/resource procedure; do not import application services into a library.
For Agent OS, the **one shared [resource procedure](../../../docs/engineering/RESOURCE_LIFECYCLE.md)** means Work
prepares one explicit Compose project and all roles reuse it. Main up/down and registered `--worktree` up/down are separate;
Docker lifecycle has no receipt/PID/worker-registration gate. Inspect actual handoffs/native resources, not
per-stage proof trees. Missing browser prerequisites hold affected advancement, not explicit task teardown.
For shared HTTPS, carry [scoped ingress preparation/retirement](../../../docs/engineering/LOCAL_INGRESS.md#scoped-task-preparation-and-retirement)
in the child request: exact checkout/name, existing supplier mode/port, leaf/include ownership/digests and peer
references. Have Work use supported tools/existing privilege for explicit task setup, including planned-name
rendering before QA allocation. On explicitly authorized macOS hosts, use the runbook's native administrator
dialog for an exact digest/master-bound test/HUP command; credentials stay in the OS dialog, no persistent
permissions or restart. `sudo -n` denial alone does not prove that path unavailable. Respect cancellation and
reconcile partial effects. Do not defer all leaf/include work to a human or silently enroll infrastructure.
A verified full-config-test/graceful-reload privilege hold blocks browser readiness, not independent cleanup;
retain referenced leaves and name the exact remaining action. Never substitute shared-service restart.

## Pin models, then launch fresh roles

Explicit invocation choices override target bindings, then local defaults: retain configured provider; for
`openai-codex`, Team Lead Sol/medium, Engineer, Review, QA and Land Sol/high. Resolve the newest
available stable numeric model in that requested family from installed Pi metadata; explicit exact IDs stay
exact. Verify thinking support. No fallback/escalation/provider change or mid-delivery refresh. Pin the resolved
provider/model/thinking per role for repairs/resume; an explicit human change preserves prior history. Record
configured identity separately from unavailable provider attestation. Check installed `pi --version`, `--help`
and `--list-models`; versions are evidence, not equality gates. No global install/settings/trust changes.

Launch **one child at a time**. A fresh native host explicitly prepared with `--fight-build-stages sdk` uses
[`fight_build_stage` for every role](../../../harness/pi/SUBAGENTS.md#all-role-build-bootstrap), including repairs
and cleanup-only Land. Actual Build/coordination authority must name the same TASK and checkout. A subordinate
Agent, profile, request or pane label cannot grant it. Never inherit Engineer conversation into assessors, resume
an old assessor as a fresh verdict, or dispatch an SDK demonstration in place of the assigned Work.

TASK-00561 is a bootstrap, not a qualified default cutover. Existing active hosts without this tool continue their
original provider-owned `scripts/run-stage.py` route; Sync still has that demonstrated process caller. Do not
update/reload this active host or shared installation implicitly. The owning Build must deliberately prepare a
fresh native host and select Build interactively to qualify the required real journey. Once an SDK attempt has
been dispatched, no process fallback is permitted, including after display loss. Reconcile its actual execution
and external effects before replacement. Source/controlled checks do not complete TASK-00561 or authorize retiring
its still-live process callers.

For process stages, resolve the launcher's absolute path
beside this skill, never from an unrelated target. The launcher uses the running Pi's exported native resource
resolver offline to inspect configured packages and direct/auto-discovered extensions. One complete Harness
selects its canonical package directory. With no configured Harness, it selects the trusted provider checkout's
`harness/pi`.
Multiple owners, filtered/disabled/incomplete resources, unavailable inventory or monitor support hold before
dispatch. Project Harness configuration requires established native project trust; conservative inspection never
grants execution authority. Offline native registration then checks the selected package's actual injection;
diagnostics hold even when Pi exits successfully. Inspect native package/extension settings and report the
prerequisite; do not install/remove packages, change settings/trust or disable discovery to bypass it.
No user-specific installation path is required. An explicit `--harness-package` remains available for a separately
trusted package, but must match any configured Harness. These checks apply to every stage, repair and cleanup-only
launch, including resumed deliveries.
Native Pi trust/resource discovery remains active; selecting a package does not grant project access.
Read installed Pi [CLI/skills documentation](../../../harness/pi/README.md) as needed before integration changes.
Native session-file birthtime, ancestry/custody and independent role admission remain unchanged. Observation is
human-only/best-effort; missing visibility never authorizes relaunch or executor substitution.

Use canonical stage inputs `--role engineer`, `reviewer`, `qa` and `land`. Owning skills remain `work`,
`review`, `qa` and `land`; never rename them to match stage labels. The process owner normalizes existing workflow
aliases using the Harness's single `src/stage-roles.json` vocabulary before launch, persistence and observation.
Legacy `work`/`review` callers remain supported; unknown roles and coordinator names refuse. Normalization never
replaces native custody or actual workflow admission. Build's `phase: qa` / `skill: build` / coordination effect
is not a QA worker. AGENTS displays verified canonical stage identity, not a prompt-derived authority claim.

Create a fresh private attempt with `request.md`. Include role, TASK, verified checkout/base/head, absolute owning
skill/context/instruction paths, target-owned record/status/branch/gate/runtime rules, permitted effects,
relevant evidence, pinned model/thinking, remaining repair
allowance and expected canonical report/handoff. Carry the exact Compose project/checkout and native state;
no Docker worker registration. Preserve native session/custody admission separately. Do not copy Engineer dialogue into independent requests or
suggest verdicts. Tell each child to verify target identity, read instructions, perform only its role and stop.
No `--continue`, `--resume`, `--session`, `--fork`, parent transcript or reused session directory.

Write and read back the request under the shared [readability rules](../../../docs/engineering/HANDOFFS.md#readable-handoff-text)
before dispatch, including when adapting an earlier or compressed handoff.

For SDK dispatch, pass the current target base/branch/record/context, exact checkout/head/attempt, canonical role,
that role's original provider/model/thinking pin and finite timeout to `fight_build_stage`. Carry `repairLimit`
and `repairsUsed` from the existing ledger. Set `repair: true` only for Engineer repair and consume its cycle
**before** dispatch; all other stages carry unchanged usage with `repair: false`. The host refuses reset/drift
and unresolved execution across reloads; fresh host creation does not reset the original ledger. Runtime
`reportObservation` records canonical bytes changed during the bound owner, not verdict validity or OS-enforced
writer provenance. Missing/unchanged/wrong-candidate reports, negative verdicts and SDK completed/steered/error
states cannot substitute for the report inspection below. Do not dispatch Land without current independent
acceptance and the original invocation's publication scope. Cleanup-only scope remains narrower than Land's tools.

For an existing process host, use its original launch path:

```sh
cd "$task_checkout"
python3 -u "$build_skill_dir/scripts/run-stage.py" \
  --attempt "$attempt" --task "$task_id" --role "$role" \
  --provider "$stage_provider" --model "$stage_model" --thinking "$stage_thinking" \
  --timeout "$stage_timeout_seconds"
```

Use actual pinned variables and a finite stage timeout; shell timeout exceeds it plus termination grace. Keep
stdout visible, relay meaningful progress at least every 60 seconds, inspect bounded `progress.log` if buffered.
Do not detach, pipeline away exits, infer percentages or echo private source/thinking/credentials. Observe the
original child through exit. Inspect monitor/Pi exits, provider errors, session model/thinking and reports;
exit zero is not acceptance. Timeout/cancel/uncertain liveness needs reconciliation before another child.
Never arbitrarily signal a reused/unknown PID or assume remote effects stopped with the CLI.

## Advance by evidence

When coordinating TASK-00561's replacement qualification, follow its
[approved staged contract](../../../planning/tasks/00561-TASK.md#approved-staged-qualification--2026-11-07).
Its bounded bootstrap Review/native QA does not accept the complete TASK or authorize Land. Carry later-stage
obligations explicitly, then obtain fresh final Review/applicable QA after cutover before ordinary Land.
Actual Land supplies delivery evidence, not a circular prerequisite for its own authorization. This TASK-specific
ordering neither changes other TASKs nor permits advancement from a negative or missing in-scope verdict.

- Engineer: committed implementation and truthful gate/resource handoff → fresh independent Review.
- Review: current canonical ACCEPT with Standards/Spec passes → applicable independent QA. Findings → bounded
  Engineer repair; evidence-only gaps → their owner, not speculative source edits.
- QA: current canonical PASS or justified criterion-specific N/A → authorized Land. FAIL → Engineer;
  INCOMPLETE → exact prerequisite. No UI does not mean no QA. For UI/TUI carry the owning capture procedure,
  terminal authority and bridge prerequisites; inspect comparable real captures, never fabricate missing images.
- Land: verify actual exact ready PR, required checks/capture access/current closeout, then eligible cleanup.

Match TASK/branch/base/head/status, independence, findings and limitations before advancement. Never select an
older PASS over newer failure. [Qualify gate reuse](../../../docs/engineering/EXECUTION.md#gate-evidence-reuse):
one final full gate for changed implementation, independent focused probes, no repeat for role/commit/metadata.
Run `./bin/build` normally for automatic receipt validation and reuse; use `--force` for deliberate fresh
execution. Report the original receipt separately from fresh evidence.

Default **five shared repair cycles** across Review and QA; explicit positive allowance may be up to ten.
Consume before an Engineer repair; initial implementation is not a repair. New processes/QA failures/resumed
invocations never reset it. After the last cycle allow its Review/QA/Land if passing; remaining blockers need a
human decision. Evidence recovery consumes no repair, but unchanged holds are not unlimited retries.

## Finish the effects

Inspect native Git/Docker absence and protected/shared state, not a cleanup invocation or passing mechanism.
Record necessary outcomes in the existing TASK/PR, then retire eligible temporary runtimes, worktrees/refs,
fixtures/logs/sessions and cleanup's own files through the shared procedure. Do not retain them automatically.
All Docker retirement uses `bin/down --worktree SELECTOR`, including Worktrunk's pre-remove hook; Docker
precedes source/config deletion and needs no worker/PID receipt. The same guarded native remover qualifies
canonical/target effective hooks and removes owned fixtures/worktrees unattended for the exact reviewed project
down hook, without persistent approval. Unknown/user/changed hooks hold source only, not Docker teardown;
do not return a routine known-hook approval request to the operator. If original Land itself consumes source,
observe its actual exit, then continue source-qualified Worktrunk cleanup from the canonical safe checkout.
Verify task ingress retirement through that same runbook: app down removes its route; only scoped owned
front-door blocks are unloaded with a full test/graceful reload before referenced leaf removal. Preserve peers
and the shared supplier; report exact loaded/pending names and privilege holds separately from Docker/source.
Use a fresh cleanup-only Land worker when required, with the same pinned model/ledger and ordinary trusted
stage entry. No publication, new runtime or tracked edits in that continuation. Preserve active coordinator,
unique source and real protections; never stop shared services/VMs. Report Docker and source holds separately.
For the shared remover's qualified `retained_unmerged` outcome, verify eligible source/runtime/registration/
config retirement and report the exact unchanged local ref intentionally retained pending integration. Do not
demand unchanged retries or merge before config retirement, claim all refs deleted or create a delivery queue.
Other native outcomes/holds stay incomplete. Locator-free repeats use the original absolute path only; they
must not rediscover a branch, redirect to a reattached worktree or fabricate publication.

Return actual PR/publication state, fresh/reused verification, warnings, removed/remaining counts, finite holds
and shared repair usage. Follow [handoff rules](../../../docs/engineering/HANDOFFS.md); success ends with the
actual human PR review/merge URL. Incomplete work names its real prerequisite. Stop after this TASK, not at a
child's next-skill recommendation when Build already authorized and evidenced the next stage.
