# Register the created checkout and complete the handoff

## Problem statement

Files or a GitHub URL alone are not a registered usable Agent OS project. Creation must finish with conservatively
identified local Git, authoritative context and an inspectable receipt, without silently adopting existing content
or starting Planning and Agent work.

## Solution and boundaries

Supply final registration/context stages and completion presentation to TICKET-00101's single durable attempt.
Register only the exact successfully identified local Git checkout generated by TICKET-00100. Consume optional
verified source-host evidence from TICKET-00102; local-only needs no remote. Reuse TICKET-00024's Repository, Host,
Checkout/Worktree, source normalization, Git common-directory, uncommitted marker, designated-checkout and first-link
confirmation contracts. Name/path/slug/remote similarity never becomes identity or authority to adopt existing work.

The complete Create Project preview and confirmation must cover this exact first link, metadata/configuration and
context initialization; integrate the existing owner's confirmation contract rather than silently bypass it or add
another ordinary-stage prompt. If exact evidence or authority changes, the attempt pauses for a revised confirmed
plan. Generated identities come from owning factories, not user-provided or improvised IDs. Detect real Workspace
slug/source/link conflicts transactionally and preserve all earlier effects when registration cannot complete.

Initialize the new Repository's accepted configuration with the selected initial branch and profile reference, and
resolve its first database-authoritative context through TICKET-00025's existing revision/resolver contracts. Record
actual configuration/context identity and provenance, recognized instruction evidence, restrictions and unresolved
conflicts truthfully. Profile selection records a revision, not a new Agent, permission grant or mutable copied
profile. Use one existing context owner, never a competing creation-only resolver.

This is a newly generated registered Repository beginning in database-authoritative Planning mode, not a cutover
of this repository's Markdown or an import of starter Planning. Create/import no Wayfinder map, EPIC, TICKET or TASK.
Files preserved by the generation manifest remain source content rather than automatically imported authority.
Do not remove/archive source Markdown or assert that registration alone qualifies all database Planning behavior.
Actual mode/context capabilities must be implemented and verified before this completion stage succeeds.

Treat registration, checkout-link and configuration/context results as individually reconciled stages under the
attempt's original identities. After lost acknowledgement or restart, inspect exact previously committed outcomes
before retry; never duplicate a Repository, Checkout link or configuration/context revision. If an existing outcome
cannot be tied to this operation, hold rather than silently adopt it. Registration/context failure preserves local
and optional remote state, with exact retained resources and an allowed next action. Registration emits its owner's
events; this consumer does not rename/re-emit them into another identity protocol.

On verified completion, present a durable safe receipt containing human/system Repository identity, canonical local
path, Host/Checkout/Worktree/Runner identities, source/tag/commit/archive digest, manifest revision, transformations,
selected initial branch/commit, preparation result and remaining tracked changes, optional GitHub provider identity/
URL/owner/visibility/push/default branch, selected profile revision, configuration/context revision, warnings,
skipped stages, attempts and retained resources. Restrict sensitive path/identity details to authorized readers.
Do not report completion while a required stage is unknown or failed; later observations must not rewrite the
original receipt or hide attributed corrections/recovery.

Offer the registered repository Dashboard and deliberate actions to inspect checkout/context or begin Planning.
No automatic conversation, coding Workflow, TASK claim, Agent session, PR or additional publication follows.
Completion grants no implementation, commit, push, PR or execution authority beyond the already confirmed effects.
The existing Dashboard/shell owners supply the destination; this is not another repository overview product.

Own integrated acceptance of the real creation path. At least one managed source, preferably `project-slim`, must
have a real immutable stable SemVer release `>=1.0.0` and valid manifest, installed through TICKET-00099 and used to
create/register an actual project with fresh Git, context, receipt and recovery evidence. Also exercise local-only
and private-by-default GitHub paths. Releasing that source is a separately authorized maintainer action outside
Agent OS; neither an empty catalog nor synthetic-only success meets this outcome. Integrate this evidence into
real delivery TASKs, not a standalone certification workflow or proof-only endpoint.

Exclude new identity/context engines, existing-content adoption, migration/cutover of existing repositories,
starter release automation, automatic Planning/Agent startup and managed Review/publication. Cleanup remains a
separate TICKET-00101 operation respecting existing identity/history/reference contracts; registration is never
silently rolled back by deleting records after another stage fails.

## Validation and permissions

Revalidate current registration/link/configuration/context/read permissions and exact Workspace/Repository/Host scope.
An attempt grant or slug is not proof of current authority or identity. Apply owning uniqueness/reference/current-
state contracts on the shared PostgreSQL connection; do not nest owner transactions or hide registration policy in
an adapter. Marker/filesystem effects retain their owning durable intent/reconciliation boundary under ADR 0002.

Apply root containment, ownership, Git evidence and conservative source/link checks through actual owner APIs.
Reject stale plan, ambiguous marker, mismatched checkout, unavailable context or unsupported mode; never fall back
to unregistered/Markdown mode and still label the operation complete. Receipt queries are bounded, no-store,
permission-filtered and secret-free. Browser navigation follows ADR 0003/0004 current-context and late-response fences.

## Acceptance and evidence

- Real local-only and private GitHub creation end in one correctly identified registered checkout and exact initial
  database-authoritative context, with a complete attributable receipt and no imported/created Planning records.
- Original confirmation covers first-link effects; conflicts, missing mode capability and changed authority fail
  safely. Restart/uncertain registration/context outcomes cannot duplicate identities, links or revisions.
- Actual required managed release and real project evidence cover fresh Git, preparation outcome, registration,
  context, receipt and recovery. Preserve external release provenance and distinguish historical receipts from
  fresh application evidence; missing source release remains an explicit prerequisite, not a waiver.
- Browser completion and Dashboard actions use real results and current permissions without automatic Agent work.
  Owned orchestration/PostgreSQL/client tests, real Git/Runner/GitHub qualification and `./bin/build` pass.
  Do not test starter quality, package internals, tooling, migrations or a demonstration-only acceptance surface.
