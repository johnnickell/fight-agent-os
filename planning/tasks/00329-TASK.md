# Manage versioned prompts and personas

## Outcome

Authorized users reconcile reviewed managed prompts/personas and create, revise or inspect custom ones as exact
scoped database resources for profile and template consumers, without a second template or Agent authority.

## Scope

- In scope: Type-specific prompt and persona invariants, managed reconciliation, custom create/revise, exact
  history/content/reference inspection and protected application/API delivery with immutable revisions and audit.
- Out of scope: Agent-template seeding/publication/ancestry, Agent creation/grants, AI prompt generation, provider
  execution, browser resource editor, retirement/rollback commands and active-session switching.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Reconcile reviewed prompt/persona | Explicit type-specific managed reconciliation | Exact source, managed key, scope, content digest and current selection | Committed resource revision/selection facts; none on no-op | Complete new immutable revision selected atomically when changed |
| Create or revise custom content | Explicit type-specific create/revise with expected state | Authorized reference choices, alias conflicts and exact history | Committed custom creation/revision facts | Owned scoped resource revision and required audit, no managed overwrite |
| Inspect exact resource | N/A — authorized read | Type, logical/revision identity, content, provenance, references and eligibility | N/A | Exact protected facts for consumer validation, not a grant |

## Validation and permissions

Reuse TASK-00327's current resource management/read authority, typed Workspace/Repository scope and shared
reference/selection contracts. Prompts and personas keep their own content/reference invariants and explicit types,
not a catch-all Skill aggregate. A persona is behavioral/presentation content, not an authenticated Agent, an
AccessControl Role or an Agent profile template. Exact supported content shapes belong to this implementation;
do not add speculative inheritance, arbitrary execution or model calls.

Separate logical identity, aliases, immutable revision and current selection; allocate new IDs with the owning
factory/UUID library. Validate bounded complete content, supported fields, exact referenced resource types/revisions,
applicable scope and effective database alias collisions. Reject missing, ambiguous, cross-scope or retired/ineligible
references for new selections; preserve historical references without substitution. Candidate validation must not
publish a temporary current resource. Keep content inert in inspection and out of ordinary logs/events.

Normalize reviewed managed input and reconcile by stable managed key: unchanged current digest is a validated no-op;
changed input appends/selects a revision. Preserve custom content and reject managed/custom identity adoption.
Missing source entries do not retire/delete resources. Custom creation/revision requires explicit current intent
and expected selection generation; moving away and back cannot validate stale writes. Neither deployment nor prompt
publication updates Agent templates or actual Agents. EPIC-00017 retains seed-once database template authority.

Commit full content/references, immutable revision, selection and required Harness audit on the shared ADR 0002
connection with PostgreSQL uniqueness/reference fences and consistent participant lock order. No external filesystem
or provider effects inside the transaction. Events follow commit; uncertain original outcomes are inspected rather
than blindly retried. Read-only reference resolution alone is not proof of atomic consumer publication; expose
precise fence participation for TASK-00299/00300 and TASK-00323 under their own mutation owners.

Retain all immutable history and scoped authorized access. Future selection changes do not rewrite snapshots or
Agent bindings, authorize disclosure or expand Permissions. Missing runtime consumers remain visibly unavailable;
the resource path must work independently of complete browser Planning, provider qualification and session launch.

## Acceptance criteria

- [ ] Actual protected operations reconcile managed and create/revise custom prompts/personas with exact scoped
  identities, immutable content/history and inspectable provenance.
- [ ] Unchanged managed replay is a no-op; changed content selects one revision without custom overwrite,
  source-absence deletion or template/Agent propagation.
- [ ] Malformed content, alias/reference conflicts, wrong scope, denied access and stale expected state fail safely;
  no resource grants authority or silently substitutes another revision.
- [ ] Real PostgreSQL concurrency and rollback preserve atomic state/audit, reference participation and exact old
  bindings; lost-response outcomes remain distinguishable from current matching state.
- [ ] Profile/template owners can consume exact prompt/persona references and required fences without depending
  on finished editors, sessions or database Planning cutover.
