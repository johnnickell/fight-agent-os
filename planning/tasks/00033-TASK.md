# Make bin build the complete read-only application gate

## Outcome

`./bin/build` is the thin sole canonical entrypoint into a deterministic, non-interactive, PHP-orchestrated application acceptance gate running in the already-started Docker Compose PHP service. Named phases validate the Composer manifest, planning, PHP syntax/style/types/dependencies, one all-suite PHPUnit/coverage execution, and bounded frontend source/behavior/build checks without testing the gate itself.

## Scope

- In scope: Extend the thin `bin/build` and `scripts/build.php` introduced by TASK-00070; explicit named phase ordering and failure propagation; Composer manifest/lock validation without install or audit; read-only planning validation; PHP syntax/PHPCS using the locked Fight Common shipped standard/PHPStan/Deptrac/Rector dry-run checks; one all-suite backend PHPUnit/coverage run with guarded PostgreSQL; bounded frontend format/lint/type/test/coverage/build/Storybook checks; tracked-tree mutation detection; final evidence format and documentation of focused-versus-canonical use.
- Out of scope: Automatic source/planning formatting, dependency updates, merge/release/deployment approval, provider/network product tests, lowest/candidate lanes, scheduler enrollment, broad E2E automation, and silently accepting warnings or unavailable mandatory phases.

| Prove read-only behavior | N/A — gate invariant | Compare tracked state before/after while allowing ignored caches/reports | N/A — no domain event | Tracked planning/source/locks remain unchanged |

## Validation and permissions

`bin/build` contains only host-side preflight and delegation: it verifies that the Compose `web` PHP service is running, then uses non-interactive `docker compose exec -T web php scripts/build.php`. It does not build an image or start an ad hoc container on every invocation. A missing/stale service fails with an actionable instruction rather than silently changing the environment.

The PHP orchestrator owns named phase execution, exit-code propagation, and concise diagnostics. It may use the locked Symfony Process capability, but must not duplicate orchestration in shell or add another task-runner dependency without demonstrated need. Existing `./bin/planning-check` remains the authoritative planning phase and may retain its implementation language.

The gate assumes dependencies were installed during explicit setup. It never installs, updates, or audits dependencies; invokes `planning-check --write`; runs format fixers; generates tracked source; or migrates a non-test database. Composer validation may lint the manifest and verify lock consistency without network access. Caches/reports/databases stay under ignored or disposable paths.

Run read-only planning validation, PHP syntax lint, PHPCS using the standard shipped by locked Fight Common, PHPStan, Deptrac, and Rector dry-run. Then run one PHPUnit invocation containing all configured Unit, Integration, Functional, and guarded PostgreSQL-backed suites with coverage enabled; validate Domain/Application and Adapter coverage from that same report without rerunning any suite. Run each accepted frontend format/lint/type/Vitest/coverage/production-build/Storybook phase once. Order should fail fast with useful diagnostics.

`./bin/build` is canonical. Focused wrappers remain supported iteration tools but cannot be cited instead of the full gate and are not called as duplicate passes by the orchestrator. The gate and its tools are inspected and invoked directly; no product test or seeded-invalid scenario may test whether they detect failures. The gate reports/fails; it cannot approve review, merge, release, or deployment.
