# Make bin build the complete read-only application gate

## Outcome

`./bin/build` is the sole canonical, deterministic, non-interactive, containerized, read-only application acceptance gate, orchestrating locked dependency validation/install/audit, planning validation, backend analysis/tests/coverage/PostgreSQL checks, frontend quality/build/catalog checks, and clean production-install/artifact proof with clear phase failures and warning disclosure.

## Scope

- In scope: Refactor canonical orchestration; explicit phase ordering/environment/cleanup; strict Composer/lock validation and production audit; locked backend/frontend installs; read-only planning validation; PHPCS/PHPStan/dependency checks; backend suites/coverage/guarded PostgreSQL; frontend format/lint/type/test/coverage/build/Storybook/audit; clean production copy/install/autoload/assets/source contract; tracked-tree mutation detection; seeded phase-failure proof; final evidence format and documentation of focused-versus-canonical use.
- Out of scope: Automatic source/planning formatting, dependency updates, merge/release/deployment approval, provider/network product tests, lowest/candidate lanes, scheduler enrollment, broad E2E automation, and silently accepting warnings or unavailable mandatory phases.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Run canonical gate | N/A — `./bin/build` tooling | Inspect locks, planning, owned source/tests, database, dependencies, and production artifact | N/A — no domain event | All required phases pass or gate exits nonzero at a clearly named phase |
| Prove read-only behavior | N/A — gate invariant | Compare tracked state before/after while allowing ignored caches/reports | N/A — no domain event | Tracked planning/source/locks remain unchanged |
| Prove clean production install | N/A — disposable build operation | Inspect no-dev backend graph, production client assets/autoload/startup/source boundary | N/A — no domain event | Disposable production tree contains only approved runtime artifacts/dependencies |
| Seed gate violation | N/A — disposable meta-verification | Introduce representative isolated violation per phase | N/A — no domain event | Correct phase fails clearly without contaminating authoritative worktree/data |

## Validation and permissions

The gate runs from committed locks without implicit updates and never invokes `planning-check --write`, format fixers, source generators that alter tracked files, migrations against non-test databases, or commands that rewrite manifests/locks. It records starting tracked state and fails if tracked files differ afterward, while caches/reports/temp copies/databases stay under ignored/disposable paths.

Include strict Composer validity/platform/lock checks, approved Composer production audit, locked development install, and clean `--no-dev` production install. Include frozen frontend install and production dependency audit under explicit network policy. Audit/install are the only approved network-sensitive phases; product tests remain network-independent and advisory/network failures are not hidden.

Run read-only planning validation, PHPCS, PHPStan, dependency enforcement, backend unit/integration/concurrency tests and accepted coverage thresholds, guarded PostgreSQL migrations/reset, frontend format/lint/type/Vitest/coverage/production build/Storybook checks, then clean production autoload/assets/startup/source/development-exclusion proof. Order should fail fast without skipping evidence needed to diagnose.

`./bin/build` is canonical. Focused wrappers remain supported iteration tools but cannot be cited instead of the full gate. The gate reports/fails; it cannot approve review, merge, release, or deployment.

- [ ] Composer/frontend installs use committed locks without updates; planning runs read-only and no fixer rewrites source.
- [ ] Generated caches/reports/artifacts/temp production trees and test databases remain ignored/disposable and are cleaned appropriately.

- [ ] Frontend source, behavior, coverage, build, Storybook, artifact, and dependency checks enforce TASK-00032 policy.
