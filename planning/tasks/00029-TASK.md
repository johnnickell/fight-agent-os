# Establish the production component catalog and state evidence

## Outcome

Storybook renders actual production React components and neutral semantic-token/Bootstrap mappings across representative responsive, loading, empty, failure, success, disabled, focus, form-validation, light/dark, and reduced-motion states without selecting or copying EPIC-00004's final visual language.

## Scope

- In scope: Pinned Storybook setup and repository wrapper; production component stories; small semantic token layer and deliberate Bootstrap variable mappings; representative form controls, buttons/busy state, alerts/status, loading/empty/error/success patterns, and responsive container/state composition; light/dark token examples; Vitest/RTL behavior/accessibility assertions; deterministic Storybook build; narrow/wide evidence and honest automated/manual observations.
- Out of scope: Final authentication/dashboard visual language, prototype promotion, product pages/journeys, full visual-regression/browser suite, universal WCAG certification, custom brand assets, runtime theme selector journey, RTL, and TICKET-00013's final coverage/gate integration.

## Use cases and contracts

|---|---|---|---|---|
| Render production component state | N/A — Storybook tooling | Read component props/tokens and fake story data | N/A — no domain event | Named deterministic state renders from production code |
| Interact with control/form | N/A — UI behavior | Inspect props/local transient state and accessible feedback | Client-only UI callbacks | Keyboard/pointer interaction, busy/disabled, focus, and validation behavior are observable/testable |
| Preview semantic modes | N/A — presentation preference | Read system/light/dark token selection in isolated catalog | N/A — no domain event | Components use semantic tokens/Bootstrap mappings without embedding final brand values |
| Build catalog | N/A — tooling | Resolve pinned stories/addons/assets | N/A — no domain event | Static Storybook artifact builds without runtime network dependency |

## Validation and permissions

Stories import production components; do not copy component implementations into catalog files or promote `.runs/prototypes/` code. Use invented sanitized data and local reviewed assets/placeholders only. No credentials, private records, provider content, or mutable external resources may enter stories/screenshots.

Start with a small semantic token layer for background/surface/text/muted/border/action/status/focus plus justified typography/spacing/motion mappings. Map tokens deliberately to Bootstrap variables. Values are a neutral foundation and must not claim the accepted EPIC-00004 design; TICKET-00014 may replace/refine them through production work.

Representative components/states use semantic HTML, labels/descriptions, keyboard operation, visible/unobscured focus, appropriate disabled versus busy behavior, status announcements where warranted, reduced motion, target/reflow considerations, and no color-only meaning. Automated checks establish a floor and manual observations remain explicit.

Storybook build/test tooling is pinned, deterministic, and network-independent after installation. Generated output/caches belong in ignored paths unless production policy explicitly requires otherwise.

No runtime authorization is implemented. Component visibility examples are presentation-only and cannot imply server permission enforcement.
