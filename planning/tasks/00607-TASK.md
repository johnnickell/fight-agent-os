# Separate workflow run bookkeeping from the Pi subagent installer

## Outcome

Give maintainers one place to trace live runs from launch to settlement without reading the installer. Preserve the single engine and its existing consumers under the [accepted local Pi integration](../tickets/00130-TICKET.md).

## Scope

- Extract the live run map, fleet summary, and shared run-to-completion path from `harness/pi/vendor/pi-subagents/src/index.ts` into a focused workflow module. Leave tool and startup-flag registration and their distinct completion delivery in the installer.
- In `src/workflow/runtime.ts` of the same package, compute the journal key once for replay lookup and live recording. Keep replay, scheduling, and teardown ownership together. No new public API, scheduler, or compatibility layer.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Run or inspect a workflow | Existing tool, startup flag, and workflow dialog controls | Live run map, fleet summary, and replay journal | Existing progress and completion delivery | Preserve live cards, tool completion outbox, flag session entry and next-turn message, and shutdown cancellation |

## Validation and permissions

Keep source resolution, feature gates, host setup, cancellation, and journal validation intact. Replay still happens before permit acquisition, and live recording still happens before the reply. No permission or installation changes.

## Acceptance criteria

- [ ] Both launch paths use the same live run bookkeeping and retain their distinct completion delivery.
- [ ] Fleet and dialog updates stay live; shutdown aborts outstanding runs as before.
- [ ] A live call uses one key calculation without changing replay eligibility, recorded entries, or ordering.

## Verification and evidence

Run the focused `workflow-tool`, `workflow-command`, `workflow-journal`, and `workflow-runtime` suites and exercise tool and startup-flag completion, including live updates and shutdown cancellation. Run the engine typecheck and `./bin/build`; record actual evidence for both entry points before independent Review and applicable QA.

## Coordination
