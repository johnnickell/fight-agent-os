# Deliver the generic password-reset request journey

## Outcome

An accepted public React route and versioned JSend API accept a canonical email, apply bounded secret-safe request controls, dispatch package `RequestPasswordReset`, and return one generic contract while eligible active users receive an atomic one-hour reset generation and recoverable delivery without exposing identity existence or lifecycle.

## Scope

- In scope: Public request route/form; typed feature service; versioned Action/validated DTO/generic View/OpenAPI; canonical email mapping; Origin/Fetch Metadata/JSON/CSRF policy; atomic endpoint rate limiting; public-contract and bounded timing-normalization strategy; package command dispatch; predecessor replacement/race handling; accepted generic success/throttle/system states; PostgreSQL/HTTP/rate/timing-path/component/accessibility/redaction tests.
- Out of scope: Reset email internals beyond TASK-00053 integration, completion form/API, authenticated password change, delivery status/retry UI, account discovery, CAPTCHA, external password services, exact wall-clock equality claims, and broad browser automation.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Request eligible reset | `RequestPasswordReset` | Package resolves canonical active identity and latest grant | `PasswordResetRequested` | One-hour hashed grant/encrypted delivery/audit commit; delivery reconciliation proceeds after commit |
| Request unknown/ineligible reset | Same command | Package resolves no eligible active identity | N/A — intentionally silent | No grant or delivery; identical generic public response |
| Replace live generation | Same command | Resolve latest grant/delivery generation | `PasswordResetRequested` for successor | Prior authority/delivery becomes terminal and one current successor commits atomically |
| Render generic request result | N/A — client presentation | Read only generic API result | Client navigation/status signal | User receives the same safe next-step guidance without identity-state detail |

## Validation and permissions

Accept only bounded JSON with one canonical email field and no user ID, actor, role, return URL, template, or delivery fields. Apply exact trusted Origin, Fetch Metadata, approved CSRF policy for this public mutation, HTTPS, method/content type/body bounds, and an atomic production rate limit before dispatch. Key limiter dimensions with bounded non-reversible representations; do not retain raw network/email data beyond justified request processing.

Dispatch package `RequestPasswordReset` through the established command path. Do not pre-query identity in the Action or branch public output. The package owns active eligibility, one-hour lifetime, credential generation/hash, encrypted delivery state, predecessor succession, audit, and event. Do not create grants directly or send mail in the request transaction.

Return the same accepted status, JSend shape, headers, copy class, navigation, and absence of delivery metadata for eligible, nonexistent, pending, disabled, deleted, and already-requested identities. Malformed transport input can receive normal validation feedback without account lookup. Rate-limit response must not reveal whether an identity exists. Public errors cannot include user/delivery/grant IDs.

Implement and document a bounded response-normalization strategy that avoids obvious fast missing-user behavior while maintaining rate/worker capacity and deterministic tests. Use injected clock/wait/work capabilities where needed rather than flaky wall-clock assertions; compare control paths and public observables without claiming perfect network indistinguishability. No unbounded sleep, random test delay, or per-identity timing detail is allowed.

Recreate TASK-00035 design with semantic production components. Support email autocomplete/password-manager conventions as appropriate, labels/instructions, keyboard/focus, generic success, rate-limit and system recovery, narrow/wide, system/light/dark, and reduced motion. Success copy tells every requester to check mail if eligible and offers safe return to Login without confirming delivery.
