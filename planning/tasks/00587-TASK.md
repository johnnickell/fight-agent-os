# Deliver local Sync from accepted TASK to refreshed PR

## Outcome

Deliver one usable `/skill:sync TASK-NNNNN` workflow that integrates current `origin/develop` into a selected,
previously accepted TASK branch and automatically refreshes its existing PR through Land. Reuse Engineer and
Land roles without routine Review/QA reruns for integration-only changes. This TASK owns the complete outcome
and one independently reviewable implementation PR under [TICKET-00137](../tickets/00137-TICKET.md) and
[EPIC-00024](../epics/00024-EPIC.md).

## Scope

- In scope: Discoverable Sync skill/coordinator; real coordinator/child role binding; accepted-subject and
  existing-PR intake; fresh sequential Engineer and Land contexts through existing qualified dispatch;
  fetch/merge and intent-preserving conflict resolution; authoritative planning regeneration; normal build
  execution/reuse; automatic non-force existing-PR update; ordinary Land verification/cleanup; concrete stop,
  interruption and partial-effect handling; participating instructions and focused discovery/documentation;
  direct native/workflow qualification and independent acceptance of Sync itself.
- Out of scope: Routine Review/QA stages for integration-only input TASKs; unrelated repairs, new behavior or
  requirement changes in those TASKs; rebase/history rewriting or force-push; PR approval/merge or replacement
  of an ended PR; release/deployment, remote-branch deletion or other-TASK sweeps; managed/database/browser
  expansion or default-checkout synchronization; a parallel role launcher, execution engine, resource registry,
  permanent delivery queue or post-merge planning chore; global installation/profile changes without separate
  operator authority.

## Acceptance criteria

- [ ] **AC-01 — Intake:** Real Pi discovery/invocation binds exactly one intended TASK, repository, selected
  checkout and existing open PR. Current independent acceptance and intervening-source applicability are checked;
  missing/contradictory identity, authority, evidence or a newer failure prevents affected effects.
- [ ] **AC-02 — Role progression:** A genuine Sync coordinator launches fresh Engineer then Land contexts using
  supported existing role/dispatch machinery. The coordinator does not edit implementation. Integration-only
  execution launches no routine Review/QA children and needs no separate manual Land invocation.
- [ ] **AC-03 — Integration:** Fetch and merge current `origin/develop`, retain published history and preserve
  incoming plus TASK intent for clean merges, meaningful code overlap and authored/generated planning conflicts.
  Inspect effective interactions, regenerate derived views and record concise nontrivial resolutions plus
  old/new base/head OIDs without rewriting original acceptance reports or adding proof machinery.
- [ ] **AC-04 — Concrete blockers:** Incompatible intent, discovered defects, failed checks or genuinely new
  behavior stop the fast path with the actual owner/action. Do not resolve these by silently changing accepted
  requirements, repairing unrelated defects, inventing acceptance or requiring Review/QA solely for overlap.
- [ ] **AC-05 — Gate:** Run useful focused checks and normal `./bin/build` on the committed integration candidate.
  Qualify changed-input execution and valid planning-only application reuse, distinguish fresh/reused results
  with original receipt identity, and disclose warnings/incomplete verification. Do not force a rerun merely
  because HEAD changed; preserve explicit required hosted/final-head checks.
- [ ] **AC-06 — Existing PR:** Successful verification proceeds automatically to Land, which updates and verifies
  the same open PR by ordinary non-force push with exact base/head/remote OID and required evidence. No automatic
  approval/merge, duplicate/replacement PR, silent retargeting or force-push occurs.
- [ ] **AC-07 — Recovery and cleanup:** Blocked/interrupted/partial cases inspect actual outcomes before retry,
  preserve completed effects and avoid duplicate dispatch/publication. Reuse normal eligible cleanup and verify
  its postconditions; publication, cleanup, protected-resource holds and human merge remain distinct with finite
  next actions. An uncertain worker or ended PR does not trigger blind replacement.
- [ ] **AC-08 — Complete implementation:** Align actual participating instructions and discovery/docs with this
  approved integration-only boundary while preserving ordinary Build and independent acceptance for new work.
  Direct qualification distinguishes real workflow/Git/gate/PR effects from walkthroughs. Sync's implementation
  has normal independent Review and applicable QA; no product-suite tests of skill/build/planning machinery.
