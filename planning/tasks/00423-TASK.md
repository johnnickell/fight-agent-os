# Protect registration and context references from cleanup

## Outcome

Actual registration/link/configuration/context reference producers and creation-stage participants share durable
resource exclusion, so separately admitted local or remote cleanup cannot race new references or erase protected
resources. Unknown coverage preserves resources rather than masquerading as absence.

## Scope

- In scope: Early actual reference inspection/admission participants, owning writer integration, exact resource
  binding, shared PostgreSQL fences/exclusion and conservative retained-reference results.
- Out of scope: Cleanup consent/UI, live filesystem/provider deletion, registration/context stage orchestration,
  new retention registry, deleting identity/history, final receipt and a second authority engine.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Inspect applicable references | N/A — protected bounded read | Actual identity/link/designation/configuration/context bindings and retained obligations | N/A | Complete known reference facts or protected unknown |
| Admit an owning reference | Existing owner command with shared reference participant | Exact resource identity/generation, current authority and exclusion | Existing owner events only | Reference/state/audit/outcome commit together or refuse |
| Fence resources for later cleanup | Internal shared exclusion participant, not cleanup consent | Complete current reference coverage and original stage state | Owning committed exclusion facts | Durable exclusion across the external-effect window; no deletion |
| Reconcile original exclusion | Existing original-result participant | Verified original disposition and retained references | Owning disposition facts | No release on timeout, uncertain absence or unrelated result |
