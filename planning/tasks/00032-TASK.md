# Enforce deterministic frontend quality checks

## Outcome

Pinned Docker-backed frontend checks prove lock reproducibility, formatting, linting, strict types, behavior tests and honest coverage, production ESBuild output, Storybook/component accessibility checks, dependency safety, and artifact hygiene across the representative client without network-dependent product tests.

## Scope

- In scope: Complete/normalize repository frontend wrappers; clean frozen/locked install; format/lint/type checks; Vitest/RTL behavior and coverage reporting; production ESBuild build; Storybook static/component/accessibility checks already justified by TASK-00029; production dependency audit under explicit network policy; bundle/artifact inspection; deterministic cache/report paths; seeded failure evidence; accepted exclusions and warning disclosure.
- Out of scope: Canonical `./bin/build` orchestration, arbitrary coverage percentage unsupported by requirements, broad E2E/browser automation, visual taste approval, universal accessibility certification, network-dependent product tests, production deployment, and repairing unplanned product behavior.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Verify client source | N/A — frontend tooling | Inspect formatting, lint, strict types, imports, and build graph | N/A — no domain event | Violations fail with actionable diagnostics and no source mutation |
| Verify browser behavior | N/A — test tooling | Render routes, authority, API client, forms, components, and states | Client-only test signals | User-observable success/rejection/cancellation/accessibility behavior is asserted |
| Build production artifacts | N/A — build tooling | Resolve locked source/dependencies/runtime config boundary | N/A — no domain event | Deterministic deployable assets contain no prohibited development/private content |
| Build component catalog | N/A — Storybook tooling | Render production components/stories/addons | N/A — no domain event | Static catalog and configured accessibility checks complete without runtime network |

## Validation and permissions

All commands use TASK-00026's pinned Node/package manager and committed lock. Clean install uses frozen/locked mode and must not mutate the lock. Formatting checks do not rewrite in acceptance mode. Lint/type configuration covers meaningful production and test/story code with narrow generated-output exclusions.

Vitest/RTL emphasizes API mapping/failures/cancellation, authority transitions/guards, routes, form/component interactions, accessibility semantics, and error states. Collect/report frontend coverage honestly and identify gaps/exclusions; do not invent a percentage-only target or satisfy behavior with snapshots alone. Storybook imports production components and runs only accepted deterministic addons/checks.

Production build and artifact inspection reject credentials, authority snapshots, private runtime configuration, prototype imports, mutable external resources, source/cache/test/story leakage contrary to policy, and accidental development-only code. Source-map policy is explicit. Dependency audits distinguish production/development scope and disclose advisory/network limitations.

Caches/reports/static Storybook output belong under ignored paths. No runtime permission applies; tooling/configuration/test changes are authorized.

## Acceptance criteria

- [ ] Clean locked frontend installation succeeds without lock mutation using pinned Node/package-manager versions.
- [ ] Formatting check, lint, strict typecheck, and production build cover meaningful client/test/story source and are deterministic/non-interactive.
- [ ] Vitest/RTL covers representative API client, cancellation, authority unknown/invalidation, guarded routes, components/forms, and error/state behavior.
- [ ] Frontend coverage is generated/reported honestly with exact narrow exclusions and does not substitute percentages/snapshots for behavior assertions.
- [ ] Storybook static build and configured component/accessibility checks use production components and no runtime network resources.
- [ ] Production artifact inspection rejects credentials, authority/private config, prototype imports, mutable remote assets, and prohibited development/test content.
- [ ] Source-map and generated-asset policies are explicit and verified.
- [ ] Production dependency audit runs under an explicit network/advisory policy and reports warnings/limitations rather than suppressing them.
- [ ] Isolated seeded format, lint, type, behavior, and production-build violations fail with clear phase diagnostics.
- [ ] Focused frontend checks and `./bin/build` pass with versions, test/story counts, coverage, artifact sizes, duration, advisories, and warnings recorded.
