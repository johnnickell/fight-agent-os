# Resolve exact role profiles with truthful capability availability

## Outcome

An authorized caller can inspect and resolve an exact approved role-template revision into a deterministic
profile with its referenced resources, requested Permissions, Repository applicability and model constraints.
Unavailable or ambiguous inputs are explicit; a resolved profile is neither an Agent nor current use authority.

## Scope

- In scope: Owned Harness read/resolution use case through a supported protected application/adapter path;
  immutable revision and alias resolution, complete requested-capability validation, model/resource availability,
  provenance and safe failures, using the single existing Harness resource authority.
- Out of scope: Another template database/registry, initial seeding, editor/publication, automatic Agent binding
  changes, Permission assignments, credential operations, provider qualification or session launch.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Inspect exact role profile | N/A — read-only | Authorized template identity/revision, prompt, resources, complete requested Permission set, scope and model constraints | N/A — resolution emits no revision or grant fact | Safe deterministic profile/provenance usable by creation and session owners |
| Resolve alias or current selection | N/A — read-only | Versioned alias mapping, authoritative selected revision and exact referenced history | N/A | Exact pinned result or explicit ambiguity/staleness, never name-based identity replacement |
| Explain unavailable profile | N/A — read-only | Missing/ineligible references, unsupported models and applicable current scope | N/A | Bounded authorized reasons; no partial profile silently presented as ready |

## Validation and permissions

Consume TICKET-00075's database authority, not the source specifications as a runtime fallback. Preserve exact
historical revision bytes, logical IDs and aliases; a later current selection cannot silently replace an Agent's
bound revision. Resolve full requested resources and current eligible `ADMIN_SAFE` Permission identities through
their owners, without inventing IDs, copying AccessControl policy or creating any grants. Ineligible or missing
requests are reported for explicit correction, not discarded to manufacture a usable desired set.

Validate installation/Workspace and registered-Repository applicability under current caller access. Names,
client claims, templates and read access to some related object cannot establish authority. Keep internal
resolution and any CLI/HTTP adapter equally protected; distinguish denied, unavailable, missing, stale and
ambiguous outcomes without disclosing another scope's prompt or requested Permissions. Template-management
rights do not imply Agent creation/assignment rights. Safe output contains no credentials, protected handles or
private provider configuration; inspection does not authorize provider disclosure.

Resolve resources through their existing type-specific Harness owners with exact identity/revision/origin where
applicable; no generic replacement resource aggregate or second Skill resolver. Consume actual model catalog and
qualified capability observations. Separate requested/configured from provider-reported model identity and
unavailable from zero cost. Unsupported selection is explicit, with no silent provider/model/resource substitution.
A role's preference for inexpensive or fast work is not measured suitability evidence.

Build a coherent exact resolution from current selections and immutable references; detect conflicting revisions
rather than mixing generations. Pin results for the consuming operation, while describing availability as an
observation rather than a reusable grant. Agent creation and every later use revalidate current authority through
their owners. Renaming an alias changes no historical event, Agent identity or Permission. Existing managed/custom
resources retain scope and ancestry; this operation neither propagates inheritance nor reconciles Agent drift.

## Acceptance criteria

- [ ] Authorized inspection/resolution returns a complete exact role revision with traceable prompt/resource,
  requested-Permission and model constraints; repeated resolution of unchanged inputs is deterministic.
- [ ] Alias ambiguity, missing/retired references, ineligible Permissions, unsupported model and wrong Repository
  scope fail safely without silent substitution, partial desired sets or fallback to source definitions.
- [ ] Real PostgreSQL history/reference and competing-selection behavior preserves exact provenance and old
  bindings; a current-revision change cannot silently rewrite an existing Agent or session.
- [ ] Denied direct/adapter calls reveal no protected cross-scope detail; reads create no Agent, grant, session,
  revision, publication or reconciliation effect. Availability is not advertised as current tool authorization.
- [ ] The eight managed definitions and the separately owned Triage extension can use the same resolver without
  special role-name grants or another registry. Actual missing runtime capabilities remain visibly unavailable.
