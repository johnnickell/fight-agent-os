# Gather MCP evidence under the invoking principal

## Outcome

A qualified Pi 1.1.0 caller can request a bounded composition of declared first-party MCP commands and queries,
then ask Jev typed questions about the resulting permitted evidence. Every sub-call retains the original trusted
principal and current operation authority, including existing effect approvals and recovery rules.

## Scope

- Extend [TASK-00171](00171-TASK.md)'s authenticated judgment entrypoint and shared evaluator/provenance, using
  [TASK-00161](00161-TASK.md)'s guard for covered bash and mutating routes. Reuse package-owned commands, queries,
  permissions and events under ADR 0001; PHP owns authoritative application operations. Jev is a classifier behind
  the tool, not a new privileged principal, peer Agent or source of executable commands.
- Accept a versioned bounded composition request with declared capability identifiers, schema-validated arguments,
  ordered dependencies, target repository/environment and typed questions or preset. Resolve capabilities against
  a protected allowlist of actual existing operations and their input/effect/authority contracts. A question, source
  document or model-selected answer cannot add an operation or change its arguments, target or approval.
- Carry server-trusted caller/delegation context through every sub-command and sub-query, including real Agent,
  assignment and repository/environment scope when applicable. Verify downstream current authorization on every
  request and before disclosing results. Caller-supplied identifiers are untrusted selectors, not authenticated
  context. Reject missing/forged/lost delegation, stale credentials and scope expansion without ambient-service
  fallback. Keep credentials outside model context, Agent-visible results and ordinary logs.
- Preserve each command's normal side-effect permission, approval, idempotency key, expected-state and uncertain-
  outcome rules. Revalidate exact arguments/target/authority and applicable guard receipts before dispatch;
  mutation semantics remain with the owning command. Approved composition is not blanket consent for every
  possible child operation, and tool composition does not alter WF-015 peer-Agent delegation.
- Demonstrate qualified read and mutating operation paths using actual maintained operations and their existing
  authority; do not invent product endpoints solely for test coverage. An unavailable required operation contract
  remains an explicit acceptance blocker. No new permission grants or broadening of existing business policy.
- Apply the deterministic and Jev guard policies to covered nested effects, using the same protected route and
  current operation binding as direct calls. Reject unqualified routes instead of bypassing the guard through MCP.
  Avoid recursive judgment-of-judgment loops: the internal evaluator remains data-only and cannot request another
  composition. Both individual-call and whole-composition depth/work budgets must hold.
- Require a finite protected composition profile for maximum depth, sub-calls, input/output/evidence bytes, elapsed
  time, concurrency, retained metadata and spend before admission. Keep existing evaluator ceilings and tighter
  session/child allocations. Shared conservative reservations include both guard and final-judgment requests;
  missing limits or uncertain remaining budget cannot become unlimited execution or a fresh budget per sub-call.
- Trace composition/step/request identities, actual caller and target scope, operation revision, timestamps,
  approval/idempotency/effect-state references and receipt identities through the existing protected evidence
  contract. Bound metadata and presentation; retain exact execution exit/receipt separately from Jev classification.
  Ordinary logs contain neither raw command/query bodies nor secrets. Scope inspection and reference access too.
- On cancellation, reload, permission loss, budget exhaustion or partial failure, stop dependent dispatch and
  invalidate late responses for the active generation. Cancellation is not proof an already-dispatched effect was
  undone. Reconcile through the owning operation's authorized status/receipt/recovery path, retaining uncertain
  effect and billing states; never blindly retry, compensate or regenerate evidence by replaying a command.
- Preserve necessary pending/uncertain step identities and usage across interrupted composition through protected
  owning operation records and bounded correlation metadata. If trustworthy recovery state is absent, return an
  intervention/unknown outcome and prohibit automatic continuation. Do not introduce a second transaction/outbox
  authority or claim all composed effects are one transaction; follow ADR 0002's durable-effect boundaries.
- Minimize/redact gathered evidence and apply independent provider-disclosure policy before evaluation. Authorized
  execution does not imply egress permission. Return typed answers, explicit unavailable/invalid/incomplete states,
  authorized evidence references and coverage; reasons remain caller-written choices, not free-form Jev output.
- Fresh operation evidence is obtained only through a currently authorized invocation. Existing immutable receipts
  may support an explicitly historical inquiry; cache lookup cannot trigger execution or disguise old observations
  as fresh. Neither TASK-00172 staged file jobs nor TASK-00173 optional reuse is a mandatory dependency here.
- Exclude arbitrary shell/string execution endpoints, new operation permissions, automatic production access,
  database provisioning, deployment, memory ingestion, main-model routing and new analyzer/SQL implementations.
  TASK-00175/00176/00177 add separately qualified analysis capabilities to this usable composition path.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Compose permitted evidence queries | Admit a bounded composition | Existing authorized MCP queries and current principal/scope | Step/composition observations with original receipt references | Bounded permitted reads and optional provider usage |
| Invoke an authorized business command | Existing owning command with its approval/idempotency contract | Current authorization and exact effect binding | Owning command events plus composition observations | Only the explicitly permitted native command effects |
| Judge gathered evidence | Submit minimized permitted evidence to shared evaluator | Typed questions, coverage and provenance | Judgment completed/partial/failed observation | Bounded provider disclosure and usage; no effect acceptance transition |
| Cancel or reconcile work | Cancel owned composition; invoke only an authorized owning recovery operation | Actual receipt/effect/billing state | Cancellation/reconciliation/intervention observations | Stop dependent work; no blind replay or implied rollback |

## Validation and permissions

Authenticate every entry and propagate verifiable delegation to every downstream request. Current permission and
resource scope must hold at dispatch, result delivery and inspection. A physical credential or prior guard decision
cannot replace live authority. Treat tool responses, source instructions and Jev answers as untrusted evidence;
reject executable intent in question/data fields. Bind approval to the actual operation and invalidate it after
changed arguments, policy, target or lifecycle. A chain can contain authorized writes without granting SQL access.
Protected receipts report actual observed effects and uncertainty; Jev cannot certify execution success or supply
missing authorization. Qualify all supported nested routes and disclose residual local same-user isolation limits.

## Acceptance criteria

- [ ] Actual Pi 1.1.0 first-party composition demonstrates permitted multi-step queries and an authorized existing
  mutating operation with original principal, current per-call scope and the owning effect/approval contract intact.
- [ ] Forged/lost identity, mid-chain revocation, cross-repository/environment requests and changed approved inputs
  stop affected dispatch/result disclosure without service-identity fallback or nested-route guard bypass.
- [ ] Whole-composition and individual limits include nested calls and guard/final-evaluation spend; recursive work,
  partial failures and unknown remaining budget cannot reset or evade limits.
- [ ] Cancellation/reload/late responses preserve actual effect and billing uncertainty, halt dependent work and
  permit only verified authorized reconciliation. No command is blindly replayed to repair a missing result.
- [ ] Minimized evidence requires separate egress permission; returned typed results/coverage/references contain no
  credentials or raw tool bodies and do not equate classification with a successful operation receipt.
- [ ] Fresh and historical evidence remain distinguishable, protected receipt inspection preserves current access,
  and ordinary primary-backed business operations retain their existing domain semantics.

## Verification and evidence

Test owned composition admission, authority propagation, limits, cancellation, partial-effect recovery and result
handling with meaningful current/revoked/uncertain cases. Qualify actual MCP delegation, nested guard coverage and
Pi 1.1.0 integration directly against maintained operations in an authorized controlled environment. Use bounded
permitted provider observations for usefulness, coverage and total cost/latency; do not invoke production merely
for acceptance. No product tests of wrapper/configuration/prompt text or testing infrastructure. Run focused owned
backend checks, `./bin/harness-check` and canonical `./bin/build`; record direct exits, tested-content identity,
exact operation/runtime/profile/evaluator versions and redacted receipts under `.runs/tasks/TASK-00174/`.
Missing real operation or delegation evidence remains an acceptance gap, not a fixture-proven capability.
