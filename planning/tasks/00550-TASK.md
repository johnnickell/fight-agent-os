# Add conditional architecture diagrams to PR authoring and review guidance

## Outcome

Authors of material architecture changes can show reviewers the relevant maintained diagram and trace it to the
source revision. Independent reviewers can check that view against the exact diff and source while retaining the
existing review criteria and verdict boundaries.

## Scope

- In scope: Update the existing pull-request authoring and independent Review guidance to require a relevant
  diagram only when class ownership, dependency direction, or runtime flow changes materially. Explain how to
  identify the changed boundary or flow, link the canonical Python source and owning feature documentation,
  present the rendered image, identify the source revision, and disclose uncertainty or omitted details. Include
  a conditional field in the PR template only if it makes this expectation clearer. Extend existing review
  instructions to compare applicable diagrams with the exact diff and implementation and record whether the view
  is accurate, inaccurate, incomplete, or unavailable with source-traceable evidence. Qualify the guidance with
  a material-change example and an example where no diagram adds useful information.
- Out of scope: Changes to application behavior, the shared source/image/renderer contract, a new review verdict,
  automated architecture scoring or build gates, independent review or merge policy changes, and Pi show-me
  behavior.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Prepare a material architecture change for review | No application command; follow the repository pull-request guidance | Read the effective diff, feature documentation, maintained diagram source/image, and cited source revision | N/A — no application or workflow event | The PR description includes the relevant rendered view, canonical source and feature-doc links, changed boundary/flow, revision, and known omissions |
| Review the architecture view | No application command; use the existing independent Review workflow | Compare the diagram with the exact PR diff, implementation, and source revision | N/A — reviewed application events are outside this documentation workflow | Existing review evidence records the view's accuracy and any traceable limitation without adding a verdict or weakening current criteria |
| Prepare a change with no informative architecture view | N/A — ordinary PR authoring | Assess whether ownership, dependency direction, or runtime flow changes materially | N/A — no application or workflow event | The PR omits an irrelevant diagram without implying incomplete work |
