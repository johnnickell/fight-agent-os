# Execute bounded work through one-shot consumers

## Outcome

The enrolled Runner executes the existing production Workflow path through three supervised one-shot consumers
by default, without exceeding independently authorized capacity or letting blocked work monopolize safe capacity.
Each disposable consumer handles at most one Workflow command before exiting.

## Scope

- In scope: Bounded supervised consumer integration, eligible dispatch iteration, owning lease/custody operations,
  actual one-shot execution, capability-loss handling and safe operational status/guidance.
- Out of scope: Another scheduler claim/commitment ledger, sandbox/provisioner/broker, Start engine, Team selector,
  phase transition engine, artificial demonstration Workflow, browser or forecast surface.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Consume one Workflow | Existing admission/lease and execution commands | Original intent, current gates/limits, capability and resource state | Existing owning admission/execution facts | One supported Workflow command in one disposable process |
| Pass blocked work | Owning safe defer/disposition, not another TASK selector | Bounded eligible queued work and exact hold reasons | No fabricated running transition | Other safe admitted work may use available capacity |
| Observe completion or loss | Existing owning result/reconciliation operation | Lease, child custody, actual result and uncertainty | Confirmed owner results only | Consumer exits; retained work/claims survive uncertainty |

partial delivery cannot activate unsupported recovery routes.
