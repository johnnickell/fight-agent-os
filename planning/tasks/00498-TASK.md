# Remove harness denials from native file reads

## Outcome

Restore native Pi file reading across consuming projects so saved build evidence and provider instructions
cannot be vetoed by harness enrollment, file classification or instruction-reference admission.

## Scope

- Remove native `read` replacement and read-blocking hooks from the enrolled profile and opt-in deterministic policy.
- Keep optional Jev discovery and structural lookup, their source disclosure bounds, budgets and accounting.
- Preserve write/edit workflow, checkout and protected-resource controls, plus the independent policy's script controls.
- Reconcile current guidance and qualify native logs, cross-project files, links, images and held/revoked profiles.
- Exclude consumer source changes, live provider calls, enrollment changes, global installation, merge and release.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Inspect evidence or instructions | Native Pi `read` | Path and optional native ranges | Native tool result | Native filesystem read only; no evaluator or enrollment prerequisite |
| Discover relevant files | `jev_read_file`, `file_locate` | Existing bounded request | Existing discovery observations | Existing authorized optional disclosure/accounting |
| Preserve mutation authority | Native wrapped `write`/`edit` | Existing workflow and policy | Existing denial/result | Only previously authorized changes |
