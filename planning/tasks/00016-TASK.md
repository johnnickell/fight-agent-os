# Establish atomic audit evidence and durable delivery intent

## Outcome

Agent OS persists package audit evidence and ADR-selected recoverable delivery intent on the shared PostgreSQL transaction, proving required business state, secret-safe evidence, and intent commit or roll back together while provider delivery remains outside the transaction.

## Scope

- In scope: Audit-evidence migration and production `AuditEvidenceRepository`; subject typing for user/agent evidence without inappropriate references; safe context serialization; application-owned durable-intent capability, migration, adapter, and composition selected by the ADR; pending discovery/claim/retry/idempotency state needed for later delivery; atomicity, recovery, and concurrency tests.
- Out of scope: Email or other provider implementation, worker/scheduler operation, feature-specific invitation/reset payload construction, HTTP/UI, event sourcing, exactly-once claims, broad audit query/admin UI, and Agent persistence.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Record audit evidence | Package/application sensitive behavior calls `AuditEvidenceRepository` | N/A — append-only foundation contract | Preserve the originating package/application event | Secret-free actor/action/subject/context evidence is committed |
| Record required delivery intent | Later orchestration writes through the durable-intent capability | N/A during business transaction | Package events retain ownership and may coordinate post-commit | Recoverable provider-neutral intent commits with business state |
| Discover and claim pending intent | N/A — TICKET-00011 delivery loop will consume capability | Select eligible pending work safely | N/A — delivery outcomes belong later | One bounded claimant receives work; abandoned work remains recoverable |
| Retry/finalize intent state | N/A — persistence operation supporting later delivery | Compare expected claim/revision/idempotency state | N/A — provider events belong later | Stale workers cannot overwrite newer state; retry history remains safe |

## Validation and permissions

Audit storage preserves actor ID, action, explicit subject type and ID, and approved string context. It must support package `UserId|AgentId` subjects without requiring an Agent row and without recording passwords, credentials, tokens, hashes, provider payload secrets, or arbitrary exception data. Context serialization is deterministic and bounded.

The durable-intent contract follows the accepted ADR and stores only minimum provider-neutral routing/payload references, idempotency identity, status/revision, eligibility, attempts, and safe failure classification needed for recovery. Sensitive delivery content must be protected or referenced according to the ADR and never enter routine diagnostics.

Audit/business state/intent writes use the same connection and enclosing `commitTransactional()` call. External provider execution must not occur inside the transaction. Claiming/retry transitions use expected-state/locking controls; crash recovery and at-least-once duplication are explicit. No exactly-once guarantee is claimed.

No end-user permission is introduced. Persistence and capability composition are authorized; providers, workers, and product delivery flows belong to TICKET-00011.
