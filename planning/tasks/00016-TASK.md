# Establish atomic audit evidence and package delivery persistence

## Outcome

Agent OS persists package audit evidence and the qualified Fight Access Control credential-delivery lifecycle on the
shared PostgreSQL connection, proving originating state, encrypted delivery work, and secret-safe evidence commit or
roll back together while claims, outcomes, and recovery obey package-owned expected-state rules.

## Scope

- In scope: After qualified Fight Access Control `v0.3.0` is tagged and locked, audit-evidence migration and production `AuditEvidenceRepository`; subject typing for user/agent evidence without inappropriate references; safe context serialization; package-compatible email-change grant/delivery persistence; cross-family secret-free due-work discovery; claim/lease/retry/outcome persistence needed by invitation, password-reset, and email-change repositories; atomicity, restart recovery, and concurrency tests.
- Out of scope: Provider implementation or invocation, worker/scheduler operation, product email-change routes/provider wiring, HTTP/UI, consumer credential outbox, event sourcing, exactly-once claims, broad audit query/admin UI, external audit publication, and Agent persistence.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Record audit evidence | Package/application sensitive behavior calls `AuditEvidenceRepository` | N/A — append-only foundation contract | Preserve the originating package/application event | Secret-free actor/action/subject/context evidence commits with owning state |
| Persist required credential work | Qualified package originating handlers write grant-owned delivery state through their repositories | N/A during originating transaction | Package events may coordinate only after commit | Aggregate, encrypted delivery material, and audit evidence commit or roll back together without a second outbox |
| Discover and claim due work | Direct package processing will consume repository contracts | Select bounded pending, due-retry, and expired-lease generations in package-defined order | Original post-commit event is optional | One exact generation gains a committed opaque claim token/lease and expected revision |
| Persist retry/final outcome | Direct package handler records its typed provider outcome later | Compare delivery ID, claim token, lease, revision, and current generation | Package outcome events remain package-owned | Stale workers cannot overwrite current state; retry timing and terminal ciphertext destruction match package policy |

## Validation and permissions

Audit storage preserves actor ID, action, explicit subject type and ID, and approved string context. It must support package `UserId|AgentId` subjects without requiring an Agent row and without recording passwords, credentials, tokens, hashes, ciphertext, provider payload secrets, or arbitrary exception data. Context serialization is deterministic and bounded.

Credential delivery persistence implements the exact locked `v0.3.0` package contracts; it does not recreate their lifecycle in Agent OS. Secret-free discovery is deterministic and bounded. Claims persist token, lease, attempts, and expected revision before any provider call. Retryable outcomes use package-calculated bounded increasing backoff until grant expiry. Delivered, permanent, expired, replaced, revoked, and cancelled terminal states destroy ciphertext when required. No generic credential outbox is created.

All originating business/grant/audit writes use the same connection and enclosing `commitTransactional()` call. Claim and outcome writes use later short transactions. Provider execution must not occur inside this TASK. Concurrency controls reject stale generations, claim races, expired claim tokens, and outcomes from superseded workers according to the package contract.

No end-user permission is introduced. Persistence composition is authorized; providers, direct processing, recovery scheduling, and product delivery flows belong to TICKET-00011.
