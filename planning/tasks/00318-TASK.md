# Safely reconcile the enrolled local checkout

## Outcome

After verified merge, perform explicitly authorized maintenance of an enrolled main Worktree without disturbing
human work: bounded fetch/prune, configured-base switch, fast-forward and exact merged local-branch retirement.

## Scope

- In scope: Safe maintenance preview/admission, exact enrolled checkout/resource fencing, recoverable constrained
  Git effects, merged Workflow local-branch retirement and truthful completed/pending explanations.
- Out of scope: Stash/reset/discard, rebase/merge/force, remote-branch deletion, broad gone-branch cleanup,
  maintenance of unenrolled human checkouts, changing merge facts or restarting the stopped Workflow.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Explain safe maintenance | N/A — read-only preview | Verified merge, enrolled Worktree, ownership, cleanliness, reservation and Git state | N/A | Exact candidate effects or concrete pending reasons |
| Update configured base | Explicit bounded maintenance authorization/execution | Original effect, current grant, clean idle checkout and configured base | Maintenance intent/result/pending facts | Authorized fetch/prune, base switch and fast-forward only |
| Retire merged local branch | Exact owned branch-retirement operation | Verified merge/remote/inclusion and every linked Worktree | Attributable retirement or retained-branch fact | Only this merged Workflow's safe local branch removed |

## Validation and permissions

TASK-00079's physical registration/designation grants no filesystem mutation authority. Require explicitly enrolled
main Worktree identity, current separate maintenance grant, approved canonical root, correct Git common-directory/
Repository/source identity and expected revisions. Re-observe ownership, path, branch/HEAD, clean index/worktree,
idle/unreserved state and all linked Worktrees before each mutation. Coordinate existing narrow checkout locks
and reservations; observation alone cannot fence a concurrent Agent or human-sensitive operation. Unsupported
safety/fencing on a host remains a hold, never an optimistic check-then-delete.

Consume TASK-00317's exact verified merge and base-inclusion facts, but refresh current remote/base state as needed.
Allow only explicitly authorized fetch/prune, switch to configured base and fast-forward update. Dirty, busy,
missing, moved, divergent, detached, inaccessible or ambiguous checkout state remains maintenance pending.
Never stash, reset, discard, rebase, merge, force or overwrite unrelated working files to make maintenance succeed.
Fetch/prune is not authorization to delete remote branches or every local branch whose tracking ref is gone.

Remove only the merged Workflow's local feature branch after proving exact ownership, verified merge/result,
remote state, commit inclusion and absence from every Worktree. Preserve ambiguous or independently changed
branches. Report other gone branches without deleting them. Durable evidence, shared services, unrelated branches
and human-owned resources remain outside the capability.

Persist exact intent/audit before external Git effects and reconcile original outcome after crash or uncertainty
before retry. Bind current authority and expected state; bounded locks never become a repository-wide execution
scheduler. Completion or failure of maintenance cannot change accepted Review history, duplicate TASK completion,
undo verified merge/eligibility or implicitly start another Workflow. Queries explain retained resources safely.

## Acceptance criteria

- [ ] Only explicitly authorized enrolled clean idle unreserved main Worktrees receive constrained fetch/prune,
  base switch and fast-forward; registration/designation alone grants no mutation authority.
- [ ] Dirty, busy, divergent, detached, missing/moved or uncertain states remain untouched with actionable
  maintenance-pending reasons, without stash/reset/discard/rebase/merge/force.
- [ ] Local branch deletion affects only the exact verified merged Workflow branch, with current inclusion,
  remote/ownership and all-Worktree checks; branch-use/reservation races deny unsafe effects.
- [ ] Duplicate/interrupted effects reconcile original state and preserve unrelated work/evidence; remote
  branches and unrelated gone branches are never deleted.
- [ ] Verified merge/Complete and downstream eligibility remain valid when maintenance is unavailable or pending.
