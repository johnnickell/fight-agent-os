# Remember and curate an Agent's scoped private memory

## Outcome

A separately authenticated Agent can record, read, correct and clear its own database-backed private memory
through first-party MCP across its permitted sessions, without exposing another Agent's notes or treating a
worktree, Pi conversation or template as memory authority. This is one independently reviewable private-memory
use case through Domain, Application, persistence and MCP delivery; it does not enable live ingestion before the
separately planned safety-removal path is ready.

## Scope

- Own the private MemoryEntry behavior for one stable Agent identity: small Workspace-private general bank for
  generally applicable learning, plus repository/assignment-partitioned working memory. Use typed registered
  `RepositoryId` and trusted Agent/assignment context, not a new Project identity, a template/display name,
  caller-selected owner or a speculative MemorySpace aggregate. Qualify any needed aggregate boundary from the
  actual use cases before implementing it.
- Store current attributed plain-language text with source references, applicability, verification state,
  creation/author/assignment and available session/phase/Workflow provenance. Record enough safe metadata to
  inspect a change; replacing or clearing one's own current text does not retain obsolete private content by
  default. Do not bulk-import raw Pi transcripts, hidden reasoning, credentials or another repository's data.
- Provide application-owned remember, exact read, replace and clear commands/queries with appropriate facts and
  safe Views. Deliver first-party MCP tool operations for the qualified HMAC Agent principal; scope IDs are
  validated targets, never authority. Ensure an uncertain exact retry resolves the original write rather than
  storing it again. Keep business ownership/lifecycle rules in Domain and Application; Adapter owns Doctrine,
  transport, validation and safe presentation under ADR 0001/0002.
- Check current Agent identity, direct/effective Permission, repository and assignment on each operation.
  Enforce one active session per identity through the existing execution owner rather than inventing a second
  session scheduler. On closed Workflow, reassignment, revocation or retirement, deny subsequent normal access
  to no-longer-authorized working memory while retaining it for the separately authorized oversight path.
  Ordinary access to the same Agent's general bank is not cross-repository disclosure authority.
- Exclude shared Workflow/TASK entries and role handoffs (TICKET-00047), proposal/promotion (TICKET-00048),
  Jev lookup (TICKET-00049), private oversight (TASK-00186), human UI and exceptional safety removal
  (TICKET-00050). An explicit confidential-source reference cannot be copied into the general bank merely
  because the caller wrote it; do not claim an infallible semantic filter for all sensitive prose.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Remember private learning | Record own entry for an assigned or permitted general scope | Resolve current Agent, scope and source references | Private entry recorded after successful change | One durable attributed current value; exact retry returns original identity |
| Recall current private learning | N/A — read-only | Exact own-entry read and bounded own-scope selection | N/A — read emits no memory-change fact | Only currently permitted private content/provenance returned |
| Correct or clear own note | Replace or clear current text under owned scope | Read current entry and expected ownership/lifecycle | Private entry corrected or cleared | Change metadata remains, but obsolete private text is not reloaded or silently shared |
| Lose normal access | N/A — no stale authority transition caused by read | Read current assignment/Agent status at next request | Existing assignment/Workflow facts under their owner | Former assignment's content is denied, not deleted or exposed through a cached pointer |

Message names describe owned intents, not fixed PHP type, MCP wire name, schema or event-sourcing requirement.

ambiguous source links and stale/revoked authority with safe errors. Do not persist credentials or raw transcripts

## Acceptance criteria

- [ ] One real qualified Agent/HMAC/MCP caller records and later reads its own Workspace-private general lesson
  and an authorized repository/assignment note through the same application authority; another Agent and an
  unrelated repository cannot read them.
- [ ] Exact same-command retry does not duplicate an entry, and repeated valid reads do not mutate memory;
  wrong scope, stale assignment, retired identity, closed Workflow and revoked Permission deny new operations.
- [ ] The owner corrects or clears its current working text, sees only the current content on recall, and leaves
  safe attribution without exposing or automatically reloading the prior private value. A shared handoff is
  never retroactively changed by this private correction.
- [ ] Source references and verification state remain context, not Planning approval, code authority, permission,
  or an invitation to import Pi sessions. A private Workspace bank cannot authorize cross-repository material.
- [ ] No live memory ingestion is activated until TICKET-00050's qualified safety-removal path is available;
  fixtures and controlled contract evidence are not mislabeled as operational safety proof.
