# Fast-forward and reconcile the designated checkout safely

## Outcome

An authorized human can preview and confirm an exact clean registered-default fast-forward through production APIs,
then inspect or reconcile the original update without overwriting unrelated work. Verified file/context effects use
existing currentness owners; the same narrow admission/delivery path later serves authorized scheduled updates.

## Scope

- In scope: Manual exact preview/confirmation, complete eligibility checks, shared custody/currentness composition,
  durable update intent, protected fast-forward delivery, verified outcomes and original-operation recovery.
- Out of scope: Remote-check implementation, schedule configuration/dispatch, browser UI, destructive recovery,
  branch switching, merge approval, arbitrary checkout selection, Pi reload, Agent continuation and Planning cutover.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Preview eligible update | N/A — current-authorized bounded observation | Exact registered source/default, local base/remote target, incoming commits and all predicates | N/A — no reservation | Complete plan or safe refusal; no implicit fetch |
| Confirm exact fast-forward | Explicit expected-state manual Sync | Current authority, plan, original operation and actual custody | Committed admission/audit/update intent | One admitted update, no external effect inside transaction |
| Deliver and verify update | Original admitted protected effect | Exact current base/target/ref/index/worktree and process evidence | Verified original fast-forward or partial/unknown fact | Only eligible clean default fast-forward |
| Reconcile or stop | Original-operation reconciliation or explicit stop | Actual effect/process/ownership and current authority | Confirmed outcome/stop/retained hold | No blind replay, rollback, destructive repair or false release |
