# Register and inspect stable repositories

## Outcome

An authorized user can register and inspect one stable Repository inside the initial durable Workspace through a versioned API; Agent OS generates typed COMB identities, PostgreSQL enforces active slug/source uniqueness transactionally, and registration creates no physical checkout, Planning or execution authority.

## Scope

- In scope: Initial Workspace identity/bootstrap under the accepted ADR; typed `WorkspaceId` and `RepositoryId`; Repository aggregate/current state, display name, Workspace-unique slug, active lifecycle baseline, optional primary and equivalent typed source descriptors, actor/timestamps/revision; internal ID generation; `RegisterRepository`/`RepositoryRegistered`; safe get/list/conflict-preview queries; PostgreSQL migrations/repository/concurrency; audit evidence; independent view/register permissions; versioned JSend API/OpenAPI/validation/error mapping; exceptional non-reserving COMB reference-generation operation accepted by WF-008.
- Out of scope: Host/Checkout/Worktree persistence, filesystem/Git observation, marker writes, checkout linking/designation/relinking, source changes after registration, archive/restore, UI, repository context, Planning records/migration, branch/remotes mutation, Runner/Workflow authority, new-project creation and multi-workspace tenancy.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Register a repository | `RegisterRepository` | Preview active slug/source conflicts | `RepositoryRegistered` | One generated Repository identity, metadata and audit evidence commit atomically in the initial Workspace |
| Inspect one registration | N/A — read-only interaction | `GetRepositoryRegistration` | N/A — reads emit no Domain event | Safe identity, metadata, lifecycle, sources and revision are returned without physical checkout claims |
| List visible repositories | N/A — read-only interaction | `ListRepositoryRegistrations` | N/A — reads emit no Domain event | Authorized registrations are returned in stable pagination/order without leaking hidden records |
| Generate an exceptional reference | Dedicated non-reserving ID-generation operation | N/A | N/A — generation does not create or reserve an aggregate | A valid typed-compatible COMB UUID is returned without granting creation or import authority |

## Validation and permissions

Generate normal Workspace/Repository IDs inside the owning operation; reject caller-selected IDs, timestamps, actors, revisions and lifecycle. Bootstrap exactly one explicit initial Workspace through a reviewed idempotent installation/migration path that does not infer identity from hostname, directory, slug or source. Preserve a future multi-workspace boundary without claiming membership/isolation not implemented here.

Validate display name and mutable Workspace-unique slug with a closed normalization policy, bounded lengths and reserved-name rejection. Model primary/equivalent sources through the accepted typed descriptors; validate provider/locator shape and explicit equivalence without network inference. Directory names and slugs do not establish source identity. Missing source is valid. Fork/upstream relationships are not equivalent unless explicitly represented by the accepted model.

Enforce one active Repository per approved source identity and unique active slug in PostgreSQL, with preflight for useful errors and named constraints as final authority. Register state, source descriptors, revision, actor/timestamps, `RepositoryRegistered` dispatch intent where required by the accepted event model, and audit evidence commit or roll back together through one transaction. Translate only known conflicts safely; competing requests cannot produce two active registrations.

Require authoritative server-side view and register permissions independently. Scope every command/query to the current authorized Workspace. HTTP uses one Action per interaction, explicit validated input, one command/query, safe Views, JSend, `snake_case`, centralized errors and OpenAPI. Do not expose persistence models, raw source credentials, arbitrary URLs, internal constraint/SQL details or hidden registrations.

The exceptional reference generator returns only a syntactically valid non-reserved COMB UUID for controlled manual/import preparation. It does not persist, reserve, authorize, predict another aggregate's ID, accept a requested timestamp, or bypass migration/import validation. Protect and rate-limit it according to the accepted API/security profile.

Registration alone creates no Host, Checkout, Worktree, marker, directory, file, branch, Git mutation, planning mode, context snapshot, Planning record, Agent, Workflow, commit/push/PR authority or Dashboard designation.

## Acceptance criteria

- [ ] One durable initial Workspace has an internally generated stable typed identity and no false multi-workspace claim.
- [ ] `RegisterRepository` generates Repository identity internally and atomically records validated metadata, source descriptors, revision, actor/timestamps, event effect and audit evidence.
- [ ] Active slug and approved source identities are unique per Workspace under normal and competing requests, with known safe conflicts and no partial registration.
- [ ] Source-less, primary-source and explicit equivalent-source registration follow the accepted typed normalization/equivalence model without directory-name or network inference.
- [ ] Get/list/preview queries use safe explicit Views, stable ordering/pagination and Workspace/permission filtering.
- [ ] Versioned JSend API and OpenAPI contracts enforce one-interaction Actions, validation, safe errors and explicit `snake_case` mapping.
- [ ] View and register permissions are independently enforced from authoritative server state; unknown/stale scope fails closed.
- [ ] Exceptional COMB generation persists/reserves nothing and grants no registration/import authority.
- [ ] Registration performs no filesystem/Git/checkout, Planning, context, execution or publication side effect.
- [ ] Focused Domain/Application/PostgreSQL/concurrency/API/redaction tests and the canonical build pass with fresh evidence.
