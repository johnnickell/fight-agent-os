# Enforce database-only Planning consumers

## Outcome

After cutover, every Agent OS Planning mutation and browser/terminal/agent-facing read uses database authority exclusively, tracked source Markdown remains unchanged and visible, and deterministic read-only Markdown representations cannot become a second writer or silent offline fallback.

## Scope

- In scope: Central planning-authority guard applied to all TICKET-00026/27 mutations/queries and migration mode transitions; first database-write recovery fence closure; refusal of Markdown-authoritative application updates after cutover and database mutations before cutover; explicit unavailable/stale/offline behavior; mode-aware read-only terminal/canonical `next` consumer transition to TASK-00096/97; deterministic rendered Markdown for aggregates plus Roadmap/Board/index Views using TICKET-00093/97 with authority/revision/template provenance; permission-filtered `text/markdown` API/download/terminal contracts; source-freeze integrity diagnostics; no-ingestion/no-sync boundaries; safe errors/OpenAPI and direct source observations.
- Out of scope: Preventing ordinary OS users/tools from editing files, automatically reverting Git changes, deleting/archiving/retiring source, creating/pushing retirement branch/PR, reverse migration, dual-write/synchronization, browser React UI, Pi/MCP transport beyond existing skill/terminal handoff and backup implementation.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Mutate Planning in current mode | Existing TICKET-00026/27 semantic command | Revalidate live Repository mode/context and first-write fence | Existing owning event only on valid database mutation | Before cutover database mutation fails; after cutover valid database mutation commits and closes pre-first-write recovery |
| Ask for next work | N/A — read-only canonical interaction | Dispatch TASK-00096/97 for database mode or current Markdown router before cutover | N/A — reads emit no event | Post-cutover terminal/agent result uses canonical database eligibility without Board parsing or duplicate rules |
| Render current Markdown | N/A — deterministic representation query | Render typed aggregate/Roadmap/Board/index Views with exact revision/authority/template metadata | N/A — rendering emits no event | Permission-filtered copy/download text is returned without writing source or becoming mutation input |
| Detect source drift/unavailability | N/A — integrity/availability query | Compare frozen source manifest/Git evidence and service/context currentness | N/A — reads emit no event | Visible warning/stale state appears; no automatic source repair, database rollback or fallback occurs |

## Validation and permissions

One central application authority policy reads live Repository Planning mode and current context for every authoritative Planning command/query. Registered/Markdown mode refuses database aggregate/order commands except migration rehearsal/cutover contracts. Registered/database mode permits authorized semantic database commands and refuses every application path that would ingest/patch/generate/synchronize authoritative repository Markdown. Missing/unknown/unavailable mode fails closed.

The first successful post-cutover database Planning mutation atomically records/closes TASK-00102's recovery fence in the same transaction. Retries do not create ambiguity. No adapter, console command, browser endpoint or skill may bypass this guard by writing projections/SQL/files. Local filesystem edits made outside Agent OS are visible integrity drift but do not become authority; state this honestly rather than claiming OS sandbox control.

Before cutover, the existing Markdown `next` skill remains the repository authority. After database mode, its application/terminal route calls TASK-00096/97 with explicit authenticated actor/repository/context and does not read Board/record Markdown for TASK selection. If unavailable or stale, report no authoritative result and recovery guidance; never silently fall back to cached/database exports or original Markdown. Preserve Wayfinder routing only where its database capability exists; do not invent a mixed authority.

Render aggregate Markdown through TICKET-00093 and Roadmap/Board/index representations from TICKET-00097 typed Views. Include database-authority label, aggregate/view revisions, observation/context revision and template version. Apply authorization/redaction before rendering. Render output is read-only: no ordinary mutation accepts complete Markdown, renderer writes no Git/database state, and no automatic checkout synchronization/export occurs. Original tracked files remain unchanged and available during stabilization.

Require normal Planning command/query Permissions plus explicit render/download authority where needed. Source integrity diagnostics expose relative classifications/digests, not content/absolute paths/secrets. Service loss and context drift follow TASK-00084: cached projections are stale/read-only, controlled mutations stop, and reconnection creates current context rather than refreshing silently.
