# Guard user disable and enable transitions

## Outcome

An authorized operator can deliberately disable or enable one eligible user through package lifecycle commands, with immediate session/authority effects and safe audit.

## Scope

- In scope: `POST /api/v1/users/{userId}/disable` and `/enable` FQCN Actions, `DISABLE_USERS`/`ENABLE_USERS`, Agent OS Application target/actor/last-admin safeguards, confirmation/revision, package `DisableUser`/`EnableUser`, safe responses/OpenAPI, audit and principal invalidation.
- Out of scope: General `UPDATE_USERS`, email edit, delete/restore, raw password/session mutation, broad web admin interface and bypassing package lifecycle invariants.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Disable user | `DisableUser` through checked Application service | Resolve actor/target/current managed authority | Package user event plus safe audit | Eligible target becomes disabled; established authority fails closed |
| Enable user | `EnableUser` through checked Application service | Same | Package user event plus safe audit | Eligible target becomes enabled without minting a new session |

## Validation and permissions

Route attributes are an early gate; the service enforces exact respective installation-wide `SUPER_ADMIN_ONLY` permission for every caller, bounded ID/confirmation/revision and target state. Reject self-lockout, removal of the last effective Super Admin, stale/conflicting transitions and managed-policy drift before invoking the package; reconcile raced writes transactionally. Do not trust role name or JWT for authorization. Keep failures non-enumerating for unauthorized actors and logs/audit free of secrets. v0.4.0's possible removal of handler permission checks changes neither service enforcement nor package lifecycle rules.

## Acceptance criteria

- [ ] Each transition uses only its own permission; anonymous/forbidden/stale actors dispatch no package command.
- [ ] Self/last-admin/raced/conflicting/invalid state cannot remove the final authorized administrator or create partial state.
- [ ] Package lifecycle and resulting session invalidation are observed in PostgreSQL; audit is durable and secret-safe.
- [ ] Actions/Views/OpenAPI are exact and route/target IDs cannot override actor; focused concurrency/HTTP/application checks and `./bin/build` pass.

## Verification and evidence

Exercise target lifecycle/state, two administrators versus last administrator, self target, concurrent disable/enable, session/JWT failure after disable, permission change between requests and redaction. Run focused PostgreSQL/HTTP/security checks, `./bin/planning-check`, `git diff --check` and `./bin/build`; record counts, audit and warnings.
