# Capture and recover enrolled operational sources

## Outcome

Application, deployed supporting-service and managed-run/check output enters recoverable bounded collection with
trusted source attribution and honest gaps across restart, rotation and retirement. This is approved slice D of
[TICKET-00112](../tickets/00112-TICKET.md), not arbitrary project/runtime discovery.

## Scope

- In scope: Actual installation enrollment and short-lived source registration, supported native reader/driver,
  reversible bounded framing, generation/stream/position persistence, fair scheduling, replay and retirement handoff
  integrated with TASK-00457's queues and TASK-00456's independent status.
- Out of scope: Registered-project runtime logs, browser JavaScript errors, transcripts/prompts/hidden reasoning,
  direct Docker private-file scraping, a new executor/telemetry protocol, search/archive services and evidence release.

Apply [WF-038](../wayfinder/tickets/WF-038-define-log-collection-and-failure-recovery.md). Enroll only actual Agent OS
sources through their existing installation/runtime owner; labels and project IDs are not authorization. Include
all accepted channels/levels, not only errors. Absent or unqualified sources remain explicitly not enrolled/unavailable.
Use lifecycle registration for short-lived sources and 30-second discovery only as reconciliation.

Qualify supported driver/API and reader behavior together. Runtime retention targets 100 MiB/source with measured
overshoot/overhead and aggregate inventory accounting; local capture/rotation cannot depend on remote destinations.
Isolate any approved privileged reader from PHP, browser, Agents and ordinary delivery sinks. No log capability
allows exec, attach/stdin, arbitrary filesystem/archive reads, environment inspection or runtime mutation.

Persist trusted source generation, stream and supported positions with pending/settled dispositions. Advance a
checkpoint only when covered bytes are recoverable from qualified persistent state or durably settled; qualify
crash-safe ordering or overlap. Timestamp cursors are not byte offsets. Preserve legitimate equal messages/ties,
late data and replay uncertainty rather than content/time deduplication. Keep original collection time distinct from
emitted time/precision; untrusted parsed fields cannot overwrite source provenance. TTY-merged streams remain merged.

Enforce at most 16 source reads with fair leases no longer than 30 seconds within the aggregate collection CPU/RAM
budget. Use native partial framing: raw pieces <=64 KiB, assembly <=1 MiB/5 seconds, then reversible continuations
with explicit incomplete assembly rather than truncating a suffix. Preserve exact captured non-UTF-8/malformed bytes,
not replacement-character loss. An event exceeding total retained capacity cannot be promised complete.

On restart, rotation, missing checkpoint, deleted source or corrupt spool, recover surviving coverage and expose
known/potential gaps. Retirement attempts collection handoff within 30 seconds without indefinite business waits;
that timer never deletes protected sole copies or satisfies Workflow/evidence release. Existing owners retain
mandatory material and their failure semantics. Shutdown is bounded to 30 seconds with recoverable pending work.

| Use case | Commands | Queries | Events | Expected side effects |

| Enroll a real accepted source | Explicit existing installation/runtime enrollment | Trusted source generation, service/process identity and read authority | Source lifecycle observation, not Workflow completion | Only permitted source streams are captured; exclusions remain excluded |
| Capture framed output | Enrolled native reader and bounded queue admission | Actual bytes/stream/position and qualified durable disposition | Capture/persistence observations | Recoverable original bytes/provenance without premature checkpoint progress |
| Resume surviving coverage | Native checkpoint/queue reconciliation | Surviving generations/positions and settled loss | Replay or gap fact | Original identities/times preserved; no fictitious exactly-once delivery |
| Retire a short-lived source | Existing bounded retirement/handoff operation | Pending capture, preserved references and actual surviving coverage | Handoff/gap observation | Bounded progress without deleting protected evidence or inventing complete capture |

## Validation and permissions

Only the existing installation owner enrolls sources or alters credentials; automatic reads/replay stay within
that capability. Reader isolation and any required daemon exposure must already be explicitly accepted under
TASK-00455; filters/read-only socket mounts alone do not qualify it. Private transport crossing hosts requires
authentication and encryption without insecure fallback. Keep runtime state under ignored `var/`, not `.runs/`.
Use current preservation participants for retirement; source/checkpoint metadata is not a hold-release grant.

## Acceptance criteria

- [ ] Actual enrolled application/service/managed sources and accepted level families are captured through the
  qualified supported reader/driver, with lifecycle registration, explicit absences and denied cross-source access.
- [ ] Checkpoint/persistence restart boundaries, rotation, source reuse/deletion and corrupt/missing state recover
  retained coverage or expose precise known uncertainty, never checkpoint-ahead silent gaps.
- [ ] Malformed/binary/large/incomplete frames preserve exact captured bytes/provenance within real CPU/RAM/storage
  bounds; ties, legitimate repeats, event/collection clocks and merged streams retain honest meaning.
- [ ] More enrolled sources than read slots receive fair service; discovery, leases, shutdown and retirement are
  bounded without weakening holds, mandatory evidence or the existing runtime outcome.
- [ ] Real source/queue/status integration and direct runtime/framing/recovery checks pass with full `./bin/build`;
  controlled fixtures alone cannot certify an unavailable managed-runtime lifecycle binding.

## Verification and evidence

Use manifested non-sensitive sources covering actual Monolog level codes, exceptions, identical legitimate records,
same-time ties, malformed/non-UTF-8/large continuations and short-lived managed output. Compare original captured
bytes and identities, counts and gaps through restart/rotation/retirement. Qualify native driver, privileges, physical
limits and scheduling with owning tools, not product tests of config, Docker internals or wrappers. Test owned
enrollment/attribution/checkpoint/retirement contracts and important integration races, preserving evidence owners.
Use separately authorized bounded runtime targets; record versions, resource peaks, measured retention coverage,
warnings and unknown capture intervals. Run focused repository checks and `./bin/build` without claiming host-loss
survival or one-second RPO from configured flush cadence.
