# Deliver the responsive authoritative application frame

## Outcome

The accepted production application frame routes public and protected journeys from restored authentication and current authority, provides responsive permission-aware navigation and current-user controls, restores only safe intended destinations, and presents accessible unknown/loading/`401`/`403`/expired/not-found/system states without exposing protected content or claiming client enforcement.

## Scope

- In scope: Public/protected/root layout composition; root decision flow; complete route metadata and exact shared permission guards; responsive header/navigation/current-user/theme/logout controls; bounded intended-route integration; loading/restoration/anonymous/forbidden/expired/not-found/system-error pages; focus/announcement/navigation behavior; stable truthful account-security/session/administration landing route seams for later journeys; direct-load/history behavior; production Storybook/component/accessibility/browser-smoke evidence.
- Out of scope: Dashboard content beyond route destination, password/session/user/invitation operations owned by later TICKETs, fabricated placeholder records/actions, new authorization source, server-side SPA-navigation security claims, workspace switcher, planning/observability data, broad browser automation, and role-name authorization.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Enter application root | N/A — navigation | Read authentication-restoration and current-principal cache state | Client navigation signal | Anonymous reaches Login; authorized authenticated user reaches Dashboard; denied user reaches forbidden state |
| Enter protected route | N/A — navigation | Evaluate complete route permission metadata through shared exact evaluator | Client navigation signal | Unknown/stale is withheld; allowed route renders; authenticated denial renders `403` |
| Restore intended route | N/A — post-auth navigation | Read one validated transient same-application destination | Client navigation signal | Safe route restores once; unsafe/denied route falls back without loop or secret retention |
| Navigate application frame | Logout is TASK-00047 API; other controls are navigation | Read safe current principal and registered routes | Client UI/navigation signals | Responsive navigation exposes current-user/account/admin controls only under exact presentation policy |

## Validation and permissions

Compose one route manifest with public/protected classification, exact required permission names, title/navigation metadata, and registered destination. Every complete protected route is guarded before page rendering through TASK-00028's shared evaluator and TASK-00049's sole principal cache. Unknown/loading/stale/malformed authority fails closed. Role names can be displayed where accepted but never grant routes or components. Client guards improve usability only; protected API Actions retain exact server checks.

For `/`, complete TASK-00048 restoration first. Anonymous routes to Login. Authenticated authority with `VIEW_DASHBOARD` routes to Dashboard; authenticated authority lacking it receives the shared `403` rather than being treated as anonymous. Bound restoration attempts and redirects to prevent loops. Direct load, refresh, browser history, and logout converge to the same state model.

Reuse TASK-00046's bounded same-origin intended-route representation. Reject external schemes/hosts, protocol-relative values, control characters, oversized values, malformed encoding, credential-like parameters, secret form state, arbitrary serialized data, and destinations the resolved principal cannot enter. Consume it once after successful authority load; terminal/logout clears it.

Recreate accepted shell structure with semantic landmarks, skip navigation, responsive primary/account navigation, current canonical email presentation, theme selector, and logout/current-security controls. Menus/dialogs/drawers support keyboard/focus escape/return, visible unobscured focus, target/reflow, status announcement, reduced motion, and narrow/wide interaction. Avoid hover-only controls.

Provide stable registered landing destinations/seams for Account/Security, Active Sessions, Users, and Invitation Administration needed by shell navigation and later TICKETs. Before their operations exist, destinations must state availability truthfully, render no fake data or enabled unavailable action, and preserve exact future route permissions. Do not duplicate later feature state. Links must never be dead.

Distinguish authentication restoration/expired `401` from authenticated `403`; provide bounded recovery actions. Not-found and system errors reveal no protected route data, stack, request internals, or credentials. Error boundaries cannot silently authorize or loop.
