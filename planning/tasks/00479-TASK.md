# Download verified archives through the native authorized catalog

## Outcome

An authorized operator selects and downloads exact verified archive objects through native Logs without needing
restore permission or obtaining arbitrary private-storage access. This approved slice B of
[TICKET-00116](../tickets/00116-TICKET.md) delivers the real catalog-to-file journey, independent of live export and
completed restore UI.

## Scope

- In scope: Native bounded download-catalog selection, protected exact object/version resolution, format/provenance
  information, bounded transfer/completion/integrity checks, current disclosure participation and accessible private
  browser save/result behavior.
- Out of scope: Restore/import, raw bucket/file browser, arbitrary keys/paths/URLs, public redirects/sharing, a giant
  aggregate object, permanent download-copy store, server spool, persistent read job or automatic transfer replay.

Use TASK-00470's download-purpose catalog with TASK-00468's verified immutable identities/digests and TASK-00467's
current disclosure/lifecycle fences. Revalidate exact eligible catalog ownership/version at fetch and release; an old
catalog result or object ID grants nothing. Deliver original archive bytes with their applicable format/provenance
information, not Loki chunks, reserialized records or an unverified replacement under the old identity. The catalog's
historical verification does not prove this transfer's bytes or completion. Missing/corrupt/restricted/changed source
state must not become successful empty output or an unnoticed substitute object.

Apply [WF-041](../wayfinder/tickets/WF-041-select-the-authorized-log-browser-integration.md) and the accepted
[TICKET-00116 transfer bounds](../tickets/00116-TICKET.md#approved-task-decomposition-and-current-handoff): <=16 MiB
compressed selected objects per explicit request, <=30 seconds, typed requests <=16 KiB. Necessary catalog reads
retain <=500 entries/1-MiB pages and their 30-second bound. Downloads now explicitly share TASK-00463's existing two
installation-wide read/export slots, one/requester; there is no extra download pool or unbounded queue. Enforce actual
byte/time/admission accounting across workers, including abandoned work until completion/cancellation is confirmed.

Offer individual catalog objects when a larger selection exceeds limits. Reject known excess with actionable narrower
selection; enforce actual bounds for uncertain size. Do not automatically fan out repeated requests, create a stored
aggregate or pin primary archives indefinitely. Current expiry/purge/deletion races deny or truthfully interrupt
transfer; downloading neither changes primary retention nor creates a new hold. Any source-read lifecycle participation
must use the existing bounded owner contract, not an invented preservation authority.

Use <=64-KiB authorization-checked output batches and <=1-MiB queued output per transfer. Revalidate actual current
actor/session/capability and exact source disclosure before fetch, release and every batch; unknown withholds bytes.
Join TASK-00467's early restrictions before exposure, tracking actual transient output/cache participation for
TASK-00472. Corrupt/partial/limited transfers never claim complete verified objects. Establish completion against exact
expected bytes/digests and declared selection using a qualified bounded integrity/completion path; HTTP success or EOF
alone is insufficient. Already released/in-flight bytes and operator files cannot be recalled or counted as remotely
purged. Do not add prohibited content to audit/status to describe removal.

Use same-origin authenticated browser delivery without storage credentials or unqualified redirect URLs. Account for
browser save buffers/copies, worker/proxy/socket/provider resources and metadata overhead, not only compressed payload
size. No unbounded Blob accumulation or hidden browser cache. Credential refresh/logout/expiry, identity/scope change
and cancellation retire volatile state; late successes and errors are generation-fenced. No automatic resume/replay.
Provide actual keyboard/focus, bounded announcements, clear selection/limits/partial results and usable zoom/narrow/
light-dark controls in the existing shell. Archive-download navigation cannot acquire a restore capability requirement.

| Download selected exact objects | Explicit user extraction; no business job | Current ownership/version/disclosure and actual bytes | Existing required safe access/audit only; no Workflow event | Bounded private original archive output with integrity/completion evidence |

## Validation and permissions

Require `READ_LOGS` + `DOWNLOAD_LOG_ARCHIVES` for the operation and necessary catalog; neither READ_LOGS alone nor
RESTORE_LOG_ARCHIVES/EXPORT_LOGS substitutes. No Role-name bypass, storage/hold/purge grant or authority from guessed
IDs. Follow ADRs [0001](../adr/0001-application-ownership-and-orchestration.md),
[0002](../adr/0002-postgresql-consistency-and-durable-effects.md),
[0003](../adr/0003-browser-authentication-security-profile.md) and
[0004](../adr/0004-client-authority-and-runtime-state.md): application policy, canonical required transactions without
transfer inside them, same-origin Bearer/applicable CSRF, no-store and volatile generation fences. Use safe filenames/
media types and inert presentation. Keep private selections/content/credentials out of URLs/history/referrers/telemetry/
logged payloads. Denied references reveal no hidden existence/counts; existing evidence downloads remain separate.

## Acceptance criteria

- [ ] Actual native catalog selection/download works with READ_LOGS + DOWNLOAD_LOG_ARCHIVES and no restore permission;
  forged/cross-purpose keys, paths, tenants and stale catalog references cannot expose unauthorized objects.
- [ ] Exact verified archive versions and applicable provenance reach the bounded save path; actual corruption,
  truncation, source replacement/deletion and unknown integrity cannot be labelled complete verified downloads.
- [ ] Fresh current checks and owner fences hold before fetch and each batch despite permission/session/purge/expiry
  races; unknown denies, with honest limits for already released/in-flight/operator bytes.
- [ ] Aggregate shared admission, 16-MiB compressed selection, 30-second deadline, batch/queue/resource limits and
  cancellation accounting hold under slow clients and outages without hidden spool, fanout, new holds or job store.
- [ ] Accessible real controls, volatile-state/late-result protection, owned behavior/integration tests, direct
  transfer/proxy/resource qualification and full `./bin/build` pass with warnings and incomplete evidence disclosed.

## Verification and evidence

mismatch, mid-transfer policy changes, actual size/deadline edges and individual-object narrowing. Test PostgreSQL

and actual remaining resource use. Qualify infrastructure directly rather than product-testing configuration,
migrations, wrappers or vendor internals. Run focused repository wrappers and full `./bin/build`; use separately
authorized safe targets for transfer/fault qualification and record unsupported mechanisms, warnings and residuals.
