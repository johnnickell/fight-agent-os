# Publish and restrict the representative OpenAPI contract

## Outcome

A validated OpenAPI contract documents the representative `/api/v1` success and failure boundary, snake_case/JSend schemas, and accepted Bearer/browser-security semantics, while Swagger UI and production diagnostics are explicitly restricted and CORS remains deny-by-default.

## Scope

- In scope: OpenAPI format/tool selection; repository-owned specification; `/api/v1` conventions; representative request/success/fail/error schemas; validation fields; known and unknown failure responses; Bearer security scheme and refresh-cookie description constrained by the accepted ADR; deterministic validation/drift checks; OpenAPI serving decision; Swagger UI environment/authorization restriction; production diagnostic/CORS defaults.
- Out of scope: Authentication/invitation/account endpoint contracts, generating product handlers, public documentation hosting, general CORS approval, browser automation, credentials in examples, and documenting deferred APIs as implemented.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Validate API specification | N/A — tooling | Parse and validate OpenAPI operation/schema references | N/A — no domain event | Invalid or stale representative contract fails deterministically |
| Inspect representative contract | N/A — documentation read | Inspect request, success, validation, known, and generic error schemas | N/A — no domain event | Consumers see truthful versioned JSend/snake_case behavior |
| Inspect documentation UI | N/A — environment-restricted UI | Verify environment and any authorization guard | N/A — no domain event | Swagger UI is unavailable by default in production and cannot disclose internals |
| Interpret browser security | N/A — security documentation | Read Bearer and opaque-cookie semantics from accepted ADR | N/A — no domain event | Contract never suggests JavaScript-readable refresh credentials or persisted access tokens |

## Validation and permissions

The specification must describe only implemented representative behavior. Include exact JSON content types, JSend success/fail/error envelope schemas, dotted validation message lists, safe known responses, generic correlated 500 response, and snake_case fields. Examples must be synthetic and secret-free.

Bearer security describes access-token transport only. Refresh credentials are opaque HttpOnly cookies and must not appear as bearer/header/body/example values or as JavaScript-readable state. Document request-protection expectations only to the level accepted by TASK-00017; do not invent authentication operations.

OpenAPI validation and representative drift checks are deterministic and non-networked after dependencies install. Swagger UI is disabled by default in production and, where enabled, limited by explicit environment and authorization/access policy. Raw route/configuration/stack/environment/secret data must not become diagnostics. CORS stays absent/deny-by-default until an approved client origin requires it.

No runtime product permission is introduced. Documentation/tooling and restricted optional UI are authorized; public production exposure is not.

## Acceptance criteria

- [ ] A repository-owned OpenAPI document validates deterministically with pinned tooling.
- [ ] The specification truthfully describes `/api/v1`, JSON-only behavior, representative request/success, validation fail, known failure, route failure, and generic error contracts.
- [ ] JSend envelopes, dotted message lists, correlation exposure, statuses, and snake_case fields match functional behavior.
- [ ] Security schemes distinguish memory-only Bearer access tokens from opaque HttpOnly refresh cookies and include no readable credential examples.
- [ ] The document does not claim unimplemented authentication, invitation, persistence, or product operations.
- [ ] Representative drift checks detect meaningful operation/schema mismatch without testing prose or Markdown wording.
- [ ] Swagger UI is off by default in production and has explicit environment/access restrictions where enabled.
- [ ] OpenAPI/UI/diagnostic routes expose no secrets, stack traces, environment dump, internal paths, or unrestricted route metadata.
- [ ] CORS remains disabled/deny-by-default without an approved origin contract.
- [ ] Focused OpenAPI/HTTP checks and `./bin/build` pass with fresh evidence.
