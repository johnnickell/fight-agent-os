# Resume and explicitly continue real sessions

## Outcome

Real participating sessions retain their exact snapshots through reconnect/recovery and require an explicit
currently authorized linked continuation after material change. Original history, pending input/proposals and
uncertain effects survive without silent refresh, duplicate work or invented model identity.

## Scope

- In scope: Actual snapshot/session activation and reconnect integration, safe continuation preview/expected-state
  execution, old/new snapshot lineage and retained-history applicability, separately attributed runtime provenance.
- Out of scope: New launcher/session/transcript engine, credential or provider lifecycle, role resolver, Workflow
  grants, proposal publication, generic terminal switching UI, browser Planning journey and database cutover.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Activate/reattach exact binding | Existing owning session admission/reconnect operations | Original snapshots, trusted host/session identity, current authority and actual loader selections | Existing owning activation/attachment facts | Actual session uses the exact binding; reconnect does not allocate another Agent or grant |
| Preview material change | N/A — authorized read | Exact old/new inputs, drift, current authority and original pending effects | N/A | Safe concise changes/consequences; no active-state mutation |
| Explicitly continue | Owning expected-state linked-continuation operation with original request identity | Current exact selections, prior lineage, live scope and reconciled effect state | Committed owning continuation/binding facts | New linked immutable snapshot/session; prior history remains intact |
| Attribute runtime identity | Trusted owning runtime observation, never a configuration rewrite | Exact attempt/provider response identity where actually reported | Safe attributed runtime evidence at its owner | Requested settings remain distinct from observed or unavailable facts |

- [ ] Actual qualified sessions load the exact retained binding and survive unchanged reconnect/process recovery
  without another Agent, grant, snapshot or acceptance ceremony; selected versus reported identity stays distinct.
- [ ] Material changes require explicit current authorization and one linked successor with new exact snapshots;
  old bytes, history and pending input/proposal references survive and applicability is revalidated.
- [ ] Real revocation, unavailable authority, stale selection and unsupported host/provider routes hold before new
  protected use, with no local fallback or snapshot mutation.
- [ ] Concurrent/interrupted continuation, lost acknowledgement and stale runtime completion preserve original
  outcomes without duplicate successor execution, uncertain-effect replay or fabricated zero billing.
- [ ] Safe authorized inspection explains current/held/continued states and exact lineage without disclosing
  credentials or private content; actual in-flight limitations are recorded honestly.
