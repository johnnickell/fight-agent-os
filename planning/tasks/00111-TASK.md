# Operate the canonical Roadmap and work queue

## Outcome

Authorized users can browse responsive Roadmap, hierarchy-progress and canonical work-queue views, understand every eligibility/priority reason, and issue supported Roadmap/TASK reorder or queue-override commands whose visual result becomes authoritative only after server confirmation.

## Scope

- In scope: Repository/workspace Roadmap pages; EPIC/TICKET hierarchy progress; canonical included/excluded TASK queue and one-TASK explanation; direct/transitive dependency impact; current/archive filters; derived Ready/In Progress/Blocked/Human Action/In Review/Complete lanes; Roadmap reorder, TASK sequence, set/clear override previews/commands; keyboard-accessible reorder alternative and pointer interaction; provisional drag state/rollback; expected ordering revisions; filters/pagination/URL state; typed API services/mappers; permission-aware scope; responsive components/catalog/states.
- Out of scope: Client eligibility/priority algorithm, persisted lanes/Blocked/Hold, generic drag-to-status, coordinated-work start/claim/agent profile/Runner, provider polling, Planning lifecycle mutation, browser conversations, Markdown Board parsing and migration parity logic.

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Browse Roadmap/progress | N/A — read-only interaction | Get TASK-00097 Roadmap/hierarchy View with revisions | N/A — reads emit no event | Ordered hierarchy/progress displays from canonical server projection |
| Browse/explain queue | N/A — read-only interaction | `FindExecutableTasks` / `ExplainTaskEligibility` via TASK-00097 View | N/A — reads emit no event | Same ordered candidates/reasons as terminal/application consumers display |

## Validation and permissions

Render candidate ordering, eligibility, exclusion reason codes/explanations and priority provenance directly from TICKET-00027 Views. Frontend filters/presentation must not remove required checks or recalculate executability. Blocked work retains priority but remains excluded. Won't Fix does not satisfy blockers. Hidden blockers/parents remain safely explained without identifiers.

Roadmap/TASK reorder and queue override require server preview, exact ordering revisions and scope-aware Permissions. Pointer drag or keyboard move creates only a local provisional arrangement and concise pending state; send one intent-specific command. On success refetch/render server order. On cancel/denial/stale/conflict/network uncertainty return to authoritative state with announcement/reason; never persist local order or simulate accepted success.

Derived lanes are read-only presentation. No manual drop into Blocked/Human Action/In Review/Complete and no generic status mutation. In Review/Complete may combine trusted typed observations but never append TASK completion or infer Planning status from GitHub. Ready-to-In Progress coordinated work/claim interaction is excluded until later WF-015/016 EPICs; show unavailable reason rather than fake start.

Support repository and authorized workspace scope, deterministic filters/pages and URL state. Cross-repository Roadmap reorder controls appear only with workspace authority. Explicit override distinguishes inherited Roadmap/authored TASK priority. Current/archive modes remain separate.

Provide loading/empty/no executable work/denied/stale ordering/partial explanation/unavailable context/service/offline read-only and long dependency states. Reorder has keyboard controls, clear labels/instructions, focus restoration and status announcements; narrow layout may use ordered list/cards rather than inaccessible horizontal drag.
