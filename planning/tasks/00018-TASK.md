# Establish the versioned JSend API interaction boundary

## Outcome

Agent OS has an explicit `/api/v1` JSON composition boundary proven by the ADR 0003 CSRF bootstrap: one final FQCN Action dispatches the genuine application `GetCsrfProof` query and delegates cookie and JSend output to an endpoint-specific Responder. No demonstration endpoint or fake access-control query is added.

## Scope

- In scope: Versioned API group; final FQCN single-interaction Action and CQRS dispatch; `GET /api/v1/auth/csrf` as an explicit public/JWT-exempt security bootstrap; Action extraction/validation of the nonce from the HTTP request cookie into transport-free query input; application `GetCsrfProof` query/handler with injected nonce generator, clock and independent MAC signer; idempotent reuse or generation of a high-entropy nonce; endpoint-specific Responder setting the ADR 0003 HttpOnly CSRF cookie when needed and `no-store` JSend proof; explicit safe View and snake_case mapping; same-origin Fetch Metadata/HTTPS restrictions and CORS denial; replacement of incompatible inherited response assumptions.
- Out of scope: Login/refresh/logout, access-token issuance or authentication, protected profile/permission queries, server-side CSRF persistence, mutation endpoint composition, invitation/account endpoints, general product policy, validation middleware, centralized exception mapping, OpenAPI publication (TASK-00021), entity serialization and speculative generic abstractions.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Bootstrap CSRF protection | N/A — server business state is unchanged | Action extracts the nonce; application `GetCsrfProof` accepts only a transport-free optional nonce value, reuses it if valid or generates a new one and signs a short-lived proof | N/A — no domain event | Responder sets only the approved HttpOnly nonce cookie if needed and returns a no-store JSend proof for memory-only client use |
| Compose versioned route | N/A — route setup | Dispatch the query through the injected bus and inspect matched FQCN Action | N/A — no domain event | `/api/v1` resolves dependencies without service-location from business code; other API-v1 operations remain JWT-required by default |

## Validation and permissions

The first interaction is the accepted ADR 0003 CSRF bootstrap, not a generic public access-control read. The Action alone reads HTTP request/cookie metadata and passes only a validated, transport-free optional nonce value to the query. The handler must not know PSR-7 requests, cookie names, headers, paths or response attributes; it returns proof, expiry, nonce and whether the nonce is new. The HTTP Responder owns `Set-Cookie` and `Cache-Control: no-store`. The nonce lives only in a host-only `__Secure-`, Secure, HttpOnly, SameSite=Strict, browser-session cookie scoped to `/api/v1/auth`, not in a database. A separate strong external MAC key authenticates nonce, configured origin and expiry (at most fifteen minutes); the client holds the proof only in memory. Provide a transport-free verifier for nonce/proof/deadline/MAC with constant-time comparison and validate key strength/configuration, but do not claim that bootstrap alone protects mutation endpoints. TASK-00043 applies the shared verifier to activation as appropriate; TASK-00045 composes exact proof-header/cookie verification with login/refresh/logout Origin/Fetch/JSON guards and login/logout rotation/deletion before dispatch. Bootstrap enforces HTTPS and same-origin Fetch Metadata without requiring mutation Origin, has no credentialed CORS, and cannot expose refresh/session authority.

Actions are final, map transport input, dispatch exactly one command/query/explicit orchestrator, and contain no business, persistence, authorization, or response policy. Endpoint-specific Responders own successful representations. Explicit Views/response models contain only approved fields; package entities, credentials, grants, hashes, internal exceptions, and arbitrary objects cannot be serialized directly.

PHP properties remain camelCase; explicit boundary mapping emits snake_case. API output uses JSON and JSend consistently with deterministic status/content type/body. Unsupported non-JSON assumptions fail safely without enabling CORS.

Only the explicit bootstrap is JWT-exempt. All other `/api/v1` routes require authenticated authority by default once the TASK-00117 route-attribute/JWT boundary is delivered; absent middleware before then must never make a protected route public. No end-user permission is needed for bootstrap. Route/method misses and non-API routes cannot turn into authentication bypasses.
