# Persist correlated issuance and credential retirement

## Outcome

Persist original Agent credential operations and safely couple Agent issuance, rotation and retirement to their
exact retained operation, reservation and audit state on one PostgreSQL transaction. Supply coherent safe status
without pretending storage-only success qualifies a live credential lifecycle.

## Scope

- In scope: Required schema/adapters/hydration; exact scoped keys, canonical request/marker, original issuance,
  immutable destination binding, Agent credential/Permission revisions, global delivery identities, stable-slot
  reservations, capacity, protected-copy storage, permanent correlation/tombstones and safe authoritative status.
  Couple Agent replacement/retirement and preserve name-only and direct-Permission writer invariants.
- Out of scope: Cipher/key generation, external sink calls, scheduler, UI, legacy backfill, new authorization policy,
  live issuance exposure and delivery/maintenance transition/query completion owned by TASK-00230.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Persist provision or rotation | Existing package services and direct repositories under the shared transaction | Original retained key/request, current authority, reservation and capacity | Package facts only after confirmed commit, no renamed owned event | Agent, original operation, reservation, protected copy and required audit commit or roll back together |
| Retire predecessor | Package lifecycle/Agent replacement with original-operation cancellation | Exact Agent/credential/revision correlation, including material-free operations | Existing package retirement facts under their original publication semantics | Original pending/claimed/admitted delivery invalidated and copy removed atomically |
| Inspect retained result | Existing operation/status repository queries under owning read authorization | One coherent authoritative original issuance and current disposition | N/A — reads have no mutation/audit/event | Safe status including tombstones and unknown markers; absence is not rollback proof |

## Validation and permissions

Every direct write uses TASK-00228's cohort-first guard on the exact package Unit of Work connection; unsupported
composition stays unavailable. Package Domain transitions own successors; repositories enforce full expected-state,
exact revisions, current references and atomic uniqueness. Preserve current contract revision starting values and
unknown canonical markers; reconstruct only through supported APIs, without reflection writes or lossy defaults.

Scoped-key collision is distinct from global delivery/credential collision and storage failure. Roll back loser
writes before original-key resolution; no callback retry, tombstone eviction or new key on uncertain commit.
Destination order spans all scopes/Agents/binding revisions and cannot reset on reassignment. Capacity applies
to genuinely new issuance, never retained-key status/recovery; failed successor admission restores the predecessor.
Retirement needs exact original correlation even after material removal and must fail on ambiguous/missing facts.

Name-only writes preserve operation/authority state and reject inactive/missing targets even for no-ops. Direct
Permission changes preserve credential correlation and package tier/reference rules; they grant no actor authority.
Current caller/target/destination authorization stays with its existing owner. No raw secret/ciphertext/claim values
in status, logs, callbacks or exception chains; sensitive concrete parameters require redaction. Safe reads never
load material or manufacture absence on storage failure.

## Acceptance criteria

- [ ] Real PostgreSQL round trips preserve complete current original request/issuance/correlation and retained
  state; all creation and hydration paths obey exact revisions and validated public package construction.
- [ ] Competing provision/rotation attempts enforce scoped-key/global identity uniqueness, cross-scope destination
  order and atomic capacity. Same-key resolution preserves original result without duplicate mutation/audit.
- [ ] Agent retirement atomically cancels original delivery and removes its copy with required audit, including
  material-free predecessors. Failure/rollback leaves no partial Agent, operation, reservation or audit change.
- [ ] Name and Permission writes preserve unrelated state and current correlation under shared fences; no direct
  storage-only bypass is retained as an alternative authority mode.
- [ ] Safe status distinguishes original issuance from current delivery/credential disposition. Unknown versions,
  stale expected state and storage/commit uncertainty do not become absence, false success or automatic reissuance.
- [ ] Both repositories use the shared contract boundary; runtime remains unavailable until the complete adjacent
  composition is qualified. Any existing incompatible rows require an explicit safe stop, not manufactured history.
