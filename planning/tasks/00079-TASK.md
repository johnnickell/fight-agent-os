# Confirm and designate checkout and worktree links

## Outcome

An authorized human can preview and confirm the first durable Checkout/Worktree link beneath an actually available approved root, then explicitly designate exactly one available linked Worktree as the Repository's ordinary Dashboard filesystem target without changing branches, remotes or working files.

## Scope

- In scope: Initial installation Host identity; typed `HostId`, `CheckoutId` and `WorktreeId`; persisted Host/Checkout/Worktree links, revisions/history and availability observations; injected approved-root and Git-observation capabilities; canonical path/common-directory/worktree/ownership/marker/source evidence; expiring confirmation bound to exact evidence; `LinkCheckout`/`CheckoutLinked`/`WorktreeLinked`; accepted recoverable Git-marker protocol; `ListRepositoryCheckouts` and registration detail extension; `DesignateWorktree`/`WorktreeDesignated`; one-designated-worktree invariant; audit evidence; independent permissions; versioned API/OpenAPI; PostgreSQL/concurrency/real-Git evidence.
- Out of scope: Automatic first linking, ambiguous relink/recovery UI, moved/copied/recloned reconciliation beyond safe refusal, source descriptor changes, archive/restore, branch checkout, worktree creation/removal, source-file mutation, repository registration UI, context resolution, Planning migration, Runner mounts/Execution authority and Git publication.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Preview the first checkout link | N/A — read-only proposal | Inspect approved root, Host, canonical path, Git common directory, marker, worktrees and sources | N/A — preview emits no Domain event | A short-lived safe proposal explains exact evidence, warnings and required confirmation without writing state/marker |
| Confirm the first checkout link | `LinkCheckout` | Revalidate the complete bound proposal | `CheckoutLinked`, `WorktreeLinked` | Generated physical identities, audit/effect state and accepted uncommitted Git marker reach the ADR-defined recoverable outcome |
| List physical links | N/A — read-only interaction | `ListRepositoryCheckouts` | N/A — reads emit no Domain event | Authorized user sees Host, safe paths, worktrees, branches, availability, evidence and designation state |
| Select ordinary Dashboard checkout | `DesignateWorktree` | Query linked available Worktrees and expected Repository revision | `WorktreeDesignated` | Exactly one linked available Worktree becomes designated; neither working tree changes |

## Validation and permissions

Create one stable installation Host identity explicitly; do not derive it from hostname, path, container ID, runner or network address. Canonicalize requested paths through TASK-00073, require exact containment beneath an actually mounted approved root, verify supported ownership and regular directory shape, and reject relative/missing/ambiguous/inaccessible paths, symlink escape, unknown Hosts, complete-home exposure and changed root evidence.

Use an injected read-only Git observer to identify the Git common directory, concrete worktree path, linked worktrees, branch/HEAD summary, normalized remotes and Agent OS marker without running arbitrary repository hooks or executing repository code. Treat all values as observations. Directory/slug similarity is never matching evidence. A first durable link always requires explicit confirmation even when one source uniquely proposes the Repository.

Bind the confirmation to authenticated actor, permission, Workspace/Repository/Host, exact canonical approved root/path/common directory, current marker/source/worktree evidence, expected aggregate revisions and a short expiry. Present safe evidence and consequences. Re-observe everything at execution; any mismatch, new marker, changed source, moved path, permission loss, stale revision or expiry refuses without partial authority.

Generate Checkout/Worktree IDs internally. Apply the exact accepted TASK-00077 database/marker consistency protocol, idempotency identity, fencing and recovery. Inspect before marker write; never overwrite unknown/conflicting values. The marker remains local uncommitted Git configuration shared by linked worktrees at the Checkout boundary. Do not alter branch, HEAD, remote, index, worktree files, hooks, attributes or committed configuration.

Designating requires an existing active Repository, linked Worktree, matching Host/Checkout, current availability and expected revision. Enforce at most one designated Worktree per Repository transactionally under competing requests. Designation changes only Agent OS state; it does not `git switch`, clean, reset, stash or write the selected worktree.

Require separate server-side permissions for viewing physical links, linking and designating. Safe Views omit Git config contents, unnecessary absolute/private path detail for unauthorized actors, credentials in remotes, file listings and persistence models. Registration/linking/designation grant no Planning, Runner, Agent, commit, push, PR or merge authority.

## Acceptance criteria

- [ ] One installation Host, each Checkout and each Worktree receive stable internally generated typed COMB identities; locators remain mutable evidence.
- [ ] Preview performs no durable/marker mutation and explains canonical approved-root, common-directory, marker, source, linked-worktree and availability evidence safely.
- [ ] First link always requires an authorized expiring confirmation bound to exact observations/revisions and revalidated immediately before effect.
- [ ] Missing/changed roots, Hosts, paths, ownership, Git shape, sources, markers, permissions, revisions or confirmations fail without silently linking.
- [ ] Link persistence, events/audit and marker effect follow the accepted idempotent recoverable protocol across retries and response loss.
- [ ] Linked Git worktrees share one Checkout/common-directory identity while receiving distinct Worktree identities.
- [ ] Exactly one currently available linked Worktree may be designated transactionally; changing designation mutates no branch, remote, index or worktree file.
- [ ] Query/API Views expose safe evidence, availability and designation only to independently authorized actors.
- [ ] Linking/designation create no Planning/context/Execution/publication authority and no Repository identity from a path or marker.
- [ ] Focused Domain/Application/PostgreSQL/concurrency/API/redaction tests, direct real-Git checks and the canonical build pass.
