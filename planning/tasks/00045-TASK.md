# Enforce browser authentication request controls

## Outcome

Reusable server controls enforce the accepted refresh-cookie lifecycle, CSRF protocol, exact trusted Origin, Fetch Metadata, JSON-only requests, HTTPS/same-origin assumptions, production `LoginThrottle`, and atomic bounded endpoint rate limiting before login, refresh, or logout can mutate authentication state.

## Scope

- In scope: Typed refresh-cookie policy/factory/deletion; ordinary/remembered persistence and exact expiry mapping; HTTP proof-header/cookie verification composition and login/logout nonce rotation/deletion reusing TASK-00018's issuer/verifier/nonce contract; exact Origin and Fetch Metadata middleware; method/content-type/JSON shape guards; trusted proxy/HTTPS configuration constraints; production package `LoginThrottle`; reusable login/refresh/logout rate limiting; safe rejection/error correlation; startup validation; focused security/concurrency/redaction tests and OpenAPI components.
- Out of scope: Login/refresh/logout Actions/UI, token claim validation, general cross-origin support, credentials in JavaScript, CAPTCHA, WAF/proxy deployment, arbitrary global rate-limiting framework, and changing accepted ADR controls.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Construct refresh cookie | N/A — transport adapter | Read TokenSet/session policy and trusted cookie configuration | N/A — no domain event | Opaque credential is emitted only as matching secure HttpOnly session/persistent cookie |
| Protect auth request | N/A until guards pass | Validate method/content type/body, CSRF, Origin, Fetch Metadata, HTTPS, and limiter | N/A — no domain event | Rejected request reaches no authentication service and receives safe failure |
| Throttle credential verification | Package login calls `LoginThrottle::allows()` | Atomically consume bounded canonical-email attempt dimension | N/A — no domain event | Excess attempts are denied without identity enumeration or raw-key storage |
| Delete refresh cookie | N/A — transport adapter | Read exact cookie identity attributes | N/A — no domain event | Browser receives expiry using attributes matching issuance |

## Validation and permissions

Implement exactly the CSRF mechanism and lifecycle accepted in TASK-00017's ADR. Reuse TASK-00018's real `GET /api/v1/auth/csrf` query/nonce-cookie/proof contract and transport-free verifier; this TASK reads the cookie/header in HTTP, passes transport-free values for constant-time MAC/deadline verification, and blocks login/refresh/logout dispatch on failure. CSRF material is unpredictable, bounded, non-authoritative, separate from refresh/session/access credentials; login/logout rotate/delete the nonce and multi-tab clients bootstrap again. Never put authority/refresh tokens into CSRF state.

Require an exact configured trusted Origin for browser auth mutations, with documented handling for absent Origin according to accepted profile. Parse, normalize, and compare origins without suffix/wildcard/userinfo ambiguity. Enforce Fetch Metadata combinations where supported while retaining Origin/CSRF as authoritative controls. Reject cross-site and impossible/malformed values before service dispatch.

Accept only approved methods and `application/json` media type/charset/body bounds with expected object shape. Reject form/multipart/text, empty/unexpected bodies, method overrides, and oversized input. Require trusted HTTPS in production and validate proxy trust explicitly; do not trust arbitrary forwarded headers. Same-origin deployment remains CORS deny-by-default.

Refresh-cookie name/domain/path/Secure/HttpOnly/SameSite and prefix follow ADR. Ordinary sessions use a browser-session cookie; remembered sessions use explicit expiry bounded by package absolute expiry. Replacement/deletion use matching identity attributes. Cookie values never enter JSON, logs, errors, metrics, audit, or browser-readable APIs.

Implement `LoginThrottle` with real atomic persistence/expiry and safe one-way/bounded canonical-email keying. Because the package port only asks `allows()`, document whether each call consumes an attempt and test success/denial behavior. Layer safe network/actor endpoint limits where accepted, reusing TASK-00041's rate infrastructure rather than creating incompatible stores. Unknown and known identities receive equivalent public behavior.

Production startup fails closed for missing/weak CSRF, invalid cookie/origin/HTTPS/proxy settings, or unavailable mandatory limiter. No end-user permission applies; these controls precede authentication.
