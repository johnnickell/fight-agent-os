# Deliver confirmed revocation of another owned session

## Outcome

An authenticated user can explicitly confirm and revoke one other usable owned refresh session through package `RevokeSession`; actor and current session remain principal-derived, current-session revocation directs to Logout, unsafe target outcomes do not enumerate cross-user state, the authoritative list converges, and applicable same-origin tabs invalidate without credential persistence.

## Scope

- In scope: Versioned Bearer-authenticated revoke Action/validated target route parameter/safe outcome/OpenAPI; principal-derived actor/current session; deny-all cross-user administration composition; package `RevokeSession` dispatch; current-session safe conflict; generic nonexistent/cross-user/expired/revoked/conflict mapping; explicit client confirmation and pending/result states; list invalidation/refetch; versioned session-revoked/list-invalidated cross-tab signal; volatile self-session comparison and terminal handling; PostgreSQL ownership/race/refresh/access-token/HTTP/client/accessibility/redaction tests.
- Out of scope: Current-session revocation outside Logout, logout everywhere, cross-user Super Admin session administration, administrative reason input, raw refresh credentials, editing lifetimes, guaranteed cross-device push, persistent session coordination, mass selection, and broad browser automation.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Revoke another owned session | `RevokeSession(actorId, currentSessionId, targetSessionId, null)` | Resolve principal and target package session ownership/usability | `RefreshSessionRevoked` | Target revokes atomically; current session remains usable; list invalidates/refetches |
| Reject current-session target | Same command or pre-dispatch safe guard without replacing package authority | Compare principal current ID with target | Package current-session rejection | No mutation; client directs user to established Logout journey |
| Converge after race | Same command may meet revoked/expired/concurrently changed target | Requery authoritative active-session list | Existing package failure/event only | Generic result followed by refetch removes stale row without revealing target ownership |
| Propagate revocation signal | N/A — client coordination after accepted outcome/event response | Compare target ID with volatile current session identity where available | Versioned client-only invalidation/terminal signal | Same-origin lists refetch; matching target tab fails closed; no cross-device guarantee is claimed |

## Validation and permissions

Require valid Bearer authority and one request-scoped `CurrentPrincipalProvider`. Accept only one bounded canonical target session ID from the versioned route; body cannot override actor/user/current session/reason/role/permission or request administrative behavior. Construct package command with actor from principal, current session from principal, target from validated route, and null reason. Require authoritative `DELETE_OWN_SESSIONS` in Agent OS Application and the early HTTP route gate, plus package-owned actor/target ownership. `DELETE_SESSIONS` cannot grant cross-user access here.

Compose package `SessionAdministrationAuthorization` to deny cross-user administration for this installation feature. Do not infer permission from role or expose a hidden administrator path. Package handler remains authoritative for usable target, current-session prohibition, ownership/administrative denial, optimistic replacement, audit rules, and event. Do not directly update repository/session flags.

Current-session target receives an explicit safe conflict code/message directing to Logout because the caller already receives its current marker through TASK-00057; no mutation occurs. Cross-user valid ID, nonexistent, expired, already revoked, and non-current competing revocation must share an allowlisted non-enumerating public class/status/body. Malformed identifier can receive transport validation without lookup. On success or safe stale/conflict outcome, invalidate and requery list rather than optimistic fabrication.

Require an explicit accessible confirmation naming only safe coarse descriptor and relative/absolute time needed to distinguish the target. Never place credential/digest or unescaped raw metadata in dialog. Disable duplicate submission while pending, manage focus into/return from dialog, announce result, and preserve a retry/refetch path. Current row exposes Logout rather than this action.

After successful server commit, emit a versioned bounded same-origin coordination signal containing only approved session ID/generation/invalidation semantics. Every tab invalidates/refetches session lists. If a tab's existing volatile authentication coordinator safely knows its own stable session ID and it equals the target, clear memory/principal and enter terminal Login; do not parse JWT as trusted state or persist the ID. Different current tabs remain authenticated. Other browsers/devices receive no BroadcastChannel promise, but TASK-00044's authoritative session resolution rejects their access token immediately and refresh rejects credential immediately.

No session ID/token/authority/coordination state enters `localStorage`, `sessionStorage`, IndexedDB, Cache Storage, service workers, URL query, or HTML. Session ID remains a safe opaque transport identifier but is redacted from unnecessary diagnostics and cannot authorize without current principal ownership.
