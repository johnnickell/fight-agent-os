# Deliver one exact new-mailbox confirmation link

## Outcome

A protected direct package delivery call sends the exact purpose-bound email-change credential only to the
reserved new mailbox through the shared mail capability. Claim, invocation and matching outcome remain package-
owned; fixed safe link/content composition supplies a precise producer contract to TICKET-00069.

## Scope

- In scope: Direct `DeliverEmailChangeHandler` composition, optional package post-commit subscriber, exact link
  identity resolution, fixed text/HTML mapping, secret-safe outcomes and actual package/PostgreSQL integration.
- Out of scope: Request exposure, confirmation page/submit, real provider enrollment, deployed schedule,
  consumer claim/retry state, old-mail credential delivery or public token/retry/claim endpoints.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Process exact committed work | Package `DeliverEmailChange` | Exact package generation, latest authority and live claim under package policy | Package `EmailChangeDelivered` only after matching outcome commit | Committed claim, external mail invocation, then separately committed outcome/audit |
| Materialize the purpose link | Existing package provider invokes shared mail capability | Exact delivery-identity lookup for necessary immutable User/expiry facts | N/A — rendering is not a business transition | Fixed safe HTTPS link and text/HTML held only during invocation |
| Attempt immediate delivery | Package `EmailChangeDeliverySubscriber` after accepted request commit | Event's exact User/delivery identity; no destination/secret inferred from scheduler input | Existing package outcome/failure facts | Optional bounded attempt, never recovery authority or a second request |

## Validation and permissions

Use TASK-00283's cipher and the selected public package handler on the canonical transaction/connection. The
handler commits the exact claim before decryption/provider work and separately commits only a matching live
claim/revision outcome and required audit. No surrounding transaction, copied handler, consumer token lease or
second credential queue is permitted. Requalify affected integration if TASK-00273 changes the selected contract.

Only trusted internal composition can invoke delivery. Actor IDs provide audit provenance, not authentication or
end-user send permission. TASK-00286 owns the worker's narrow recovery-actor integration; direct and subscriber
paths must use trusted provenance and reject untrusted dispatch. The subscriber is an optional latency optimization:
loss of an event cannot lose work, and post-commit delivery/event failure cannot prove request rollback or authorize
another request. Do not register unfinished public issuance merely to produce an event.

The inspected `CredentialDeliveryInvocation` carries purpose, stable delivery ID, destination and secret, but
**not User ID or expiry**. `confirmEmail()` needs the User/credential pair. Resolve needed immutable facts through
the public exact `EmailChangeGrantRepository::getByDeliveryId()` boundary and validate purpose/identity/destination
binding. Never search by new address, current canonical address or issuance time, invent invocation fields, use
private reflection or fall back to a newer generation. Missing/inconsistent facts fail safely. Additional reads
cannot recall an in-flight provider call or replace package confirmation authority.

Build the link from exact configured trusted HTTPS origin and a fixed purpose path/encoding contract handed to
TICKET-00069. Prefer the narrowly required inbound fragment to keep credentials out of HTTP request lines; include
only necessary routing identity and never put the new address in the URL. No Host/forwarded-header derivation,
open redirect, persisted dynamic template or caller-supplied URL is allowed. The consumer must later capture the
same credential in volatile memory and promptly remove it from history; a generated link is not a working landing.

Use deterministic escaped text/HTML, historical issuance expiry or truthful one-hour-from-request guidance,
never a fresh lifetime computed on retry. No tracking, remote active content, auto-confirmation, old-mail approval,
password-reset link, extra secret or administrator credential copy. Keep canonical content stable across retries
for provider idempotency; qualify changed-template/origin deployment behavior without a second credential queue
or persisting plaintext. Separate actual provider acceptance from mailbox receipt and confirmation.

Catch/map provider errors only to supported safe outcomes. Credentials, hashes, ciphertext, bodies, URLs, provider
secrets and arbitrary exception messages stay out of status, logs, events, audit and retained test records.
Cancellation/consumption/expiry/replacement fence authority and stale outcomes but cannot unsend accepted mail.
A lost outcome may cause another same-identity attempt; permanent delivery failure is not automatically expired
email authority or a released reservation.
