# Deliver the accessible production theme preference

## Outcome

The accepted semantic visual language is recreated in production with an accessible `system`/`light`/`dark` preference that defaults to and tracks the operating system in system mode, persists only the explicit presentation choice, applies before ordinary rendering without avoidable flash, and respects reduced motion.

## Scope

- In scope: Accepted semantic token and Bootstrap mapping recreation; typed three-state preference; safe `localStorage` adapter; early theme bootstrap compatible with accepted CSP; OS media-query subscription/cleanup; root theme/color-scheme application; accessible compact selector; unavailable/corrupt storage fallback; reduced-motion integration; production component/Storybook adoption; deterministic unit/component/render evidence across modes/viewports.
- Out of scope: Prototype source/assets promotion, business/authentication state persistence, server account preference, cross-device synchronization, arbitrary user themes, RTL, broad visual-regression suite, universal WCAG certification, and shell/dashboard composition owned by later TASKs.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Bootstrap presentation | N/A — pre-render client bootstrap | Read validated explicit preference and OS color scheme | Browser presentation signal | Effective semantic mode applies before ordinary render with safe system fallback |
| Select theme preference | N/A — local presentation interaction | Read current preference and selected `system`/`light`/`dark` value | Preference-change client signal | Explicit choice persists and effective mode updates immediately |
| Track operating system | N/A — media-query response | Observe `prefers-color-scheme` while preference is system | OS preference signal | Effective mode changes only in system mode; listener lifecycle remains bounded |
| Handle storage failure | N/A — adapter fallback | Catch unavailable/denied/corrupt storage | N/A — no domain event | Rendering continues in system mode without leaking or persisting other state |

## Validation and permissions

Accept exactly `system`, `light`, or `dark`; absent, wrong-type, oversized, or unknown stored values safely become `system` and may be cleaned according to the accepted ADR. Persist only the explicit preference under one versioned application-owned key. Never store effective OS result, credentials, tokens, principal/permission snapshots, intended routes, form state, or business data.

Apply the effective mode to a stable root attribute/class and `color-scheme` before ordinary React rendering using a minimal CSP-compatible mechanism selected by prior ADR/security work. Keep server/base HTML free of authority and secrets. Bootstrap and React runtime use one mapping implementation/contract so they cannot drift. Failure to access storage or media APIs must not block rendering.

In `system`, subscribe to OS changes and update effective mode; explicit light/dark ignore later OS changes. Remove obsolete listeners and support current browser listener APIs according to supported baseline. Avoid unbounded events, remount duplication, and hydration/render mismatch.

Recreate TASK-00035's accepted values in production semantic tokens and deliberate Bootstrap mappings; do not copy ignored prototype implementation. Color/motion/focus/state semantics remain understandable without color alone and respect `prefers-reduced-motion`. The selector has an accessible group/name, visible selected state, keyboard operation, unobscured focus, adequate target behavior, and no misleading permission semantics. No authentication or application permission is required.

## Acceptance criteria

- [ ] Missing preference defaults to `system`; malformed/unknown/unavailable storage safely falls back without blocking rendering.
- [ ] Exact `system`, `light`, and `dark` values persist and restore through one versioned key; no other application state is stored.
- [ ] System mode follows initial and subsequent OS changes; explicit modes remain stable when OS preference changes.
- [ ] Effective mode/root `color-scheme` applies before ordinary rendering with no avoidable wrong-theme flash or runtime/bootstrap mapping drift.
- [ ] Bootstrap is compatible with accepted CSP and contains no credential, authority, secret, remote dependency, or unsafe dynamic code.
- [ ] Semantic tokens and Bootstrap mappings recreate the independently accepted production handoff without importing prototype code.
- [ ] Selector exposes an accessible name/current state, keyboard behavior, visible focus, adequate target/reflow, and deterministic interaction.
- [ ] Reduced-motion behavior and non-color-only status/focus communication apply consistently in production components.
- [ ] Media/storage listeners are bounded and cleaned up; remount, storage denial, and unsupported API paths remain safe.
- [ ] Storybook renders production components in system/light/dark and representative narrow/wide/reduced-motion states.
- [ ] Focused bootstrap/storage/media/component/accessibility/CSP checks and `./bin/build` pass with fresh evidence.
