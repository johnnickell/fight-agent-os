# Establish the React and TypeScript application shell

## Outcome

A production `client/` application builds reproducibly with pinned React, strict TypeScript, ESBuild, Bootstrap, Vitest, and React Testing Library tooling, and renders a responsibility-separated non-product shell with typed runtime configuration and deterministic route/loading/error behavior.

## Scope

- In scope: Evidence-based Node/package-manager choice and pin; committed manifest/lock; repository Docker wrappers; React/strict TypeScript/ESBuild/Bootstrap; lint/format baseline appropriate to the client; production asset build and Slim/static integration; entry point; Routes/Layouts/Pages/Components boundaries; typed non-secret runtime configuration; representative home/unknown/loading/system-error shell states; Vitest/RTL setup; build/type/owned-behavior evidence.
- Out of scope: Authentication, activation, recovery, dashboard, account/admin journeys; final navigation/visual design; API client; authority guards; Storybook; service workers/offline behavior; broad browser automation; final quality thresholds owned by TICKET-00013.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Build production client | N/A — frontend tooling | Read pinned dependencies/config/source | N/A — no domain event | Deterministic assets and manifest are emitted to an approved production-served path |
| Start browser shell | N/A — client boot | Read and validate non-secret runtime configuration | UI lifecycle only | React mounts once and renders route through Layout/Page boundaries |
| Navigate foundation routes | N/A — navigation | Read route metadata/match state | Browser history/navigation effect | Representative page, unknown, loading, and system-error states render deterministically |
| Test shell behavior | N/A — tooling | Render production components/routes under controlled config | N/A — no domain event | Vitest/RTL assert user-observable structure and interaction without a browser server |

## Validation and permissions

Pin runtime/tooling versions and commit the selected lock. Repository wrappers run through Docker and do not depend on unpinned global Node tools after explicit setup. Generated caches/reports belong under ignored paths; decide whether production assets are committed or built.

Keep Routes responsible for matching/metadata, Layouts for shell/outlet, Pages for one journey/state, and Components for focused interaction/presentation. Do not create empty speculative feature layers. The representative shell must not claim dashboard/planning/observability data or imitate final EPIC-00004 design.

Runtime configuration is explicitly decoded, typed, non-secret, and separate from authority. Missing/malformed values fail safely without dumping environment. No roles, permissions, token, cookie, provider key, or private server config may enter base HTML or client bundle.

Use semantic HTML, usable document title/landmarks, keyboard-visible focus, reduced-motion-safe defaults, and narrow/wide reflow. This is a foundation baseline, not a complete accessibility or final-design claim.

No runtime permission is implemented. Client toolchain/shell/assets are authorized; product journeys are not.

## Acceptance criteria

- [ ] Node/package-manager choice and versions are pinned, with a committed reproducible lock and Docker-backed repository wrappers.
- [ ] Clean locked install, strict typecheck, lint/format check, ESBuild production build, and Vitest run succeed without implicit updates.
- [ ] React mounts through a production entry point and generated assets are served under the selected same-origin production topology.
- [ ] Routes, Layouts, Pages, and Components have clear demonstrated responsibilities without speculative feature scaffolding.
- [ ] Representative shell route, unknown route, loading state, and system-error state are deterministic and tested.
- [ ] Typed runtime configuration accepts only approved non-secret values and fails safely for absent/malformed data.
- [ ] Client bundle/HTML contain no authority snapshot, credential, provider key, or private environment dump.
- [ ] Shell semantics, focus visibility, reduced-motion handling, and narrow/wide reflow have behavior/evidence appropriate to the foundation.
- [ ] No product journey, fake dashboard/metrics, API client, or final visual language is introduced.
- [ ] Focused frontend checks and `./bin/build` pass with versions, artifact details, counts, and warnings recorded.
