# Complete PHP style static-analysis and dependency enforcement

## Outcome

Pinned, Docker-backed PHP syntax, Fight Common 1.2 PHPCS, PHPStan, Deptrac, and Rector dry-run checks enforce accepted Fight PHP conventions, static correctness, and Domain/Application/Adapter direction across owned backend code with narrow justified exclusions.

## Scope

- In scope: Pin PHPCS and its plugins and consume the Fight Common 1.2 shipped standard directly; add deterministic PHP syntax linting; encode only justified repository additions; select/pin/configure PHPStan at the highest evidence-supported baseline; extend Deptrac across representative namespaces/paths; pin/configure Rector in dry-run mode; focused `./bin/*` wrappers against the running Compose PHP service; ignored cache/report paths; documentation of narrow exceptions.
- Out of scope: Backend line coverage, frontend tooling, canonical-build integration, source repair beyond violations introduced/exposed within authorized tool-adoption scope, upstream package analysis, broad baselines/ignore lists, and style preferences not established by repository conventions.

|---|---|---|---|---|
| Check PHP syntax and style | N/A — repository tooling | Lint every owned PHP file and inspect it with the Fight Common 1.2 PHPCS standard plus justified repository additions | N/A — no domain event | Parse/style violations fail with file/line/rule diagnostics and no source mutation |
| Analyze static correctness | N/A — repository tooling | Inspect owned types, calls, generics, returns, and configuration boot shapes | N/A — no domain event | Owned type errors fail without hiding behind a broad baseline |

| Iterate with focused wrappers | N/A — repository tooling | Read pinned config/source | N/A — no domain event | Developers run deterministic checks with caches only under ignored paths |

## Validation and permissions

PHP syntax linting must cover every owned production, test, configuration, migration, and executable PHP file exactly once per canonical gate. PHPCS must load the standard shipped by the locked Fight Common 1.2 package directly rather than copying it, then apply only documented Agent OS additions. It must enforce applicable Fight/repository conventions, including strict declarations, naming, imports, formatting, multiline capitalized active-verb docblocks without trailing periods, `@inheritDoc` usage, and owned namespace/path conventions. Class finality and readonly defaults are code-review guidance, not additional PHPCS acceptance requirements. Do not encode subjective rules lacking an accepted source or auto-fix source during acceptance checks.

PHPStan must run at the highest level supported by representative owned code with explicit extensions/stubs only where necessary. Do not generate a broad baseline or wildcard-ignore owned paths/errors. Every ignore must identify a narrow tool limitation or external contract and include a removal owner where possible. Vendor code is not reanalyzed as owned source.

Rector must use a committed, pinned configuration derived from demonstrated Agent OS needs and run only with `--dry-run` in acceptance checks. Any skip must name an exact compatibility or behavior reason; the gate must never rewrite source automatically.

Extend rather than replace TASK-00010's architecture check. Enforce accepted Domain/Application/Adapter direction, composition-root exceptions, capability dependencies, direct Fight package use, and copied/renaming-wrapper prohibitions where mechanically reliable. Exclude generated/cache/vendor paths, not meaningful owned behavior.

All tools and plugins are pinned in the committed Composer lock, run non-interactively through wrappers that execute in the already-running Docker Compose PHP service, and place cache/results under ignored `var/` or `.runs/`. Focused wrappers may select one phase for iteration but must not cause the canonical gate to duplicate a phase. No runtime permission applies; tooling/configuration changes are authorized.
