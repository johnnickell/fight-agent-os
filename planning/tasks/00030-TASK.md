# Complete PHP style static-analysis and dependency enforcement

## Outcome

Pinned, Docker-backed PHPCS, PHPStan, and dependency-analysis checks enforce accepted Fight PHP conventions, static correctness, Domain/Application/Adapter direction, and package ownership across owned backend code with narrow justified exclusions and clear seeded-failure evidence.

## Scope

- In scope: Select/pin PHPCS and rules; encode accepted repository PHP conventions; select/pin/configure PHPStan at the highest evidence-supported baseline; extend the Deptrac/equivalent checks from TASK-00010 across representative namespaces/paths; focused `./bin/*` wrappers; ignored cache/report paths; deterministic valid and seeded-invalid evidence; documentation of narrow exceptions.
- Out of scope: Backend line coverage, frontend tooling, canonical-build integration, source repair beyond violations introduced/exposed within authorized tool-adoption scope, upstream package analysis, broad baselines/ignore lists, and style preferences not established by repository conventions.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Check PHP style | N/A — repository tooling | Inspect owned PHP tokens/files against accepted rules | N/A — no domain event | Violations fail with file/line/rule diagnostics and no source mutation |
| Analyze static correctness | N/A — repository tooling | Inspect owned types, calls, generics, returns, and configuration boot shapes | N/A — no domain event | Owned type errors fail without hiding behind a broad baseline |
| Enforce dependencies | N/A — repository tooling | Inspect layer/package imports and composition boundaries | N/A — no domain event | Prohibited inward/package dependencies fail; accepted composition passes |
| Iterate with focused wrappers | N/A — repository tooling | Read pinned config/source | N/A — no domain event | Developers run deterministic checks with caches only under ignored paths |

## Validation and permissions

PHPCS must enforce applicable Fight/repository conventions, including strict declarations, naming, imports, formatting, final/readonly defaults where mechanically appropriate, multiline capitalized active-verb docblocks without trailing periods, `@inheritDoc` usage, and owned namespace/path conventions. Do not encode subjective rules lacking an accepted source or auto-fix source during acceptance checks.

PHPStan must run at the highest level supported by representative owned code with explicit extensions/stubs only where necessary. Do not generate a broad baseline or wildcard-ignore owned paths/errors. Every ignore must identify a narrow tool limitation or external contract and include a removal owner where possible. Vendor code is not reanalyzed as owned source.

Extend rather than replace TASK-00010's architecture check. Enforce accepted Domain/Application/Adapter direction, composition-root exceptions, capability dependencies, direct Fight package use, and copied/renaming-wrapper prohibitions where mechanically reliable. Exclude generated/cache/vendor paths, not meaningful owned behavior.

All tools and plugins are pinned in the committed Composer lock, run non-interactively through Docker-backed wrappers, and place cache/results under ignored `var/` or `.runs/`. No runtime permission applies; tooling/configuration changes are authorized.

## Acceptance criteria

- [ ] PHPCS and required standards/plugins are pinned and enforce documented Fight/repository conventions on all owned backend PHP.
- [ ] PHPCS check mode does not rewrite source and excludes only vendor/generated/cache paths.
- [ ] PHPStan is pinned at a documented evidence-supported level with no broad baseline or wildcard suppression of owned failures.
- [ ] Every static-analysis ignore/stub/extension is narrow, justified, and recorded with its consequence.
- [ ] TASK-00010's dependency checks are extended across representative Domain, Application, Adapter, configuration, and package-ownership paths rather than replaced.
- [ ] Composition exceptions are explicit and narrow; meaningful owned code is not excluded to make the gate pass.
- [ ] Docker-backed focused wrappers are deterministic, non-interactive, and write only ignored caches/reports.
- [ ] Isolated seeded style, type, inward-dependency, copied-package, and renaming-wrapper violations fail with clear diagnostics while valid examples pass.
- [ ] No upstream package suite or vendor source is treated as owned code.
- [ ] Focused checks and `./bin/build` pass with tool versions, file/error counts, exceptions, and warnings recorded.

Verify cache/report locations and compare tracked state before/after check mode. Review every exclusion/ignore against the accepted ownership ADR.
