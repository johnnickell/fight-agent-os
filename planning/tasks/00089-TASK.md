# Create and revise implementation TASK artifacts

## Outcome

Authorized planners can idempotently create, inspect and semantically revise event-sourced implementation TASKs with immutable repository-local references, valid optional TICKET parentage, explicit standalone bug/chore semantics and delivery evidence that never conflates implementation acceptance with review, publication or merge.

## Scope

- In scope: Separate `Task` aggregate/stream; COMB ID and immutable repository-local TASK reference allocator; active Repository ownership; optional same-Repository requirement TICKET parent; closed feature/bug/chore kind and standalone rules; accepted machine status representation; title/outcome/scope/contracts/validation/verification/coordination/completion sections; typed verification requirements and delivery-link/reference metadata; semantic create/section/delivery-link commands/events; idempotency/expected versions; transactional parent/reference/current projections; Repository/TICKET hierarchy/detail/history Views; view/create/revise/delivery-link Permissions; PostgreSQL/concurrency; versioned API/OpenAPI.
- Out of scope: Generic documents, reparenting, dependency edges, priority/order and executable queue, claims, criteria/evidence satisfaction, lifecycle completion/Won't Fix, review workflow, PR publication/merge control, GitHub synchronization, Markdown import, browser UI and execution attempts.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Create a parented TASK | `CreateTask` | Preview active Repository/TICKET, kind, reference and initial status/content | `TaskCreated` | One stream, immutable reference, parent/allocator/current constraints commit atomically |
| Create standalone work | `CreateTask` with no TICKET | Validate explicit bug/chore kind and reason | `TaskCreated` | Valid standalone bug/chore is repository-owned without inventing a TICKET; standalone feature is rejected |
| Revise TASK intent | Section-specific revise commands | Compare normalized section and expected stream version | Type-specific semantic revision event | Complete changed value appends without generic replacement or changing parent/status implicitly |
| Link delivery observations | Explicit add/supersede delivery-link command | Validate typed branch/commit/review/PR/merge/artifact observation and provenance | Type-specific delivery-link event | Multiple attempts and superseded links remain; no observed provider state changes TASK status |
| Inspect TASK history | N/A — read-only interaction | Get hierarchy/detail/version/history and delivery attempts | N/A — reads emit no Domain event | Safe rebuildable Views explain work and delivery evidence without becoming authority |

## Validation and permissions

Use a dedicated Task aggregate and semantic commands/events, not an EPIC/TICKET parameterization or generic Planning artifact. Allocate immutable TASK references atomically per Repository and never reuse them. A parented TASK has exactly one active same-Repository TICKET. A TASK with no TICKET must be explicitly `bug` or `chore` with standalone rationale; standalone feature and arbitrary missing-parent cases fail.

Use closed typed fields for kind, parent, initial status, verification requirements and delivery-link classes. Narrative sections are bounded complete Markdown-capable values. Section revisions neither change parent nor status. Initial status must be an accepted lifecycle value valid for creation/import boundaries; no generic status setter is exposed. TASK order/priority is intentionally deferred to TICKET-00027.

Delivery links record typed observation identity, locator/reference, actor/source/time and supersession. Git branch names/provider IDs are discovery/relationship evidence, never TASK identity or authority. Preserve multiple branches, commits, reviews and PR attempts. Do not infer Done, acceptance, publication, merge, release or deployment from GitHub/provider state. No external provider call occurs in the transaction.

Every command checks expected stream/constraint version, idempotency and intent-specific Permission. Append, allocator/parent constraints and command-critical projection commit atomically. Stale commands expose safe intervening facts without merge. Unrelated TASK edits do not conflict through a repository-global version.

Require separate view/create/revise/delivery-link Permissions scoped to Repository and parent. HTTP Actions dispatch one command/query and explicit safe Views; transport/API omits hidden parent existence, credentials, provider tokens, unsafe URLs, arbitrary metadata and persistence details.

## Acceptance criteria

- [ ] Task is a separate event-sourced root with COMB identity, immutable Repository-local reference and semantic history.
- [ ] Parented TASKs require an active same-Repository TICKET; only explicitly reasoned bug/chore TASKs may be standalone.
- [ ] Closed typed and bounded narrative content replays exactly; revisions cannot smuggle parent/status/dependency/priority changes.
- [ ] Idempotent retry returns the original TASK; stale/different commands fail without append or projection drift.
- [ ] Stream append, reference allocation, parent/standalone constraints and current projection commit or roll back together.
- [ ] Typed delivery observations retain multiple/superseded attempts and never infer lifecycle, review, publication, merge, release or deployment state.
- [ ] Unrelated TASK edits proceed without a Repository-global lock/version.
- [ ] Detail/hierarchy/history/delivery Views are rebuildable, non-authoritative and permission-scoped.
- [ ] APIs expose no generic document/status path or provider credential/unsafe metadata.
- [ ] Focused Domain/Application/PostgreSQL/concurrency/API tests and the canonical build pass.
