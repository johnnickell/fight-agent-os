# Persist activation grants and replacement races

## Outcome

A production PostgreSQL adapter satisfies the stable `ActivationGrantRepository` contract with secret-safe storage, exact reconstruction, latest/delivery lookup, atomic replacement and succession, and controlled race behavior.

## Scope

- In scope: Activation-grant migration/mapping; complete production repository adapter and composition; package-approved credential digest and safe delivery/lifecycle state; stable, delivery, latest-user lookups; add, replace, replacement-with-successor, and successor insertion; reference/uniqueness/ordering constraints; rollback and controlled concurrency tests.
- Out of scope: Invitation commands/orchestration, credential generation, provider delivery, activation HTTP/UI, password policy, raw grant persistence, password-reset grants, and admin operations.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Add activation grant | Package invitation behavior later uses repository | Resolve user/reference validity | Package invitation events remain package-owned | One secret-safe grant state persists for its user/delivery identity |
| Resolve activation state | N/A — repository read | Find by ID, delivery ID, or latest user grant | N/A — no adapter event | Exact package aggregate is reconstructed with deterministic latest ordering |
| Replace grant | Package activation/delivery behavior | Compare expected predecessor and replacement transition | Events only continue after committed package behavior | One valid expected-state transition commits; stale writers fail without mutation |
| Supersede grant | Package resend behavior | Resolve predecessor/latest state | Package successor outcome remains package-owned | Predecessor and successor change atomically according to repository contract |

## Validation and permissions

Persist no raw activation credential. Store only package-approved one-way credential material and safe lifecycle/delivery metadata. Constraints must enforce stable and delivery identifiers, user references, any credential digest uniqueness, successor relationships, and deterministic latest ordering without making database rows transport models.

Implement every stable `ActivationGrantRepository` method directly. Expected-state operations must compare the complete contract-required predecessor, validate successor ownership and transitions, and use the ADR-selected lock/conditional strategy. Duplicate IDs/delivery identities, stale replacements, invalid successors, and missing users map to safe known outcomes.

No end-user permission or public activation behavior is implemented. Repository/schema/composition changes are authorized; grant issuance, delivery, and consumption orchestration remain later TICKETs.

## Acceptance criteria

- [ ] A versioned snake_case migration adds activation-grant storage and authoritative user, unique, ordering, revision/state, and successor constraints.

- [ ] The production adapter implements every stable `ActivationGrantRepository` method directly.
- [ ] ID, delivery ID, and latest-user lookups round-trip exact package entities and define deterministic ordering ties.

- [ ] Duplicate add, activation/replacement, resend/activation, and competing-successor tests allow one valid authoritative outcome.

- [ ] Database conflicts map safely without exposing SQL, credential material, or internal details.
- [ ] Focused migration/repository/transaction/concurrency checks and `./bin/build` pass with fresh evidence.
