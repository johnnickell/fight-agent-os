# Contain and remove prohibited private and shared memory

## Outcome

A separately authorized safety operator can quarantine and remove prohibited payload from an Agent's private
or shared Phase/Workflow/TASK memory, including its retained shared history, without allowing ordinary
correction or retraction to preserve or redisclose it. Safe attribution and removal evidence remain while
affected current/known-ID/history reads fail closed until verified remediation. This is a complete,
independently reviewable initial safety-removal path with a secure Application operation available before
any basic human UI. Live private/shared ingestion remains unavailable until that path and the relevant
installation's export/backup and provider-disclosure boundaries are qualified.

## Scope

- Reuse [TASK-00188](00188-TASK.md)'s private and shared entries, revisions and exact/ordinary/historical
  reads. Define a distinct explicit safety-removal intent with its own currently qualified effective
  Permission, actor, target scope, bounded secret-free reason and durable safe audit. It is not the private
  owner edit, shared retraction, Team Lead template, Super Admin title or general memory-write Permission.
  Expose a guarded first-party operator/application path without waiting for the browser journey.
- Atomically mark affected entry identity/revisions/history unavailable to every normal and historical
  reader before or as forbidden content is deleted from current private text and retained shared originals,
  corrections and source/preview fields. Preserve only non-sensitive metadata where safe; do not preserve
  prior private values, source snippets or prohibited bytes in change events, search terms, notifications,
  logs or audit. Retain enough stable safe identity/lineage to investigate links without restoring the body.
- Inventory actual owned storage, rendered views, query projections, MCP outputs, Jev/provider admission,
  receipts, exports and backup/retention paths for these scopes. Remove affected local copies or prevent
  access until a verifiable remediation completes. Provider input must independently exclude prohibited
  payload; a generic prompt or unrestricted model classification is not a reliable secret filter. Disallow
  live disclosure if the qualification cannot establish safe egress. Account for already disclosed external
  content honestly rather than promising instantaneous third-party erasure.
- Use a guarded PostgreSQL transaction for authoritative quarantine/deletion and safe audit, with recoverable
  follow-up for any export/backup effect that cannot be made atomic with it under ADR 0001/0002. Interrupted
  removal cannot re-expose source payload while retrying, including through a known ID, stale receipt,
  queued judgment or previously rendered derived response. A separate later exact read rechecks removal.
- This initial scope includes private/shared current/history, not broader published copies or proposal text;
  [TASK-00197](00197-TASK.md) extends the path across the publication graph before any broader publication
  is activated. If a linked broader copy already exists, quarantine it and deny disclosure until that
  extension/remediation is qualified; do not claim this TASK alone certified the entire graph. No
  scheduler-based routine expiry, universal backups redesign or transcript import.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Remove prohibited private/shared payload | Separately authorized safety-removal command | Resolve target entry, revisions, retained history and affected local surfaces | Secret-free safety removal/quarantine fact after commit | Body inaccessible, safe audit and metadata retained |
| Continue pending remediation | Recover or verify exact outstanding removal identity | Inspect safely bounded state and real export/backup status | Remediation completed/blocked fact when observed | Access stays blocked until required copies are actually handled |
| Read removed entry | N/A — read-only rejected | Check current quarantine/tombstone before normal or historical read | N/A — no memory change | No body, title/snippet, source quotation or stale cached result disclosed |
| Reject unauthorized deletion | Rejected removal command | Resolve actor Permission/target separately from normal curation | Safe denial observation where required | No routine Agent deletion or role-name bypass |

Semantic names do not prescribe specific Doctrine mapping or remote backup technology.

## Validation and permissions

Qualify the safety-removal Permission and who can exercise it under the actual installed access-control
contract; no invented protected-tier or unguarded console bypass. Authoritative scope, actor and target
checks remain in Application. Only safe idempotency identity and non-sensitive facts may survive a retry;
never use the forbidden payload in a deduplication key, event, diagnostic or notification. Safe failure
when a copy or backup cannot be confirmed removed/blocked must preserve the quarantine and show a precise
operator recovery action without leaking text. If the actual backup/export/third-party retention route
cannot be inspected, leave live ingestion/disclosure disabled and report the limit; do not relabel an
ordinary retraction as removal. Do not run a provider call to discover whether secret handling works.

## Acceptance criteria

- [ ] An independently permissioned safety operator removes a controlled prohibited payload from private
  current text and multiple linked shared historical/current versions; safe actor, target and action
  metadata remain without the payload.
- [ ] Ordinary correction/retraction retains shared history where allowed but does **not** satisfy this
  exceptional deletion; known-ID, historical, MCP and pending Jev reads cannot expose quarantined text.
- [ ] Unauthorized Engineer/Lead/peer/reviewer, stale Permission, wrong target or a guessed ID cannot invoke
  removal or learn hidden content; retries and interrupted remediation neither duplicate nor unquarantine it.
- [ ] Actual owned projections, receipts, exports and backup-retention routes are inventoried and remediated
  or blocked with explicit recovery; any unverifiable external retention remains a live-use blocker, never
  an asserted complete erasure.
- [ ] Provider egress for private/shared memory has an independently qualified secret-safe admission path;
  live ingestion/Jev disclosure is not activated merely because a redaction command exists.
