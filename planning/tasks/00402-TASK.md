# Install verified immutable starter snapshots

## Outcome

An authorized operator installs or refreshes an exact public GitHub starter release and can inspect verified
immutable bytes, manifest and provenance through protected API/console operations. Generation and preview owners
receive usable pinned inputs without fetching another revision or executing source commands.

## Scope

- In scope: Bounded public-source retrieval, strict stable release selection, immutable installation/recovery,
  shared versioned manifest schema/validation, private snapshot storage, early eligibility/reference/hold fences,
  protected original-outcome inspection and actual installation of one qualifying managed release.
- Out of scope: Private GitHub credential integration, source releases/edits, executing preparation, project
  generation, Git initialization, full creation attempts/browser, operator conflict resolution and snapshot purge.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Install or refresh public source | Exact original snapshot-install operation | Current entry/source, bounded complete release-selection facts and prior operation | Committed intent, verified installation or conflict facts | Protected bounded retrieval/storage after commit; no source execution |
| Reconcile interruption | Explicit reconcile of original operation | Exact bytes, digest/size, source identity and committed state | Verified or unresolved original-result facts | Recover same operation without replacing trusted bytes |
| Inspect installed input | N/A — read-only | Authorized exact snapshot, manifest, provenance and eligibility | N/A | Installed facts without network fetch, repair or substitution |
| Pin or hold a snapshot | Owning transaction participant for exact caller operation | Current eligibility, generation and retained references | Committed reference/hold facts | Atomic protection of pinned bytes; no independent transaction or external effect |

## Validation and permissions

### Exact release and manifest

Validate current actor, Workspace, entry, operation-specific install/read authority and complete expected state.
Resolve provider-native GitHub source identity rather than trusting a mutable URL/name. Apply identical eligibility
rules to managed and custom sources. Choose only the newest stable strict SemVer tag at or above `1.0.0`, excluding
prereleases and historical selection for new attempts. Bounded discovery must establish the newest eligible tag;
an incomplete page set, ambiguous equal-precedence tags or unavailable source cannot justify choosing an older one.
A bad newest release/manifest does not authorize fallback. A tag declares maintainer support, not certification.

Bind exact tag, commit, archive digest/size and manifest identity/version to an immutable installation. A known tag
resolving to another commit or archive digest fails refresh closed and retains conflict evidence plus original
bytes; do not normalize the discrepancy away. TASK-00404 owns explicit resolution. New releases affect future
selection only. Retain source/provenance history without silently replacing source identity after rename/reuse.

Own the small shared generation-manifest contract consumed by TICKET-00100/00101. Validate supported schema/version,
exact identity substitutions and at most one optional preparation command. Validate declared targets and expected
matches against the pinned archive; missing, duplicated, ambiguous, changed, unmatched or unsafe contracts reject.
No broad replacement, framework assumptions, implicit Composer package identity or model repair. Exact field names
remain implementation detail. Preparation declaration is inert data here, never execution or egress permission.
Generation must independently recheck exact bytes, targets, expected matches and chosen values before effects.

Bound tag pages, response/archive and expanded sizes, entry counts, nesting, concurrency and time. Validate all
archive entries and relative targets before accepting bytes: reject traversal, absolute paths, unsafe entry types,
link escapes and ambiguous/duplicate paths. Never extract into a trusted project root or inherit `.git`, local
credentials/state or a source worktree. Retrieval is a constrained GitHub adapter, not arbitrary URL access;
qualify redirect destinations, transport and credential handling without broadening into a network proxy.

### Durable installation and independent source authority

Reuse TASK-00374's qualified private storage service/capability, not its Workflow/grant-specific Artifact admission
as catalog authority. Implement this owner's Workspace-scoped snapshot authorization, identity, references and
release retention over that narrow storage boundary. Qualify actual integration; do not forge a Repository,
Workflow, Agent or grant merely to store an archive. No second storage stack or full installation/browser dependency.

On the shared PostgreSQL connection commit exact operation/state/audit/required retrieval intent before external
work. Verify actual digest/size and manifest before marking installation eligible; an ETag, process exit or upload
acknowledgement alone is insufficient. Reconcile original outcomes across restart, response loss, duplicate delivery,
stale claims, incomplete storage and concurrent refresh; no blind retry, duplicate current selections or exactly-once
claim. External work never runs inside the business transaction. Unknown storage effects preserve bytes and hold.

Implement early shared selection/reference/hold fences now so future attempt admission can atomically check current
eligibility and protect exact snapshot/manifest bytes. They participate in the caller's canonical transaction, not
nested commits or query-only promises. Selection, eligibility and reference changes compare complete state and
monotonic generations. Preserve referenced and uncertain content; physical cleanup is not this slice. Later
TASK-00404 integrates actual attempt participants, without reverse-blocking these primitives or early admission.

Authorized queries inspect only retained safe facts and never fetch/refresh/reconcile implicitly. Installed eligible
bytes remain usable for local generation during GitHub outage without claiming installation, preparation, publication
or other network stages work offline. Missing/corrupt/withdrawn or uncertain bytes fail truthfully, never substitute.
Keep secrets and raw provider/storage errors out of ordinary logs, events and Views. Record provenance/compatibility
claims without asserting starter architecture, quality or source certification.
