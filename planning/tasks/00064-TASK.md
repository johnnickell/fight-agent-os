# Prove integrated authorization throttling and secret safety

## Outcome

A deterministic integration security matrix proves the completed application fails closed across anonymous, ordinary, Super Admin, partial-permission, stale-authority, and cross-user scenarios; consistently enforces request/rate controls and audit contracts; and keeps seeded credentials, grants, URLs, secrets, and internals out of every normal observability surface without substituting late tests for journey-owned controls.

## Scope

- In scope: Integrated actor/permission/ownership matrix; `401`/`403`/allowed/stale behavior; ambient/public/Bearer request-control consistency; all required rate-limit boundaries/isolation/concurrency; authority/session/grant/invitation race integration; durable audit review; seeded secret/redaction scans across HTTP/log/audit/metrics/analytics/URLs/referrers/browser artifacts/snapshots; deterministic failure/recovery tests; integration-only wiring corrections and owner-linked regression evidence; security evidence summary.
- Out of scope: Replacing focused journey tests, inventing controls at verification time, penetration-test certification, external scanning service, broad fuzz campaign, production provider/deployment, accepting known blocking defects as documentation, and merge/release approval.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Exercise authority matrix | Existing application commands only | Existing current-principal and journey queries | Existing events only | Allowed actor completes operation; anonymous/stale/partial/cross-user actor receives safe denial without mutation |
| Exercise request/rate controls | Existing endpoint operations | Inspect limiter/request-control state and public outcomes | Existing failure events only as designed | CSRF/origin/fetch/content/rate denials occur before mutation without identity/resource disclosure |
| Inspect audit evidence | Existing sensitive/admin operations | Read durable approved audit projections | Existing package/owned audit effects | Required actor/target/action/result evidence exists and contains no secret context |
| Seed and scan secrets | Existing safe deterministic fixtures | Inspect response, diagnostics and browser/worker artifacts | N/A — verification operation | Distinct markers are absent except explicitly authorized one-time provider invocation memory unavailable to scans |

## Validation and permissions

Build an authoritative endpoint/journey matrix from implemented OpenAPI/routes and TICKET-00014 through TICKET-00021. Include anonymous, `ROLE_USER`, managed Super Admin, misleading role name, no permissions, each single permission, selected combinations, stale authentication version, revoked/expired/wrong-owner session, non-active user, malformed authority, and cross-user identifiers. Expected access uses exact server permission or ownership contracts; client controls are never cited as enforcement.

For each protected operation, prove missing/invalid authentication gives sanitized `401`, authenticated insufficient authority gives sanitized `403` where resource-independent, valid authority succeeds, and stale authority fails before mutation. For target APIs, compare unknown/cross-user/ineligible outcomes where non-enumeration requires equivalence. Verify route/client behavior aligns but do not weaken server denial to match presentation.

Exercise CSRF, exact Origin, Fetch Metadata, HTTPS, method/content type/body shape and source restrictions across login/refresh/logout and public credential-bearing mutations according to their accepted profiles. Bearer endpoints cannot accidentally use cookie authority. Same-origin/CORS policy comes from TASK-00063. Prove control rejection occurs before service/command side effects.

Test configured login, activation, reset request/completion, refresh, invitation issue/status recovery actions and applicable delivery limits at below/at/over boundaries, concurrency, expiry and key isolation using deterministic clocks/separate PostgreSQL connections and bounded synchronization, never sleeps. Keys/diagnostics avoid raw email/IP/credential retention and public outcomes do not reveal identity eligibility.

Inspect audit requirements for bootstrap/invitation/elevation/recovery/password/session/security actions: actor, target, action, time and approved safe result/context are accurate, committed with business state where required, and never misattribute target as actor. Audit absence where no success occurred is also tested.

Seed unique password, access/refresh token, grant, digest, ciphertext, credential-link, signing/encryption/CSRF/provider key, cookie, SQL and stack markers. Scan JSend/headers, OpenAPI examples, HTML/DOM, URLs/history/referrers/request logs, application/worker/proxy logs, correlation, audit, metrics/analytics, mail test-record redactions, screenshots/videos/traces, snapshots, console output, dumps and build artifacts. Mail catcher intentionally holds test links; scope it as a credential-bearing test sink and exclude only with explicit containment/cleanup evidence, not a false no-secret claim.

Any found journey defect gets a reproducing regression test before repair and is linked back to its owning control/TASK in completion evidence. Integration glue may be corrected here when ownership is truly cross-cutting; blocking findings cannot be waived or merely listed.
