# Export and serve public-safe form validation schemas

## Outcome

An explicit Docker-backed CLI exports allowlisted browser-safe rules from named PHP validation attributes,
and a real unauthenticated `GET /api/v1/validations/{form_name}` serves only the complete safe catalog through
an owned, versioned response contract. Server enforcement remains independent and unchanged.

## Scope

- In scope: Installed Fight Common attribute/parser qualification; explicit public form/field/rule projection;
  bounded form identifiers; deterministic versioned JSON generation/replacement; repository CLI; generated
  artifact location/integrity/availability contract; real read Action/Responder and safe failures; API-v1/OpenAPI
  documentation; future JWT guard handoff; direct generation/HTTP/redaction evidence.
- Out of scope: Formik/client implementation, login/activation/reset operations, fabricated body-bearing routes,
  publishing every attribute, per-request scanning, dependency upgrades without qualification, server-policy
  changes, Swagger hosting, user/permission catalogs and product tests of exporters or generated files.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Export browser-safe schemas | Explicit repository CLI; no domain command | Inspect eligible named attributes, rule semantics and explicit publication set | N/A — tooling | Complete deterministic artifact generation; safe failure preserves prior complete output |
| Read an approved schema anonymously | None | Resolve canonical allowlisted form name/revision | None | Safe JSend metadata; no authentication, account lookup, cookie or business mutation |
| Reject unsafe/unknown/unavailable lookup | None | Bounded identifier/catalog resolution | None | Documented safe client/not-found/unavailable outcome; no filesystem/private rule disclosure |
| Add a real form later | Owning journey's implementation workflow | Inspect its actual attribute and browser-safe subset | Owning journey only | Deliberate registration/export without inferring endpoint authorization from metadata |

## Validation and permissions

Implement [TICKET-00036's schema/generation contract](../tickets/00036-TICKET.md#public-schema-and-generation-contract).
Use installed Fight Common `Validation` and `RulesParser` directly where they express the contract; do not patch
vendor or clone parser policy. Record gaps or unsupported rule semantics rather than emitting misleading rules.
Keep attribute discovery, artifact storage and HTTP adaptation in appropriate Adapter boundaries; only introduce
inward capabilities where an actual read/policy boundary justifies them under ADR 0001.

Define exact schema version, bounded form/field identifiers, safe rule/message arguments, deterministic ordering,
revision identity, file/catalog integrity and safe HTTP status/cache/content-type contracts before publishing.
Use the existing JSend and snake_case conventions. Return no form values, private metadata, user existence,
provider identifiers or machine paths. Resolve names from a catalog, not arbitrary path concatenation; reject
traversal, encoded separators, oversized names and unsafe field keys. No anonymous enumeration endpoint is needed.

The single read Action is explicitly public: no Bearer or `VIEW_DASHBOARD` prerequisite. It accepts no mutation
or credential data, does not authorize any named form operation, and grants no new CORS access. Document its
Action identity for TASK-00117's explicit public allowlist. Do not implement or relax that future JWT guard here;
prove current behavior and leave later composed security evidence to its owner.

Generated artifacts stay outside `public/`, ignored source caches and secret directories. Give deployment an
explicit artifact packaging/generation requirement and safe runtime failure when absent/corrupt; do not generate
at request time or silently serve partial/empty rules. An intentionally empty **complete** catalog before real
form registration is valid and differs from missing/corrupt output. Future forms register only when their owning
operations exist; no fabricated endpoint or test-only attribute class is needed to claim positive export evidence.

      publication requires an explicit allowlist beyond `formName` and excludes private/server-only constraints.
- [ ] AC-2: Explicit Docker CLI produces versioned deterministic complete generations, rejects ambiguous names or
      unsupported safe projection, replaces obsolete output coherently and preserves prior output on failure.
- [ ] AC-3: The real API-v1 read Action returns only allowlisted safe schemas without authentication/permissions,
      business writes, user lookup or cookies; no static path or unbounded file read exposes other artifacts.
- [ ] AC-4: Malformed/unknown names, missing/corrupt/unsupported catalog states and method failures have bounded,
      safe documented outcomes; missing rules never become a valid empty schema.
- [ ] AC-5: The schema supports explicit field mapping, multiple public error messages, supported comparison
      dependencies and content/schema revision; no PHP code or arbitrary regex is executable client input.
- [ ] AC-6: Server-side validation remains authoritative; this read exemption never weakens operation permissions,
      credential-flow protections or future JWT-default enforcement.
- [ ] AC-7: OpenAPI describes only the actually implemented read contract. Export/install/read instructions state
      artifact provenance and limits; no future authentication form or positive real-attribute export is invented.
- [ ] AC-8: Direct exporter checks, owned HTTP/catalog behavior and important integration-contract checks pass;
      planning validation, diff check and `./bin/build` pass with fresh counts, warnings and unavailable proof.
