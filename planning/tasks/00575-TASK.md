# Cut registration and inspection over to Project-owned CQRS

## Outcome

Replace the current registration-shaped model and mixed Store with Project-owned CQRS across creation,
inspection and advisory conflict reads. Deliver the second complete cutover of
[TICKET-00134](../tickets/00134-TICKET.md), normally one PR, including Domain, persistence, handlers, actual entry
admission, presentation, owned consumers, tests/docs and removal. Do not split writes and reads into layer PRs
requiring temporary adapters around the rejected model.

## Scope

- Implement the coherent Project root, ProjectId, value objects and collection-like ProjectRepository under the
  approved aggregate-first ownership. Preserve one collaboration/publication target per Project in its Workspace,
  optional primary/equivalent Git-source facts, normalization, fork distinctions, metadata and needed history.
  Host, Checkout and Worktree stay separate. The repository returns declared aggregates, not registration payloads,
  HTTP responses, original results or unrelated Workspace/limiter behavior.
- Provide Domain-owned RegisterProject, a registered RegisterProjectHandler and ProjectRegistered. Entry adapter
  generates the typed ID before void CommandBus dispatch and derives trusted actor/Workspace context. Handler
  coordinates aggregate behavior, persistence and required audit through the qualified generic transaction boundary;
  success facts publish only after commit. No mutable command result, private handler invocation or inferred audit.
- Deliver registered GetProjectById/ListProjects-style queries and the existing advisory conflict preview together.
  Produce safe typed ProjectView/page/conflict results as justified, including relevant source facts, deterministic
  bounded pagination and explicit required absence. Queries cause no business mutation, audit-success event or
  implicit bootstrap; metadata is not proof of a linked or available checkout.
- Move actual HTTP operation/Workspace-scope authentication/admission and mapping to adapters. Preserve current
  independently justified access and validation outcomes; remove RegistrationAccess/Application admission wrappers
  and locks/tests used solely for ordinary permission-revocation/commit serialization. Retain genuine business
  uniqueness, expected-state consistency and needed locking rather than deleting all fences indiscriminately.
- Use authoritative database uniqueness and safe recognized conflicts for Workspace/source/slug claims. Keep
  Project state, source claims and required audit atomic on the same connection; audit failure rolls back creation.
  Unknown infrastructure/commit failure is not a safe uniqueness conflict, and post-commit failure is not rollback.
- Replace ordinary-create idempotency input, immutable original-response snapshots/journals and replay-only
  machinery with the approved conflict/fresh-query contract. After response loss a new creation may conflict;
  authorized fresh list/detail reads reveal authoritative Project/ID. Required audit/correlation/history is not
  discarded merely because it shares tables or foreign keys with obsolete result bookkeeping.
- Reconcile the primary projects table and related sources/relationships/constraints, identifiers, permission
  vocabulary, routes, API input/Data/Responders, generated OpenAPI and actual owned callers together. Use descriptive
  camelCase PHP collaborators/Views and transport-owned snake_case/status/headers. No aliases, dual endpoints,
  legacy mode or deprecation machinery solely for application compatibility; no unapproved product UI.
- Preserve needed existing identities, source facts, grants/access meaning and audit history through explicit
  generated migrations and deliberate consumer changes. Establish real current data needs and default to
  preservation; only explicit authorized disposal permits loss. Do not rewrite applied migration history.
- Qualify any required available canonical Common failure contracts and deliberate dependency changes in this real
  path. Required absence, validation/Domain refusal, known conflicts and internal faults must work through the
  existing centralized error owner, with only necessary explicit safe mappings and agreed wire contracts. Coordinate
  full shared-boundary replacement with TICKET-00136; do not create a competing classifier, wrapper or error framework.
- Delete remaining RegistrationStore/PostgresRegistrationStore, accidental RepositoryRegistration model,
  command-shaped services, obsolete input/result/replay types, tests and superseded routes after replacement proof.
  Reconcile affected current architecture/runbooks and direct executable dependency rules with their owning tools.

Excludes checkout linking/relinking, new lifecycle/source-edit/access writers, project generation, Planning cutover,
Agent/Runner/Execution or publication authority. Existing product TICKETs retain those unfinished features.
TASK-00574 owns explicit Workspace/reference prerequisites; TICKET-00132 owns the complete unfinished-plan repair.
No blanket ORM replacement, guessed supplier API, generic replay/outbox platform or sibling package mutation.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Authorized entry registers a Project | ID-bearing RegisterProject through configured CommandBus; void | Existing advisory preview only where useful | ProjectRegistered after commit | Project, canonical source claims and required audit commit together; known ID can be returned |
| User reconciles a lost creation response | A new attempt may safely conflict; no original-response replay | Fresh ListProjects/GetProjectById | None from reads | Authoritative Project and ID are visible under fresh independent read admission |
| User inspects a Project or bounded page | N/A; read-only | Registered scoped detail/list queries | None | Safe typed Views, deterministic pagination, intentional absence and no physical authority |
| User previews source/slug conflicts | N/A; advisory read | Existing preview intent as a registered query | None | Safe bounded conflict kinds without another Project's private identity or a reservation |

## Validation and permissions

Apply TASK-00564's approved contract and the Workspace boundary from TASK-00574. Each actual entry establishes a
trusted actor, validates transport shape and performs current operation/Workspace-scope admission; no client field
asserts actor, timestamp, revision or authority. Domain values own metadata/source rules. Registration grants no
Project access, physical link, Planning, Agent, Runner or publication authority. Read/register permissions remain
independent. An ordinarily admitted request may finish after revocation; subsequent requests check afresh.

Keep credentials/private source material out of Views, audit, exceptions and diagnostics. Preserve real business
invariants and needed data/history. The conflict/fresh-query contract does not weaken separately justified physical
or remote recovery in other product owners. This is a planned architectural cutover, not a declared bug repair.
