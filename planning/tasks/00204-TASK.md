# Start classified normal work from the terminal

## Outcome

One deliberate authorized terminal request for a selected normal TASK runs Triage preflight and, when current,
starts the existing single-TASK Team Lead → Software Engineer Workflow **without another normal-route
confirmation**. It returns the authoritative Workflow identity and actual state or a safe refusal. This is one
independently reviewable end-to-end terminal start use case, not a new claim/dispatch mechanism.

## Scope

- Consume [TASK-00201](00201-TASK.md)'s typed Jev recommendation or labeled declared-kind normal fallback
  and [TASK-00202](00202-TASK.md)'s current human disposition for any material conflict. Match the supported
  category deterministically to [TASK-00203](00203-TASK.md)'s initial catalog and resolved Repository base.
  No second Jev route selector, queue scan, priority reorder or automatic hotfix inference. Unsupported,
  unresolved or stale advice stops before start; a valid fallback does **not** require a second normal prompt.
- Extend the existing terminal entry path from [TASK-00139](00139-TASK.md), not a new command authority: a
  single authorized request binds selected TASK, actor, grant, profile, budgets, expected Planning/context,
  Repository configuration/catalog and route/base. Preflight itself cannot claim or create a Workflow. Call
  the **same** authoritative PHP Start coordinated work operation that TASK-00139 established and TASK-00141
  uses for Team Lead → Software Engineer. That operation revalidates canonical TASK eligibility, live direct
  Permissions and grant, active ownership, source/base, role availability, budgets, revisions and resource
  readiness at atomic claim; it alone writes Workflow, dispatch intent and exclusive claim.
- Return safe accepted/preparing, refused, Needs Human or existing-owner/current-Workflow outcomes, with
  bounded classification/fallback/disposition and route/configuration provenance. Same-command retry returns
  the same Workflow; a different competing command does not create another claim or launch. Recover unknown
  dispatch results through the owning Workflow operation, never by retrying an unobserved provider effect.
- No new branch strategy confirmation or routine normal-work prompt. This later extension does not alter the
  approved first Team Lead execution slice. Hotfix confirmation, emergency transfer, release and deployment
  belong to other TICKETs. A terminal selection or recommendation is **not** a successful status transition.
