# Add a resumable Pi package release skill

## Outcome

A portable Pi `release` skill accepts a version, discovers the actual release stage, and coordinates package
documentation, branch preparation, certification, human signing, publication, Packagist observation and merge-back.
John's existing global Pi skill path makes it available when working in Fight Common and Fight Access Control.

## Scope

- In scope: Original skill instructions, conditional references, concrete per-release terminal signing-script
  requirements, index/role inventory updates and direct discovery/instruction qualification.
- Out of scope: Performing a release, modifying either package, installing software or changing global settings,
  creating a second certifier, production deployment, managed Runner execution or TASK-00138–00142 completion.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Discover or resume a version | Skill invocation; target-owned tooling when authorized | Local policy, canonical planning, refs, receipts, provider state | N/A: instruction resource | Scoped release work and evidence only within existing authorization |
| Prepare human signing | Generate a release-specific script after verifying the candidate | Exact commit, receipt, signer and remote identities | N/A | Ignored operator handoff; signer secrets remain in the terminal |

## Validation and permissions

Follow the target repository's accepted release policy and tooling. Existing approval persists; a version alone
does not grant every publication effect. Unknown provider state is not absence. Preserve published tags, unrelated
work and signer custody. Report incomplete checks and distinguish package metadata from installed-consumer proof.

## Acceptance criteria

- [x] Discover and resume partial releases without restarting completed effects; handle contradictions explicitly.
- [x] Cover documentation chronology, release branch/PR, exact final-commit certification, human signed annotated
  tags, separate tag push/GitHub publication, Packagist observation, merge-back and owned cleanup.
- [x] Derive certification schemas and asset requirements from the target; preserve Fight Common's zero-asset
  option and Access Control's distinct evidence format without importing one package's policy into another.
- [x] Specify a concrete per-release signing script with identity/evidence checks, separate sign/push modes,
  safe recovery and terminal-only secrets; no live script is generated for an uncertified candidate.
- [x] Verify Pi discovery through the existing global path from both package directories, metadata/links,
  representative success/failure instruction walkthroughs, planning checks and the full build.
