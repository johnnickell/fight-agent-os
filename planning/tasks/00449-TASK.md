# Display the existing main-checkout Docker logs in the terminal workspace

## Outcome

Deliver [TICKET-00110](../tickets/00110-TICKET.md)'s lower-right live log pane using the Docker logs available
from the existing main-checkout Agent OS runtime. No planned logging backend or isolated-worktree containers
are required.

## Scope

Provide a fixed trusted local adapter for Docker Compose log reads, with an explicit operator-selected runtime,
validated service selection, bounded initial tail, live follow, pause/resume and bounded scrollback. Reuse Docker's
existing output; show available service/timestamp detail and preserve emitted text except terminal-control
escaping needed for safe rendering. Choose and document finite line/byte/buffer/reconnect limits within this TASK.
Do not change application instrumentation or imply complete history or log coverage.

Display the main-checkout runtime as shared. Switching worktree or child observation context retains the selected
runtime and its visible source identity; do not silently derive a different Compose project from the current
working directory. No task/worktree filtering is required, and untagged output is not attributed by inference.
Use explicit trusted local configuration for the selected Docker context/project and main checkout, verified
against actual source identity. This preference selects an observation source; it creates no ownership registry
or Workflow grant. Ignore repository/model attempts to redirect it. Persist non-secret preference/runtime state
under the owning ignored `var/` boundary, not execution scratch.

Exclude per-worktree containers, Compose overrides, automatic worktree-to-runtime switching, container lifecycle
commands, full-text search, collector/backend deployment, new instrumentation, archives, retention changes,
browser integration and registered-project log collection. These are separate work; do not allocate speculative
TASKs or introduce a dependency on the active observability map. TASK-00140 retains managed runtime preparation.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| View existing Agent OS logs | Select explicit runtime and service; follow/pause/resume | Fixed bounded Docker log read and availability | Container output only, not Workflow authority | Trusted host reader and bounded UI buffer |
| Change worktree context or close pane | Existing context selection; close pane | Visible selected runtime identity | N/A — local presentation | Same shared source across worktrees; closing stops reader only |

## Validation and permissions

The local human operator uses existing Docker authority through a trusted host adapter. Invoke a fixed log-read
operation with validated argument values, no shell interpolation or arbitrary Docker/Compose option passthrough.
Resolve the intended main-checkout source explicitly rather than executing untrusted worktree configuration.
Do not expose the Docker socket, Docker credentials, arbitrary commands or pane contents to agent tools, child
environments or model context. Docker daemon permission is generally powerful; this adapter's read-only behavior
is not a new Docker authorization boundary. No browser or remote log endpoint is introduced.

Treat output as untrusted data: neutralize terminal control/escape actions, handle malformed/oversized records,
and bound buffering, process lifetime and reconnect attempts. Missing Docker, denied access, stopped source and
lost history yield honest states, never automatic startup, privilege escalation or fabricated success. A paused
view may retain only the bounded recent window; display any truncation/gap. Closing the pane terminates only its
log reader. Preserve emitted diagnostic content; do not introduce a conflicting logging/redaction policy.

## Acceptance criteria

- [ ] The actual existing main-checkout Agent OS Compose output appears with finite initial tail, live follow, service choice, pause/resume and bounded scrollback.
- [ ] Runtime/service identity is explicit; changing worktree context keeps the shared-runtime label and does not claim isolated logs or silently switch Compose projects.
- [ ] Empty/stopped source, Docker unavailable/denied and interrupted stream show useful states; reconnect gaps or duplicate limits are honest.
- [ ] High-volume/oversized output stays bounded and responsive; truncation is visible and terminal control content cannot execute display actions.
- [ ] Closing the pane stops its reader while containers and agents continue unchanged; no observation operation creates, restarts or reconfigures containers.
- [ ] The actual tool/child boundary exposes no generic Docker/shell capability or automatic log ingestion into model context.

## Verification and evidence

Test owned source selection, fixed-operation validation, stream lifecycle, hostile content and bounded buffer
behavior. Qualify the owning Docker tool directly against the existing source and capture actual terminal
Before/After behavior. No container is started merely to make the display appear successful; unavailable live

observed source/limitations without recording secrets. See the
[Docker Compose logs reference](https://docs.docker.com/reference/cli/docker/compose/logs/) for supported tail,
follow, timestamp and service arguments; qualify the installed tool at implementation.
