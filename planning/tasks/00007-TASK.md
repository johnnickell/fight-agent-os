# Adopt and prove the stable dependency graph

## Outcome

Fight Agent OS resolves and installs a committed stable dependency graph using Fight Common `~1.2.0` and Fight Access Control `^0.2.0`. The canonical build proves strict manifest validity, locked installation, advisory status, application tests, planning validity, and a development-package-free production install without candidate-reference or lowest-version machinery.

## Scope

- In scope: Replace Fight development references with approved stable constraints; set stable minimum stability; update and commit the compatible lock; remove obsolete candidate commit-reference validation; make `./bin/build` prove strict Composer validity, locked development installation, advisory audit, planning validation, PHPUnit, and clean `--no-dev` installation; record fresh install and audit evidence.
- Out of scope: Application behavior changes, inherited support-test removal, production source-contract redesign, upstream package changes, unreleased dependency exceptions, lowest-version lanes, broad dependency pruning, and the complete quality-tool expansion owned by TICKET-00013.

## Validation and permissions

`composer.json` must require Fight Common `~1.2.0`, Fight Access Control `^0.2.0`, and stable minimum stability. The committed lock must resolve compatible stable releases and pass content-hash validation. The canonical build must install from the lock without an update, run `composer validate --strict`, run `composer audit --locked --no-dev`, preserve read-only planning validation and PHPUnit, and prove a clean production install excludes development packages.

Remove `scripts/validate-composer-candidate.sh` and every invocation only after confirming no remaining candidate identity contract needs it. Do not restore commit-reference exceptions, support-receipt generation, or lowest-version locks/lanes. Do not suppress Composer warnings or advisory/network failures; record their exact effect on verification.

No runtime permission model applies. Repository dependency, lock, wrapper, and build changes are authorized. Upstream repositories, product behavior, broad provider pruning, and unreleased refs are not authorized.
