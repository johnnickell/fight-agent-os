# Work in the responsive Pi terminal workspace

## Outcome

Deliver [TICKET-00110](../tickets/00110-TICKET.md)'s usable local Pi conversation with independently focused side
panes, without requiring Herdr or tmux. This bounded local presentation slice has no external TASK blocker.

## Scope

Implement the wide half/quarter/quarter layout, keyboard focus, bounded pane scrolling, resize behavior, textual
identities and narrow selectable-view fallback. Reuse existing Fight branding. Side panes display honest
empty/unavailable states until TASK-00448 and TASK-00449 attach their respective producers.

Qualify the currently installed Pi's supported APIs against the actual persistent layout and input requirements.
If extension APIs cannot support it cleanly, deliver a dedicated terminal client over supported Pi SDK/RPC
capabilities. Never pin Pi to a version number or require version equality. Document the selected integration,
required capabilities and actual tested version as evidence; do not infer future compatibility from that version,
fork Pi, nest a second renderer in its extension or replace its agent/provider/session machinery. Qualification is
part of this usable product slice, not a separate demonstration TASK. Preserve current Harness policy hooks and
normal input paths.

Exclude managed connection/linked-continuation integration owned by TASK-00325, durable attachment owned by
TASK-00352, new agent orchestration, Docker operations and global package/configuration changes. Later managed
integration must consume those owners without claiming it as completed local behavior here.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Converse while viewing side panes | Existing Pi input; focus/view selection | Local conversation and pane identity | Existing Pi lifecycle notifications; no new business event for rendering | Existing authorized conversation input and local presentation changes |
| Resize or close workspace | Resize, collapse/restore, existing exit | Current terminal dimensions and local session state | N/A — local presentation lifecycle | Restore terminal and subscriptions; preserve normal Pi exit behavior |

## Validation and permissions

Preserve enrolled tool policy, file screening, provider handling and session boundaries through the actual entry
point. RPC does not authorize shell access. Display active conversation target separately from observation
context; changing pane focus must not redirect input to an agent or alter its directory/grants. Persist only
non-secret local presentation state under the owning ignored `var/` boundary, never `.runs/` runtime state.

## Acceptance criteria

- [ ] A real primary Pi conversation remains usable with the requested persistent layout and truthful side-pane placeholders.
- [ ] Keyboard input reaches only the intended interactive target; read-only panes cannot submit agent commands.
- [ ] Wide/narrow terminals, resize, long lines, Unicode, themes and pane scrolling remain readable and bounded.
- [ ] Normal exit and rendering errors restore terminal state; existing local session semantics remain explicit.
- [ ] Actual policy/file-screening hooks still run through the qualified entry point; credentials are not copied into UI state or child environments.
- [ ] Actual tested Pi version (evidence only, never a pin), selected extension or SDK/RPC route, required capabilities, limitations and real terminal evidence are recorded.
