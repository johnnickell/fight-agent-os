# Retrieve separately authorized public pages

## Outcome

An authorized Agent can retrieve one bounded selected public page through the protected first-party capability,
with connection-level SSRF enforcement and exact-content screening before release. Search results, local file
access and allowed shell roots never confer retrieval authority.

## Scope

- In scope: Independently permissioned retrieval Tool/application Query, URL/destination policy, actual connection
  and redirect enforcement, bounded safe extraction, screened delivery, provenance and interruption handling.
- Out of scope: Search, arbitrary proxying, authenticated/private-site browsing, crawling, browser automation,
  executing page code, unrestricted shell network and retained/cached/resumed delivery before TASK-00384.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Retrieve selected public page | N/A — application Query | Current retrieval/disclosure scope and exact bounded URL | Sanitized request/destination/coverage observations | Bounded external HTTP read plus authorized Jev evaluation |
| Follow a permitted redirect | Continuation of the same bounded request, not new authority | Every resolved connection destination and remaining aggregate limits | Safe checked-chain provenance | Only the qualified allowed target is contacted |
| Deliver page representation | N/A — bounded result | Exact extracted representation, digest/coverage and admission | Delivered/partial/withheld facts | Only screened permitted source reaches Agent; links cause no automatic calls |
| Inspect or stop original request | Existing cancellation; read-only status inspection | Original request/outcome and current generation | Actual cancellation/outcome facts | No provider replay or inference of unsent/unbilled work |

## Validation and permissions

Consume TASK-00381 and the shared protected broker/MCP/current-authority path transitively, without depending on
TASK-00382 search. Require explicit intent-specific retrieval Permission, applicable delegation, actual assignment/
Repository/environment, host and independent outbound disclosure checks before every request. URL query fields,
referers and headers may disclose sensitive data; minimize them and reject prohibited inputs rather than infer
permission from an Agent-provided link. Apply separate Jev disclosure admission before screening extracted content.

Validate strict supported scheme/host/port and unambiguous canonical URL forms. Enforce policy against every actual
resolved connection address and redirect destination, not just a preflight DNS lookup. Qualify address pinning or an
equivalent effective connection-time defense with TLS host verification intact. Deny loopback, private/link-local,
internal/metadata and other forbidden targets, including alternate IP encodings, IPv4/IPv6 forms, DNS rebinding,
redirect chains and proxy/environment bypasses. Unsupported resolution or ambiguous addresses fail closed.
No arbitrary cookies, credentials, forwarded auth or cross-origin secret propagation.

Bound redirects, total requests, response headers/bytes, decompression, content types, extraction work, elapsed time,
concurrency and aggregate spend/work. Do not execute JavaScript, plugins, fetch embedded resources or follow links
implicitly. Qualify the actual HTTP/parser boundary; a safe-looking URL or response MIME label is insufficient.
Each separately selected page/subpage requires its own current authorization and full gate.

Construct exact bounded source representation before screening, preserving actual fetched identity/time, redirect
provenance, digest and honest coverage. TASK-00381 admits page text and extracted link labels before release; safe
failure output never echoes withheld content. Unsupported/binary/oversized or incomplete pages remain explicit,
not silent truncation certified as whole-page screening. Retained evidence and resumed/cached contexts wait for
TASK-00384; no raw Artifact, persisted-context or direct-network fallback bypasses admission.

Keep request/evaluator/usage correlation and redacted bounded receipts; retain unknown cost instead of zero. Current
revocation/stop/context generations fence new dependent requests and late delivery without claiming retroactive
cancellation of accepted external effects. Any required intent/audit commits through existing owners before external
work; recover original outcomes rather than blindly refetching after timeout or loss. Status reads never repair,
retry, broaden crawl scope or mutate Planning/Workflow state.

## Acceptance criteria

- [ ] Actual authenticated retrieval of a selected permitted public page yields bounded attributable screened
  content; search-only Permission, local access and forged scope cannot authorize it.
- [ ] Actual HTTP connection/redirect handling rejects forbidden addresses, alternate encodings, rebinding and
  unsafe proxy/destination behavior without contacting forbidden live services or exposing credentials.
- [ ] Redirect/body/decompression/extraction/time limits and every separately selected follow-up remain enforced;
  partial/unsupported content is honest and source instructions cannot execute or expand authority.
- [ ] Revocation, interruption and lost results preserve original correlation/liability and withhold stale delivery;
  no unscreened retained/cached/resumed route or hidden refetch is available.
