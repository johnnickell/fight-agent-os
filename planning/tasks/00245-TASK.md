# Enforce current authority throughout first-party MCP discovery and invocation

## Outcome

Compose the existing Common Tool registry/discovery/invoker and package Agent availability with real authenticated
first-party transport and current scope checks. Every exposed list page, invocation and supported retry crosses
the same authority boundary, with truthful unknown/unavailable results and no direct-path bypass.

## Scope

- In scope: Reusable authenticated first-party MCP transport/composition, strict trusted-origin/connection binding,
  package permission metadata and current-use intersection, request/job lifetimes, protected discovery/invocation,
  supported retry handling, safe protocol/diagnostic output and Harness availability integration.
- Out of scope: A second MCP server/origin registry, new protocol or permission catalog, judgment/provider engine,
  arbitrary third-party origins, general interactive workflow, browser bearer fallback or unqualified Pi launch.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Discover available Tools | No business command | Common `tools/list` through `AgentToolAvailability` plus current scope/host checks | No business event for enumeration | Filtered private zero-TTL catalog before ordering/pagination; each later page authenticates anew |
| Invoke one authorized Tool | Common invocation through the same composed availability and actual owning handler | Current authenticated principal, exact all-required Permissions and bounded-use context | Only existing owning Tool events, if any | Protected work only after authority, before validation/handling/progress/disclosure |
| Retry a supported interaction | Existing Common protected retry flow with a fresh signed request | Current authority before protected restoration/confirmation/resume | Owning interaction facts only | Exact authorized continuation or denial; a retained token is not authority |
| Deny unknown/unavailable or alternate path | No protected dispatch | Trusted transport context and complete exposed registry | Safe diagnostic only | Neutral protocol failure; direct/bus/CLI invocation cannot bypass caller/target policy |

## Validation and permissions

Use TASK-00242's single request-bound provider and signed request/correlation across transport, availability and
Tools; no second nonce transaction or singleton principal/filtered catalog. Requirements use the package catalog
bound to the exact Common registry instance and every native `RequiresAgentPermission` declaration on `handle`.
Missing/malformed requirements fail composition; foreign definitions cannot borrow same-name authority. An empty
registry grants nothing. Only genuinely static metadata with the same registry may be reused; request-bound Tools
force their registry/catalog to be rebuilt together. No duplicate Tool list, scanner or permissive default.

Intersect package all-required direct Permissions with TASK-00244's current scope/activation/host admission; a
signed request or discovery result is not later invocation authority. Every page and later call is a new authenticated
request with fresh nonce. Within one admitted request preserve package snapshot semantics without claiming retroactive
cancellation; future uses still observe revocation. For supported interactions, a fresh availability check precedes
state restoration, response validation, confirmation consumption, resume and progress. Unsupported interactive modes
remain unavailable until real state-protection, binding and atomic confirmation owners qualify them.

Bind the transport to the configured host-assigned installation/first-party origin, not localhost, repository input,
redirects or arbitrary URLs. Reuse the existing connection/trust owner. Enforce actual TLS/origin/proxy, body/stream,
header, resource and session limits; no Agent credentials via browser JWT routes or model/child environment. Keep
Common's private `ttlMs: 0` discovery policy and safe cursor-key separation from Agent credentials.

Denied and unknown Tool identities use Common's neutral response before input validation, Tool execution, CQRS,
progress or protected diagnostics. Sanitize the real outer responder/diagnostic sink and command failure subscribers;
never log signed input, arbitrary Tool bodies, original provider throwables or secret-bearing collaborators.
Metadata alone cannot protect direct `handle`/bus access; those paths must use the same current caller/target policy.

## Acceptance criteria

- [ ] Actual authenticated first-party transport uses the shared protected registry/invoker; wrong origin/identity,
  malformed metadata or unsupported participant denies, with no alternate unsigned or bearer route.
- [ ] Listing filters before ordering/limiting; later pages and invocations resolve fresh authority after revocation,
  rotation, Permission/scope changes and restart. No request-bound state leaks across principals/jobs.
- [ ] Direct invocation applies identical permission/scope checks before validation/handling/progress; unknown and
  denied names conceal protected details. Direct/CLI/bus alternatives cannot bypass current policy.
- [ ] Supported retries use fresh signed requests and current authority before protected restoration/consumption;
  valid old tokens cannot rescue revoked authority. Unqualified interaction modes remain unavailable.
- [ ] Harness unavailable/revoked states are truthful and safe, without cached authority or fallback tools. Actual
  protocol/error/log surfaces disclose no credentials, claims, signed bodies or raw invocation data.
