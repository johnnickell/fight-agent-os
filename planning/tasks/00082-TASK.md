# Resolve deterministic repository context snapshots

## Outcome

One permission-controlled application query deterministically resolves a lean immutable versioned `RepositoryContextSnapshot` and size-capped prompt projection from registered identity, designated-checkout evidence, current Repository configuration, non-overridable application restrictions, observed Git state and recognized Pi instruction paths/digests without copying instruction contents or inventing authority.

## Scope

- In scope: Closed snapshot schema and version; generated snapshot identity/revision/token; Workspace/Repository/Host/Checkout/Worktree/source bindings; configuration revision and planning mode; base/branch/current Git guidance; ordered named verification checks; application restrictions; recognized instruction paths/content digests/provenance; optional owned reference sections; availability/warnings/recognized conflicts; injected registration/configuration/Git/instruction-discovery/time capabilities; deterministic resolution and bounded projection; projection-size diagnostics; safe complete and prompt Views; viewing permission; versioned API/OpenAPI; unit/integration/functional evidence.
- Out of scope: Editing configuration or files, parsing arbitrary prose into policy, persisting session choices, drift enforcement after binding, silent context refresh, Pi/MCP transport/injection, browser UI, full instruction contents in snapshots/prompts, Planning cutover, Workflow/Runner limits not implemented, arbitrary plugin data and claiming operating-system sandbox authority.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Resolve registered context | N/A — read-only resolution | `ResolveRepositoryContext` | N/A — resolution emits no Domain event | One immutable typed snapshot and bounded projection are created/returned from the same exact observations |
| Inspect complete context | N/A — read-only interaction | Get safe snapshot detail/provenance by authorized binding | N/A — reads emit no Domain event | Detailed identities, revisions, provenance, warnings and conflicts remain outside model prompt context |
| Render prompt projection | N/A — deterministic representation | Project an exact snapshot under the declared size limit | N/A — representation has no side effect | Model receives only useful guidance and a short revision token, not UUIDs, services, secrets or duplicate instruction text |
| Refuse unresolved authority | N/A — failed resolution | Explain missing/ambiguous registration, checkout, mode, branch or verification facts | N/A — failure emits no Domain event | Non-interactive resolution fails with safe actionable diagnostics rather than guessing |

## Validation and permissions

Resolve from one active authorized Repository and its current configuration revision. Require the exact designated Worktree/Checkout/Host link and current availability from TICKET-00024 for registered modes. Revalidate approved-root containment and safe Git observations through existing capabilities; do not use client-supplied paths, identities, branch facts, instruction lists or authority.

Use a closed schema containing only accepted current concepts. Optional future sections are absent unless their owning capability exists; do not manufacture Workflow limits, tracking endpoints, Runner state or plugin payloads. Record schema version, snapshot revision/token, resolution time and provenance deterministically. Same normalized inputs, injected clock/ID and contract version must yield equivalent semantic snapshots and projections.

Compose precedence exactly as WF-009: application safety/live authorization are non-overridable; registered configuration may preserve or narrow them; local instructions and Skills may guide more strictly but cannot grant application Permission or widen structured authority. Compare only explicitly recognized structured fields such as planning mode, branch/base rules and required verification. Record ordinary Pi instruction files as ordered recognized paths and content digests/provenance. Do not parse arbitrary prose with an LLM/regex into enforceable rules or claim complete conflict detection.

Support explicit unregistered/local, registered/Markdown-authoritative and registered/database-authoritative representations. Unregistered/local has no registered Repository Planning/Execution authority. Registration alone does not switch modes. Database mode is valid only after TICKET-00028's authoritative state says so. Missing services or inconsistent mode fail visibly rather than falling back.

The bounded prompt projection includes safe repository display, planning mode, active branch/base guidance, named verification checks, active restrictions, unresolved recognized conflicts/warnings and a short revision token. It excludes raw UUIDs where unnecessary, credentials, service URLs, filesystem details not needed by the model, complete instruction contents and arbitrary plugin data. Apply deterministic item/byte limits and report truncation/size diagnostics outside the projection; never truncate in a way that hides a restriction/conflict or changes meaning. Fail safely if mandatory content cannot fit.

Require authoritative permission to view registered context, with Repository/Workspace scope and lifecycle checks. Safe complete Views may expose more provenance than the prompt only where authorized. HTTP uses the shared API/JSend/OpenAPI/error boundaries. Resolution itself mutates no configuration, Repository, Git, instruction, Planning or execution state; any persisted immutable binding belongs to TASK-00083.

## Acceptance criteria

- [ ] One `ResolveRepositoryContext` query returns a closed versioned immutable snapshot and deterministic prompt projection from the same exact observations.
- [ ] Snapshot binds current Workspace, Repository, source, Host, Checkout, Worktree, configuration revision, planning mode, Git guidance, checks, restrictions, instruction digests, provenance, conflicts and availability.
- [ ] Application restrictions/live authorization cannot be overridden; registered/local guidance may only preserve or narrow structured authority.
- [ ] Only recognized structured conflicts are classified; arbitrary instruction prose is not parsed or promoted to application policy.
- [ ] Instruction provenance records ordered paths/digests without duplicating complete file contents in snapshot projection or model prompt.
- [ ] Unregistered/local, registered/Markdown and valid registered/database modes remain explicit and never transition or fall back automatically.
- [ ] Missing/archived/unauthorized Repository, undesignated/unavailable checkout, invalid mode, ambiguous branch/check or changed observations fail with safe reasons rather than guessing.
- [ ] Prompt projection is deterministic and size-capped without omitting mandatory safety/conflict meaning; diagnostics disclose bounded size/truncation outside the prompt.
- [ ] Permission-filtered API Views and prompt projection contain no secrets, credential locators, unnecessary UUIDs/paths, service URLs or arbitrary plugin data.
- [ ] Focused resolution/precedence/determinism/integration/API/redaction tests, direct Pi-discovery comparison and the canonical build pass.
