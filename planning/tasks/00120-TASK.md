# Guard user soft deletion and restoration

## Outcome

Explicitly confirmed installation-wide user deletion/restoration uses Fight Access Control's reversible lifecycle commands, preserves last-admin authority and audits actual outcomes without leaking credentials.

## Scope

- In scope: `DELETE /api/v1/users/{userId}` and `POST /api/v1/users/{userId}/restore`, exact `DELETE_USERS`/`RESTORE_USERS`, FQCN Actions, Agent OS target/actor authorization, confirmation and revision, package `DeleteUser`/`RestoreUser`, safe View/OpenAPI and audit.
- Out of scope: Hard delete, implicit restore on invite, active-email replacement, generic `UPDATE_USERS`, bulk mutation, session-admin shortcut or password/token disclosure.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Delete user | `DeleteUser` through checked Application service | Current actor/target/last-admin state | Package lifecycle event and safe audit | Only eligible user becomes deleted; existing sessions cease to authorize |
| Restore user | `RestoreUser` through checked Application service | Current actor/target/conflicting identity state | Package lifecycle event and safe audit | Eligible user restores under package conflict policy, no automatic new credentials |

## Validation and permissions

Use the early route gate and authoritative respective `SUPER_ADMIN_ONLY` permission in Agent OS Application on **every** path. Protect self/last-admin/managed authority, require deliberate confirmation and optimistic revision, and defer to package lifecycle, reservation and session invalidation invariants. Check conflict/race against current PostgreSQL state in the same authorized operation. Redact credentials, deleted identity internals and audit secrets; do not imply that restore reactivates a session. Package handler permission checks may change at v0.4.0; never rely on them.

## Acceptance criteria

- [ ] Exact permission/confirmation/target guard denies forbidden, stale, self and last-admin transitions before mutation.
- [ ] Delete/restore have package-valid, atomic, audited effects with safe conflict and no unauthorized session revival.
- [ ] FQCN Actions/Views/OpenAPI and UI state are truthful without hard-delete claims or secret leakage.
- [ ] Focused lifecycle/race/session/HTTP/PostgreSQL/redaction checks and `./bin/build` pass with warnings recorded.

## Verification and evidence

Exercise pending/active/disabled/deleted/restored, stale revision, identity conflicts, concurrent admin transitions, last-admin count and session authority after delete/restore. Inspect durable audit and safe output with owning PostgreSQL/HTTP tools; run `./bin/planning-check`, `git diff --check` and `./bin/build` and record actual evidence.
