# Guard user soft deletion and restoration

## Outcome

Explicitly confirmed installation-wide user deletion/restoration uses Fight Access Control's reversible lifecycle commands, preserves last-admin authority and audits actual outcomes without leaking credentials.

## Scope

- In scope: `DELETE /api/v1/users/{userId}` and `POST /api/v1/users/{userId}/restore`, exact `DELETE_USERS`/`RESTORE_USERS`, FQCN Actions, Agent OS target/actor authorization, confirmation and revision, package `DeleteUser`/`RestoreUser`, safe View/OpenAPI and audit.
- Out of scope: Hard delete, implicit restore on invite, active-email replacement, generic `UPDATE_USERS`, bulk mutation, session-admin shortcut or password/token disclosure.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Delete user | Package `DeleteUser` through configured CommandBus after entry admission | Current actor/target/last-admin state | Package lifecycle event and safe audit | Only eligible user becomes deleted; existing sessions cease to authorize |
| Restore user | Package `RestoreUser` through configured CommandBus after entry admission | Current actor/target/conflicting identity state | Package lifecycle event and safe audit | Eligible user restores under package conflict policy, no automatic new credentials |

## Validation and permissions

Every actual entry adapter authenticates its caller and checks the respective `SUPER_ADMIN_ONLY` permission, target/scope, deliberate confirmation and optimistic revision before configured bus dispatch. HTTP admission is declared once on its Action, not repeated in Application. Follow the [canonical timing contract](../../docs/engineering/STANDARDS.md#entry-admission-and-authorization-timing): an ordinary admitted request may finish after permission revocation; later requests check fresh authority. Preserve self/last-admin/managed-authority business safeguards and package lifecycle, reservation and session invariants with their owners. Registered handlers coordinate supported package persistence and required audit atomically on one shared generic transaction; conflict/race consistency is not replaced by a preflight or nested consumer transaction. Redact credentials, deleted identity internals and audit secrets; do not imply that restore reactivates a session. Package handler permission checks may change in the qualified release; never rely on them or a prospective version number.

## Acceptance criteria

- [ ] Exact permission/confirmation/target guard denies forbidden, stale, self and last-admin transitions before mutation.
- [ ] Delete/restore have package-valid, atomic, audited effects with safe conflict and no unauthorized session revival.
- [ ] FQCN Actions/Views/OpenAPI and UI state are truthful without hard-delete claims or secret leakage.
- [ ] Focused lifecycle/race/session/HTTP/PostgreSQL/redaction checks and `./bin/build` pass with warnings recorded.
