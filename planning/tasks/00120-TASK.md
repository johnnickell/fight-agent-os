# Guard user soft deletion and restoration

## Outcome

Explicitly confirmed installation-wide user deletion/restoration uses Fight Access Control's reversible lifecycle commands, prohibits self-deletion and audits actual outcomes without leaking credentials.

## Scope

- In scope: `DELETE /api/v1/users/{userId}` and `POST /api/v1/users/{userId}/restore`, exact `DELETE_USERS`/`RESTORE_USERS`, FQCN Actions, Agent OS target/actor authorization, current-state confirmation, package `DeleteUser`/`RestoreUser`, safe View/OpenAPI and audit.
- Out of scope: Hard delete, implicit restore on invite, active-email replacement, generic `UPDATE_USERS`, bulk mutation, session-admin shortcut or password/token disclosure.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Delete user | Package `DeleteUser` through configured CommandBus after entry admission | Authenticated actor and target identity | Package lifecycle event and safe audit | Only eligible user becomes deleted; existing sessions cease to authorize |
| Restore user | Package `RestoreUser` through configured CommandBus after entry admission | Current actor/target/conflicting identity state | Package lifecycle event and safe audit | Eligible user restores under package conflict policy, no session revival; pending restoration may issue package-required activation authority without disclosure |

## Validation and permissions

Every actual entry adapter authenticates its caller and checks the respective `SUPER_ADMIN_ONLY` permission, target/scope and deliberate current-state confirmation before configured bus dispatch. HTTP admission is declared once on its Action, not repeated in Application. Follow the [canonical timing contract](../../docs/engineering/STANDARDS.md#entry-admission-and-authorization-timing): an ordinary admitted request may finish after permission revocation; later requests check fresh authority. Prohibit self-deletion and preserve package lifecycle, reservation and session invariants with their owners. No displayed whole-account revision, new entity revision, administrator-count prerequisite or atomic cross-target last-admin decision is required for this TASK; concurrent admitted administrators may delete each other. Registered handlers coordinate supported package persistence and required audit atomically on one shared generic transaction; conflict/race consistency is not replaced by a preflight or nested consumer transaction. Redact credentials, deleted identity internals and audit secrets; do not imply that restore reactivates a session. Package handler permission checks may change in the qualified release; never rely on them or a prospective version number.
