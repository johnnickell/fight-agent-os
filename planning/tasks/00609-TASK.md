# Use one pane-width calculation in the Pi workflow dialog

## Outcome

Make the workflow dialog easier to maintain by keeping pane layout and frame drawing in agreement. Preserve the vendored engine's workflow inspector alongside the [accepted local Pi integration](../tickets/00130-TICKET.md); this does not enable it in the Fight profile.

## Scope

- In `harness/pi/vendor/pi-subagents/src/ui/workflow-dialog.ts`, calculate pane widths once and reuse them for layout and frame drawing.
- Extract selected-agent detail rows into a private renderer only if the layout still reads more clearly that way. No separate module, layout redesign, or changes to actions or runtime controls.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Inspect a workflow | Existing menu, fleet route, and dialog keys | Selected agent, progress, and terminal display width | Existing dialog action callbacks | Keep rows within their panes and target actions at the same selected agent |

## Validation and permissions

Retain visible-width measurement, clipping, and action availability. No new permissions, runtime state, or installation changes.

## Acceptance criteria

- [ ] Frame, titles, and rows use the same measured pane widths.
- [ ] Narrow widths, wide characters, expanded prompts, and selected-agent actions retain their behavior. Record the decision on the optional detail renderer.

## Verification and evidence

Run `workflow-dialog.test.ts` and `workflow-dialog-open-agent.test.ts`, and inspect narrow and wide terminal renders for unchanged layout. Run the engine typecheck and `./bin/build`, then hand off for independent Review and applicable visual and behavioral QA.
