# Persist recoverable delivery and maintenance state

## Outcome

Complete the operation repository's delivery/maintenance persistence and bounded authoritative discovery so
package recovery can resume exact original work after restart without stale completion, material resurrection,
page-based key accounting or runtime repair during reads.

## Scope

- In scope: Schema/adapters for full expected-state delivery/maintenance replacement; claims, monotonic attempt
  fences, policy, lease/admission deadlines and epochs, retry/failure, receipts, key references and cleanup state;
  due discovery, maintenance keyset pages and global key-reference counts on the canonical connection.
- Out of scope: New delivery lifecycle policy/queue, scheduler enrollment, actual encryption/rewrapping/sink
  implementation, physical key deletion, UI, controlled restoration or live operation enablement.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Persist claim/admission/outcome | Package-driven `replaceDelivery` in each owning transaction | Current Agent, exact operation tuple/revision, slot reservation and authority epochs | Existing package outcomes only as their public contract specifies | Exact successor persists atomically; old claims/admissions cannot acknowledge changed authority |
| Discover due work | N/A — read-only bounded selection | `listDueDeliveries` for exact original scope/destination, current reservation and due time | N/A — selection has no event or grant | Safe eligible page; obsolete slots excluded before ordering/limit |
| Persist and inspect maintenance | Package-driven `replaceMaintenance`; no command for read | `listMaintenance`, `countDeliveryKeyReferences` and current key write admission | Existing maintenance facts only where supplied; no invented event for a query | Validated rewrap/expiry/cleanup successor and references commit together; complete secret-free reads |

## Validation and permissions

Acquire the cohort fence before subordinate Agent/operation/authority/destination/key fences and hold all through
commit/rollback. Compare the entire expected operation and relevant Agent authority, preserve original immutable
correlation and require the exact package revision advance. Reject stale/unknown/unbound epochs, retired authority,
closed target key versions and missing operations; never reconstruct absent work or restart retention on hydration.
Package transitions govern material removal, retry and cleanup eligibility, not adapter-invented policy.

Due selection uses the authoritative reservation for the stable destination across all scopes/Agents/binding
revisions, not a maximum computed from the current query subset. Sort by due time then global delivery ID, apply
bounded limits only after eligibility, and leave obsolete copies for maintenance. Maintenance retains original
historical binding and includes all retained copies with keyset order/cursor semantics; a page is never a global
key count. Count all scopes, states, versions and obsolete copies under the shared key-reference protocol.
Zero references alone grants no physical destruction authority.

Queries use current authoritative storage, load no material/tokens/receipts, take no claims and perform no mutation,
commit, lifecycle repair or capacity admission. Failures propagate safely, never empty work/zero counts. Owning
handlers recheck actual actor/scope/target authority; selection is not sensitive invocation admission. Persisted
sensitive state and callback arguments stay out of public Views, error chains and ordinary logs. No external sink
call or key deletion occurs inside a repository transaction.

## Acceptance criteria

- [ ] Exact delivery and maintenance successors round-trip through restart without losing original bindings,
  pinned policy, leases/admission, receipts, failure/retry, key versions, cleanup or terminal/tombstone facts.
- [ ] Competing claims, retirement, outcome and maintenance updates accept only current full expected state and
  correct revision/authority; failures roll back all material/reference changes and cannot resurrect retired work.
- [ ] Due queries exclude cross-scope obsolete reservations before limiting, including when the winning reservation
  is not due or already complete. Pending/retry/expired-lease and retention-expired work follow package semantics.
- [ ] Maintenance pages and global counts handle more than one page, obsolete/terminal/unknown-version records,
  closed key admission and concurrent writes without a misleading empty result or permission to destroy a key.
- [ ] Safe projections never load secret-bearing state; storage failure and indeterminate commit remain distinct
  from no work/success. No query-time mutation or separate consumer queue exists.
- [ ] Complete persistence is still not live delivery/activation/use qualification; unavailable participants keep
  the production contract unavailable.
