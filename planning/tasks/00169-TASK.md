# Evaluate compaction timing with Jev after each eligible turn

## Outcome

Each completed turn from the notice tier receives an attributable bounded Jev timing evaluation, while
recommendations, early Agent choices and snoozes retain their accepted meaning. Evaluation failures are visible
and never disable deterministic request-tier compaction in a participating Pi 1.1.0 session.

## Scope

- Integrate [TASK-00159](00159-TASK.md)'s shared evaluator into [TASK-00168](00168-TASK.md)'s timing lifecycle on
  **Pi 1.1.0**. Reuse the existing provider, protected configuration and budget accounting rather than adding a
  second client or selecting a different main Agent model.
- Evaluate after every completed Agent turn at or above the resolved notice threshold, including during a snooze.
  Use the runtime's qualified turn-completion semantics, not merely the end of a potentially multi-turn run.
  A useful work boundary is judgment input, never a prerequisite for the evaluation hook or proof of safe compaction.
- Deduplicate duplicate delivery for the same completed turn, bind requests/results to session/turn/checkpoint and
  current profile/policy/rubric/evaluator identity, and invalidate obsolete results after context/profile changes.
  Do not apply a time cooldown or coalesce away otherwise eligible completed turns. If evaluation is unavailable
  or budget-limited, record that outcome for the eligible turn instead of claiming a judgment occurred.
- Ask for predefined compact/defer/uncertain and caller-authored reason choices. The Agent/Harness must supply
  reason wording before dispatch; Jev selects supplied choices, not new explanatory prose. Bound and version
  the input description of work state/next need. No borrowed 0.70 relevance or 0.95 tool-guard threshold, and no
  reinterpretation of choice confidence as measured timing accuracy.
- Between notice and recommendation, return advice to inform optional early compaction; an explicit Agent request
  needs no positive answer. Between recommendation and request, a positive judgment can initiate at a safe point
  unless a valid Agent snooze applies. At request, the deterministic path proceeds without waiting for Jev or
  accepting a negative/uncertain verdict or snooze as veto. Validate current state again before any initiation.
- Preserve TASK-00168's quiet notices and separately suppress repeated unchanged notifications. A fresh evaluation
  need not produce a new human-facing notice. Direct human alerts remain limited to actual intervention needs.
- Enforce shared encoded input/question/choice/concurrency/time limits: 64 KiB, eight questions, sixteen choices,
  two concurrent calls and fifteen seconds per request, with zero automatic retries and tighter limits prevailing.
  Use explicit operator request/session spending caps, conservative reservations and uncertain billed outcomes.
- Qualify session-attributed and aggregate budgets for each supported parent/child path, using explicit allocations
  and an enforced shared accounting boundary where aggregation is promised. Independent sessions are not proof
  of account-wide enforcement. Budget exhaustion becomes recorded degraded evaluation, never a silent cap increase
  or suppression of deterministic escalation. Define supported scope and resource ceilings before activation.
- On outage, timeout, denied disclosure, invalid/missing response, cancellation or exhausted budget, retain early
  Agent requests, deterministic tiers and qualified native fallback. Do not fabricate a verdict or add a human
  approval requirement when accepted fallback can safely proceed. Required checkpoint failures still preserve/pause.
- Cancel/ignore late work after stop/reload/compaction or changed inputs; no stale result can trigger duplicate
  compaction, overwrite a current snooze or restart stopped work. Reconcile usage without double counting or
  converting unknown charges to zero. No repeated questions merely to obtain a preferred decision.
- Emit bounded per-turn evaluation/provenance/coverage, supplied reason identifier, available usage/cost/latency and
  failure/fallback observations into the shared contract. Exclude raw checkpoint/transcript/source bodies and
  credentials from ordinary records. Evaluation and notification counts are distinct facts.
- Exclude optional-context ranking, new checkpoint storage/repair, timing-policy ownership, historical comparison
  UI, managed Agent launch, memory promotion and unsupported global propagation claims.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Evaluate an eligible completed turn | Submit one current bounded timing evaluation | Predefined timing and supplied reason choices | Evaluated/unavailable/invalid/budget-limited fact | Authorized provider request and usage receipt |
| Act on current advice | Request permitted safe-point initiation through timing owner | Current tier/snooze, safe state and valid judgment | Advice used/deferred/stale observation | Optional or recommended compaction only under TASK-00168 rules |
| Handle an unavailable evaluator | Record degraded state; cancel obsolete work | Remaining budget, fallback and current timing obligation | Degraded/cancelled/fallback facts | Deterministic timing continues; no fabricated verdict or hidden retry |
| Inspect current timing advice | N/A: presentation is read-only | Latest valid answer and supplied reason label | Notification observation when meaningfully changed | Quiet session/Agent status; no new authority |

## Validation and permissions

Apply current source access and provider disclosure independently; only authorized bounded work-state evidence
may leave the session. Agent-authored text cannot alter endpoint/model/profile/budgets or declare new valid answer
choices after a result arrives. Reject undeclared, incomplete, malformed or stale responses. The evaluator never
authorizes tools, overrides checkpoint checks or determines context capacity. Preserve parent/child and reviewer
privacy; status visibility does not permit ingestion of another Agent's context.

## Acceptance criteria

- [ ] Actual Pi 1.1.0 behavior records an evaluation or explicit unavailable/budget outcome after every eligible
  completed turn, including snoozed work; no cooldown skips turns and duplicate hooks do not duplicate calls.
- [ ] Compact/defer/uncertain and prewritten reason choices remain typed and version-bound. No generated reason,
  fabricated confidence measure, or threshold copied from another consumer controls timing.
- [ ] Notice-tier advice leaves early action to the Agent; recommendation-tier positives respect valid snooze;
  request-tier compaction never waits for or is vetoed by Jev. All initiation still uses verified safe points.
- [ ] Shared and qualified aggregate bounds hold under concurrency/cancellation; unknown billing stays reserved,
  duplicate completion does not double count, and failed evaluations preserve deterministic timing/fallback.
- [ ] Profile/context changes, reloads, explicit stops and late responses cannot cause stale or duplicate compaction,
  overwrite valid current state or silently restart work.
- [ ] Supported parent/child allocations and instruction/evaluation paths are demonstrated with honest exclusions;
  notification deduplication is independent of evaluation frequency and human alerts remain exceptional.
- [ ] Representative useful/unsafe-to-compact work boundaries are compared for useful advice, misses, context
  pressure, cost/latency and fallback outcomes, without claiming optimal timing from classification confidence.
