# Resolve configured comparison scope safely

## Outcome

Deliver one independently reviewable project-selection path for the future `compare` skill: shared defaults,
complete local replacement, explicit selection and safe resolution of host checkout paths. This delivers
[TICKET-00140](../tickets/00140-TICKET.md)'s portability and secret-safe configuration outcome under
[EPIC-00026](../epics/00026-EPIC.md), not a generic settings infrastructure demonstration.

## Scope

- In scope: specify and document the exact small YAML schema, explicit-selection syntax, variable grammar,
  setting-request/result contract and bounded dotenv semantics before implementing their consumers. Cover
  comments, whitespace, quoting, duplicate keys, malformed assignments and empty values. Keep the contract in
  one owning reference that the later skill can consume; examples and defaults must agree with it.
- Add tracked root `compare.yaml` with `project-slim`, `project-symfony`, `project-laravel`,
  `project-codeigniter` and `project-yii`, expected `johnnickell` repository identities and paths such as
  `${PROJECT_BASE}/project-slim`. Ignore `compare.local.yaml`. A present local file replaces the shared file
  completely; invalid local input never falls back to shared defaults. Explicit selection overrides configured
  selection for that run. Missing scope prompts for input, not a sibling-directory scan.
- Support `$VARIABLE` and `${VARIABLE}` path substitution without shell evaluation or implicit tilde expansion.
  Resolve relative paths from the active configuration file's directory. Treat malformed syntax, missing values
  and missing/unreadable checkouts as explicit gaps; do not invent locations.
- Add host-side `./bin/env PROJECT_BASE`. Allow only supported setting names, initially `PROJECT_BASE`. Use a
  nonempty process setting first, then the invoking checkout's parsed `.env` according to the documented
  contract. Output only the requested value or a safe error; never dump the environment, execute dotenv text
  or print unrelated secret-bearing lines. Do not modify the user's existing `.env` automatically.
- Document a portable absolute-path example in `.env.example`, process/file precedence and safe usage. Do not
  require a container, application boot or database, or forward host paths into application containers.
- Keep the setting request independent of transport so a future permitted MCP tool can replace the host
  command without changing configuration. Capability denial stops dependent resolution; no direct `.env`
  bypass, alternative provider or Bash fallback. This does not implement managed authorization or confinement.
- Document and walk authorized source/revision inspection, including mismatched repositories, forks,
  ambiguous source evidence and dirty state. Paths, names and remotes are evidence, not managed identity;
  follow [ADR 0005](../adr/0005-repository-identity-and-link-consistency.md) without registering or linking
  Projects. Never silently substitute, clone, modify or certify a checkout.
- Out of scope: drift analysis, the `compare` skill entrypoint, HTML/PDF reports, Desktop delivery, compared
  project repairs, planning-record generation by comparison, a comparison parser/runner or option framework,
  MCP implementation, a settings provider registry, container changes, global installation and publication.
  [TICKET-00141](../tickets/00141-TICKET.md) owns the later skill and report journey.

## Validation and permissions

Resolve context from the invoking project, not the installed skill provider. Configuration is data, never a
source of permission. Read only authorized settings and selected checkout evidence. Denied or unavailable
capability pauses dependent work without widening access; independent scope remains explicitly incomplete.
Reject unsupported setting names even if they exist in `.env` or the process environment. Define malformed,
duplicate and empty-value handling before implementation, keeping diagnostics secret-safe.

No application Commands, Queries, database mutations, transactional audit, domain Events or new managed
Permissions apply. Native access remains necessary; this local tool is not an OS security sandbox. Do not
add infrastructure tests to the product suite or weaken accepted project contracts to match current source.
