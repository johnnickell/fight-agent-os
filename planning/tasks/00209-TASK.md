# Offer a verified hotfix merge-back

## Outcome

A permitted human can inspect one completed hotfix's exact post-PR state and see a merge-back offer **only**
when its PR is trusted-verified merged into the Repository-configured GitFlow production base and its fix is
not already included in the configured development base. This is an independently reviewable read-only
eligibility-and-presentation path; it never merges branches, changes TASK status or reacquires a Workflow claim.

## Scope

- Consume [TASK-00207](00207-TASK.md)'s hotfix identity, independently accepted subject, verified PR
  publication and immutable base/head provenance. Reuse the **actual qualified** managed trusted merge
  observation from [EPIC-00008](../epics/00008-EPIC.md), not an unverified webhook, branch-name match, PR
  title or model assertion. Confirm provider-native repository/PR identity, expected production target,
  accepted/published head, actual merge result and commit inclusion for merge-commit, squash and rebase
  strategies. Wrong-target, replaced-head, pending, closed-unmerged, inaccessible or unknown observations
  cannot make the action available.
- Read [TASK-00203](00203-TASK.md)'s current versioned GitFlow strategy and explicit production/development
  identities, current source/target OIDs, target inclusion, branch protection and required-check expectations.
  Present a bounded preview of the proposed source, target, inclusion and reasons with revision provenance,
  scoped to an authorized human. Only offer action where the configured development base still needs the fix;
  trunk-based projects with no separate development base have no merge-back action. Do not presume branch
  names, merge unrelated development changes into production or equate PR publication with production merge.
- Preserve the existing hotfix Workflow history after PR handoff as the subject of the preview. This read does
  not resume implementation, reopen TASK completion or issue a post-PR grant. [TASK-00210](00210-TASK.md)
  owns the human authorization, durable effect and outcome; do not add a separate Workflow or TASK.

  return distinct safe reasons, not an implicit `develop` target or a second TASK.
