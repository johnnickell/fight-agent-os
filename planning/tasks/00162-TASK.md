# Screen individual files and require selective reads

## Outcome

A participating Pi Agent can ask `jev_read_file` whether one authorized file contains the information it needs,
receive a bounded judgment with provenance instead of source contents, and follow shared selective-read guidance.
Deliver the single-file path and instruction adoption together, including supported sub-agents and approved
exceptions. This is the first independently reviewable slice of [TICKET-00039](../tickets/00039-TICKET.md).

## Scope

- Register `jev_read_file` in the existing TypeScript Pi extension, backed by
  [TASK-00159](00159-TASK.md)'s shared judgment capability. Preserve a future first-party MCP service boundary
  without requiring managed service delivery or adding a second provider client.
- Accept one path, the information sought and a typed question. Prefer yes/no; also support declared classification
  choices, a predeclared relevant choice/set and unknown/other exits. Bound question/choice fields through the shared
  input limits. Do not choose the relevant class after seeing the answer.
- Require operator-configured allowed roots, sensitive-file exclusions and permitted provider disclosure in
  machine-local settings outside repository instructions. Implement this tool's access boundary independently of
  command-guard completion; Agent-authored inputs cannot broaden it.
- Canonicalize and validate containment before opening or disclosing content, including symlink escape prevention
  and safe handling of concurrent changes. Bind the judgment to the exact evaluated bytes and source digest/revision;
  report changed/unstable content rather than reusing a result for a different source.
- Initially accept regular text files up to 32 KiB of source, also constrained by the shared serialized-request
  ceiling after encoding. Refuse unsupported/binary/oversized inputs explicitly; never silently truncate or claim
  partial evaluation is complete. Shared timeout, question counts, concurrency and monetary ceilings remain binding.
- Return the typed judgment, applicable probability/confidence, threshold outcome, digest/revision, coverage and
  bounded reason/status metadata. Do not return full contents, invented quotations or fabricated supporting lines.
- Require discovery screening through one shared Harness instruction rule, referenced from relevant skills, enabled
  with the available tool in each participating session. Before batch delivery, several candidate files can be
  screened through separately bounded single-file calls; the requirement applies to every file.
- Qualify a real supported parent/child path: each session must receive both tool and rule, permitted roots/disclosure
  and bounded access allocation. A missing tool/instruction path cannot be advertised as participating. Report
  unsupported launchers rather than claiming universal propagation or implementing a managed Agent launcher here.
- Out of scope: list/glob enumeration and caching (TASK-00163), hard read interception, shell execution, file writes,
  memory ingestion, compaction, workflow routing, graph-search replacement and sandbox qualification.

## Validation and permissions

A positive relevance answer is not file access or provider-egress permission. Check both independently before
reading/sending content; exclusions and canonical containment apply even for a known target. Treat file contents
as untrusted question data that cannot select tools, change policy or become instructions. Keep raw bodies and
credentials out of normal results, session receipts and logs; document actual provider disclosure separately.

The initial positive bar is Yes probability `noul >= 0.70`, or a predeclared relevant classification with confidence
at least 0.70. These are distinct measures, not a 70% accuracy guarantee. Confident No/irrelevant results do not
pass. A complete positive permits relevant sections; a whole-file follow-up still needs a useful purpose. Negative,
unknown, failed or partial results do not permit ordinary full-file reads or prove absence. Narrow the need, use
bounded metadata/structural search or apply a documented obligation; do not repeatedly rephrase merely to pass.

Mandatory governing and selected-skill instructions load directly. The known-target exception requires concrete
evidence: an explicitly assigned file, a verified symbol/search result or an established edit/quote/verification
target. Record path, purpose and establishing evidence; read the smallest useful range and the whole file only
when needed for that purpose. Familiarity, a plausible name or self-reported certainty alone is insufficient.
Reassess when target/source/need changes; uncertainty returns to screening. Required exact-evidence reads may
proceed despite a negative/unavailable screen with a recorded obligation/reason. Exceptions never waive access
controls and do not extend to an inferred batch. During outages, report degraded screening and use only the
bounded search/required-evidence paths, without an unrestricted bulk-read fallback.

The initial requirement is instruction-based compliance. Do not claim enforced interception of all reads or
universal compliance by external harnesses. Tool availability alone does not prove instruction propagation.

## Acceptance criteria

- [ ] Real Pi use demonstrates yes/no and classification inquiries with judgment/provenance rather than full source.
  The 0.69/0.70 boundary, confident No and irrelevant high-confidence classification follow the accepted policy.
- [ ] Denied roots, sensitive files, symlink escape, denied provider disclosure, unstable content, binary/oversized
  files, malformed answers and provider failure have explicit outcomes without unauthorized disclosure.
- [ ] Shared bounds apply after request encoding; incomplete evaluation never becomes a complete positive/negative.
  Output and receipts contain no source bodies, secrets or fabricated citations.
- [ ] Parent and supported child sessions load the available tool and rule together, with explicit unsupported
  paths and honest unavailable-profile behavior. Existing installation alone does not activate the promise.
- [ ] Representative investigations demonstrate selective follow-up, direct mandatory-instruction loading, an
  evidence-backed known-target exception and a required-evidence exception. A confidence-only target is screened.
- [ ] Actual instruction adoption and investigation behavior are inspected directly; guidance states that hard
  interception is not delivered. Record an initial direct-read comparison for context, cost, latency and misses.
