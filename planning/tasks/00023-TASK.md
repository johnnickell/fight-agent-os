# Compose direct package credential delivery

## Outcome

Agent OS directly registers the qualified Fight Access Control credential-delivery commands, queries, and handlers
for invitation and password reset so each exact package handler commits its claim, invokes the configured provider
with no transaction open, and commits only a matching expected-state outcome. Immediate post-commit coordination is
an optimization; package due-work discovery remains recovery authority.

## Scope

- In scope: Direct package handler/query registration; exact repository, Unit of Work, clock, cipher, and provider adapter composition; invitation/password-reset processing; immediate post-commit dispatch where supplied by the package; delivered/retryable/permanent/throwable/stale outcomes; transaction-state, idempotency, redaction, and competing-claim integration tests.
- Out of scope: Agent OS command/handler aliases, copied package transition policy, batch/recovery console runner, consumer outbox, consumer retry/backoff rules, production providers, product email-change provider wiring, user-facing status UI, and exactly-once delivery.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Process one package delivery | Exact locked package command | Package handler resolves one current generation and commits a claim | Existing package event may request immediate processing | Provider runs after claim commit; matching outcome commits later |
| Record delivered outcome | Same package handler lifecycle | Compare delivery ID, claim token, lease, and revision | Package event only after durable state as defined upstream | Ciphertext is destroyed and delivered/audit status commits |
| Record failure | Same package handler lifecycle | Inspect typed provider result | No product event inferred from retries | Retryable uses package next due time; permanent becomes ciphertext-free terminal state |
| Survive duplicate invocation | Same package generation may be reclaimed | Resolve stable delivery-generation ID | Original event may be absent or duplicated | Repeated provider attempt has identical idempotency identity; stale state cannot overwrite current work |

## Validation and permissions

Composition uses package messages and handlers directly and injects their declared contracts. It must not wrap them
in an Agent OS transaction: the package handler owns separate claim and outcome boundaries. Transaction probes prove
no originating, claim, or outcome transaction is open during TASK-00022 provider invocation.

Only current committed package work may invoke a provider. Rolled-back, absent, not-due, delivered, terminal,
superseded, stale, or claim-losing work cannot invoke. Retry schedule, lease semantics, grant-expiry boundary,
terminal policy, and unexpected-throwable behavior remain package-owned.

Logs/status include only package-approved safe IDs, attempt/state/reason codes, and correlation. Exclude credentials,
hashes, tokens, provider secrets, ciphertext, URLs, plaintext bodies, destinations where not approved, and arbitrary
provider exception messages. End-user authorization belongs to the originating package use case; delivery authority
is internal.

## Acceptance criteria

- [ ] Exact package invitation/password-reset messages and handlers are registered directly with no Agent OS aliases.
- [ ] One processing timeline is claim-commit, provider invocation with no transaction open, and matching outcome-commit.
- [ ] Rolled-back, absent, ineligible, delivered, terminal, superseded, stale, or claim-losing work cannot invoke a provider.
- [ ] Delivered, retryable, permanent, unexpected-throwable, expired-claim, and stale-outcome behavior follows the locked package contract.
- [ ] Competing claims permit one live owner for the relevant generation/revision.
- [ ] Duplicate processing reuses the exact delivery-generation identity and does not infer duplicate business events.
- [ ] Immediate package-event coordination can attempt committed work but is not required for later recovery.
- [ ] Logs and safe projections expose no credentials, hashes, tokens, provider secrets, ciphertext, URLs, plaintext bodies, or unsafe errors.
- [ ] Product email-change provider wiring, production providers, scheduler, and consumer outbox remain absent.
- [ ] Focused package-handler/PostgreSQL/redaction checks and `./bin/build` pass with fresh evidence.
