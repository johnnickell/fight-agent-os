# Coordinate bounded multi-tab session continuity

## Outcome

The client restores cookie-backed sessions after reload and coordinates refresh/logout across tabs through bounded Web Locks and BroadcastChannel protocols, sharing access authority only in volatile memory, suppressing stale generations, recovering leader failure conservatively, and providing accessible terminal-expiry behavior without credential persistence or infinite retries.

## Scope

- In scope: Client session coordinator/state machine; startup restoration; Web Locks leader election with timeout/abort; versioned BroadcastChannel messages; memory-only access-token handoff/invalidation/logout signals; request generation/stale-result suppression; one bounded package-conflict recovery; unsupported-API fallback; terminal `401`/expiry/logout/network UI states; safe intended-route continuity; deterministic fake clock/lock/channel tests; minimal browser-only smoke for platform behavior; Storybook/state evidence.
- Out of scope: `/api/v1/me` roles/permissions, server authorization, service workers/offline queue, token persistence, broad browser matrix/E2E suite, session listing/other-session revocation, logout everywhere, and cross-origin clients.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Restore after reload | N/A — client coordinator invokes refresh API | Read unknown memory state, CSRF readiness, and protected cookie only through server | Client restoration signals | One bounded refresh attempt obtains memory access token or reaches anonymous/terminal state |
| Coordinate refresh leader | N/A — browser lock and refresh client | Inspect token expiry/generation, lock availability, and peer signals | Versioned client-only token/invalidation signals | One leader refreshes; followers accept current volatile result or refetch state |
| Recover leader failure | N/A — timeout/abort/fallback control | Observe lock/channel deadlines and current generation | Client failure/re-election signal | Bounded successor attempt proceeds without deadlock or unbounded retries |
| Propagate logout/terminal failure | Logout API only in initiating tab | Read server result and local generation | Versioned logout/invalidation signal | Every tab clears memory, rejects late results, and enters accessible anonymous/expired state |

## Validation and permissions

Start with authority `unknown`, not authenticated. On reload no access token is available by design; invoke the protected refresh API once through the coordinator without reading the HttpOnly cookie. Model unknown/restoring/authenticated/anonymous/conflict/network-degraded/terminal/logout states explicitly and fail closed for protected operations while unknown/stale.

Use Web Locks only on supported secure origins with a fixed application-owned lock name, bounded acquisition/hold timeout, AbortSignal, and `try/finally` release. Recheck generation/need after acquiring. Never hold a lock across unrelated UI work. If leader exits/crashes, followers time out and make at most the accepted bounded successor attempt.

BroadcastChannel messages are versioned, bounded, runtime-validated, and origin-local. They may carry the fresh access token/expiry required for volatile sibling authority under the ADR, or an invalidation/refetch signal, but never refresh credential, CSRF secret beyond accepted coordination, roles/permissions as trusted authority, password/form data, user private data, or arbitrary object. Close channels/listeners on teardown.

Use monotonic local generation/request IDs so old refresh/login/logout/network results cannot overwrite a newer credential, logout, terminal failure, or authority invalidation. A package conflict permits only one coordinated recovery according to ADR; no recursive response interceptor or infinite refresh loop. Network failure remains distinguishable from terminal authentication but cannot authorize protected work.

Where Web Locks or BroadcastChannel is absent, use the ADR's conservative bounded fallback: independent volatile tabs may race, but only one explicit conflict recovery is attempted and terminal failure clears authority. Never coordinate through `localStorage`, `sessionStorage`, IndexedDB, Cache Storage, service workers, cookies readable by JS, URL, or HTML.

Logout broadcast and terminal `401` clear memory and intended secret state in every tab. Preserve only TASK-00025/00046's validated transient same-origin intended route. Provide accepted loading, expired/revoked, network, and login-restoration presentation with focus management/status announcement/reduced-motion support. Client state is usability, never server permission enforcement.

## Acceptance criteria

- [ ] Reload begins unknown and performs one controlled server refresh without JavaScript cookie access or presumed authority.
- [ ] Explicit state machine covers unknown/restoring/authenticated/anonymous/conflict/network-degraded/terminal/logout and fails closed while unknown/stale.
- [ ] Supported secure-origin Web Locks elect one refresh leader with recheck, bounded timeout/abort, reliable release, and leader-crash recovery.
- [ ] Versioned runtime-validated BroadcastChannel messages share only approved volatile authority/invalidation/logout data and close cleanly.
- [ ] Access token remains memory-only; refresh/CSRF credentials, roles/permissions, passwords, form state, and private data are absent from prohibited messages/storage.
- [ ] Generations suppress late login/refresh/logout responses and prevent authority restoration after logout, terminal failure, or newer rotation.
- [ ] Package refresh conflict triggers at most one coordinated recovery and no interceptor/lock/channel path can loop indefinitely.
- [ ] Unsupported Locks/Channel fallback is bounded, compatible with package conflict semantics, and never adds persistent coordination state.
- [ ] Logout and terminal refresh/`401` propagate to all participating tabs, clear memory, and render accessible anonymous/expired behavior.
- [ ] Network failure is distinguishable/recoverable but cannot retain stale authority for protected operations.
- [ ] Safe intended route may survive restoration; credentials, email/password, request bodies, and arbitrary state do not.
- [ ] Deterministic fake-clock/lock/channel tests plus minimal browser evidence cover leader/follower/race/crash/timeout/reload/logout/terminal/fallback behavior.
- [ ] Focused frontend type/lint/Vitest/RTL/Storybook/browser-smoke checks and `./bin/build` pass with fresh evidence.
