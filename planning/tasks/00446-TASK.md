# Restore one glob-loaded service container and trusted console commands

## Outcome

A maintainer can determine the application's service graph by reading `config/services.php` and the files in
`config/common/` and `config/application/`, without tracing the selected console command or later container
mutations. Restore deterministic glob loading and normal shared Symfony Console command registrations. This
removes an immediate maintainability blocker in the invitation and Super Admin bootstrap delivery path, not a
speculative dependency-injection redesign.

The maintainer explicitly requested this refactor and immediate priority after inspecting TASK-00038's
command-specific bus replacement, then selected a simple Console-facing check: refuse bootstrap when a Super
Admin already exists. A failed authoritative lookup must also refuse. The accepted direction is a trusted
machine-access CLI, not separate service-container profiles per console operation. Agent shell/CLI exclusion
belongs to the existing managed execution boundary; it is not implemented merely by changing registration.

The maintainer explicitly rejected concurrency handling for this manually operated CLI. Assume one trusted
operator runs bootstrap at a time. Do not add database locks, serialized admission, leases, fencing, or concurrent
bootstrap machinery/tests to this refactor, and do not claim it supports simultaneous bootstrap invocations.
This supersedes TASK-00038's concurrent-bootstrap requirement for the refactored command.

The maintainer explicitly allows another manual bootstrap attempt after failure or partial completion while no
Super Admin exists. Remove the permanent claim as a retry blocker. This supersedes TASK-00038's permanent
claim/no-retry requirement for the refactored command. Once a Super Admin exists, refuse subsequent attempts.
A failed presence query also refuses; do not interpret an unavailable lookup as permission to proceed.

## Scope

- In scope: `config/services.php`, service configuration under `config/common/` and `config/application/`,
  command/query/handler/filter registrations affected by the refactor, `scripts/console.php`, normal Console
  registration, and the corresponding invitation/bootstrap Application simplification, behavior tests and docs.
- Replace the explicit per-file manifest and command-dependent configuration loading with one deterministic,
  glob-loaded registration graph. Give files a consistent registration contract; metadata/helper files must not
  masquerade as loadable service modules. Do not retain hidden exceptions or duplicate nested loading.
- Register the ordinary invitation, additive role assignment and bootstrap Console commands together in the
  existing shared container/application. CLI parsing selects a command to execute, never a container profile.
- Remove console/bootstrap-specific replacement of `messaging.command.bus` and routing-stage/intent/scope
  scaffolding whose purpose is to simulate trusted CLI access through alternate service graphs. Remove obsolete
  permanent-claim admission code and its no-retry behavior; an earlier claim must not block a new manual attempt
  when no Super Admin exists. Preserve historical audit evidence. Keep genuine use-case invariants with their
  owning Domain/Application behavior, not in a renamed equivalent guard stack.
- Update the focused engineering/composition guidance so later features do not reintroduce command-specific
  loading, bus replacement or service absence as access control.
- Out of scope: implementing the managed Agent tool/shell restriction, new Runner or sandbox capabilities,
  package changes, framework/container replacement, eager service construction, public admin CLI endpoints,
  unrelated Console migration, invitation/activation features, interrupted-bootstrap recovery/reset/resume,
  and concurrent bootstrap support or synchronization mechanisms.

## Validation and permissions

The trusted CLI assumes the operator already has authorized SSH/machine/process access. Neither `--internal`, an
operator UUID, `PHP_SAPI`, a command name, nor registration in the container proves a caller is human or creates
an authentication credential. Keep explicit operator attribution, input validation, confirmations and secret-safe
output. Do not expose trusted operator operations through HTTP, an Agent tool, or an arbitrary-process capability.

Follow [ADR 0001](../adr/0001-application-ownership-and-orchestration.md) for ownership, injection and configured
bus dispatch; do not replace pipelines with direct handler/repository calls. Preserve authenticated elevated
assignment's current authoritative permission checks in an explicit Application-owned authenticated assignment
use case. Its real owned responsibility is fresh principal/actor/permission validation before package dispatch,
not merely aliasing a package command. Require every actual web/nontrusted assignment entry to use that boundary;
add no new endpoint merely to demonstrate it.

The shared raw package bus is trusted in-process composition infrastructure, not a public authenticated API.
Raw package dispatch alone need not resolve an authenticated browser principal. This replaces TASK-00038's
raw-message guard placement while retaining the same permission decisions for authenticated callers. No ambient
trust flags/scopes, alternate bus, forged principal, direct handler calls or raw-message HTTP/Agent forwarding.
Record the boundary and migrate actual consumers explicitly; do not describe removing a bus filter as preserving
raw-message authentication. Registering a service is not executing it or authorizing every caller to use it.

Make the Console command's eligibility check direct: query for an existing Super Admin; if one exists, refuse;
if the query fails, refuse; otherwise proceed with bootstrap. No database lock, serialized admission, alternate
container, or transient intent/claim-scope choreography is required. This is a manually invoked trusted operator
command, not a concurrent registration endpoint.

Preserve operator/target audit, package-owned invitation and assignment, ordinary activation, and truthful
partial/uncertain outcomes. Do not restore unsupported atomic transactions across the package handlers. A
subsequent manual invocation performs the same presence check and may proceed if no Super Admin exists,
regardless of an earlier failure or partial attempt. Do not add automatic retry, rollback, reset or resume
machinery. Existing invitation/email conflicts retain normal package behavior; retry permission does not imply
silently resending credentials or undoing an earlier invitation.
