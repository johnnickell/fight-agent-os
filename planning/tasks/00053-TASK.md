# Deliver recoverable secret-safe password-reset email

## Outcome

Package-owned encrypted `PasswordResetDelivery` generations become recoverable password-reset mail through the existing durable-effect pipeline: reconciliation registers one allowlisted idempotent intent, invocation materializes a canonical fragment-based HTTPS completion link only in memory, successful delivery confirms and destroys ciphertext, terminal expiry destroys ciphertext, and crashes retain honest at-least-once recovery.

## Scope

- In scope: Password-reset delivery bridge/reconciliation; allowlisted versioned durable-intent mapping; stable delivery-generation idempotency; protected credential decrypt-at-invocation handling; canonical reset URL builder; deterministic text/HTML templates; generic mail capability mapping; package `ConfirmPasswordResetDelivery`/`ExpirePasswordResetDelivery` integration; development catcher reuse; production key/provider/origin guards; registration/provider/outcome/confirmation crash recovery; retry/expiry/redaction tests and operational documentation.
- Out of scope: Reset-request HTTP/UI, reset completion HTTP/UI, production mail-vendor enrollment, arbitrary template engine/endpoints/callables, another outbox/queue, user-facing delivery status, plaintext credentials in operational views, analytics/tracking, and scheduler/platform enrollment.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Reconcile reset delivery | Internal bounded reconciliation operation | Discover package reset deliveries still recoverable and inspect existing intent by delivery ID | `PasswordResetRequested` may prompt reconciliation but is not sole recovery source | Exactly one allowlisted existing-pipeline intent is present or terminal expiry is requested |
| Invoke reset mail | Existing durable-effect runner | Resolve registered delivery generation and protected ciphertext through allowlisted mapper | N/A — provider outcome remains pipeline-owned | Credential is decrypted transiently, canonical mail is invoked with stable idempotency, and outcome persists |
| Confirm successful delivery | `ConfirmPasswordResetDelivery` | Resolve exact current delivery generation after delivered pipeline outcome | `PasswordResetDeliveryConfirmed` | Package ciphertext is destroyed idempotently after durable delivered outcome |
| Expire undelivered work | `ExpirePasswordResetDelivery` | Resolve recoverable delivery at/after one-hour expiry | `PasswordResetDeliveryExpired` | Ciphertext is destroyed and no later mail invocation is allowed |

## Validation and permissions

Treat package `PasswordResetDelivery` persisted with the one-hour grant as the authoritative durable source work. `PasswordResetRequested` can trigger prompt post-commit reconciliation, but correctness cannot depend on that in-memory event: bounded deterministic reconciliation must recover a crash after grant commit and before existing-pipeline intent registration. Reconciliation is idempotent by delivery generation, validates that the generation remains current/recoverable/unexpired, and does not create another delivery authority or outbox.

Persist only an allowlisted versioned provider-neutral intent/reference in TASK-00016 through TASK-00024's existing pipeline. Persisted values cannot dynamically select code, service, template, endpoint, or callable. Copy protected material only if required by the accepted pipeline design; otherwise resolve it from package state at invocation. In either case it remains encrypted at rest with externally configured validated keys. Plaintext exists only during invocation; PHP zeroization limitations are documented and references are minimized.

Build completion URLs only from configured canonical HTTPS origin/path, never request Host/forwarded headers/user input. Place bounded user routing identity and reset credential in the URL fragment according to the accepted contract so neither reaches request lines/referrers. Reject userinfo, ambiguous host/path, query credentials, and non-HTTPS outside explicit test/development.

Use fixed/versioned escaped text and HTML templates with expiry, ignore-if-unrequested, and recovery guidance. Include no remote image/font/script, tracking pixel, analytics parameter, unnecessary identity data, or mutable content. Reuse TASK-00040's mail capability/catcher/provider composition and never print links to console/logs.

Preserve claim/invoke/outcome phases, stable delivery-ID idempotency, bounded retry, leases, stale-worker protection, and honest at-least-once semantics. A delivered durable outcome is finalized through `ConfirmPasswordResetDelivery`; confirmation failure is itself recoverable without resending unnecessarily. Provider-success-before-outcome may duplicate under retry. At expiry, prevent new invocation and dispatch `ExpirePasswordResetDelivery`; terminal package state destroys ciphertext. Internal reconciliation/runner authority is not an anonymous product endpoint.

- [ ] Deterministic bounded reconciliation recovers grant-commit/event/intent-registration crash gaps and creates at most one existing-pipeline intent per delivery ID.
- [ ] Intent schema is versioned, bounded, provider-neutral, allowlisted, and cannot resolve arbitrary code/template/service/endpoint.
- [ ] Stable delivery-ID idempotency survives reconciliation, retries, worker crashes, and duplicate attempts.
- [ ] Credential ciphertext remains protected at rest; plaintext exists only during invocation and is absent from ordinary reads/diagnostics/test records.

- [ ] Deterministic text/HTML templates escape data, explain one-hour expiry/recovery, and contain no tracking or remote mutable content.
- [ ] Durable provider success is finalized through package confirmation and destroys recoverable ciphertext; confirmation crash is recoverable.

- [ ] Provider-success/outcome-commit crash behavior remains explicitly at-least-once with no exactly-once claim.
- [ ] Development catcher is scoped/disposable; production-like boot fails for absent provider, missing/weak key, or invalid canonical origin.
- [ ] Focused reconciliation/PostgreSQL/worker/mail/catcher/idempotency/expiry/composition/redaction checks and `./bin/build` pass with fresh evidence.
