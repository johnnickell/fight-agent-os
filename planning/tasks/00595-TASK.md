# Simplify browser cookie handling and Workspace tests

## Outcome

Reduce repeated security-sensitive cookie-header handling in existing authentication responses and make
Workspace test failures easier to diagnose, without changing application behavior or losing protection.
The operator approved all three findings from the PHP Simplify assessment at `6ec7ef06` and selected the main
checkout. Deliver the bounded cleanup as one independently reviewable PR; no new product capability is added.

## Scope

- Centralize response cookie deletion in
  [`BrowserSessionCookies`](../../src/Adapter/Http/Api/V1/Auth/BrowserSessionCookies.php).
  Update its four existing callers: `SessionResponder`, `PasswordChangeResponder`,
  `ResetCompletionResponder` and `ApiResponseBoundary`. Keep deletion clock-independent and leave the
  decision when to clear cookies, and cache policy, with their existing owners. Do not add another service.
- Split `testTypedReadsAndAdvisoryConflicts()` in
  [`ProjectApplicationTest`](../../tests/Unit/Workspace/ProjectApplicationTest.php) into focused detail,
  pagination, conflict and message-contract scenarios. Replace pagination's expectation obtained from
  executing the detail handler with independently specified fixture expectations.
- Replace manual rejection-count loops in `ProjectApplicationTest::testMismatchedDispatch()` and
  [`WorkspaceApplicationTest::testMismatchedDispatch()`](../../tests/Unit/Workspace/WorkspaceApplicationTest.php)
  with named cases using PHPUnit exception expectations, or separate short tests if a provider would need
  awkward factories. Construct mocks within each test invocation.

## Validation and permissions

This is a behavior-preserving cleanup, not a new entry point or permission. Preserve existing admission,
CSRF and session policy, exact cookie attributes and expiry, and conditional clearing decisions. In particular,
reset completion must not clear an unrelated browser's session; refresh conflict and request-control rejection
must not acquire cookie-deletion obligations. The outer error boundary must clear cookies without resolving
a clock or normal session-response dependencies. No database migration or durable-data disposal is needed.

Follow the [architecture contract](../../docs/engineering/STANDARDS.md#architecture) and
[test quality guidance](../../docs/engineering/QUALITY.md). Existing handler guards are owned behavior,
not redundant checks to remove.
