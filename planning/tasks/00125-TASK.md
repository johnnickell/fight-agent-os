# Manage custom role definitions without changing managed roles

## Outcome

Installation operators can create, rename and remove custom role definitions through guarded Agent OS Application services and package commands, while managed roles and existing assignments remain protected.

## Scope

- In scope: `POST /api/v1/roles` (`CREATE_ROLES`), `PATCH /roles/{roleId}` (`UPDATE_ROLES`) and `DELETE /roles/{roleId}` (`DELETE_ROLES`); FQCN Actions; name-only creation with server-generated returned ID/revision, existing route IDs and caller revision/removal confirmation; package `CreateCustomRole`, `RenameCustomRole`, `RemoveCustomRole`; safe outcomes/OpenAPI/audit and client authority invalidation.
- Out of scope: Managed policy change, granting/revoking role permissions, user-role assignment, general role-to-role inheritance, arbitrary permission creation, scoped Workspace/Repository admin.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Create role | `CreateCustomRole` through authorized service | Check actor/catalog/name | Package role event and audit | Unique custom role created |
| Rename role | `RenameCustomRole` through authorized service | Check actor/custom target/revision | Package role event and audit | Only custom name changes |
| Remove role | `RemoveCustomRole` through authorized service | Check actor/target/references | Package role event and audit | Only eligible custom role removed, references fenced |

## Validation and permissions

Early attribute and authoritative Agent OS Application checks require exact respective `SUPER_ADMIN_ONLY` permission for HTTP and non-HTTP callers. Never delegate global security authority through custom roles. Package managed-role/assignment/reference invariants remain binding, even if the qualified release removes handler permission gates; do not copy verified intrinsic checks into Agent OS. Application owns actor permission/scope and self-admin safety; the package must reject race, stale revision, duplicate/conflicting name and managed targets safely. Authorize creation before generating its identity with package `RoleId::generate()`; create accepts only a name and returns the generated ID/revision. Reject caller-supplied creation IDs and injected authority/grant fields at transport. Rename/remove retain existing UUID route validation and exact caller revision/removal confirmation. Confirm destructive remove, audit without raw secrets or serialized entities.
