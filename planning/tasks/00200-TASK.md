# Diagnose selected TASKs through a permission-limited Triage profile

## Outcome

An authorized human can request a bounded diagnosis of one selected TASK through a distinct Triage team profile
and see the canonical eligibility reasons and permitted evidence. The same permission-filtered subject snapshot
can be consumed by later classification; neither diagnosis nor profile selection makes the TASK executable.
This is a complete read-only use case, normally one independently reviewable PR.

## Scope

- Qualify the actual versioned team-template capability planned in [TICKET-00034](../tickets/00034-TICKET.md).
  Introduce a distinct Triage profile with only its direct requested Permissions, supported model/limits and
  revisioned identity. It is **not** a new Access Control Role or a permission grant. Preserve historical
  profile identities and do not change the approved first Team Lead → Software Engineer start path.
- Reuse [TASK-00096](00096-TASK.md)'s canonical `ExplainTaskEligibility` facts, scope checks and safe reasons
  for a *human-selected* TASK, including an explicitly requested incomplete TASK. Do not scan/rank the queue,
  invent semantic readiness or insert a second eligibility algorithm.
- Supply a bounded safe representation of current declared kind, TASK intent, relevant permitted evidence,
  Planning/context/eligibility revision identities and profile provenance for the later Jev consumer. Disclose
  only facts the actor and actual Triage Agent are permitted to see; read access alone does not permit later
  upstream provider egress. Do not persist raw TASK/source bodies as receipts.
- Expose the explicit diagnosis through a supported read-only application/terminal interaction (and a safe
  presentation contract reusable by later browser work). A UI drag and start/claim remain outside this TASK;
  [TICKET-00052](../tickets/00052-TICKET.md) owns authoritative routing and start. No Jev call or typed
  recommendation is delivered here.
