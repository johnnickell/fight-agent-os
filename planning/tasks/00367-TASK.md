# Explicitly continue after context or provider changes

## Outcome

A planner sees why new work is held after meaningful context/provider change, reviews a concise exact change
summary and explicitly creates a linked continuation. History remains coherent and pending proposals are
revalidated; unchanged reconnect needs no acceptance ceremony or replacement snapshot.

## Scope

- In scope: Browser drift/availability presentation, initial/continuation model picker, explicit catalog refresh,
  authorized default selection through existing profile writers, exact change preview/confirmation, linked-result
  recovery and retained-candidate applicability feedback.
- Out of scope: Another snapshot/provider/session engine, silent failover, mutable in-place rebinding, automatic
  regeneration/Apply, cross-machine migration, credential setup and terminal switching already owned elsewhere.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Inspect hold/change | N/A — authorized read | Exact old/current/proposed snapshots, drift, allowed choices and original effects | N/A | Concise safe summary without launching a model or continuation |
| Continue explicitly | TASK-00342's exact expected-state linked-continuation operation | Current authority, selected qualified path and reconciled original outcome | Existing committed continuation/snapshot facts | One linked successor, never rewritten old configuration |
| Inspect retained candidate | Existing candidate validation/correction only when explicitly submitted | TASK-00357 candidate/current-base applicability and preserved answers | Existing candidate facts where changed | Stale/held/reviewable state, not transferred approval or automatic Apply |

## Validation and permissions

Consume TASK-00361's browser scope, TASK-00342's actual continuation contract and TASK-00357's typed candidate
validation. Display meaningful package/resource/profile/Repository/provider changes and their consequences using
safe exact references, not raw credentials, protected paths or hidden context. Requested and reported model identity
remain distinct. Allowed/configured/qualified choices are not interchangeable; unavailable providers cannot be
selected through fabricated defaults or silent fallback.

Bind confirmation to current actor, original conversation/binding/generation and exact new selection. Revalidate
current rights, delegation, host support, immutable resources and budget/disclosure before the owning continuation.
Unknown original tool/provider/Apply outcomes hold dependent work; cancellation or missing transport does not prove
free capacity or an unsent request. A changed-away-and-back selection or concurrent update invalidates stale preview.
Duplicate clicks/lost acknowledgement resolve one original successor; no automatic retry creates another session.

Unchanged reconnect keeps the existing binding without another confirmation. A meaningful change requires explicit
Continue with updated context/provider, preserving old lineage, accepted answers and pending proposals. Revalidate
candidate/base/current authority through its owner; history is not fresh approval. Stale candidates remain visible
only to authorized readers and require separately reviewed correction/reconciliation/Apply. Never regenerate or
choose human preferences merely because configuration changed.

Use ADR 0003/0004 strict decoding, no-store, private-cache retirement and context/request-generation fences. Late
old continuation or model responses cannot change the selected conversation, overwrite manual preview edits or
restore logged-out/revoked data. Clear browser authority on invalidation while retaining server history under its
own policy; do not persist drafts or mutation queues.

## Acceptance criteria

- [ ] Current/stale/unavailable model lists, explicit refresh and scoped Set as default work through the existing
  catalog/adapter/profile owners; old conversations keep their selection and no inference/allowance refresh or
  automatic fallback occurs. Real browser states are accessible and current-authorized.
- [ ] A between-turn OpenRouter model change previews permitted context and truncation, preserves original usage
  and uses the confirmed linked successor; active/uncertain work cannot be silently restarted or reassigned.
- [ ] Real unchanged reconnect needs no new snapshot/ceremony; meaningful changes show exact consequences and hold
  new protected work until an authorized explicit linked continuation succeeds.
- [ ] Supported current selections produce one successor with preserved old lineage; stale previews, concurrent
  changes, lost responses and unknown original effects cannot silently rebind or duplicate execution.
- [ ] Retained questions/answers/proposals survive but applicability is revalidated; no automatic paid regeneration,
  transferred approval or Apply follows configuration change.
- [ ] Denied/unavailable providers and host/authority failures are honest; credentials stay protected and requested
  versus reported model facts remain distinct.
- [ ] Owned client/continuation integration tests and actual accessible supported-path evidence pass.
