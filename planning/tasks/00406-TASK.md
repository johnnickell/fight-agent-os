# Inspect exact local-generation feasibility

## Outcome

An authorized caller inspects whether exact installed starter inputs can generate a new local project at the
selected Runner-accessible destination. Protected query/console results supply truthful bounded facts to the
complete creation preview without creating files, reserving paths or running source commands.

## Scope

- In scope: Installed snapshot/manifest inspection, independent name/branch/path validation, canonical containment,
  exact transformation feasibility, current Runner/root capability checks and safe read-only results.
- Out of scope: Full browser form/preview, attempt admission, destination reservation, root/mount changes, source
  fetching, profile registry, filesystem mutation, Git initialization, preparation and publication.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Inspect exact generation inputs | N/A — read-only | Authorized snapshot/digest/manifest and exact selected substitutions | N/A | Safe transformation facts or refusal; no source fetch or execution |
| Inspect the selected destination | N/A — read-only | Canonical root/parent/destination, collisions and current bounded access | N/A | Scoped path feasibility without creating or reserving anything |
| Explain capability limits | N/A — read-only | Actual enrolled Runner/root/tool availability and freshness | N/A | Distinct denied, stale, unsupported or unavailable reasons |

## Validation and permissions

Reuse TASK-00402's versioned manifest and immutable installed bytes, TASK-00073's approved-root authority and
TASK-00368's authenticated Runner identity/capability facts. This slice owns the bounded local feasibility query,
not another root registry, remote shell or sandbox. Configuration and enrollment alone do not prove access; qualify
actual scoped Runner-side inspection. Missing access returns unavailable, never an unrestricted host fallback.

Require current initiating-human read/inspection authority for the Workspace, snapshot, Host/Runner and selected
root. Known IDs, source permissions or an earlier preview cannot authorize unrelated path inspection. Bound bytes,
entries, names, path depth, transformation work and runtime probes. Do not enumerate unrelated directories or leak
hidden contents through collision details, raw errors or environment dumps.

Keep display name, Workspace slug, local directory, parent path, initial branch and optional remote name independent.
Validate supported platform path/name/ref rules without shell interpolation. Suggesting `develop` does not create
it or override a selected `main`. Do not request Composer vendor/package identity merely because Composer exists.
Recheck pinned digest/manifest version, every declared target/match and chosen substitution value. Missing, duplicate,
unsafe, ambiguous or changed targets reject; no alternate release, broad search/replace or model repair.

Resolve existing path components, approved-root identity, safe nested parents, containment and collisions against
actual observations. Detect symlink escape, traversal, unsupported filesystem semantics and ambiguous ownership.
An absent path is only an observation, not a durable claim; later mutation must revalidate and fence the destination.
Outside-root selection requires the separate explicit installation/mount operation, not browser configuration repair.

Return bounded safe facts with exact source/manifest/input/root/Runner generations and observation freshness for
TICKET-00101 to bind into its full preview. Local feasibility does not certify profile, GitHub or registration
availability. Reads never seed, refresh, authenticate, reconcile, prepare, initialize Git or create an attempt.
Installed usable bytes may be inspected during a GitHub outage; missing or corrupt bytes remain unavailable.
