# Extend selective lookup to published and historical scopes

## Outcome

The same authenticated, bounded typed memory lookup can select currently authorized published Repository/
Workspace entries and, on a distinct explicitly authorized path, retained shared or private historical
entries. Published, historical and audit scopes preserve their owning Application access policies; Jev
never inherits a steward, reviewer or audit Agent's Permissions independently. Matching IDs remain
references for a later exact read under freshly checked authority. This TASK owns one independently
reviewable extended-scope tool behavior, not another memory query or provider implementation.

## Scope

- Extend [TASK-00194](00194-TASK.md)'s owned current-scope selection and [TASK-00193](00193-TASK.md)'s
  single-entry typed question across existing authorized reads from [TASK-00191](00191-TASK.md) for
  published Repository/Workspace entries, [TASK-00189](00189-TASK.md) for completed shared-work history,
  and [TASK-00186](00186-TASK.md) for separately permitted private oversight. Reuse the one qualified
  first-party MCP/HMAC Agent and shared Jev evaluator path; no Jev Agent identity, direct database read,
  duplicate permission service, offline store or memory-specific cache.
- For normal current guidance, select only currently published, non-retracted broader entries permitted by
  the caller's Repository/Workspace authority, alongside its eligible private/shared entries. Pending or
  rejected proposals and derived-impact notices are not guidance; an already published entry remains governed
  by its own current/retracted status even while reassessment is pending. Retain accurate source/entry
  revision without equating publication to truth. A Project
  Manager's estimation access or a human's historic read never authorizes publication.
- Require an explicit separately authorized historical/self-learning request for retained completed Workflow/
  TASK entries and corrections/retractions. Project Manager, human and audit principals use their actual
  current effective Permission and target scope from the owning history operations. For private memory,
  require `READ_PRIVATE_AGENT_MEMORIES` and target authority; an audit Agent additionally needs its real
  purpose/target-scoped audit TASK. Ordinary reviewer independence never creates peer-private read rights.
- Preserve [TASK-00194](00194-TASK.md)'s bounded eligible-candidate selection, disclosure check, partial
  coverage, evaluation/usage provenance and matched-ID-only output. A historical result identifies its
  status as historical, never instruction-grade current guidance. Later exact read rechecks the caller and
  requested target; a Jev result or prior receipt cannot revive closed, revoked or removed content. No
  provider disclosure of prohibited material until TICKET-00050's safety-removal path and egress policy
  are qualified.
- Out of scope: new historical authority, audit-TASK issuance, reviewer access to another Agent's private
  notes, browser UI, Jev-generated summaries, proposal publication, semantic embeddings, provider account
  management, routine archive and exceptional safety removal.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Narrow published guidance | Submit typed question on permitted Repository/Workspace scope | Resolve current published eligible revisions under live caller authority | Selection/usage observation | Matching published IDs with honest coverage, no proposal drafts |
| Inspect explicitly authorized history | Submit typed historical selection intent | Resolve current qualified history/audit target and status | Selection/usage and safe access observation where required | Only permitted historical matching IDs/status, not automatic guidance |
| Follow selected source | N/A — read-only | Exact original entry under a fresh permission/lifecycle check | Existing authorized-access audit where required | Bounded original content returned only to current authorized principal |
| Deny stale or improper context | Rejected judgment intent | Resolve revoked scope, unrelated Repository, absent audit TASK or reviewer isolation | Safe denial observation where required | No provider request, private title/count, or stale matched ID disclosure |

## Validation and permissions

The four direct blockers are true access/integration contracts, not a claim they are already implemented.
TASK-00186/00189/00191 currently have `needs-info` authority gaps; do not claim this TASK's extended
accepted behavior or run a live historical/provider request until those paths are qualified. This TASK
itself is decision-complete when its blockers permit execution. Preserve separate application source-read,
provider-egress and later exact-read decisions. Validate authenticated caller, actual scoped principal,
current Permission, target Repository/Workspace and lifecycle at request and result release; candidates
that turn inaccessible during evaluation cannot be disclosed from a prior snapshot. Scope IDs and model
answers are not access tokens. Protect private payload, rejected drafts and prohibited content in Jev
requests, receipts, errors and output. Missing service/database means unavailable, not an offline fallback.

## Acceptance criteria

- [ ] A genuinely authorized caller selects permitted published Repository/Workspace memory and receives
  only eligible matched IDs/revisions; an unprivileged Engineer cannot use a source entry, job title or
  publication proposal to search another target's guidance.
- [ ] Qualified Project Manager/human/audit principals can run separately explicit historical selection
  for their actual scope; ordinary Engineer/Team Lead closure and reviewer independence still block
  unauthorized past Workflow or another Agent's private content.
- [ ] Private historical selection requires actual `READ_PRIVATE_AGENT_MEMORIES`, current target access and,
  for an audit Agent, its real assigned audit TASK. No positive path is accepted from a fake audit assignment.
- [ ] Retracted or rejected material never enters normal guidance; historical results are labeled and
  bounded, provider input is admitted separately, incomplete outcomes stay incomplete, and a later exact
  read can fail after revocation or safety removal without resurrecting cached bytes.
- [ ] No Jev-derived permission, source-of-truth claim, automatic startup memory dump, silent fallback or
  live unsafe disclosure is introduced.
