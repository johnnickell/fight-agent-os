# Publish and clean isolated work during landing

## Outcome

Make an explicit `land` invocation finish the complete human-review handoff: record accepted completion everywhere,
push the final feature branch, create or update its pull request, return the PR link, and remove the clean isolated
worktree plus ownership-proven TASK Docker resources without requiring separate publication or cleanup permission.

## Scope

- In scope:
  - Change `.pi/skills/land/SKILL.md` and `docs/engineering/LANDING.md` so invoking `land` grants bounded planning,
    landing-commit, push, PR creation/update, and ownership-proven cleanup authority for that TASK.
  - Require the final pushed branch to contain TASK completion evidence, generated planning views, and the PR URL;
    verify the remote PR head before cleanup and always return a clickable PR link.
  - Remove a clean registered isolated worktree after publication when landing runs from another checkout.
  - Remove only exact TASK-owned containers, volumes, and ignored build outputs supported by inspected ownership
    evidence; handle root-owned ignored Docker build output without broad pruning or forced worktree deletion.
  - Reproduce the TASK-00067 retained-worktree failure and directly verify the corrected workflow instructions.
- Out of scope:
  - Automatic PR approval or merge, remote-branch deletion, release, deployment, certification, or archive.
  - Broad Docker pruning, shared-service teardown, ambiguous resource deletion, or deleting a dirty/active worktree.
  - Creating a project changelog where none exists or changing unrelated execution/review skills.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Land accepted isolated work | `/skill:land TASK-NNNNN` | Read accepted review, TASK, generated views, Git/PR state, registered worktree, and ownership evidence | N/A — repository workflow | Final records are committed and pushed, PR is created/updated, URL is returned, and safe owned resources are removed |
| Reject unsafe cleanup or publication | N/A — landing coordinates Git, hosting, and exact cleanup commands | Inspect credentials, remote/PR state, active checkout, dirty files, container/volume labels, and ignored output preview | N/A — no application event | Landing stops before destructive cleanup and reports the exact unmet condition rather than claiming completion |

## Validation and permissions

The explicit `land` invocation is the user's authority for TASK-owned planning finalization, landing commits,
non-force push of the named feature branch, creation/update of its PR against the accepted base, and cleanup of the
clean non-active isolated worktree and exact ownership-proven TASK resources. Approval, merge, remote-branch deletion,
archive, release, deployment, and certification remain unauthorized.

Before mutation, require an independently accepted exact implementation head, clean understood state, valid feature
ancestry, available authenticated remote/hosting operations, and a cleanup plan. If the target worktree is the
landing session's active checkout, stop before finalization and require rerunning `land` from another checkout so the
session never deletes its own working directory. Preserve dirty, shared, durable, or ambiguous resources.

## Acceptance criteria

- [x] `land` treats explicit invocation as bounded authority to finalize planning, commit, push, create/update the PR,
      and clean ownership-proven TASK resources; it no longer silently stops after a local commit for missing
      separately repeated publication or cleanup permission.
- [x] Landing creates or updates the PR, records its URL in the TASK and generated views, pushes that metadata, verifies
      the remote PR head equals the final local commit, and returns the clickable URL.
- [x] Landing stops before mutation when authentication, remote/hosting access, accepted base, or safe publication is
      unavailable; it never presents local-only completion as a successful landing.
- [x] A clean registered isolated worktree is removed only after final push/PR verification and only from a different
      active checkout; dirty, current, unregistered, or ambiguous worktrees are preserved with an explicit failure.
- [x] Cleanup previews and removes only exact ownership-proven TASK containers, volumes, and ignored build outputs;
      broad prune/shared teardown/forced worktree removal remain prohibited.
- [x] Root-owned ignored outputs produced by containerized checks are handled through an exact inspected path so they
      cannot leave an unregistered residual directory after worktree removal.
- [x] The final handoff distinguishes PR publication from human approval/merge and reports the PR URL, retained local
      branch, every cleanup result/refusal, warnings, risks, and remaining human action.
- [x] No changelog is invented; the authoritative TASK, generated Board/indexes, and existing completion surfaces are
      current before publication.
