# Persist input and fence original attempts

## Outcome

Authorized input becomes durable before delegated work can start, with stable submission/attempt identity and one
fenced active-turn owner. Provider admission/accounting and runtime consumers share the same original attempt and
cancellation state rather than inventing separate queues or accepting client process IDs as authority.

## Scope

- In scope: Protected submit/inspect operations, bounded durable input and exact snapshot references, current
  attempt/owner generations, claim/release/outcome participants, cancellation/hold markers and original recovery facts.
- Out of scope: Runtime/process launch, paid calls, model-context transcript duplication, provider accounting,
  proposal/answer semantic acceptance, Workflow scheduler, browser UI and actual process stop/takeover.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Submit input | Authorized original submission with expected conversation/question state | Current assignment, snapshot binding and accepted input identity | Committed input/submission facts | Durable bounded input and required audit before any delegated execution |
| Own one attempt | Authenticated expected-state attempt claim/release/outcome participant | Current owner/epoch, pending input and exact original attempt | Committed owning attempt facts | At most one active turn; no external effect from a state claim alone |
| Mark stop/hold or reconcile | Authorized cancellation/hold marker; original-status reads are queries | Exact original generation, pending effects and lifecycle state | Confirmed state facts only | Fence new work, retain uncertainty and original accounting references; not proof of process quiescence |

Consume TASK-00348's real intent/delegation and TASK-00340/00341's exact binding/currentness. Authenticate human,

from an attachment or status read. Retain exact pending question identity, accepted input and answer/proposal
references; TICKET-00091 owns semantic decision/proposal acceptance. Old answers do not renew expired approvals.

Complete owned input/attempt/required audit and any necessary durable intent on the canonical shared connection.
TASK-00344/00345 consume actual transaction participants for budget admission/outcome correlation without nested
transactions, another generic queue or credential-delivery state. Claiming an attempt alone grants no provider/
tool use; TASK-00351 composes final admission and TASK-00350 qualifies host ownership. Stale owners, duplicate
callbacks, changed-away-and-back generations and revoke/regrant cannot revive old acting windows.

Cancellation/hold records immediately fence new admission. Unknown owner liveness or external effects remain held;
no release/reclaim merely because a heartbeat disappeared or a lease elapsed. TASK-00353 performs actual process/
effect reconciliation and stop recovery. Preserve legitimate attributable late outcomes/accounting against the
original operation without letting them overwrite a newer lifecycle, re-open work or attach to another input.
Protect stored input under owner-first access/retention; ordinary history/progress excludes raw prompts, secrets
and hidden reasoning. Missing storage/authority denies rather than falling back to local files or in-memory input.

- [ ] Real protected submission persists exact input/identity before execution; duplicate/lost acknowledgements
  resolve the original without another input, attempt or conversation.
- [ ] PostgreSQL independent races enforce one active turn/owner, coherent binding and atomic required audit;
  stale writers, conflicting input and partial rollback cannot dispatch or overwrite state.
- [ ] Actual provider admission/outcome consumers can share the original transaction/fence contract independently
  of completed runtime execution; unsupported participants cannot activate the path.
- [ ] Stop/hold state fences new work and preserves original uncertain effects; claiming/releasing state never
  invents quiescence, resets limits or restores approval validity.
- [ ] Safe owner-first inspection preserves pending questions and references without launch, retry or disclosure
  of another conversation's private input.
