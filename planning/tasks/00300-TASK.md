# Author and publish human-reviewed Agent templates

## Outcome

An authorized administrator can browse managed/custom templates, create a custom template or revise a managed
or custom one, review the complete prompt and requested Permissions with history/diff and affected Agent
references, then explicitly publish. This delivers the human editor/publication path consumed by TICKET-00077's
AI proposals and TICKET-00079's custom-role use, without waiting for TASK-00301's ancestor review/rollback.
One complete browser/API/Application/persistence outcome normally owns one PR.

## Scope

- In scope: Authorized browse/detail/history/diff and impact; scoped custom creation and managed/custom revision;
  volatile human draft/review; complete candidate validation; atomic immutable publication/current selection and
  required audit; original-outcome inspection, safe conflicts/uncertainty, accessible browser integration.
- Out of scope: Another template/resource/Permission catalog, source seeding or reconciliation, AI/provider calls,
  ancestor-update review or retained-revision rollback (TASK-00301), Agent creation, Permission assignment,
  profile rebinding, session refresh, generic Skill editing, Workflow routing or a proof-only screen.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Browse and inspect a template | N/A — read-only | TASK-00299's scoped template/history authority, TASK-00249's exact resource/profile facts, TASK-00259's authorized Agent references | N/A — reads create no business fact | Bounded safe list/detail/history/diff and attributable impact observations |
| Prepare a human candidate | Volatile editing; no implicit publish | Current eligible Permission choices, resource/model/Repository constraints, complete candidate validation and current base | N/A — preview grants nothing | Explicit unsaved/reviewed/stale state bound to exact content and scope |
| Publish a new custom template or reviewed revision | Owned Harness publication operation under current human authority | Fresh expected selection generation, complete candidate/reference checks and reviewed intent | Owned committed template/revision publication fact after commit | Stable identity where new, immutable revision, current selection and required audit commit together |
| Inspect an uncertain publication | No automatic repeat or compensation | Authorized original-publication outcome and current history, distinguished explicitly | No new publication event on inspection | Original result or truthful unresolved state before another human action |

Names describe owned behavior, not existing message classes or a new generic workflow. Reuse TASK-00299's type-
specific Harness store, identity/provenance and audit ownership; do not create an editor-specific registry.

## Validation and permissions

### Current authority and safe inspection

Use TASK-00299's approved managed `MANAGE_AGENT_TEMPLATES`, SUPER_ADMIN_ONLY and assigned only through managed
Super Admin, without another Permission definition. Require trusted current human identity, intent, installation,
Workspace/registered-Repository scope and target on every supported HTTP/direct-bus/CLI/worker entry. Unsupported
modes stay unavailable; a model, Agent, Role label, UI guard or supplied actor ID cannot publish. Preserve existing
HTTP authentication and applicable mutation/Origin/CSRF controls; direct calls cannot bypass Domain/Application
policy. Template rights neither grant Agent management nor authorize provider disclosure.

Reuse TASK-00259's Agent inspection and its separate current scope/management checks for affected-Agent details.
Show exact bound revisions separately from future template selection; do not duplicate a directory or expose
credentials, lifecycle internals or hidden names/counts. Bound list/history/diff/impact reads with stable ordering,
explicit coverage and freshness. An inaccessible join or incomplete page set is not an empty complete impact
result. Do not invent affected Agents or current sessions when their owning capability is unavailable. Publication
changes no existing Agent, so impact is an attributed observation, not a promise that no later Agent can be created.
Required review cannot be satisfied by a failed or misleading preview.

Render prompts/diffs as inert content, not HTML, executable instructions or a source of authority. Protect original
scope/provenance and historical resource identities; no name-based identity replacement, cross-scope inheritance,
secret-bearing resource configuration or unrestricted entity serialization. Reads emit no revision/audit-change
fact, repair references or select a new current revision.

### Complete human review and candidate validation

Support installation/Workspace-wide and registered-Repository-scoped custom templates and revisions of the managed
starting templates through the same owned publication boundary. Preserve managed origin, stable logical identity,
functional role/persona, complete system prompt, desired direct-Permission set, resource/model/Repository constraints,
ancestry and source provenance. A new custom template is not a managed catalog entry or an AccessControl Role.
Generate new identities with the owning factory/UUID library; neither aliases nor caller-selected IDs replace
existing identities. Record any selected ancestor as an exact authorized revision, not a moving name/current pointer.

Review both prompt and the complete desired set. Bind publication intent to actor, target/new-template intent,
scope, exact candidate and expected base/selection generation. Editing any relevant input invalidates the prior
review; cancellation dispatches nothing. Do not accept a client Boolean or a model assertion as authorization.
Bound prompt/field sizes, collection counts, ancestry depth, input and query duration with explicit safe failures.

Reuse AccessControl's supported Permission queries and current ID/tier checks; list results are choices, not
write authority. Requests must be current eligible ADMIN_SAFE IDs within approved grant limits. Missing, removed,
ineligible, ambiguous or wrong-scope items require explicit correction and renewed review; never silently drop
them, substitute names, create Permissions or assign a SUPER_ADMIN_ONLY right to an Agent. Preserve historical
requests rather than rewriting old revisions after later Permission changes. Recheck at actual Agent assignment.

Consume TASK-00249's exact resource/model/scope facts and their type-specific owners. A read-only resolver over
published revisions is not an unpublished-candidate validator or atomic publication guarantee. Validate the complete
candidate without temporarily publishing/staging it as current, inventing inline replacement resources or adding a
second resolver. No provider call is needed to save a human-authored template; configured/requested model constraints
are distinct from measured suitability or live provider availability, with unavailable capability shown honestly.

### Publication-safety hold and atomic state

Keep `needs-info` until the supported complete-candidate validation and final reference/current-authority fencing
composition is qualified. Record actual participating writers, currentness guarantees and transaction ordering for
template selection, resource revision/lifecycle, Repository scope and Permission removal/reclassification, plus
all actual old source writers excluded by TASK-00299. Resolve required primitive mappings under their existing
owners; read-only preflight checks, a build or a successful seed cannot substitute for this guarantee. Missing
upstream seams require separately authorized owner work/qualification, not vendor patches or invented blocker IDs.

The owned Harness publication handler controls one canonical transaction on the shared connection under ADR 0002.
Append the exact immutable revision, compare and advance expected current-selection generation, and commit required
review/provenance/audit together. New-template creation must be equally atomic under competing identity/alias/scope
claims. Preserve applicable reference/cohort lock ordering; repositories do not begin/commit hidden transactions,
flush independently or hide policy/audit. Do not wrap package handlers in a nested transaction. External/provider
or filesystem effects remain outside. Later source input cannot overwrite the database selection.

Stale expected state, including selection moving away and back, conflicts rather than overwriting newer work.
No-op behavior still validates current rights and references and must not fabricate another publication fact.
Retain all prior revision bytes and Agent/session references. Publication cannot call Agent assignment, credential,
binding, session or Workflow mutation handlers; references describe requested behavior, not live authority.

Bind the actual original publication to durable owned revision/audit provenance sufficient for safe authorized
outcome inspection. Lost acknowledgement or post-commit event failure does not establish rollback; later equal
content or a matching current pointer alone does not prove the original result. Qualify duplicate same-intent and
conflicting-payload handling without replaying uncertain publication or creating another custom template. Keep
unresolved status explicit; do not create a generic operation ledger/outbox or promise eventual event delivery.

### Browser ownership and AI-independent publication

Use TASK-00051's authenticated frame and ADR 0003/0004's sole `/me`, exact evaluator, private-data generations and
memory-only state. Guard loaders, routes, controls and callbacks; retire old successes/errors and protected drafts/
previews on applicable context/authority invalidation. Never let a delayed response restore old state or terminate
a newer login. Refresh authentication does not replay publication. No browser storage, URL/history/base-HTML draft,
autosave queue, broadcast prompt/Permission list or second principal store. Private success/error responses are
no-store; redact bodies, arbitrary exceptions and provider/credential configuration from ordinary telemetry.

Show unsaved, reviewed, publishing, published, stale, denied, unavailable and uncertain states honestly. Provide
keyboard/focus/error recovery, cancellation and narrow/wide light/dark evidence through existing components.
Bound refetch/reconciliation and preserve a newer draft against old responses; explicit conflict resolution requires
fresh human review, not automatic merge-and-save. A lost browser draft is not a published revision.

Do not flag the editor or publication path with `ai-template-proposals`. Human-only authoring works when that
Feature is OFF or its catalog/provider path is unavailable, subject to ordinary current authorization. TICKET-00077
adds bounded suggestions to this same draft/review/publication boundary, not another publisher or self-approval
path. TASK-00301 consumes this boundary later; neither AI nor finished ancestor review blocks its delivery.
