# Establish and prove controlled landing

## Outcome

The repository has a concise project-local `land` skill and shared landing/ownership standards that close reviewed implementation deterministically, publish only authorized work, clean only demonstrably owned resources, and return merge control to a human. Bounded demonstrations prove both successful handoff and safe refusal.

## Scope

- In scope: Add `.pi/skills/land/SKILL.md`; add or refine concise shared landing and resource-ownership standards; verify independent review and blocking-finding disposition; finalize TASK evidence/status and generated planning views; run required final checks; commit, push, and open/update a PR only when authorized; clean only TASK-owned resources; hand off for human review/merge; demonstrate a successful path and at least one refusal path.
- Out of scope: Repeating implementation review, repairing unresolved defects, planning decomposition, autonomous merge, archive, release/deployment/certification, broad environment cleanup, deleting shared or ambiguous resources, and publication without explicit authority.

## Validation and permissions

Stop for missing independent review, unresolved blocking findings, stale or incomplete acceptance evidence, failing required checks, unexpected unrelated changes, inconsistent branch/diff state, missing commit or publication authority, unavailable remote/hosting prerequisites, or ambiguous cleanup ownership. Trust the review verdict only after verifying its presence, independence disclosure, target/baseline, and finding dispositions; do not repeat implementation review.

Run `./bin/planning-check --write`, `./bin/planning-check`, required focused checks, `git diff --check`, and final `./bin/build`. Preserve every warning, skipped check, and remaining uncertainty. `done` records implementation acceptance and required verification, not PR publication, merge, release, deployment, certification, or archive.

Cleanup is limited to ownership-proven TASK scratch, worktrees, prototype folders, captured processes, test databases, and task-specific containers/volumes. Shared services, source files, durable evidence, and ambiguous resources require explicit human direction.

No application permission model applies. Landing may edit authorized planning/documentation and may commit, push, and create/update a PR only where TASK/user authority explicitly permits. It may not re-scope requirements, fix implementation, merge, deploy, release, certify, archive, or delete ambiguous resources.
