# Inspect optional allowance in connection settings

## Outcome

An authorized user inspects recorded provider allowance for their own exact connection in self-service settings,
and explicitly requests bounded refresh through the existing allowance owner. This complete settings interaction
reuses source/admission/query contracts rather than requiring a Workflow or creating another accounting system.
It is optional for first production and never gates connection management or useful browser Planning.

## Scope

- In scope: Current-authorized connection-settings composition, recorded allowance query consumption, explicit
  refresh interaction and original-refresh recovery, safe provenance/status presentation and browser invalidation.
- Out of scope: Allowance source/admission/storage reimplementation, provider transport/authentication, connection
  secret entry/lifecycle, model discovery/defaults, generation, billing management, new budgets/ledgers/live channels,
  Workflow creation, forecast/usage replacement and hosted ChatGPT.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Inspect your recorded allowance | N/A — current-authorized read | TASK-00399's sanitized snapshot for TASK-00520's exact owned connection/generation | N/A from reads | Show recorded source/scope/time/units and unavailable/stale/partial states; no external request |
| Explicitly refresh allowance | Existing TASK-00399 bounded refresh intent | Current ownership/refresh authority, exact generation and original refresh state | Existing owner observation facts only | Existing TASK-00346 protected metadata read after owner admission; no new queue or credential exposure |
| Recover failed or uncertain refresh | Read original outcome; explicit owner-supported reconciliation only | Original refresh identity and current authorization | Existing owner facts only if its operation commits | Preserve uncertainty/stale facts without implicit polling, blind repeat or account substitution |
| Leave or change connection context | N/A — local invalidation, not a Domain command | Fresh current-authorized connection/allowance after context changes | Local client invalidation only | Retire private cached data and old requests; no refresh or mutation as a navigation side effect |

## Validation and permissions

Consume TASK-00520's safe connection identity/status and ownership/current-generation checks. TASK-00399 owns
allowance refresh admission, sanitized durable observations and authorized recorded queries; TASK-00346 alone
owns the protected OpenRouter `/key` transport. Reuse those existing capabilities through the shared API/client
and owning application handlers, adding only justified settings composition. No generic forwarding aliases,
shadow observation store, quota calculator or second provider adapter.

Preserve `/api/v1/me/provider-connections/{connection_id}/allowance` as the recorded GET direction. Exact explicit
refresh route/payload follows its owner contract. Current self-service connection ownership and intent-specific
allowance disclosure/refresh authority are checked on the server; Repository/Workflow/conversation access or
administrator status alone is insufficient. A connection ID from the browser/model does not grant authority.

The settings surface uses the account-scoped query/refresh contract without a dummy Workflow, dependency on a
Workflow record or duplicated Workflow UI. TASK-00399's existing TASK-00391 delivery dependency remains unchanged;
its unfinished source/host qualification can delay this optional interaction, not the required first-browser path.

Show only supported facts with exact provider/account/key scope, source/report time, units, reset/window and
partial/stale/pending/unavailable distinctions. Cap is not wallet balance or guaranteed capacity; null is not
unlimited. Separate provider allowance from local conversation usage/application budgets; never subtract usage to
invent a balance, multiply a shared allowance across Agents or imply different keys have different wallets.
Missing allowance neither hides connection management nor disables otherwise safely admitted work.

Normal render, GET, navigation, reconnect and status inspection cause no provider/login/model-discovery request.
Only explicit refresh uses the owner's bounded effect path and original identity; uncertain results do not trigger
automatic replay. Replacement/disconnect fences stale snapshots and refresh publication, preserving original
inference liabilities. No refresh extends budgets or reactivates a retired connection.

Follow ADR 0003/0004: no-store/private responses, volatile scoped state, server-authoritative permission and
identity/generation-fenced successes and errors. Clear retired private data on context changes; abort alone is not
sufficient. Do not expose key/ciphertext/handles, raw provider bodies, unnecessary account identifiers or arbitrary
errors in browser/logs/evidence. Refresh does not collect another key or request provider login.

## Acceptance criteria

- [ ] The actual connection-settings path displays current-authorized recorded allowance and explicit refresh using
  TASK-00399's real contracts, without a Workflow record, duplicate store, refresh engine or provider adapter.
- [ ] Normal reads/render/reconnect and denied refresh cause zero provider requests. Explicit refresh binds the exact
  owner/environment/connection generation and preserves original identity through failure and uncertain outcomes.
- [ ] Display distinguishes source/scope/time, reported units/reset windows, stale/partial/pending/unavailable and
  true zero values. Unsupported fields remain unknown rather than synthetic balance/capacity.
- [ ] Replacement, disconnect, logout, identity/environment change and late successful/error responses cannot expose
  another connection's observations or restore a retired snapshot; current server authority always governs reads.
- [ ] Allowance failure/absence leaves connection management and independently admitted Planning usable, without
  borrowing another connection, replaying paid work or changing budgets/defaults.
- [ ] Actual keyboard/focus/announcements, narrow/wide light/dark and retry/uncertainty states work with safe browser
  evidence; provider/source qualification remains attributable to TASK-00399/00346, not claimed from UI doubles.
