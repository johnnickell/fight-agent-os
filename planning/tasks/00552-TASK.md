# Automatically reuse unchanged successful build receipts

## Outcome

Repeated normal build invocations reuse a verified successful receipt when project contents, installed
dependencies, runtime and retained artifacts match, avoiding repeated ten-minute gates across agent roles.
John authorized implementation in an isolated worktree, runtime fingerprinting, `--force`, existing-receipt reuse
and guidance updates in the October 31, 2026 chat.

## Scope

- Extend the canonical PHP build and local wrapper, keeping the existing phase graph and receipts.
- Fingerprint actual project/dependency contents and runtime; retain a small ignored `var/build.json` pointer.
- Validate original evidence and artifacts, guard before/after identity, invalidate before attempts and publish atomically.
- Add `--force` to both entry points; update agent guidance to use the normal build command.
- No product feature, remote cache service, cross-environment success sharing, publication or independent acceptance.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Verify unchanged work | `./bin/build` or native `php scripts/build.php` | File/runtime digests, guarded database identity, original receipt and artifacts | N/A tooling | Reuse exact original pass or execute existing full phase graph |
| Demand fresh execution | Same commands with `--force` | Same identity/stability checks | N/A tooling | Invalidate old cache, run every phase, write existing receipt and publish eligible success |
| Reject stale evidence | Normal command | Missing/changed inputs, failed/interrupted attempts, evidence integrity | N/A tooling | Never fall back to an older green run; execute full gate |

## Validation and permissions

Use the user-selected isolated worktree from `develop`, preserving unrelated main-checkout work. Use an isolated
tmpfs test database and explicit existing dependencies/tool image. Never persist secret environment values in
fingerprint receipts. Qualify tooling directly with its owning PHP/CLI tools, not the product test suite.
