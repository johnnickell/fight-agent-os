# Standardize HTTP Actions on handle and Responders on respond

## Outcome

Every owned HTTP Action exposes an explicit `handle()` entry point rather than relying on `__invoke()`;
Responders continue to present results through `respond()`. Slim routing, API input-attribute discovery,
public form projection and attribute-owned OpenAPI remain aligned with the actual handler method without
changing observable endpoint behavior. This is a standalone convention/adapter migration, not an amendment
to the already accepted TASK-00151 implementation or its PR.

## Scope

- In scope: Migrate the existing API Actions (`CsrfBootstrapAction` and `ReadValidationAction`) to `handle()`;
  preserve the existing web Actions' `handle()` convention and all Responder `respond()` calls; adapt the
  actual Slim API route callable, post-routing `ApiInputValidation` lookup, `SchemaProjection` declaration
  lookup, public-form registration guidance and affected tests/API/engineering guidance to the same method;
  qualify attribute scanner behavior and future Action/public-guard integration against the installed stack.
- Out of scope: New routes or form registrations, changes to CSRF or JWT policy, permissions, CORS, public
  catalog safety, JSend/OpenAPI wire shapes, input-validation rules, business use cases, migrations, package
  upgrades, generic controller frameworks, a dual `__invoke()`/`handle()` compatibility API, or product tests
  of router configuration, attribute text, generator output or tooling.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Dispatch an existing API request | Existing endpoint-owned commands only; no new command | Existing bootstrap or public catalog read | None added | Same status, headers, envelope, authorization and no-store behavior as before; Slim calls `handle()` on the injected Action |
| Validate declared API input before dispatch | None on rejection | Read method-owned source/Validation attributes for the routed Action | None | Same bounded checked input or safe rejection; no bypass when the declared method or metadata is missing/ambiguous |
| Export and read public form schemas | Explicit existing CLI; no new domain command | Resolve future named Action's `handle()` Validation declaration and opt-in publication | N/A — tooling | Deterministic complete private artifact and unchanged anonymous catalog read; no automatic publication |
| Produce endpoint documentation | Existing OpenAPI exporter/checker | Scan real Action operation attributes | N/A — tooling | Same documented operations; method rename does not invent or remove a public endpoint |

## Validation and permissions

Preserve TICKET-00010's explicit single-source input and attribute-order policy and TICKET-00036's
independent public allowlist. Its historical `__invoke` method references describe the existing
implementation; this TASK changes only the method location and must reconcile those references in the owning
TICKET and current guidance before claiming completion. The maintainer requested `handle()` for Actions and
approved keeping `respond()` for Responders; no permission or validation-policy change is implied.

Keep Action class identity stable for TASK-00117's later explicit public exception. A route resolver change
must still expose a bounded known Action to post-routing validation; reject unknown/ambiguous callable forms
as configuration errors rather than skip validation. Keep CSRF cookie/origin/Fetch checks, validation metadata
source/field rules, anonymous catalog read, safe missing-artifact errors and responder-owned status/headers
unchanged. Do not create a second handler method merely to keep old tests passing. Preserve the supported
OpenAPI/source/Validation/access attribute targets and ordering when declarations move to `handle()`.

## Completion notes

Implemented on `feature/task-00156-standardize-http-actions` from `develop` (implementation commit recorded by Git). API routes now use Slim's `Class:handle` notation: installed Slim 4's `CallableResolver::resolveSlimNotation` resolves that string via the container, and `Route::handle` dispatches the resolved method. Web routes already call injected Actions' `handle`. Both API Actions retain their attributes on the executed method, with no invocable shim. The post-routing middleware requires a class-string `:handle` callable and a public declared method before reading source/Validation attributes; class identity still distinguishes the CSRF bootstrap. Public schema projection reads the named Action's `handle` without changing the allowlist. Existing Responder `respond` paths and operation IDs are unchanged.
