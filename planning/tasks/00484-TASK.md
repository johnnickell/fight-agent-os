# Launch and reclaim bounded temporary restore runtimes

## Outcome

Restore owners can reserve, launch, inspect and reclaim exact private temporary runtimes through a narrow enrolled
installation capability. This approved slice D of [TICKET-00117](../tickets/00117-TICKET.md) supplies the actual native
mechanisms, not a generic provisioner or a claim that provisioning proves restored query readiness.

## Scope

- In scope: Scoped native provisioning/removal adapters, process/storage/network/credential isolation, fixed owner
  generation binding, bounded resource reservation/accounting and supervision/cancellation/reclamation evidence.
- Out of scope: Restore request/authority state, archive verification/import, content readiness, scheduled retirement
  policy, public scope administration, arbitrary container/command APIs or another backend/storage stack.

Consume TASK-00482 private storage/physical allocations, TASK-00483 runtime supervision and TASK-00461's qualified
backend integration. Implement only exact owner-scoped operations on installation-owned temporary resources, never
caller-selected images/commands/mounts/URLs/tenants. Keep backend provisioning credentials away from requests, browser,
Agents and ordinary sinks. Exact native launcher exposure/security acceptance is a prerequisite, not inferred from
existing Docker access or the historical Loki experiment.

Supply usable early capacity/lifetime contracts for TASK-00474, actual provisioning/disposal for TASK-00475 and
retirement/removal observation for TASK-00477 without depending on those completed consumers. Native attempts carry
original identity, exact resource ownership and generation; unknown authority/ownership denies new effects or unsafe
removal. A stale worker cannot publish, control or delete successor scopes. Consumers retain authoritative job/requester/
policy leases on the canonical owner boundary; this capability adds no competing restore state or permission store.

Enforce [WF-039](../wayfinder/tickets/WF-039-define-searchable-retention-and-verified-archives.md)'s one running/four
pending, one outstanding/requester and four-ready-scope profile through the owning admission integration; native capacity
must not silently exceed it. The worker is bounded to 512 MiB/1 vCPU with additional measured finite backend resources;
all temporary staging/indexes/imports/residuals fit the aggregate 4-GiB physical limit. Execution lasts <=15 minutes,
requests <=30 seconds; owner pending/ready deadlines remain one hour/fixed 24 hours. Native runtime fit does not prove
that a full 1-GiB archive selection is query-ready; TASK-00475 owns that evidence.

Count uncertain/abandoned resources until actual disposition is known. Provider cancellation/HTTP success or missing
process contact does not prove stopped work or freed bytes. Reconcile the original native attempt, bounded inventory
and exact residuals after interruption. Prevent late work from recreating retired resources. Source lease release and
logical requester denial remain with TASK-00474/00477, never contingent on successful physical cleanup. No read/export
renews lifetime and no temporary copy becomes an independent preservation owner.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Reserve and launch an owned temporary runtime | Enrolled exact native provisioning request | Current owner/generation/capacity and qualified image/storage | Owner lifecycle facts only | Isolated finite resource allocation, not content-ready status |
| Inspect/cancel/reclaim exact work | Narrow owning native operation | Actual process/storage and original attempt | Safe disposition observations | Truthful stopped/removed/reclaimed states, residuals counted |
| Recover an uncertain attempt | Reconcile original identities | Current ownership and bounded actual resources | Existing recovery facts only | No duplicate grant, stale successor deletion or hidden leftover |

## Validation and permissions

Use existing installation authority plus exact owner operation scope, not RESTORE_LOG_ARCHIVES as an infrastructure
grant. Follow ADRs [0001](../adr/0001-application-ownership-and-orchestration.md) and
[0002](../adr/0002-postgresql-consistency-and-durable-effects.md); external effects occur outside owner transactions.
Keep all networks/credentials/private status scoped and secret-safe. Runtime state belongs under ignored `var/`, not
`.runs/`. Every actual launch/destructive qualification requires bounded explicit authority and cleanup ownership.

## Acceptance criteria

- [ ] Actual native launch/storage/network/credential isolation protects live data and other temporary scopes without
  exposing a general Docker/backend API or claiming content readiness from health/provisioning success.
- [ ] Real capacity/reservations, worker/backend/physical limits and original generation/lifetime participation
  support the accepted restore profile; uncertain allocations remain counted.
- [ ] Stale/unknown operations, restart and cancellation races cannot resurrect retired work, release capacity early
  or delete successors; exact physical reclamation is distinct from requested/processed removal.
- [ ] Early contracts are consumed without waiting for finished import/browser/retirement; requester authority and
  logical expiry remain independent of native cleanup failure.
- [ ] Owned operation/generation tests, direct launcher/provider/resource qualification and full `./bin/build` pass
  with exact unsupported cases and residual state recorded.

## Verification and evidence

Use separately approved isolated temporary targets and actual provider/runtime tools to qualify fixed operations,
resource pressure, process death, late operations, failed removal and restart reconciliation. Controlled native inputs
prove the mechanism, not product import readiness. Test owned adapters/participants, not configuration, wrappers,
migrations or vendor internals; record exact images, credentials scope, bounds, physical bytes and warnings. Run
focused repository wrappers and full `./bin/build`; no historical probe receipt substitutes for fresh evidence.
