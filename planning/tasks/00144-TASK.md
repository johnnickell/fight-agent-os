# Break the hosted-verification review and publication cycle

## Outcome

The canonical local build is the mandatory default; optional hosted CI cannot create an acceptance blocker.
Where hosted CI is explicitly required, an implemented TASK can obtain that evidence without an empty
implementation revision or premature acceptance.

## Scope

- In scope: review/work/land/next skill routing, governing review/execution/landing guidance, completion and QA
  consistency, and direct instruction qualification.
- Out of scope: changing any consumer TASK or review, publishing PRs, modifying CI triggers, runtime sandbox
  planning, installations, or introducing a new review verdict/schema.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Route missing hosted proof | work, review, next | Canonical report, TASK, CI triggers | N/A: instruction resource | Accurate next-action handoff; no manufactured source changes |
| Obtain hosted proof | Authorized land or CI-publication request | Target identity, PR and run evidence | N/A | Bounded draft publication; final acceptance and cleanup remain pending |

## Validation and permissions

Only an independent report with no other unresolved requirements qualifies for draft publication. Preserve
existing user authority, local proof, source identity, all required hosted checks and truthful incomplete status
until implementation acceptance. Administrative completion and final delivery use the explicitly permitted
candidate/closeout contract; literal-final-head acceptance requirements require the owning authority's amendment.
A review report alone grants no publication authority. Distinguish the PR source head from an actual tested
merge candidate. Confirmed code failures return to implementation; pending infrastructure evidence does not.

## Acceptance criteria

- [x] Make the local gate mandatory and hosted acceptance evidence explicit opt-in; disclose optional CI without
      blocking acceptance, while preserving actual defects and separate merge restrictions.
- [x] Route evidence-only findings without waiving requirements or requiring empty repair passes.
- [x] Permit authorized draft publication before final acceptance with precise eligibility and stopping rules.
- [x] Support focused independent evidence continuation and preserve source/run provenance.
- [x] Align work, review, land, next, completion and visual QA instructions.
- [x] Validate metadata, links, representative instruction scenarios, planning, whitespace and the full gate;
      report author qualification separately from live invocation or independent acceptance.
