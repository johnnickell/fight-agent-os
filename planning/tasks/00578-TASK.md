# Correct directory authority catalogs and existing Role administration

## Outcome

Deliver current user-directory, authority-catalog and custom-Role interactions with visible canonical package
contracts, adapter admission and a justified typed directory projection. This is slice C of
[TICKET-00135](../tickets/00135-TICKET.md), normally one PR. Correct the shared installation-authority/reference
integration supporting these real capabilities, not a new administration API or audit-only infrastructure exercise.

## Scope

- Consume ListUsers, ListRoles, ListPermissions, GetRoleById and GetPermissionById through configured buses with
  their qualified safe package Views/results. Remove ReadAuthorityCatalogs' admission/forwarding facade.
- Turn the genuine directory User-plus-Role projection into a registered owned query/handler and safe typed result;
  replace raw users/roles arrays and transport-shaped rows. Preserve bounded deterministic pagination, exact Role
  presentation and honest missing-reference/internal-fault behavior without copying package result validation.
- Dispatch CreateCustomRole, RenameCustomRole and RemoveCustomRole directly after actual entry admission.
  Adapters generate RoleIds before void creation and own explicit removal confirmation; preserve expected revisions,
  known name/reference/business conflicts and authoritative reconciliation. Remove ManageCustomRoles and identity-
  recovery reads/wrappers with no independent responsibility; no response snapshots or duplicated message aliases.
- Correct InstallationManagedPolicy and shared installation-admission helper ownership, inward dependencies and
  descriptive names. Preserve TASK-00591's single JSON catalog, stable identities, independent live references,
  three-Permission User baseline and approved all-current/future-managed-Permissions Super Admin default. Adapters own invocation permission/target admission; required upstream callbacks use their
  actual qualified contract, not a new blanket Application gate or null/no-op hook.
- Trace AuthenticatedRoleAssignment's real callers. Remove its apparently composition/test-only forwarding graph
  if confirmed unused; do not create an authenticated assignment endpoint or replace Console-owned assignment.
- Account for existing User/Role/Permission/Agent/Feature persistence, hydration and shared reference helpers within
  this capability's scope. Correct aggregate-oriented adapter organization/names and retained callers. Preserve
  real references, permission tiers, uniqueness and actual business fences; another slice owns credential/session
  field semantics. Update moved AgentCredentialOperation contracts and repository return types with the adopted
  release; keep current unavailable Agent operation behavior explicit, not newly implemented provisioning.
- Preserve required current Role audit composition until TASK-00573 performs its independently owned explicit
  handler-audit replacement. No new specialized UoW, inference decorator, nested transaction or weakened audit.
- Migrate actual Actions/Data/Responders, composition, catalog/managed-policy runtime callers, OpenAPI, affected
  browser consumers, current runbooks and meaningful tests. Remove superseded types, imports and tests after proof.

Excludes new user/Role/Feature/Agent administration journeys, delegation/access features, upstream implementation,
Project correction, generic transaction replacement and shared safe-error replacement. No new permission or data
loss is authorized; preserve needed existing IDs, managed authority, access meaning and audit history.
