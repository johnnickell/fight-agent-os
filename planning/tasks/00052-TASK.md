# Deliver the honest permission-aware dashboard

## Outcome

The first authenticated Dashboard uses the accepted production design and sole current-principal authority to present an honest application destination, current-user/account/session navigation, and exact-permission administration shortcuts while explicitly stating that planning, observability, and agent-session capabilities are not installed and rendering no invented product data.

## Scope

- In scope: Protected Dashboard route/page composition; exact `VIEW_DASHBOARD` route requirement; safe current-user and installed-capability copy; account/security/session links; independently permission-gated Users/Invite/Invitation Recovery shortcuts; truthful empty/availability explanation; loading/stale/forbidden/system transitions inherited from frame; responsive/theme/reduced-motion production components and stories; route/component/permission/accessibility/redaction tests.
- Out of scope: Dashboard metrics/charts/activity, planning/observability/agent data APIs, workspace switching, password/session/user/invitation operation implementation, role-name shortcuts, new principal cache, server data endpoint with fabricated content, broad personalization, and client-side security claims.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Open Dashboard | N/A — navigation | Read current principal through sole cache and exact `VIEW_DASHBOARD` evaluator | Client navigation signal | Authorized user sees honest shell destination; denied authenticated user sees `403` |
| Navigate account security | N/A — navigation | Read authenticated route registration | Client navigation signal | User reaches truthful Account/Security or Active Sessions destination |
| Show administration shortcut | N/A — presentation/navigation | Evaluate exact permission required by each registered destination | Client navigation signal | Only individually allowed Users/Invite/Recovery shortcut is visible/enabled |
| Explain unavailable capabilities | N/A — static accepted product copy | Read versioned installed route/capability registry if needed | N/A — no domain event | Dashboard states what is and is not installed without synthetic records or counts |

## Validation and permissions

Require exact `VIEW_DASHBOARD` in complete route metadata. An authenticated principal without it receives TASK-00051's `403`; unknown/loading/stale state never renders Dashboard. The static page exposes no protected server data, so do not invent a no-op dashboard API merely to claim server authorization. Client checks are presentation-only, and every linked operation's API remains server-authorized.

Use only TASK-00049's safe principal projection for current-user presentation. Do not parse JWT, query an alternate authority store, infer from role names, or persist/broadcast roles and permissions. On principal invalidation, remove Dashboard/shortcuts immediately and return to frame state until authoritative refetch resolves.

Gate shortcuts independently: Users requires `READ_USERS`; Invite User requires `INVITE_USERS`; Pending Invitation Status/Recovery requires `MANAGE_USER_INVITATIONS`; elevated assignment is not advertised unless later interaction has exact `ASSIGN_SUPER_ADMIN`. `ROLE_SUPER_ADMIN` itself grants nothing. Account/Security navigation remains available to authenticated owners; Active Sessions navigation requires `READ_OWN_SESSIONS` and package owner checks, while revocation controls later require `DELETE_OWN_SESSIONS`. Neither requires an administrative permission.

Every link resolves to TASK-00051's truthful registered destination and later feature route; do not emit dead URLs. Before later operations exist, do not display fake lists/forms/status or enabled controls that imply availability. Copy must clearly say planning, observability, agent sessions, charts, metrics, and workspace switching are not installed rather than showing placeholders that resemble data.

Recreate accepted Dashboard layout with semantic heading/landmarks/cards or links as approved, responsive order/reflow, theme modes, keyboard/focus, target size, contrast, reduced motion, and comprehensible empty/availability text. Permission hiding is not a substitute for server denial and inaccessible shortcuts cannot remain focusable.
