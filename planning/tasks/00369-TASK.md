# Admit work against shared capacity and commitments

## Outcome

Existing execution admission atomically establishes only compatible bounded capacity, Agent commitments and
policy-declared resource ownership. Competing starts/delegations cannot double-book an Agent or shared resource;
uncertainty retains obligations and a preview never reserves capacity.

## Scope

- In scope: Narrow owning execution admission/read/release participants, revisioned limits and gates, shared
  transaction-duration fences, safe availability reasons and atomic integration through existing Start ownership.
- Out of scope: Another Start, TASK claim, commitment ledger or scheduler, Team selection/fairness, provider calls,
  process launch, sandbox provisioning, complete named-role integration and configured-base inclusion inference.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Inspect availability | N/A — read-only | Current Runner gates/limits, owning commitments, scope and declared resources | N/A | Coherent bounded facts or explicit unknown, never a reservation |
| Admit bounded work | Existing Start/phase owner composes non-nested admission participants | Exact grant, actor/Agent, membership, revisions, resources and original command | Existing committed admission/commitment/audit facts | Owning state and required intent commit together or all roll back |
| Release or retain commitments | Existing authorized lifecycle operation with exact expected state and verified disposition | Current owner, obligations, quiescence and remaining limits | Owning confirmed disposition facts | Only proved releasable resources become available; unknown work remains held |
