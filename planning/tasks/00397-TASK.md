# Inspect known execution time

## Outcome

Authorized operators can inspect wall elapsed, known active work, queue, interruption and human wait separately
from actual execution boundaries. Incomplete timing stays explicit instead of becoming a precise continuous run.
This early timing supplier enables TASK-00387 without provider accounting, completed browser delivery or forecasts.

## Scope

- In scope: Actual semantic/process boundary integration, attributable interval/category policy, bounded protected
  API/console inspection and rebuildable time projections, supported corrections and honest uncertainty.
- Out of scope: New execution clock/lease/claim engine, telemetry-driven recovery, provider cost accounting,
  forecast computation, arbitrary human-wait prediction and browser components.

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Admit known boundary or correction | Existing authenticated source operation and owned timing admission where needed | Exact Workflow/phase/process, source identity/time and supported boundary semantics | Committed timing facts, not new execution decisions | Durable attributable intervals or explicit incompleteness |
| Inspect known durations | N/A — read-only | Current-authorized bounded categories, intervals, gaps and as-of time | N/A | Safe measured/partial/unavailable values, never invented active time |
| Rebuild timing views | Existing bounded projector operation | Original boundary/correction identities and current restrictions | Committed derived-view updates | Idempotent timing without replaying execution |
