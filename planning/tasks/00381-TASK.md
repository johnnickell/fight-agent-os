# Admit exact web content through Jev

## Outcome

Protected research consumers can admit only the exact web representation evaluated under a qualified injection
policy, withholding uncertain or unsupported content rather than releasing unscreened material to the working Agent.
This is the shared web-consumer gate, not another Jev client or general authorization engine.

## Scope

- In scope: Versioned web-injection question/rubric, conservative typed admission policy, exact representation and
  provenance binding, bounded protected receipts, safe refusal/cancellation and actual evaluator qualification.
- Out of scope: Search/fetch, general tool-result screening, source retention/cache, file-relevance policy, new
  evaluator/provider/credential service, automatic policy tuning and permission or Workflow transitions.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Screen exact web representation | Existing bounded typed Jev evaluation under real caller context | Current disclosure/limits and typed result | Redacted evaluation/admission observations | Separately authorized evaluator request and available usage |
| Decide release | PHP-owned consumer admission for exact identity/coverage | Current policy, evaluator, source digest and invocation generation | Actual admitted/withheld fact, not permission | Only an exact qualified representation becomes eligible for caller-authorized delivery |
| Inspect or cancel original evaluation | Existing cancellation; status read never invokes Jev | Safe original identity, outcome, coverage and uncertain usage | Owning cancellation/outcome facts | No silent retry, alternate evaluator or raw-body diagnostic |

## Validation and permissions

Consume TASK-00171's actual protected typed-judgment entrypoint and its shared TASK-00159 evaluator/access/budget
contracts, with TASK-00245/00244 authentication and current-use authority transitively. Local TASK-00184 Pi readiness
alone does not qualify managed service access. Keep the original human/Agent, assignment, Repository/environment and
actual Workflow where present; never invent a Workflow or privileged Jev identity for manual use. Internal evidence
resolution must not recursively screen its own evaluator input or acquire a second ambient service authority.

Authorize disclosure to Jev independently of search/retrieval and local source access. Use a protected versioned
question asking whether the exact untrusted web content contains a likely prompt-injection attempt. Source text is
data for the evaluator, never instructions, tool authority or permission to change evaluator/settings. PHP owns
admission. Define and qualify conservative thresholds and required measures before activation; do not reuse the
file-relevance 0.70 threshold or equate Yes probability with classification confidence or measured accuracy.

Bind the judgment to exact released bytes/representation, origin, source time/digest, transformation/coverage,
rubric/policy/evaluator versions and current caller/disclosure context. Include all source-controlled titles,
snippets, text and extracted labels delivered by the consumer. Changed content, representation or policy requires
new authorized evaluation; a verdict on an earlier body cannot bless later extraction or a different source.
A valid sufficiently negative result may admit only its evaluated representation. Likely injection, uncertainty,
partial/refused/invalid results, timeout, unavailable service or exhausted budget withhold content without echoing it.
No rephrasing, alternate provider or repeated evaluation to obtain a preferred answer.

Apply shared strict input/output/time/concurrency/spend limits and tighter consumer bounds. Oversized inputs remain
unsupported/incomplete; never silently truncate and certify an entire page. Any supported chunk policy must cover
every released segment and qualify context-spanning attacks within aggregate bounds. Passing is not a guarantee of
safety and does not weaken SSRF, disclosure, filesystem, tool or Workflow restrictions.

Reuse original request/evaluation identities, reservations and usage facts. Required durable state/audit/intent
participates in the owning canonical transaction; provider calls occur outside it. Stop/context/policy generation
changes fence late delivery, while uncertain charges remain liabilities. Keep safe bounded receipts for source/query/
redirect correlation, coverage, decision/failure and available usage; no hostile body, private query, secret or raw
provider exception in ordinary logs. Inspection neither reevaluates nor implies current admission.

## Acceptance criteria

- [ ] Actual shared protected Jev delivery evaluates the versioned web question and PHP admits only exact qualified

- [ ] Typed negative, likely injection and every uncertainty/failure outcome remain distinct; limits, cancellation

- [ ] Benign references, quoted attacks and adversarial evaluator-directed input qualify the selected rubric,

- [ ] Compact attribution/usage receipts expose no raw hostile/private content and never grant tool authority.
