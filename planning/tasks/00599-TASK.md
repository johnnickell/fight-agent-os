# Publish the first shared frontend package and scoped skeleton handoff

## Outcome

Applications can install one identified shared frontend release with usable branding, table and backend
integration guidance. The human-account handoff is complete without waiting for EPIC-00018's all-capability
reference bundle or the four later skeleton adoptions.

## Scope

- Resolve working name `@fight/react`, registry/visibility, publisher ownership/access and versioning using the
  actual candidate. Prepare package metadata, changelog and exact distributable before external publication.
  Keep library semantic versioning independent of application and Composer release numbers.
- Deliver focused integration guidance and a scoped human-account capability matrix from TASK-00598's actual
  package/consumer evidence, including safe setup, API/session/admission contracts, brand/extension exports,
  table callbacks/URL protocol, tested versions and exclusions. Reuse actual OpenAPI ownership without publishing
  private specs, credentials or inaccessible scratch references as the handoff.
- After exact-candidate publication authority, publish through the verified channel, retrieve the version,
  compare package contents/identity and install the published artifact in Agent OS and Symfony. If bytes or
  meaningful metadata change after qualification, assess/recheck affected claims before publication.
- Record a practical upgrade/changelog/breaking-change procedure and declared supported backend/API versions.
  Consumers choose upgrades deliberately; no automatic update or fleet-wide release gate.
- Exclude account creation/spending/access grants without authority, starter tags, production, recipient outreach,
  later Agent secrets and the full TASK-00305/00307/00308 handoff.

## Validation and permissions

Public/package visibility is selected explicitly, not inferred from Agent OS source visibility. Never log
publisher credentials or overwrite an existing release identity. Prepare privately inspectable artifacts and
request any still-needed publication authority only after the candidate is concrete. A failed upload may have
published remotely; inspect first. Keep server-authority and nonproduction limitations explicit in the guide.

- [ ] Later Agent/HMAC, email-change, production mail and unqualified skeletons are not claimed complete.
