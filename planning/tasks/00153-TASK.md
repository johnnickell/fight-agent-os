# Export the attribute-owned OpenAPI contract as deterministic JSON

## Outcome

An explicit Docker-backed CLI exports a validated OpenAPI JSON artifact from PHP attributes describing actual
operations and shared transport schemas. The existing representative YAML contract transitions without losing
its behavioral evidence or creating two independently authored specifications. Export does not expose Swagger
or its document over HTTP; TASK-00154 owns local-only permission-gated serving and the themed viewer.

## Scope

- In scope: Qualify/pin an attribute-aware OpenAPI generator against locked PHP/tools; authoritative attribute
  locations and common schemas; explicit repository export command; stable private JSON artifact; migrate the
  current CSRF/failure/security contract and response-to-schema checks; direct deterministic generation and
  artifact checks; truthful future endpoint documentation conventions and API documentation updates.
- Out of scope: Product handlers/client generation, exporting unimplemented routes as available, HTTP document
  publication, Swagger UI/themes, environment/debug implementation, authentication changes, token issuance,
  public static spec assets, new domain behavior, unrelated dependency upgrades and tests of tools/artifacts.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Export current API contract | Explicit repository CLI, analogous to `swagger:export`; no domain command | Read approved PHP operation/schema attributes | N/A — generation is tooling | Complete deterministic validated JSON written outside public assets |
| Inspect schema consistency | Existing owning validator and application contract checks | Inspect document and real HTTP responses | None | Drift/invalid source fails visibly; no source rewrite or implicit dependency install |
| Add a real endpoint later | Owning feature's existing implementation workflow | Read actual route/input/response/security contract | Owning use case only | Attributes and export reflect that implementation, not speculative operations |
| Recover failed export | Explicit correction and rerun | Inspect safe generation diagnostics | None | No partial replacement; failed generation never passes as a fresh release artifact |

## Validation and permissions

Reuse the current [API contract](../../docs/api/README.md) and TASK-00021's actual response/failure semantics.
Qualify a supported attribute generator and the existing OpenAPI 3.0.3 validator/response-checker integration;
record exact manifest/lock changes and licenses. Do not silently move to OpenAPI 3.1, force incompatible packages
or duplicate Fight package contracts. Stop for a dependency/format decision if the supported path is unavailable.

PHP attributes become the single authored source for implemented operations and shared schemas. Record the
transition explicitly in API docs: replace handwritten YAML authority with generated projections and update
all existing consumers together. Preserve historical TASK-00021 evidence, document version meaning and its
unimplemented-future security annotations without relabeling them delivered. A retained YAML output may only
be generated from the same source, not maintained independently. This spec migration is not a Planning database
cutover and never removes or archives Markdown planning records.

Scan bounded owned API/schema locations using installed code, not arbitrary filesystem paths or runtime user
input. Produce stable ordering and relative/local references without clocks, machine paths, private environment
values, live credentials, actual personal data or provider secrets. Do not infer endpoints from standalone
response schemas. Describe exact JSend/snake_case, status/header, sensitive-input and current auth/CSRF semantics;
public validation metadata and protected Swagger metadata have different security contracts.

Write generated output to an ignored non-public artifact directory. Validate a complete temporary result before
atomic replacement; a failed export must not leave a partial document or be reported as current. Old retained
artifacts carry provenance and cannot substitute for a failed current build. Record source/content identity
and explicit generation/packaging requirements. No default `public/openapi.json`, static alias, symlink or
web-server bypass is permitted. No request-time reflection/generation, CDN validator or external `$ref` fetch.

Generation is explicit maintenance through repository Docker wrappers. Acceptance checks neither install/update
packages nor rewrite authoritative source; caches/reports belong under ignored paths. Canonical gate integration
must coordinate with TASK-00033 rather than creating an independent competing acceptance gate.

## Verification and evidence

references, security schemes and secret-free synthetic examples, and compare hashes. Exercise exporter paths
through the owning tool; do not add product tests of command wiring, PHP attribute text, generated JSON/YAML or
deliberately seeded tool failures. Preserve a clear source-to-artifact receipt outside tracked files.

Retain meaningful application response-to-schema checks against actual CSRF success/rejection/failure and
existing mapper boundaries. New operations added by other TASKs supply their own real behavior contract evidence.
Directly inspect every old spec consumer after migration, and verify exporter execution has no tracked-source
or live-publication effects. No fake product endpoint is allowed solely to validate generation.

Use repository Docker wrappers for dependency qualification/export, `./bin/openapi` or its deliberately updated
owning validation workflow, focused HTTP/mapper checks, `./bin/planning-check --write`, `./bin/planning-check`,
`git diff --check` and `./bin/build`. Independent QA challenges explicit generation, repeatability, safe output
and absence of unintended HTTP/static exposure; screenshots are N/A for this non-visual slice.
