# Restore Build child confirmations and reduce routine command prompts

## Outcome

Unblock authorized Build stages whose independently screened command needs an operator decision.
A child running in JSON mode must deliver its exact command to the interactive coordinator's native
confirmation dialog, instead of immediately refusing because the child has no UI. Complete ordinary judgments
with confidence >=0.70 proceed within existing authority, reducing routine prompts under the operator-selected
balanced policy. Risky, uncertain and unavailable results still need a one-command decision.

## Scope

- Temporary local confirmation transport for enrolled Build launches and enrolled stage children.
- Exact command, directory, task, role and session presentation; separate one-command decisions.
- Cancellation, stale authority, unavailable UI/transport, context mismatch and denied-decision behavior.
- Balanced command-risk threshold: complete ordinary confidence >=0.70; no change to secret-disclosure holds.
- Native Pi parent/child regression and harness-owned transport checks; workflow/recovery guidance.
- Excludes screening bypasses, automatic approvals, new task/effect authority, global settings,
  CMS implementation or continuation, deployment, publication and general harness redesign.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Confirm a held stage command | Existing Build stage monitor and native bash | Existing screening and workflow status | Existing held/approved observations | One operator decision reaches that child command |
| Decline, cancel or lose authority | Native dialog decline or session cancellation | Current parent/child boundary checks | Existing command-held result | Command remains unexecuted; transient transport closes |
