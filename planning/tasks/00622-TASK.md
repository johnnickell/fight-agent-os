# Move local runtime and resource lifecycle to PHP

## Outcome

Keep `./bin/runtime`, environment setup, and owned resource lifecycle working without Python on the migrated path.

## Scope

Port the live runtime, environment, and shared lifecycle behavior to PHP. Keep host wrappers thin and qualify a bootstrap that requires neither host PHP nor a running application container. Preserve [resource ownership and teardown rules](../../docs/engineering/RESOURCE_LIFECYCLE.md): per-worktree Compose identity, guarded resource cleanup, and Docker teardown before source removal. Retain Python modules only while live callers still import them; expose the shared PHP behavior needed by the ingress and QA ports without adding permanent compatibility layers.

## Acceptance criteria

- [ ] Existing runtime and environment commands work from explicit setup through teardown in a disposable registered worktree.
- [ ] Foreign, shared, or protected resources are refused or held according to the existing contract. Owned cleanup preserves the required order and does not affect main data.
- [ ] Bootstrap works without host PHP or an active application container; migrated entry points do not require Python. Remaining consumers are identified.

## Verification and evidence

Record exact commands, runtime identities, positive and refused outcomes, and cleanup evidence using the owning tools. Do not target unrelated or durable resources. Hand off to independent Review and applicable QA.
