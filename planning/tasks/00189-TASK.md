# Inspect retained lessons under historical authority

## Outcome

A Project Manager with current Repository authority, a separately permitted human or an audit Agent with an
explicit target-scoped audit TASK can inspect attributed completed Workflow/TASK learning for estimation and
authorized improvement. Ordinary Engineer and Team Lead execution reads still close with their Workflow/TASK;
retention is not a silent feed or an extension of another role's session. This TASK owns the server-side
historical read path; TICKET-00050 owns the basic human UI and safety removal.

## Scope

- Expose bounded exact and historical reads of the retained shared Workflow/TASK entries and linked
  corrections/retractions from [TASK-00188](00188-TASK.md), with stable provenance and clear ordinary-versus-
  historical presentation. Preserve entries across completion, failure, reassignment and time; completion
  changes association/access, not storage. Inspect only shared content; do not grant a Project Manager,
  normal human or audit Agent another Agent's private notes without TASK-00186's distinct private Permission
  and target checks.
- Authorize a Project Manager against its **current** Repository scope and effective direct Permission, not
  title or template. Apply an independently permissioned principal/target boundary to human historical reads.
  For an audit Agent, require both current direct Permission for shared history and a real assigned audit TASK
  binding purpose and Repository/Workflow/TASK targets; the permission alone does not grant retrospective
  access. Revocation, reassignment and expiry deny subsequent reads despite previously obtained entry IDs.
- Supply separately authorized historical guidance for estimation, improvement, metrics or handoff-template
  learning without making it an unrestricted batch export, automatic training feed or publication channel.
  Ordinary current guidance still excludes retracted claims; historical inspection identifies the retracted
  original and attribution without mistaking it for approved guidance. Never automatically rewrite source
  code, published Planning, Workflow handoffs or derived entries because of a historical memory note.
- Provide an Application-owned safe read boundary, plus the minimal first-party delivery required for
  authorized principals; detailed human browser presentation belongs to TICKET-00050. Any access audit or
  receipt is safe and bounded, with no private/shared payload copied into log output. Keep retention and
  authority policy out of Adapter transport code under ADR 0001; guarded PostgreSQL is authoritative under
  ADR 0002.
- Out of scope: routine archiving/removal, unsafe-content safety deletion (TICKET-00050), promotion
  (TICKET-00048), Jev questions (TICKET-00049), private memory inspection (TASK-00186), extending the
  terminal Workflow phases, or implementing an arbitrary new Project Manager/audit provisioning system.

## Acceptance criteria

- [ ] Shared Phase/Workflow/TASK lessons and linked corrections/retractions survive Workflow/TASK completion;
  permitted historical inspection identifies author, sources, scope, order and retracted status without
  presenting a retracted claim as current guidance.
- [ ] A real Project Manager with current Repository authority accesses a completed Workflow within that
  Repository for estimation and is denied another Repository; a genuinely authorized human historical path
  obeys its own effective Permission and target access.
- [ ] A separately granted audit Agent reads only historical shared entries within a real assigned audit
  TASK's purpose/target boundary; direct Permission alone or a forged/expired audit assignment is denied.
- [ ] Engineer and Team Lead ordinary reads stay denied after their respective Workflow/TASK closes, even
  given known entry IDs; revocation and reassignment cut off later historical reads without deleting history.
- [ ] No private note, unqualified feed, raw text in audit/logs, implicit promotion or automatic expiry is
  introduced. No live disclosure is claimed safe without TICKET-00050's removal capability.
