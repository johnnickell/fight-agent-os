# Intervene through existing Workflow and Runner controls

## Outcome

Authorized humans can deliberately pause/cancel/resume/take over a Workflow and drain/halt/recover its Runner through
existing semantic operations, with truthful current consequences, limits and original-command outcomes.

## Scope

- In scope: Protected browser controls and needed single-use-case HTTP delivery for existing operations, current
  preconditions/consequences, original-result reconciliation and accessible pending/held/denied outcomes.
- Out of scope: New Workflow/Runner engine, generic status setter, Start/Pending duplication, automatic command replay,
  arbitrary shell control, new limit-extension/cleanup UI, Review/QA execution, publication and merge.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Pause/cancel/resume/take over | Existing intent-specific Workflow operation with original identity and expected state | Current grant/claim/attempt, consequences and remaining limits | Existing owning committed outcomes only | Existing bounded effect or concrete refusal/hold |
| Drain/halt Runner scope | Existing Runner/installation operation | Current scope, gates, affected work and authority | Existing gate/pause-intent facts | Drain or safe-pause requests, never assumed quiescence |
| Recover or inspect uncertainty | Existing explicitly authorized recovery; inspection remains read-only | Original result, actual ownership/liveness/evidence and safe next action | Existing confirmed recovery/hold facts | Original work resumes safely or remains held, never blind replay |

## Validation and permissions

Consume TASK-00391 presentation/authority and TASK-00373's real Runner/recovery integration, TASK-00372 controls
transitively and TASK-00142's actual terminal interruption/isolation qualification. Use existing Commands/queries
and exact owner policy; an HTTP Action maps one validated interaction rather than becoming a second orchestrator.
Capability absence or incomplete required evidence disables the affected action truthfully, not a fake success path.

Distinguish Repository/Workflow viewing from intent-specific intervention and Runner/installation authority. A
repository-visible summary cannot grant control of unrelated work or reveal installation-wide private details.
Revalidate expected Workflow, claim/lease/attempt, grant/limit, source/context and gate state at the owning server
operation; stale views, Role labels or live messages never authorize effects. Do not weaken owner-held prerequisites
merely because a button can render.

Explain precise target/scope, consequence, retained resources and current remaining limits before deliberate action.
Pause retains claim/resources; cancel remains pending until every child stops or is proved absent. Drain closes new
admission while current work continues; Halt requests safe pauses and is not immediate stop evidence. Runner versus
installation scope remain distinct. Reopening admission is not resuming paused work; takeover preserves Workflow,
attempt and budget history. Terminal work cannot reopen through a generic control.

Preserve exact command identity/payload and expected revisions across duplicate delivery or lost responses. Inspect
the original outcome before offering another effect; do not mint an ID to bypass an unresolved command. No automatic
mutation replay after 401, refresh, reconnect, tab wake or client timeout. Durable operation results survive caller
loss under current access; browser drafts/confirmations remain volatile. Unknown process/effect state retains the
hold and claim rather than implying cancellation, success or permission to clean up.

Reuse ADR 0003/0004 request/context fences for loaders, rendering and handlers. Clear protected state/controls on
invalidation and suppress late errors/successes without preserving sensitive payloads in storage, URLs or logs.
Closing dialogs, navigating away, archiving, disconnecting or refreshing never sends a lifecycle command. Supported
recovery must reconcile actual process/storage/Git/effect evidence through the owner, not telemetry completeness.

## Acceptance criteria

- [ ] Actual browser commands reach the same owning operations as console with current intent-specific authority,
  expected state and bounded target; no client state or visibility action advances execution.
- [ ] Pause/cancel/resume/takeover and drain/Halt/recovery show distinct pending/confirmed/refused/held consequences;
  no claim release before actual quiescence and no budget reset or terminal reopening.
- [ ] Lost responses, duplicate clicks, stale commands, authority changes and reload/reconnect reconcile originals
  without blind replay, hidden effects or false success.
- [ ] Real keyboard/focus/announcements and narrow/wide light/dark states safely expose consequences and unavailable
  controls; actual browser probes qualify the integration rather than reusing terminal receipts as fresh UI evidence.
