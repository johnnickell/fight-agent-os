# Capture immutable Git evidence subjects

## Outcome

An authorized producer retains an exact immutable implementation subject with complete discoverable changes and
source provenance, rather than relying on a branch name, mutable worktree or future PR to identify submitted work.

## Scope

- In scope: Owned source capture, full base/head and status/change manifests, retained patch/equivalent snapshot,
  selected ignored Artifact references, contribution binding, original-operation recovery and safe metadata inspection.
- Out of scope: Running checks, editing/committing source, arbitrary filesystem browsing, Review/acceptance,
  prerequisite merge-inclusion policy, publication, browser rendering and another Git workspace owner.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Capture exact subject | Authorized expected-state evidence capture | Workflow/TASK revision, owned checkout, exact source and contribution references | Committed subject receipt after verified capture | Immutable manifests and private verified snapshot Artifact |
| Resolve capture uncertainty | Reconcile original operation | Actual snapshot digest, source identity and prior outcome | Verified original-result or explicit hold fact | Same subject, never silent rebinding to latest branch |
| Inspect captured identity | N/A — bounded metadata read | Exact commits/manifests, completeness and availability | N/A | Safe retained identity distinct from mutable live observations |

## Validation and permissions

Consume TASK-00140's actual checkout/worktree custody, TASK-00374's verified Artifact/reference participants and
TASK-00375's attributable source facts. Require current scoped producer authority and complete expected state.
Bind Workflow, approved TASK revision, Repository/Checkout/Worktree, acting role/Agent/session where applicable,
immutable context/Harness snapshots, configured base, full base/head commit IDs and complete status/changed-tree
manifests. Branch/path labels remain observations, not identity. No Workflow or role identity is fabricated.

Capture a digest-verified patch or equivalent immutable snapshot sufficient for independent evidence and retain
all changed-file metadata, including adds/deletes/renames/mode changes and explicit binary/oversized/unavailable
states. Include selected ignored evidence by exact Artifact/digest, not arbitrary ignored directory traversal.
Bound work and paginate manifests without silently truncating the subject. Unsupported/incomplete capture is not
certified complete. Do not execute hooks, filters, external diff tools, submodule commands or untrusted content as
an implicit read; qualify the supported Git capture route through its owning tools.

Distinguish immutable base/head tree comparison from live staged/unstaged/untracked observations and pin their
capture provenance. Detect source changes during capture and refuse mismatched status/tree combinations instead of
claiming a nonexistent coherent snapshot. Preserve human-owned files and scope; canonical ownership/containment
checks reject path traversal, symlink escape, moved checkouts and ambiguous Repository identity.

External Git/storage work follows durable intent outside the business transaction. Commit verified subject,
reference/hold participants, provenance and required audit under current authority/expected generations on the
canonical connection. Lost acknowledgements reconcile originals. A moved branch or replacement Artifact never
rewrites retained evidence; source/material changes require another linked subject. Detected prohibited content is
not retained/exposed to preserve a snapshot; mark restricted/incomplete evidence and use owning redaction controls.

## Acceptance criteria

- [ ] Actual owned Git capture retains exact commits, complete manifests, provenance and verified snapshot bytes;
  changed branches and later worktree changes cannot alter the recorded subject.
- [ ] Concurrent source mutation, partial/missing objects, stale authority, mismatched digests and unsafe paths
  reject or report incomplete state rather than fabricate an accepted immutable subject.
- [ ] All changed files remain discoverable with bounded metadata and honest special-file/availability states.
- [ ] Interrupted capture/reference commit resolves the original operation without duplicate evidence, implicit
  source edits, unsafe external commands or another handoff transition.
