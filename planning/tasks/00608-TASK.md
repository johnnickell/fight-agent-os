# Remove repeated Pi subagent launch and resume bookkeeping

## Outcome

Keep usage, activity, compaction, transcript cleanup, and tool diagnostics from drifting across execution paths in the single engine maintained for the [accepted local Pi integration](../tickets/00130-TICKET.md).

## Scope

- In `harness/pi/vendor/pi-subagents/src/agent-manager.ts`, share the repeated run callbacks and best-effort transcript cleanup. Keep the existing call sites and settlement order.
- In `agent-runner.ts` of the same package, calculate unknown built-in tool names once. Keep separate extension-name views where warnings and zero-tool refusal have different rules.
- Assess moving the extension-tool scoping helpers only after the cleanup. Extract them only if loader and admission ordering stays easy to follow without a reverse dependency. Otherwise record why they stayed. No scheduling rewrite or tool-policy changes.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Start or resume an agent | Existing foreground and background launch and resume paths | Current agent record and tool diagnostics | Existing activity, usage, compaction, and completion callbacks | Update the same record and finalize transcripts as before; preserve tool warnings and refusal |

## Validation and permissions

Preserve callback order: update the record, call the manager observer, then call the per-run observer. Keep transcript cleanup timing, slot accounting, worktree lifecycle, extension loading, and tool admission unchanged. No permission or installation changes.

## Acceptance criteria

- [ ] Start and resume use common bookkeeping without losing or counting events twice.
- [ ] Cleanup remains best effort and occurs at the same points, including failure paths.
- [ ] Warning and refusal behavior, including late registrations, is unchanged. Record the decision on the optional split.

## Verification and evidence

Run focused manager, runner, usage-reporting, background-resume, output-file, and foreground-detach tests. Preserve checks for late registration, direct tool calls, and zero-tool refusal. Run the engine typecheck and `./bin/build`, then hand off for independent Review and applicable QA.

## Coordination

Approved as one standalone chore with no prerequisite TASK. Keep the existing execution paths; do not combine their lifecycle rules to remove repetition.
