# Reconcile controlled restoration without resurrecting authority

## Outcome

Implement and qualify the actual stop/reconcile/resume path for controlled current-contract Agent storage
restoration. Independent history and the live sink are reconciled before attesting a newer incarnation generation;
missing, uncertain or conflicting evidence remains unavailable rather than resurrecting authority or secrets.

## Scope

- In scope: TASK-00227's selected independent history and physical restoration tools; close/invalidate admission
  before replacement, offline restore, exact reconciliation, monotonic generation/witness publication, bounded
  restart/recovery and abort/hold behavior; real delivery/cleanup and activation/use integration evidence.
- Out of scope: Legacy conversion, arbitrary out-of-band rollback detection, witness restored with the database,
  reconstructed/fabricated operation facts, automatic reissuance, credential export, a separate test product,
  general backup platform or automatic live deployment.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Stop before replacement | Protected operator admission closure, quiesce and offline restore | Exact target incarnation, independent checkpoint/history and admitted calls | Secret-free operational evidence, not an issuance event | All relevant writes and activation/use held before storage replacement |
| Reconcile retained authority | Protected reconciliation using authoritative retained current-contract facts | Original requests/issuance/audit, Agent state, sink receipts/tombstones/order, keys/epochs and actual restored dataset | Attributable reconciliation outcome only after verified state | Lossless forward repair or safe hold; no invented identity, secret or reset order |
| Attest and resume narrowly | Protected newer-generation/witness publication followed by qualified existing recovery | Independent exact-incarnation attestation and current actor/scope/credential authority | Existing package facts only for actual subsequent operations | Fresh original-key recovery; stale acknowledgement and revoked activation/use remain denied |

## Validation and permissions

Use TASK-00232's unavoidable admission closure before replacing storage, including direct/stale binaries and
activation/use paths. Keep trusted generation/incarnation identity and complete operation/audit history, scoped
keys, exact receipts, permanent tombstones, slot high-water and authority/key evidence outside the restore target.
A backup file, empty local table or absent event is not proof that external effects never occurred. Prefer forward
repair; restore only the supported current contract under quiescence, with no physical access implied by this plan.

Compare independently retained authoritative facts with the actual live dataset and sink, including delayed
admitted effects. Preserve original exact request/issuance/binding and maximum established order; recover original
facts only from authoritative history. Missing/ambiguous facts, unknown participant state, lost keys or mismatched
receipt/tombstone evidence require hold, not new IDs, replacement secrets, authentication-envelope fallback or
reset generations. Reconciliation reads safe metadata and protected encrypted state, never exposes credential bytes.

Publish a strictly newer generation and its exact-incarnation witness under exclusion only after complete
verification. Either partial update or uncertain acknowledgement stays closed until independently confirmed.
Old admissions cannot acknowledge even if a restored revision/epoch matches numerically. Preserve lease and
original retention deadlines. Restart discards readiness caches; current caller/target/delegation, destination,
activation and broker-use checks remain mandatory after reconciliation. No routine manual approval is added to
normal recovery; exceptional restoration retains explicit operational authority.

## Acceptance criteria

- [ ] Real restoration replaces an isolated authorized target with an older current-contract database behind
  actual sink acceptance/cleanup history. Independent evidence survives outside it and admission is closed first.
- [ ] Lossless repair preserves original scoped keys, issuance/audit, terminal state, material absence, exact
  bindings, receipts/tombstones and nondecreasing order. It issues no successor credential or duplicate audit and
  never treats missing local evidence as absence of an external effect.
- [ ] Missing/unavailable/replayed/swapped witness, wrong incarnation, receipt/binding mismatch, lost tombstone
  or high-water evidence, tool failure and uncertain publication cannot partially admit repaired state.
- [ ] Restore/reconciliation contends with real writers and stale/restarted/direct processes. Delayed real delivery
  and cleanup remain inert, stale acknowledgements reject, and fresh authorized recovery uses the original identity.
- [ ] Actual activation and broker use deny superseded/revoked/unreconciled credentials despite successful
  authentication or a restored snapshot. Successful reconciliation is not a grant of continuing use.
- [ ] New generation/witness agreement and real composition qualification support narrow resumption eligibility;
  complete TICKET-00060/00061 security evidence remains necessary before live enablement. Supported controlled
  restore and unsupported arbitrary rollback are distinguished explicitly.
