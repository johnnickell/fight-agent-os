# Bind role selections to isolated immutable Agent sessions

## Outcome

Integrate exact role-profile selection with existing protected Harness session owners so each participating Agent
retains its own identity, bounded authority and immutable profile/context provenance. Current use remains live;
no session can become another role or inherit another Agent's power by changing a prompt or alias.

## Scope

- In scope: Agent profile integration with owned session/snapshot operations, separate Agent/holder/session
  bindings, applicability and current scope checks, role independence facts, stale-state handling and safe
  model/provider provenance; supported actual session integration and denial qualification.
- Out of scope: New launch/Workflow engine, snapshot store, credential broker, Team roster, Agent creation,
  browser Planning conversation, full role outcomes, independent review verdicts, hotfix repair or deployment.

| Bind a permitted role session | Existing owning session/snapshot operation with exact resolved profile | Named Agent bound revision, Team/Repository/context, holder, current authority and qualified host/provider | Existing session/snapshot facts only after their owning commit | Distinct role-bound session with exact immutable profile/resource provenance, not an extra grant |
| Check applicability and independence | N/A — read-only checks consumed by existing admission | Current scope/constraints and owning contribution/assignment history | N/A — no technical verdict | Safe eligible/ineligible/unknown result without redefining Workflow selection or review policy |

| Deny a later unauthorized use | TASK-00244's existing current-use operation, not another authorizer | Fresh Agent/delegation/holder/Team/context/host authority | Existing owning safe denial observations | No new protected effect or credential/tool fallback |

Use TASK-00249's exact approved profile and the actual named Team-bound Agent, not a fixture label, local operator
identity or model-supplied Agent ID. Templates request behavior only. Keep credential holders, identities and
sessions separate; no raw key, provider secret or arbitrary signing capability enters model context, child
environment, transcript, profile or output. TICKET-00063 and TASK-00234–00243 retain creation/enrollment/activation.

Integrate with the existing immutable Harness and Repository snapshots rather than persisting another identity
or session record. Record exact bound template/resource revisions, profile/connection/package identities and
requested/configured/provider-reported model facts where available. Cost/suitability evidence remains measured
or explicitly unavailable. An unsupported profile/host/provider denies; no silent substitution or local-tool fallback.

Current Agent direct Permissions, initiating-human/manual-session or Workflow delegation and Team/Repository/
context/host constraints are enforced through TASK-00244 and the real tool owner. A pinned snapshot is not a
cached allow. Later requests observe revocation; do not promise retroactive cancellation of already-admitted
bounded effects. A profile change cannot rebind an existing Agent or escalate a session. Meaningful governing
profile/context/provider changes use existing explicit linked-continuation policy after fresh authorization;
unknown in-flight state is reconciled before dependent effects, never replaced by a duplicate session.

Consume authoritative contribution/assignment history for independence, including design and build contributions,
not merely distinct names. Missing history cannot establish independent review. Senior Engineer review uses a
fresh separate session, QA follows review without source repair, and publication/emergency effects retain their
