# Store and reconcile verified private Artifacts

## Outcome

Execution and Planning owners can retain immutable, digest-verified private evidence through one application-owned
Artifact capability, with original-operation recovery instead of trusting upload acknowledgements or disposable paths.

## Scope

- In scope: Artifact admission/transfer/verification/status, immutable metadata, early reference/hold transaction
  participants, bounded reconciliation and the necessary installation-owned private SeaweedFS integration.
- Out of scope: Another storage stack, full browser installation, arbitrary file hosting/browsing, transcript store,
  handoff/Review acceptance, full previews/downloads, retention purge or general infrastructure demonstration.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Retain owned evidence | Admit exact bounded Artifact operation; transfer and confirm original result | Current producer authority, declared content and original operation | Committed Artifact intent/verified or unresolved facts | Private bytes outside the business transaction; verified immutable metadata |
| Recover transfer | Reconcile original intent and expected generation | Actual storage digest/size and committed outcome | Confirmed recovery facts only | Same Artifact or explicit hold, never a blind replacement |
| Link or hold content | Owning reference/hold participant on caller transaction | Exact verified Artifact, references and current availability | Actual committed reference/hold facts | Atomic consumer reference and protection without external storage effects |

## Validation and permissions

Consume TASK-00139's existing Workflow/grant/intent boundary and TASK-00234's actual protected worker authority.
Authorize actual producer, Repository, assignment/Workflow and sensitivity scope; enrollment or an Artifact ID alone
is not permission. Keep Planning ownership separate and expose a reusable reference participant without requiring
completed TASK-00087, managed roles or final consumers. Use owning ID factories and closed bounded metadata.

PostgreSQL owns immutable identity, digest, size, media type, safe display name, provenance, sensitivity, links,
holds and lifecycle. Retain original command identity/payload/outcome with state, audit and required intent on the
canonical transaction. Transfer bytes afterward through the private S3-compatible adapter; confirm actual size and
digest, not merely an ETag or upload acknowledgement. Replacements create new Artifacts. Partial transfer, lost
acknowledgement, mismatched bytes or unknown commit remain unresolved until the original operation is reconciled.

Implement genuine shared reference/hold and monotonic lifecycle-fencing participants now, not a query-only promise
or nested transaction. Failed linking cannot certify evidence; orphan reconciliation never deletes existing/shared
or uncertain content. Missing required references preserve bytes. Destructive lifecycle work belongs to TASK-00379.

Extend the existing installation's storage boundary selected by TASK-00072/TICKET-00023: one private pinned SeaweedFS
service, durable owned volume, scoped external credentials, bounded readiness/recovery and operator guidance. No
second Compose project, public bucket, exposed S3 endpoint or import of TASK-00072's complete browser prerequisite
chain. Later installation delivery reuses this same service. Qualify storage directly before live activation.

Bound transfer sizes/concurrency/time and resolve only owned content references, never arbitrary client object keys,
URLs or filesystem paths. Credentials and prohibited content are rejected or made inaccessible under supported
policy from first admission; no raw secrets/hidden reasoning in ordinary metadata, errors or evidence. TASK-00380's
later cross-copy redaction does not excuse unsafe capture or disclosure. Storage credentials never reach Pi children.

## Acceptance criteria

- [ ] Real private storage retains exact bytes across bounded restart; metadata becomes verified only after actual
  digest/size checks and replacement never mutates accepted content beneath its identity.
- [ ] Interrupted transfer, conflicting retry, rollback and lost acknowledgement preserve the original operation
  and truthful unresolved state without contradictory completion or unsafe orphan deletion.
- [ ] Current producer scope and shared reference/hold fences reject unauthorized/stale linking and prevent
  partially committed consumer evidence or missing-reference assumptions.
- [ ] Necessary private storage is integrated into the existing installation, with safe status, bounded operations
  and no public access, arbitrary paths, secret exposure or parallel stack.
