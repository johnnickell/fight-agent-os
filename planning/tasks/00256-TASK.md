# Protect human Agent administration and name updates

## Outcome

Protect human Agent administration with explicit intent-specific current authority and deliver a safe name-only
update through the package command. Neither a Super Admin label nor typed actor provenance is authorization.
The reusable management boundary supports subsequent creation, inspection and lifecycle work.

## Scope

- In scope: Explicit complete managed-policy extension, stable generated Permission identities/references,
  caller/target/scope enforcement across supported entry paths, package `UpdateAgent` composition and protected
  HTTP acknowledgement/errors; qualification of name-only persistence under current writer admission.
- Out of scope: Full directory/detail UI, provisioning or grants to Agents, template administration, ad hoc
  Permission editor, Team transfer, self-profile Tools, duplicate lifecycle/authorization policy or live enablement.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Establish explicit management rights | Existing managed-policy preview/reconcile operations | Complete current policy and referenced definitions | Existing package managed-policy facts after commit | Distinct protected management rights with preserved existing definitions/memberships |
| Rename an authorized Agent | Package `UpdateAgent` with trusted typed User initiator and target | Current actor/target/scope, owning admission and Agent correlation | Package `AgentNameChanged` only for a real committed change | Only normalized name and update time change; no credential, Permission or profile mutation |
| Refuse or reconcile an update | No automatic mutation retry | Current authorized state after uncertainty | Preserve package failure/publication semantics | Safe refusal or fresh observation, not a false rollback or latest-state acknowledgement |

## Validation and permissions

Explicitly extend TASK-00036's historical exact catalog rather than silently rewriting it or supplying a fragment
that removes existing rights. Generate stable identities once with the owning ID factory/library; reconcile the
complete policy with all current code references, including other approved extensions. Separate Agent creation/
lifecycle management from direct-Permission assignment; template and Team management do not imply either. All human
management rights are `SUPER_ADMIN_ONLY`, initially held only through current managed Super Admin membership.
No protected right may reach an Agent or custom Role, and no role-name bypass or new administrator Role is added.

Derive actor identity from trusted current authentication, then check intent, target and applicable scope on every
HTTP, console, worker and direct-bus path that is enabled. An actor ID supplied to a package command records
provenance only. Reuse package authority and TASK-00228–00230's cohort-first shared connection/fences; a preflight
allow cannot outlive a competing authority change. Unsupported/unfenced routes remain disabled. Lower-level Team
binding qualification must not depend on a downstream creation/browser journey to obtain these rights.

Preserve the inspected name contract: `AgentName` trims, rejects empty names and limits the normalized name to
120 characters. Names are not unique and have no expected old-name/name-revision token: last committed name wins.
The repository samples trusted time after writer admission, validates ACTIVE state and exact operation correlation
including normalized no-ops, and changes only name/update time. Rotation/Permission changes cannot be overwritten
by a stale aggregate; revocation rejects even a no-op. No key/sink call or new-work capacity requirement is added.

Use the synchronous void package handler directly, not a forwarding owned wrapper. A successful acknowledgement
contains exactly the target and validated requested normalized name; it is not a fresh latest-name observation.
Any thrown failure, including post-commit publication failure, prevents success acknowledgement. Preserve committed
state and safe uncertainty rather than claiming rollback or reusing issuance's publication-warning semantics.
No automatic replay, synthetic name revision or compensation. Sanitize transport/errors/diagnostic arguments.

## Acceptance criteria

- [ ] The explicit full-policy extension preserves previous definitions and grants only distinct approved human
  management rights, without assigning Agent Permissions or changing Team/template administration implicitly.
- [ ] Actual current authority protects direct and HTTP name updates; role-name, forged actor, revoked/expired
  authority, hidden/wrong-scope target and unfenced paths deny without leaking target detail.
- [ ] PostgreSQL competing rename/rotation/Permission/revocation paths preserve unrelated state and current
  correlation; normalized no-ops, last-committed names and fenced clock sampling match the package contract.
- [ ] Valid acknowledgement describes the successful request only. Rollback, unknown commit and post-commit
  publication failure have safe distinguishable outcomes with no false success or automatic retry.
