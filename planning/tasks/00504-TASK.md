# Support release-scoped independent review and QA handoffs

## Outcome

Remove the TASK-only acceptance obstacle in package releases: a release coordinator can prepare a version-owned
requirements packet, obtain independent technical review and applicable QA, and resume delivery without borrowing
an implementation TASK identity. John authorized selectively porting the useful skill changes from unmerged
commit `b492de63cde83147158a1013c4d43c4a16f70dbb` into a new TASK/feature branch and selected the main checkout.
That historical branch's TASK-00157 record is unrelated to the current scratch-cleanup TASK and is not imported.

## Scope

- Extend release, review and QA instructions, their shared report/routing authorities and role documentation.
- Reuse version-owned `.runs/handoffs/release-<version>/` storage; preserve current discovery, target-context,
  terminal-capture, disposable QA runtime, quality-check and TASK delivery guidance.
- Specify candidate identity, sourced criteria, independent report ownership, freshness and bounded repair/resume.
- Coordinate independent sessions only through a provider-supported release-capable dispatch contract. Preserve
  existing Build accounting and roles; explicitly document the current TASK-only dispatch limitation and standalone
  recovery. Do not port the old ad hoc print-session fallback.
- No runtime/launcher/parser changes, new certifier, package release, external publication, global installation,
  branch deletion or changes to TASK-00157/TASK-00502. No invented release TASK or new product tests for skills.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Prepare/resume release acceptance | `/skill:release <version>` | Target requirements, Git identity, prior reports | N/A: local instructions | Version-owned packet/ledger; authorized preparation only |
| Independently assess release | `/skill:review release <version>`, `/skill:qa release <version>` | Frozen packet, source and evidence | N/A: no Domain event | Separate canonical reports; source/planning unchanged |
| Recover unavailable dispatch or changed candidate | Release resume or explicit independent entrypoint | Current packet/report digests, provider capabilities | N/A | Named prerequisite or fresh affected assessment, not self-acceptance |
| Inspect release status | `/skill:release <version> status` | Current stage and evidence | N/A | Owned status evidence only; no dispatch, repair or report replacement |

## Validation and permissions
