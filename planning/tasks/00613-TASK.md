# Run the existing client checks as a standalone pass

## Outcome

Give humans, agents, and GitHub a way to verify the client without provisioning PostgreSQL or preparing the backend test suite. Keep the checks and build output already required by the existing build.

## Scope

- Provide a thin local Docker-backed command and a runner-native entry point for type checking, lint, formatting, Vitest and coverage, production build, and Storybook checks. Reuse the same check definitions from the existing build.
- Keep the production output available to browser smoke without building it a second time in the same run. Browser smoke runtime and setup belong to [TASK-00614](00614-TASK.md). Shared selection, receipts, and merge requirements belong to [TICKET-00149](../tickets/00149-TICKET.md).

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Verify a client change | Local Docker-backed command or direct GitHub invocation | Client source, locked dependencies, and check results | N/A: verification | Reports, production output, and Storybook evidence |
| Verify the full build | Existing build entry point | Existing inputs and client outputs | Existing build result | Run the client checks once and provide assets to smoke |

## Validation and permissions

Keep preparation explicit, preserve locked tooling, source stability, output and failure handling, and do not install dependencies during routine checks. Do not change merge settings or product permissions.

## Acceptance criteria

- [ ] The independent client checks pass locally through Docker and directly on GitHub without containers, PostgreSQL, or backend test setup.
- [ ] Verification accounts for all existing client checks and shows that the existing build delegates to them once without dropping required checks.
- [ ] The existing browser smoke route can use the production build output without a second build.

## Verification and evidence

Record the check inventory, exact commands and results, and evidence of the build-to-smoke handoff. Run the canonical build and surface warnings or incomplete verification. Use owning commands rather than product tests of build orchestration. Hand off to independent Review and applicable QA.

## Coordination

No prerequisite TASKs. Coordinate the production output handoff with [TASK-00614](00614-TASK.md) and changes to the existing build with [TASK-00611](00611-TASK.md). Planning approval does not select a checkout or authorize implementation or publication.
