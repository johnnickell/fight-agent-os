# Approve an exact Planning migration rehearsal

## Outcome

An independently authorized human can approve one complete clean migration rehearsal through immutable migration-authority state bound to the exact Repository, source, mapping, importer/schema versions, report, target assumptions and current Markdown-authoritative mode; any material change invalidates approval.

## Scope

- In scope: Migration-attempt/rehearsal approval authority model separate from Planning aggregates; `ApprovePlanningMigrationRehearsal`/`PlanningMigrationRehearsalApproved`; approval preview/readiness query; exact Repository/CutoverId/manifest/mapping/report/importer/event/projection/template/queue schema digests; clean-target assumptions and current planning-mode/configuration/context revisions; approver identity/time/reason; short-lived human confirmation and approval expiry/invalidation; idempotency/expected migration revision; PostgreSQL persistence/audit/concurrency; separate report-view/approval Permissions; safe API/OpenAPI/console.
- Out of scope: Importing production streams, changing Planning authority, waiving warnings/mismatches, source repair/edit/freeze, browser UI, agent self-approval, multi-user approval, scheduled cutover, Markdown retirement and treating approval as aggregate evidence.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Preview rehearsal approval | N/A — read-only validation | Explain report completeness, blockers, exact versions/digests/mode and approval scope | N/A — preview emits no event | Human sees one bounded exact approval subject without persistence |
| Approve clean rehearsal | `ApprovePlanningMigrationRehearsal` | Revalidate rehearsal/report/source/mapping/version/mode/current context | `PlanningMigrationRehearsalApproved` in migration authority | Immutable attributable approval binds one exact cutover candidate; no Planning aggregate/mode changes |
| Inspect approval currentness | N/A — read-only interaction | Compare approved subject with current source/configuration/schemas/report/authority | N/A — currentness is derived | Changed facts produce stable expired/stale reasons and block cutover without rewriting approval history |

## Validation and permissions

Approval targets one successful TASK-00100 rehearsal report whose complete-accounting result is clean: no unresolved warning, rejection, ambiguity, mismatch, omitted record or failed stage. Bind exact Repository/CutoverId, source manifest/commit/tree/digest, baseline mapping/identity/payload digest, importer and aggregate-event schemas, projection/template/eligibility versions, normalized rehearsal report digest, expected clean production-target state, current configuration revision, context snapshot/currentness and registered/Markdown-authoritative mode.

Require a fresh short-lived human confirmation bound to authenticated user, approval subject, impact summary, current migration revision and expiry. Agents/processes cannot impersonate the user, approve their own output, grant themselves Permission or satisfy confirmation. One human is sufficient; no multi-person approval. Reason/acknowledgment records that source edits are paused for final revalidation but does not itself enforce a filesystem freeze.

Preview is advisory; command rereads every authoritative fact, confirmation and Permission. Persist approval event/state/audit atomically with expected migration revision and command idempotency. Exact retry returns the accepted approval. A changed command/rehearsal under reused identity or competing approval fails safely. Approval is immutable historical migration evidence; currentness is derived rather than mutating/deleting it.

Any material source commit/tree/file/manifest, mapping identity/payload, importer/event/projection/template/queue schema/version, report result, target cleanliness, Repository/configuration/context/authority mode, Permission or expiry change invalidates use. There is no warning waiver/exception field. A new clean rehearsal and approval are required after material change.

Require separate migration-report view and guarded approval Permissions. Cutover Permission remains separate and is not granted by approval. Safe Views expose references/counts/digests/version summaries and stale reasons but not source/event content, internal IDs unnecessarily, credentials, database details or hidden records.
