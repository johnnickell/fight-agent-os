# Configure and preview project release policy

## Outcome

An authorized Repository manager can version, preview, restore and resolve a qualified project-owned
library-publication or application-deployment policy/runbook reference for a candidate. Missing, stale or
incompatible project facts are explainable and cannot confer release effects. This is one independently
reviewable configuration-to-resolution path, not a generic release executor.

## Scope

- Extend [TASK-00081](00081-TASK.md)'s closed versioned Repository configuration and append-only restore
  operations with a typed release policy: supported library/application type and line, applicable branching
  strategy from [TASK-00203](00203-TASK.md), release procedure/runbook identity and version, required
  registry/host or named deployment environment, expected checks/certification, verification and
  rollback/forward boundaries. Project owners choose explicit relevant fields; a registry, GitHub release,
  Packagist or deployment platform is not universal. Neither a runbook file's prose nor a template grants
  release, signer or production privileges.
- Resolve the current effective policy using [TASK-00082](00082-TASK.md)'s immutable context, approved
  Repository identity, revision/digest and compatible candidate/line/target. Show safe previews of changes,
  rollback, conflicts, supported targets and current effect eligibility without reading secrets into a
  prompt or assuming an early TASK candidate's final commit is certified. Configuration revision preserves
  existing Workflow snapshots; drift blocks new authority-bearing operations rather than retargeting an
  active release.
- Require qualification of the target project's actual runbook/required provider and verification contract
  before enabling release effects. Return typed unsupported, missing, stale, unqualified and contradictory
  reasons for release policy resolution. The absence of a library registry or a supported deployment
  platform is not covered by fallback generic commands. [TASK-00213](00213-TASK.md) consumes this result
  for routing; [TICKET-00056](../tickets/00056-TICKET.md) owns actual certification and grants, and
  TICKET-00057/00058 own project effects.
- Out of scope: live signing, effect grants, release TASK creation, automatic merge-back, provider adapters,
  a generic deployment operation and execution of runbook prose.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Preview and revise release policy | Reuse authorized versioned Repository configuration revision | Compare current type, line, procedure, targets, checks and branch strategy | Existing attributed configuration revision fact on success | Validated immutable future policy revision, not a release effect |
| Restore prior project policy | Reuse append-only configuration restoration after current validation | Inspect selected/current revisions and effect of policy change | Existing restoration fact on success | New attributable policy revision; historical release snapshots remain |
| Resolve support for one candidate | N/A — read-only resolution | Effective project policy/runbook identity, current context/target and qualification | N/A — resolution itself emits no release event | Typed supported or safe unsupported reason, no tag, deployment or claim |

Names denote owning operations and are not a second configuration or Workflow authority.

## Validation and permissions

Require current Repository manager view/revise/restore Permissions, active scoped Repository identity and
expected revisions. Enforce typed project release kind/line, branch base/target, allowed provider/environment,
runbook ownership/version/digest and applicable verification/rollback conditions. Reject arbitrary shell
commands as grant, secret values, unknown adapters, stale/unsupported procedures, incoherent branching policy
and effect targets absent from project authority. A REST preview or model cannot install an unqualified
runbook or widen direct Release Manager Permissions. Revalidate current qualified policy again at later start
and before effects; old Workflows retain history and cannot silently inherit a broader new policy.

## Acceptance criteria

- [ ] A scoped manager can preview and append/restore typed project release policy revisions for a library
  or application without rewriting history or switching Planning authority mode.
- [ ] Resolution binds exact Repository/context/branch/policy/runbook version and candidate type; incompatible,
  absent, stale or unqualified procedure/environment/host/registry blocks effect eligibility with safe reasons.
- [ ] Application policy and actual Permissions cannot be widened by TASK prose, arbitrary runbook content,
  copied credentials or a Jev recommendation. Configuration changes execute no tag/push/deploy/rollback.
- [ ] GitFlow, trunk or custom follow-through requirements remain explicit; library and application
  destinations are distinguished rather than a universal publishing or deployment command.
