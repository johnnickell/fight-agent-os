# Serve authorized static Skill manifests and bytes

## Outcome

Authorized Agents discover exact database-owned static Skills and retrieve manifest-bound bytes through the single
existing protected first-party MCP composition, with fresh authority on each request and no duplicate server.

## Scope

- In scope: Skills capability negotiation/publication, bounded catalog and exact lookup, complete immutable
  manifests, authorized resource reads and safe protocol failure behavior over existing transport/current use.
- Out of scope: New MCP transport or authentication registry, resource authoring, host loading/cache, arbitrary
  third-party origins, dynamic Skills, alternate bearer credentials and protocol libraries in Fight Common.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Discover Skills | N/A — protected read | Negotiated capabilities and authorized bounded catalog/pages | N/A — enumeration is not a Domain mutation | Origin-bound revision/manifest summaries without eager file retrieval |
| Inspect exact publication | N/A — protected read | Exact Skill URI/revision, complete manifest, frontmatter and provenance | N/A | Complete exact entry or safe denied/unknown/unavailable result |
| Retrieve a held resource | N/A — protected read | Exact authorized origin/manifest/revision/file bytes | Safe read observations only | Bounded byte response; no resource selection, execution or grants |

## Validation and permissions

Reuse TASK-00245's actual request-bound authenticated transport/current-use composition and TASK-00333's origin
binding. Preserve its single Common registry/provider for Tools; Skills/resource reads are not implicitly protected
merely because Tools are. Apply the same actual current principal, delegated scope and resource-access checks to
every exposed Skill/resource route and page before disclosure, including alternate direct/CLI/bus paths. No second
nonce lifecycle, anonymous resource bypass, browser JWT fallback for Agent operations or singleton cached principal.

TASK-00327 owns immutable database bytes, type/scope/history and complete static manifests. Map exact publication
identities to that authority, preserving host-assigned origin plus URI and explicit revision. Names, URI schemes
and MCP server display metadata do not confer identity/trust. Missing/retired/ineligible resources for new selection
remain distinguishable from authorized historical reads; never substitute a later current revision or filesystem copy.

Use qualified official SDK/protocol capabilities, pinning exact source/version/lock at implementation. Revalidate
current stable Skills negotiation, method/resource semantics, limits and optional directory support against primary
sources rather than coding to historical WF-013 receipts. Do not advertise unsupported methods/capabilities. Listing
coverage is explicit; partial pages are not proof of absence. Optional directory results cannot enlarge a held
manifest, authorize arbitrary URI reads or enable nested activation.

Return complete exact frontmatter and per-file identity/size/digest for static entries. Bound pages, input, file and
aggregate size, concurrency and time; reject dynamic/incomplete/unverifiable entries, path escape, cross-origin
requests and revision mismatch. Metadata discovery does not fetch all files. Resource content is untrusted data,
not executable policy. `allowed-tools` cannot modify live discovery, Permissions or local tools.

Live credential/Permission/delegation/session/origin changes apply to subsequent requests under the owning admitted-
request semantics; do not promise retroactive recall. Unavailable current authority denies even if bytes are retained.
Private content/results receive safe cache/disclosure controls. Never log signed input, credentials, handles,
unauthorized bodies or arbitrary SDK/provider exceptions. Reads do not append Domain revision/audit-change facts.
