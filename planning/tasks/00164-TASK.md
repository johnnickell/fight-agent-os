# Preserve required context through compaction and validated resume

## Outcome

A participating local Pi 1.1.0 session can preserve required context through compaction and resume only after
checkpoint integrity, current authority and outstanding work are validated. Interrupted creation retains a prior
recoverable state, and missing/conflicting facts cause an explicit pause. This is the first independently useful
slice of [TICKET-00040](../tickets/00040-TICKET.md), without optional Jev selection or automatic context-pressure tiers.

## Scope

- Target Pi **1.1.0**, as confirmed by John. Integrate through the existing TypeScript Harness and qualify actual
  native compaction, session lifecycle and supported parent/child hooks on that exact runtime. The presentation
  package's historical Pi 0.87.1 qualification is not compaction evidence. No implicit runtime upgrade or package install.
- Keep Pi the owner of model context. Use native compaction entries for model-visible continuation plus protected
  session-linked companion storage for additional required checkpoint facts/validation state. Keep this outside
  the repository and normal telemetry; select its protected machine-local root under operator policy.
- Define a versioned checkpoint format with stable fact/reference identities and bind it to exact conversation/Pi
  session branch/lineage, source boundary, role/assignment and applicable context/policy versions. Include objective,
  accepted decisions/constraints, completed and remaining work, pending human questions, uncertain effects,
  source revisions/evidence references and next action. Separate facts, proposals and unknowns.
- Let the Agent draft semantic facts while Harness captures/checks actual identity, approval and operation records,
  required fields, references and declared gaps. Summaries cannot mint approval. Field completeness is not proof
  of semantic recall. Additional supporting context remains behind authorized references rather than bulk reloaded.
- Produce and validate a complete candidate before activation, preserving the prior recoverable state through
  activation. Bind native and companion revisions so partial writes, corrupt contents or a stale branch cannot
  masquerade as a valid checkpoint. Corrections are attributable revisions, not silent replacement of history.
- Support normal native/manual compaction entry points without adding TICKET-00041's thresholds. Qualify native
  summarization of older context and recent retention as the baseline/fallback, retaining required facts. Its
  model use requires existing authorization and cost capacity. An unchecked native summary is not safe fallback.
- Bound checkpoint input/output, duration and context allowance under a versioned operator profile; reserve current
  governing instructions/selected skills and the next action. Remove optional material first and permit additional
  allowance only within known effective limits. Unknown limits or required-context overflow preserve/pause, without
  silent truncation or provider/model change. Pin concrete ceilings and accounting in the implementation receipt
  before profile activation; do not infer sufficient reserve from nominal model capacity.
- Before continuation, validate integrity/binding, current governing instructions/skills, source/evidence subjects,
  permissions and applicable assignment/claim/lease state. Local mode uses only its real available authority;
  unsupported managed checks are explicit, not invented grants. Meaningful instruction/policy drift follows
  WF-009's linked-continuation rule. Missing facts/source reconciliation needing reads pauses pending TASK-00166.
- Preserve actual approvals only while scope, expiry and consumption state remain valid. Reconcile verified tool
  completion, billing uncertainty and concurrent human replies before dependent work. Retain exact pending question
  identities, content, context and unanswered status. Unknown effects never become success or automatic replay.
- Respect cancellation/reload and discard late/obsolete candidates. Separate each Agent/sub-agent's private context
  and authorized parent handoff; independent review uses fresh conversations. Refuse unsupported lifecycle routes
  rather than advertising protected continuation. Qualify a real supported child path without building a launcher.
- Emit bounded sanitized preparation/validation/activation/resume/failure observations with session/attempt/revision,
  policy/runtime identity, digests/protected references and known context/usage facts. No fabricated managed IDs,
  checkpoint prose, credentials or hidden reasoning in ordinary logs. Missing telemetry is not lost durable state.
- Exclude optional Jev ranking (TASK-00165), source repair (TASK-00166), terminal cleanup (TASK-00167), timing tiers,
  aggregate observation UI, memory promotion, browser delivery, managed execution launch and sandbox claims.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Preserve required context | Prepare, validate and activate a checkpoint at a permitted compaction boundary | Current facts, native context, authority and operation state | Candidate/activation succeeded or failed | Protected native/companion state and authorized summarization |
| Resume valid state | Validate and activate continuation | Integrity, lineage, current constraints and outstanding work | Resume validated/resumed/blocked | Continuation only after required checks; no source bulk reload |
| Survive interruption | Reconcile native/companion candidate state | Prior recoverable revision and actual activation result | Recovery or preserved-pause observation | Verified recovery with no duplicate operation |
| Compact while awaiting input | Preserve waiting state through compaction | Exact question and concurrent reply state | Checkpoint/waiting-state observation | Question remains pending or verified reply is reconciled |

These are local session operations, not new Workflow grants. Checkpoint validation is not independent review acceptance.

## Validation and permissions

Consume [TASK-00160](00160-TASK.md)'s operator-controlled deterministic restrictions to protect companion/policy
resources through all declared supported Agent routes. Canonicalize storage/reference paths and reject unsafe
symlink or cross-session access. Same-user processes and malicious trusted extensions are not sandboxed by these
hooks; preserve TASK-00138's distinct isolation boundary. A digest establishes identity, not authorization.
Separate provider disclosure from source read permission, and keep source bodies/credentials out of ordinary receipts.
Keep required facts available to their own authorized model context without disclosing another role's private state.
Unknown authority or unreconciled effects blocks dependent continuation. Before TASK-00166, repair-required cases
pause honestly; they do not bypass screening to reconstruct missing facts.

## Acceptance criteria

- [ ] Actual Pi 1.1.0 compaction and resume preserve all required fields, exact pending questions, next action and
  source/evidence provenance; native and companion records agree on session/branch and activated revision.
- [ ] Interrupted saves/activation, corrupt contents, duplicate hooks and stale responses retain recoverable state
  or an explicit pause, never a fabricated completed checkpoint or repeated effect.
- [ ] Revoked/expired/consumed authority, uncertain billing/effects, concurrent replies and governing instruction
  drift lead to verified reconciliation, required linked continuation or preserved pause as applicable.
- [ ] Native baseline/fallback obeys required-fact validation and profile reserves; overflow, unknown limits and
  unavailable summarization cannot silently drop facts or select another model.
- [ ] Supported parent/child paths maintain private checkpoint ownership and fresh reviewer context. Protected
  paths and all claimed lifecycle routes are qualified, with unsupported guarantees reported explicitly.
- [ ] Sanitized observations carry attributable lifecycle/provenance and honest measured/estimated/unavailable
  usage; missing telemetry cannot authorize or prevent an otherwise valid durable-state check by itself.
- [ ] The usable baseline documents what it can resume directly and what still requires source-repair delivery.
  No timing automation, managed runtime or complete TICKET acceptance is claimed from this slice alone.
