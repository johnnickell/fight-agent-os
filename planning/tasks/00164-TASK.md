# Preserve required context through compaction and validated resume

## Outcome

A local Fight Pi session keeps working through native automatic compaction, manual compaction and resume.
Preserve the task objective, accepted constraints and decisions, completed and pending work, exact unanswered
questions, evidence references and the next safe action. A resumed session must respect current authority and
reconcile uncertain effects before dependent work.

## Scope

- Qualify the installed supported Pi runtime on Fight's normal terminal and Build child paths. Record the tested
  version and capabilities as evidence. Leave native auto-compaction enabled. Check effective model context
  limits, reserves and recent-history retention. TASK-00168 owns the configurable timing tiers.
- Use Pi's session history, native compaction entry and available lifecycle events first. Check what survives
  native compaction and restart, including repeat compaction and interrupted or failed compaction.
- If native state leaves a concrete required recovery gap, keep only the missing facts in protected session-linked
  storage. Bind them to session lineage, role, assignment and source boundary. Validate before use, preserve the
  previous recoverable state through interrupted writes, and apply ownership and retention rules before activation.
  Reuse authoritative workflow state where it exists.
- Recheck governing instructions, permissions and applicable claim, approval and operation state. A summary cannot
  renew or grant authority. Reconcile concurrent answers and uncertain effects without replay. Pause when required
  facts, current authority or safe continuation cannot be established. Keep reviewer and child context private.
- Use existing observation surfaces for available counts, latency, usage and failure reasons. Keep transcript and
  checkpoint contents out of ordinary logs. Jev, custom timing tiers and cache extensions are outside this slice.

## Acceptance criteria

- [x] Native automatic and manual compaction and restart/resume work on the supported Fight entry points without
  Jev credentials or tools. Evidence records the effective settings, tested runtime and observed trigger.
- [x] Representative continuation preserves the required facts and next action across repeated compaction.
  Missing or stale evidence, revoked approval, an unanswered question and an uncertain tool outcome are handled
  explicitly. Dependent work pauses when needed without replaying effects.
- [x] An interrupted or failed compaction leaves a recoverable state. Any companion data is justified by an
  observed gap, bound to the right lineage and recoverable after interrupted writes. Unsupported paths are explicit.
- [x] Record summary duration, time to first response after compaction, before/after context and available cache
  reads/writes separately. Distinguish measured, estimated and unavailable values.

## Verification and evidence

Qualify the owning runtime directly with representative task histories and controlled interruption. Use disposable
sessions and the authorized Fight provider path. Record native retention and fallback behavior before adding
storage or evaluating extensions. Use the [Pi compaction reference](https://pi.dev/docs/latest/compaction)
to identify supported capabilities and verify their behavior on the installed runtime. Validate owned
application behavior where changed and run applicable gates.
