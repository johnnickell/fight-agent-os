# Keep native Pi usable in an owned Herdr workspace

## Outcome

Deliver the [approved Herdr-native workspace](../tickets/00110-TICKET.md#approved-herdr-native-workspace-and-task-decomposition--2026-10-23):
the operator keeps the existing native Pi conversation and Fight harness while an explicit package-owned action
opens adjacent child-activity and log panes. Herdr owns terminal layout; Fight does not replace Pi's frontend.
This is the first of three approved delivery TASKs, normally one independently reviewable PR each.

## Scope

- Provide an explicit action from native Pi inside Herdr that splits the current tab into a primary conversation
  at left and two named observation panes stacked at right. Show honest placeholders until TASK-00511/00512.
- Qualify supported installed Pi and Herdr APIs/CLI behavior, including the existing official Pi integration where
  relevant. Record observed versions as evidence, never a Pi version gate. Do not fork either product.
- Preserve the actual primary process, session/file, checkout, tools, role/workflow binding, native editor,
  completion, Markdown, themes, dialogs and resource discovery. No RPC conversation, replacement editor or
  screen-scraping bridge is introduced.
- Track only panes created by this action, using returned opaque IDs and current caller context. Repeated open
  reuses healthy owned panes; partial failure reports known effects and cleans only proven-owned resources.
- Preserve primary focus on open; let Herdr handle focus, resize and zoom. Provide explicit close/reopen of
  companions without submitting input to, restarting, moving or closing the primary Pi or unrelated panes.
- Keep the current public client available during this staged delivery. TASK-00512 owns final migration/retirement.
- Exclude observation producers, Docker operations, agent execution/delegation, global installation/configuration,
  unrelated Herdr topology and managed Workflow/sandbox implementation.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Open the workspace | Explicit native Pi workspace action; supported Herdr pane split/rename operations | Actual native session, caller pane/tab/workspace, live topology and supported capabilities | Native session lifecycle; no new business event | Two owned companion panes in the current tab; primary focus and cwd unchanged |
| Repeat open or recover partial creation | Same explicit action | Current opaque IDs, ownership and live pane/process identity | Local companion lifecycle only | Reuse healthy owned panes; disclose partial effects without duplicate/replacement agents |
| Close/reopen companions or resize | Explicit companion controls; native Herdr focus/resize/zoom | Owned pane identities and current geometry | Local terminal lifecycle | Companion-only changes; existing Pi conversation continues |

## Validation and permissions

Require a genuine native Pi context and Herdr-managed caller before control operations. Outside Herdr, with an
incompatible/missing server API, or with ambiguous/stale caller/ownership identity, leave normal Pi usable and
report the prerequisite; never launch the RPC client as an automatic fallback. Do not infer targets from whichever
pane a human or another client currently focuses. Do not blindly retry an uncertain mutation: inspect actual state.
Bound requests and cleanup; closing companions cannot kill Pi, delegated children or pre-existing terminals.

Pane orchestration does not grant tool, workflow, role or execution authority. Preserve current Harness rules,
including optional Jev and native shell behavior. Model-invoked layout commands cannot become trusted operator
workflow selection. Persist necessary non-secret local ownership state only under ignored `var/`, never `.runs/`;
validate it against live identities before reuse. Do not install integrations, change global settings or expose
credentials. Setup requiring those effects is an explicit operator prerequisite.

## Acceptance criteria

- [ ] An explicit action opens the requested half/quarter/quarter layout around the same live native Pi session,
  preserves primary focus, and labels both placeholder companions truthfully.
- [ ] `/next` plus Tab retains native completion; typing, editing, submission, Markdown/tool rendering,
  light/dark colors, native dialogs and workflow selection remain native Pi behavior without resume detours.
- [ ] Real wide/narrow use, resize, zoom and focus transitions remain understandable and do not intercept Pi's Tab.
- [ ] Repeated open, a manually closed companion, partial creation failure, stale IDs and unavailable Herdr do not
  duplicate agents, mutate unrelated panes or disable the original conversation.
- [ ] Companion close/error/shutdown restores its terminal and leaves the primary session and observed work intact.
- [ ] Supported API qualification, actual terminal captures, focused checks and the canonical gate are recorded;
  independent Review/QA remain separate from implementation evidence.
