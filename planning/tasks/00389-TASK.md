# Follow committed Workflow updates through Mercure

## Outcome

An authorized client can follow committed Workflow projection changes, reconnect by reloading durable queries and
retire stale contexts safely. Live loss or duplication affects timeliness only, never authority or recoverability.
The delivered capability includes real protected hub operation, not the inherited MockHub fallback.

## Scope

- In scope: Post-commit safe projection publication, current-authorized subscription/reload, bounded typed client
  transport integration, generation/reconnect fencing and narrow protected Mercure installation qualification.
- Out of scope: Dashboard components, second client authority/cache, new Workflow event stream or telemetry service,
  durable transcript transport, automatic Command replay and a second installation topology.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Publish committed projection change | Existing bounded publication operation after commit | Exact committed projection generation and current safe audience | Safe committed projection notification, not Domain authority | Best-effort Mercure delivery outside the database transaction |
| Subscribe under current access | Authorized bounded subscription setup | Current principal, Repository/Workflow scope and supported transport | N/A — subscription grants no execution authority | Scoped protected connection with bounded lifetime |
| Reconnect or refresh state | N/A — durable authorized reads before following updates | TASK-00387 queries and current source/projection identity | Client coordination signals only | Truthful fresh/stale/unavailable state; no execution or replay |
| Retire access/context | Existing authority invalidation and teardown | Current context/restriction generation | Secret-free invalidation where supported | Late responses/notifications cannot restore retired protected data |

## Validation and permissions

Consume TASK-00388's actual copy/restriction participants and TASK-00387's durable queries transitively, plus
TASK-00049's production sole `/me` authority/cache integration. Reuse qualified Fight Common/Symfony publication
capabilities rather than another event protocol. The inherited optional MockHub is not proof of availability:
missing qualified runtime/configuration must report live updates unavailable, never a false successful delivery.

Publish only data whose corresponding projection transaction committed. Do not emit before commit or treat an
in-process callback as guaranteed delivery. Best-effort delivery may be lost/repeated/delayed; durable queries recover
state without a new exactly-once outbox claim. If a bounded retry mechanism is used, retain original projection
identity and current restriction/audience fences, not a raw queued private body that can bypass later redaction.

Authorize current intent-specific reads at subscription and reload and qualify the actual ongoing audience boundary.
A private topic or old subscription credential is not permanent permission. Use narrowly scoped bounded credentials,
no wildcard audience, raw key in URL/log/storage or second persistent browser credential scheme. Minimize payloads
and check current disclosure before publishing; where current audience safety cannot be guaranteed, withhold private
payloads and require a currently authorized durable read. Document real revocation limits without claiming recall
of already delivered bytes. Topic metadata itself must not leak forbidden Repository or Workflow existence.

Integrate the typed transport into the existing volatile API-cache/authentication owners under ADR 0003/0004. Reload
durable current state on reconnect before applying subsequent notifications; qualify the subscribe/reload race with
projection versions or safe invalidation/requery semantics. Older successes and errors cannot overwrite newer state.
Fence context, scope, authority, result and restriction generations; terminate/retire listeners and pending reads on
logout, refresh/invalidation or identity change. No persistent business cache, per-row history polling or automatic
business-request replay. Report interrupted/stale/denied/unavailable transport honestly without clearing durable state
as though work vanished or inferring cancellation/completion from disconnect.

Extend TASK-00072/TICKET-00023's single installation boundary with the narrow private pinned Mercure service and
approved ingress path needed here, protected publisher/subscriber setup, bounded readiness/restart behavior and
operator guidance. Reuse shared services, no parallel Compose project or public administration/secret endpoint.
Do not import TASK-00072's complete browser prerequisite chain; its later topology delivery reuses this qualified
addition. Credentials, certificate trust, service lifecycle and external targets require separate explicit authority.
