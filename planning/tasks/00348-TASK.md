# Record bounded assignments and conversation identities

## Outcome

An authorized human explicitly records a bounded assignment and stable conversation identity for an existing named
Agent. Exact intent/delegation facts support immutable snapshot binding without implicitly launching work, granting
provider disclosure or fabricating a TASK Workflow.

## Scope

- In scope: Protected assignment create/inspect/narrow/revoke operations, original operation identity, conversation
  identity, initiating human/acting Agent/Team/holder/Repository scope, expected generations and shared authority fences.
- Out of scope: Agent creation, credential delivery/activation, session launch, provider work, Workflow claims,
  snapshot duplication, role resolution, proposal acceptance and browser Planning presentation.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Assign bounded manual work | Explicit expected-state assignment intent | Current human assignment authority, named Agent/Team, enrolled holder and exact resolved scope | Committed assignment/conversation-intent facts | Stable identity, bounded delegation facts and required audit; no execution |
| Inspect or reconcile intent | N/A — authorized read | Exact original operation and safe retained scope/status | N/A | Original result or explicit pending/denied outcome without another conversation |
| Narrow/revoke assignment | Current authorized expected-generation operation | Current scope, references and monotonic authority epochs | Committed owning scope/revocation facts | Subsequent admission denied or narrowed; no claim to recall an admitted external effect |

## Validation and permissions

Consume TASK-00339 exact resolution, TASK-00253 Team/Repository fences, TASK-00258 actual named creation and
TASK-00234 real holder enrollment. These suppliers retain their own supported-composition holds. Creation rights,
admin labels, template names or caller-supplied identities do not confer assignment/delegation rights. Require
current intent-specific human authority and bind the actual acting Agent, Team, installation, enrolled holder,
Repository/checkout/context, objective, allowed provider/model, tool/effect scope and finite limits. Existing Agent
Permissions remain independently authoritative. Manual work has no dummy Workflow; actual Workflow grants stay
with their existing execution owner.

Distinguish retained assignment intent/identity from a fully bound, activated, running session. The early transaction
contract supplies stable authorized facts to TASK-00340; it cannot require a completed snapshot binding, broker,
loader or running provider as a reverse prerequisite. Final activation uses that binding and current authority
through TASK-00351. A stored identity or old delegation never becomes a reusable grant. Owner-first visibility
applies from creation; detailed scope is not disclosed merely because an ID exists.

Use owning ID factories, bounded closed inputs and safe status/history queries. Persist owned intent, original
request identity and required audit atomically on the ADR 0002 shared connection. Expose genuine transaction
participants for binding/attempt owners, not nested transactions or post-commit audit workarounds. Complete current
human/Agent/Team/holder/reference writer participation and monotonic generations prevent stale/no-op and revoke/
regrant bypasses. External host inspection remains outside transactions and does not prove later readiness.

Lost acknowledgements reconcile the original request under current read authority. Conflicting retries preserve
one intent; narrowing cannot expand scope or revive consumed/expired authority. Stop new admission on unavailable
required authority. Keep credentials, protected handles, private instructions and arbitrary exceptions outside
ordinary Views/logs/events. No connection, enrollment, launch or paid request occurs as an inspection side effect.

## Acceptance criteria

- [ ] Actual protected assignment operations retain exact authorized human/Agent/scope and one original identity
  without automatic Agent creation, snapshot mutation, launch or provider disclosure.
- [ ] Wrong Team/holder/Repository, management-only rights, stale generations and unavailable authority reject;
  narrowing/revocation fences subsequent admission and cannot revive old authority after regrant.

  delegation references and required audit without duplicate conversations or partially authorized state.
- [ ] Snapshot retention can consume the early identity/transaction contract independently of completed execution;
  final readiness remains visibly separate from stored intent and safe inspection never runs work.
