# Install private starters through protected GitHub access

## Outcome

An authorized administrator installs an accessible private GitHub starter through the Workspace's protected
server-side connection, using the same immutable release/manifest path as public sources without exposing source
credentials to snapshots, generated projects, users or Agents.

## Scope

- In scope: Actual protected private-source inspection/retrieval adapter, Workspace connection and current source
  authority composition, bounded safe failures and original-operation recovery through TASK-00402.
- Out of scope: Credential enrollment/authentication UI, token collection, arbitrary GitHub/network proxy, source
  writes/releases, generated-project publication, managed Release Manager grants and a second snapshot engine.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Install a private source | TASK-00402's original install/refresh operation with exact protected source scope | Current connection/access and source identity under explicit operation | Existing committed installation/conflict facts | Bounded protected GitHub retrieval, same verified snapshot pipeline |
| Reconcile private retrieval | Original-operation reconciliation with current authorization | Exact original provider/storage outcome and current permitted access | Confirmed or unresolved original-result facts | No blind retry, credential substitution or duplicate selection |
| Explain unavailable private input | N/A — ordinary read | Retained safe operation/status and supported connection capability | N/A | Safe denied/unavailable/unknown reason, no live polling or authentication |

## Validation and permissions

Keep `needs-info` until the exact protected Workspace GitHub credential/access supplier and supported enrollment/
current-use contract are identified and mapped. Existing source-host tooling or a configured URL is insufficient;
TASK-00315's Release-Manager-only broker is not authority for private catalog reads, and TICKET-00102's human
project publisher is not credential enrollment. No future supplier ID is invented. Resolve this gap under its
actual owner before readiness, then qualify the real source/connection path inside delivery. Planning authorizes
neither reading credential contents nor enrolling or authenticating a connection.

Require current initiating-human catalog/install authority, correct Workspace/entry/source identity, exact operation
and independent permitted private-source access. Revalidate connection identity and authority at actual use and
before accepting an outcome. Missing, revoked, expired, wrong-scope, inaccessible or uncertain access holds safely;
a remembered successful fetch, old preview, role name or public-source permission cannot authorize it. Retained
private source disclosure follows current rights; possession of a snapshot ID is not access.

Use the protected server-side connection through its qualified narrow contract. Raw tokens, credential handles,
SSH material and provider secrets never enter requests supplied to children, archives, generated files, browser
responses, events, ordinary logs, prompts or Agent environments. Do not ask users/Agents to paste secrets, inspect
home/keychain/config contents, silently authenticate or reuse a different account to bypass a failure. Credential
rotation and revocation retain their owner's lifecycle and do not mutate original operation provenance.

Constrain retrieval to the confirmed GitHub source and qualified endpoints/redirects; do not forward credentials
to arbitrary locations, expose provider-native errors or leak private source existence across scopes. Bound requests,
bytes, time, concurrency and retry/reconciliation. Report organization policy/SAML/scope/connectivity limitations
honestly without widening authority. No source modification, Git push, PR, release or remote creation is permitted.

Reuse TASK-00402's newest-stable SemVer, known-tag immutability, tracked archive, manifest, digest verification,
PostgreSQL intent/outcome and private-storage/reference protocols unchanged. Private sources do not bypass validation
or gain a relaxed fallback. External reads occur only for an explicit authorized installation/reconcile operation
outside its committed business transaction. Ordinary catalog/status/snapshot reads neither contact GitHub nor repair
access. A connection failure cannot transform uncertain installation into success or authorize another identity.

Public installed snapshots and local generation remain independent of this optional private-source route. Private
installed content may be used without a fresh source fetch only when current local disclosure/eligibility policy
permits; do not promise offline authorization checks that the actual qualified connection contract cannot support.
