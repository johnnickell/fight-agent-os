# Cut over browser journeys and forward plans to root URLs

## Outcome

Deliver [TICKET-00138](../tickets/00138-TICKET.md)'s complete root-URL cutover in one independently reviewable
PR. People enter the existing permission-aware Dashboard at `/`, sign in at `/login` when required, and use
all existing browser journeys without `/app`. Routing, credential links/intake, strict configuration, local
tools and current/forward guidance agree at cutover; no broken intermediate route-only change is delivered.

## Scope

In scope:

- Make `/` the canonical Dashboard location, not an additional requirement for a `/dashboard` alias. Preserve
  Dashboard content, exact `VIEW_DASHBOARD` admission, independently permitted shortcuts and unavailable-content
  copy. Anonymous entry goes to `/login`; authenticated lack of Dashboard permission remains Forbidden.
- Move existing public, account, administration and Swagger browser destinations, route lookups, navigation,
  brand/menu links and session return defaults to root URLs. Preserve `/reset-password` and
  `/reset-password/complete`; activation is `/activate`. Remove old `/app` routing aliases without redirects.
- Serve React as the final browser GET fallback with explicit server routes and asset handling taking precedence.
  Direct entry/refresh and meaningful client Not Found work; API/MCP errors, missing assets and unsupported
  server methods must not become successful shell responses. Keep `/api/v1`; reserve `/mcp/v1` without MCP
  implementation or changes to its future separate authentication/admission contract.
- Update credential email generation, exact canonical path/trusted-origin validation, fragment capture and
  early URL clearing, intended-route admission, environment examples, isolated-runtime setup and synthetic-mail
  QA extraction as one change. Inspect retained delivery-material and operator/configuration obligations before
  changing paths; preserve needed identities and invitation/reset recovery state without unauthorized disposal.
- Update current documentation and unfinished forward planning requirements prescribing browser `/app/...` or
  unversioned MCP routes. Amend prospective requirements in their owners while preserving historical decisions,
  completed implementation/acceptance records, receipts and publication evidence. Preserve unrelated requirements,
  dependencies, priority and qualification holds. Reconcile current/future guidance, not historical observations.
- Recheck the live bounded reference inventory and record meaningful remaining-match exceptions. Initial source
  pointers are in [EPIC-00025](../epics/00025-EPIC.md). They include routes/journey/intent, auth credential and
  prepaint handling, frame/pages, PHP security/delivery configuration, runtime preparation and QA setup.

Out of scope: managed-policy JSON/default changes owned by [TICKET-00139](../tickets/00139-TICKET.md),
Dashboard expansion, changed business permissions, invitation transaction redesign, legacy redirects/aliases,
API version changes, MCP implementation, production deployment, speculative routing infrastructure and filesystem
`/app` moves. Container workdirs/mounts, filenames and import aliases are not browser prefixes.

## Validation and permissions

Preserve exact server-enforced operation permissions, principal ownership, current Swagger environment admission
and protected spec access. Route visibility never grants authority; no Role-name bypass, new grant or relaxed
Dashboard permission follows from moving the root. Use the sole existing principal/session graph.

Update safe intended-route grammar without admitting external/arbitrary same-origin destinations, unsafe query
values or credential fragments. Preserve fragment-only credential transport, pre-render URL sanitization, exact
trusted HTTPS origins/canonical paths, CSRF/browser request controls and redacted failures. Renaming routes is
not permission to broaden admission. Keep reserved server namespaces out of the SPA fallback, including misses.

No new business Command, Query, event, Permission or database schema is inherently required by route matching.
Retain supported package operations and shared architecture/dispatch boundaries; do not introduce a second
router/authority graph or change unrelated capability ownership. Needed durable data and credentials remain
protected; explicit no-redirect approval does not authorize data loss.
