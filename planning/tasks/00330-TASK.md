# Manage versioned themes

## Outcome

Authorized users manage and inspect exact database-backed theme revisions for Harness profiles, preserving custom
presentation and historical identity instead of silently replacing it with mutable package or source content.

## Scope

- In scope: Type-specific theme validation, managed reconciliation, scoped custom create/revise, immutable history,
  exact content/provenance/reference inspection and protected application/API delivery.
- Out of scope: New branding/design, generic resource editor, live Pi theme installation, user-profile persistence,
  environment indicators/collision warnings, session switching and resource retirement/rollback commands.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Reconcile reviewed theme | Explicit managed theme reconciliation | Managed key, exact bounded source/digest, type compatibility and scope | Committed theme revision/selection facts; none on unchanged replay | Immutable theme revision and current selection, never personal configuration |
| Create or revise custom theme | Explicit scoped creation/revision with expected state | Valid content/reference choices, alias conflicts and current history | Committed custom theme creation/revision facts | New owned revision and atomic required audit |
| Inspect exact theme | N/A — authorized read | Exact type/content/revision, light/dark facts where represented, provenance and eligibility | N/A | Safe facts for profile validation and presentation consumers |

## Validation and permissions

Consume TASK-00327's shared current authorization, Workspace/registered-Repository scope and reference-generation
contracts while keeping theme content invariants separate from Skills, prompts and personas. Define bounded valid
presentation fields and applicable compatibility using the supported theme format at implementation; inspect with
owning tools rather than treating arbitrary files as valid themes. Theme content is not executable code or policy.
Do not introduce a new light/dark-pair aggregate merely for coverage; expose exact applicable references/facts for
the approved profile consumer.

Logical identity, immutable revision and alias/current selection remain distinct. Generate new IDs through the
owning factory/UUID library. Validate complete supported content, reserved names, reference identity/type/scope,
uniqueness, sizes and expected selection generation. Invalid, ambiguous, cross-scope or unsupported content fails
visibly; no silent fallback to a similarly named package theme or local file. Protect authorized content reads as
well as writes and keep private bodies/configuration out of ordinary diagnostics/events.

Reconcile managed themes by stable key and normalized exact input digest, no-op when unchanged and append/select
when changed. Preserve custom work; absent source is not retirement/deletion. Custom commands cannot overwrite
managed identities. Enforce PostgreSQL alias/reference/selection constraints and shared reference fences; stale
intent cannot succeed after the current pointer moved away and back. State, immutable bytes, current selection and
required audit commit or roll back together through the owning ADR 0002 transaction; events follow commit.
External import/tool effects stay outside it. Unknown original outcomes require inspection before another action.

Retain exact historical bytes and references for authorized readers. Changing future selection never refreshes an
active snapshot or personal Pi settings. TASK-00323 owns user preferences; TASK-00325 owns actual terminal identity,
theme-collision warning/accessibility override and linked switching. Database validation does not claim terminal
legibility or qualified rendering. Resource storage is independent of completed profiles and runtime consumers.

## Acceptance criteria

- [ ] Actual protected managed/custom operations yield type-valid exact themes, immutable history, current
  selections and source provenance without changing user configuration or branding.
- [ ] Managed replay no-ops and updates preserve custom resources and retained bytes; source absence does not
  delete or retire themes.
- [ ] Invalid/unsupported content, wrong-scope references, aliases, stale edits and unauthorized access reject
  safely without source fallback or private-content leakage.
- [ ] PostgreSQL races, pointer return, rollback and uncertain outcomes preserve atomic audit and precise
  reference/selection guarantees needed by profile consumers.
- [ ] Exact theme facts are consumable independently of final profile/switching delivery; runtime presentation
  and collision-warning qualification remain explicitly separate.
