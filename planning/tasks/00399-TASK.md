# Inspect independently scoped provider allowance

## Outcome

Authorized humans can inspect genuinely provider-reported account/key allowance separately from Repository usage,
with bounded explicit protected refresh and truthful source/scope/time/reset-window provenance. Unsupported quota
stays unavailable rather than being guessed from local usage or generation support.

## Scope

- In scope: Exact qualified safe allowance source and protected refresh integration, sanitized durable observations,
  bounded current-authorized queries and independently loaded browser presentation using existing history/live owners.
- Out of scope: Billing/payment management, account enrollment or scraping, credential import, new providers,
  inferred Repository balances, generative refresh requests, automatic limit extension and duplicate live channels.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Refresh exact allowance source | Explicit bounded authorized refresh with original operation identity | Current configured source, disclosure authority, supported limits and original result | Committed safe source observation, never grant mutation | Declared protected external read after intent commit |
| Inspect recorded allowance | N/A — read-only | Current-authorized exact account/key-scope snapshot and freshness | Existing committed projection notification only | Honest broader-scope values or unavailable state; no network work |
| Recover uncertain refresh | Inspect original outcome; only owner-supported bounded reconciliation | Original operation/generation and qualified source semantics | Known original result or uncertainty | No implicit login, account switch, generation or blind replay |
