# Run Planning validation and refresh through PHP without the application stack

## Outcome

Give humans and agents a fast Planning check that needs neither host PHP or Composer nor a running application stack. Keep one PHP implementation for local use and direct invocation on GitHub.

## Scope

- Port the live validator and generated-view refresh to a PHP entry point under `scripts/`. Keep `./bin/planning-check` and its `--write` option as the host interface, using an explicitly prepared lightweight one-shot Docker container. Do not install dependencies during validation.
- Migrate the existing build caller to invoke the PHP entry point directly rather than launching the host wrapper inside its execution environment. Trace remaining callers, including the archive tool's refresh call, and preserve their supported behavior. Remove the superseded Python validator after verification.
- Leave the archive tool's PHP port, diagram tooling, four-workflow cutover, change selection, and per-pass receipts out of scope. Shared verification cutover belongs to [TICKET-00149](../tickets/00149-TICKET.md).

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Validate Planning | `./bin/planning-check` locally or direct PHP entry point in the build and on GitHub | Records, references, and generated views | N/A: verification | Report valid, invalid, and stale views without writing source |
| Refresh views | `./bin/planning-check --write` | Records and current generated views | N/A: maintenance | Rewrite only generated content; preserve authored content |

## Validation and permissions

Preserve command exit outcomes, actionable diagnostics, explicit write admission, and Markdown authority. Invalid planning still stops the existing build before application phases, even when application evidence is reusable. Do not require Docker inside the build environment, start the local web stack, change CI merge settings, or add product permissions.

## Acceptance criteria

- [ ] The PHP command preserves validation and refresh behavior on valid, invalid, and stale Planning records. Default validation writes nothing; explicit refresh preserves authored content and leaves the views current.
- [ ] Both host commands work in a prepared one-shot container on a host without PHP or Composer, with the application stack stopped. The direct PHP entry point runs on a GitHub runner without starting a container for Planning validation.
- [ ] The build invokes the PHP entry point directly and stops on invalid planning, including with a reusable application result. Surviving callers work without the removed Python validator.

## Verification and evidence

Compare old and new command output, exit results, and refresh diff on bounded fixtures before retiring the old command. Exercise both host modes and the direct hosted path, and verify the build's failure boundary. This hosted evidence concerns the Planning invocation, not the container-free cutover of the existing application workflow. Record the actual commands, results, and limits; run `./bin/planning-check`, `git diff --check`, and the existing canonical gate for the finished change. Use owning commands and direct probes, not product tests of wrappers or check machinery. Hand off to independent Review and applicable QA.
