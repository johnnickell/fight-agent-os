# Inspect current Agents and manage lifecycle intent

## Outcome

A currently authorized administrator can inspect safe Agent directory/detail and original-operation status,
confirm credential rotation or revoke current authority through existing lifecycle owners. Views distinguish
immutable identity/bindings, actual-versus-requested Permissions and issued/delivered/activated/currently usable
outcomes. No read or management acknowledgement authorizes a session or protected effect.

## Scope

- In scope: Current authorized package list/detail plus owned Team/template/scope/status composition; safe
  name-update integration, exact confirmed rotation/revocation, original-outcome recovery, protected Application/
  HTTP paths and status/denial contracts consumed by the final browser journey.
- Out of scope: Another lifecycle service/queue, activation override, secret console, maintenance/enrollment UI,
  template publication, existing-Agent Permission reconciliation, Team transfer or real role execution.

## Validation and permissions

Reuse TASK-00256's distinct current management rights and actual actor/target/scope policy across direct and API
paths. Establish permitted target scope before disclosure; neither package administrative Views nor a caller-
supplied ID authorize reading. Compose through package queries and justified owned cross-boundary orchestration,
not renamed wrappers or another Agent authority. Safe responses include immutable identity, current name, Team,
Repository scope, exact bound template revision and actual direct Permissions only within caller visibility.

Permission resolution must be complete: package invalid/missing definitions are failures, not partially returned
sets. Clearly identify the bound requested set and any compared revision without silently selecting a newer one.
Invalid/ineligible/unknown items stay explicit. Reading does not fix drift or call assignment handlers;
TICKET-00078 retains Add Missing and complete Auto-sync. Safe paging has deterministic order and truthful totals/
visibility; hidden items, failed joins or outages cannot masquerade as a complete empty result.

Combine current status coherently from actual owners, rejecting mixed or stale generations. Issuance, delivery,
activation and bounded use have different conditions; ACTIVE aggregate state or a sink acknowledgement alone is
not usable. TASK-00242–00245 supply authentication/activation/current-use and first-party MCP controls through
TASK-00245's dependency chain. Missing session/grant/host/context for an actual action means unavailable/unknown,
not globally usable. Show safe reasons and observation freshness, never an enduring capability token or a claim
that an Agent already performed work. No provider call or signing side effect is needed merely to view status.

Confirmed rotation binds exact expected predecessor/holder/destination and retained original intent under current
fences. Stale confirmation requires refetch and renewed human review. Revocation has independently current target
authority and cannot depend on key availability, sink contact, original destination access or new-work capacity.
Its effect retires/cancels through the package and denies later uses; do not promise recall of already admitted
effects. Uncertain liveness or commitment state cannot authorize implicit transfer or snapshot rebinding.

Preserve issuance's confirmed-publication-warning semantics versus revocation/name update's post-commit rethrow.
A timeout, missing status or failed notification proves neither rollback nor permission to create/rotate again.
Reconcile authoritative original state under current visibility before another attempt; no automatic retry after
401, disconnect or refresh. Do not expose operation request payloads/keys, claims/leases, receipts, protected
holder handles, ciphertext, private provider configuration or raw diagnostics, even to the Super Admin browser.
