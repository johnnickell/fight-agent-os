# Limit build CI triggers to primary branches and PRs

## Outcome

Run the Build workflow only for pushes to `develop` or `main` and pull requests targeting `develop` or `main`.

## Scope

- In scope: Narrow `.github/workflows/build.yml` event triggers to the approved branches and events.
- Out of scope: Changing build jobs, runtime, dependency installs, credentials, branch protection, or unrelated workflows.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Select CI runs | N/A — workflow configuration | Inspect GitHub Actions event filters | Push or pull request event | Build runs only on pushes to `develop`/`main` and PRs targeting `develop`/`main` |

## Validation and permissions

GitHub Actions branch filters must not match feature or release pushes or PRs targeting other branches. No application authorization changes. The human requested only these two events, so remove the optional manual dispatch as well. Do not modify the workflow's job steps.

- [x] The changed workflow is inspected and validated directly, and the canonical build passes with warnings disclosed.
