# Discover complete Feature references for exact code scopes

## Outcome

Protected inspection can obtain complete native and explicitly registered Feature references for one exact
CANDIDATE or CURRENT code scope through the package `FeatureReferenceDiscovery` contract. Honest empty discovery
is distinguishable from unavailable coverage; discovery neither changes business state nor permits deployment.

## Scope

- In scope: Real consumer discovery, exact code/module identity, native Attribute validation, one explicit
  non-HTTP reference registration source, bounded safe operational inspection and contract qualification.
- Out of scope: Runtime availability enforcement, provisioning/preparation, UI, automatic source changes,
  arbitrary-code execution, deployment enrollment, retirement and a dummy product Feature.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Inspect candidate references | N/A — protected read-only inspection | `FeatureReferenceDiscovery::discover(CANDIDATE)` over selected exact code | N/A — metadata has no business event | Complete validated reference set or unavailable/error; no catalog mutation |
| Inspect current references | N/A | Same discovery for authoritative CURRENT code/module identities | N/A | Fresh scope-correct inventory; unknown running-version coverage refuses completeness |
| Merge explicit checks | N/A | Native Attributes plus owning explicit non-HTTP registrations | N/A | Deduplicated package `FeatureReferences`; no new settings, grants or runtime checks |

## Validation and permissions

Implement the public package port directly; retain `FeatureDiscoveryResult`, `FeatureReferenceScope`,
`FeatureReferences` and strict `FeatureName` semantics rather than owned aliases. Inspect the selected tagged
package/source/Composer lock at implementation. TASK-00126 supplies a qualified storage/package baseline, not
scanner evidence. Fix and document the supported application/module declaration surface and authoritative
registration source before claiming coverage; scanning only already-loaded classes or one router is insufficient.

Instantiate every discovered package Attribute with native reflection, not only `getArguments()`. Account for
supported method resolution, inheritance/traits and all included modules; reject malformed names, multiplicity
and invalid placement rather than silently skipping declarations. No trimming, case normalization, inferred
Feature names or dynamic unregistered checks. Preserve package deduplication/first-reference order and validate
every supplied registration even when its name duplicates another. Runtime consumers in TICKET-00071 must use
this same registration boundary rather than invent a second list.

Bind discovery to exact intended code and lock/source identity, not a caller-supplied scope label. Candidate
and CURRENT are not interchangeable, even if paths or branch names match. Prevent current-process autoloaded
classes from substituting for different candidate bytes. Qualify candidate inspection without application boot,
Action construction, credential/provider access or execution of arbitrary caller-selected code. Any loading needed
for native Attribute validation is restricted to the expressly trusted selected code in a bounded inspection
context, not a general upload/path execution service. Use repository Docker wrappers for operational tooling.

Retain verifiable code/module identity alongside the operational observation; the package scope enum alone is
not deployment evidence. Detect changed inputs, incomplete enumeration, inaccessible modules, ambiguous roots,
scan failures and bound exhaustion. They return unavailable or a safely mapped failure, never a truncated or
complete-empty success. A genuinely complete inventory with zero references is valid and requires no Feature.
Do not cache a negative inventory across code changes or relabel/reconstruct a result under a different scope.

Use explicit trusted operator access and target/code scope for inspection, not a Feature's testing Permission,
role name, browser parameter or bare `--internal` assertion. No public endpoint or management Permission extension
is needed here. Bound scan resources and output; safe summaries expose no arbitrary source/paths, SQL, exception
messages, environment secrets or credentials. CLI/configuration/tooling are directly qualified, not product-tested
as text or wiring. A selected local scope is not proof of all remote workers or overlapping deployments.

For CURRENT, complete means all applicable actual running versions/modules for the declared supported target.
Unknown identity, undisclosed process coverage, stale observations or unsupported topology hold. Supply the reusable
inventory capability without creating a universal deployer. TICKET-00074 retains actual retirement-time deployment/
overlap qualification and protection of that observation; a prior scan cannot fence later activations.

- [ ] Actual candidate/current identity differences, unloaded declarations, malformed/invalid placements,
  inaccessible/changed inputs, bounds and honest empty inventories are exercised without business effects.
- [ ] Operational inspection has explicit trusted scope and safe diagnostics; unknown current-version coverage
