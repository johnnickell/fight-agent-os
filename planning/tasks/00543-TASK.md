# Manage local task resources from preparation through verified cleanup

## Outcome

Make normal main-stack operation and disposable registered-worktree operation explicit, using Compose rather
than a second resource ownership/lifecycle system. John approved this standalone chore on 2026-10-27, expanded
it on 2026-10-31, then explicitly replaced the earlier receipt/PID/branch-gated design with the contract below.
This replacement supersedes conflicting earlier scope and interrupted implementation, not historical acceptance
of TASK-00542/00546/00547/00548. The user selected the canonical main checkout and authorized source/planning
revision plus the bounded ingress extraction. Work stops without automatic Review/QA/Land or publication.

## Scope

- `bin/up`: start the main checkout's full declared direct local TLS application stack, normally at
  `https://localhost:18443`, using existing explicit `.env`/certificate prerequisites and root/CSRF readiness.
  No shared-ingress requirement, auto-proxy selection or generated main/task proxy override. `bin/down`:
  stop/remove that main stack while retaining normal persistent data. No TASK receipt, worker/PID or branch gate.
- `bin/up --worktree task-00543`: resolve an actual registered Git/Worktrunk checkout, start its full declared
  application stack with disposable isolated database/storage. `bin/down --worktree task-00543`: remove it.
  Exact path/branch selectors disambiguate same-task checkouts; project identity is stable per checkout, not TASK ID.
- Generate explicit source/settings/image overrides; select Compose files explicitly so task overrides cannot
  enter main. Native Compose labels and Docker metadata own discovery/cleanup; retain only a minimal locator
  outside removable source for interrupted teardown. No resource ledger, command receipts, stale branch/PID gates,
  recovery framework, compatibility lifecycle or per-resource disposal approvals.
- Teardown runs Compose `down --volumes --remove-orphans`, removes task image tags and remaining project-owned
  resources, including a dedicated builder if created. Shared downloads/build caches are not task-exclusive;
  maintain them separately and explicitly. Never globally prune or touch foreign projects or main data.
- Worktrunk, Land and owned qualification fixtures use ONE guarded native removal callable, always public
  `bin/down --worktree SELECTOR` before source/config deletion; repetition is harmless. Routine owned cleanup
  runs unattended for absent hooks or only the exact reviewed project `pre-remove.runtime` down template,
  rechecking complete effective canonical/target system/user/project pre/post-remove hooks immediately before
  per-invocation native noninteractive consent. Unknown/user/changed hooks refuse source removal without
  persistent approvals, global config/trust changes, hook hiding/skipping, force/reap or custom Git fallback.
  Delivered branches retain exact publication/ref proof; clean owned fixtures use exact OID/ancestor proof,
  not fabricated PR evidence. Unique/dirty source, ignored private data, actual consumers and genuine filesystem
  protections remain independent guards; parent exposure/cached file-sharing handles need native qualification.
- Isolated task startup consumes TASK-00553's one separately operated public Nginx plus nonpublic docker-gen
  (only docker-gen has a read-only socket), with a clear missing-ingress/certificate prerequisite and no fallback
  to main. Task down remains available without ingress. Only application web gateways join shared ingress;
  private services do not. Remove inherited task host publishing. Qualify intended shared main/worktree
  `<name>.localhost` origins and actual-name certificates through TASK-00145's explicit setup tooling separately;
  this future integration must not break ordinary direct main startup. No implicit trust/custom DNS/shared control.
- Preserve direct TLS authority: qualify HTTPS proxy-to-gateway transport, exact origin, Secure cookies, available
  authentication and forwarding-spoof denials. Print a usable URL only after actual readiness, not config presence.
- Preserve independent native session/custody/Harness role admission. Docker lifecycle does not register or gate
  those sessions. Reuse one project across roles; Work/Build handoffs report actual native resources and missing prerequisites.
- Exclude implementing TASK-00553, full installation provisioning, custom DNS, unrelated foundation, managed PHP
  provisioner/Runner authority, fleet setup, global installation/trust/reset, shared shutdown and source deletion of main.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Run main | `bin/up`, `bin/down` | Compose state/readiness | N/A — operator infrastructure | Full main stack; persistent data survives down |
| Run isolated checkout | `bin/up --worktree SELECTOR` | Git registration, source mounts, private data, HTTPS readiness | N/A | Stable isolated project and distinct origin |
| Retire isolated checkout | `bin/down --worktree SELECTOR` | Native project resources and remaining consumers | N/A | Disposable stack/volumes/private networks/task tags absent, other projects unchanged |
| Remove source after delivery | Same down command, then Worktrunk | Exact source/ref, delivery, private data and consumers | N/A | Docker first; eligible Git removal only |
