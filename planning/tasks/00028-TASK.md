# Establish fail-closed client authority and guarded routing

## Outcome

A client-side current-principal cache and shared permission evaluator drive guarded routes and component presentation through explicit unknown, loading, anonymous, authenticated, forbidden, stale, and terminal states, using an injectable test loader until EPIC-00004 delivers `/api/v1/me`.

## Scope

- In scope: Safe current-principal model; injectable loader capability; one API-cache owner; authority state machine; invalidation/refetch and stale-response controls; permission evaluator; complete-route permission metadata; guarded routing; component visibility/disabled decisions; safe intended-route representation; deterministic tests and representative UI states.
- Out of scope: Real `/api/v1/me` HTTP operation, login/refresh/logout implementation, token parsing, role/permission persistence, product routes, server authorization, cross-tab transport implementation, final UI design, and a broad state-management framework without demonstrated need.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Load current principal | N/A — client authority load | Invoke injectable authoritative principal loader | Client cache lifecycle only | Cache enters loading then authenticated/anonymous/failure without trusting stale data |
| Guard complete route | N/A — navigation decision | Evaluate route metadata against current authoritative permissions | Browser navigation/UI effect | Unknown/denied state does not render protected page; allowed state renders outlet |
| Gate component action | N/A — presentation decision | Use same evaluator for required permission | N/A — no domain event | Control is hidden/disabled according to explicit component policy, never treated as server enforcement |
| Invalidate authority | N/A — coordination response | Process refresh/logout/terminal/authority-change signal | Client invalidation signal | Stale authority is removed and optionally refetched; late responses cannot restore it |

## Validation and permissions

Model principal fields explicitly and reject malformed loaders rather than accepting transport objects. Roles may be displayed as safe data but cannot grant via role-name shortcuts. Permission comparison is exact and unknown/stale state fails closed. Route requirements must be complete metadata, not scattered component-only checks.

The one cache owner controls request generation, loading, freshness, invalidation, refetch, and late-result suppression. Invalidate after refresh, logout, terminal authentication failure, and authority-changing operations/signals according to the ADR. An older load cannot overwrite a newer invalidation or principal.

Safe intended routes are same-origin application paths with approved query/hash policy and bounded size. Exclude credentials, secret form fields, request bodies, arbitrary serialized state, and external/open-redirect targets. Intended route is transient, not persistent business state.

Use an injected deterministic loader for this foundation. Do not claim or document `/api/v1/me` as implemented until EPIC-00004 supplies the server operation and feature service. Client checks are usability only; all protected server interactions remain authorized server-side.

## Acceptance criteria

- [x] One cache owner models unknown, loading, anonymous, authenticated, forbidden/denied presentation, stale, and terminal authority states.
- [x] A safe explicit current-principal model contains only approved identity display fields, roles, and permissions and is not derived from a JWT/HTML/runtime config.
- [x] One exact permission evaluator serves both complete-route metadata and component visibility/disabled decisions.
- [x] Unknown/loading/stale/malformed authority fails closed and role-name shortcuts cannot grant access.
- [x] Refresh, logout, terminal authentication failure, and authority-change signals invalidate/refetch according to the accepted ADR.
- [x] Request generations prevent late/stale loader results from restoring invalidated authority.
- [x] Guarded routes preserve a bounded safe same-origin intended path without secrets, form state, arbitrary serialization, or open redirects.
- [x] Client checks state explicitly that server authorization remains authoritative.
- [x] A deterministic injected loader proves behavior while the real `/api/v1/me` operation remains deferred to EPIC-00004.
- [x] Focused route/cache/permission/component tests and `./bin/build` pass with fresh evidence.
