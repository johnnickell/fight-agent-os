# Enroll and inspect the installation Runner

## Outcome

An explicitly authorized operator enrolls and inspects one installation-owned Runner whose durable identity and
protected credential boundary survive container recreation. Actual bounded capability reports distinguish usable,
stale, unavailable and unsupported facts without authorizing execution.

## Scope

- In scope: Runner-only extension of the existing installation Compose/bootstrap path, stable identity and protected
  credentials, generated boot/process identities, scoped capability/health queries, explicit rotation/revocation/
  de-registration, preserved history and operator guidance.
- Out of scope: A second installation, remote fleet, whole Planning runtime/ingress transition, sandbox/provisioner/
  broker implementation, Workflow Start, consumer dispatch, provider calls and automatic host setup.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Enroll the Runner | Explicit authenticated operator bootstrap/enrollment with original identity | Installation, existing enrollment and exact selected profile | Committed Runner enrollment/audit facts | One retained Runner identity and narrowly protected credential installation |
| Inspect availability | N/A — read-only | Actual versions, approved roots, tool/network/Artifact support, freshness and health | Heartbeats are observations, not semantic transitions | Safe bounded status, never automatic repair or launch |
| Rotate revoke or de-register | Exact current-authority expected-state lifecycle operation | Original operation, retained ownership and current credential generation | Committed security/lifecycle facts and required intent | Fence future use, preserve history and unresolved work; not implicit Halt or cleanup |

## Validation and permissions

Consume TASK-00138's accepted profile/qualification boundary and TASK-00321's exact Harness package facts, not an
assumption that qualification implements hosting. Extend the same installation incrementally for terminal use;
coordinate TASK-00072/00073's eventual topology/root contracts without importing their complete browser prerequisite
chain or duplicating approved-root authority. Runner exposure must be explicit, canonical, contained and measured;
configuration alone is not a mounted usable root. Missing required host support reports unavailable.

Require accepted authenticated operator/system authority, exact installation scope and current revisions. Shell
possession and a supplied Runner ID do not authenticate enrollment. Preserve one durable Runner across boots;
generate identities through owning factories/libraries. Repeating original bootstrap reconciles its outcome rather
than creating another credential or pairing ceremony. Credential rotation/revoke/regrant uses monotonic generations;
stale boot reports or old holders cannot restore access. Retain de-registered identity and obligations.

Persist state, audit and required intent together on ADR 0002's canonical PostgreSQL transaction. Secret installation
and service effects occur outside it with original-operation reconciliation. Keep installation secrets outside
images, children, ordinary output and evidence, using the accepted narrowly permissioned installation store. Give
this service no Docker socket, broad home mount or Agent-facing inbound port. Do not expose arbitrary signing,
provider credentials or privileged provisioner commands. Reads have bounded probes and no corrective effects.

Report actual safe Pi/Harness/sandbox versions and qualified roots/tools/network/storage capabilities independently.
Unknown, unsupported, revoked, disabled, incompatible and stale are distinct from available. Neither a heartbeat
nor successful bootstrap admits a Workflow; capacity/gates and current authority are rechecked by their owners.
