# Guard API-v1 Actions with JWT and permission attributes

## Outcome

Every registered `/api/v1` route defaults to TASK-00044 authoritative Bearer authentication, and matched FQCN Actions declare an explicit approved public-read/credential-flow exception, authenticated access or conjunctive `#[RequiresPermission]` metadata checked before instantiation or dispatch. A genuine protected `/api/v1/me` query with a safe no-store current-principal View proves the gate before other protected routes exist. This is an early HTTP gate, not the sole policy boundary.

## Scope

- In scope: Slim route group and routing order; final FQCN Action registration/metadata inspection without resolving all Actions; JWT context from TASK-00044; exact request-scoped permission evaluator; explicit public bootstrap/credential-flow and approved validation-schema-read markers; default-deny missing/invalid metadata; multiple permission conjunction; first protected `GET /api/v1/me` Action/query with safe identity and current role/permission projection, no-store JSend/OpenAPI, 401/403, route/method misses and no-dispatch proof; focused tests.
- Out of scope: Implementing JWT cryptography, login, permission policy/catalog, owner/target-role decisions, role-name bypasses, `/mcp` HMAC, test-only product endpoints, or claiming HTTP attributes authorize non-HTTP package callers.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Project current principal | None | Inspect matched Action metadata; use `CurrentPrincipalProvider` and package-owned safe identity lookup | None | `/api/v1/me` returns current authorized safe no-store View without trusting role claims |
| Dispatch permitted Action | Existing Action owns its use case | Inspect matched Action metadata and current principal/permissions | Owning use case only | Exactly one authorized Action is instantiated and dispatched |
| Reject missing/stale/insufficient authority | None | Resolve TASK-00044 authoritative principal and exact permissions | None | Safe 401/403 before Action construction or package dispatch |
| Admit an explicitly approved public operation | Only the endpoint's own use case | Inspect the single matched allowlisted public Action marker | Endpoint-owned event only | CSRF bootstrap, separately controlled credential flows and the approved safe validation-schema read bypass JWT alone, not their own security guards |

## Validation and permissions

After Slim route selection and before Action resolution, inspect the matched FQCN class without instantiating it. Default API-v1 to Bearer; require one explicit marker for approved public-read/credential-controlled or authenticated routes, or `#[RequiresPermission]` with one or more valid catalog names. Unmarked, conflicting, unknown or malformed metadata fails closed. Public exceptions are allowlisted by actual Action identity, not URL-pattern string or inherited blanket group bypass. A permitted attribute checks current request-scoped authoritative permissions, not JWT role claims, role names, client state, or stale cached snapshots. Revocation or permission changes between requests fail closed.

[TICKET-00036](../tickets/00036-TICKET.md) additionally approves the exact public schema-read Action at
`GET /api/v1/validations/{form_name}`. When registered by TASK-00151, admit it without authentication or
`VIEW_DASHBOARD`, while retaining its form/rule allowlist and bounded safe read contract. Do not infer a public
exception for other validation, documentation, Swagger or arbitrary API routes. This is deliberately safe
metadata, not anonymous access-control data or business-operation authority.

Credential-controlled login/refresh/logout/activation/reset retain their separate CSRF/Origin/Fetch/JSON/rate/grant policies; an explicit public marker never declares them unprotected. Owner/self checks, package target authorization, tier delegation rules, last-admin protection and confirmation/audit remain inside application/package services. Do not register protected API endpoints before this boundary exists. Leave `/mcp` to future independent HMAC authentication; preserve root/web routes and honest route/method misses.
