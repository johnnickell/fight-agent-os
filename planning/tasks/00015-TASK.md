# Persist password-reset grants and terminal succession

## Outcome

A production PostgreSQL adapter satisfies the stable `PasswordResetGrantRepository` contract with purpose-separated secret-safe storage, exact reconstruction, terminal append/replacement/succession rules, and controlled one-time race behavior.

## Scope

- In scope: Password-reset-grant migration/mapping; complete production repository adapter and composition; package-approved credential digest and safe delivery/lifecycle state; stable, delivery, latest-user lookups; add, append-after-terminal, replace, and replacement-with-successor; authoritative constraints, rollback, and controlled concurrency tests.
- Out of scope: Reset request/completion orchestration, credential generation, provider delivery, password/session mutation, HTTP/UI behavior, throttle, raw grant storage, activation-grant changes, and denylist/password-policy implementation.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Add reset grant | Package password-reset behavior later uses repository | Resolve user/reference validity | Package reset events remain package-owned | One purpose-bound secret-safe grant state persists |
| Resolve reset state | N/A — repository read | Find by ID, delivery ID, or latest user grant | N/A — no adapter event | Exact package aggregate is reconstructed with deterministic latest ordering |
| Append after terminal state | Package request behavior | Compare terminal predecessor and proposed new grant | Package events only after committed behavior | New grant appends only after a contract-valid terminal predecessor |
| Replace or supersede grant | Package delivery/completion behavior | Compare complete expected predecessor | Package replacement/completion outcomes remain package-owned | One valid transition/successor commits; stale or duplicate work writes nothing |

## Validation and permissions

Persist no raw reset credential. Keep reset purpose and storage distinct from activation grants while following shared mapping conventions. Enforce stable/delivery identifiers, user references, credential digest uniqueness, lifecycle/revision and successor constraints, and deterministic latest ordering.

Implement every stable `PasswordResetGrantRepository` method directly. `appendAfterTerminal`, replace, and replacement-with-successor must compare complete expected state and enforce package terminal/successor rules atomically. Duplicate IDs/delivery identities, invalid predecessor state, stale completion, and missing users map to safe outcomes.

No public reset permission or behavior is implemented. Repository/schema/composition work is authorized; password changes, session revocation, delivery, and transport remain later TICKETs.
