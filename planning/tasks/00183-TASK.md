# Refresh test assessments when cases or contracts change

## Outcome

A current PHPUnit usefulness report reassesses cases whose tests, expectations, contracts or relevant behavior
changed, while reusing only fully matching evidence under current permissions. The current population and
criterion denominators exclude removed cases and retain original provenance for reused outcomes.

## Scope

- Extend [TASK-00181](00181-TASK.md)'s changed-case assessment using
  [TASK-00179](00179-TASK.md)'s qualified current-subject refresh/impact/coverage mechanics and inherited shared
  reuse capability. Target Pi 1.1.0; no second cache, classifier, handoff trigger or permission policy. Do not
  depend on TASK-00182 solely to deliver this useful changed-case refresh path.
- Pin the new exact base/head, test configuration/discovery identity and eligible case population before matching
  old results. Preserve declarations versus provider instances versus execution receipts. Added, deleted, moved,
  renamed, inherited and split/merged cases must be reconciled without conflating identities or double counting.
- Include case code, assertions, setup/teardown, shared helpers, providers/datasets, fixture/snapshot expectations,
  related owned behavior and requirements/conventions in the relevant context manifest. Changes to any evidenced
  influence can invalidate a case even when its method text is unchanged. A name/path match is not proof of meaning.
- Reuse only when the entire relevant evidence/context, criterion question/declared choices, rubric/preset,
  evaluator/configuration, source/disclosure/consumer policy and current caller/session/repository scope match.
  Re-establish source identities and current access through bounded owning capabilities before exposing metadata.
- Where impact or dependency mapping is unknown, reassess the bounded relevant case population or report explicit
  gaps. Do not infer complete semantic coverage from file-level diff, a green suite, unchanged assertions or a
  guessed provider expansion. Receipt freshness/identity must match the question; historical results stay historical.
- Reassess affected cases using the same four criterion enums and budgets as TASK-00181. Shared fixtures/providers
  may affect many cases; honor aggregate ceilings and report remaining gaps instead of silently sampling or
  increasing limits. No automatic discovery/test execution or retry of effects to fill a missing cache entry.
- Rebuild current coverage and per-criterion counts/proportions from the current population and actual outcomes.
  Remove deleted/no-longer-eligible cases from current assessed counts while retaining historical provenance under
  the owning evidence policy. Keep declaration/dataset denominators separate and unknown inventory visible.
- Label fresh and reused outcomes with original evaluation identity/time and current validation/subject binding.
  Unknown/N/A/partial outcomes never become supported complete criteria through reuse. Keep model concerns separate
  from independently confirmed/dismissed findings; a prior finding's current applicability requires its owning
  review rules and cannot be inferred from a cached classification.
- Respect the shared session-local cache and lifecycle restrictions. An Engineer report, a resumed historical
  assessment or an independent reviewer session is not a cross-principal/private-context cache grant. Revalidation
  may require local reads; report that work and do not claim every hit avoids all source access or has zero cost.
- Avoid double-counted provider charges and preserve uncertain reservations. Concurrent edits, base movement,
  stop/reload, cancellation and stale responses cannot publish mixed-revision reports or reset budgets. Repeated
  notifications are deduplicated rather than repeated samples for a preferred answer.
- If the optional full-suite workflow is installed, expose the same compatible case/context invalidation contract
  to its owner. TASK-00182 remains responsible for scoped full-suite population and safe same-job continuation;
  do not claim live combined qualification before it exists or require it just to refresh changed-case handoffs.
- Preserve advisory outage/gap behavior: missing or exhausted Jev leaves explicit unassessed/stale cases while normal
  handoff proceeds under required gates. No special waiver, automatic test deletion/repair, changed acceptance
  threshold or inherited independent-review approval is introduced.
- Exclude cross-session/principal cache sharing, live query/operation replay, mutation tooling, seeded product
  failures, tests of tests, production-data fixtures and automatic full-suite reviews.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Refresh changed-case usefulness | Start a bounded current-subject refresh | Current inventory and test/contract/context impact | Fresh/reused/ineligible/gap observations | Authorized revalidation and optional bounded provider usage |
| Reuse a supported match | N/A: reuse is read-only | Full identity/policy/current-authority match | Reuse observation with original provenance | Avoid provider evaluation only on a verified match |
| Reconcile removed or remapped cases | Update owned current report population | Actual case/dataset identities and eligibility | Coverage/denominator update | Current counts exclude removed cases; historical report remains historical |
| Continue with gaps | Existing review handoff | Current subject, explicit unknowns and required-gate receipts | Advisory gap/handoff facts | No waiver, test mutation or automatic acceptance |

## Validation and permissions

Validate case/reference identities against actual current sources and enforce caller access plus provider
redisclosure independently. Unchanged text, a prior score or old permission is insufficient. Unknown dynamic
provider/context identity makes reuse ineligible rather than authorizing provider execution. Follow established
selective-read rules for any main-Agent source follow-up. Shared cancellation/budget controls and separate reviewer
verification remain in force; a cached model outcome cannot become a current formal finding automatically.

## Acceptance criteria

- [ ] Real Pi 1.1.0 handoff refresh reassesses affected PHPUnit cases and reuses a fully matched permitted outcome
  without new evaluation, retaining old evaluation provenance and current subject/validation identity.
- [ ] Changes to requirements, related behavior, assertions, providers, setup/helpers, fixtures/snapshots, criterion/
  evaluator/policy or permissions invalidate affected results even when case text is unchanged.
- [ ] Ambiguous impact or dynamic discovery yields reassessment/gaps, while additions/removals/renames and inherited
  or provider-expanded cases produce honest current identities, coverage and consistent denominators.
- [ ] Reuse cannot upgrade unknown/N/A/partial outcomes, transfer private Engineer context, revive deleted cases or
  turn old reviewer findings/execution receipts into newly verified evidence.
- [ ] Stop/reload/concurrent edits and budget exhaustion cannot create stale mixed-subject reports, duplicate charges,
  hidden retries or advisor-only handoff blocks; no tests or effects execute to regenerate cached evidence.
- [ ] Representative changes report actual hits/misses/invalidation, revalidation work, false flags/missed concerns,
  coverage and available total cost/latency without unsupported correctness or savings claims.
