# Open confirmation links without changing account state

## Outcome

An actual new-mailbox confirmation link opens an accessible public landing page that captures its exact
purpose-bound credential transiently and promptly removes it from visible history. Opening, prefetching or
revisiting the page never confirms a change, sends a notice or starts a session/authentication restoration.

## Scope

- In scope: TASK-00285 producer-contract integration, existing public routing and shared grant-link bootstrap,
  bounded volatile capture/cleanup, neutral landing/recovery states and real safe browser evidence.
- Out of scope: Confirmation POST, public validity/status lookup, private account read, request/cancel actions,
  new credentials, automatic login/refresh, provider enrollment or mutation during link navigation.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Open a delivered link | N/A — nonmutating page navigation | Decode only the fixed bounded link identity/credential from TASK-00285 | Client-only history replacement, no business event | One volatile credential owner; clean URL before ordinary rendering/navigation |
| Inspect neutral guidance | N/A | Local capture/shape state only, not account/grant validity | N/A | Accessible purpose/explicit-action guidance without account enumeration |
| Revisit or leave the page | N/A | Local lifetime and route generation, never browser-persisted recovery | Local cleanup only | Discard secret; missing capture receives generic recovery, no request or confirmation replay |

## Validation and permissions

Consume the exact configured-HTTPS purpose path/encoding produced by TASK-00285. Reuse TASK-00043's qualified
invitation-link bootstrap and TASK-00051's public routing, not a second secret store or copied password/activation
flow. Distinct purpose ownership remains explicit. Parse only the necessary bounded User routing identity and
credential; use owning identifier parsing and preserve the credential's exact bytes. Reject missing, duplicate,
extra, malformed, ambiguous or oversized fields without echoing them. Fix/test exact bounds against the producer
contract before acceptance; shape validity is not proof that a grant exists or remains usable.

Capture the narrowly required inbound fragment once into an ephemeral owner and replace visible/history URL
with the fixed clean route before ordinary rendering, analytics, diagnostics, screenshots or navigation handling.
Never move it into a query string, redirect, hidden field, DOM attribute, HTML/config, route state, intended-route
restoration, API cache, devtools snapshot or persistent browser storage. No remote active content, tracking or
third-party resources are added. No-store, no-referrer and compatible restrictive CSP apply to the actual route.
Inspect real edge/application logs and client failure paths, not just a sanitized UI. There is no promise to erase
mail-provider/browser-internal copies outside application control; record residual platform limits honestly.

Permit legitimate external-mail top-level navigation. Do not apply the mutation-only Origin/Fetch rules as a
blanket landing prohibition. The public page does not require an existing session or administration Permission
and must not trigger automatic confirmation, refresh, login, logout, private `/me` lookup or email on load.
Existing session state cannot replace the captured mailbox proof. Link GET/HEAD/prefetch and repeated rendering
leave grant, reservation, canonical email, authentication/session, audit and notice business state unchanged.

Choose neutral guidance rather than inventing a validity query. No GET calls `confirmEmail()` as a probe or
expires/repairs grant state; optional validity inspection in the parent is deliberately not implemented here.
Display no private target name, current/new address, grant/delivery internals or fabricated valid/expired status.
Missing/locally malformed capture may be described safely without confirming whether an account exists.

Use one nonrenewing bounded local lifetime and clear references on terminal outcome, expiry, route replacement
or teardown. A local deadline never extends package one-hour authority; do not compute a new server lifetime
from arrival or retry. Remount, back/forward, reload, failed boot, missing assets/JavaScript or history-replacement
failure must never become mutation or secret persistence. If secure capture/removal cannot complete, withhold
submission and give safe generic recovery. Retire restored/bfcache page state before reuse rather than resurrecting
an abandoned credential. Do not claim guaranteed zeroization of browser memory.

Deliver accepted responsive production components with visible focus, keyboard operation, announcements,
system/light/dark, reduced-motion, loading/missing-link/unavailable states. Before TASK-00289 supplies deliberate
submission, no fake success or working-looking mutation action is exposed. The bounded capture seam hands the
same credential to that owner without serializing or broadcasting it.
