# Reconcile and inspect managed static Skills

## Outcome

An authorized operator reconciles reviewed static Skill bundles into database authority and inspects exact scoped
revisions through a protected application/API path. Template, profile and trusted-loader consumers receive real
identity, manifest and reference contracts, not another catalog or a schema-only prerequisite.

## Scope

- In scope: Type-specific managed Skill identity, complete static bundle validation, immutable bytes/manifests,
  provenance, current selection, idempotent reconciliation, protected exact inspection and reference fences;
  the bounded shared resource-authorization/reference contracts needed by the approved follow-on resource types.
- Out of scope: Custom Skill publication, other resource-type aggregates, retirement/rollback commands, MCP
  transport/cache/host trust, template seeding, Agent grants, provider use, session resolution and general editors.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Reconcile reviewed bundle | Explicit managed Skill reconciliation with exact source and expected state | Managed key, scope, normalized manifest/digest and current generation | Committed creation/revision/selection facts; none on unchanged replay | Complete immutable revision, selection and required audit commit atomically |
| Inspect exact Skill | N/A — authorized read | Logical/revision identities, retained bytes, complete manifest, provenance and current eligibility | N/A — inspection does not mutate | Safe exact data for authorized consumers without source fallback |
| Validate a resource reference | N/A for inspection; transaction participation belongs to the caller's mutation | Exact type/scope/revision, lifecycle and selection generation | N/A independently | Supported reference/current-selection fences for actual owning mutations |

## Validation and permissions

Reuse TASK-00036's managed policy and TASK-00078's typed Workspace/Repository identities, with TASK-00117's
protected HTTP context. Define bounded intent-specific resource-management and read capabilities under the existing
policy owner; no role-name, source-file, CLI flag or supplied actor-ID grants. Enforce current scope and authority
on every supported direct/adapter path, including no-ops. Unsupported Agent/host entry modes stay unavailable;
TICKET-00061/00087 own their later live invocation composition. Viewing content does not authorize provider disclosure.

Keep Skills type-specific within Harness. Stable logical IDs and managed keys are independent of aliases and
immutable revision IDs. Allocate IDs with the owning factory/UUID library. PostgreSQL owns current selections and
retained bytes; reviewed definitions under `database/skills/` are inputs, never a second runtime authority.
Normalize a complete bounded bundle before mutation; validate exact frontmatter, paths, per-file sizes/digests,
references, total limits and reserved `agent-os-*` bootstrap names. Reject traversal, escaped/symlinked resources,
incomplete or dynamic/unverifiable bundles and ambiguous aliases/references. Import never executes supporting files
or expands Skill instructions. `allowed-tools` is a non-authoritative request, never a Permission or local tool grant.

Resolve the stable managed key, no-op on an unchanged current digest, otherwise append and atomically select the
complete revision with expected-state protection. Competing imports cannot duplicate revisions or overwrite newer
selection; changed-away-and-back pointers do not validate stale intent. Preserve custom resources and reject
ambiguous adoption/collisions. Source absence causes no deletion or retirement. Retain old bytes and references;
source changes never modify active snapshots. TASK-00331 owns explicit lifecycle/retained-selection operations.

The owning Application handler controls one shared ADR 0002 transaction for state, references, selection and required
Harness audit. Specify actual reference-fence participation and lock order for later type-specific writers and
consumers; a preflight read is not an atomic publication guarantee. Filesystem reads occur outside the transaction
against held exact input. Events follow commit. Unknown original outcomes require authoritative inspection, not
blind replay or a claim that matching current content proves this caller's success. No generic outbox/audit platform.

Bound authorized catalog/history/content reads and keep bodies, secrets and private source out of ordinary logs/events.
Separate safe metadata from explicitly authorized content delivery. Supply exact database manifest facts to
TICKET-00087; origin identity, wire publication and host collision observations stay with that owner. Resource storage
must not reverse-depend on completed loading, custom publication, profiles, templates or browser Planning.

## Acceptance criteria

- [ ] Actual protected reconciliation/inspection creates complete immutable Skill revisions with stable identities,
  exact manifests/provenance and scoped current selections; source copies alone are not runtime authority.
- [ ] Unchanged replay is a validated no-op; changed input selects one new revision without custom overwrite,
  source-absence deletion or mutation of retained bytes.
- [ ] Malformed frontmatter/manifests, escaped paths, oversized/dynamic content, reserved names, invalid references,
  stale selections and unauthorized reads/writes fail safely without partial state or disclosure.
- [ ] Real PostgreSQL competition, rollback and uncertain outcomes preserve state/audit atomicity and exact reference
  fences; safe inspection distinguishes historical content from current eligibility.
- [ ] Later resource/profile/template/loader owners can consume precise contracts independently of completed
  sessions, Agent provisioning or database Planning cutover; no resource confers authority.
