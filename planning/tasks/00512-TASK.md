# Follow verified worktree logs in Herdr and retire the RPC workspace

## Outcome

Complete the [Herdr-native workspace](../tickets/00110-TICKET.md#approved-herdr-native-workspace-and-task-decomposition--2026-10-23):
while the operator uses native Pi and the child companion, a separate human-only pane follows the selected
child's verified existing test logs, or the primary worktree when no child is selected. Deliver the final
entry-point/documentation migration without retaining a second conversation frontend as the default experience.

## Scope

- Attach the named log companion from TASK-00510 to TASK-00511's validated selection/worktree/session-generation
  metadata. Reuse TASK-00449/00502's bounded readers and exact Docker source/container verification.
- Preserve explicit human bindings to already-existing worktree test stacks. Supply bindings once per workspace
  launch/open, not per child switch; do not infer permission from cwd, naming prefixes, model output or saved
  preferences. Multiple eligible stacks/services require labelled selection. Shared main-runtime mode stays a
  separate explicit human choice and remains visibly shared.
- Rebind on verified selected/pinned worktree changes, otherwise use the primary worktree. Stop/reap the previous
  reader, clear live/paused buffers and reject stale callbacks before accepting another source. Custody loss or
  stale generation removes log-source authority; unavailable mappings never silently fall back to shared logs.
- Provide readable source/service/reader state, follow, pause/drain, close/reopen/reconnect, bounded scrollback,
  clipping/gap notices and details. Keep logs out of Pi, child tools and provider context.
- Complete the native Pi + Herdr entry-point/runbook migration and explicit non-Herdr guidance. Retire the public
  RPC conversation path only with accepted end-to-end replacement delivery; preserve the existing client during
  earlier TASKs and preserve historical evidence/session data. Document how existing RPC sessions are opened in
  native Pi using their actual session file, without cloning or silently selecting a workflow/role.
- Keep ordinary `pi` available outside Herdr. Never silently reinstall Herdr/integrations, modify a live global
  package or fall back to the old RPC editor after a Herdr prerequisite failure. Package rollout is a separate
  authorized effect; repository implementation does not mutate the operator's current installation.
- Exclude container provisioning/restarts, Compose overrides, database mutations, full logging/search/archive
  infrastructure, managed execution, automatic integration installation and historical evidence rewriting.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Open verified test logs | Explicit workspace/source binding and companion open | Human-declared bindings, local Docker endpoint, exact checkout/service/running container | Existing Docker output | Bounded human-only reader; no container lifecycle changes |
| Follow selected child or primary worktree | Companion selection/pin/unpin from TASK-00511 | Validated session/worktree/generation and eligible source | Validated local selection notification, not a Workflow event | Old reader reaped; buffers cleared; exact new source verified before reading |
| Select shared source or pause/reconnect | Explicit source/service/mode controls | Current eligible service/container and reader state | Output/disconnect notices | Display/read lifecycle only; shared identity remains explicit |
| Migrate from RPC client | Documented native entry action and existing Pi session-open operation | Actual existing session file and native Harness binding | Existing native session lifecycle | Same stored conversation opened in native Pi; no history rewrite or authority selection |

## Validation and permissions

Docker operations use the existing fixed argument-vector adapter, exact local endpoint, checkout label, service
and full running-container identity. No arbitrary command passthrough, Compose evaluation, Docker socket exposure
to children or model-directed source choice. Recreated/ambiguous/stopped/denied sources require fresh validated
human binding rather than an automatic fallback. Saved preferences and child labels alone grant no source authority.
Preserve all existing finite record/buffer/process/deadline/reaping limits and terminal-control escaping. A powerful
human Docker credential is not a Docker-enforced read-only grant or OS isolation.

The independent observer boundary does not claim to confine existing authorized native shell/file access. The
integration must not read pane logs into a prompt/transcript, install automatic Herdr pane scraping, or publish
private captures. Closing an observer cannot cancel Pi, children or containers. Runtime state remains under
ignored `var/`, never `.runs/`; run evidence belongs under the TASK scratch directory.
