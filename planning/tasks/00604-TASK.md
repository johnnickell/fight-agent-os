# Isolate the bundled Git-detection test from the current directory

## Outcome

Remove the ambient-checkout assumption that failed the bundled subagent engine's check during the earlier
frontend planning build. The positive environment-detection test owns its temporary Git repository and
remains valid when the suite runs outside Git discovery. John requested this separate fix and PR on 2026-11-17
and selected the clean main checkout on a new branch from develop.

## Scope

- Replace the first `test/env.test.ts` case's `process.cwd()` dependency with a freshly initialized temporary
  repository; remove it in `finally`, including on assertion or initialization failure.
- Retain actual `detectEnv` Git/platform assertions and the existing committed-branch and non-repository cases.
- Record the maintained test delta in the bundled component README.
- Exclude production detection changes, skipped/deleted tests, build-gate changes, dependency upgrades and
  frontend planning work from PR #283. No new product-suite test of test tooling is introduced.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Run environment detection checks outside a checkout | Owning Vitest command and fixture-local Git init | Existing detectEnv Git/platform results | N/A — test-only change | Temporary repository created and removed; runner directory need not be a repository |

## Validation and permissions

No application permissions, HTTP contracts, database state or runtime behavior change. Git initialization is
limited to the test-owned temporary path. Cleanup retains the existing fixture convention and never removes
the caller's working directory. Use the repository runtime wrapper and installed component tooling.

ambient-directory defect; it does not establish every cause of the earlier full-build failure.

three environment tests passed. Both runs removed their disposable consumer and test repositories afterward.
