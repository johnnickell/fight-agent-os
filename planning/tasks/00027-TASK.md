# Establish the typed shared API client boundary

## Outcome

One shared browser API client and a representative feature service safely map the documented `/api/v1` JSend/snake_case transport into camelCase client models, validate responses at runtime, normalize common failures and cancellation, and accept access credentials only through a memory-owned seam.

## Scope

- In scope: Shared transport client; base/runtime configuration; headers/correlation and same-origin credentials policy; memory access-token provider seam; request cancellation; JSON/JSend/status parsing; runtime response decoding; normalized transport/validation/authentication/authorization/conflict/not-found/system/network/cancellation outcomes; explicit snake_case/camelCase feature mapping; deterministic tests against TASK-00021's representative contract.
- Out of scope: Refresh implementation, cookie inspection, current-principal cache, product endpoints/services, React query/cache library adoption beyond demonstrated need, retries, offline queue, CORS, generated clients for unimplemented operations, and server changes.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Call representative operation | Feature service maps one typed client interaction | Feature service maps one typed read | Server events are not recreated client-side | Shared transport sends documented request and mapper returns safe camelCase model |
| Reject malformed response | N/A — client boundary validation | Inspect status/content type/JSend/schema | N/A — no domain event | Invalid response becomes a normalized safe system/protocol failure |
| Cancel superseded work | N/A — client transport control | Observe cancellation/abort state | Client-only cancellation signal | Obsolete response cannot overwrite newer UI state and is not shown as server failure |
| Send access authority | N/A — transport concern | Read current access token from memory provider only | N/A — no domain event | Bearer header is added when explicitly required; token is never persisted/logged |

## Validation and permissions

The shared client owns URL/base configuration, JSON headers, same-origin cookie mode where required, correlation handling, AbortSignal/cancellation, response content/status/JSend parsing, and common failure normalization. Feature services own endpoint paths, request/response codecs, snake_case-to-camelCase mapping, and endpoint-specific semantics. Components do not parse transport objects.

Treat network content as untrusted. Runtime validation rejects malformed JSON, non-JSON success, wrong JSend status/envelope, missing/extra unsafe fields according to explicit codec policy, wrong scalar/container types, and status/envelope contradictions. Do not hydrate arbitrary class instances from server objects.

Access tokens are supplied only by an injected memory capability and sent as Bearer when requested. The client cannot read refresh cookies and cannot expose them in models. Redact Authorization, Cookie, CSRF, credentials, response bodies, and sensitive URLs from diagnostics. No credential, principal snapshot, or response cache enters browser persistence.

Cancellation is a distinct normalized outcome and stale responses cannot update the consuming state. Do not add automatic authentication retry/refresh loops in this foundation.

## Acceptance criteria

- [ ] One shared client owns common transport/configuration/headers/correlation/credentials/cancellation/failure behavior.
- [ ] A representative feature service owns endpoint-specific typed codecs and explicit snake_case-to-camelCase mapping.
- [ ] Runtime validation safely rejects malformed JSON, content type, JSend envelope/status, field shape, and scalar/container types.
- [ ] Validation, authentication, authorization, conflict, not-found, generic server, protocol, network, and cancellation outcomes remain distinguishable without arbitrary server messages.
- [ ] Access credentials come only from a memory provider and are attached only to explicitly protected operations.
- [ ] Refresh cookies remain JavaScript-inaccessible and absent from request/response models, logs, errors, storage, and test snapshots.
- [ ] Abort/cancellation works, is not rendered as ordinary failure, and prevents stale-result state overwrite.
- [ ] Diagnostics redact credentials, sensitive headers/bodies/URLs, and internal transport details.
- [ ] No product endpoint, refresh loop, persistent response cache, or generated unimplemented client is introduced.
- [ ] Focused client/service tests and `./bin/build` pass with fresh evidence.
