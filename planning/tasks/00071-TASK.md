# Prepare develop documentation for public visibility

## Outcome

The `develop` branch no longer publishes machine-specific user-home paths or describes Fight Agent OS as a private
repository, while preserving historical provenance and intentional references to private data, installations,
networks, and other repositories.

## Scope

- In scope: Redact tracked absolute user-home paths on `develop`; remove current-repository private-visibility claims from public documentation, project instructions, foundation wording, and package metadata; refresh generated planning views.
- Out of scope: Git history rewriting; the `planning/complete-agent-os-vision` and other open branches; references to the separate private Factory repository; private application data, deployment, network, installation, cache, and implementation semantics; changing GitHub visibility or settings.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Read the public project | N/A — documentation chore | Inspect current project status, guidance, metadata, and research citations | N/A — no domain event | Readers receive visibility-neutral current documentation without machine-specific user paths |

## Validation and permissions

Only tracked documentation, package metadata, and this standalone planning record may change. Generic relative paths
and intentional security/privacy terminology remain intact. No product runtime permission applies, and this TASK
does not authorize Git history rewriting, GitHub visibility changes, open-branch mutation, push, or publication.

## Acceptance criteria

- [x] Tracked `develop` content contains no absolute `/home/<user>` or `/Users/<user>` path.
- [x] Current project documentation, instructions, and package metadata contain no private-visibility claim.
- [x] Historical provenance and intentional references to private data, installations, networks, caches, implementation state, and the separate Factory repository remain accurate.
- [x] Generated planning views are current, focused scans and `git diff --check` pass, and `./bin/build` passes with fresh evidence.

## Verification and evidence
