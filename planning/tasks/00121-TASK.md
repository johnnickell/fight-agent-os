# Authorize user role assignments and removals

## Outcome

Each entry adapter admits the authenticated actor's exact permission and target scope, then dispatches package assignment/removal through configured buses. Owned user-state, self-lockout and last-admin business safeguards remain reusable Domain/Application policy, coordinated by registered handlers with required atomic audit, not duplicate transport authorization.

## Scope

- In scope: `PUT`/`DELETE /api/v1/users/{userId}/roles/{roleId}` FQCN Actions; `MANAGE_USER_ROLES` plus `ASSIGN_SUPER_ADMIN` for managed elevated assignment or `REMOVE_SUPER_ADMIN` for managed elevated removal; explicit separate confirmation/audit for both; package `AssignRoleToUser`/`RemoveRoleFromUser`; actor/target/role/intrinsic checks, safe OpenAPI/View and principal invalidation.
- Out of scope: Managed-role mutation, arbitrary permission writes, custom-role tier delegation, global role-name bypass, bootstrap replacement, self-promotion, invitation's separate `INVITE_USERS` flow, explicit Project access grant/revoke and multi-workspace assignment.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Assign role | Package `AssignRoleToUser` through configured CommandBus after entry admission | Resolve actor/user/role/permission/current administrator state | Package assignment event and durable safe audit | Authorized current association commits once; elevation needs both permissions and confirmation |
| Remove role | Package `RemoveRoleFromUser` through configured CommandBus after entry admission | Resolve actor/user/role/last-admin state | Package removal event and durable safe audit | Only safe removal commits; final Super Admin remains reachable |

## Validation and permissions

HTTP route metadata gates `MANAGE_USER_ROLES` before Action instantiation. Every actual entry adapter authenticates its caller, identifies the exact target Role and admits current permission/target scope. Assigning `ROLE_SUPER_ADMIN` additionally requires `ASSIGN_SUPER_ADMIN` and distinct confirmation; removal requires `REMOVE_SUPER_ADMIN` and distinct confirmation. Under the [canonical contract](../../docs/engineering/STANDARDS.md#entry-admission-and-authorization-timing), do not repeat blanket permission admission in Application or lock ordinary commit against permission revocation. Self-change/last-effective-administrator and user/Role-state consistency stay with their business owners, enforced in registered handler coordination with required audit on the shared generic transaction. Qualify package participation; no nested consumer transaction or transaction decorator substitutes for explicit atomic coordination. No ordinary permission or role name alone authorizes stripping global authority. Require TASK-00126's qualified authorization, protected-tier and persistence contracts before adopting the package operations and their intrinsic invariants; use its exact tested release and source commit, not a prospective version target. Never rely on tier label or an HTTP-only check to protect console/Agent callers. Bound IDs and stale revision, audit actor/target/action/outcome without secret or permission snapshots.

## Acceptance criteria

- [ ] Ordinary assignment/removal requires `MANAGE_USER_ROLES`; elevated assignment requires it **and** `ASSIGN_SUPER_ADMIN`, while elevated removal requires it **and** `REMOVE_SUPER_ADMIN`, each with distinct confirmation and durable audit.
- [ ] Self-escalation, self-lockout, removal of last effective Super Admin, stale/invalid target and races fail closed.
- [ ] Every exposed entry proves actor authentication, permission/target admission and configured bus dispatch; the raw bus stays trusted internal infrastructure. Owned last-admin/user-state invariants and required audit remain enforced without duplicate Application admission.
- [ ] HTTP FQCN Actions/Responses/OpenAPI expose no internal authority and refetch current principal after mutation.
- [ ] Focused role/state/permission/concurrency/PostgreSQL/HTTP/security checks and `./bin/build` pass with warnings disclosed.
