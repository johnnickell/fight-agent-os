# Authorize user role assignments and removals

## Outcome

Each entry adapter authenticates the actor and checks the exact permission and target before dispatching an allowed package role change through the configured bus. The app never removes the managed Super Admin role; that is database maintenance only. Each entry refuses role assignment and removal for pending, disabled or deleted targets and for the signed-in user targeting themselves, at admission only. Registered handlers preserve package conflicting-write checks and required atomic audit without repeating those admission checks at commit.

## Scope

- In scope: `PUT`/`DELETE /api/v1/users/{userId}/roles/{roleId}` FQCN Actions; `MANAGE_USER_ROLES` for allowed changes; additional `ASSIGN_SUPER_ADMIN` and explicit confirmation for managed Super Admin assignment; rejection of managed Super Admin removal before dispatch; package commands, required audit, safe OpenAPI/View and principal invalidation.
- Out of scope: Managed-role mutation, arbitrary permission writes, custom-role tier delegation, global role-name bypass, bootstrap replacement, self-promotion, invitation's separate `INVITE_USERS` flow, explicit Project access grant/revoke and multi-workspace assignment.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Assign role | Package `AssignRoleToUser` through configured CommandBus after entry admission | Resolve actor/user/role/permission/current administrator state | Package assignment event and durable safe audit | Authorized current association commits once; elevation needs both permissions and confirmation |
| Remove role | Package `RemoveRoleFromUser` through configured CommandBus only for allowed roles | Resolve actor, target and authoritative Role identity | Package removal event and durable safe audit for a committed change | Managed Super Admin removal is refused before dispatch |

## Validation and permissions

`#[RequiresPermission('MANAGE_USER_ROLES')]` gates both HTTP Actions before instantiation. Before dispatch, each Action refuses both assignment and removal for pending, disabled or deleted targets and for the signed-in user targeting themselves. These target-state and self-target checks are admission-time only, with no commit-time recheck requirement. Any other exposed entry must authenticate its caller and enforce the same admission rules. Every actual entry adapter authenticates its caller, identifies the exact target Role and admits current permission/target scope. Assigning `ROLE_SUPER_ADMIN` additionally requires `ASSIGN_SUPER_ADMIN` and distinct confirmation. No application permission, including `REMOVE_SUPER_ADMIN` if still present in the catalog, authorizes removing that Role. Under the [canonical contract](../../docs/engineering/STANDARDS.md#entry-admission-and-authorization-timing), do not repeat blanket permission admission in Application or lock ordinary commit against permission revocation. The owner-approved role admission amendment below governs target-state and self-target checks. Preserve the package's conflicting-write checks and required audit coordinated by registered handlers on the shared generic transaction; do not duplicate entry admission in Application. No last-admin count or cross-user serialization is required for role removal because managed Super Admin removal is prohibited. Qualify package participation; no nested consumer transaction or transaction decorator substitutes for explicit atomic coordination. No ordinary permission or role name alone authorizes stripping global authority. Require TASK-00126's qualified authorization, protected-tier and persistence contracts before adopting the package operations and their intrinsic invariants; use its exact tested release and source commit, not a prospective version target. Never rely on tier label or an HTTP-only check to protect console/Agent callers. Validate IDs and reject stale or invalid targets and conflicting writes. Do not assume this requires a displayed whole-account revision or rejecting unrelated account changes. Audit actor, target, action and outcome without secrets or permission snapshots.
