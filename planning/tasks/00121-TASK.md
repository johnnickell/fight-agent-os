# Authorize user role assignments and removals

## Outcome

An Agent OS Application service enforces authoritative actor permission, target role, user state and last-admin safeguards on every role change, then delegates actual assignment/removal to Fight Access Control without depending on duplicate package handler permission checks.

## Scope

- In scope: `PUT`/`DELETE /api/v1/users/{userId}/roles/{roleId}` FQCN Actions; `MANAGE_USER_ROLES` plus `ASSIGN_SUPER_ADMIN` for managed elevated assignment or `REMOVE_SUPER_ADMIN` for managed elevated removal; explicit separate confirmation/audit for both; package `AssignRoleToUser`/`RemoveRoleFromUser`; actor/target/role/intrinsic checks, safe OpenAPI/View and principal invalidation.
- Out of scope: Managed-role mutation, arbitrary permission writes, custom-role tier delegation, global role-name bypass, bootstrap replacement, self-promotion, invitation's separate `INVITE_USERS` flow and workspace/repository-scoped admin without separate policy.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Assign role | Package `AssignRoleToUser` through checked service | Resolve actor/user/role/permission/current administrator state | Package assignment event and durable safe audit | Authorized current association commits once; elevation needs both permissions and confirmation |
| Remove role | Package `RemoveRoleFromUser` through checked service | Resolve actor/user/role/last-admin state | Package removal event and durable safe audit | Only safe removal commits; final Super Admin remains reachable |

## Validation and permissions

HTTP route metadata gates `MANAGE_USER_ROLES` before Action instantiation. Application independently checks the same current actor permission on every entry, identifies exact managed target role and, for assignment of `ROLE_SUPER_ADMIN`, also requires `ASSIGN_SUPER_ADMIN` and distinct confirmation; removal of that managed role instead requires `REMOVE_SUPER_ADMIN`, distinct confirmation, and self-change/last-effective-administrator protection. No ordinary permission or role name alone authorizes stripping global authority. Verify v0.4.0 release contracts in TASK-00126 before implementing or wiring package handler authorization. Never rely on tier label or an HTTP-only check to protect console/Agent callers. Bound IDs and stale revision, audit actor/target/action/outcome without secret or permission snapshots.

## Acceptance criteria

- [ ] Ordinary assignment/removal requires `MANAGE_USER_ROLES`; elevated assignment requires it **and** `ASSIGN_SUPER_ADMIN`, while elevated removal requires it **and** `REMOVE_SUPER_ADMIN`, each with distinct confirmation and durable audit.
- [ ] Self-escalation, self-lockout, removal of last effective Super Admin, stale/invalid target and races fail closed.
- [ ] Agent OS Application enforces actor/target authorization regardless of package handler permission checks; no raw package caller bypass from exposed entry points.
- [ ] HTTP FQCN Actions/Responses/OpenAPI expose no internal authority and refetch current principal after mutation.
- [ ] Focused role/state/permission/concurrency/PostgreSQL/HTTP/security checks and `./bin/build` pass with warnings disclosed.
