# Move managed authority to JSON catalogs and reconcile approved defaults

## Outcome

Deliver [TICKET-00139](../tickets/00139-TICKET.md)'s single JSON-managed authority catalog through Fight's
existing idempotent reconciliation path in one independently reviewable PR. Operators can preview/apply the
complete desired policy, ordinary Users retain their approved baseline and Super Admin receives all current
and future managed Permissions. Replace the PHP catalog rather than add a second seeding system.

## Scope

In scope:

- Make `database/seeds/permissions.json` and `database/seeds/roles.json` the single authoritative managed
  definition/membership catalog. Preserve existing stable IDs, names, tiers and complete application references.
  Remove superseded PHP catalog literals and redundant paths after verifying surviving consumers.
- Load and validate the catalogs into the supported typed package policy. Retain explicit trusted-operator
  `./bin/managed-policy preview --internal` and `./bin/managed-policy apply --internal` through configured buses
  and the existing package reconciler. Do not introduce a parallel synchronizer or automatic startup loading.
- Preserve `ROLE_USER` membership exactly as `VIEW_DASHBOARD`, `READ_OWN_SESSIONS`, `DELETE_OWN_SESSIONS`.
  Give `ROLE_SUPER_ADMIN` every current and subsequently added managed Permission without a duplicate manually
  expanded Super Admin list. Apply changes through reconciliation, not a role-name authorization bypass.
- Preserve idempotency, managed drift correction, stable identity/rename behavior, collision rejection,
  custom/unmanaged authority protection, protected-tier/reference/removal fences and existing transactional and
  post-commit uncertainty semantics.
- Update surviving policy consumers, applicable current documentation and unfinished forward requirements to
  reflect the JSON source and approved defaults. Preserve historical acceptance/publication evidence and
  unrelated requirements, priority, dependencies and qualification holds.
- Preserve ordinary HTTP/Console invitation assignment of `ROLE_USER`, complete-policy admission and existing
  elevated/bootstrap semantics. Invitation, assignment and audit retain their disclosed separate commits and
  partial-failure boundaries; this change does not make issuance atomic.

Out of scope: TASK-00590's URL cutover, wider Permission audit, new User defaults, User backfill, invitation
redesign, altered elevated/bootstrap policy, new public endpoints, generic seeding framework, automatic startup
reconciliation, database resets, removal of custom authority and production deployment. Omphalos is representation
evidence, not an instruction to import its synchronizer, unrelated catalogs or workflow.

## Validation and permissions

Validate catalog structure, typed identities, names/tiers, duplicate names/IDs, membership references and the
approved Role policies before unsafe effects. Missing, unreadable, malformed or incomplete catalogs must fail
safely, not become an empty replacement policy or silent authority change. Preserve complete application
references and reference/removal fences; catalog absence alone is not permission to retire referenced authority.

Preserve custom/unmanaged definitions and assignments outside managed convergence. Reject name/identity
collisions rather than adopting records or replacing stable IDs. Do not change protected delegation restrictions
or infer ordinary User/custom/Agent membership from Permission definition or tier. The all-managed-Permissions
Super Admin default is the explicit approved amendment to the former separate-membership approval rule in the
[managed authority contract](../../docs/engineering/MANAGED_POLICY.md#permission-eligibility-is-not-assignment).
It does not waive operation/target admission or introduce role-name authorization.

Keep the trusted local operator boundary: `--internal` acknowledges machine/database authority, not end-user
authentication. No HTTP exposure or automatic boot effect. Preview remains advisory; apply re-reads actual state
inside the existing supported canonical transaction. Preserve rollback on transactional failure and disclose
post-commit event/output uncertainty; use fresh preview to establish actual state rather than infer rollback.
Do not add a durable event/audit protocol solely for the catalog representation.

Qualify the available tagged package contracts and actual consumers at implementation under the shared
architecture contract and [ADR 0001](../adr/0001-application-ownership-and-orchestration.md) as amended. Reuse
public package Commands/Queries and configured shared buses. Do not patch vendor, copy handlers, call private
handlers or build a forwarding compatibility graph. A missing guarantee holds the affected behavior with concrete
evidence; a source example or historical receipt is not fresh supplier/runtime qualification.
