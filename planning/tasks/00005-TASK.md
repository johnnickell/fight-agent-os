# Establish and prove disposable product-design exploration

## Outcome

The repository has a concise project-local `design` skill and shared design standards that turn one bounded UI, workflow, or visual-language question into sourced disposable evidence and a production handoff without changing production UI. A bounded, explicitly non-authoritative demonstration proves the workflow and its safety boundaries.

## Scope

- In scope: Add `.pi/skills/design/SKILL.md`; add concise project-owned design standards that specialize the existing `prototype` lifecycle; cover context inspection, bounded briefs, provenance, meaningful alternatives, fake data, responsive and interaction states, accessibility observations, evidence limits, verdicts, and production handoff; support a Bootswatch-like visual-language specimen and semantic-token-to-Bootstrap recommendations; demonstrate the workflow beneath `.runs/prototypes/<scope>/`.
- Out of scope: Production React/components/assets, durable prototype source, final design acceptance, planning creation/decomposition, hosted design-agent dependencies, wholesale installation of external skill packs, private/production data, and promotion of prototype code into the application.

|---|---|---|---|---|
| Frame a bounded design question | N/A — design workflow coordinates research and prototype tools | Read approved requirements, architecture, existing UI/assets, constraints, prior evidence, and source licenses | N/A — no application domain event | Brief defines audience, job, journeys, states, fidelity, constraints, alternatives, decision, and evidence needed |
| Explore meaningful alternatives | N/A — disposable file, browser, rendering, and capture operations | Inspect cited references and rendered alternatives | N/A — no application domain event | Structurally or behaviorally distinct fake-data artifacts and comparison notes exist only under the prototype scope |

## Validation and permissions

Require a bounded question, explicit fidelity, safe fake or sanitized data, source/asset/license provenance, meaningful alternatives unless justified inapplicable, and separation among observed evidence, automated results, manual observations, subjective preference, and unverified claims. Reject credentials, private production data, unsafe or repository-wide viewers, mutable/unpinned tooling without disclosure and approval, inaccessible-by-assertion claims, and attempts to write production or authoritative planning files without separate authorization.

All prototype source, dependencies, assets, captures, check output, process records, and handoff artifacts remain beneath `.runs/prototypes/<scope>/`. Any viewer binds only to loopback, serves only the prototype directory, uses a selected free port, records its PID, and is stopped after capture. Do not fetch mutable scripts/assets, serve repository root, or give untrusted prototype content access to repository files. Tool/browser versions must be pinned or explicitly controlled and disclosed.

No application permission model, commands, queries, or domain events apply. Filesystem, browser, network, and process effects are restricted to the authorized disposable scope. Project requirements and human decisions remain authoritative; references and external tools are evidence or inspiration only.
