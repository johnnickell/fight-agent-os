# Inspect review-to-merge history in the Dashboard

## Outcome

Extend the existing sessions-first Dashboard so a human can inspect the complete managed Review, revision,
acceptance, QA, publication and merge/reconciliation journey without browser inspection becoming a delivery gate.

## Scope

- In scope: Rebuildable later-phase projections, bounded authorized queries and independently loaded Summary,
  Changes, Activity and Evidence extensions; existing human intervention controls and truthful delivery history.
- Out of scope: New shell/theme, second Workflow/event/evidence store, execution transcript viewer, alternate
  acceptance or eligibility policy, automatic effects on reconnect and forecast computation owned by TASK-00320.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Inspect managed delivery | N/A — bounded authorized reads | Review/QA subjects, criteria/findings, cycles, acceptance/bridges, checks, PR and maintenance | N/A — reads never grant authority | Independently paginated current/history panels with explicit partial states |
| Inspect exact changes/evidence | N/A — private bounded reads | Immutable base…head manifest/patch, Artifact digests and applicability | N/A | Safe lazy text rendering or explicit binary/oversized/unavailable paths |
| Intervene where authorized | Existing semantic pause/halt/cancel/annotate/continuation/takeover operations | Current authority, expected revisions, consequences and original result | Existing owning transition/annotation facts only | Actual owner-controlled operation or hold, never client-side acceptance |

## Validation and permissions

Consume TICKET-00096's history/query/live-projection and TICKET-00097's Dashboard foundations. Extend their same
owned channels, safe Views and pagination, keeping authority separate from duplicated/delayed/missing observations.
Show Review attempt/session, immutable subject and criteria, stable findings/dispositions, requested/effective/
consumed/remaining revision limits, acceptance/invalidation/bridges, QA scenarios/dispositions, fresh versus
historical final checks, publication intent/result, canonical PR/human action, merge and cleanup/maintenance.
Keep Planning done, PR handoff and human merge visibly distinct; never infer success from missing reports.

Render bounded syntax-highlighted exact base…head patches with every changed file discoverable. Lazily load file
bodies, route binary/oversized material to authorized digest-verified private Artifacts and expose unavailable or
purged content honestly. Mark live worktree diffs as mutable observations, never reviewed evidence. Treat content
as untrusted and inert; do not expose prompts, thinking, transcripts, credentials or private transport internals.

Each Summary/Changes/Activity/Evidence section retains independent loading, empty, denied, stale, partial,
interrupted, cancelled, failed, purged and unavailable states and independent pagination. A failed query cannot
erase the remaining dossier. Preserve whole-result server search and stable cursors; no silent historical caps.
Current access applies to subscriptions, reloads, metadata and bytes, not just cached UI or private topic names.

Reconnect reloads durable queries before live updates. Viewing, refreshing, reconnecting or opening a deep link
never accepts, retries, publishes or reconciles. Human controls invoke existing exact semantic operations with
expected revisions and current authority; explain scope, limits and original uncertain outcome before any retry.
Browser code inspection/intervention remains optional; terminal/application publication does not wait on this UI.
Use committed rebuildable projection updates under existing infrastructure, never observations as transition input.
