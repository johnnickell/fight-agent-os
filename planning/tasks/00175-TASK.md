# Run qualified repository analysis for judgments

## Outcome

A qualified Pi 1.1.0 caller can request an explicitly supported repository analyzer through the authenticated
MCP composition path, then obtain typed judgments over its bounded authorized observations. Actual execution
constraints, source identity and analyzer receipts establish what ran; the label static analysis is not a safety
or correctness guarantee.

## Scope

- Add a complete repository-analysis capability to [TASK-00174](00174-TASK.md), reusing its caller propagation,
  per-call authority, guarded effect admission, budgets, receipts and shared evaluator. Consume actual package
  authority directly under ADR 0001; do not create another analyzer-specific identity or permissions framework.
- Accept a protected analyzer-profile identifier, a permitted repository/checkout target and revision, schema-
  constrained options and typed questions/preset. Resolve exact tool/version, executable/script digest, arguments,
  working directory, input roots, configuration and plugin/bootstrap/dependency-loading behavior before dispatch.
  Arbitrary executable paths, command strings or repository-authored profile changes are not supported inputs.
- Deliver at least one useful maintained repository analyzer with a specifically qualified profile, using the
  owning repository wrapper where applicable. Qualify candidate behavior rather than assuming the wrapper, a
  package script or analyzer name makes it safe. Unsupported analyzers remain unavailable; no automatic install,
  configuration rewrite, dependency download or execution of arbitrary repository bootstrap code.
- Inspect potential code execution from configuration/plugins/autoloading, child processes, cache/temp writes,
  filesystem traversal, credential/environment inheritance and network access. Define permitted effects and enforce
  the profile's path, process, environment, network and resource constraints through qualified controls. If required
  containment is absent, block that profile instead of substituting a prompt, safe-looking arguments or Jev score.
- Apply the existing deterministic and semantic guard policies to every covered execution effect, including nested
  routes; refuse unqualified bypasses. Add only narrowly bounded supported analyzer forms within the protected
  profile's intended policy, never a generic interpreter allow entry or relaxation of the sandbox owner's scope.
  If a candidate needs stronger isolation, record that concrete missing capability before enabling the candidate.
- Bound analyzer inputs, visited paths, runtime, process/resource use, concurrency, output and artifact sizes under
  a finite operator-owned profile plus the whole-composition budgets. Use only designated temporary/artifact paths;
  source/configuration writes and arbitrary network access are forbidden unless part of an explicitly permitted
  profile effect. Temporary writes do not authorize modifying repository content or operator settings.
- Bind observations to actual repository/checkout identity and observed source revision/content digest, analyzer
  version/configuration/plugin revisions, arguments, timestamps and execution receipt. Detect relevant changes
  during analysis and mark the evidence stale/incomplete rather than claiming one coherent source revision.
- Keep execution status, tool diagnostics and Jev classification distinct. An analyzer finding exit, crash, timeout,
  cancellation, malformed output and incomplete coverage retain their own meanings; a typed score cannot convert
  any of them to a passed build or completed verification. Parse supported output with bounded trusted adapters.
- Minimize/redact observations and separately authorize provider disclosure before evaluation. Return compact typed
  results, assessed/excluded/incomplete scope and verified source/receipt references. Raw analyzer output or exact
  source access uses its separately authorized owning evidence path; no full log dump enters the main context.
- Preserve TASK-00174's cancellation, stale-generation and uncertain-outcome behavior. Cleanup is limited to owned
  artifacts/processes and qualified cancellation controls; do not kill unrelated processes or rerun analysis after
  ambiguity solely to obtain a preferred answer. Historical receipts remain marked historical.
- Exclude running-application inspection, Agent-controlled SQL, production deployment/provisioning, permission
  grants, generalized shell execution and automatic changes to source or analysis configuration. Existing static
  file judgments remain usable independently; upcoming quality/test-usefulness assessment need not wait for SQL.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Analyze a repository | Invoke one qualified analyzer profile with constrained arguments | Current repository authority, source identity and profile readiness | Analysis started/completed/partial/failed observations | Only qualified process/read/temp/network effects within limits |
| Judge analysis evidence | Submit permitted minimized observations to shared evaluator | Typed result, coverage and actual execution/source provenance | Judgment completed/failed observation | Bounded provider usage and authorized metadata |
| Inspect exact findings | Existing separately authorized evidence read | Receipt/artifact/source reference availability and revision | Owning evidence access observations where applicable | Minimal permitted exact evidence, no automatic rerun |
| Stop an analysis | Cancel the owned invocation | Process/receipt/generation state | Cancelled/uncertain/cleanup observations | Qualified bounded cleanup of owned resources only |

## Validation and permissions

Recheck actual caller, repository scope and profile authority immediately before execution and before evidence
disclosure. Treat repository configuration and analyzer output as untrusted data/code inputs. Profile qualification
must establish their permitted behavior, not merely trust an extension or filename. The guard cannot turn an
unsupported process/isolation guarantee into a supported one. Deterministic controls, current permission and
separate provider egress all remain required. No analysis receipt grants production or SQL access.

## Acceptance criteria

- [ ] A real Pi 1.1.0 inquiry runs at least one useful qualified maintained analyzer through TASK-00174 and returns
  typed findings with actual tool/configuration/source identity and authorized references.
- [ ] Unapproved arguments, configuration/plugins/bootstrap execution, changed profile revisions, escaped paths and
  unintended environment/network/process effects cannot bypass the qualified constraints or nested guard policy.
- [ ] Finite runtime/resource/concurrency/input/output bounds hold; source/configuration remains protected and
  cancellation/cleanup affects only owned resources. Unsupported profiles are explicitly unavailable.
- [ ] Actual execution outcomes and coverage remain distinct from Jev classifications; failures, partial output and
  source drift cannot appear as a completed analysis, passing gate or coherent revision.
- [ ] Caller revocation and denied provider disclosure prevent prohibited execution or disclosure; ordinary result
  metadata contains no raw source, secret or full analyzer log.
- [ ] Representative inquiries demonstrate useful evidence with measured coverage, missed/unsupported conclusions,
  main-context size, available total cost and latency; historical results are never represented as fresh runs.

## Verification and evidence

Test owned profile admission, invocation/result handling, source provenance, authorization, cancellation and limits.
Qualify the actual analyzer/configuration/plugin/process/filesystem/network boundary directly with its owning tools
in a controlled environment; do not add product tests that prove static-analysis tools or tests detect seeded faults.
Record unsupported profiles honestly. Run applicable focused backend checks, `./bin/harness-check` and canonical
`./bin/build`; retain direct exits, tested-content identity, exact analyzer/runtime/profile and redacted execution/
judgment evidence under `.runs/tasks/TASK-00175/`. A synthetic adapter response is not live analyzer qualification.
