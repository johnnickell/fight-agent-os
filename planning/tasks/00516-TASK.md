# Resume Land to reconcile ended merge handoffs

## Outcome

Let an explicitly resumed Land workflow safely reconcile a verified merge or closed-unmerged handoff, even
when the original worktree has been removed. Preserve acceptance history, make non-delivery and uncertainty
explicit, and avoid duplicate corrective publication or repeated no-op commits. This completes the Land-owned
recovery path in [TICKET-00118](../tickets/00118-TICKET.md).

## Scope

- Extend the shared Land entry point and owning standards with a bounded ended-handoff intake and
  correction/publication route that consumes the normal synchronization contract from TASK-00515.
- Qualify exact subject/PR identity and live state using existing capabilities. Distinguish verified merged,
  closed-unmerged and unverifiable outcomes; do not infer state from `done`, old prose or a PR link.
- Document safe resumption after original-worktree cleanup, including selected checkout, owned correction
  branch, existing corrective PR and publication-authority checks. Never assume the original merged PR can
  receive another update or that a human checkout may be repurposed.
- Reconcile current handoffs and generated views without rewriting acceptance evidence, altering unrelated
  priorities or reopening implementation solely because delivery ended without merge.
- Recover interrupted correction by inspecting actual local/remote state; reuse an existing correction and
  leave already-consistent unchanged state without another commit.
- Out of scope: validator/live-routing implementation (TICKET-00119), ten-project rollout (TICKET-00120),
  implementation repair, automatic reopen/replacement of the original PR, merge/approval, deployment/release,
  archive, remote-branch deletion and managed database Workflow changes.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Reconcile a verified merge | Explicit Land resume; authorized correction and view refresh | Exact PR identity/state, current handoffs and preserved acceptance provenance | Local reconciliation receipt only | Ended merge instruction is retired; current documents reflect observed merge without claiming agent merge authority |
| Reconcile closure without merge | Explicit Land resume | Verified closed-unmerged PR and unresolved owner decision | Local receipt only | False merge instruction removed, actual non-delivery retained and required human decision named |
| Recover after cleanup or interruption | Documented bounded Land recovery/publication path | Checkout/worktree ownership, current base, exact existing correction and remote publication result | Local recovery evidence only | Safe continuation or precise hold; no duplicate PR or destructive checkout reuse |
| Revisit unchanged consistent state | Explicit Land resume | Current sources, prior correction and live evidence as needed | Read-only outcome receipt | No new correction commit, acceptance mutation or publication retry |

These are local skill/tool operations, not new application Commands, Queries or Domain events. No database or
application permission change is needed.

## Validation and permissions

Follow [landing standards](../../docs/engineering/LANDING.md),
[handoff rules](../../docs/engineering/HANDOFFS.md),
[planning conventions](../CONVENTIONS.md) and
[Writing for Agents](../../.pi/skills/writing-for-agents/SKILL.md).
Routing may recommend this path but cannot invoke it or mutate records automatically. Land must verify current
subject, checkout and effect authority before correction or publication; missing authority produces an exact
human handoff. Preserve unrelated work and do not broaden cleanup permissions.

Stop on missing or contradictory identity/state evidence, unsafe checkout ownership, unresolved publication
outcome or a correction that changes requirements/implementation. Missing CLI/authentication or unavailable
hosting is unverified, never presumed merged or still open. Preserve historical independent reports and
accepted-candidate provenance; correction alone neither toggles acceptance nor supplies new independent review.
Existing gates still apply to any actual corrective candidate/publication.

The documented procedure must be finite and resumable: inspect before retry, reuse an already-published
correction, and do not recursively create metadata commits to certify the last metadata commit. Correcting a
closed-unmerged instruction does not authorize reopening or replacing that original PR.
