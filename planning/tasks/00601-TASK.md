# Adopt the shared React frontend in the Laravel skeleton

## Outcome

The actual `project-laravel` skeleton installs the released shared frontend and provides working, branded human
account and administration journeys with the same React/TypeScript/Bootstrap conventions. Applications can
select this skeleton independently of the other framework adoptions.

## Scope

- Consume TASK-00599's identified package through public exports and ordinary locked dependencies; no copied
  components, private Agent OS source imports or framework-specific fork of the library.
- Implement the documented account/admin HTTP, session/CSRF, safe error, current-principal, permission and
  persistence contracts using qualified Common/Access Control packages and this target's owning adapters.
  Include the server-side pagination/order/count contract; dependency installation alone does not implement endpoints.
  Keep search disabled for all Access Control features. Shared optional search supports application-specific
  queries owned by the receiving application; no Access Control search projection is part of adoption.
- Demonstrate distinct branding, host-owned navigation/page composition, Users/Roles/Permissions tables and
  restorable URL state. Preserve custom-role/managed-role boundaries, explicit confirmation and server refetch.
- Remove the existing Tailwind dependency, Vite Tailwind plugin, utility styles and obsolete callers after replacing their needed behavior with Bootstrap. Preserve Laravel/Vite integration where useful; do not replace the build tool merely for uniformity. Qualify the released Laravel permission adapter and actual middleware ordering.
- Keep shared UI in React/Bootstrap with no Tailwind. Replace any actually superseded local styling/controls
  and verify surviving callers; preserve unrelated application work, framework defaults and needed data.
- Document setup, independent local secrets, first administrator, captured local mail, API compatibility and
  real-mail/production gaps with the target's own instructions.
- Exclude other skeletons, product finance/social/home behavior, registry publication, automatic starter tags,
  production deployment, email-change and later Agent/HMAC features.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Use the branded skeleton | Qualified existing account/admin operations | Safe current account/list/detail reads | Existing canonical package events | Real authorized UI through the installed shared package |
| Extend a host page | Host-owned composition/operations | Host-owned reads | Host-owned only | Business UI can reuse conventions without editing library internals |
| Restore a list URL | None | Validated authorized dataset read | Table restoration/callback contract | Correct supported list state; Access Control search remains disabled |

## Validation and permissions

Follow the receiving repository's instructions and exact framework admission model. Prove server denial and
self/admin separation, protected managed Roles, safe grants, cookie/CSRF/session boundaries and truthful failures.
Use independent local secrets and no-store safe Views. URL parameters are untrusted; filtering and sorting
operate over the authorized dataset before pagination. Shared UI checks never replace server authorization.
