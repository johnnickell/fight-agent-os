# Hold protected work on Harness drift

## Outcome

Callers can inspect concise exact Harness drift and use one owned currentness guard to stop new protected work
when configuration or required authority is stale/unavailable. Unchanged reconnect is distinguishable from a
material change without silently replacing the original snapshot.

## Scope

- In scope: Deterministic bound/current comparison, safe reason/difference projection, expected-generation and
  reference/currentness guard composition for owning admission paths, with qualified writer participation.
- Out of scope: Another authorization/grant engine, mutation of historical snapshots, automatic continuation,
  repairing configuration, provider fallback, session launch or promises to recall already-admitted effects.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Inspect Harness currentness | N/A — read-only | Exact retained binding and fresh authorized package/profile/resource/origin/provider facts | N/A — comparison is derived | Concise current/stale/revoked/unavailable/unsupported result without mutation |
| Guard new protected work | Existing owning operation composes the currentness guard | Current reference/selection generations, Repository guard and relevant authority | Owning operation/hold facts only when committed by that owner | Reject before new effect when stale/denied; no cached allow |
| Check unchanged reconnect | Existing owning reconnect operation only if it changes state | Original binding and current qualified observations | No new snapshot fact from a read | Same binding remains applicable or explicit continuation/hold is required |
