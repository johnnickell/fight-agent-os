# Enforce backend behavior coverage and PostgreSQL verification

## Outcome

The backend test gate separately measures owned Domain/Application and Adapter code, enforces 100% line coverage for meaningful owned Domain/Application behavior with rejection paths, selects and enforces an evidence-based Adapter threshold, and runs guarded deterministic PostgreSQL integration/concurrency suites without replacing behavior assertions with percentages.

## Scope

- In scope: Pin/configure coverage driver/tooling; classify owned Domain/Application, Adapter, generated, and composition paths; measure representative suites; close legitimate uncovered behavior; enforce 100% meaningful Domain/Application line coverage; propose/record/accept an Adapter threshold from measured persistence/HTTP/composition/delivery code; focused unit/integration/concurrency suite wrappers; guarded PostgreSQL lifecycle; deterministic reports; seeded coverage/test/database failure evidence.
- Out of scope: Frontend checks, canonical build orchestration, testing vendor package behavior, percentage-only assertions, broad browser tests, network-dependent product tests, arbitrary mutation testing, and hiding difficult behavior through exclusions.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Verify owned behavior | N/A — test tooling | Execute unit/behavior tests and collect owned lines/branches where supported | Test doubles observe expected events | Behavior and rejection assertions pass; uncovered required lines fail policy |
| Verify adapters | N/A — test tooling | Exercise HTTP, composition, persistence, and delivery adapters | N/A beyond behavior under test | Separate Adapter report meets accepted evidence-based threshold |
| Verify PostgreSQL contracts | N/A — integration tooling | Migrate/reset guarded test DB and inspect transactions/constraints/races | Only committed test outcomes continue | Production-faithful mappings, rollback, locks, and races pass deterministically |
| Seed gate failure | N/A — isolated verification | Introduce uncovered/failed/DB-invalid fixture in disposable copy | N/A — no domain event | Relevant check fails clearly without mutating production source/database |

## Validation and permissions

Meaningful owned Domain/Application behavior requires 100% line coverage, including rejection and failure paths. A line counted as executed is insufficient where acceptance requires an outcome; tests assert returned state, exceptions, events, capability calls/non-calls, and transactional effects. Keep unit tests dominant and deterministic.

Measure Adapter code separately after representative persistence, HTTP, composition, and delivery code exists. Select a threshold based on the measured executable/testable surface, risk, and justified composition/generated exclusions; record human acceptance of the threshold. Do not lower it merely to match untested behavior. Report excluded files/lines explicitly.

PostgreSQL suites use TASK-00012's test-target guards, migrations, reset/isolation, real transactions, and separate connections for concurrency. Use deterministic clocks/IDs and bounded synchronization, not sleeps, retries masking races, shared residue, execution order, or network providers. SQLite is not persistence/concurrency evidence.

Do not repeat Fight Common/Access Control package suites. Owned tests cover application contracts and adapter responsibilities at package boundaries. Reports/caches/databases stay ignored/disposable. No runtime permission applies.

## Acceptance criteria

- [ ] Pinned coverage instrumentation produces stable separate owned Domain/Application and Adapter reports.
- [ ] Meaningful owned Domain/Application code reaches 100% line coverage with behavior assertions for success, rejection, and failure paths.
- [ ] Coverage exclusions are limited to generated or explicitly justified composition code and list exact files/lines/rationale.
- [ ] Representative Adapter coverage is measured separately and an evidence-based threshold is explicitly accepted and enforced.
- [ ] Unit tests remain dominant and do not duplicate upstream package conformance suites.
- [ ] Migration, mapping, constraint, rollback, locking, competing-write, HTTP, composition, and delivery behavior run in their appropriate suites.
- [ ] PostgreSQL integration uses explicit test mode, guarded targets, deterministic migration/reset, and separate connections where concurrency requires.
- [ ] Tests use deterministic clocks/IDs/synchronization and no timing sleeps, network dependence, order dependence, or shared-state residue.
- [ ] Isolated seeded uncovered behavior, assertion failure, and PostgreSQL contract violation each fail clearly.
- [ ] Focused tests/coverage and `./bin/build` pass with suite/test/assertion counts, coverage, durations, exclusions, and warnings recorded.

Seed failures in a disposable copy and exercise forbidden test-target guards without connecting to protected databases.
