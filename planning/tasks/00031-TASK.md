# Enforce backend behavior coverage and PostgreSQL verification

## Outcome

One coherent backend test execution runs every configured Unit, Integration, Functional, and PostgreSQL-backed suite exactly once, enforces 100% line coverage for meaningful owned behavior—including Adapter behavior where practical—and verifies guarded deterministic PostgreSQL integration/concurrency behavior without manufacturing tests for infrastructure or percentages.

## Scope

- In scope: Pin/configure coverage driver/tooling; configure one canonical PHPUnit invocation that includes every Unit, Integration, Functional, and PostgreSQL-backed suite exactly once and emits one coherent coverage report; classify meaningful owned behavior versus generated, configuration, composition, migration, and tooling paths; close legitimate uncovered behavior; enforce 100% line coverage for meaningful Domain/Application behavior and Adapter behavior where practical; non-canonical focused suite wrappers for iteration; guarded PostgreSQL lifecycle; deterministic reports.
- Out of scope: Frontend checks, canonical build orchestration, testing vendor package behavior, percentage-only assertions, broad browser tests, network-dependent product tests, arbitrary mutation testing, and hiding difficult behavior through exclusions.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Verify owned behavior | N/A — test tooling | Execute unit/behavior tests and collect owned lines/branches where supported | Test doubles observe expected events | Behavior and rejection assertions pass; uncovered required lines fail policy |
| Verify adapters | N/A — test tooling | Exercise owned HTTP, persistence, and delivery behavior | N/A beyond behavior under test | Separate Adapter report shows meaningful owned behavior coverage |
| Verify PostgreSQL contracts | N/A — integration tooling | Migrate/reset guarded test DB and inspect transactions/constraints/races | Only committed test outcomes continue | Production-faithful mappings, rollback, locks, and races pass deterministically |

## Validation and permissions

Meaningful owned Domain/Application behavior requires 100% line coverage, including rejection and failure paths. A line counted as executed is insufficient where acceptance requires an outcome; tests assert returned state, exceptions, events, capability calls/non-calls, and transactional effects. Keep unit tests dominant and deterministic.

The canonical backend phase runs one PHPUnit invocation across all configured Unit, Integration, Functional, and PostgreSQL-backed suites and collects coverage during that same execution. The coverage policy reads the resulting report; it must not run Unit first and then rerun Unit as part of an all-tests pass. Focused wrappers may run a selected suite during development but are not additional canonical phases.

Measure Adapter code separately after representative persistence, HTTP, and delivery behavior exists. Target 100% for meaningful Adapter behavior where practical, using mocks or integration collaborators when they prove owned outcomes. Exclude configuration wiring, migrations, generated code, wrappers, and tooling rather than manufacturing tests for percentages. Report excluded files/lines explicitly.

PostgreSQL suites use TASK-00012's test-target guards, migrations, reset/isolation, real transactions, and separate connections for concurrency. Use deterministic clocks/IDs and bounded synchronization, not sleeps, retries masking races, shared residue, execution order, or network providers. SQLite is not persistence/concurrency evidence.

Do not repeat Fight Common/Access Control package suites. Owned tests cover application contracts and adapter responsibilities at package boundaries. Reports/caches/databases stay ignored/disposable. No runtime permission applies.

## Acceptance criteria

- [ ] One canonical PHPUnit execution runs every configured Unit, Integration, Functional, and PostgreSQL-backed suite exactly once and produces the coverage evidence; no suite is repeated solely for coverage.
- [ ] Pinned coverage instrumentation produces stable separate owned Domain/Application and Adapter reports from that execution.
- [ ] Meaningful owned Domain/Application code reaches 100% line coverage with behavior assertions for success, rejection, and failure paths.
- [ ] Coverage exclusions are limited to generated or explicitly justified composition code and list exact files/lines/rationale.
- [ ] Meaningful Adapter behavior targets 100% line coverage where practical, with exact justified exclusions for non-behavioral configuration, composition, migration, generated, wrapper, and tooling code.
- [ ] Unit tests remain dominant, do not duplicate upstream package conformance suites, and are not rerun inside a second all-tests pass.
- [ ] Mapping, constraint, rollback, locking, competing-write, HTTP, and delivery behavior run in their appropriate suites without tests of migration or composition wiring.
- [ ] PostgreSQL integration uses explicit test mode, guarded targets, deterministic migration/reset, and separate connections where concurrency requires.
- [ ] Tests use deterministic clocks/IDs/synchronization and no timing sleeps, network dependence, order dependence, or shared-state residue.
- [ ] No test exists solely to cover infrastructure, configuration wiring, migrations, wrappers, test support, or the coverage mechanism itself.
- [ ] Focused tests/coverage and `./bin/build` pass with suite/test/assertion counts, coverage, durations, exclusions, and warnings recorded.
