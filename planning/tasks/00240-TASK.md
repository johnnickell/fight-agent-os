# Maintain original material and hold unsafe key retirement

## Outcome

Protected bounded maintenance rewraps, expires and cleans exact original delivery material, progresses past
unchanged/broken items and preserves permanent correlation/order. Operators can close new key references and
inspect complete accounting/retirement holds without mistaking a zero delivery count for physical deletion authority.

## Scope

- In scope: Actual package maintenance service and read-handler composition; current separate maintainer grants,
  original historical bindings, finite keyset scheduling/cursors, bounded rewrap, key-free expiry, outside-transaction
  inert-entry cleanup, safe reference accounting and closed-version retirement holds.
- Out of scope: Physical key destruction, a new key manager, credential reissuance, authentication-envelope
  maintenance policy, backup deletion, browser key/receipt controls, permanent history purge or another delivery queue.

|---|---|---|---|---|
| Maintain original protected copy | `AgentDeliveryMaintenanceService::rewrap/expire` with original key/destination/delivery ID and authorized target version where needed | Current maintainer, full expected operation, key admission/references and original retention | No new event; persisted package outcome is authoritative | Exact rewrap or key-free expiry, preserving identity/order/history and releasing only legitimate references |
| Remove terminal inert sink material | Package `cleanup` for exact original tuple | Terminal/window eligibility and current historical authority | No duplicate delivery/issuance event | Confirmed admission, outside-transaction exact removal/tombstone, then fresh fenced acknowledgement |
| Schedule bounded maintenance | One `ListAgentDeliveryMaintenance` page and at most one operation per selected item | Authorized material/cleanup work, exclusive delivery-ID cursor and policy | Safe scheduling observations only | Durable page progress; later wraparound includes concurrent inserts and retries |

## Validation and permissions

Maintenance is not delivery authority. Authenticate the real maintainer with explicit current scope/target and
original historical-destination grants, including obsolete or revoked operations; current slot ownership alone
cannot authorize predecessor cleanup. Rewrap needs target-key authority and open write admission. Read and global
accounting permissions remain separate, checked before and after selection/count and for each disclosed target.

Use package policy/transitions without copying them into scheduler code. Rewrap runs inside the bounded owning
transaction with real source/target key-use/reference fences; authenticate all issuance data, preserve bytes and
recorded policy/history, recheck time after crypto and CAS exact state. Slow work cannot extend original retention.
Expiry accesses no key/sink and never revokes the authentication credential. Transient target loss retains source
material; permanent source loss/corruption follows the package terminal outcome, never envelope fallback or rotation.

Cleanup requires irreversible terminal state, no retained copy and elapsed original retention plus finite grace;
a current delivered credential is never eligible. Separate confirmed admission precedes external exact-tuple
cleanup outside transactions. A current epoch/revision/deadline must still match for acknowledgement. Lost responses
or uncertain acknowledgements reconcile/repeat only the original tuple; delayed staging cannot recreate tombstoned
material or reset high-water. Already-admitted erasure targets only inert entries and cannot erase a successor.

Process one bounded keyset page per pass, persisting the last returned ID even for unchanged/unavailable items;
continue next pass and reset only after the final page. Include obsolete copies, not delivery discovery's current
reservation filter. Global reference counting spans all scopes/pages/dispositions/versions, including unknown
versions. Outages/malformed state are unavailable, never zero. Closing writes must survive restart and uncertain
writes must reconcile; separately account for admitted snapshots, active key uses, authentication envelopes,
backups/restoration and other key consumers. Physical retirement remains separately authorized owning-tool work,
not a consequence of this TASK. Routine authorized maintenance needs no new per-pass human approval.

## Acceptance criteria

- [ ] Actual rewrap preserves exact original bytes/binding/history and revision semantics through restart; races
  with completion, revocation, expiry and key closure produce one valid state without resurrecting removed material.
- [ ] Key-free expiry works for obsolete reservations using original pinned retention; unavailable authorization/
  storage is reported honestly and no timely physical erasure is promised during outage.
- [ ] Real cleanup before/after arrival, lost response and stale acknowledgement preserves tombstones/order and
  successor material; current delivered or nonterminal work cannot become eligible by missing-copy inference.
- [ ] Multiple finite maintenance pages progress past unchanged/broken entries, retain cursor across restart and
  revisit earlier concurrent inserts after wraparound, without an unbounded drain loop.
- [ ] Authoritative all-scope counts, durable closure and explicit independent key-user holds remain accurate under
  concurrency/uncertainty. Zero never authorizes physical deletion or conceals envelope/backup dependencies.
- [ ] Safe results distinguish confirmed, unchanged, retryable, terminal, unavailable and indeterminate outcomes;
  actual traces reveal no secret/material/receipt/key-provider internals.
