# Enforce current email-change authority

## Outcome

Establish trusted active-human self-service and distinct protected cross-user authority for email-change request,
status and cancellation. Extend the complete managed policy and qualify the package administration callback and
all supported entry paths without exposing unfinished mutations or confusing actor IDs with authentication.

## Scope

- In scope: Stable managed administration Permission/reference extension, package policy preview/reconcile,
  current actor/target checks, `EmailChangeAdministrationAuthorization`, shared entry authorization and denial tests.
- Out of scope: Request/cancel endpoints or UI, notice/delivery implementation, direct active-email editing,
  another authority store, general profile Permission, role-name bypass or implicit production enrollment.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Extend managed email administration | Existing package `ReconcileManagedPolicy` after authorized preview | `PreviewManagedPolicy` over the complete policy and references | Existing package policy fact after commit | One stable protected definition initially assigned only to managed Super Admin |
| Admit self-service | Owning request/cancel operation later; N/A for status | Trusted current active principal and exact self target | No authorization-success event needed | Permit only the authenticated owner's operation, never a caller-selected self target |
| Admit cross-user work | Owning package operation through its qualified callback and entry guard | Current effective protected Permission, actor and active target in installation scope | Owning operation audit, not a duplicate authorization event | Bounded permitted actor/target decision or sanitized denial |

## Validation and permissions

Use TASK-00036's complete versioned managed catalog, including already accepted extensions. Generate the new
stable Permission ID once through an owning factory/UUID library, preserve existing identities and include every
actual reference; do not reconcile a one-Permission replacement policy. Select and document a distinct precise
email-change administration name with `SUPER_ADMIN_ONLY` tier, initially assigned only to managed
`ROLE_SUPER_ADMIN`. Neither custom roles nor direct Agents may receive it. Self-service requires the active owner,
not this administration Permission or an invented general profile grant.

Reuse applicable `InstallationAuthority` behavior and package public contracts, extending only demonstrated
email-specific policy. Authenticate actor provenance before trusting command IDs. Resolve self target exclusively
from the current principal; cross-user intent supplies only a validated target under current installation/action
scope. Check active actor, active target and actual current protected Permission; role name, `READ_USERS`, invitation
rights, client `/me`, JWT claims or possession of another target's ID do not grant email administration.

Qualify the package callback for actor != target, plus current self/target guards on every exposed HTTP, console
and direct-bus path. The callback alone cannot authenticate an actor and is not called for actor == target.
Unsupported or untrusted entry paths deny. TASK-00117's HTTP gate is early defense, not non-HTTP authorization.
Inspect actual transaction/current-authority participation and exercise changed authority; do not claim that a
cached preflight or an existing helper proves every protected operation's current checks.

Replace `UnavailableEmailChangeAdministration` only when this policy and actual callback/entry integration are
qualified. This must not register otherwise unfinished request/cancel routes or bypass TASK-00273's notice seam,
TASK-00280's delivery gate or TASK-00281's cancellation contract hold. Keep package lifecycle/tier policy and
canonical transaction ownership; no copied handlers, nested transaction or hidden repository policy.

Authorization failure returns bounded non-enumerating errors without target existence, private state or arbitrary
package exception messages. Required operation audit preserves actual actor versus target and remains with the
qualified operation owner. No credential, email form body, provider secret or raw principal dump enters diagnostics.

## Acceptance criteria

- [ ] Complete managed preview/reconcile safely adds the distinct protected Permission with stable identity,
  exact initial membership and application references, preserving unrelated managed/custom authority.
- [ ] Trusted active self-service needs no admin Permission and rejects cross-user target injection; cross-user
  request/status/cancel require the actual current protected Permission and active permitted target.
- [ ] Supported HTTP/non-HTTP/callback paths deny forged actor IDs, stale/disabled principals, missing or
  reclassified Permission, role-name spoofing and unavailable authority; unsupported routes remain closed.
- [ ] Callback replacement and policy qualification expose no unfinished mutation or new credential path.
