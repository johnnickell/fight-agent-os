# Recover retry and observe durable effect delivery

## Outcome

An internal operational runner discovers and processes pending/retryable durable effects in bounded deterministic batches, reclaims abandoned leases, applies configurable bounded retry, handles competing PostgreSQL workers safely, and exposes operator-safe status sufficient for later recovery UI.

## Scope

- In scope: Internal console runner/wrapper; explicit operational configuration/authority; eligible discovery and deterministic ordering; bounded batches; lease duration/reclamation; configurable attempt limit and retry schedule; deterministic clock/backoff tests; competing workers; delivered/terminal transitions; safe status/diagnostics; integrated rollback, crash, duplicate, restart, and no-network evidence using deterministic mail/audit adapters.
- Out of scope: Cron/systemd/Kubernetes enrollment, production mail/audit provider, invitation/reset product integration, end-user UI/API, arbitrary job types, exactly-once claims, network-dependent tests, and broad observability platform.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Run one recovery batch | Internal console operation | Discover eligible pending/retryable/abandoned work in deterministic order | Original in-memory event is optional | At most configured batch size is offered to TASK-00023 processor |
| Retry recoverable failure | Same internal operation at/after eligibility time | Read attempts, next eligibility, lease, and terminal boundary | No duplicate business event | Capability is attempted with stable idempotency until success or bounded terminal state |
| Reclaim abandoned work | Internal operation after lease expiry | Detect claimed work whose lease is no longer live | No event required | Work becomes safely claimable without stale worker overwrite |
| Inspect delivery state | N/A — safe operational query/projection | Read pending, claimed, retryable, delivered, terminal and bounded diagnostics | N/A — read-only | Operators/later UI can diagnose state without credentials or provider secrets |

## Validation and permissions

The runner requires explicit internal operational mode and least-privilege database/provider configuration. It cannot be invoked as an anonymous product endpoint. Discovery uses bounded batch size, deterministic eligibility/order, and concurrency-safe PostgreSQL selection. Exit behavior and partial-batch failure are explicit.

Attempt limit, lease duration, and retry delays are configured and validated. Tests use deterministic clocks and bounded synchronization, not sleeps or randomness. Recoverable failures advance attempts/schedule; permanent failures and exhausted retries become terminal. Expired claims may be reclaimed only under the accepted lease/revision rules; stale workers cannot record outcomes over a new owner.

Status distinguishes pending, claimed, retryable, delivered, and terminal with timestamps/attempt counts and safe reason codes. It excludes payload, credentials, tokens, provider keys/messages, ciphertext, credential-bearing URLs, and unnecessary destination data.

At-least-once semantics and the provider-success/outcome-commit crash window remain explicit. Stable idempotency mitigates duplicates but does not justify exactly-once claims.

- [ ] A repository console wrapper runs one bounded recovery batch with explicit internal operational configuration and clear exit behavior.
- [ ] Eligible work selection is deterministic, indexed, batch-limited, and safe under competing PostgreSQL workers.
- [ ] Retry limit, lease duration, and delays are validated/configurable; deterministic tests use no timing sleeps.
- [ ] Abandoned claims become recoverable after lease expiry while stale workers cannot overwrite the new owner.
- [ ] Recoverable failures retry until success or bounded exhaustion; permanent failures become terminal immediately according to policy.
- [ ] Safe status distinguishes pending, claimed, retryable, delivered, and terminal work without exposing sensitive/provider data.

- [ ] Integrated tests prove commit-before-immediate-dispatch loss is recovered after restart without the original event.
