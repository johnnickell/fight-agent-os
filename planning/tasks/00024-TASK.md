# Recover and observe package credential delivery

## Outcome

An internal Agent OS runner reads qualified package due-work discovery in bounded deterministic pages, dispatches
direct package handlers, recovers pending retries and expired leases under package policy, tolerates competing
workers, and exposes secret-free operational status sufficient for later recovery UI.

## Scope

- In scope: Internal console runner/wrapper; explicit operational configuration/authority; package due-work query; bounded pages and worker capacity; direct handler dispatch; lease-duration configuration where the package contract permits; deterministic clocks; competing workers; package retry-until-expiry and terminal outcomes; safe status/diagnostics; integrated rollback, crash, duplicate, restart, and no-network evidence using deterministic credential provider adapters.
- Out of scope: Cron/systemd/Kubernetes enrollment, production provider enrollment, consumer retry/backoff or attempt-limit policy, consumer outbox, product email-change provider wiring, external audit publication, end-user UI/API, arbitrary job types, exactly-once claims, network-dependent tests, and broad observability platforms.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Run one recovery page | Internal console operation dispatches exact package commands | Discover secret-free pending, due-retry, and expired-lease package work in deterministic order | Original in-memory event is optional | At most configured page/capacity is offered to direct package handlers |
| Retry recoverable failure | Same operation after package-calculated due time | Read attempts, next due time, lease, grant expiry, and delivery ID | No duplicate business event | Package handler retries with stable identity until delivery, permanent failure, replacement, cancellation, or expiry |
| Reclaim abandoned work | Same operation after lease expiry | Discover an expired package claim | No event required | Later package handler claims current revision; stale claimant outcome remains fenced |
| Inspect delivery state | N/A — safe operational query/projection | Read package-approved pending, claimed, retryable, delivered, permanent, expired, and terminal status | N/A | Operators/later UI diagnose state without secret material or unsafe provider data |

## Validation and permissions

The runner requires explicit internal operational mode and least-privilege database/provider configuration. It cannot
be invoked as an anonymous product endpoint. Discovery uses the package's bounded deterministic order; Agent OS may
configure page size, worker capacity, cadence, and allowed lease duration but must not select retry backoff, attempt
budgets, terminal policy, or lifecycle transitions owned by the package.

Tests use deterministic clocks and bounded synchronization, not sleeps or randomness. Retryable work remains
eligible under package-calculated bounded increasing backoff until the grant expires. Permanent failure is terminal
immediately, and replacement/cancellation/expiry fence old work. Expired claims may be reclaimed only through the
package contract; stale workers cannot record outcomes over a current owner.

Status excludes raw credentials, hashes, tokens, provider secrets, ciphertext, URLs, plaintext bodies, arbitrary
provider messages, and unnecessary destination data. At-least-once semantics and the provider-success/outcome-
commit crash window remain explicit; stable delivery identity mitigates duplicates but does not establish exactly
once.

## Acceptance criteria

- [ ] A repository console wrapper reads one bounded package due-work page and dispatches exact package handlers with clear exit behavior.
- [ ] Discovery order is deterministic, indexed, page-limited, and safe under competing PostgreSQL workers.
- [ ] Agent OS operational capacity/lease configuration is validated without overriding package retry/backoff or terminal policy.
- [ ] Expired claims recover while stale workers remain unable to overwrite a new owner.
- [ ] Retryable work follows package backoff until grant expiry; permanent failure, replacement, cancellation, and expiry terminalize according to package policy.
- [ ] Safe status exposes package-approved lifecycle state without secret/provider material.
- [ ] Integrated tests prove originating rollback creates no discoverable work or provider call.
- [ ] Integrated tests prove loss after originating commit is recovered after restart without the original event.
- [ ] Integrated tests prove claim crash, provider-success/outcome-commit crash, stable duplicate identity, and competing-worker outcomes.
- [ ] Deterministic null/in-memory credential adapters prove behavior without network access or silent production fallback.
- [ ] Focused recovery/console/PostgreSQL concurrency checks and `./bin/build` pass with fresh evidence.
