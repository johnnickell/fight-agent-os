# Accept the browser-authentication security-profile ADR

## Outcome

An explicitly accepted security ADR defines the browser authentication transport profile, complete JWT consumer validation, external key/secret handling, refresh-cookie and request protections, production throttling, rotation/reuse behavior, multi-tab coordination, and logout/invalidation semantics before EPIC-00004 authentication transport work begins.

## Scope

- In scope: Access-token issuance/consumer claims and validation; clock policy; externally configured signing material and rotation; memory-only Bearer transport; opaque refresh-cookie attributes/lifetimes/scope; CSRF, exact Origin, Fetch Metadata, content-type and shape controls for login/refresh/logout; login throttling ownership; rotation/conflict/reuse/revocation behavior; Web Locks/BroadcastChannel coordination and bounded fallback; logout and authority invalidation; enforcement/deferred-test ownership.
- Out of scope: Implementing tokens, cookies, throttle, middleware, endpoints, session persistence, client code, identity journeys, key-management infrastructure, MFA/passkeys/SSO, and general CORS enablement.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Validate access authority | N/A — ADR decision | Validate algorithm/signature and registered/custom claims before authoritative principal resolution | N/A — no domain event | Invalid, expired, mis-scoped, revoked, or stale authority fails closed |
| Protect ambient-cookie interactions | N/A — ADR decision | Evaluate CSRF token, exact Origin, Fetch Metadata, JSON expectations, and cookie scope | N/A — no domain event | Login/refresh/logout accept only the documented browser request profile |
| Rotate refresh authority | N/A — ADR decision | Resolve credential/session state, expected revision, reuse, and conflict | Package lifecycle events remain package-owned | One valid rotation succeeds; conflicts/reuse have bounded safe outcomes |
| Coordinate browser tabs | N/A — browser coordination decision | Inspect memory expiry and broadcast/lock support | Client-only signals, never trusted domain events | One leader refreshes; logout/invalidation propagates; unsupported APIs use bounded fallback |

## Validation and permissions

The ADR must close the inspected Fight Common decoder's consumer gaps rather than equating signature verification with authentication. Define accepted algorithm/key, `exp`, `nbf`, `iat`, issuer, audience, subject, token type, session identifier, JTI, authentication version, required/optional claims, type/format checks, clock skew, error behavior, and authoritative user/session resolution. Define issuance duration as 15 minutes without putting roles/permissions in JWTs.

Signing material and rotation metadata remain externally configured and are never committed/logged. Define overlap and rejection expectations without claiming infrastructure not delivered. Access tokens remain memory-only and are sent as Bearer credentials; refresh credentials remain opaque and only in narrowly scoped Secure, HttpOnly, SameSite cookies with ordinary/remembered lifetime behavior.

Specify request protections for ambient-cookie login, refresh, and logout, including CSRF token lifecycle, exact trusted Origin, Fetch Metadata where supported, JSON-only/content-type behavior, and safe failure. Require a real production `LoginThrottle` implementation and non-enumerating failures.

Define refresh conflict/reuse/revocation, one bounded recovery where safe, terminal failure, current-session logout, authority-version changes, and cookie expiration. Define Web Locks/BroadcastChannel leader, timeout/crash handling, logout propagation, and bounded unsupported-API fallback without credential persistence.

No user-facing permission is implemented. Architecture documentation is authorized; authentication code is not.

- [x] A numbered accepted ADR records context, threats, decision, alternatives, consequences, enforcement, and deferred work.
- [x] JWT algorithm/signature plus every required registered/custom claim and authoritative-resolution step are explicit in the accepted ADR.
- [x] Missing, malformed, expired, premature, mis-issued, mis-audienced, wrong-type, revoked-session, and stale-authentication-version tokens have documented fail-closed outcomes (not yet implemented).
- [x] External key/secret configuration, overlap/rotation expectations, clock skew, and redaction are explicit.
- [x] Memory-only access-token and opaque refresh-cookie scope, attributes, ordinary/remembered lifetime, and deletion rules are specified.
- [x] CSRF, exact-Origin, Fetch Metadata, JSON/content-type, and correlation with login/refresh/logout are explicit.
- [x] A production throttle is required rather than treating the `LoginThrottle` interface as an implemented control.
- [x] Rotation conflict, suspected reuse, revocation, bounded retry, logout, and cross-tab invalidation outcomes are explicit and fail closed by policy.
- [x] Web Locks/BroadcastChannel fallback is bounded and never stores credentials in browser persistence.
- [x] The human explicitly approved ADR 0003 on 2026-09-25 before EPIC-00004 authentication transport implementation.
