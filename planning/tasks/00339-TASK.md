# Resolve and inspect exact Harness configuration

## Outcome

An authorized caller resolves and inspects one deterministic exact Harness configuration beside Repository context,
with complete safe provenance or actionable missing-capability reasons. This supplies early snapshot inputs without
requiring a running Agent, completed remote loader or final role integration.

## Scope

- In scope: Bounded read-only resolution/inspection through an owned Application and protected adapter path;
  exact package/extensions, connection/profile, type-specific resources, aliases/choices, origin/manifests and
  provider/requested-model facts; coherent generations, safe differences and compatibility diagnostics.
- Out of scope: Another resource/model catalog or role resolver, persisted session bindings, credential access,
  Skill activation, provider calls, grants, conversation launch and browser Planning/database cutover.

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|

| Inspect reproducibility/readiness | N/A — read-only | Exact resolved choices, qualified compatibility and bounded provenance/differences | N/A | Safe inspectable explanation, never a cached allow or persisted snapshot |
| Explain unresolved inputs | N/A — read-only | Missing/ambiguous references and authorized source generations | N/A | No fallback or partial result advertised as ready |

identical effective choices and provenance; do not confuse generated IDs/timestamps with nondeterministic selection.

observation, not an authority token; TASK-00340 revalidates exact references at its owned commit.

Repository policy precedence stays with TASK-00082/00083: Harness resources and prose cannot override application

existing role integration; do not implement its resolution or make TASK-00250's completed role journey a prerequisite

Authorize principal, installation, Repository and applicable assignment scope from real owners, never caller labels.

scope-filtered; model projection is bounded and does not duplicate full instruction bodies or unnecessary private
paths. Requested configuration is distinct from runtime-reported model/response evidence, which cannot be invented
by resolution. Inspection emits no Domain event, changes no configuration and initiates no network model work.
