# Resolve canonical executable TASK eligibility

## Outcome

One permission-controlled application capability deterministically finds and explains executable TASKs for an actor and exact Planning/context revision, applying eligibility before priority and returning stable inclusion/exclusion reasons that every later browser, terminal, agent and Coordinator consumer must reuse.

## Scope

- In scope: `FindExecutableTasks` and `ExplainTaskEligibility`; closed typed eligibility fact/result/reason contracts; actor/Workspace/optional Repository scope; bounded filtering/pagination; TASK/TICKET/EPIC lifecycle/archive checks; implementation-permitting ancestry; direct/transitive blocker evaluation where every blocker must be Done and Won't Fix is unsatisfied; Planning authority/context currentness from TICKET-00025; active owned/conflicting claim observation capability with honest absent-capability semantics before claims exist; ordering from TASK-00094/95; active owned work precedence; deterministic ties; extension seam for later typed claim/Runner/checkout/capability facts without another algorithm; safe API/OpenAPI and Permission behavior; focused behavior/integration evidence.
- Out of scope: Mutating priority/lifecycle/dependencies/context/claims, creating claim/Runner/Workflow state, persisting Blocked/Hold/eligibility, client-side eligibility, provider/GitHub inference, Markdown Board parsing after cutover, browser components and migration/cutover parity execution.

## Validation and permissions

An included executable TASK is unarchived and Ready for Agent; its TICKET and EPIC, when present, are active, unarchived and implementation-permitting; every direct/transitive blocker path terminates in Done; actor Workspace/Repository/view/work authority is valid; database Planning authority and bound context are current; and no observed conflicting active claim exists. Standalone bug/chore rules remain valid. Won't Fix, missing, archived, unauthorized or cyclic/invalid blockers never satisfy prerequisites.

Evaluate eligibility completely before sorting by priority. Valid active work owned by the actor takes precedence when the later claim capability supplies current authoritative facts. Remaining eligible TASKs use explicit queue override, inherited Roadmap priority, authored TASK order, then stable Repository/TASK-reference ties under TASK-00094/95. Blocked candidates retain those values but remain excluded. Pagination is applied only after full deterministic ordering and authorization filtering.

Return a closed ordered set of stable machine reason codes and safe human explanations for inclusion/exclusion, including lifecycle, parent, archive, dependency path, authority, context, Permission and claim facts. Distinguish unavailable/unknown facts from negative facts and fail closed where authority is required. Do not expose inaccessible ancestor/blocker names or allow reason differences to enumerate hidden records. One result carries exact Planning ordering/constraint/context/authority revisions and observation time/provenance.

Before claims/Runner capabilities exist, no claim/Runner state can exist; represent that supported baseline honestly rather than fabricating a service outage or persisted fact. Later capabilities must supply typed observations under a stable evaluator seam and add reason codes/tests to this same handler. They cannot fork a Coordinator query or override base safety. Current Repository designated-checkout facts are included only where this TICKET owns them; future execution capability requirements remain explicit extension facts.

Require authoritative Planning queue view/work-selection Permission with Workspace/Repository scope and live authorization on every query. API Actions dispatch the same query handler used by internal consumers. Results contain safe Views only, no raw projection rows, inaccessible IDs/paths, instruction contents, claim secrets, internal services or arbitrary extension payloads. Querying never writes eligibility/cache/Blocked state or emits events.
