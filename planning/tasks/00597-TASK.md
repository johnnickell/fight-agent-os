# Browse Users through shared stateful tables and URL-backed queries

## Outcome

Operators can page and sort the real Users directory, copy its URL and restore it through
reload or Back/Forward. The same shared table and catalog read protocol are ready for Roles/Permissions in
TASK-00128. Optional search controls and query-state integration are ready for application-specific queries;
search stays disabled for all Access Control features.

## Scope

- Implement [TICKET-00143](../tickets/00143-TICKET.md)'s full state, nested-control, callback, URL/history,
  authorized dataset and validation contracts. The table owns interactions; the page owns fetching/history.
- Deliver nested pagination, page-size, page X of N and optional search controls, typed columns/cells/actions,
  sort indicators and loading/empty/error states using shared React/Bootstrap conventions.
- Mount it in the existing Users page with search disabled. Support bounded whole-dataset ordering with correct totals,
  stable identity ties and safe typed rows. Supply compatible Role/Permission list APIs for TASK-00128, without
  creating its management screens or changing mutations. Preserve independent READ_* admission.
- Extend typed query options, server request validation and API documentation for qualified package pagination,
  ordering and only actually supported filters. Map allowlisted fields; no Access Control search endpoint,
  search projection, competing store or page-local free-text filtering.
- Deliver optional search interactions, callbacks and URL restoration with a representative application-query
  consumer fixture and integration example. Applications supply their own searchable queries; do not invent
  a product feature or generic backend search service. This capability is included in the first release.
- Reuse existing table/page and client tests. Remove superseded pagination markup/state and inaccurate
  pagination-only descriptions; no old/new UI modes or page-local sorting masquerading as global sorting.
- Exclude bulk/export/grid frameworks, arbitrary filter expressions, persistent selected rows, mutations,
  Agent/HMAC controls and registry publication.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Change a list control | None | Current authorized filtered/sorted page and total | One normalized table callback | Internal state changes; page writes history and fetches |
| Restore a URL | None | Validated query state then one authorized page | Explicit restoration without user callback | Table matches navigation without feedback loops |
| Search disabled or malformed query | None | Only a valid allowed query | Safe normalization/notice | No unbounded request or unauthorized field selection |

## Validation and permissions

The parent owns exact URL keys (`page`, `per_page`, `sort`, `order`, `search`, `filters`) and bounded unpadded
base64url JSON handling. Validate independently at browser and server entries. Keep secrets out of URLs,
callbacks and diagnostics. Cancel/fence stale requests with query and authority identity; never reuse a row
under another principal. Public filter names/order identifiers cannot become raw SQL or authority claims.

## Acceptance criteria

- [ ] Table-owned state and nested controls emit one complete normalized callback per committed user change.
- [ ] The page tracks the specified URL keys and restores reload/deep links/Back/Forward without loops.
- [ ] Real Users/catalog data across multiple pages proves whole-dataset ordering and totals; search is disabled.
- [ ] Application-query consumer coverage proves optional search commits, page reset, callback and URL behavior.
  No Access Control search query is issued even when a URL supplies search text.
- [ ] Normalization covers invalid/duplicate/oversized values, Unicode/base64url JSON, search-off mode and
  preserved unrelated host parameters; APIs reject malformed input independently.
- [ ] Count changes, zero results, rapid input, out-of-order responses, errors and authority retirement are truthful.
- [ ] Real Users UI and Role/Permission read contracts are usable, accessible and consistent in both themes.
- [ ] Owning tests/gate pass with Unit-only coverage and honest warnings; no copied components remain.
