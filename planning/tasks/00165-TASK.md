# Select optional retained context with Jev

## Outcome

A local Pi 1.1.0 session uses Jev to select useful optional context while always preserving required checkpoint
facts and safe fallback. Deliver selection and actual checkpoint integration together, with evidence of recall,
context size, cost and latency rather than a promise that smaller context means better work.

## Scope

- Extend [TASK-00164](00164-TASK.md)'s versioned checkpoint and Pi 1.1.0 lifecycle using
  [TASK-00159](00159-TASK.md)'s shared evaluator, protected setup and usage accounting. Do not add another provider
  client, general-purpose tool or a new authenticated Jev identity.
- Identify bounded optional segments with stable source/session identities. Supply caller-authored categories:
  helpful now, possibly useful later and unnecessary for this continuation. Use declared bounded rank values
  within categories, validating their range and resolving ties deterministically by stable source order.
  Unknown, invalid and missing outcomes are not unnecessary; Jev selects typed values, never writes explanations.
- Always retain required facts independently of selection. Fit helpful material first, then later-useful material
  as space permits, under profile-derived context allowances and reserves. Selection never changes authority,
  instruction loading, approval state or pending effects/questions. Do not promote checkpoint content into memory.
- Preserve the shared ceilings: 64 KiB encoded input, eight questions, sixteen choices per choice question,
  two concurrent calls, fifteen-second request timeout and zero automatic retries, subject to tighter limits.
  Budget segment enumeration and aggregate selection separately under explicit operator settings. Never silently
  truncate required material or treat a partial optional selection as complete.
- Use existing configured request/session monetary caps and conservative reservations; include native fallback
  costs and uncertain billed outcomes honestly. Pin bounded segment sizes/counts and the aggregate attempt
  ceiling within the chosen checkpoint profile before activation; no undocumented unbounded collection.
- On Jev failure, denied disclosure, unknown/invalid answers or exhausted budget, retain the checkpoint contract
  using the qualified native older-context summary/recent retention path. Required facts stay protected; native
  model access/cost constraints still apply. If no safe candidate fits, preserve/pause rather than invent a selection.
- Remove optional material first on overflow; bounded allowance growth is only within the active profile's known
  limits and instruction/next-step reserve. Do not silently change models or repeatedly query for a desired rank.
- Bind selection to segment/evidence digests, information need, rubric/evaluator/profile and session/checkpoint
  revision. Cancellation/reload or changed inputs invalidate stale results. Keep parent/child context and spending
  allocations explicit; independent sessions do not imply an account-wide budget guarantee.
- Emit bounded optional identifiers, inclusion/exclusion decisions, validated category/rank outcomes, coverage,
  fallback, latency and usage observations with attribution. Ordinary logs/receipts exclude segment bodies,
  checkpoint prose, credentials and hidden reasoning; protected detail requires current access.
- Exclude timing thresholds/snoozing, missing-fact source repair, retention deletion, managed memory and score gates.

## Validation and permissions

Source access does not permit provider disclosure. Enforce each segment's permitted source/role/session scope,
redaction and egress policy before evaluation, including retries explicitly initiated under current authority.
Treat segment content as data, not instructions to change tools or rubric. Reject incomplete/undeclared/non-finite
or out-of-range values; no cross-role private context transfer. Reuse only evidence-bound valid decisions where
current permission allows it; late/cancelled results cannot mutate an activated checkpoint or duplicate billing.
The file-screening 0.70 threshold is not a category/rank acceptance policy.

## Acceptance criteria

- [ ] Actual Pi 1.1.0 integration selects optional context by the approved categories/ranks and stable ties while
  required fields/questions/effects remain intact across compaction and resume.
- [ ] Unknown/partial/invalid selection, denied disclosure, timeout and exhausted budget cannot discard mandatory
  facts, claim complete coverage or silently expand limits; qualified fallback or preserved pause is observable.
- [ ] Encoded payload/question/choice/concurrency/time/spend and aggregate segment limits hold with cancellation,
  uncertain billing and stale results. Available usage is not double counted and missing cost is not zero.
- [ ] Optional context is removed first on overflow; any allowance increase respects known profile limits and reserve.
  There is no model switch or query resampling merely to force a desired selection.
- [ ] Privacy and supported parent/child propagation hold; observations preserve provenance and bounded selection
  detail without copying checkpoint/segment bodies into normal telemetry.
- [ ] Representative continuations compare useful recall, context size, repeat reads, cost and latency against the
  baseline/native path, retaining misses and incomplete evidence without claiming a universal improvement.
