# Observe current-session children beside native Pi in Herdr

## Outcome

Make the owned child-activity companion from [TASK-00510](00510-TASK.md) useful while the operator works in
native Pi. Reuse existing current-session observation to follow real delegated child progress, choose among
concurrent children and pin a selection without replacing Pi's frontend or changing child execution.

## Scope

- Connect the named Herdr companion to the actual primary native session using supported lifecycle/context and
  existing observation custody from TASK-00448/00502. Do not obtain identity by scraping a terminal or transcript.
- Reuse bounded safe progress, labels, omission/gap notices and honest idle/unavailable/unknown states. Show
  TASK, role, worktree, attempt and known lifecycle separately from the primary conversation.
- Preserve current follow/selection/pin rules: one active child follows automatically; new siblings/output do
  not steal an active selection; absent a retained active selection, select newest trusted start order with a
  stable tie-break. Pins retain completed/disconnected labels; unpin recomputes; no active child means idle.
- Support companion-only selection, pin/unpin, pause/drain, close/reopen and explicit rediscovery. Publish only
  the validated selection/worktree/lifetime metadata needed by TASK-00512 through a bounded local contract;
  progress content is not a control or log-source authority channel.
- Invalidate old admissions and selection authority on actual primary session/file replacement, custodian loss
  or companion-generation changes; reject late events. Reopening observes existing work, never relaunches it.
- Exclude child execution/cancellation/retry, bash/tool interception, managed dispatch, transcript collection,
  new origin attestation and Docker log consumption. No second agent is created to render activity.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Observe current children | Explicit workspace open/reopen | Actual primary session and admitted monitor associations | Existing safe progress/lifecycle/heartbeat | Bounded human-only read subscriptions |
| Choose or pin a child | Companion selection and pin/unpin controls | Admitted active/retained identities and trusted start order | Selection changes, not Workflow events | Local display selection and validated log-context metadata only |
| Pause, disconnect or replace session | Companion pause/close/rediscover; actual native session lifecycle | Current source generation and liveness facts | Existing disconnect/session lifecycle notifications | Bounded draining or reader cleanup; stale context loses authority |

## Validation and permissions

Preserve [TASK-00502's owner-approved trusted-local-process boundary](00502-TASK.md#owner-approved-trusted-local-process-amendment--2026-10-21):
local Pi/provider bootstrap assertions are trusted; malicious same-user impersonation is outside current protection.
Signatures are not independently attested native origin or OS isolation. TASK-00507 remains a non-blocking future
investigation. Normal honest-parent separation, exact session/file binding, stale/replaced/malformed/cross-session
refusal, bounded elapsed requests/cancellation and fixed monitor associations remain required.

The companion is human-only observation, not another agent or a model-facing tool. Do not forward progress to
Pi/provider context or Herdr metadata surfaces that automatically inject it into context. No automatic pane read
or input forwarding to agents. Runtime data belongs under ignored `var/`; `.runs/` is evidence only. Validate local
ownership, identity and generation before accepting selection metadata. Missing association must not affect the
ordinary monitor's execution, tool settings, shell route, authority, result or cleanup. Closing an observer stops
only its subscriptions; it cannot terminate the primary Pi, children or unrelated panes.

## Acceptance criteria

- [ ] Real current-session children appear without per-child socket flags or child relaunch; unrelated honest
  parent sessions remain separate and absent/malformed/stale sources are explicitly unavailable.
- [ ] Real concurrent children demonstrate stable following, explicit selection and pin/unpin; completion,
  disconnection, heartbeat loss and idle are truthful, with no guessed execution success or acceptance.
- [ ] Pause drains within bounds; reconnect/close/reopen and slow/failed observation leave primary and child
  execution unchanged. Session changes clear stale authority and reject late updates.
- [ ] Validated selection/worktree metadata is available for the log companion; unverified progress/labels cannot
  redirect logs. Cross-parent/session/generation data is rejected.
- [ ] Native completion, colors, dialogs and primary typing remain intact while activity updates; focus and
  selected identity are readable in wide/narrow terminals and both themes.
- [ ] Real integration/capture evidence, focused owning checks and the full gate are recorded, with privacy,
  trust limitations, warnings and independent Review/QA state explicit.
