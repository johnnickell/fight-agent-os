# Accept the PostgreSQL consistency and durable-effects ADR

## Outcome

An explicitly accepted architecture decision defines PostgreSQL persistence, migrations, transaction ownership, repository mapping and concurrency strategies, test isolation, and recoverable durable intent before affected schema or adapter work begins.

## Scope

- In scope: Inventory foundation repository contracts from the stable Fight Access Control release; decide PostgreSQL authority, Doctrine migration policy, shared-connection transaction ownership, contract-specific ORM/DBAL/mapping and concurrency choices, database constraints, safe conflict mapping, guarded test databases, deterministic migration/reset, and the durable-intent mechanism required before external delivery.
- Out of scope: Migrations, repository adapters, database tooling implementation, external delivery, event sourcing, HTTP/UI behavior, feature commands, and speculative persistence for deferred Agent or email-change journeys beyond state required by implemented contracts.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Decide repository persistence | N/A — ADR work | Inspect stable package repository contracts, entities, revisions, references, and ordering promises | N/A — no domain event | ADR maps each required contract to a faithful storage and concurrency strategy |
| Decide transaction ownership | N/A — ADR work | Inspect `DoctrineTransactionalUnitOfWork`, connection ownership, command handlers, and post-commit coordination | N/A — no domain event | One shared connection and canonical transaction boundary are explicit |
| Decide durable intent | N/A — ADR work | Inspect required delivery effects and commit/dispatch crash window | Package events retain their true ownership | Recoverable intent commits with business state; delivery remains post-commit and at-least-once |
| Decide test safety | N/A — ADR work | Inspect local/container environments, credentials, database naming, migration/reset needs | N/A — no domain event | Integration tooling cannot target known development or production databases |

## Validation and permissions

The ADR must make PostgreSQL authoritative for persistence and concurrency evidence, Doctrine Migrations the only schema-evolution path, and `DoctrineTransactionalUnitOfWork::commitTransactional()` the canonical transaction boundary. It must prohibit request-time schema creation, SQLite concurrency claims, and external email/HTTP/filesystem effects inside transactions.

Inventory the stable package contracts needed by the approved foundation: permissions, roles, users, refresh sessions, activation grants, password-reset grants, and audit evidence. Include the atomic `UserRepository` authority/session operation and cross-repository fences. Explain ORM mapping, targeted DBAL, optimistic revisions, pessimistic locks, conditional updates, constraints, and ordering per contract rather than imposing one strategy universally.

The durable-intent decision must define atomic creation, discovery/claiming, retry state, idempotency identity, safe payload/reference storage, retention, and recovery assumptions while assigning provider execution to TICKET-00011. It must state honest at-least-once semantics.

Test databases require separate credentials/names, explicit test mode, deterministic migrations/reset, and hard refusal of known development/production targets. Secrets remain external. No runtime user permission applies; only architecture documentation is authorized.
