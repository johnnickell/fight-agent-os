# Export selected live diagnostics with bounded current-authority output

## Outcome

An authorized operator explicitly exports selected live diagnostic records from native Logs with exact content and
honest coverage, without an unbounded job or stale-authority release. This approved slice A of
[TICKET-00116](../tickets/00116-TICKET.md) owns the complete native control/application/private-source/output path,
not a generic transfer framework. It supplies reusable extraction and output-fence behavior for restored export.

## Scope

- In scope: Permission-gated native selection/export controls, typed exact query selection, bounded streaming output,
  current disclosure checks, truthful completion/partial states, cancellation/admission accounting and transient
  output/cache participation in existing restriction fences.
- Out of scope: Restored export, archive download, permanent report/export-copy store, persistent read job, server
  spool, arbitrary backend proxy, public sharing and automatic extraction replay.

Consume TASK-00463's whole-scope typed query, tie-safe traversal, current-authority and shared admission contracts,
TASK-00462's protected permissions and TASK-00467's early disclosure participants. Export actual selected original
records, not rendered rows or a silently substituted preview. Preserve original bytes through an explicit reversible
representation where necessary, identities, collection/emitted clocks, source/fragment provenance and native fields.
Do not redact, synthesize missing fields, content-deduplicate legitimate messages or claim stable/complete coverage
when late arrivals, partial queries or unavailable sources prevent it. Exact eight levels plus unknown remain distinct.

Apply [WF-041](../wayfinder/tickets/WF-041-select-the-authorized-log-browser-integration.md) and the accepted
[TICKET-00116 transfer bounds](../tickets/00116-TICKET.md#approved-task-decomposition-and-current-handoff): <=7 days,
<=16 MiB total encoded export including framing/coverage information, <=30 seconds, requests <=16 KiB with <=4 KiB
literal search. Use the existing two installation-wide shared read/export/download slots and one/requester, not
per-process counters or a new waiting queue. Count provider work until actual completion/cancellation is confirmed.
Known excess rejects before extraction with narrower-selection guidance; actual counters stop unknown excess safely.

Output batches are <=64 KiB, with <=1 MiB queued output per transfer. Revalidate actual current actor/session/
capability/source/policy before fetch and private release and at every output batch. A request-principal snapshot,
client permission cache or earlier successful query is not fresh authority. Unknown state withholds output. Join
TASK-00467's current restriction fence before exposure; output cannot republish data restricted during traversal.
Track actual transient buffers and release/cancellation boundaries for TASK-00472 without inventing a retained copy
store. Already released/in-flight bytes, screenshots and operator files cannot be recalled.

Define explicit machine-checkable completion and integrity/coverage information; HTTP 200 or EOF alone is not
complete extraction. Reserve bounded framing space or use an equivalent qualified mechanism so limit/failure paths
never appear complete. After output begins, deny further private bytes safely without appending raw exceptions or
pretending the public error envelope can replace already released bytes. A missing terminal confirmation is incomplete,
not an empty successful result. Do not manufacture immutable evidence certification from transfer integrity.

Use an actual bounded authenticated browser save path. Account for browser buffers/copies, worker occupancy, proxy
buffers, socket/backpressure and provider work; encoded caps alone do not bound heap. Do not hide whole-file Blob
accumulation outside the resource budget or silently persist private query caches. Cancellation, deadline, credential
refresh/logout and scope/identity changes retire volatile content and fence late successes/errors. No automatic retry
or resume after credential restoration. Accessible selection/limits/progress/results must work in the existing shell
without a separate Dashboard, stealing focus or announcing every batch.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Explicitly export selected live records | User extraction request; no business job/mutation | Current READ_LOGS + EXPORT_LOGS, exact typed selection and policy | No Workflow event; existing required safe access/audit only | Bounded private output of actual records and declared coverage |
| Traverse/export exact content | No business replay | Tie-safe bounded source pages and fresh release authority | N/A | Exact native/reversible bytes, not preview replacement or deduplication |
| Interrupt or lose authority | Bounded cancellation of owned read/transfer | Current policy, deadline and actual provider/output state | Safe required operational facts only | Further release withheld; incomplete result and counted residual work |

## Validation and permissions

Require `READ_LOGS` + `EXPORT_LOGS`; READ_LOGS alone never authorizes bulk export. No Role-name bypass, direct-Agent
or custom-role delegation, storage/purge/hold/evidence authority or caller tenant/LogQL/URL is accepted. Follow ADRs
[0001](../adr/0001-application-ownership-and-orchestration.md),
[0002](../adr/0002-postgresql-consistency-and-durable-effects.md),
[0003](../adr/0003-browser-authentication-security-profile.md) and
[0004](../adr/0004-client-authority-and-runtime-state.md): application-owned policy, canonical required state/audit
transactions without network transfer inside them, same-origin Bearer/applicable CSRF, no-store and generation-fenced
volatile state. Use safe filenames/media types and inert presentation; keep content/search text/credentials out of
URLs, history, referrers, telemetry and logged payloads. Denied targets reveal no hidden counts/existence.

## Acceptance criteria

- [ ] Real native export returns exact selected captured records with identities/clocks/provenance; tied, repeated,
  malformed/binary/large records and unstable coverage never silently become complete previews or altered originals.
- [ ] Actual current authority and owner fences govern fetch and every bounded output release; real revocation,
  expiry, purge and unknown-authority races deny further bytes without claiming recall of released content.
- [ ] Time/byte/batch/queue and aggregate admission limits hold across concurrent workers, slow clients, disconnects,
  cancellation and unknown provider outcomes; no hidden spool, read job or premature capacity release occurs.
- [ ] Explicit completion/integrity checks distinguish full selected coverage from partial/interrupted output;
  credential restoration and late callbacks cannot replay extraction or revive private browser state.
- [ ] Owned API/application/client/concurrency tests, actual accessible save controls, direct transport/proxy/resource
  qualification and full `./bin/build` pass with precise unsupported cases and warnings recorded.

## Verification and evidence

including ties, legitimate duplicates, oversized records and late coverage. Test real PostgreSQL authority/purge races
at output boundaries, bounded concurrency, slow/disconnected clients, cancellation failures and deadline/byte edges.
Inspect request/response headers, safe output framing, browser lifetime and actual process/proxy/provider resources.
Qualify infrastructure with owning tools; do not product-test configuration, migrations, wrappers or vendor internals.
Run focused repository wrappers and full `./bin/build`. No private-content transfer or runtime experiment is authorized
by this planning record; record actual targets/authority, direct evidence and incomplete verification at delivery.
