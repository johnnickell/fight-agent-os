# Enforce snapshot drift and unavailable-authority boundaries

## Outcome

Bound Repository context snapshots remain immutable while current configuration, instructions, checkout/Git evidence, Repository lifecycle, live authorization and service availability are compared explicitly; stale or unavailable context blocks new authority-bearing Agent OS operations without silently refreshing, falling back or expanding authority.

## Scope

- In scope: Deterministic current-versus-bound context comparison; stable drift/stale/unavailable reason codes and safe explanations; configuration/schema/revision drift; recognized instruction path/digest/effective-set drift; designated Host/Checkout/Worktree, approved-root, Git branch/base and availability drift; Repository source/lifecycle drift where meaningful; live permission narrowing/revocation; planning-mode/authority availability; immutable stale status/projection; explicit new linked-context requirement; new registered-resolution failure during service loss; existing registered snapshot offline/read-only state; explicit unregistered/local continuation with no registered authority; reusable context-current guard for later controlled operations; permission/API/OpenAPI and integration evidence.
- Out of scope: Mutating historical snapshots/bindings, silently refreshing a session, model/Pi conversation implementation, service repair, cached database writes, Planning/Workflow commands not yet implemented, instruction editing, browser UI, network/offline simulation framework, global authorization replacement and claiming OS sandbox control.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Compare a bound snapshot with current facts | N/A — read-only comparison | Get context currentness/drift explanation | N/A — drift is derived, not a Domain event | Stable current/stale/unavailable reasons are returned without changing the bound snapshot |
| Attempt controlled work with stale context | Existing/future authority-bearing command invokes context-current guard | Revalidate live authority and context subject | Existing owning event only on success | Operation stops before side effects with actionable stale reason; no automatic re-resolution occurs |
| Continue during service loss | N/A — explicit mode selection | Inspect service and cached/bound snapshot availability | N/A — no authority event | Existing context may be viewed stale/read-only; new registered authority remains unavailable |
| Continue locally without Agent OS authority | N/A — explicit unregistered/local choice | Resolve local instruction context only where the host permits | N/A — no application authority event | User can continue ordinary local Pi activity with no registered Planning/Execution authority |
| Reconnect after drift/outage | N/A — create a new linked context through TASK-00082/83 | Resolve current context and compare lineage | N/A — resolution itself is read-only | A new binding is created explicitly; prior snapshot/session history remains unchanged |

## Validation and permissions

Compare the retained TASK-00082/83 snapshot/binding with freshly authorized facts through the same normalized capabilities and schema rules. Never compare client assertions. Classify at least configuration revision/schema, instruction path/digest/effective-set, Repository lifecycle/source where relevant, designation/Host/Checkout/Worktree/root availability, recognized Git branch/base state, planning authority/mode, application restriction version and live Permission status. Distinguish stale, revoked, unavailable, unsupported and harmless no-semantic-change outcomes.

A changed configuration revision, meaningful effective instruction digest/set, designated physical target, recognized Git guidance, Repository archive/source authority, planning mode or application restriction marks the binding stale according to explicit rules. Harmless resource reloads that normalize to the same effective context may remain current. Record reasons/provenance and comparison time without modifying the historical snapshot, chosen result or conversation lineage.

Live authorization may always narrow/revoke access even if snapshot revision is unchanged. Cached roles, prompt content, old permissions, local instructions, Skills, route visibility and possession of a context token cannot preserve revoked authority. The reusable guard composes with each later owning command's direct authorization and expected-state checks; it does not become a generic permission substitute or emit another event.

New registered context resolution requires live Repository/configuration/authority services and current physical evidence. When unavailable, fail with direct reasons and never reuse a cached snapshot to create authority. An existing binding may remain inspectable as visibly stale/offline/read-only, but Planning mutations, migration, Workflow commands, claims and other controlled operations are unavailable. Reconnection starts/forks an explicitly linked current binding and never mutates the prior one.

Explicit unregistered/local continuation has no Agent OS Repository Planning/Execution authority, registered configuration promise, database cache authority or hidden mode fallback. It may describe local instruction discovery as ordinary Pi behavior but cannot claim application control over local OS tools. Missing database authority never reactivates Markdown authority automatically.

Require permission to inspect detailed registered drift/currentness. Safe prompt/client projections contain only necessary stale/offline warnings and short tokens; detailed Views remain scope-filtered and exclude instruction contents, secrets, credentials, internal services, unnecessary paths/IDs and raw errors. Observation/comparison emits no Domain event and performs no repair, refresh, migration or file write.

## Acceptance criteria

- [ ] Currentness comparison is deterministic, permission-scoped and covers configuration, instructions, physical designation/root/Git evidence, Repository lifecycle, planning authority, application restrictions and live authorization.
- [ ] Stable reasons distinguish current, stale, revoked, unavailable, unsupported and harmless semantically unchanged observations without mutating the binding.
- [ ] Configuration/effective-instruction/meaningful Git/designation/lifecycle/authority drift preserves historical snapshots and visibly marks affected bindings stale.
- [ ] Live authorization narrowing/revocation blocks access regardless of cached snapshot, roles, prompt, local guidance or context token.
- [ ] Reusable context-current guard stops authority-bearing operations before side effects but never replaces their owning permission/invariant checks or emits duplicate events.
- [ ] New registered resolution fails during required service loss and never inherits authority from cache.
- [ ] Existing offline bindings are visibly stale/read-only; no registered Planning, migration, Workflow, claim or execution mutation is available.
- [ ] Explicit unregistered/local continuation carries no registered Planning/Execution authority and never silently changes planning mode.
- [ ] Reconnection creates an explicit new linked binding while prior snapshots/choices/history remain immutable.
- [ ] Focused drift/authorization/availability/API/redaction tests, direct instruction/service observations and the canonical build pass.
