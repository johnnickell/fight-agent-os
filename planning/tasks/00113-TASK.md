- In scope: Final shell/navigation/breadcrumb/repository-scope integration; cross-feature route boundaries and deep links; shared Planning page header/context/authority/revision/status patterns; loading/empty/denied/not-found/stale/conflict/partial/unavailable-checkout/unavailable-service/frozen/migration-failure/offline read-only states; query cancellation/cache invalidation on principal/Repository/context/mode changes; error/retry/focus/announcement consistency; narrow/wide and theme/reduced-motion integration; component-catalog production states; keyboard/focus/semantics/labels/contrast/target/reflow/accessibility evidence; bounded critical browser smoke for representative direct Planning journey.
- Out of scope: New Domain/API behavior, browser Agent conversations/proposals, coordinated claims/Execution/session dashboards, universal WCAG/browser certification, broad end-to-end suite, testing React/router/framework mechanics, source retirement and release/deployment certification.

## Validation and permissions

Integrate TASK-00107–00112 through the existing application frame, current-principal authorization service, shared API client/error boundary, route metadata, semantic tokens/theme and accepted component catalog. Do not create a parallel Planning app shell, fetch client, auth cache or error vocabulary. Route visibility reflects Permissions but server responses remain authoritative.

Repository/principal/context/mode changes invalidate or isolate all affected cached/in-flight data. Never combine old header/context with new artifact/queue/migration body. Unknown authority fails closed. Partial query identifies unavailable sections; global error does not erase safely available context, and cached/offline state is labeled read-only with observation revision/time.

Standardize status/error copy and accessible behavior without hiding backend reason detail. Loading avoids fabricated records/metrics; empty differs from denied/not-found/unavailable. Stale/conflict preserves authoritative current data and safe transient form intent as owning tasks specify. Retry is idempotent and does not repeat uncertain mutations.

Verify keyboard navigation/order, skip/navigation landmarks, headings, form/dialog focus, focus restoration on route/modal/error/reorder, visible/unobscured focus, labels/instructions, status/error/live-region announcements, contrast, target sizes, 200% zoom/reflow, narrow dense tables/cards, reduced motion and theme variants. Automation/manual evidence is scoped and honest.

Keep browser automation to critical behavior not proven below: authenticated shell into selected Repository, context visibility, traverse representative hierarchy, one safe semantic edit with server confirmation, one guarded preview/cancel or authorized operation, queue explanation/navigation, archive/render and a stale/denied recovery. Do not test every form/route/state in browser or framework rendering.
