# Clean separately authorized local creation resources

## Outcome

An explicitly admitted local-cleanup operation removes only precisely owned creation resources after current
reference, ownership and quiescence checks. Replaced, unrelated, referenced or uncertain resources remain protected,
and interrupted cleanup returns truthful retained-resource facts without erasing attempt history.

## Scope

- In scope: Exact local cleanup effect adapter, bounded impact/ownership inspection, current reference/process/root
  safety composition, original-operation reconciliation and safe partial-result evidence.
- Out of scope: Cleanup consent/UI or attempt transitions, automatic compensation, arbitrary filesystem deletion,
  remote GitHub deletion, snapshot purge, registration/profile/context removal, new retention or sandbox platform.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Inspect precise local cleanup impact | N/A — read-only | Exact owned resources, current references, process obligations and unrelated changes | N/A | Bounded safe impact facts for the separate cleanup preview |
| Execute admitted local cleanup | Exact currently authorized cleanup-stage intent | Confirmed impact, actual owner/generation/root identity and verified quiescence | Verified cleanup facts through attempt owner | Only exact approved local resources removed; history retained |
| Reconcile interrupted cleanup | Explicit original-cleanup reconciliation | Actually removed and retained identities, uncertainty and original result | Verified partial/complete/held facts | No blind repeat against a reused path or unrelated resource |
