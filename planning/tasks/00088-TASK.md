# Create and revise EPIC and TICKET artifacts

## Outcome

Authorized planners can create, inspect and semantically revise separate event-sourced EPIC and requirement TICKET aggregates with immutable Project-local references, typed content, stable use-case children, same-Project hierarchy and explainable history.

## Scope

- In scope: Separate `Epic` and `Ticket` aggregate roots/streams; adapter-generated typed COMB IDs in void commands; immutable Project-local EPIC/TICKET reference allocators; active Project ownership; mandatory one-EPIC parent for TICKET; initial machine status; titles/target/kind and typed sections; Markdown-capable destination/problem/boundary/rationale/progress/supplemental sections; stable ordered use-case children with command/query/event/effect fields; intent-specific create/revise/add/reorder/retire commands and semantic events; expected versions/required audit; transactional parent/reference/current projections; hierarchy/detail/history Views; view/create/revise Permissions; PostgreSQL/concurrency; versioned API/OpenAPI.
- Out of scope: Generic Planning documents, reparenting/cross-Project replacement, dependency edges, acceptance criteria/evidence, terminal lifecycle/closeout, archive/restore, priority/queue, Markdown import, Dashboard components and automatic TICKET creation from EPICs.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Create an EPIC | `CreateEpic` | Preview active Project, reference allocation and normalized initial content | `EpicCreated` | One stream, immutable reference, allocator constraint and current projection commit atomically |
| Create a TICKET | `CreateTicket` | Preview active same-Project EPIC, reference allocation and initial requirement | `TicketCreated` | One child stream and parent/reference/current constraints commit atomically; parent is not revised implicitly |
| Revise structured/narrative content | Section-specific commands | Compare normalized section/use-case and expected aggregate version | `EpicDestinationRevised`, type-specific section/use-case events | Complete changed values append with provenance; unrelated streams do not conflict |
| Inspect hierarchy/history | N/A — read-only interaction | Get Project EPIC/TICKET hierarchy, detail/version and event history | N/A — reads emit no Domain event | Rebuildable typed Views explain current content and provenance without becoming authority |

## Validation and permissions

Use distinct Epic and Ticket models/events/handlers/views. Do not parameterize behavior through a generic artifact/document aggregate or generic status/content setter. Creation entry adapters generate each typed aggregate ID through its owning factory into a void command.
Allocate EPIC/TICKET references independently and atomically per Project/kind and never reuse them. Untrusted
clients cannot select IDs/references. A successful adapter already knows the ID; lost responses reconcile through
fresh authorized list/detail reads and uniqueness conflicts, not original-result replay or a receipt journal.

A TICKET has exactly one existing active EPIC parent in the same Project. Creation validates current parent/Project versions and command-critical projection state in the append transaction. EPIC/TICKET ownership and references never change here. Cross-Project relationships and client-supplied Markdown links do not establish identity or parentage.

Use a closed hybrid content schema. Titles, targets/kinds, parents, current machine status, use cases and their command/query/event/effect columns are typed. Narrative sections are bounded Markdown-capable complete values. Preserve explicitly labeled supplemental content for later imported unrecognized sections without interpreting it as policy. Stable use-case IDs survive reorder/revision/retirement; removal is historical retirement, not deletion.

Each entry admits caller/operation/Project scope before configured bus dispatch under TICKET-00026. Registered
aggregate-owned handlers enforce expected stream/constraint versions and coordinate repositories/required audit
through the shared generic UoW; no second blanket Application permission gate or repository-owned commit. Stale commands return current version/intervening facts without silent merge or last-write-wins. Completing a use case or child does not change lifecycle. Initial lifecycle uses accepted values and no generic setter; full transitions/closeout belong to TASK-00092.

Require separate view/create/revise Permissions admitted for Workspace/Project and parent. HTTP Actions dispatch one command/query; Responders present safe typed
Views/JSend/OpenAPI, without fetching or putting transport DTOs in Domain. Hide raw event payload storage, SQL, unauthorized Project/parent existence and prohibited content.
