# Reconcile the exact managed authority policy

## Outcome

One version-controlled managed policy with stable identities defines the exact initial roles, permissions, memberships, and application references, while safe console preview/apply operations use Fight Access Control's `PreviewManagedPolicy` and `ReconcileManagedPolicy` behavior to detect and transactionally repair drift.

## Scope

- In scope: Stable managed role/permission IDs and definitions; `ROLE_USER`/`ROLE_SUPER_ADMIN`; twenty-one approved permissions from TICKET-00015; exact memberships and tiers; referenced permission IDs; typed policy factory/provider; package query/command composition; trusted console preview and apply entry points; safe deterministic output/exit status; PostgreSQL idempotency, drift, removal/reference, rollback, and controlled concurrency tests; operational documentation.
- Out of scope: User bootstrap/invitation, custom-role administration, HTTP endpoints, role-name authorization, UI, additional permissions/roles, multi-workspace policy, direct repository mutation outside package behavior, and automatic request-time reconciliation.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Preview managed authority | N/A — read-only console operation | `PreviewManagedPolicy` | N/A — no domain event | Deterministic create/reconcile/remove/no-change plan is displayed without mutation |
| Reconcile managed authority | `ReconcileManagedPolicy` | Planner/repository reads inside package handler | `ManagedPolicyReconciled` | Exact managed definitions and memberships commit atomically; event follows commit |
| Repeat reconciliation | `ReconcileManagedPolicy` | Re-preview current policy | `ManagedPolicyReconciled` only according to package contract | No duplicate/drift mutation; stable deterministic outcome |
| Reject conflict/race | `ReconcileManagedPolicy` | Resolve identifier/name/reference/current revisions | `CommandFailedEvent` according to package contract | Transaction rolls back and console exits nonzero without leaking internals |

## Validation and permissions

Define stable version-controlled IDs for managed authority; never generate them at runtime. Use TICKET-00015's exact twenty-one-name catalog. `ROLE_USER` has only `VIEW_DASHBOARD`, `READ_OWN_SESSIONS`, and `DELETE_OWN_SESSIONS`; `ROLE_SUPER_ADMIN` has all twenty-one. Set installation-wide security definitions to `SUPER_ADMIN_ONLY`, and only self-service/dashboard definitions to `ADMIN_SAFE`. `READ_USERS` explicitly replaces unimplemented `LIST_USERS`; retain `INVITE_USERS` for intent-specific pending invitations. Do not invent `CREATE_USERS` or a generic `UPDATE_USERS`/`UPDATE_PROFILE`. Application permission references include every checked permission so reconciliation cannot remove a still-used definition; labels alone never authorize delegation.

Use package `ManagedPolicy`, `PreviewManagedPolicy`, and `ReconcileManagedPolicy` directly through established query/command composition. Preview is strictly read-only. Apply uses the canonical transactional connection and package planner/handlers; do not duplicate reconciliation logic or mutate repositories from the console adapter.

Managed identity/name/tier/membership drift is explicit. Obsolete managed definitions follow package reference/assignment fences and fail atomically when unsafe. Existing unmanaged/custom definitions must not be silently converted, renamed, granted, or removed. Concurrent preview is advisory; apply revalidates transactionally and a stale/conflicting plan fails safely.

Console operation requires trusted local execution, is non-interactive unless confirmation is deliberately documented, returns meaningful exit codes, and redacts credentials, connection strings, SQL, stack traces, and private configuration. It does not run during HTTP requests or application startup implicitly. No end-user permission applies to local operational access.

## Acceptance criteria

- [ ] One typed version-controlled policy defines stable IDs/names/tiers for exactly the twenty-one approved managed permissions and two managed roles.
- [ ] `ROLE_USER` has only dashboard and two own-session permissions; `ROLE_SUPER_ADMIN` has the full catalog, while effective authority is always evaluated by permission and target.
- [ ] Every permission checked by initial application code is present in managed referenced-permission IDs.
- [ ] Preview dispatches `PreviewManagedPolicy`, performs no write/event, and displays a deterministic safe plan and exit status.
- [ ] Apply dispatches `ReconcileManagedPolicy` on the canonical transaction and does not duplicate package planner/repository behavior.
- [ ] Fresh reconciliation creates exact definitions/memberships with no duplicates and post-commit package event behavior.
- [ ] Repeated reconciliation is idempotent; name/tier/membership drift is detected and repaired deterministically.
- [ ] Obsolete managed definitions honor assignment/reference fences; custom/unmanaged authority remains untouched.
- [ ] Invalid definitions, identity/name conflicts, stale state, controlled races, and injected failures roll back without partial policy.
- [ ] Console output/logs contain no credentials, SQL, stack traces, or private environment details.
- [ ] No request-time migration/reconciliation, role-name authorization, user bootstrap, or extra policy is introduced.
- [ ] Focused unit/PostgreSQL/command/query/console/concurrency checks and `./bin/build` pass with fresh evidence.
