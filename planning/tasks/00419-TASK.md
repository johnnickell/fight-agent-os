# Create and reconcile the exact confirmed repository

## Outcome

One admitted creation stage creates only the exact human-confirmed GitHub repository and retains attributable
provider-native identity. Interrupted or lost responses reconcile the original operation or hold, never adopt a
matching name or create a second remote to conceal uncertainty.

## Scope

- In scope: Protected exact repository-creation adapter, provider-native ownership/provenance, independent outcome
  verification, bounded original-effect reconciliation and safe results through the existing attempt owner.
- Out of scope: Local remote configuration/push/default branch, account enrollment, existing-repository adoption,
  private-starter retrieval, PR/release workflows, cleanup and a new attempt or delivery engine.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Create confirmed remote | Execute original admitted remote-creation operation | Current consent, human/provider authority, exact target and original result | Verified creation facts through attempt owner | One repository with exact owner/name/visibility/description |
| Reconcile uncertain create | Explicit original-operation inspection and only proved-safe retry | Attributable provider-native identity and actual original outcome | Verified result or uncertainty/hold | Resolve original remote, not adopt or duplicate |
| Inspect retained remote result | N/A — read-only | Authorized verified identity, provenance and partial disposition | N/A | Safe input to publication/registration/cleanup; no live provider call |
