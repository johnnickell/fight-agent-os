# Observe every command query and event dispatch

## Outcome

Operators can follow actual application command/query invocations and event dispatch, including nested and non-HTTP
paths and events without subscribers, without changing business behavior or confusing an observation with committed
Workflow state. This is approved slice C of [TICKET-00111](../tickets/00111-TICKET.md).

## Scope

- In scope: Actual shared Common command/query filter instrumentation and an owned event-dispatch observation
  boundary; native message identity/type/time, selected safe context, lifecycle/duration, nested context and fault
  handling; important integration contracts with the installed messaging implementation.
- Out of scope: Another bus/router/subscriber engine, wildcard business subscriber as coverage, package aliases,
  payload/result serialization, distributed tracing, transaction/publication machinery, retry policy and new UI.

Consume [WF-037's native activity contract](../wayfinder/tickets/WF-037-define-redacted-diagnostics-and-shared-http-adoption.md#native-diagnostics-and-application-activity),
[ADR 0001](../adr/0001-application-ownership-and-orchestration.md) and
[ADR 0002](../adr/0002-postgresql-consistency-and-durable-effects.md). Use the existing shared service graph and Common
message/filter/dispatcher contracts directly. Observation adds real behavior, not aliases for package-owned messages.
Do not patch vendor or select a new package version merely to add logging.

Observe every invocation/dispatch, not just failures, including nested command/query/event chains, worker callers
and no-subscriber events. Keep started, returned/completed and failed distinct; elapsed time measures the actual
observed boundary. Capture actual known attempt/retry/replay metadata rather than classifying equal text as replay.
Preserve native message identity, payload type and available time/context; unrestricted `toArray()` on a message or
payload is not safe producer selection. Missing lineage stays unknown.

A returned handler/dispatcher is not proof of committed state, durable publication or all consumers' success. Use
commit/publication labels only from an actual confirming owner; do not add a transaction or external delivery to
manufacture such proof. Preserve subscriber order, lazy registration, result propagation, exceptions and existing
postcommit delivery semantics. A diagnostic failure never repeats dispatch or converts its outcome.

Establish bounded nested context lifetimes that restore the caller on return/failure rather than clearing an active
parent; TASK-00454 owns job/root context reset. Failure observations here remain distinct from the single HTTP or
console/worker boundary reporter. No content/time deduplication may erase legitimate nested/repeated activity.

### MCP and canonical activity coverage boundary

These filters observe configured CommandBus/QueryBus calls and the event-dispatch boundary, not every MCP request.
[TASK-00245](00245-TASK.md#safe-mcp-observation-boundary) owns MCP adapter request/capability instrumentation;
TASK-00335 supplies its static Skill/Resource paths, while TASK-00245 includes static Prompts. HTTP 200, provider return and
response/stream creation are not equivalent to protocol success, stream completion or business commit. Qualify
actual terminal/cancellation coverage at the stream owner and disclose gaps after abrupt loss.

Private operational Logs remain separate from selected Agent-readable activity. TASK-00386 may consume only
allowlisted safe boundary facts under
[TICKET-00096's Common recording contract](../tickets/00096-TICKET.md#canonical-observation-supplier-and-delivery--2026-11-06),
not copy every diagnostic record or raw payload into another ledger. Common TASK-00205 supplies planned typed
facts, not instrumentation. Avoid duplicate semantic counting across request/nested bus boundaries and recursive
capture of the observer's own recording/status dispatch; preserve observation of unrelated business work. Optional
recording policies dispatch through configured buses with independent transactions and idempotent source identities,
never wrap observed work in Common's recording transaction or retry business work to repair telemetry.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Observe command/query invocation | Existing commands, unchanged dispatch | Existing queries, unchanged results | Native invocation lifecycle observations only | Every included call has attributable start and actual terminal observation where process survival permits |
| Observe event dispatch | Existing owning event-dispatch operation | Existing actual event metadata | Original event unchanged, plus diagnostic observation | Dispatch is observable even with no subscribers; no invented consumer success |
| Follow nested or repeated work | Existing nested/retry invocation only | Known identity/context and actual elapsed time | Distinct observations with truthful provenance | Caller context is restored; legitimate repeats remain visible |
| Survive diagnostic or postcommit failure | No new business retry/transaction | Actual original failure/outcome and independent status | Failed/degraded observations, not fabricated rollback/commit/publication | Original result/throwable and authoritative business state remain unchanged |

## Validation and permissions

This instrumentation grants no execution/read authority and emits no new authoritative Workflow events. Use actual
trusted context; caller metadata cannot impersonate an actor or source. Explicitly select useful safe payload fields
where justified, excluding credentials, provider material, object/result dumps, transcripts and hidden reasoning.
No pipeline redaction follows emission. Preserve package-owned mandatory audit/credential boundaries and one shared
bus graph, including trusted console composition from TASK-00446.

Guard diagnostic projection/normalization/handler work through TASK-00451; independent status must remain bounded
and non-recursive. Native traces contain no deliberately collected stack arguments/locals. Observations are not
transaction participants, required-effect outboxes or evidence acceptance.

## Acceptance criteria

- [ ] Actual shared command/query/event paths emit native lifecycle observations for successful, failed, nested,
  non-HTTP/worker and subscriber-free dispatch without ordinary sampling or missing invocation families.
- [ ] Native identities/type/time and available trusted metadata are retained; unsafe payload/result serialization
  is absent, missing relationships are explicit and caller context restores correctly after nested failures.
- [ ] Results/throwables, subscriber execution/order, lazy routing and package event ownership remain unchanged;
  no observation causes a second business dispatch, transaction or retry.
- [ ] Returned/failed/retried/replayed and confirmed committed/published facts are distinguished according to actual
  owner evidence, including a failure after business commit. Equal messages/timestamps are not deduplicated.
- [ ] Diagnostics failing before, during or after the observed call preserve the original result and independent
  degraded status without recursively instrumenting the failure channel.
- [ ] Owned behavior/integration checks and full `./bin/build` pass; configuration inspection remains direct tooling.
