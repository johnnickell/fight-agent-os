# Complete independent Build delivery through upstream agents and retire replaced launchers

## Outcome

An explicitly authorized local Build journey executes Work, independent Review, applicable independent QA,
repair and authorized Land through upstream agents, with unchanged evidence requirements and no routine Python
stage dispatch. Complete TICKET-00130's replacement rather than retaining a permanent dual launcher. John
approved this bounded slice on 2026-11-02; implementation remains unstarted.

## Scope

- Extend TASK-00560's qualified session-local stage admission to actual Review/QA/Land owners, not merely
  renamed advice-only assistant profiles. Each role receives the tools/effects its responsibilities require,
  governing context and bounded independent request/evidence pointers, never Engineer conversation inheritance.
- Preserve canonical reports, exact candidate identity, per-role provider/model/thinking pins, selected checkout,
  one Compose runtime, shared repair accounting and authorized delivery/cleanup. Build stays the sole local
  stage/evidence coordinator; upstream owns execution, not a second workflow scheduler.
- Reconcile actual upstream lifecycle, finite stage deadlines, cancellation/provider failure, shutdown/reload and
  resumed coordinator state before advancing or replacing a worker. Do not casually reuse an old assessor's
  session as a fresh independent verdict or replay uncertain publication/cleanup effects.
- Follow successive eligible stage agents in one native Herdr parent with the existing verified worktree/log
  context. Preserve passive observer/custody boundaries. Display failure cannot trigger execution substitution.
- Update Build skill, actual callers, stage definitions, package contents and runnable adoption/help together.
  Qualify private installed layouts and document deliberate everyday adoption; active journeys do not silently
  migrate and global packages/settings/trust never change automatically.
- Inventory real surviving Python/process-monitor callers after replacement qualification. Remove replaced
  launch machinery, redundant adapters and obsolete owning checks/docs. Retain a non-Build path only for a
  demonstrated live caller, not hypothetical compatibility. No separate cleanup framework or delivery queue.
- Out of scope: application-managed Runner/server-side grants, sandboxing, broad release-subject dispatch,
  automatic installation, upstream worktree cleanup, new scheduler, AGENTS browsing and new LOGS controls.

## Validation and permissions

Trust session-specific launch admission, not agent names, model-authored selectors, pane state or shared environment
mutation. Each worker must hold the correct independent workflow/effect/TASK/checkout; concurrent sessions cannot
inherit/overwrite each other's authority. Preserve the parent invocation's publication scope and all existing
role/resource obligations. A canonical report must come from its actual independent owner, on the correct candidate;
SDK `completed`, `steered`, exit status, missing reports and display labels cannot substitute for ACCEPT/PASS.

Failed/aborted workers, unsupported capabilities, timeout and uncertain liveness hold affected advancement until
reconciled. Rootless/foreign/nested records remain refused. Reader close is passive; upstream parent runtime
shutdown may abort agents. Never claim OS isolation or managed Execution delivery. HTTP/database permissions,
migrations and new Domain events are N/A; existing local stage permissions and lifecycle contracts remain.

## Acceptance criteria

- [ ] A real Engineer -> fresh independent Review -> applicable fresh independent QA -> authorized Land journey
  uses upstream workers. A bounded repair loop preserves the original shared allowance and fresh assessors.
- [ ] Every role has correct trusted session-local workflow/effects/TASK/checkout and pinned provider/model/thinking;
  simultaneous SDK contexts cannot leak or overwrite roles through process-global state.
- [ ] Canonical Review/QA reports come only from independent owners and match the candidate. Negative/missing/
  wrong-candidate reports, provider errors and SDK terminal states cannot advance Build improperly.
- [ ] Timeout, cancellation, failed/aborted/steered workers, shutdown/reload and resumed coordination yield honest
  outcomes; no duplicate execution/publication or old assessor reuse masquerades as a fresh verdict.
- [ ] One native Herdr parent follows successive workers and existing verified runtime context without reopening
  panes. Lost visibility cannot replay a worker, weaken custody or change the executor/result.
- [ ] Actual Build default/callers, stage profiles, package contents and adoption instructions agree on upstream
  execution. Private installed qualification passes; ordinary installation remains an explicit safe-boundary action.
- [ ] Caller inventory and replacement evidence justify deleted launch code/adapters/checks/docs and every retained
  non-Build monitor path. No permanent fallback engine or unused compatibility layer remains.
- [ ] Direct owning Harness checks, real native/installed interaction and inspected captures, normal full gate and
  independent Review/applicable QA cover the replacement; fresh/reused evidence and delivery limits are explicit.
