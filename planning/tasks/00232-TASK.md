# Operate controlled cohort changes and exclude old writers

## Outcome

Provide protected, directly qualified operations for quiescing and switching a current-contract Agent cohort,
advancing its generation and excluding incompatible binaries at storage or a trusted boundary they cannot bypass.
Restarted workers cannot rely on startup readiness; already admitted effects cannot gain stale authority.

## Scope

- In scope: Actual deployment/storage admission tools selected in TASK-00227; complete participant inventory,
  protected quiesce/switch/restart flow, conflicting cohort fence, monotonically advancing generations, independent
  witness binding, actual old-writer access exclusion, external-call drain/fencing and safe uncertain outcomes.
- Out of scope: Mixed-version support, manufactured legacy consumers, older canonical readers, automatic deployment,
  key/sink implementation, physical database restoration, browser operations or permission to enable incomplete use.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Quiesce and exclude | Protected operator stop/drain/storage-admission operations | Actual processes, credentials/pools, direct connections and admitted work | Secret-free operational observations, not new credential events | Relevant writers and activation/use held; old access revoked at an unavoidable boundary |
| Switch qualified cohort | Protected current-contract switch under exclusive cohort fence | Complete stored state, actual participants, independent witness and next generation | Attributable switch outcome, never inferred success from an attempted update | Strictly newer generation for exact incarnation; old delivery/cleanup admission cannot acknowledge |
| Restart or reconcile uncertainty | Explicit authorized inspection/recovery using original state | Durable generation/witness identity, pending work and current composition | Existing recovery facts only when confirmed | Restart without cached readiness; incomplete/uncertain transition remains closed |

## Validation and permissions

Operational switching requires separately trusted operator authority; Super Admin UI rights and Agent HMAC
identity do not grant storage admission. Inventory issuance, name/lifecycle/Permission/policy, destination/key,
worker/discovery/maintenance and all direct administrative paths. Quiesce and drain or fence admitted external
calls before certifying the new composition. Storage/trusted-boundary exclusion must stop old direct connections,
credentials/pools and restarted binaries; installing new code or adding new-code guards alone is insufficient.

Hold the conflicting fence against active transactions. Preserve current-only versions, original correlation,
terminal/tombstone state, slot high-water, receipts, key references and authority epochs. Every switch, including
switch-back, advances generation; never resume an unsupported old contract. Independent witness publication must
bind the exact live incarnation. Partial generation/witness updates and lost acknowledgements stay closed until
independently verified; do not infer rollback from failure or enable via a local flag.

Previously admitted bytes cannot be recalled: actual sink semantics must keep late effects inert, reject stale
acknowledgement and retain original identity for authorized recovery. Activation and every later use need their
independent current controls. A successful switch is not itself enrollment or a grant. Use current finite recovery
semantics without adding human approval to routine retries, and keep secrets, key paths and receipt internals out
of operator output/evidence.

## Acceptance criteria

- [ ] Actual supported tools quiesce every inventoried writer and exclude incompatible binaries/credentials at
  an unavoidable boundary. Restarted workers and direct connections fail with independently unchanged authority,
  operation, audit, order and key-reference state.
- [ ] Cohort switches contend with real in-flight transactions; compatible switch-back advances generation and
  cannot acknowledge old delivery/cleanup admission. Wrong/unavailable participants never become ready.
- [ ] Real admitted calls are drained or fenced; delayed delivery/cleanup has only permitted inert effects,
  stale outcomes reject and exact original recovery remains possible without duplicate issuance.
- [ ] Missing/uncertain generation or witness publication and restart retain the safe hold. Confirmed identity
  and actual composed capability evidence, not an attempted command or ready flag, govern resumption eligibility.
- [ ] Controlled switch guidance identifies exact tool/runtime/package/adapter identities, residual unsupported
  paths and separate activation/use gates; no production enablement or arbitrary-rollback detection is claimed.

## Verification and evidence

Exercise actual storage/admission controls with independent processes and connections, not only package fixtures
or manually edited capability arrays. For real replacement, use the actual excluded binary/credentials and restart
paths; do not manufacture a historical schema or claim an old-format migration. Qualify bounded replacement drills
in explicitly authorized isolated targets, preserving unrelated development/production data. Record before/after
state, commands, versions, timing/exits and actual exclusion/drain outcomes without material disclosure.

Run applicable consumer-bound cohort/service scenarios against real participants plus direct tool probes and owned
behavior tests. No product tests of deployment scripts, configuration, migrations or tests that tooling detects
seeded defects. Run planning/whitespace checks and `./bin/build`; surface warnings and incomplete qualification.
