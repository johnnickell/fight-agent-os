# Organize and archive execution scratch and repair planning references

## Outcome

Organize this repository's ignored `.runs/` material into meaningful top-level categories, archive inactive
material without losing evidence, and repair changed references. Independently verify that planning documents
resolve to the correct current artifacts. John requested this standalone chore as the highest-priority next work;
it does not mark the active execution-boundary TASK complete or authorize Agent launch.

## Scope

- Inventory `.runs/` in the main checkout and the registered TASK-00138 qualification worktree. Identify artifact
  ownership, active consumers, live worktrees/mounts/processes, canonical reports and retention requirements before
  moving anything. Inspect other registered checkouts only if needed to resolve a reference; do not reorganize
  unrelated projects or other owners' work without authority.
- Group new working material under stable categories: `.runs/tasks/<TASK-ID>/runs/<run-id>/` for task execution,
  `.runs/prototypes/<TASK-ID>/<experiment>/` for experiments, and `.runs/archive/<batch>/<original-relative-path>`
  for retired material. Keep justified tool-owned categories documented; no loose logs or ad hoc task/date folders
  directly under `.runs/` after the agreed cleanup. Put the inventory and move manifest under
  `.runs/tasks/TASK-00157/`.
- Preserve canonical `.runs/reviews/<TASK-ID>/` and `.runs/qa/<TASK-ID>/` report locations and their consumers.
  Do not relocate active worktrees, attached images, credentials, running resources or active tool output just to
  make the directory listing tidy. Retain explicit exceptions until safe retirement is separately established.
- Archive inactive scratch with a reversible old-to-new path manifest and file digests. Repair every changed
  operational reference across planning, engineering docs, skills, scripts and retained handoffs. Distinguish
  executable paths from historical command transcripts and original source identities.
- Add a concise authoritative scratch-layout convention and update affected Review/QA guidance so both phases
  verify planning path correctness. Preserve role ownership: Engineer may read its TASK's canonical review/QA
  directories, but only their independent owners publish them. This documents intent, not runtime enforcement.
- Out of scope: deleting evidence, archiving authoritative planning records, automatic removal of Markdown,
  rewriting review verdicts or historical verification claims, broad source refactors, a new production runner,
  MCP implementation, Agent launch, publication, merge or deployment.
