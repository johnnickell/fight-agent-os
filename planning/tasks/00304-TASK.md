# Create and use a custom-template Agent for bounded manual work

## Outcome

An authorized administrator selects a newly published custom template, creates a distinct named Team-bound Agent
through the existing administration journey, then separately assigns useful bounded manual work through the
qualified Harness. This delivers TICKET-00079's way to learn from a new role before designing Workflow support.
One complete browser-creation-to-real-use outcome normally owns one PR; there is no separate creation demo,
per-template certification ceremony or proof-only TASK.

## Scope

- In scope: Extend existing template selection/creation to eligible published custom revisions; exact complete
  preview and confirmation, original creation/status recovery, handoff to existing manual-assignment/session/tool
  owners, safe unavailable/denied/recovery feedback and attributable actual-use evidence.
- Out of scope: Another editor, directory, Agent store, credential path, Team surface, manual-work engine, provider
  client or conversation platform; custom AccessControl Roles, generic grant editing, AI authoring, ancestor review,
  existing-Agent reconciliation, automatic TASK selection, cross-Team delegation or new Workflow routing.

|---|---|---|---|---|
| Select a published custom role | N/A — read-only | TASK-00300's exact published revision and TASK-00257's complete creation preview through existing scoped resource/Team/enrollment owners | N/A — preview grants nothing | Reviewable name, exact revision, one Team, Repository scope, complete desired Permissions and constraints |
| Create the reviewed Agent | TASK-00258's retained creation intent/package operation through TASK-00260's existing browser path | Fresh authority, references, exact intent and original outcome/status | Existing package issuance/assignment and owned binding facts only | One distinct identity/holder binding with pinned revision, complete eligible initial authority and truthful lifecycle state |
| Start separately assigned manual work | Existing human-authorized manual admission/session/tool operations | Current Agent, human delegation, exact context/snapshot, host/provider/disclosure and limits | Actual owning admission/session/tool facts | Useful bounded work by the created Agent, not an invented TASK Workflow |
| Reconnect, stop or inspect the outcome | Existing exact-session recovery/stop operations; read-only status/result queries | Original creation/work correlation, committed state and current visibility | Existing owning lifecycle observations only | Same authorized identity/session or truthful hold; evidence informs a separately reviewed template revision |

Names identify consumed behaviors, not new transport messages or substitute owners. A functional role/persona is
not an AccessControl Role or automatic Workflow registration.
