# Run real HTTPS browser smoke on native GitHub runners and retire its Python setup

## Outcome

Run the existing real browser journeys on a container-free GitHub runner while keeping the local Docker path, TLS, PostgreSQL fixtures, and mail capture. Remove the superseded Python smoke setup.

## Scope

- Port live browser smoke setup to PHP and migrate its callers. Replace GitHub's Nginx and mail-catcher containers with runner-native services. Preserve the PHP-serving route, HTTPS, database and mail-catcher behaviors, and the [browser smoke contract](../../docs/engineering/BROWSER_SMOKE.md).
- Keep smoke owned by frontend verification. Consume the existing production client output, run smoke once when requested, and do not run or depend on the backend PHPUnit pass. Preserve the existing build's smoke behavior until cutover.
- Remove the old Python setup once both supported routes are verified. Leave selection from backend, frontend, and shared inputs, per-pass reuse, and hosted cutover to [TICKET-00149](../tickets/00149-TICKET.md).

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Run the existing browser journeys | Local Docker-backed route or runner-native invocation | Browser outcomes, TLS trust, test database identity, and mail capture | N/A: verification | Report existing journeys; clean up owned disposable services and fixtures |

## Validation and permissions

Preserve real HTTPS and isolated browser trust without insecure fallbacks or global trust changes. Retain test database identity and mail-catcher ownership checks. Keep setup explicit, reports credential-safe, and source unchanged. Cleanup must not touch shared or durable resources. An interrupted run is not successful evidence.

## Acceptance criteria

- [x] GitHub runs the existing journeys with runner-native services and no running containers. Real TLS, guarded PostgreSQL fixtures, and working mail capture are verified.
- [x] The local Docker route still works and demonstrates cleanup after success and a bounded failure. The native GitHub route demonstrates cleanup after a successful run. Neither route may clear unowned data.
- [x] A requested smoke run uses existing client output and runs once without rerunning the PHP suite. Surviving callers no longer need the superseded Python setup.

## Verification and evidence

Record the local and hosted commands, scenario results, runtime topology, and cleanup evidence, including any held or incomplete result. Run the canonical build; verify through owning commands and bounded probes, not product tests of wrappers. Hand off to independent Review and applicable QA.

## Coordination

No prerequisite TASKs. Use the existing client build output; coordinate the handoff with [TASK-00613](00613-TASK.md). Do not wait for the standalone PHP workflow. Planning approval does not select a checkout or authorize implementation or publication.
