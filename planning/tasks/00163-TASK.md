# Screen file sets with bounded discovery and cached judgments

## Outcome

A participating Pi Agent can screen an explicit file list or glob through `jev_read_file`, see independent results
and honest coverage, and reuse valid scoped judgments without repeating a provider call. Deliver bounded larger
investigations and evidence of usefulness as the second slice of [TICKET-00039](../tickets/00039-TICKET.md).

## Scope

- Extend [TASK-00162](00162-TASK.md)'s existing tool, access boundary and shared guidance to explicit lists/globs.
  Narrow candidates with paths, metadata/frontmatter, symbols or graph results where useful; a repository-wide
  pattern is bounded discovery, not a promise that the entire repository was evaluated.
- Set initial per-call ceilings of 50 files, 1 MiB total source, 10,000 visited directory entries and 60 seconds
  overall. Keep the 32 KiB per-file ceiling and shared serialized-request limit, two-request concurrency,
  fifteen-second upstream timeout and configured spending ceilings; the tightest applicable bound wins.
- Bound enumeration itself before evaluation, avoid symlink loops/escapes and deduplicate canonical candidates
  without exposing unauthorized paths. Stop at limits; report that additional candidates may exist rather than
  inventing a complete count. Do not expand a glob through shell execution.
- Return per-file judgments, source identities, threshold outcomes, evaluation coverage and skips/errors. Aggregate
  counts identify their scope and completeness. Use bounded reasons/statuses rather than source excerpts. Excluded
  paths or details may be redacted where the caller lacks permission to see them.
- A positive result or known-target exception for one file never qualifies the rest of the set. Oversized, binary,
  excluded, changed, failed or unvisited candidates remain explicitly unresolved/skipped; no silent truncation or
  chunk aggregation may imply complete source coverage.
- Add an initially 128-entry session-local, bounded cache of judgment metadata only, with least-recently-used
  eviction. Key by caller/authority scope, exact content digest, question/choices, evaluator, rubric and policy.
  Recheck current file/disclosure authorization before lookup/result reuse and re-establish the source digest under
  the same bounded read rules. Changed input/configuration invalidates reuse; failures are not cached as judgments.
- No source-body storage or cross-session cache sharing. Clear cache on session shutdown/reload; cached metadata
  cannot outlive an applicable authority boundary. Cache hits avoid upstream calls but still incur explicitly
  accounted local source checks and must not be counted as new billed evaluations.
- Bound retained result/cache metadata and result presentation through the tool/shared input limits. Batch execution
  respects common session budgets; cancellation stops new dispatch and invalidates late obsolete delivery, retaining
  uncertain charge reservations through the shared capability.
- Extend shared guidance and relevant skill references for batches, coverage and cache semantics. Complete a
  representative comparison against direct reads, including false negatives, unnecessary reads and exceptions.
- Out of scope: hard read interception, arbitrary unbounded corpus scans, cross-session/private-source cache sharing,
  content ingestion, a graph index replacement, general-purpose judgment tools, compaction and workflow routing.

## Validation and permissions

Preserve TASK-00162's independent root/access/disclosure restrictions and 0.70 positive-read policy on every file.
Check current authorization before returning cached content-derived metadata. An old result, a broader caller or
an identical path under another authority scope cannot inherit private evidence. Bind content identity to exact
bytes; check for changes during reads and before reuse. Source bodies never enter normal results or cache entries.

Partial batch completion is not failure of every completed file and is not proof that remaining candidates lack
an answer. Return completed per-file outcomes with explicit incomplete batch coverage. Do not silently continue
beyond count/time/spend bounds or repeatedly retry failed requests. Structural enumeration does not authorize
provider disclosure. Known-target exceptions require their own path/purpose/evidence per file and remain bounded.

Keep cache/session accounting honest on cancellation and uncertain billing. No performance claim may hide local
rereads needed to validate digests, provider costs, exceptions, misses or unsupported cases. The tool remains
read-only with respect to source and performs no shell execution, memory promotion or authority mutation.

## Acceptance criteria

- [ ] Real supported Pi use demonstrates explicit lists and globs, independent yes/no/classification results,
  selective source follow-up and useful coverage/skipped reasons without returning full contents.
- [ ] File/source/enumeration/time/concurrency/spend limits stop work predictably. Include large candidate trees,
  symlink loops/escapes, duplicates, oversized/binary files and denied disclosure; no unbounded traversal occurs.
- [ ] A valid current cache hit avoids an upstream call. Changed source, question, evaluator, policy or authority
  prevents stale reuse; current denied access cannot expose prior private judgments or metadata.
- [ ] Cache size/metadata remain bounded, contain no source bodies and clear on lifecycle changes. Hits and uncertain
  billed calls are accounted for without double counting or inventing zero cost.
- [ ] Partial provider failures, cancellation and late responses preserve valid completed outcomes and clearly mark
  incomplete coverage. A positive/exception for one file never qualifies an entire set.
- [ ] Representative parent/child investigations follow the shared batch guidance. Unsupported session propagation
  remains explicit, and instruction compliance is not described as enforced interception.
- [ ] A reproducible bounded comparison reports main-Agent context saved, total available Jev/main-Agent costs,
  latency, missed relevant files, unnecessary reads and exception/exclusion frequency. Preserve negative results
  and distinguish controlled fixtures from live model observations; no savings or recall guarantee is presumed.
