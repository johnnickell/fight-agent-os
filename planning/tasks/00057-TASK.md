# Deliver authoritative owned-session visibility

## Outcome

The authenticated Active Sessions route and versioned API derive actor, owner, and current session from `CurrentPrincipalProvider`, use package `ListActiveSessions` to return only usable owned refresh sessions, and present authoritative creation/activity/idle/absolute/remembered/current state with deliberately coarse bounded device metadata captured at Agent OS session creation.

## Scope

- In scope: Coarse session-presentation metadata model/persistence/migration/parser; activation/login metadata capture and safe missing-data fallback; authenticated paginated listing Action/query mapping/explicit View/OpenAPI; principal-derived actor/user/current session; fixed deterministic ordering/bounds; typed client feature service; replacement Active Sessions route/page; current/remembered/device/activity/expiry presentation; loading/empty/error/pagination states; PostgreSQL/HTTP/client/component/accessibility/redaction tests.
- Out of scope: Raw User-Agent/IP/geolocation/fingerprinting, credential or used-digest exposure, current/other-session revocation, cross-user administration, logout everywhere, editing session lifetimes, live presence claims, background tracking, broad browser automation, and changing package session authority.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Capture coarse presentation metadata | N/A — Agent OS session-response orchestration | Parse bounded request presentation input after successful activation/login session creation | N/A — no domain event | Idempotent sidecar metadata records browser family/device class or safe unknown for stable session ID |
| List owned active sessions | N/A — read-only API | `ListActiveSessions(actorId, userId, currentSessionId, pagination)` | N/A — no domain event | Explicit paginated View returns only current owner's usable sessions and safe presentation metadata |
| Identify current session | N/A — query input | Read refresh-session ID from request-scoped current principal | N/A — no domain event | Exactly the session carrying authenticated request is marked current; no client/cookie claim is trusted |
| Render session security page | N/A — client read | Load typed active-session page through shared API client | Client cache/navigation only | User sees truthful coarse activity/lifetime data and current marker without credentials or presence inference |

## Validation and permissions

Declare GET pagination through [TASK-00155](00155-TASK.md)'s source-only `QueryString` plus Validation fields/rules
and consume checked request values without input-only DTOs. Follow [canonical attribute ordering](../tickets/00010-TICKET.md#canonical-action-and-responder-attribute-ordering).
Prove valid/boundary/duplicate/encoded/unknown pagination input and no dispatch on rejection through this real
route. This shared capability does not add sort, filter, deleted-session or identity-selection options to this TASK.

Require TASK-00044 Bearer authentication and resolve one request-scoped `CurrentPrincipalProvider`. Construct package `ListActiveSessions` with actor ID and user ID both equal to the principal user and current-session ID equal to the principal refresh-session ID. Request input may supply only bounded pagination from an allowlist; it cannot select actor/user/current session, administrative mode, arbitrary ordering, or internal fields. Require exact authoritative `READ_OWN_SESSIONS` before package query dispatch as well as package-enforced actor/target ownership; membership in `ROLE_USER` or a JWT claim alone is not authority. The HTTP attribute is an early gate; the Agent OS Application checks the permission on all entry points.

Use package handler/repository for usable-session selection and `SessionView` creation. Map through an explicit HTTP View rather than returning package objects directly. Include stable session ID required for later revocation, coarse device label/structured fields, `created_at`, `last_activity_at`, `idle_expires_at`, `absolute_expires_at`, `remembered`, and `current`. Omit redundant user ID from public View unless a proven client need is approved. Exclude credential/digests/used digests, authentication version/revisions, revoked flags/history, audit/provider data, cookie values, and raw persistence state. Use no-store/private cache policy as selected by API standards.

Capture session-presentation metadata in an Agent OS-owned sidecar keyed uniquely by stable package session ID when activation/login creates a TokenSet. Define a fixed local parser with strict input length, allowlisted browser family and device class (for example desktop/mobile/tablet/unknown), no browser/OS version, no raw header retention, no IP, no geolocation, no canvas/hardware identifier, and no external enrichment. Treat User-Agent as untrusted presentation input, escape output, and use deterministic `Unknown device` fallback. Refresh cannot silently rewrite the original descriptor. Metadata is non-authoritative: capture failure/missing legacy row cannot invalidate or extend a session and must produce safe unknown presentation. Reconcile/delete retention with session expiry operationally without making metadata an alternate session source.

Activity is package `lastActivityAt` from successful refresh rotation, not page views, access-token requests, websocket activity, or inferred online presence. Explain timestamps/session type truthfully in the UI. Render current session distinctly without relying on color alone. Use bounded pagination and one fixed allowlisted deterministic ordering with stable tie-break; expired/revoked sessions are absent under package clock semantics.

Strictly decode client response, use existing API-cache conventions without persisting rows, and replace TASK-00051's truthful Active Sessions landing state. Recreate accepted list/card/table behavior across narrow/wide modes with semantic headings, timestamp labels, current/remembered explanations, loading/empty/failure/pagination, keyboard/focus, status announcements, target/reflow, themes, and reduced motion.
