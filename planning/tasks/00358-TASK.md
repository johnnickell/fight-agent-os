# Explicitly create or apply reviewed Planning changes

## Outcome

An authorized human explicitly creates or applies a reviewed single-artifact Planning candidate through the same
semantic operations as direct editing, or receives a preserved conflict with no false acceptance. Stable command
identity makes lost-response recovery inspect the original committed result rather than repeat a mutation.

## Scope

- In scope: Exact candidate review/confirmation, supported semantic create/revision composition, current authority
  and revision checks, atomic accepted state/audit/intent, safe committed-result inspection and recovery.
- Out of scope: New Planning domain/allocator, whole-document replacement, atomic decomposition batches owned by
  TASK-00359, automatic acceptance, lifecycle bypass, template publication, coding execution or Git effects.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Review exact change | N/A — protected preview | Complete candidate version, proposed semantic changes, current constraints and expected revisions | N/A | Inspectable human intent; preview grants no mutation authority |
| Create or apply | Explicit human semantic command/orchestration with stable identity | Revalidate candidate, actor, scope, mode and all affected revisions | Actual owning Planning events and accepted proposal linkage | Complete approved change and required audit/intent, or rollback |
| Resolve uncertain apply | Original-command reconciliation where needed; ordinary reads remain queries | Actual committed result, identities and current visibility | Only confirmed owning facts | Original outcome before another Apply is offered; no mutation replay from GET |

## Validation and permissions

Consume TASK-00357's exact candidate, not model-authored success text. Independently authorize propose, read, create,
revise and guarded lifecycle actions under current human scope. Preserve acting-Agent provenance without using the
Agent as human approver. Any candidate edit changes the reviewed version. Bind confirmation to actor, target,
operation, candidate and applicable revisions/expiry; no reusable generic approval token. Guarded reopen/restore,
waiver, archive or closure remain explicit owner operations, never inferred from generated content.

Reuse TASK-00085–00095 semantics and TASK-00103 authority/fences through TASK-00356/00104. Database mutation before
verified cutover is refused, and unavailable database authority never falls back to Markdown. Revalidate expected
aggregate, child/relationship/constraint and applicable queue revisions immediately at commit. Persist actual
semantic Planning state, proposal acceptance/result linkage, required audit and effect intent on the canonical
shared connection. Expose precise transaction participants rather than nesting already-transactional handlers or
committing proposal acceptance afterward as a false success. Missing participant guarantees block the operation.

References/identities come from existing owners, not model-generated IDs. Research/prototype acceptance uses
TASK-00087's verified durable evidence; external storage preparation remains outside the business transaction and
failure cannot produce an authoritative unverified reference. Acceptance promotes findings only, not code.

Stable command identity binds an exact payload and original result. Double submit/lost acknowledgement resolves
that result; changed payload under the same identity rejects. Unknown commit outcome holds new Apply until
reconciled. Status is read-only and access-checked even after revocation. Preserve rejected/stale candidates,
accepted answers and safe history; no silent overwrite, automatic merge or request retry. Applying the final
proposal completes only that authorized Planning operation, never starts decomposition, TASK work or publication.
