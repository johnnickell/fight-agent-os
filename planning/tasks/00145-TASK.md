# Enable opt-in trusted local HTTPS

## Outcome

Serve the existing root and CSRF bootstrap at `https://localhost:18443` through an opt-in local Docker TLS
entrypoint, with explicit reversible host trust and no weakening of the existing HTTPS/origin checks.
The maintainer authorized this early slice of TASK-00063, this checkout on a feature branch, and local CA trust
enrollment if needed. The integrated production-like security envelope remains with TASK-00063 and its blockers.

## Scope

- In scope: Pinned local TLS tooling; mkcert localhost certificate enrollment; Docker TLS-to-FastCGI delivery;
  setup/up/status/down/remove wrappers; ignored leaf certificates and private keys; preserving the CSRF key and
  unrelated `.env` fields while setting the local HTTPS origin; documentation and direct transport verification;
  the maintainer-authorized existing `.gitignore` change to ignore `.env` instead of `.env.local`.
- Out of scope: Public DNS/certificates/deployment, completed authentication journeys, production proxy trust,
  CSP/HSTS/rate-limit/security-envelope completion, global CA removal without separate explicit authorization,
  database credential changes and database resets.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Enroll local HTTPS | `./bin/https setup` | Inspect mkcert, ignored configuration and existing CSRF key | N/A — infrastructure only | Explicit mkcert CA trust, localhost leaf files, update only browser origin |
| Start secure local access | `./bin/https up` | Validate origin/key and leaf files | N/A — no domain event | Loopback-only TLS on 18443; PHP receives server-owned HTTPS metadata |
| Inspect local access | `./bin/https status` | Certificate validity and a verified TLS root request | N/A — no domain event | Status only; never display credentials or full Compose configuration |
| Stop/remove local access | `./bin/https down`, `./bin/https remove` | N/A — explicit infrastructure lifecycle | N/A — no domain event | Remove only TLS services and optionally owned leaf files; preserve databases, `.env`, and shared CA |

## Validation and permissions

Setup is opt-in and may require a human system password prompt; never collect passwords in chat. mkcert's CA
trust is broader than the localhost leaf and may already be shared by other projects. Do not automatically
uninstall or delete that CA. Leaf files live under ignored `.runs/https/`; private material never enters Git,
HTTP responses, or evidence. Require ignored `.env`, a valid existing independent CSRF key, and exact local
origin before startup. No secret fallback or automatic CSRF rotation. Only the TLS port is exposed for the new
services; FastCGI has no host port. Reject wrong Host, cross-origin bootstrap and insecure bootstrap, even with
spoofed forwarding headers. Preserve existing HTTP on 18087 for the root only. No application permissions or
business mutations apply to these infrastructure commands.

## Acceptance criteria

- [x] Setup enrolls or reuses mkcert trust, generates only a localhost leaf, and updates origin without changing other settings or the key.
- [x] HTTPS serves the existing root and CSRF bootstrap with certificate verification enabled and the existing Secure/HttpOnly/SameSite cookie contract.
- [x] Wrong authority and cross-origin/insecure bootstrap are denied; forwarding headers cannot promote HTTP or change the HTTPS authority.
- [x] FastCGI is not published to the host; the new TLS listener binds only to loopback.
- [x] Missing/invalid local configuration fails safely; status/down/remove and re-enrollment are documented and directly exercised without affecting databases or shared CA trust.
- [x] Documentation distinguishes local TLS from complete browser authentication and the deferred security envelope; direct checks and `./bin/build` pass with limitations recorded.
