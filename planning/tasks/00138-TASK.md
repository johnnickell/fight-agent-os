# Define and qualify the terminal execution sandbox boundary

## Outcome

Produce the human-readable PHP ownership and sandbox contract, then directly evaluate hardened local container primitives against it. Record failures and unsupported requirements as blockers, never as sandbox readiness.

## Scope

Deliver the terminal-first slice of [TICKET-00032](../tickets/00032-TICKET.md). Preserve its security, PHP ownership,
durability and fail-closed contracts. Browser presentation, database Planning cutover, review/QA/publication,
release and deployment are outside this TASK. An unresolved required sandbox property blocks live Agent launch.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Define and qualify the terminal execution sandbox boundary | Scoped console/application operations; N/A for read-only qualification | Authoritative eligibility/state or measured capability evidence | Semantic Workflow facts only after verified effects; N/A for research | Only owned, explicitly authorized resources; research has no Workflow authority |

## Validation and permissions

Use package-owned identity/authorization contracts and canonical contained paths. Reject stale grants, task/context
revisions, owners and unsupported profiles. Models cannot expand policy. No shell command, skill or observation
creates authority. Define precise PHP interfaces and failure outcomes before their implementation.

## Acceptance criteria

- [ ] Settle operator enrollment, revision-bound Markdown eligibility, PostgreSQL Workflow authority, provisioner ownership, role isolation and broker boundaries before implementing start.
- [ ] Identify the supported host, immutable image identities, permitted mounts, test services, network/credential paths and resource ceilings.
- [ ] Probe two independent disposable filesystem/database environments using owning tools; never attach an autonomous Agent to an unqualified profile.
- [ ] Record observed protections, residual risks and exact unresolved requirements; do not claim a local probe qualifies native Linux or hostile workloads.

## Verification and evidence

Application changes require meaningful behavior tests and the full `./bin/build`; infrastructure is qualified
directly through its owning tools. Keep scoped raw evidence in `.runs/`, summarize durable outcomes here, and
distinguish observed behavior, limitations and unverified platforms. Formal independent review remains separate.

## Coordination

Dependency order is explicit in frontmatter. The current checkout is authorized for preparation. No autonomous
Agent launch is allowed before required profile qualification and authority contracts are implemented and verified.
