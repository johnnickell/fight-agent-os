# Define and qualify tool-mediated execution boundaries

## Outcome

Settle the tool-mediated Engineer, trusted-controller and restricted-check contracts, directly qualify their
minimum mechanisms, and hand explicit implementation responsibilities to TASK-00139–00142. Preserve failed and
partial historical qualification; a usable file-only prototype is not production readiness.

## Scope

Deliver the terminal-first slice of [TICKET-00032](../tickets/00032-TICKET.md). Preserve its security, PHP ownership,
durability and fail-closed contracts. Browser presentation, database Planning cutover, review/QA/publication,
release and deployment are outside this TASK. John's October 6 amendment replaces the first Engineer-root/private-
engine VM strategy with [tool-mediated execution](../../docs/engineering/TOOL_MEDIATED_EXECUTION.md): scoped source
and scratch writes, TASK-only Review/QA reads, bounded Lead/Engineer messages, trusted Git/check operations and no
Agent shell. Candidate checks require a separately qualified restricted execution profile. The complete MCP suite
is not a prerequisite for one capability; the prototype is not a managed Workflow or acceptance of a real TASK.

In scope: explicit risk/authority/permission contracts, minimum file/handoff qualification, selection and scoped
qualification of a supportable restricted-check mechanism, and a clear downstream implementation handoff. Actual
PHP lifecycle, protected file/check service composition, production role sessions and recovery belong to the
existing downstream TASKs. Do not duplicate them inside a disposable Runner or close this TASK on docs alone.
