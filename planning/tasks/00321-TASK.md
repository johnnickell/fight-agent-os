# Install and maintain exact Harness releases

## Outcome

Users can deliberately install, update and roll back one exact independently versioned Harness package across
repositories, while checkout-loaded development stays visibly mutable and existing sessions retain their identity.

## Scope

- In scope: Release-ready Pi npm package from the canonical monorepo's `harness/` source, exact release provenance
  and compatibility inspection, explicit personal install/update/retained-release rollback and development mode.
- Out of scope: New branding, release automation platform, automatic personal configuration changes, credentials,
  connection trust, general database Skill distribution, snapshot/session engine and managed Agent launch.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Install an exact release | Explicit owning package-tool install | Exact source/version/digest, compatibility and intended personal scope | Safe package-operation observations; no fabricated Domain event | Deliberate installation of one identified compatible release |
| Update or roll back | Explicit exact update or reinstall retained release | Current/target package identity and original operation state | Attributable installation outcome or uncertainty | Future loads select the requested release; active history remains intact |
| Use checkout development | Explicit checkout-mode selection | Canonical source identity, mutable content and compatibility | Safe mode/inspection observations | Visibly mutable development loading, never silent production fallback |
| Inspect installed facts | N/A — read-only | Actual package source/version/digest/mode and support | N/A | Safe reproducible facts for connection and snapshot consumers |
