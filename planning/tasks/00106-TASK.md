# Independently accept the Planning workspace handoff

## Outcome

An independent `design-review` invocation renders and adversarially challenges the registered Planning workspace candidate, separate design revisions resolve every blocking finding, re-review returns `accept`, and durable planning evidence records a production-ready handoff without making disposable prototype code authoritative.

## Scope

- In scope: Reviewer independence and intake; render candidate/alternatives; trace all repository/context/Planning/Roadmap/archive/migration routes, tasks, Permissions, states, modes and viewports; challenge hierarchy/information architecture, copy, semantic forms, confirmations, stale/conflict recovery, provisional reorders, authority honesty, responsive behavior, keyboard/focus/semantics/announcements/contrast/reflow/motion and handoff completeness; classify findings; coordinate separate design revision; re-review; final verdict and durable accepted handoff.
- Out of scope: Reviewer editing/repair, production React/API implementation, changing approved product scope, broad accessibility certification, private/real data, browser Agent/session design, merge/deployment approval and retaining prototype source as production dependency.

## Validation and permissions

Reviewer must not have authored or revised TASK-00105's candidate. Intake requires brief, alternatives, selected rationale, runnable artifact, route/task/Permission/state matrix, provenance/licenses, responsive/theme coverage, evidence claims and implementation handoff. Missing material blocks or qualifies review.

Render the candidate rather than trusting screenshots/source alone. Trace repository registration/selection/switch, checkout/context/configuration/conflict, every artifact hierarchy/detail/history/evidence/dependency/render, semantic edit, guarded lifecycle/relationship/archive, Roadmap/queue and migration authority interaction. Cover loading/empty/denied/not-found/stale/partial/conflict/unavailable/offline/frozen/failure/success and dirty-form behavior across narrow/wide and accepted themes.

Challenge server-authority language, expected revisions, safe stale recovery, no generic document/status path, exact confirmations, no cascade, queue reason fidelity, provisional drag rollback, rehearsal/render non-authority, source freeze, permission filtering and deferred Agent/claim/execution boundaries. Any control that implies unsupported capability or successful client-only mutation is blocking.

Explicitly review keyboard order/operation, focus visibility/obscuring/restoration, dialog focus, labels/instructions, headings/landmarks, live status/error announcements, contrast, target size, zoom/reflow, reduced motion, tables/dense graphs/forms at narrow width and long content. Automated/screenshot/manual evidence does not establish universal conformance; record limitations.

Findings include observation, reproduction/evidence, affected user task/requirement, severity and recommended correction. Reviewer does not edit. `revise` returns to a separate `/skill:design`; changed candidate receives independent re-review. Completion requires `accept` with no blocking finding silently waived.
