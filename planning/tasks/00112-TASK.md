# Operate migration and Planning authority

## Outcome

Authorized humans can inspect immutable source inventory/mapping and complete rehearsal reports, approve an exact clean rehearsal, invoke guarded cutover or permitted pre-first-write recovery, understand current authority/failures, and render read-only Markdown without mistaking rehearsal/output for authoritative Planning.

## Scope

- In scope: Repository migration/authority page; current mode/context/source-freeze/recovery-boundary summary; source inventory/mapping report status; rehearsal launch/progress/stage/result/detail/discard for owned attempts; complete comparison/accounting/warning/rejection presentation; approval readiness/exact confirmation; cutover readiness/exact confirmation; pre-first-write recovery state/action; failed/uncertain result recovery; frozen-source integrity diagnostics; read-only artifact/Board/Roadmap/index render links/download; typed TICKET-00028 API mappings; distinct Permission states; responsive accessible components/catalog evidence.
- Out of scope: Client import/validation rules, warning waiver/repair, source editing, automatic retry/fallback, scheduled/agent-only cutover, dual write, post-first-write reverse migration, backup implementation, source retirement/deletion/archive/branch/PR, production cutover execution in this implementation TASK and browser conversations.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Inspect migration readiness | N/A — read-only interaction | Get mode/source/manifest/mapping/report/schema/context/currentness and blockers | N/A — reads emit no event | Exact safe state/reasons display without implying rehearsal authority |
| Run/review rehearsal | Dispatch exact rehearsal/discard command | Query stages, complete accounting/comparisons and attempt ownership | Rehearsal operational evidence only | Owned clean target is exercised; Repository authority remains unchanged |
| Approve rehearsal | Dispatch exact human-confirmed approval | Preview clean report and bound source/version/digest/impact | Migration-approval event | Approval binds one exact subject and changes no Planning authority |
| Cut over/recover | Dispatch exact human-confirmed cutover or allowed recovery | Preview source/approval/target/mode/recovery boundary | Authority event on success | Server performs atomic transition/recovery; UI reflects result only after authoritative query |
| Render Markdown | N/A — read-only representation | Render permission-filtered typed Views with authority/revision/template metadata | N/A — render emits no event | Labeled representation/download is available but cannot be applied as mutation |

## Validation and permissions

Display server-provided stages, completeness, counts, digests, versions, mappings, warnings/rejections/mismatches and readiness reasons; frontend never decides clean/approvable/cutover-ready, compares source semantics or hides blockers. Rehearsal state is visually and semantically distinct from authoritative Repository Planning. Rendered output is distinct from source and authority.

Approval and cutover are separate actions/Permissions/confirmations. Confirmations show Repository/CutoverId, source commit/tree/manifest, mapping/report digest, target/mode, current revision, impact, expiry and recovery boundary as safe server Views. An agent/process actor cannot be represented as required human approval. Any stale/changed fact returns to readiness without silent retry.

Cutover UI enters a guarded pending state but never claims success until authoritative mode/result query confirms. Closing tab/network loss does not infer failure/success; uncertain outcome resolves current operation identity before offering retry. On failure show stage and safe recovery while preserving mode. Do not offer warning waiver, best-effort import, partial apply, scheduled cutover or dual-write controls.

Pre-first-write recovery appears only when server says eligible and clearly warns that the first database Planning write closes it. After closure, show backup/restore/forward-repair guidance with no reverse/fallback action. Frozen-source drift is a warning/blocker and never ingested/reverted. Source retirement/deletion/branch/PR controls do not exist.

Require distinct preview/report, rehearsal, approval, cutover/recovery and render Permissions. Unknown/stale principal/context/mode fails closed. Safe UI omits full source/event payloads, credentials, database details, absolute paths and hidden records. Offline/cached views are read-only and cannot approve/cut over.
