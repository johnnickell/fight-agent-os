# Configure and inspect allowed provider choices

## Outcome

Installation administrators configure exact allowed generative provider/model choices, and authorized profile,
template and snapshot callers inspect safe compatible references before any session or paid generation exists.
Saved configuration remains distinguishable from actual qualified readiness.

## Scope

- In scope: Protected configuration/revision and bounded inspection path; OpenRouter and local openai-codex
  selection metadata, allowed-model references, exact runtime compatibility, qualification provenance, selection
  generations and shared reference fencing for real writers.
- Out of scope: Provider credential material, account enrollment, live requests, budgets/attempt execution,
  session switching, another profile/role resolver, Jev Decisions or additional providers/routing.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Configure permitted choices | Authorized expected-state connection/catalog revision | Current installation authority and exact existing definitions | Committed owned configuration facts | Atomic non-secret configuration/history and required audit |
| Inspect usable references | N/A — authorized read | Scope-filtered models, exact compatibility and qualified/unavailable facts | N/A | Safe choices for real profile/template/snapshot consumers, no session or credential access |
| Reconcile an uncertain change | No blind replacement | Exact original operation/revision under current read authority | N/A for status | Original outcome without duplicate revisions or a false live-readiness claim |

## Validation and permissions

Consume TASK-00322's exact trusted installation/connection identities. Provider connections remain distinct from
Agent OS connection profiles; reuse their authority facts, not their schema as a provider credential store. Require
current intent-specific installation management authority for configuration and current scoped access for reads.
Administrative access, a model label or permission to read a Repository never authorizes provider disclosure.

Bound catalog entries, identifiers, queries and revision history. Select only explicit approved endpoints/accounts/
models; repository instructions, model output, redirects and discovery cannot add a provider or alter routing.
Retain exact source/runtime/model/qualification provenance and supported limits. Keep credentials and protected
handles outside safe Views, profiles, snapshots, logs, events and model context. Secret material remains with the
protected provider owner: TASK-00520 supplies OpenRouter lifecycle/custody consumed by TASK-00346;
TASK-00347 retains independent Pi-owned local authentication. Neither belongs to this catalog.

Distinguish configured, allowed, compatible, qualified, denied and unavailable states. Early catalog facts do not
require completed snapshots, Agent sessions or live-provider consumer acceptance. Missing current qualification
must be explicit and cannot be converted to ready by configuration alone. Exact readiness observations from the
provider owners invalidate when relevant configuration/runtime changes; they are not cached grants. No inspection
implicitly probes a model, refreshes authentication, enrolls an account or initiates paid work.

Persist owned current state, immutable revisions, required audit and original mutation identity on the ADR 0002
shared connection. Real catalog changes and profile/template/snapshot reference participants share complete
expected-state/reference fences. Changed-away-and-back generations reject stale intent. Preserve referenced
history; no automatic purge, silent model substitution or mutation of a retained session. Initial selection and
explicit continuation remain with existing profile/snapshot/session owners.

  model catalogs; actual qualified readiness stays separately attributable.
