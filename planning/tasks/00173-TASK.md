# Reuse judgments when evidence and authority still match

## Outcome

Authorized Pi 1.1.0 callers avoid repeated provider evaluation when a prior typed judgment still answers the same
question over unchanged evidence and context. Current authority and disclosure checks remain mandatory, and
inspection makes reused provenance, freshness and measured savings explicit.

## Scope

- Extend [TASK-00172](00172-TASK.md)'s complete general judgment/investigation path, reusing TASK-00163's bounded
  metadata-cache mechanics. Do not build a second provider, source resolver, permission policy or independently
  privileged result service. Safe same-job continuation remains TASK-00172's responsibility.
- Add optional reuse across separate bounded inquiries in the same qualified authenticated session/scope. Retain
  an initially 128-entry session-local LRU metadata cache, bounded by the admitted metadata-size limits. Store typed
  results, coverage, provenance, source/context digests and authorized reference metadata; no source bodies,
  credentials, raw tool/query output or hidden reasoning. No cross-session or cross-principal cache sharing.
- Clear disposable cache on shutdown/reload and authority-boundary changes. This does not erase TASK-00172's
  separately protected resumable progress or unresolved usage reservations. Historical receipts remain available
  only through their owning authorized retention/access capability, not a covert persistent cache.
- Key entries by exact evidence bytes/revisions and evaluated subset; question/choices/anchors/context/preset;
  evaluator and relevant configuration; source/disclosure/consumer policy; and authenticated caller/session/
  repository scope. Include discovered-set/coverage identity when an aggregate claim depends on enumeration.
  Identical file text alone is not sufficient when any governing context or population changed.
- Recheck current access and provider-disclosure policy before exposing cached derived metadata. Re-establish
  source identity through the same bounded contained resolver and account for the work. A digest check may require
  rereading source; cache savings mean avoiding a qualified provider call, not eliminating every local read.
  Revoked authority, moved/changed sources, symlink changes, unavailable identity or stale policy cause a safe miss
  or explicit denial, never fallback to an older caller's result.
- Reuse only strictly validated results with coverage suitable for the new request. Failure, invalid/unavailable
  output and uncertain dispatch are not cached as judgments. Partial or unknown results can never satisfy a request
  for a complete determinate answer; reuse of a completed source result still leaves remaining coverage explicit.
  Never turn not-applicable, unknown or incomplete into false, a low score or measured correctness.
- Treat existing immutable receipt questions as historical evidence bound to their observation identity and time.
  Live application/MCP/SQL observations remain fresh by default and are not made reusable merely by matching a
  request string. This TASK executes none of those operations; reuse never replays a source operation. Later
  TICKET-00043 integration must preserve its explicit freshness/authority contract.
- Return the original evaluation identity/time plus current validation time, cache outcome and current coverage;
  distinguish fresh evaluation from reuse without copying an old usage charge into new billed usage. Repeated hits
  cannot double count cost. Report local lookup/revalidation work and measured/estimated/unavailable savings
  separately; model confidence is not a correctness rate or guaranteed financial saving.
- Protect metadata and reference inspection by current scope, including existence and aggregate information.
  Bound lookup, invalidation, presentation and cache growth. Eviction, corruption or a missing entry safely yields
  a fresh-admission path under remaining limits or an explicit unavailable outcome, never an unbudgeted call.
- Propagate stop/reload/generation changes through lookup, revalidation and dispatch; stale hits cannot update the
  active investigation. Concurrent misses use the shared evaluator's reservation/concurrency rules; do not promise
  exactly-once billing or retry an ambiguous provider call to populate the cache.
- Exclude cross-user/session caches, raw-source persistence, automatic retries for preferred answers, memory
  ingestion, production observation collection, new permission grants and automatic threshold/policy tuning.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Reuse a qualified answer | N/A: query is read-only with respect to source/domain state | Current authority, exact evidence/context identity and cached validated judgment | Reuse/miss/denied observation | Bounded local revalidation; no upstream call on a valid hit |
| Handle changed inputs | Admit a fresh evaluation only under existing limits | Changed source/context/policy/coverage and remaining budget | Invalidation and fresh-evaluation observations | Optional authorized provider usage, with no hidden retry |
| Inspect provenance and savings | N/A: bounded inspection | Original evaluation and current validation facts, coverage and available usage | N/A: inspection grants no authority | Compact authorized metadata; historical and current evidence distinguished |
| End a cache lifecycle | Evict/discard disposable scoped entries | Active scope/generation and metadata bounds | Lifecycle observations where applicable | Cache metadata cleanup only; durable progress/usage remain owned separately |

## Validation and permissions

An answer or reference derived under earlier permission is not itself permission. Apply current source and disclosure
policy before lookup results leave the service, bind every hit to the authenticated invocation, and reject forged
identity/context keys. Source text and cached choices cannot execute operations or redefine policy. Retain
TASK-00171's explicit statuses, qualified caller boundary and specialized-consumer rules. Evidence freshness and
coverage remain constraints even when reuse would be cheaper. Unknown cost is not zero, and unverifiable evidence
is not an exact match.

## Acceptance criteria

- [ ] Actual Pi 1.1.0 repeat inquiry can reuse a validated answer after current authorization/evidence checks and
  avoid an upstream call, preserving original provenance and a new validation timestamp.
- [ ] Changed source, question/context, choices/anchors, preset, evaluator/configuration, policy or aggregate
  population prevents inappropriate reuse; unchanged text alone cannot satisfy changed context.
- [ ] Revoked permissions, forged callers, cross-session/principal access and denied disclosure do not reveal
  cached private answers/references. Source identity races and symlink changes cannot serve stale results.
- [ ] Unknown/partial/not-applicable/failure outcomes never become complete determinate answers; historical receipt
  answers stay historical, live observations are fresh by default and no operation is replayed.
- [ ] Cache metadata stays within entry/size/scope bounds, contains no raw bodies and clears on qualified lifecycle
  changes without destroying progress or usage obligations. Eviction/corruption remains a safe miss or explicit failure.
- [ ] Cancellation and concurrent misses preserve current-generation delivery, conservative budgets and uncertain
  billing. Cache hits never count as new billed evaluations or bypass admission for fresh calls.
- [ ] Representative single-source and many-stage comparisons report actual hit/miss/invalidation rates, coverage,
  correctness limitations, main-context volume, local revalidation work, total available costs and latency.
