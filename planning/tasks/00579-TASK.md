# Correct authentication session and CSRF ownership

## Outcome

Correct the current authentication/session/CSRF capability and its real HTTP entries without routing raw secrets
through buses or replacing the owning package. This is slice D of
[TICKET-00135](../tickets/00135-TICKET.md), normally one complete PR. Keep sensitive synchronous APIs, current
security consistency and justified device presentation while removing admission-only Application forwarding.

## Scope

- Replace the removed AuthenticationService directly with supported synchronous UserAuthentication::login()
  and SessionLifecycle::refresh()/logout(), qualifying the actual release signatures and shared TokenIssuer
  composition. Update all live callers and fixtures, not just injected types. Keep sensitive inputs synchronous;
  no password/token Commands, replacement facade, direct handler bypass or duplicated package session transitions.
- Correct access-token verification and current-state authentication ownership: JWT/provider/HTTP details stay in
  Adapter; any retained inward coordination must have a demonstrated capability purpose. Preserve authoritative
  User/session identity, lifecycle, authentication-version and expiry checks, not just token signature acceptance.
- Own shared HTTP authentication/admission plumbing, ApiActionSecurity/PermissionGuard-related ownership, request-
  scoped principal context, trusted bearer extraction, browser origin/CSRF/cookie control and existing endpoint/
  network/login admission budgets. Migrate live shared callers when helpers move, without an Application blanket
  gate, service location, process-wide cached principal or replacement compatibility graph.
- Dispatch RevokeSession directly after actual entry permission/ownership admission; remove RevokeOwnedSession's
  admission-only facade. Keep the currently supported self-service boundary and explicit denial for unsupported
  cross-user administration. Required package authorization ports are not satisfied with a no-op shim.
- Turn the genuine active-session-plus-device projection into a registered owned query/handler with a safe typed
  result, consuming ListActiveSessions/SessionView. No raw sessions/devices array or copied package query/result
  validation. Session/device PHP properties are camelCase; HTTP Data owns wire fields and formatting.
- Correct SessionPresentation, device/browser enums/descriptors, capture/prune adapters and persistence ownership.
  Device hints remain bounded optional presentation, never authority; loss of optional hints need not destroy an
  otherwise valid authoritative session page. Keep trusted ownership, current-session indication and page bounds.
- Keep GetCsrfProof and its real registered query/handler, proof/nonce/clock capabilities and technical adapters
  with cohesive ownership. No artificial business aggregate or duplicated CSRF implementation for folder symmetry.
- Preserve refresh rotation/reuse defenses, terminal-versus-unavailable results, logout meaning, credential fencing
  and actual authentication/session business locks. Remove only solely ordinary permission-revocation serialization
  and its superseded tests; a newly revoked permission is checked on the next request.
- Reconcile affected Actions/Data/Responders, composition, OpenAPI, current browser callers/docs and meaningful
  tests; remove superseded types. Account for shared private-documentation/public-shell/runtime HTTP adapters as
  corrected or justified unchanged, without rewriting the frontend or engineering tools.

Excludes new authentication factors, cross-user APIs, Agent/HMAC/MCP authentication, password/activation correction
owned by TASK-00580, generic errors owned by TICKET-00136 and credential-worker changes owned by TASK-00581.

or device hint supplies authority. Preserve request-local principal lifetime and real security transitions; no
