# Enforce shared cohort admission

## Outcome

Implement one shared PostgreSQL cohort/admission boundary for both package repository participants, backed by
independently verified storage-incarnation evidence. Transactional checks retain the fence through completion;
nontransactional checks are fresh observations only. Incomplete composition stays sanitized `UNAVAILABLE`.

## Scope

- In scope: Accepted TASK-00227 design; required migrations and real admission/witness adapter; durable cohort
  markers/generation, same-connection fence, exact incarnation verification, safe contract projection and
  participant qualification checks. Integrate the current Agent repository and supply the same boundary to the
  operation repository delivered by TASK-00229/00230.
- Out of scope: Completing operation storage, cipher/sink/worker implementation, controlled switch/restore
  orchestration, live enablement, UI, legacy conversion and any fabricated compatibility or readiness flag.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Check transactional admission | Existing package transaction requests the cohort guard | Persisted markers/generation, actual local participants and independently verified live incarnation | N/A — contract lookup emits no business event | Shared cohort fence retained on the same connection through commit/rollback |
| Inspect outside a transaction | N/A — authoritative read only | Same fresh contract/witness boundary without a write transaction | N/A | Safe current snapshot or sanitized unavailable, never authority for a later call |
| Refuse incomplete composition | No successful mutation or bootstrap | Missing storage, mismatch, unsupported versions/participants or uncertain witness | Safe refusal observation only | No automatic cohort creation, synthetic reconciliation or material access |

## Validation and permissions

Both `getOperationContract()` paths must use the same persisted authority and trusted incarnation boundary;
equal generations do not prove a shared database/connection. Preserve unknown stored markers so package validation
can reject them. Project `reconciledGeneration` only from positive independently verified evidence, not a copied
local generation or a witness restored with the dataset. Verify under the same fence held before subordinate locks.

Derive capabilities from the persisted qualified profile intersected with the actual injected participants;
interface names, manually supplied arrays or startup checks are not production qualification. No runtime lookup
bootstraps storage or starts/commits a nested transaction. Outages, invalid state or unverified participants produce
sanitized `AgentOperationFailure::UNAVAILABLE` without provider messages or previous exceptions. Protected
operational authority manages witness material; ordinary UI/Super Admin access does not confer admission.

## Acceptance criteria

- [ ] Actual PostgreSQL cohort state and independent witness identity are read coherently against the selected
  contract. Missing/unknown/incompatible markers, nonpositive or mismatched generations and wrong incarnations deny.
- [ ] Cohort admission contends with a conflicting real connection and retains its fence through commit/rollback
  before subordinate locks; outside-transaction reads mutate nothing and cannot authorize later transactions.
- [ ] Missing/substituted actual participants, witness unavailability and process restart cannot retain cached
  readiness or disclose sensitive diagnostics. Capability declarations alone cannot enable support.
- [ ] The shared boundary is used by the existing Agent repository and made mandatory for the operation repository
  in TASK-00229/00230; no second authority, nested transaction or automatic storage bootstrap is introduced.
- [ ] Current runtime remains unavailable while storage/cipher/sink/maintenance/authenticated-use composition is
  incomplete. Bounded component evidence is labeled as such and cannot become a production-ready profile.

## Verification and evidence

Test owned admission behavior and important real PostgreSQL/witness adapter contracts using independent
connections, controlled contention and restart. Observe unavailable outcomes and absence of mutation/material
access; qualify the actual independent boundary with its tools, not an in-memory ready flag. Positive component
scenarios do not qualify absent production participants. Record exact package/source/lock and adapter/tool versions.
Generate migrations through Doctrine and validate them directly; no product tests of migration text, wiring,
configuration or tooling. Run focused checks, planning/whitespace checks and `./bin/build`, recording warnings.
