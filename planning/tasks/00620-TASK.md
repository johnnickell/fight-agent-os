# Pilot four parallel GitHub verification workflows

## Outcome

Qualify four independently reported native GitHub workflows before requiring them for merges.

## Scope

Run PHP, Frontend, Pi Harness, and Planning in separate parallel workflows with stable check names. Use the shared selector inside each workflow so the check reports even when unaffected. Prepare only the required tools on the runner and invoke the owning commands directly, without running containers. Use dependency caches if useful; do not reuse cross-run check results. Keep the old required gate during the pilot. The current PHP coverage gate is sufficient for the pilot, not for cutover.

## Acceptance criteria

- [ ] All four checks report a result for relevant candidates, including explicit not affected. Failure or unknown scope is not reported as an unaffected success.
- [ ] Representative PHP-only, frontend-only, Pi-only, planning-only, and shared changes produce the expected results, including smoke once when changes on either side can affect a journey.
- [ ] Hosted evidence confirms native execution and accounts for every existing mandatory check. Cold and representative PR timings, warnings, and gaps are recorded against the current layout.

## Verification and evidence

Record candidate revisions, check names, exact invocations, hosted run links and results, check inventory, and timings. Use separately authorized publication for real hosted evidence and preserve the current gate while evidence is incomplete. Hand off to independent Review and applicable QA.

## Coordination

Needs the shared selector and all four runner-native entry points, including smoke. May proceed in parallel with local receipts. Required-check settings and retirement of the old gate belong to [TASK-00621](00621-TASK.md).
