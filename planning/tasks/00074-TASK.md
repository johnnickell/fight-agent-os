# Expose authorized installation capabilities and diagnostics

## Outcome

An appropriately authorized authenticated user can query one bounded, versioned, secret-safe view of the current Planning installation's service, migration, ingress, approved-root and private-storage capabilities, with truthful healthy, degraded, unavailable, stale and not-checkable reasons and no corrective mutation.

## Scope

- In scope: Agent OS-owned installation-capability query and safe View; injected read-only probes for declared EPIC-00005 services; bounded timeouts; version/health/migration/ingress/approved-root/Planning-storage facts; observation timestamps and freshness; stable reason codes; authenticated permission enforcement; versioned JSend API endpoint/OpenAPI contract; copyable text diagnostic representation; redaction and failure mapping; unit, integration and functional behavior tests.
- Out of scope: Browser guide/page implementation, setup mutation, service start/restart/repair, migrations, upgrades, backup/restore, log collection, directory listing, secrets or environment dumps, arbitrary network probes, registered Repository/Checkout health, Runner/provider/Workflow/Artifact capabilities, metrics/telemetry stack, and treating observations as authority.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| View current installation capabilities | N/A — read-only interaction | `GetInstallationCapabilities` | N/A — reads emit no Domain event | A bounded safe View reports declared capability facts, observation time, freshness and reasons |
| Diagnose an unavailable capability | N/A — read-only interaction | `GetInstallationCapabilities` with bounded probes | N/A — reads emit no Domain event | Unavailable/degraded/not-checkable facts are returned without starting or repairing anything |
| Copy a support report | N/A — representation of the same query | Render the safe capability View as bounded text | N/A — representation has no side effect | User receives copyable non-secret facts and remediation context without automatic upload |
| Reject unauthorized inspection | N/A — authorization failure | N/A — protected query is not dispatched successfully | N/A | Request fails closed without revealing topology, paths, versions or probe detail |

## Validation and permissions

Own the cross-boundary query in `App\Application` only because it coordinates installation-specific adapters and policy. Keep service/process/filesystem/HTTP/storage probes in capability-first Adapters and inject them; Domain and Application must not import Docker, Compose, filesystem, HTTP-client or S3 implementations. The Action dispatches one query and the Responder maps one explicit safe View to `snake_case` JSend data. Do not expose raw adapter exceptions or persistence/runtime models.

Define a finite declared capability inventory for this EPIC. Each item reports a stable capability key, support state, observed state, bounded safe version where relevant, observation time/freshness, and stable reason code plus human-safe explanation. Distinguish not configured, not mounted, unreachable, timeout, unhealthy, migration required, unsupported, stale and not-checkable instead of collapsing them into failure. Unknown probe errors map to correlated internal/unavailable outcomes without raw messages.

Use short bounded probes and no broad host inspection. Never return credentials, tokens, cookies, keys, certificates, DSNs, bucket credentials, Docker metadata, raw environment values, SQL, object names/content, directory listings, arbitrary logs, private root descendants, usernames or unnecessary personal paths. Approved-root output is limited to the explicitly safe locator and capability facts established by TASK-00073.

Require authentication and a specific installation-information permission resolved from authoritative server state. UI visibility, ordinary login, cached client roles, route access and possession of a locator do not grant the query. The copyable diagnostic is the same safe View, not a less-restricted debug endpoint. No browser capability mutates installation settings; later operator authority remains separate.

Observations are not business authority and emit no Domain event. A failed or stale probe never starts, repairs, migrates, reconfigures or marks a service healthy. Cache only if a bounded freshness policy is explicit; visibly stale cached results remain read-only and cannot authorize registration, migration or execution.

## Acceptance criteria

- [ ] One Agent OS-owned read-only query returns an explicit safe View of every EPIC-00005 installation capability and no later capability.
- [ ] Service, version, migration, ingress, approved-root and private-storage probes are injected, bounded and incapable of corrective mutation.
- [ ] Results distinguish healthy, degraded, unavailable, stale, unsupported and not-checkable states with stable safe reason codes.
- [ ] The versioned API uses one Action/query/Responder path, JSend, explicit `snake_case` mapping and an accurate OpenAPI contract.
- [ ] Authentication and installation-information permission are enforced server-side; absent, stale or insufficient authority fails closed without topology disclosure.
- [ ] Safe JSON and copyable text contain no secret, credential, DSN, raw exception, environment dump, directory listing, object content, private descendant or unnecessary personal path.
- [ ] Timeout, malformed response, unavailable dependency and unknown adapter failures are correlated and safely represented without claiming health.
- [ ] Stale cached observations are visibly timestamped/read-only and cannot authorize installation, registration, migration or execution.
- [ ] Reads emit no Domain event and do not start, stop, repair, migrate, upgrade, mount or reconfigure anything.
- [ ] Focused unit/integration/functional/redaction tests and the canonical build pass with fresh counts and evidence.
