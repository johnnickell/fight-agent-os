# Simplify numeric settings in the Pi subagent extension

## Outcome

Make each numeric setting easier to maintain without letting the displayed value, input prompt, and applied value drift apart. This supports the settings surface of the [accepted local Pi integration](../tickets/00130-TICKET.md).

## Scope

- In `harness/pi/vendor/pi-subagents/src/index.ts`, give each of the five numeric settings one local definition: background and foreground concurrency, default max turns, grace turns, and nested depth.
- Leave nonnumeric settings, the persisted schema, and workflow extraction out of scope.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Edit a numeric setting | `/agents` → Settings | Read current effective value | Existing `subagents:settings_changed` | Apply, save, and notify as before; cancellation does not change the setting |

## Validation and permissions

Preserve the existing defaults, integer parsing, per-setting minimums, and meanings of zero. Keep persistence warnings and session-local effects. No permission or installation changes.

## Acceptance criteria

- [ ] Rows, prompts, and updates use the same local definition for each numeric setting.
- [ ] Valid input, invalid input, cancellation, and save failure retain the current behavior. Zero remains distinct from unset where the current contract requires it.

## Verification and evidence

Exercise the five settings through the existing dialog, including invalid input and cancellation. Run focused settings checks and the engine typecheck. `settings.test.ts` covers saving and broadcasting, not the entire numeric dialog; record direct evidence for the dialog cases. Run `./bin/build` and hand off for independent Review and applicable QA.
