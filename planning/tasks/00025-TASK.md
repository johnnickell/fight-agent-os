# Accept the client-authority and runtime-state ADR

## Outcome

An explicitly accepted client architecture ADR defines authoritative principal ownership, fail-closed authorization, memory-only credentials, refresh/invalidation coordination seams, narrow runtime-state ownership, typed non-secret configuration, and theme-preference bootstrap boundaries before the React foundation encodes them.

## Scope

- In scope: `/api/v1/me` authority source; principal API-cache ownership/lifecycle; unknown/loading/stale/terminal states; shared route/component permission evaluation; memory-only access-token and inaccessible refresh-cookie boundaries; refresh/logout/authority-change coordination signals; URL/local/API-cache/context ownership; intended-route handling; typed runtime configuration; `system`/`light`/`dark` preference bootstrap/persistence; enforcement and deferred product integration.
- Out of scope: React/tooling implementation, `/api/v1/me` endpoint, login/refresh/logout code, product routes, final design, state-library selection beyond justified responsibilities, service workers/offline mode, and browser-storage business workflows.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Resolve current authority | N/A — client read | Load/cache authoritative `/api/v1/me` principal projection | Client invalidation signal only | One session-scoped cache owns principal state; unknown/stale fails closed |
| Guard navigation/presentation | N/A — UI decision | Evaluate route/component permission through one service | N/A — no trusted domain event | Unauthorized visibility/navigation is denied while server checks remain authoritative |
| Coordinate authentication state | N/A — browser coordination | Read memory token/authority state and refresh/logout signals | Client-only refresh/logout/invalidation signals | Tabs invalidate/refetch safely without persisted credentials or authorization snapshots |
| Own runtime state | N/A — client architecture | Determine URL/local/API-cache/context/preference owner | N/A — no domain event | Each state has the narrowest authoritative owner and duplicate stores are rejected |

## Validation and permissions

The ADR must make `/api/v1/me` the only client authority projection for roles/permissions. Tokens, HTML, runtime configuration, route metadata, and persisted storage cannot carry trusted authorization snapshots. One API-cache owner models unknown/loading/authenticated/anonymous/stale/terminal states and invalidates after refresh, logout, terminal authentication failure, or authority-changing operations/signals.

One permission evaluator serves complete-route requirements and component visibility/disabled decisions. Unknown/stale state fails closed, role names are not permission shortcuts, and client checks never replace server authorization. Define bounded safe intended-route restoration without form values, credentials, external/open redirects, or arbitrary state.

Access credentials remain memory-only under the browser-security ADR; refresh credentials remain inaccessible to JavaScript. Clarify permitted transient coordination and prohibit credentials/business workflow state in `localStorage`, `sessionStorage`, IndexedDB, Cache Storage, service workers, URLs, base HTML, or runtime config.

Assign shareable navigation/filter/sort/page state to URLs, transient interaction to local state, server state/principal to API cache, and only true application-wide concerns to context. Runtime configuration is typed and non-secret. Only explicit `system`/`light`/`dark` presentation preference may initially persist; system is default and OS tracking/bootstrap must avoid encoding final visual design.

No runtime permission is implemented. Architecture documentation is authorized; client/server production code is not.

- [x] `/api/v1/me` is the sole authoritative client source for roles/permissions and one API cache owns principal state.

- [x] Route metadata and components use one permission evaluator without role-name bypass or claims of server enforcement.
- [x] Access credentials remain memory-only and refresh credentials remain JavaScript-inaccessible under TASK-00017's accepted profile.
- [x] Tokens/authority snapshots and business workflow state are prohibited from HTML, runtime config, URLs, and browser persistence.
- [x] Refresh, logout, authority-change, cross-tab invalidation/refetch, and safe intended-route semantics are explicit.
- [x] URL, local state, API cache, application context, and presentation preference each have narrow ownership rules.
- [x] Typed runtime configuration contains no secrets or authority and fails safely when invalid.
- [x] Theme preference is the only initial approved persisted state and a human explicitly accepts the ADR.
