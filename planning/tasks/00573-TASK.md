# Replace Role audit inference with explicit package-handler audit

## Outcome

Replace Role mutation audit inferred by `RoleMutationUnitOfWork` with explicit canonical package-handler audit,
keeping required state/audit atomicity through the configured bus and real PostgreSQL persistence. Deliver the
second complete integration slice of [TICKET-00133](../tickets/00133-TICKET.md), normally one PR, and delete the
superseded consumer machinery only after equivalent replacement is verified.

v0.10.0 resolved the earlier CLI assignment contract hold but has a separate delivery defect. The locked

## Scope

- Refresh affected consumed Access Control/Common handler, repository, audit, event and transaction contracts and
  actual consumers. Qualify a supported tagged Access Control release whose handlers explicitly coordinate required
  audit for custom Role create/rename/remove and safe Role subjects/actor/action evidence. Inspect actual transitive
  Common requirements and signatures; record exact release/source/lock and deliberately update manifest/lock.
- Bind the supplier's actual required-audit contract to needed consumer persistence on the same generic transaction
  authority and connection as Role mutation. Use canonical public contracts directly; do not invent factory names,
  interfaces or optional-injection choices before the supplier's separate design is accepted and released.
- Configure real package command registration/routing and handler dependencies for all three existing mutations.
  Qualify through actual protected HTTP entry paths and configured package buses; no privately invoked handler,
  alternate privileged bus, event-result inspection, repository interception or outer/nested transaction may
  manufacture required audit. A post-commit subscriber is not an atomic audit replacement.
- Preserve existing admission and business outcomes. TICKET-00135 owns broader relocation/removal of redundant
  Application admission; coordinate touched entry/caller contracts without making that whole correction a blocker
  or adding another blanket gate. Actor/target scope must remain trusted at actual entries.
- Keep required mutation and safe audit together: audit failure rolls back the mutation; rejected operations and
  unchanged-name no-op rename do not record successful mutations. Preserve known name/revision/reference conflicts,
  real business concurrency, after-commit success publication and truthful uncertain/post-commit failures.
- Reuse/adapt needed PostgreSQL audit persistence and qualified subject mapping/hydration; preserve existing audit
  history and safe bounded evidence. A new API must not silently lose old Role rows or weaken secret restrictions.
  Add a migration only if the actual adopted model requires one, with explicit needed-data preservation/disposition.
- Remove `RoleMutationUnitOfWork`, its obsolete tests, superseded local `RoleMutationAudit` and redundant persistence/
  composition branches after meaningful replacement coverage exists. Needed live audit adapters may be adapted,
  not deleted for a quota. No forwarding aliases, null/no-op required-audit binding or temporary imitation layer.
- Update affected callers, tests, custom Role/transaction runbooks and current docs in the same slice, using
  descriptive dependencies. Coordinate actual manifest/composition overlap with TASK-00572/TICKET-00136, rather
  than creating a package-upgrade-only prerequisite or forcing unrelated features onto one prospective version.

Excludes implementing/releasing the upstream package, vendor patches, API guesses/snapshots, new Role features or
endpoints, publication providers/outboxes, universal retries, broad identity refactoring, ordinary replay guarantees
or safe HTTP framework replacement. Database transactions do not make external effects rollback-safe.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Create a custom Role | Existing package CreateCustomRole through the configured bus | Existing authoritative detail/catalog reads | Existing CustomRoleCreated after commit | Role and required safe audit commit together or neither persists |
| Rename a custom Role | Existing package RenameCustomRole | Existing authoritative Role read | Existing CustomRoleRenamed after real committed change | Atomic mutation/audit; valid unchanged-name no-op has no successful-mutation audit/event |
| Remove an eligible custom Role | Existing package RemoveCustomRole | Existing authoritative Role/reference reads | Existing CustomRoleRemoved after commit | Atomic removal/audit with retained actual reference/revision consistency |
| Reject or encounter audit/commit/publication failure | Existing mutation intent, no new retry engine | Fresh authoritative state where reconciliation is needed | Only facts justified by the actual outcome | No successful audit for refusal, rollback on required audit failure, no false rollback after commit |

Actual adopted signatures/events must be qualified from the selected supplier; this table states existing use-case
intent, not permission to implement guessed upstream APIs. No new permission, UI or audit publication provider.
