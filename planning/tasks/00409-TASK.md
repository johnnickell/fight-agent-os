# Run and recover the declared preparation command

## Outcome

An admitted optional stage executes only the exact manifest preparation command under qualified containment and
reports real success, failure or uncertainty with retained local Git and visible tracked changes. Explicit retry
reconciles the original process/effects first; it never hides changes or duplicates unknown work.

## Scope

- In scope: Exact optional preparation invocation, current scope/capability enforcement, bounded process/effect
  inspection, original-operation recovery, safe observations and tracked-change accounting.
- Out of scope: Arbitrary commands, model-selected repairs, new process/sandbox/broker platform, package-manager
  policy, credential enrollment, additional Git commits, remote publication, overall attempt transitions and cleanup.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Run selected preparation | Execute exact admitted manifest-stage intent | Current plan, command, initial Git subject and qualified capabilities | Verified preparation facts through attempt owner | Only bounded declared executable/network effects |
| Inspect or reconcile preparation | Explicit original-operation reconciliation; status itself is read-only | Actual process lineage, liveness, exit/effect evidence and tracked changes | Confirmed outcome or uncertainty | No second launch while liveness/effects remain unknown |
| Retry safe failed work | Exact separately admitted retry of original stage | Prior effects, current authority, quiescence and allowed retry scope | Attributed retry/result facts | Bounded retry only after reconciliation, not a new hidden attempt |
| Respect skipped preparation | N/A — choice is recorded by attempt owner | Explicit selected/skipped plan facts | N/A — this adapter does not invent a skip transition | No command, credential or network requirement for an opted-out stage |

The preparation process executes source-controlled code: enforce the accepted real isolation, finite CPU/memory/

unrestricted network fallback. Qualify actual descendants and supported cancellation/acting windows, not PID labels.

as dirty state; never silently stage/commit, discard/reset/stash or add them to the published initial subject.
Unexpected modifications or altered Git/root ownership hold for an explicit decision, not silent repair. Capture
bounded sanitized output and verified process/effect/result facts without raw environments, credential-bearing
