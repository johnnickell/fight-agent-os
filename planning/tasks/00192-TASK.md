# Reassess published guidance when a source changes

## Outcome

When a linked source memory is corrected or retracted, the owner of each affected broader entry or derived
summary receives a durable, safely scoped notice and can independently assess whether to append a correction
or retraction to its own published claim. A prior publication is not silently rewritten, withdrawn or
approved by the source change. This TASK delivers one end-to-end source-to-owner reassessment path using the
existing memory lineage and first-party operations, not a speculative notification provider.

## Scope

- Consume [TASK-00191](00191-TASK.md)'s distinct publication/source/evidence lineage and the private/shared
  source revision/correction facts from TASK-00185/TASK-00187/TASK-00188. On a relevant source change,
  durably record a bounded pending impact for each linked broader entry and derived memory summary, keyed to
  source identity/revision and target lineage. A change to private text must not cause obsolete private
  bodies to be retained in an impact record or leaked to a target owner; a reviewer still needs independent
  permission before seeing a private source. Multiple linked targets and repeat delivery are idempotent.
- Let the currently authorized Repository/Workspace target owner inspect its pending impacts and permitted
  source/evidence references, mark a notice assessed with safe rationale, or append its own linked
  correction/retraction under the same attributed shared history policy. Retraction removes a claim from
  ordinary guidance but preserves permitted history; an independently supported broader conclusion may
  remain current after documented assessment. Contradictions stay visible to authorized assessment, never
  merged/invalidated by a model judgment.
- Make impact discovery recoverable across a committed source change and process failure. Use a transactionally
  maintained dependency/impact record or durable intent on the canonical PostgreSQL connection; if later
  delivery is external, qualify the durable post-commit effect separately. Do not claim an in-memory event
  listener or transient prompt constitutes notification. A bounded authorized pending-impact query through
  the existing first-party path suffices initially; the human UI may display it under TICKET-00050.
- Keep source code and published Planning authoritative for behavior/intent; the owner checks them afresh
  where applicable. Review of a source correction does not retroactively edit a published entry, proposal
  decision, Workflow handoff, test result or permission. Exceptional prohibited-content removal takes
  precedence and is **not** fulfilled by an impact notice or ordinary retraction; TICKET-00050 owns removing
  affected copies and safe handling of exports, views and backups.
- Out of scope: automatic publishing, general alert-service enrollment, age-based archive, bulk learning
  feeds, Jev selection (TICKET-00049), or human browser UI (TICKET-00050).

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Observe changed source | Record impact with source correction/retraction as one recoverable operation | Resolve linked published/derived targets and safe source revision | Source change and impact-ready fact after commit | Pending notices persisted without copying old source text |
| Inspect pending impacts | N/A — read-only | Read current owner's bounded impacts with live target authority | N/A — no memory mutation | Owner learns which claims need assessment, not private text it cannot read |
| Reassess a target entry | Record assessment and optionally append own correction/retraction | Check target ownership, current source/evidence and target history | Assessment and linked change after successful commit | Published claim stays or is corrected/retracted with fresh attribution |
| Retry/revoke | Repeat exact intent or deny stale owner | Resolve prior intent and live target scope | N/A for exact retry or denial | No duplicate notice, change or unauthorized published edit |

## Validation and permissions

Target owner checks remain live on each inspection and reassessment, regardless of who authored or later
changed the source. A source correction is evidence to review, not target-write authority. Reject forged
source/target IDs, revoked owner, stale target revision, unverified evidence and unsafe private links; keep
source text and prohibited bytes out of notice bodies, logs and audit. Persist source-to-derived impact
atomically with change or through recoverable intent; prove no lost notices on interrupted delivery. Exact
retry returns prior result, distinct source changes retain separate assessment history. An ordinary
correction/retraction cannot certify safety deletion, so live ingestion still waits for TICKET-00050.

## Acceptance criteria

- [ ] Correcting/retracting a linked private or shared source leaves a durable safe impact visible to each
  qualified derived owner, including after restart, without exposing prior private text or a prohibited body.
- [ ] Publication and proposal remain unchanged until a currently authorized target owner checks source and
  independent evidence; a supported conclusion can remain current with an attributed assessment rationale.
- [ ] An owner can append its own linked published correction/retraction and ordinary guidance then excludes
  retracted current claims, while permitted historical inspection retains safe original authorship.
- [ ] Retries and concurrent source/owner changes cannot lose or duplicate impacts or produce a target write
  without current authority; stale/revoked principals are denied even with known lineage IDs.
- [ ] No alert alone deletes unsafe bytes, rewrites independently supported evidence, grants a Permission,
  changes Planning/Workflow facts, or substitutes for TICKET-00050's safety-removal path.
