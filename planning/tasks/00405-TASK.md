# Associate exact recommended development profiles

## Outcome

An authorized administrator associates a starter with existing Workspace-owned managed/custom profile-template
revisions, and preview consumers can inspect the exact recommendation and availability without creating an Agent
or copying profile authority into the catalog.

## Scope

- In scope: Protected API/console expected-state association changes and inspection, exact template/revision/scope
  and provenance, actual read/reference composition, safe availability and immutable selection inputs for preview.
- Out of scope: Template seeding/editor/publication, user Harness preferences, automatic Skill activation, Agent
  creation or grants, new profile registry, source-driven recommendations, browser creation form and provider calls.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Set or remove a recommendation | Authorized association change with expected state | Current starter/association and exact authorized template/revision | Committed association facts | Scoped recommendation and audit only, not a profile or Agent change |
| Inspect a recommendation | N/A — read-only | Exact retained revision, current authorized availability and provenance | N/A | Safe preview inputs or explicit denied/unavailable/stale reason |
| Resolve a future selected profile | Existing TASK-00249 resolution consumed under current scope | Exact chosen revision and resource/model constraints | N/A — resolution grants nothing | Coherent pinned facts for the creation owner, no automatic activation |

## Validation and permissions

Consume TASK-00401's scoped catalog and TASK-00249's exact profile resolver, with TASK-00299's database template
identity/history transitively. Reuse existing Workspace-owned managed/custom templates, not TASK-00323 user-owned
Harness preferences or inline profiles copied from source. TASK-00300 retains custom publication/editor ownership;
a completed editor is not a prerequisite of this association primitive. Fixture records cannot be presented as
fresh qualification of live custom publication.

Enforce current operation-specific association administration and independent template/read scope at every entry
path. A management role label, starter read permission, authenticated session or known template ID does not grant
profile disclosure or Agent authority. Source repository/manifest content cannot create, recommend authoritatively,
activate or revise Skills/profiles. Recommendations are explicit Workspace administration, never a source-driven
fallback. Validate stable identity, immutable revision, scope, bounded association shape and expected state.

Qualify actual Workspace-level profile-read/reference composition before a new Repository exists. Do not fabricate
a Repository to satisfy a registered-Repository-only resolver or loosen its scope checks. Preserve TASK-00249's
unresolved scoped-read/context and TASK-00299's independent Triage-input holds. Their dependency mapping is not
operational availability; if the required Workspace-only path is unsupported, hold affected operations and return
to the owning capability rather than implement a competing resolver or silently widen access.

Commit association state/revision, retained reference and bounded audit in one canonical PostgreSQL transaction.
Use complete expected-state/current-selection generations and real shared reference fences, not an earlier query
as an atomic guarantee. Concurrent template selection/retirement, catalog change, association edit and reference
changes must yield one coherent exact revision or safe conflict. Preserve historical references and original
outcomes across rollback, lost acknowledgement and repeated requests; no dangling reference, accidental duplicate
revision or silent substitution by alias/name/current pointer.

Expose recommendation revision separately from the user's actual selected revision. TICKET-00101 binds its preview
and confirmed plan to exact selected facts and revalidates material changes; TICKET-00103 records the same selection
in context/receipt. Updating a recommendation cannot rewrite an earlier preview/attempt, active profile, session or
generated project. Retained history is not permission to use a currently unavailable profile. Profiles and Skills
remain independently versioned, with current applicability resolved through their existing owners.

Use bounded stable safe Views and current-authorized API/console paths with sanitized errors. Report missing,
retired, denied, unsupported or ambiguous references honestly without hidden content/counts, partial profiles
advertised as usable, provider secrets or raw prompt disclosure beyond current rights. Reads never call providers,
seed templates, repair associations, launch sessions or grant requested Permissions. Catalog eligibility and source
certification do not follow from profile compatibility; selecting a development profile is only a recommendation/
configuration choice, not measured model suitability or execution consent.
