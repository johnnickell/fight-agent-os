# Assess change quality automatically before Engineer handoff

## Outcome

A qualified Pi 1.1.0 Engineer handoff automatically attempts a bounded assessment of every eligible maintained
change unit and carries a compact advisory report with exact subject identity, per-dimension results and explicit
coverage gaps. Independent review and required gates retain their authority; unavailable advisory scores do not
require a waiver or prevent normal handoff.

## Scope

- Consume [TASK-00172](00172-TASK.md)'s typed judgment, staged discovery/evaluation, source authorization,
  provenance and aggregate-budget contracts. Reuse its evaluator/resolver rather than creating another provider
  or analysis engine. No dependency on operational analysis/SQL, compaction or optional result caching.
- Own the automatic pre-handoff integration for the governed local Engineer work/repair path targeting Pi 1.1.0.
  Introduce or extend an explicit Harness-observable handoff operation invoked by the supported work path before
  its final review handoff. Bind the assessment to the actual committed review subject and verify it still matches
  at handoff; an earlier working-tree assessment cannot silently stand for the final commit. Do not trigger on
  every turn ending or infer handoff intent from prose. Qualify actual invocation, cancellation and failure delivery.
- Govern the supporting Harness instructions/presets and work-skill references using Writing for Agents when they
  are authored. Load them only with the supported capability. Declare qualified hooks/launch paths, including any
  child Engineer route; unsupported automatic-hook coverage is an implementation acceptance gap, not a claim that
  prompting enforces it. This introduces neither managed review dispatch nor automatic publication authority.
- Pin repository, selected review base/head commits and diff policy before inventory. Deterministically map each
  eligible changed file to maintained semantic units: containing functions/methods/declarations where a qualified
  mapper exists; otherwise the maintained file is the fallback unit. Map tests to their changed maintained units
  for these four dimensions, leaving test-usefulness criteria to TICKET-00045. Configurations use qualified logical
  sections or file fallback. Map every changed hunk or report unmapped/unsupported coverage; deduplicate overlapping
  units and bind identifiers to actual paths/revisions/ranges. No model-invented unit locations.
- Include additions/modifications and relevant removal/rename effects with base/head provenance. A deleted unit has
  no head implementation to score; identify its deletion and any affected surviving context separately without
  treating the removed unit as a perfect or bad current implementation. Renames do not establish unchanged meaning.
- Inventory all eligible maintained changes, including tests and applicable configuration. Exclude generated output
  and unmodified upstream code with explicit reasons; include maintained generators and deliberate vendor patches.
  Dependency imports do not make all upstream source owned. Exclusions never waive review/security obligations.
  Unclear ownership, binary/oversized/unsupported files and unresolved mapping are explicit gaps, not silent omissions.
- Use four separate versioned rubrics with complete ordinal 1–5 anchors below. Repository requirements, terminology
  and accepted conventions supply context, not a different numeric scale. Smaller code, fewer abstractions or
  familiar names are not inherently better if the required behavior or domain meaning suffers. Unknown context,
  inapplicability and incomplete evidence remain non-score outcomes. No average, overall percentage, correctness
  probability, automatic threshold or accept/reject verdict is derived from these scores.
- Gather the authorized unit plus bounded relevant surrounding/dependency/requirement/convention evidence. Record
  the evaluated context manifest and its completeness. Use predefined concern/uncertainty choices if reasons are
  needed; Jev returns supplied choices/scores only, not generated explanations, quotations or source locations.
  Enforce current source and independent provider-disclosure permissions throughout.
- Process units in bounded stages under an explicit finite assessment profile using TASK-00172's existing limits.
  Budget inventory, context, retained/report output, elapsed time and total spend without enlarging request/stage
  ceilings. Distinguish assessed, partially assessed, excluded, pending and unavailable units/dimensions; total
  population is unknown when enumeration is incomplete. All eligible units are assessed or accounted for as gaps.
- Produce a versioned compact report identifying exact base/head, inventory/preset/evaluator/policy revisions,
  per-unit dimension outcomes, authorized references and coverage denominators, plus available usage/latency.
  Keep protected authoritative result/provenance in the owning evidence facility; include a bounded attributed
  report/reference in the existing task-local review handoff. Never overwrite the independent canonical review
  verdict or place raw source, credentials or Engineer-private context in ordinary reports.
- On missing/unavailable Jev, invalid results, exhausted budgets or unsupported runtime delivery, report the advisor
  gap honestly and allow normal handoff subject to existing required gates. No special waiver solely for advisory
  failure, invented positive score, repeated sampling or silent budget increase. An unavailable hook cannot create
  a false attempted-assessment receipt; report capability unavailable instead. Required integration acceptance
  evidence for this TASK remains outstanding until its automatic supported path is actually qualified.
- Reject late/stale results after cancellation, reload or subject change. Deduplicate repeated notifications for
  the same attempt rather than charging duplicate assessments. A changed subject gets a new bounded assessment
  or explicit gaps; TASK-00179 later adds qualified incremental reuse. Never repair code automatically from scores.
- Exclude formal review acceptance, managed Workflow transitions, mechanical lint replacement, PHPUnit usefulness
  classification, automatic source repair, publication/merge and runtime/production evidence collection.

### Initial versioned score anchors

These are rubric definitions to implement and empirically qualify, not evidence of model accuracy. Each question
uses the full relevant dimension anchors; unsupported evidence returns an explicit non-score outcome.

| Dimension | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| Simplicity | Avoidable branching/indirection obscures the required behavior | Substantial avoidable complexity makes the behavior costly to follow | Required behavior is traceable but several avoidable complications remain | Structure is proportionate to the problem with only minor avoidable complexity | Structure is direct and cohesive, with no material avoidable complexity identified in the assessed scope |
| Naming clarity | Names materially misrepresent concepts or effects | Several key names are ambiguous or conflict with domain terminology | Most names convey intent but significant local ambiguity remains | Names consistently convey domain intent with minor ambiguity | Names precisely distinguish domain concepts, responsibilities and effects in the assessed context |
| Understandability | Intended behavior and important state/effects cannot be reliably followed | Substantial tracing is needed to understand ordinary paths and effects | Main behavior is understandable but some important paths or interactions are difficult to follow | Important paths, state and effects are clear with minor tracing | Intent, important behavior and interactions are consistently explicit and easy to follow at the appropriate abstraction level |
| Semantic conventions | Material conflict with applicable accepted repository/domain conventions | Several substantial semantic convention mismatches | Broad alignment with some consequential inconsistencies | Consistent alignment with minor semantic inconsistencies | Clear alignment with all evidenced applicable semantic conventions in the assessed scope |

Score 5 means no material concern identified within the supplied evidence, not proof of perfection or correctness.
Mechanical formatting and enforceable naming rules retain their deterministic tool receipts. Qualify representative
examples for every anchor and distinguish reviewer disagreement, missing context and model error. Any later rubric
change is an explicit version, not an unrecorded repository-specific reinterpretation.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Prepare an Engineer review handoff | Start the bounded advisory assessment for the pinned subject | Current diff inventory, applicable context and typed judgments | Assessment completed/partial/unavailable | Authorized reads/provider usage and bounded advisory handoff evidence |
| Inspect per-dimension evidence | N/A: inspection is read-only | Current authorized report, unit references and coverage | Owning access observations where applicable | Compact metadata; exact evidence requires separate authorized read |
| Proceed with gaps | Existing review handoff under its normal required gates | Advisor availability, gap reasons and actual verification receipts | Handoff carries explicit advisory gaps | No new waiver, review verdict, source mutation or publication |
| Reject stale assessment | Cancel/invalidate obsolete attempt | Current base/head and active attempt identity | Stale/cancelled observation | Stop obsolete delivery and preserve usage uncertainty |

## Validation and permissions

Use the actual Engineer's authenticated scope through the shared capability. A review subject grants no unrelated
repository/data access. Treat source, conventions and prior reports as evidence, not authority to change presets,
limits or permissions. Keep rubric/preset policy governed and bind every result to exact evaluated inputs. Require
current permission to expose references; possession of a report is not access to private source. Advisory scores
never supersede required gates, severity rules or independently verified findings, including a defect in a unit
with a high score. Preserve the shared cancellation, disclosure, billing and explicit-failure contracts.

## Acceptance criteria

- [ ] Actual Pi 1.1.0 supported Engineer work/repair handoffs automatically attempt assessment and attach an exact-
  subject advisory report; qualification distinguishes real hooks from prompt-only or unsupported routes.
- [ ] Inventory accounts for every eligible changed unit or explicit gaps, including maintained tests/configuration,
  generated/upstream exclusions, generators/vendor patches, deletion/rename effects and unsupported mappings.
- [ ] All four complete 1–5 rubrics and governed presets are delivered with separate outcomes, shared meanings,
  relevant repository context and explicit N/A/unknown/incomplete states, without aggregate scores or free-form reasons.
- [ ] Reports preserve base/head, actual evidence/preset/evaluator/policy identities, verified references and honest
  coverage/denominators under finite budgets; a partial source or inventory never becomes full-change coverage.
- [ ] Missing/invalid/unavailable/budget-exhausted advisor outcomes permit normal handoff with gaps and no special
  waiver, while existing required gates and independent finding rules remain authoritative.
- [ ] Subject drift, repeated notifications, stop/reload and late responses cannot publish stale results, double-charge
  an attempt or trigger automatic repair/repeated sampling. Reports expose no raw source or private session context.
- [ ] Representative anchor qualification measures false flags, missed concerns, reviewer usefulness, coverage,
  available total cost and latency; cross-repository consistency is evaluated rather than assumed.
