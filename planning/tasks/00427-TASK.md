# Explain failures with versioned playbooks and safe diagnostics

## Outcome

An authorized human understands a failed or partial creation attempt through the existing browser attempt view,
applicable versioned troubleshooting and a deliberately exported safe report. This useful recovery path works
without an Agent, model configuration or provider disclosure and supplies bounded evidence to optional assistance.

## Scope

- In scope: Creation-specific playbooks within the single operator guide, deterministic applicability, protected
  bounded attempt-evidence projection, explicit copy/download and production failure-view integration.
- Out of scope: A second guide or capability registry, new live host/provider inspection, model work, raw-log/file
  access, automatic upload, installation/setup mutation, retry/cleanup execution and completion-receipt ownership.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Understand a creation failure | N/A — read-only | Current authorized retained attempt/stage facts and applicable exact playbook | N/A | Safe explanation of verified effects, uncertainty and permitted next actions |
| Inspect bounded evidence | N/A — read-only | Immutable plan identity, safe source/manifest/capability facts, outcomes and resources | N/A | Versioned minimized projection, not a new attempt or live capability check |
| Export diagnostics | N/A — explicit read/export | Current authorized secret-safe representation and source revisions | N/A — ordinary read logging only | User-controlled copy/download; no automatic external upload |

## Validation and permissions

Extend TASK-00075's one versioned task-based guide and TASK-00416's original-attempt browser surface. Stage facts
come from TASK-00414 and its actual owners; do not require a successful TASK-00426 receipt to explain an earlier
failure. Missing Repository/Checkout/context identity stays absent, never fabricated. Final receipt and authoritative
attempt state remain with their existing owners. Optional AI cannot become a prerequisite for any read or export.

Define a closed bounded projection with exact plan/evidence revisions, safe selected source/manifest and observed
capability facts, confirmed stage outcomes, retained resources, warnings, uncertainty and current allowed next
actions. Minimize identifiers and paths; exclude credentials, keys, credential-store contents, raw environment or
log dumps, arbitrary files, prompts/hidden reasoning and unrelated data. Sanitize errors before presentation or
persistence. Untrusted source text remains inert data, not a command, HTML or reason to expand inspection.

Require current attempt/playbook visibility and applicable Workspace/environment scope on every query/export.
Distinguish current rights from historical plan consent and source observation time from current qualification.
Bound fields, bytes and query work; deny unsafe or incoherent evidence rather than returning a misleading complete
report. Ordinary reads never contact providers, inspect private paths, run commands, reconcile effects or refresh
capabilities. A displayed allowed action is not a grant; the operation owner revalidates when explicitly invoked.

Each playbook identifies its revision, applicable known conditions, primary sources, expected results, safe
commands or normal UI actions, and recovery/rollback limits. Unsupported or outdated cases remain explicit unknowns
with useful safe evidence. Keep platform/tool qualification honest. Human-run setup remains explicit, scoped work
outside the browser Agent; viewing/copying a command never executes it or collects credentials.

Use the existing frame/theme, sole current `/me`, no-store transport and volatile caches. Fence late successes and
errors on authority/attempt/context change and retire private data on revocation/logout. No persisted browser draft,
report cache or automatic export/replay. Explain that an explicit downloaded/copied report is user-controlled;
application invalidation cannot recall an external copy. Export permission does not confer provider-disclosure
permission. Preserve loading, partial, stale, denied, unavailable and unsupported states.

## Acceptance criteria

- [ ] Real creation failures, including retained local/remote effects and failure before registration, show the
  applicable versioned playbook and safe export without Agent/provider availability or a fabricated final receipt.
- [ ] Projection/export behavior enforces bounds, current scope and redaction; malformed/unsafe/stale evidence does
  not leak private facts, invent success or cause live inspection/upload.
- [ ] Playbooks cite exact revisions/sources and truthful qualification, with directly reviewed/exercised commands
  and recovery limits; unknown conditions remain unknown rather than speculative repair.
- [ ] Fresh production keyboard/focus/announcement, responsive light/dark, reflow/accessibility and applicable
  reduced-motion evidence covers useful failures, denied/stale/unavailable states and explicit export.
