# Review and explicitly reconcile an Agent's template Permission drift

## Outcome

An authorized administrator compares an existing Agent with an explicitly selected published template revision,
then deliberately adds reviewed missing Permissions or synchronizes the complete eligible set. This delivers
TICKET-00078's safe maintenance outcome after template evolution without automatically changing existing Agents.
One complete browser/API/Application/package-assignment journey normally owns one PR; preview, both actions,
recovery and verification are parts of that outcome, not separate inspection or infrastructure TASKs.

## Scope

- In scope: Exact version-bound desired/actual drift, distinct Add Missing/Auto-sync confirmations, protected
  complete-set package assignment, atomic reviewed-source evidence, fresh current checks and no-op safety;
  accessible browser results, stale/uncertain recovery and actual next-use revocation evidence.
- Out of scope: Another Agent/Permission store, generic grant editor, Agent creation or credential rotation,
  Team transfer, template publication, prompt/profile rebinding, session refresh, recurring synchronization,
  automatic ancestor propagation, AI/provider proposals or a standalone proof product.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Inspect an Agent against a published revision | N/A — read-only | TASK-00259's protected identity/assignment facts plus TASK-00300's exact published template, current definitions and scope | N/A — preview repairs nothing | Bound revision and compared revision shown separately with complete drift or explicit failure/uncertainty |
| Add reviewed missing Permissions | Confirmed additions-only reconciliation using supported package complete-set assignment | Fresh authority, expected Agent assignment, selected revision, full resulting set and reference/scope checks | Package assignment facts and required owned reviewed-source evidence for actual effects | Reviewed eligible missing items added atomically; extras preserved and remaining drift shown |
| Synchronize the complete desired set | Separately confirmed full reconciliation using the same qualified package boundary | Fresh complete desired/actual sets, additions/removals and expected state | Same owning assignment/evidence semantics, never invented per-item events | Exactly the reviewed eligible desired set replaces actual direct Permissions atomically |
| Resolve conflict or uncertain completion | No automatic replay; explicit fresh confirmation only after safe resolution | Current protected assignment and attributable original outcome where established | No success fact inferred from a matching later set | Truthful outcome/current-state distinction without duplicate grant or hidden repair |

Names describe owned cross-boundary behavior, not existing command classes. Public package assignment remains the
mutation owner; Agent OS owns template-derived intent, human authority, scope and reviewed-source coordination.

## Validation and permissions

### Current authority and honest drift

Reuse TASK-00256's distinct protected direct-assignment management right and current managed Super Admin policy.
Do not define another management Permission or treat MANAGE_AGENT_TEMPLATES, a Role name, actor ID or a preview
as assignment authority. Every supported HTTP/direct-bus/CLI/worker path enforces current human intent, target,
installation and applicable Team/Repository scope; unsupported routes stay disabled. Ordinary browser JWT,
Origin/CSRF and safe transport validation remain in their existing owners. Agents cannot invoke human management
by using their own signed request or acquiring a SUPER_ADMIN_ONLY right.

Use TASK-00259's existing safe Agent inspection and TASK-00300's scoped template selection/impact path, not a new
directory or Permission catalog. Independently authorize disclosure of the Agent and compared template. Display
stable Agent identity, existing bound template/revision and the explicitly compared immutable published revision.
Never substitute today's current revision, a same-named template, a draft or an unreviewed ancestor update.
Show complete desired and actual sets, additions, removals/extras, invalid/ineligible references and uncertainty,
with attributable observation/selection revisions. Bounded/paged reads must not masquerade as complete sets.

Distinguish narrowly established missing/ineligible references from an unavailable or inconsistent source. Failed
joins, hidden details or malformed package views cannot become an empty set or a partial successful comparison.
A historically requested ID stays identifiable where authorized; do not rewrite history or resolve by name.
Previews have no grant/revoke, repair, audit-change or provider effect and are not durable permission to mutate.

### Two explicit operations, one complete-set boundary

For Add Missing, bind confirmation to the exact reviewed eligible missing items and actual assignment. Compute the
complete resulting set from that reviewed actual set plus those items; preserve all extras. Validate the full
result under package tier/reference rules and owner-approved grant limits. Invalid existing assignments cannot
be laundered by validating only the additions. Invalid or unselected desired items remain visible and unresolved;
never silently drop them and label the Agent synchronized. This is not arbitrary grant entry outside the selected
template. Any supported partial additions must be explicitly reviewed and reported as remaining drift.

For Auto-sync, review the complete desired set and explicitly confirm additions and removals, including an empty
eligible desired set when permitted by the owning rules. Invalid requested items block exact synchronization;
no filtering, normalization by name or guessed replacement can manufacture a valid desired set. Cancellation
sends no assignment command. Neither action establishes an always-on policy.

Bind each intent to the current human, exact Agent, action type, compared published revision, expected assignment
revision and complete reviewed before/after sets, plus applicable template selection and scope observations.
Validate strict bounded transport values rather than relying on package coercion; use the actual assignment
revision contract, including valid initial zero, not the Feature subsystem's positive-revision rule.

At mutation, revalidate authority, Agent state, current references/tiers, scope, grant limits and all relevant
expected generations. A changed set, scope or selected revision requires refresh and renewed human confirmation;
no automatic rebase to the latest desired/actual set. Preserve ABA protection when visible values return to the
same content. A valid no-op still checks current authority, state and references, changes no assignment revision
and emits no fabricated grant/revoke fact. Direct Permissions must be eligible ADMIN_SAFE even for Super Admin.

### Atomic-assignment and outcome hold

Keep `needs-info` until the chosen tagged/locked public package contracts support the complete consumer composition.
The inspected ReplaceAgentPermissions command accepts actor ID, Agent ID, expected assignment revision and desired
IDs. Its handler delegates to an internal coordinator that owns the canonical transaction and emits an assignment
event afterward. This supplies package set/revision behavior, not atomic consumer authorization, template/scope
intent or required reconciliation audit. The actor is provenance, not an authorization check. The coordinator is
`@internal`, not an available consumer extension point.

Qualify current actor/Agent/Team/template selection/reference checks and narrowly owned secret-free reviewed-source/
actual-outcome evidence in the same supported assignment transaction. No hidden repository policy/audit, outer or
nested transaction, copied package handler, vendor patch or post-commit subscriber may manufacture atomicity.
Resolve missing seams under their actual owner with separate authorization and release qualification, then map
real prerequisite TASKs; do not invent blockers or imply initial-creation qualification resolves this whole contract.

Include desired-state no-ops in the proof: the inspected coordinator can return before final repository replacement.
A previously read matching Agent/set is not evidence of final current authority under competing writes. Qualify
actual cohort-first ordering, shared-connection reference fences, full expected-state comparison and all relevant
assignment, Permission removal/promotion, scope and authority participants through commit/rollback. Existing
PostgresAgentRepository::getOperationContract() rejects unavailable composition; storage fixtures are not live
assignment qualification. These are unresolved integration guarantees, not a demonstrated deployed exploit.

Preserve public package event semantics. The inspected replacement handler returns void and can rethrow after
post-commit event failure; lack of acknowledgement does not prove rollback. Record attributable reviewed-source
and actual outcome through the qualified narrow owner, not an event-only audit or generic operation ledger.
Current state may establish present facts without proving the original operation succeeded. After uncertainty,
refresh authoritative state and resolve original attribution where supported before another attempt; retain
unresolved status rather than replay, compensate, infer success from equality or retry with a new identity.
