# Admit requester-owned restores with bounded lifecycle authority

## Outcome

An authorized requester can submit and inspect one exact bounded archive-restore operation through protected API
operations, with durable original-request recovery and current owner fences. This approved slice A of
[TICKET-00115](../tickets/00115-TICKET.md) supplies real early admission/status/lease behavior, not a generic job engine
or a promise that later browser/cleanup work will establish authority.

## Scope

- In scope: Exact catalog selection, idempotent request/status operations, durable intent and expected-generation
  transitions, aggregate admission/reservations, bounded source leases, current requester/scope authority and early
  restriction/publication/disposal participants.
- Out of scope: Worker import, backend provisioning, browser UI, export/download, new hold/purge authority, sharing,
  automatic mutation replay or another Workflow/queue platform.

Follow [WF-039](../wayfinder/tickets/WF-039-define-searchable-retention-and-verified-archives.md)'s restore contract and
[WF-041](../wayfinder/tickets/WF-041-select-the-authorized-log-browser-integration.md)'s current-authority rules.
Resolve only TASK-00470's currently authorized catalog identities; record requester, exact selected segments,
source/time basis, original request identity/payload, limits and lifecycle state. Unknown estimates require bounded
discovery, never unlimited scans or trusting caller size declarations. Reject conflicting reuse of a request identity;
uncertain submission is resolved against the original outcome before any explicit retry.

Enforce up to seven days/1 GiB decompressed input per selection, one running/four pending per installation, one
outstanding/requester and at most four ready scopes. Coordinate actual capacity/reservations under real PostgreSQL
races; leftover/abandoned work counts until its disposition is known. Pending expiry is one hour; execution budget
15 minutes; ready lifetime is fixed at 24 hours from actual readiness, never sliding or renewed by reads/exports.
Actual byte/resource enforcement remains TASK-00475's worker and the installation binding, not a manifest estimate.

Bind bounded source-segment leases to TASK-00467's existing owner participants. Restore cannot indefinitely extend
primary archive retention or become a new preservation owner. Current hold/purge/policy changes, lease acquisition,
claim/release and late publication must agree under actual expected-state fences. A lease is not a permanent grant.
Persist intent/claims and required audit on the canonical transaction; external operations follow after commit.
Keep source ownership/restrictions authoritative after restart; missing state denies unsafe publication/disposal.

Require current requester/session/capability/policy at admission, execution and each status/content fetch/release.
A scope must additionally be requester-owned, query-ready (or deliberately published verified partial), unexpired
and unrestricted. Failed/cancelled/expired scopes are inaccessible regardless of physical leftovers. These logical
checks ship here, not only with TASK-00477's later cleanup scheduler. Unknown authority withholds output; a request
snapshot, valid job ID or another Super Admin's rights cannot substitute for current ownership. Do not persist raw
Bearer tokens or recreate requester authority from worker credentials. Status truthfully distinguishes pending,
working, incomplete, unavailable and denied states without claiming an absent worker/import is ready.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Request bounded temporary search | Exact idempotent restore admission | Current catalog, requester authority, policy and capacity | Committed restore intent, not Workflow events | One bounded recoverable operation or busy/denied outcome |
| Inspect or reconcile a request | No mutation for status; original-outcome reconciliation where required | Current requester and exact operation | Committed lifecycle facts only for transitions | Truthful status without cross-requester existence leaks |
| Claim work and lease sources | Enrolled exact generation/lease operation | Current actor, source owners, expiry and restrictions | Committed claim/reference facts | Bounded work authority without extending primary retention indefinitely |
| Deny stale publication/access | Current expected-generation transition/check | Current policy, requester, readiness and expiry | Safe lifecycle facts | Immediate logical denial independent of physical cleanup |

## Validation and permissions

Require `READ_LOGS` + `RESTORE_LOG_ARCHIVES`, through TASK-00462/00463, plus exact requester/scope policy. No log right
confers storage, launcher, hold or purge authority. Use ADRs [0001](../adr/0001-application-ownership-and-orchestration.md),
[0002](../adr/0002-postgresql-consistency-and-durable-effects.md),
[0003](../adr/0003-browser-authentication-security-profile.md) and
[0004](../adr/0004-client-authority-and-runtime-state.md): no external effect inside business transactions, same-origin
Bearer/applicable CSRF, private no-store and current checks before release. Typed requests are bounded to 16 KiB;
status/catalog operations retain bounded deadlines, responses and shared admission, not an unbounded polling queue.
No arbitrary bucket/tenant/URL/path, raw content in errors or Role-name bypass. Unknown and unauthorized IDs do not
reveal existence/counts. Preserve required audit semantics and safe public HTTP behavior.

## Acceptance criteria

- [ ] Actual API admission/status enforces both permissions, requester ownership and exact catalog selection;
  concurrent jobs/reservations cannot exceed limits or disclose another requester's state.
- [ ] Original request/payload/result survives interruption; duplicate/conflicting/uncertain requests do not create
  contradictory work, reset clocks or replay a mutation automatically.
- [ ] Real owner leases and PostgreSQL hold/purge/policy/claim races prevent stale publication, unsafe source release
  and indefinite primary-retention extension; unknown authority denies affected operations.
- [ ] Fixed pending/execution/ready deadlines and current scope checks deny expired/revoked/failed content before
  scheduled physical cleanup, without storing credentials or inventing readiness.
- [ ] Owned API/authority/state/concurrency tests and actual owner integration pass with full `./bin/build` and
  explicit missing runtime/resource limits disclosed.

## Verification and evidence

Use real PostgreSQL participants and independent controlled connections/clocks to test simultaneous admission,
request retries, lease races, revocation and unknown owner state. Exercise actual protected API operations and
original outcomes; fake principal snapshots do not prove fresh execution/release authority. Test owned behavior,
not migrations/configuration/wrappers or vendor internals. Run focused repository wrappers and full `./bin/build`.
Record exact actor/operation/participant identities, bounds, warnings and uncertainty. Provider qualification is
separate; no live restore or private-content read is authorized by this planning record.
