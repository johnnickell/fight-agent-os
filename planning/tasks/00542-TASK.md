# Retire task-owned disposable Docker storage and qualify active-repository cleanup

## Outcome

Remove the concrete disk-exhaustion delivery blocker: local task execution must not silently accumulate
owned disposable Docker storage, and Land/Build completion must report verified cleanup or finite incomplete
holds. Extend the existing executable cleanup operation and its callers, then qualify the actual lifecycle
across the current active repositories. This is a separate standalone bug, not reopened TASK-00540 acceptance.
John approved this scope, separate identity and cleanup-first top priority on 2026-10-27.

## Reproduction and evidence

The authorized October 27 machine recovery found 2,766 volumes, including 2,715 unreferenced anonymous volumes
occupying approximately 341 GB. It removed 2,560 qualified unreferenced non-Omphalos volumes without force,
prune or service shutdown. That one-time discard grant is historical, not a permanent cleanup policy or fresh
proof of this TASK. Concurrent test resources appeared during inventory; global snapshot differences cannot
establish ownership. Logical Docker allocation and physical host free-space recovery are distinct measurements.

Read-only Fight Common evidence at observed HEAD `1d6feb98aa6944ed8c92f39c9232b0f0c0674a37`,
`bin/.disposable-database-runtime`, shows image-declared MySQL/PostgreSQL anonymous volumes outliving container
removal. The exact source copy/digest and storage corroboration are retained under canonical ignored
`.runs/build/storage-recovery-20261027-2bnuaogV/`, including `root-cause-reference.json`. This is source evidence,
not a fresh reproduction or permission to edit Common. Reproduce safely before repair. Agent OS currently
accounts for containers/networks/worktrees/refs, but its volume-preservation statement is not leak-free storage
retirement. Preserve TASK-00534/00537/00540 history and canonical reports.

## Scope

- Extend the same bounded helper, Land callers, Work/QA inventory and Build cleanup-only continuation with
  named and image-declared anonymous volume provenance captured while creating containers still exist.
  Bind exact IDs, workload/source revision, mounts, creation evidence, declared disposability, authority and
  current consumers, including stopped containers. Do not lose that provenance when containers disappear.
- For containers, networks and storage, distinguish task-created resources from merely used and shared/reused
  resources. Account explicitly for task-created images/build caches too; reused images/layers are not disposable
  by association. Define safe retention, dependencies, size and reason without deleting shared layers or pruning.
- Repair leaks in the provider's owned executable lifecycle, not just its wording. Identify each active
  repository's source/runtime leak owner and separate adoption from an owning-project executable fix. This
  central TASK grants no cross-project edits: obtain that project's repair authority and carry exact revision,
  owning evidence and integration result. Any missing required fix is a finite integration hold, never fleet PASS.
- Resolve the current operator-authoritative active-repository inventory at execution, including current
  Common/Agent OS/Omphalos use as applicable. TASK-00519's historical nine-project inventory is only a reference,
  not today's completeness proof. Record every current repository, source revision, runtime path, caller,
  qualification result, exclusions and unresolved owner/action before claiming active-fleet completeness.
- Provide one reusable bounded lifecycle checker as direct owning-tool infrastructure qualification. Exercise
  real Docker and actual helper/callers; it is neither product-suite testing nor a second canonical gate
  orchestrator. Keep the checker within this repair, not a separate proof-only TASK or global registry.
- Qualify normal completion, failure, cancellation and interruption/recovery. Reobserve identity, exclusions,
  consumers and actual absence before effects/resume; execute only missing authorized effects. Report exact
  removed/retained/held/failed outcomes, bytes, storage observations and finite recovery without blanket exemptions.
- Out of scope: global prune/force, shared-service shutdown, unknown/durable data erasure, remote-ref deletion,
  automatic merge/deploy, universal shell enforcement, hostile-code sandbox claims or a forever leak-free guarantee.

## Validation and permissions

Recheck exact identity, creation provenance, data classification, authority, consumers and exclusions immediately
before every effect. Names, labels, timestamps and global before/after differences alone are insufficient.
Unknown/shared/durable/excluded resources and inspection/permission failures hold; do not stop a consumer,
change protections, force removal or acquire broader authority to clear them. Existing proven-disposable task
authority should not require recurring prompts; a receipt or this plan creates no new discard permission.

All qualification uses bounded isolated task-owned fixtures, never live Omphalos data/services or another
repository's active workload. Preserve protected resource configuration, mounts, data sentinels and permissions
before/after. Concurrent Common/Omphalos activity remains foreign, not an equality failure to repair or an owned
volume delta. Evidence stays outside deletion candidates, with credentials/private values excluded from output.

- [ ] Normal, failure, cancellation and interrupted/resumed real-Docker lifecycles leave zero required owned

- [ ] Actual installed Pi Land and Build continuation exercise the changed lifecycle on disposable fixtures;
