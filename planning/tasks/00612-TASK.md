# Enforce 100% Unit-only line coverage of owned unit-testable PHP behavior

## Outcome

Make the PHP quality gate reject missing Unit coverage for owned unit-testable behavior, even when other suites exercise the same lines. Keep Integration, Functional and PostgreSQL-backed behavior checks.

## Scope

- Run Unit, Integration, Functional and Postgres once each, without overlap or omissions. Collect coverage only from Unit. Remove the combined reports and gate; do not set coverage quotas for other suites.
- Define the denominator of owned unit-testable executable lines, retain unexecuted files, and justify exact runtime-only exclusions. Close gaps with meaningful Unit tests in this TASK, not follow-up TASKs.
- Enforce 100% Unit-only line coverage and report the denominator, count and exact gaps. Do not rerun suites just to generate another report.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Verify Unit-only coverage | Owning backend verification command | Unit coverage and owned PHP source inventory | N/A: verification | Report Unit coverage and fail the gate when required lines are uncovered |

## Validation and permissions

Preserve report freshness, trusted local coverage artifact handling, existing database guards, and suite failure behavior. Missing or unusable Unit coverage must not pass. No new product permissions.

## Acceptance criteria

- [ ] The gate reports and enforces 100% Unit-only line coverage against the documented denominator, with unexecuted owned source included and exact exclusions explained.
- [ ] A line exercised only outside Unit fails the coverage gate. Missing or unusable coverage does not pass.
- [ ] All four existing suites run without duplicate execution or lost cases. Added Unit tests assert owned behavior rather than merely executing lines.

## Verification and evidence

Record measured gaps, disjoint suite membership, denominator and exclusions, and final reports. Show failure and success through owning checks or bounded probes without adding product tests of coverage tooling. Run the canonical build and hand off to independent Review and applicable QA only when complete.

## Coordination

No prerequisite TASKs. Coordinate shared gate changes with [TASK-00611](00611-TASK.md) without integrating that branch here. Planning approval does not select an implementation checkout or authorize implementation or publication.

## Decisions

The original plan kept the combined gate and qualified same-run per-test attribution. That attribution reconciled against JUnit in the initial measurement. The maintainer subsequently selected the Fight Common execution pattern and retired combined coverage; see the [ADR amendment](../adr/0001-application-ownership-and-orchestration.md#maintainer-amendment--unit-only-coverage-task-00612). The maintainer waived the one-reviewable-PR size constraint for this TASK, not the coverage requirement or independent acceptance.
