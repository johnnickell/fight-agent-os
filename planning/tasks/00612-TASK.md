# Enforce 100% Unit-only line coverage of owned unit-testable PHP behavior

## Outcome

Make the PHP quality gate reject missing Unit coverage for owned unit-testable behavior, even when other suites cover the same lines. Keep the combined coverage check and the integration, functional, and PostgreSQL-backed tests.

## Scope

- Qualify per-test attribution from the existing single PHPUnit execution before choosing how to enforce the requirement. Preserve the [accepted execution model](../adr/0001-application-ownership-and-orchestration.md). If attribution cannot support enforcement, report the evidence and obtain an ADR amendment before making an incompatible change.
- Define the denominator of owned unit-testable executable lines, retain unexecuted files in scope, and document concrete reasons for exclusions. Close measured gaps with meaningful Unit tests. Do not count combined coverage, omit files, or waive gaps to get a passing gate.
- Enforce 100% Unit-only line coverage in the owning PHP checks and report the denominator, coverage, and remaining gaps separately from existing combined results. Do not rerun a suite just to generate another report.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Verify Unit-only coverage | Owning backend verification command | Per-test attribution and owned PHP source inventory | N/A: verification | Report Unit coverage and fail the gate when required lines are uncovered |

## Validation and permissions

Preserve report freshness, trusted local coverage artifact handling, existing database guards, and coverage failure behavior. Do not treat absent or unknown attribution as a pass or introduce new product permissions.

## Acceptance criteria

- [ ] The gate reports and enforces 100% Unit-only line coverage against the documented denominator, with unexecuted owned source included and exclusions explained.
- [ ] A line covered only by Integration or Functional tests fails the Unit-only gate even when the combined check passes. Missing or unusable required attribution does not pass.
- [ ] The existing combined check and all suites still run without duplicate execution. Added Unit tests assert owned behavior rather than merely executing lines.

## Verification and evidence

Record measured gaps, attribution qualification, denominator and exclusion decisions, and the final reports. Show the failure and success cases through owning commands or bounded probes; do not add product tests of coverage machinery. Run the canonical build and hand off to independent Review and applicable QA. If gaps exceed one reviewable PR, report the measured groups and propose bounded follow-up TASKs; do not claim compliance or weaken the requirement.
