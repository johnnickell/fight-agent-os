# Apply multi-record Planning proposals atomically

## Outcome

An authorized human applies a complete Make Tickets/Make Tasks proposal, or supported initial map/decision set,
as one all-or-none Planning change. Any stale member or invalid relationship preserves the whole proposal for
review without leaving a partial hierarchy. This extends the existing semantic Apply path, normally in one PR.

## Scope

- In scope: Bounded complete batch preview/confirmation, existing/new member correlation, atomic semantic creation/
  revision/relationship/ordering composition, original batch result and concurrent failure recovery.
- Out of scope: Arbitrary batch-command platform, new allocator/queue, best-effort partial application, distributed
  saga presented as atomic success, automatic child generation, lifecycle bypass, execution or publication.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Review complete decomposition | N/A — protected preview | Parent/current children, exact member revisions, relationships and queue impact | N/A | Complete intended batch with safe blockers and explicit additions/revisions |
| Apply exact batch | Explicit human operation-specific batch command | Current authority, parent eligibility, complete graph and expected revisions | Owning committed Planning events plus accepted batch linkage | All intended records/constraints/audit/intent commit together or none |
| Inspect original outcome | N/A — authorized query | Stable batch command result and created/revised references | N/A | Original mappings after response loss, not another hierarchy |
