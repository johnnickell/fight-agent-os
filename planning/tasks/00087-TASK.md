# Version research notes and prototype evidence

## Outcome

Research notes and disposable prototypes are independently versioned Planning evidence with semantic history, safe provenance, explicit findings/verdicts and managed durable artifact references; accepting a prototype promotes findings without making scratch code authoritative.

## Scope

- In scope: Separate event-sourced `ResearchNote` and `Prototype` aggregates; COMB identities; repository ownership; typed research question/sources/findings/citations/decision links; prototype question/hypothesis/type/assumptions/disposable scope/run instructions/findings/review/cleanup ownership and accepted/rejected/inconclusive verdict; semantic revisions/expected versions/idempotency; Planning-root links; managed artifact-storage capability and metadata references/digests/media type/size/provenance; copy-before-acceptance; retention holds/tombstoned purge references; current/history/list Views; create/revise/verdict/link Permissions; PostgreSQL streams/projections/API.
- Out of scope: Generic documents, arbitrary executable artifact hosting, running prototypes, preserving disposable `.runs/` copies, browser design UI, generalized criterion satisfaction/waiver, Markdown import, automatic promotion of code, external object-store selection beyond a bounded capability and automatic deletion on archive.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Create/revise a research note | Intent-specific create/section/source/finding commands | Preview source/citation/Planning links and expected version | Semantic research events | One independent stream and rebuildable projection preserve normalized evidence/provenance |
| Create/revise a prototype | Intent-specific create/scope/instruction/finding/review commands | Preview disposable boundary, cleanup owner and artifact state | Semantic prototype events | One independent stream preserves question, experiment, findings and review without promoting code |
| Attach durable artifact evidence | Record a verified managed artifact reference | Validate storage reference, digest, media type, size and provenance | `PrototypeArtifactRecorded` or equivalent | Durable metadata links only after content is copied and verified outside disposable scratch |
| Record prototype verdict | Accept/reject/mark inconclusive command | Explain findings, review, cleanup and durable evidence readiness | Type-specific verdict event | Verdict appends; acceptance promotes cited findings only, never files/code or application authority |
| Retain or purge artifacts | Explicit retention/purge command where authorized | Explain active links/holds and resulting tombstone | Retention/purge semantic event | Holds prevent premature purge; later purge leaves digest/provenance tombstone and never runs automatically on archive |

## Validation and permissions

ResearchNote and Prototype are separate aggregate types and streams, not work items or EPIC hierarchy children. Validate one active Repository owner, closed typed fields, bounded Markdown-capable narrative, normalized citation/source metadata and explicit links to authorized Planning roots. A note may link to multiple roots; links do not transfer ownership or authority.

Prototype acceptance requires completed findings, review disposition, cleanup ownership, verified durable artifact references for any accepted file evidence, and expected version. Managed storage receives copied content before the event commits; record stable reference, digest, media type, size and provenance, not embedded generated files. Coordinate non-transactional storage safely: failed copy records no event; failed database commit cleans only ownership-proven new unreferenced content or records recoverable cleanup, never an existing artifact.

Acceptance promotes immutable findings/references for consumers and never prototype code, dependencies, runtime configuration or `.runs/` paths. Rejected/inconclusive verdicts remain evidence. Revision after verdict requires an explicit reopen/revise path that preserves prior verdict history. No process executes run instructions or trusts artifact media/type based only on client input.

Retention holds last while linked Planning remains active and through accepted map handoff/resulting EPIC linkage as WF-010 requires. Archive may release a mandatory hold but never deletes automatically. Purge is explicit or separately policy-driven, refuses active holds, removes only an ownership-proven managed object and appends a tombstone/digest/provenance; backup retention limitations are reported honestly.

Require separate view/create/revise/verdict/link/artifact-retention Permissions. Repository and linked-root scope are authoritative. Safe Views/API expose citations and bounded artifact metadata but no local scratch paths, embedded binaries, credentials, private service locators or raw storage errors.
