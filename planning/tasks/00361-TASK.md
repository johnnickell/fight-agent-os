# Start and continue repository Planning intake

## Outcome

An authorized planner submits durable repository-scoped intent from the existing Planning Dashboard, inspects
meaningful existing-work recommendations and explicitly chooses continuation or new work. Intake is not a map.
This is the first production browser conversation slice, not a demonstration route or a new Dashboard.

## Scope

- In scope: Prominent What do you want to build? entry, durable intake, active-intake navigation, bounded existing
  artifact inspection/recommendations, explicit target selection and initial permitted provider/model choice.
- Out of scope: Automatic artifact creation/attachment/reparenting, final interviews/Apply, a new conversation or
  role registry, Coding Workflow controls, persistent manual drafts and final named Project Manager integration.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Submit intake | Explicit durable intake/input command through existing owners | Registered Repository, current scope, permitted model and capability readiness | Owning intake/input/attempt facts | Durable input before bounded delegated inspection, not a Wayfinder map |
| Inspect matches | Explicit admitted inspection when generation is needed; status remains read-only | Authorized maps/artifacts, current operation and exact source revisions | Existing attempt/result facts only | Attributable recommendations with uncertainty, never automatic attachment |
| Choose continuation or new work | Exact expected-state target/operation selection | Current target eligibility and human authority | Owning selection/operation facts | One deliberate bounded intent, not implicit decomposition or execution |

## Validation and permissions

Extend TASK-00114's authenticated, registered, database-authoritative Planning workspace. Consume TASK-00250's
actual identity/profile integration and TASK-00352's protected conversation operations, including upstream durable
input, serialized attempts, finite provider admission and original outcomes. Do not put provider or Agent keys in
browser transport, HTML, logs or storage. Bind initiating human, acting Agent, Repository, target or new-artifact
intent, conversation/attempt and exact snapshots; a profile or role name grants no authority.

Inspect only currently authorized artifacts and children. Recommendations are untrusted suggestions with sources,
not automatic duplicate detection authority. Explain unavailable/denied/stale support; never silently search another
Repository, create a map or launch a fallback Agent. Expected-state selection fences late recommendations, changed
intake and duplicate submission. Ordinary navigation/status makes no paid request. Selecting a terminal/archived
parent explains its owning reopen/restore prerequisite rather than performing it.

Follow ADR 0003/0004's single current-principal/cache owners, strict response decoding, no-store and local context/
request-generation fences. Logout, revocation or Repository change retires private data; late successes and errors
cannot restore it. Form input stays volatile until explicit submission, with dirty-navigation warning rather than
an autosave promise. Durable intake is recoverable through the protected owner, not browser persistence.

## Acceptance criteria

- [ ] Real browser submission preserves exact intake and original attempt before delegated work; duplicates or lost
  acknowledgements resolve the original outcome without another paid request.
- [ ] Existing-work recommendations are scoped, source-attributed and human-selected; new-work choice creates no
  map, reparenting, duplicate artifact or follow-on execution.
- [ ] Initial allowed provider/model selection retains exact requested/reported identity and honest unavailable
  states; credentials and hidden reasoning never reach the client.
- [ ] Revocation, malformed responses, stale callbacks and cross-Repository navigation fail safely without private
  cache leakage or browser-persistent business state.
- [ ] Owned API/client behavior tests and actual accessible browser intake evidence pass.
