# Await asynchronous authentication-result focus in acceptance checks

## Outcome

Remove the intermittent frontend focus-check delivery blocker observed during
[TASK-00516](00516-TASK.md), whose accepted Land guidance does not change application components or these
checks. Make existing login/password-reset completion checks observe the required actual focus, rather than
treating heading DOM presence as proof that the passive focus effect has completed. Preserve the strict
accessibility requirement and all other behavior assertions. This is a standalone bug, not a new feature or
testing-infrastructure project.

  `waitFor` around the actual strict focus predicate. Preserve heading discovery, field-clearing, request-count,
