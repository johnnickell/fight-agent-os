# Reconcile the four protected log capabilities

## Outcome

Trusted operators can preview and deliberately reconcile the four approved log permissions through the existing
managed-policy operation, preserving stable identities and protected delegation invariants. This is approved slice B
of [TICKET-00113](../tickets/00113-TICKET.md), an explicit additive extension of the delivered catalog.

## Scope

- In scope: Stable managed definitions for `READ_LOGS`, `EXPORT_LOGS`, `RESTORE_LOG_ARCHIVES` and
  `DOWNLOAD_LOG_ARCHIVES`; existing preview/apply/reference integration; affected exact-name consumer catalogs and
  operator documentation; actual package-backed reconciliation and protected-delegation verification.
- Out of scope: A second grant model, new roles, non-admin delegation, user promotion, automatic reconciliation,
  live permission assignment during planning, log endpoints, restore/export/download implementation and Docker rights.

Use [WF-041's approved audience](../wayfinder/tickets/WF-041-select-the-authorized-log-browser-integration.md#approved-audience-resolution),
[TICKET-00015](../tickets/00015-TICKET.md)'s existing managed policy and
[TICKET-00031](../tickets/00031-TICKET.md)'s delegation rules. All four definitions are `SUPER_ADMIN_ONLY`, included
in managed Super Admin authority and excluded from ordinary users, custom-role and direct-Agent grants. Runtime
consumers check exact current capabilities, never Role-name bypasses. Separate intent checks do not promise separately
grantable audiences under the initial managed role, nor prevent manual copying of already disclosed content.

Preserve every existing permission/role identity and invariant. Generate new stable IDs using owning factories or
the UUID library at implementation; do not invent UUID literals or regenerate existing identities. Reuse package
preview/reconciliation, transaction/audit and explicit trusted-operator activation paths; no new bootstrap workflow.
A missing/unreconciled definition must fail closed in consumers, not create permissions at application boot.

Supply the exact intent contract early: `READ_LOGS` for live reads/coverage; add `RESTORE_LOG_ARCHIVES` for requester-
owned restore operations/scopes; add `EXPORT_LOGS` for extraction, additionally restore authority for restored exports;
`DOWNLOAD_LOG_ARCHIVES` with `READ_LOGS` permits verified downloads and their necessary bounded catalog reads without
restore power. Hold/purge/policy/storage/execution authority remains separate. Later consuming TASKs prove enforcement
at their actual operations; this catalog TASK cannot certify endpoints that do not yet exist.
