# Narrow a current memory scope to matching entry IDs

## Outcome

An assigned Agent asks a bounded typed question over its currently permitted private and shared memory
scope, receives only matched entry IDs, revision/provenance and honest coverage, and selects exact source
text only by a later separately authorized read. A partial set or failed Jev evaluation is not complete
negative guidance. This is one independently reviewable scope-selection MCP/Application/evaluator use case,
not a bulk Agent-context preload or a replacement for exact-source reads.

## Scope

- Reuse [TASK-00193](00193-TASK.md)'s authenticated Agent, permitted exact-source resolution, independently
  qualified provider disclosure, typed-question validation and shared Jev budget/receipt capability. Require
  an explicit current source scope and typed yes/no or declared-choice question; server-side Application
  authority selects eligible current private/shared entries, not an Agent-supplied enumeration of guessed IDs
  or an unrestricted database search. Respect Agent identity, Repository/assignment, Phase/Workflow/TASK
  lifecycle and revocation for every candidate; ordinary helpful-memory selection excludes retracted entries
  and pending/rejected proposal text. No vector store or Jev-held Agent Permission.
- Evaluate bounded chunks of eligible actual revisions on behalf of the same caller under the shared
  evaluator's payload, question, concurrency, timeout and conservative spend ceilings. Choose memory-specific
  candidate, byte, count and coverage policy from measured authorized behavior rather than copying the file
  tool's threshold or example file cap. If the scope cannot be completely processed, report bounded matched
  IDs plus precise incomplete coverage/reason (or fail safely), never an all-clear/negative answer for
  unevaluated items. Stop on revocation or stale source/assignment and do not use cached judgments.
- Return only matched authorized IDs and compact source-revision/evaluator/question/outcome provenance, not
  bodies, free-form summaries, fabricated line references or other hidden records' titles/counts. A later
  exact read uses the original memory operation and rechecks authority, freshness and safety; a matched ID
  cannot grant another principal, future session or closed assignment access.
- Verify usefulness and risks with bounded **permitted** sample cases and separately recorded live
  qualification when authorized: missed useful entries versus actual exact reads, scope coverage, latency,
  spend, output size and provider disclosure. No fixed universal threshold or claim that model selection
  proves completeness; source code and published Planning remain authoritative.
- Out of scope: published Repository/Workspace and separately authorized historical/audit scope paths
  (TASK-00195), future start index, general-purpose Jev investigations, SQL/repository-file screening,
  shared provider credentials in Pi, safety removal or an automatic offline fallback.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |

| Narrow active scope | Submit bounded typed selection intent, no memory write | Select authorized current entries and validated per-entry judgments | Selection/usage observation only | Bounded provider requests; matching IDs and honest coverage |
| Read selected original | N/A — read-only | Existing exact read under new current authority | N/A — no memory mutation | One permitted original source enters Agent context when requested |

## Validation and permissions

The application's current actor/scope check is authoritative for the whole request and each selected
candidate; no additional ceremony within the already authorized operation is required, but a separate
later exact read must reauthorize. Keep inaccessible candidate existence/count, bodies and source references
out of results, errors, receipts and logs. Reject broad, malformed or unsupported scopes, unbounded result
sets, unsafe provider disclosure, stale revisions, cancelled sessions and expired budget before another
provider request. Distinguish timeout/provider/input/limit exhaustion and uncertain charges; report actual
coverage with source revision so new/changed entries cannot inherit an older judgment. When Application or
database is down, stop scope lookup rather than falling back to a local copy. No memory-specific cache,
preload or live disclosure before qualified TICKET-00050 safety handling.

## Acceptance criteria

- [ ] A real authenticated Agent asks a typed question about an authorized current private or shared scope,
  gets only matching entry IDs and accurate evaluated/source-revision coverage, then separately reads an
  original selected entry under fresh authority.
- [ ] Wrong Agent/Repository, former Workflow, completed TASK, revoked Permission, retracted guidance,
  pending/rejected proposals and guessed scope IDs yield no hidden metadata or provider disclosure.
- [ ] Bounded multi-entry work respects shared payload, timeout, concurrency and spend ceilings; partial
  selection or provider failure exposes unevaluated coverage rather than a false negative, blind retry or
  unqualified alternate search. No memory-specific judgment cache is reused.
- [ ] Measured permitted scenarios compare missed useful entries, exact-read usefulness, latency, spending,
  context returned and actual provider disclosure; absence of a defensible bound/egress policy keeps live
  selection unavailable rather than silently accepting provider risk.
