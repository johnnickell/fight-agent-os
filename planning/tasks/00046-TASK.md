# Deliver the canonical email and password login journey

## Outcome

A versioned JSend login API and accepted responsive React route authenticate active users by canonical email/password through `AuthenticationService::login()`, support ordinary or explicitly remembered bounded sessions, return access authority only to memory, set refresh authority only in HttpOnly cookies, and preserve only a safe intended route under generic failures.

## Scope

- In scope: Login route/Action/validated DTO/View/OpenAPI; request protections/rate/throttle integration; exact configured `AuthenticationTokenPolicy`; TokenSet-to-access-response/refresh-cookie mapping; generic failure translation; typed client login service; in-memory token/session state transition; remember control; safe intended-route capture/restore; accepted production login/recovery navigation/loading/failure states; PostgreSQL/HTTP/cookie/client/accessibility/redaction/race tests.
- Out of scope: Refresh/logout endpoints, cross-tab coordination, `/api/v1/me`, dashboard implementation, public registration, MFA/passkeys/magic links/SSO/social login/usernames, password reset implementation, credential persistence, and broad browser automation.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Log in ordinarily | `AuthenticationService::login(email, password, false)` | Resolve canonical identity/hash, throttle, policy, and authority | `UserLoggedIn` | Authority/session commit; 15-minute access token returned and browser-session refresh cookie set |
| Log in remembered | `AuthenticationService::login(email, password, true)` | Same plus remembered policy | `UserLoggedIn` | 30-day idle/one-year absolute session commits; persistent refresh cookie bounded by absolute expiry |
| Reject login | N/A beyond attempted package service | Dummy/real password verification, throttle/rate/current identity state | Redacted package failure only | Generic response/UI reveals no identity lifecycle or credential detail |
| Restore intended navigation | N/A — client navigation | Read validated transient same-origin path | Client navigation signal only | Safe destination is retained for later shell routing without form/credential persistence |

## Validation and permissions

Validate bounded JSON with canonical email string, sensitive password, boolean remember, and no actor/role/permission fields before service call. Apply TASK-00045 CSRF, exact Origin, Fetch Metadata, HTTPS, JSON, `LoginThrottle`, and endpoint limits. Public login has no prior user permission but all controls are mandatory.

Configure package `AuthenticationTokenPolicy` explicitly: 15-minute access; ordinary one-day idle/two-day absolute; remembered 30-day idle/one-year absolute; ADR-approved conflict window. Do not use package starter defaults where they differ. Use `AuthenticationService::login()` directly for canonical lookup, dummy-hash behavior, verification/rehash, authority revision, session creation, token issuance, and event.

Nonexistent, pending, disabled, deleted, wrong-password, and throttled identities map to the same public status/envelope/message class and equivalent cookie behavior. Correlation retains only allowlisted operation context. Rate retry metadata must not reveal identity existence. Never echo/copy password into command serialization, logs, errors, audit, analytics, or client state beyond form memory.

Return only approved access token/access expiry/safe session metadata through explicit View; set opaque refresh credential only through TASK-00045 cookie factory. Access credential enters TASK-00025/00027's memory provider and no persistence. Ordinary cookie is session-only; remembered cookie persists no later than absolute expiry.

Intended route is a bounded validated same-origin application path, transiently owned by navigation/session restoration. Reject schemes/hosts/protocol-relative/control/oversized values and exclude password/email/form body/credential/arbitrary serialization. Client success may use a truthful bounded destination until TICKET-00018 supplies dashboard/current principal.

Recreate TASK-00035 accepted login design with semantic components/tokens. Support password managers, paste, labels/instructions, show-password only if accepted, remember explanation, keyboard/focus, recovery link, loading, generic failure, throttle, narrow/wide, light/dark, and reduced motion.
