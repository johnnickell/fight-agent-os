# Curate attributed lessons within a Workflow

## Outcome

An assigned Team Lead publishes attributed Phase/Workflow shared lessons through the first-party authenticated
MCP path, and an Engineer assigned to that Workflow reads relevant current guidance without reading anyone's
private notes. An authorized shared correction or retraction appends linked history; it never changes or erases
another author's original text. This is one independently reviewable end-to-end shared Workflow use case.

## Scope

- Extend [TASK-00185](00185-TASK.md)'s entry identity, source/provenance representation, guarded PostgreSQL
  persistence and authenticated Agent delivery for distinct shared Phase/Workflow scopes. The Team Lead owns
  Workflow-scoped publication; applicability to a Phase does not make an Engineer's private phase working memory
  shared. Authenticate the actual Agent, direct/effective Permission and current Workflow/Phase assignment on
  every operation; caller-provided scope IDs are targets, never a grant.
- Append in a deterministic accepted order with author, acting identity, source links, verification and scope
  metadata. Exact retries return the original result; two distinct similar or conflicting appends remain
  independently attributed, without automatic merge or a false claim of truth. Keep required Workflow phase
  handoffs and outcomes in the existing execution contract; a memory note neither creates nor edits them.
- Let an authorized shared-scope owner append linked corrections, supersessions or retractions with their own
  attribution and expected target identity. Original shared text remains historical; ordinary current guidance
  excludes a retracted claim while a separately permitted historical path can find its history. An ordinary
  correction does **not** remove prohibited content: TICKET-00050 owns exceptional removal.
- Expose bounded exact and current-scope reads to the assigned Team Lead/Engineer through the same Application
  authority. Engineer access to completed/other Workflows ends when its current Workflow assignment closes;
  current assignment to a new Workflow does not reopen its predecessor. Keep Domain invariants and Application
  authorization out of Doctrine and MCP adapters under ADR 0001/0002.
- Out of scope: TASK summary publication and successor consumption (TASK-00188); completed-work Project Manager,
  human and audit history (TASK-00189); another Agent's private memory (TICKET-00046); Repository/Workspace
  publication (TICKET-00048), Jev lookup (TICKET-00049), safety removal and human UI (TICKET-00050).

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Publish a Workflow lesson | Append shared lesson at owned Workflow/Phase scope | Resolve current Agent, Workflow/Phase, source and assignment | Shared lesson appended after commit | One durable, attributed entry; exact retry returns its identity |
| Read current guidance | N/A — read-only | Resolve permitted current scope and exact/current shared entries | N/A — no business mutation | Bounded relevant Phase/Workflow lessons, never peer private content |
| Correct, supersede or retract | Append linked attributed change | Resolve original, owner, current scope and history | Shared change appended after commit | Original stays in history; ordinary guidance excludes retracted claim |
| Lose ordinary access | N/A — read-only denial | Resolve live assignment/Workflow state before read | N/A — no change fact | Closed or unrelated Workflow content is not disclosed to the Engineer |

Semantic names do not fix message, event-store, database or MCP wire types.

## Validation and permissions

TASK-00185 supplies the authenticated first-party Agent/storage foundation and transitively depends on real
Team Lead/Engineer sessions and trusted Workflow context from TASK-00141 and the MCP path from TASK-00171.
Qualify those capabilities at execution, not from their planning text. Reject guessed Workflow/Phase IDs, stale
assignment/revocation, retired identity, wrong author/owner, unsafe source references and excessive content.
Preserve original attribution and current/retracted selection transactionally across concurrent appends; use
explicit idempotency identity and stable order, not timestamps or model text as unique authority. Never send raw
Pi sessions, credentials or private notes into shared output, receipts or logs. Unavailable Workflow authority
fails closed; Markdown Planning or a role title is not a substitute for a verified grant. No live ingestion is
activated before the TICKET-00050 safety-removal path is qualified.

## Acceptance criteria

- [ ] A real assigned Team Lead appends a Phase-applicable and a Workflow-scoped lesson through authenticated
  MCP; its assigned Engineer reads relevant shared entries but cannot read private notes or another Workflow.
- [ ] Authorship, sources, verification state and deterministic order survive guarded PostgreSQL round trips.
  Exact retry creates no duplicate, while two distinct or contradictory entries remain separately attributed.
- [ ] Linked correction, supersession and retraction retain original shared history; ordinary guidance omits
  retracted claims, and a separately permitted historical read can distinguish original from correction.
- [ ] Closure, reassignment or revocation blocks later ordinary Engineer reads; memory does not change the
  required phase handoff, code/Planning authority, Workflow state or reviewer independence.
- [ ] No live memory ingestion is enabled until TICKET-00050's separately authorized prohibited-content
  removal path is ready; controlled fixtures are not presented as proof of safe production ingestion.
