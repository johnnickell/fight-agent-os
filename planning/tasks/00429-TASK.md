# Ask for support safely from the creation browser

## Outcome

An authorized human deliberately requests bounded help from the existing creation failure view, inspects attributed
advice and recovers the original conversation. Advice remains separate from deterministic controls, and optional
help failure never makes a retained project or otherwise usable recovery path appear failed.

## Scope

- In scope: Explicit evidence/disclosure review and assistance submission, allowed-model/budget presentation,
  protected advisory result/history, same-conversation reconnect/cancellation and normal-control navigation.
- Out of scope: Generic coding chat, automatic Agent startup/upload, persistent browser drafts, another creation
  wizard, provider/session authority, automatic recommendation application and source-host/setup/cleanup effects.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Review and request help | TASK-00428's explicit exact assistance request | Current permitted evidence/playbook/model/budget and actual Agent capability | Only owning admitted request facts | One deliberate bounded disclosure and original request, not a project effect |
| Inspect or reconnect | Existing authorized attachment/read operations | Original request/result, safe provenance, uncertainty and usage | Existing attachment facts where owned | Same durable help without another Agent, holder or paid turn |
| Stop or recover help | Existing explicit original-conversation operations | Current authority and original outcome/liability | Existing confirmed lifecycle outcomes | Honest stopped/pending/unknown result; no silent retry or budget reset |
| Use a recommendation | N/A here — deliberate navigation to the normal operation owner | Fresh original attempt and actual permitted controls | Only the real operation owner's facts | Advice grants nothing; human reviews and confirms any deterministic effect separately |

## Validation and permissions

Extend TASK-00427's production playbook/diagnostic view and TASK-00416's original-attempt surface through TASK-00428.
No successful receipt or registered context is fabricated to unlock help. Missing pre-registration Agent/snapshot/
assignment qualification keeps assistance unavailable with a precise reason; playbooks and safe diagnostics remain
independent. Do not create or activate an Agent implicitly from opening the page or selecting a development profile.

Present the exact minimized evidence and versioned applicable playbook to be disclosed, selected qualified allowed
model and bounded request/conversation limits before explicit submission. Current viewing and AI/provider-disclosure
rights remain separate; the server owns their definitive checks. Material evidence/scope/model changes require fresh
review through the existing owner, not hidden resubmission. No arbitrary attachment/file picker or log dump input.
Volatile browser edits may be lost on navigation/reload; durable accepted input lives with the session owner only.

Show observations versus inference, cited playbook revision, source freshness, partial side effects, uncertainty,
original request identity and honest usage/cost status. Advice is untrusted inert content: no executable HTML,
automatic URL/resource fetching, command execution or action grants. Denied, malformed, incomplete, unsupported,
stale and unavailable advice must not masquerade as verified repair or successful creation. Retain original advice
provenance when creation state changes; never silently refresh it with another paid request.

Navigation to retry/revised input/cleanup uses TASK-00416/00417's existing controls where currently available, never
a second API or pre-authorized Apply button. Each actual operation still obtains current state, complete impact and
its own consent. Copied commands are human-reviewed explicit operator actions under the guide's boundaries, not
Agent execution. No recommendation confirms a preview, changes roots/settings, authenticates GitHub, deletes or
retries anything. The support UI cannot acquire those capabilities through hidden direct calls either.

Use sole current `/me`, strict decoding, no-store transport and volatile state with authentication/attempt/request
and restriction-generation fences. Retire private evidence/results on authority or context loss; late success/error
cannot restore them. Reconnect reads the original durable baseline; disconnect/logout is not cancellation, refresh
never replays a mutation, and an unknown send/bill remains unknown. No persistent cache/draft, offline queue or
cross-tab private-state sharing. Provider key, hidden reasoning and raw private payloads never reach the client.

Missing configuration, OpenRouter outage, denied disclosure, exhausted budget and interrupted help are help states,
not project failure. Model-free guide/export, retained progress and independently permitted deterministic controls
remain usable according to actual capabilities. Do not require cleanup availability, both providers or finished
browser Planning to offer independently qualified help.

## Acceptance criteria

- [ ] Real browser help reviews exact permitted disclosure and submits once through TASK-00428; safe attributed
  advice cites the playbook, distinguishes inference/uncertainty and never applies a recommendation.
- [ ] Actual bounded OpenRouter/browser evidence covers original-result reconnect, interrupted/unknown outcomes,
  denial, missing configuration, outage and budget exhaustion without duplicate paid calls or budget reset.
- [ ] Stale advice, injection and attempts to retry/delete/authenticate/alter mounts cannot bypass normal current-
  state deterministic controls; optional help failure leaves permitted inspection/recovery/guide/export usable.
- [ ] Logout/revocation, malformed responses, late success/error and attempt changes retire private data without
  persistent business state or automatic replay.
- [ ] Fresh keyboard/focus/announcement, responsive narrow/wide light/dark, reflow/accessibility and applicable
  reduced-motion evidence covers normal, denied, stale, unavailable and recovered assistance.
