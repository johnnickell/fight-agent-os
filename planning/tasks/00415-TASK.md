# Create from the complete browser preview

## Outcome

An authorized human completes the production creation form, reviews every intended effect and confirms exactly
one server-owned attempt. The browser shows the actual admitted/pending result without pretending execution or
registration has completed.

## Scope

- In scope: Authenticated form/preflight/preview/confirmation, independent editable choices, exact public warning,
  server original-outcome handling, current-authority and volatile-state fences, accessible production UI.
- Out of scope: New plan/admission authority, browser root changes, persistent drafts, progress/recovery controls,
  final receipt/Dashboard handoff, automatic authentication or optional support Agent.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Prepare a project | N/A — read-only form/preflight | TASK-00411 exact catalog/profile/local/publication/finalization facts | N/A | Complete current preview or actionable refusal |
| Confirm displayed effects | TASK-00411 exact confirmation | Original command outcome and current authority | Existing owning attempt facts | One admitted attempt; no client-inferred execution |
| Revise invalid preview | Explicit new preview and subsequent confirmation | Changed facts and safe refusal | N/A until confirmation | Old consent cannot authorize revised effects |

## Validation and permissions

Consume TASK-00411 server contract and TASK-00051 frame/authentication/component owners; inherit their holds.
Keep display name, Workspace slug, directory/parent, selected branch, starter, exact development profile and
optional owner/repository name independent. Suggest defaults without overwriting deliberate input; never request
Composer vendor/package identity merely because Composer exists. Distinguish recommendation from actual profile
selection. Preparation defaults selected when declared and shows its executable/network implications; publication
defaults private and public requires explicit heightened acknowledgement bound to the exact preview.

Render exact source/tag/commit/digest, manifest transformations, canonical destination, branch/initial-commit
intent, command/network effects, publication target and registration/context effects. No incomplete or stale
preflight may enable confirmation. Input changes invalidate the preview/acknowledgement. Missing capabilities,
source/profile access, first-link composition or external availability show honest refusal, not a guessed plan.
Local-only and skipped preparation do not query or require their unselected external routes.

Outside-root setup points to the explicit installation operation; no browser mount/configuration mutation. Preserve
form/preview only in volatile memory where the current context permits. Reload, teardown, logout or authority loss
may discard it; never promise persistent recovery or put private inputs in storage, URL/history or cross-tab data.
The durable attempt, once admitted, is recovered by authorized server reads, not persisted browser business state.

Use the sole current `/api/v1/me` authority and shared cache/evaluator; server checks remain decisive. Gate loaders,
outlets and handlers, and fence all late successes/errors by authentication/context and restriction generations.
Protected responses are no-store. Refresh/reconnect never automatically replays confirmation. An uncertain response
uses explicit original-outcome inspection with the same operation identity, not a new request that creates another
attempt. No token, secret, raw environment, source content or private form value enters diagnostics.

Show genuine pending/denied/unavailable/interrupted results separately. TASK-00416 later provides progress controls;
unavailable execution never becomes fabricated success. TICKET-00103 retains the completed receipt/navigation.
Do not automatically start Planning, Agent sessions or unrelated operations after confirmation.

## Acceptance criteria

- [ ] Real form/preview/confirmation uses exact independent choices and server facts; selected public visibility
  requires its specific acknowledgement and material drift disables stale confirmation.
- [ ] Duplicate/uncertain submissions preserve the original attempt, with no automatic replay after authentication
  or reconnection and no fake success while execution remains unavailable.
- [ ] Current-authority, late-response and teardown fences protect all private data; volatile form preservation
  makes no reload/storage promise and never permits browser installation/account repair.
- [ ] Production keyboard/focus/announcement, responsive light/dark, accessibility and applicable reduced-motion
  behavior has fresh evidence across success, invalid, denied, stale, unavailable and interrupted states.
