# Evaluate native Pi MCP before choosing an adapter prerequisite

## Outcome

After subagent adoption, choose the smallest maintained Pi MCP client integration that meets Fight's actual
workflow needs. John requested this deferred evaluation on 2026-11-01. It does not implement Fight's MCP server.

## Scope and options

1. Native Pi MCP is the baseline: qualify actual current HTTP connection, authentication, tool discovery,
   invocation, errors/cancellation and tool-policy behavior against Fight's server as available.
2. Evaluate upstream `pi-mcp-adapter` only for unmet needs: lazy connections, OAuth credential storage,
   prompts/elicitation, background Tasks and MCP UI. These are options, not requirements until a real workflow needs them.
3. If selected, require the upstream package and use native registration, its event API or `createMcpAdapter`
   as appropriate. Avoid copying its transport/authentication implementation. Fork only for an evidenced essential
   gap that cannot reasonably be supported upstream, with an explicit maintenance decision.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Find/call Fight workflow tools | Supported MCP client calls | Server catalog/results | MCP responses | Only authorized server operations |
| Use tools in delegated sessions | Same qualified tools | Child tool scope and connection lifetime | Child/server lifecycle | Scoped calls and bounded connection resources |
| Decide client dependency | N/A, evaluation | Native versus adapter evidence | N/A | Documented decision; installation separately scoped |

## Validation and permissions

Test parent and child sessions, allowlists, proxy/direct tool enforcement, unavailable servers, headless auth,
credential isolation and shutdown. Prefer remote HTTP to multiplying local server processes when appropriate.
Server authorization remains in Fight. Do not import every host MCP config or change global settings during
evaluation. Adapter installation currently replaces native MCP handling; inspect current install/removal
effects before adoption. No Pi version pin, global rollout or implementation authorization follows from options.
