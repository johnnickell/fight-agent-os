# Edit Planning through semantic forms

## Outcome

Authorized users can create and directly revise typed Planning records, sections, stable children, criteria and evidence through small command-oriented forms with server validation/previews and expected revisions, while stale submissions preserve authoritative state and no whole-document replacement or browser draft authority exists.

## Scope

- In scope: Permission-aware create forms for supported Wayfinder/research/prototype/EPIC/TICKET/TASK/standalone records; type-specific title/typed-field/narrative-section/use-case/decision/finding/criterion/evidence/delivery-link forms; add/revise/reorder/retire/satisfy/correct/supersede operations where TICKET-00026 exposes them; expected aggregate/constraint revisions; server preview/validation choices/impact; typed API service mappings; field/global errors; stale/conflict result and reviewed reload/resubmit; idempotent uncertain-outcome handling; dirty-form leave warning; no autosave/persisted direct drafts; accessible form/focus/status/component evidence.
- Out of scope: Generic document/Markdown/status replacement, lifecycle/closeout/Won't Fix/reparent/dependency/waiver/archive/restore, Roadmap/queue ordering, multi-record AI proposals/reconciliation, browser conversations, persistent drafts, source-file editing, migration commands and client-side Domain validation beyond safe transport/usability constraints.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Create Planning record | Dispatch exact type-specific create command | Preview parent/reference/kind/schema/Permission and normalized proposal | Owning aggregate creation event | Server-confirmed record appears and navigation uses returned identity/reference |
| Revise field/section | Dispatch exact section-specific command | Query current value, choices, validation/impact and expected version | Type-specific semantic event | One normalized concept changes; unrelated fields/history remain |
| Manage stable child | Dispatch exact add/revise/reorder/retire/satisfy command | Preview child identity/order/disposition/evidence impact | Child-specific semantic event | Stable child history changes without mutable-row replacement |
| Record/correct evidence | Dispatch exact evidence command | Validate closed kind/provenance/supersession | Evidence semantic event | Immutable reference appends/supersedes; prior proof remains |
| Handle stale submission | N/A until user explicitly retries revised intent | Return current version/intervening facts and rejected proposal | N/A — rejected command emits no event | Authoritative state remains; user reloads/reviews and resubmits a new command |

## Validation and permissions

Each route/form maps explicitly to one application command and safe View. Do not build a schema-driven generic command/document editor that can bypass intent. Typed client input validates shape, required UI constraints and safe lengths for feedback, but server Domain/Application validation remains authoritative. Do not duplicate lifecycle, parent, criteria, evidence or Permission policy in React.

Forms load current aggregate/child/constraint versions and preview data. Submission includes command identity and expected revisions; disabled controls/preview do not grant authority. Unknown or changed principal/context/Repository/mode fails closed. Exact retry after uncertain transport outcome resolves command status before offering another apply, preventing duplicate children/evidence.

Stale response keeps the rejected submitted values in transient component state where safe, shows current/intervening semantic facts and requires explicit reload/review/resubmit. Do not silently merge, overwrite or automatically rebase. AI-assisted reconciliation belongs to later browser-Agent work. Authoritative query cache changes only from server success/refetch; optimistic visual feedback cannot imply accepted mutation.

Support closed typed fields and bounded Markdown-capable narrative input as values, not whole source documents. Never expose raw event JSON, arbitrary plugin data, generic status setter, full-document upload/paste-as-replacement or source-file path. Evidence URL/locator fields apply safe display/input boundaries and do not fetch providers in browser.

V1 direct edits are not autosaved/persisted. Warn on route/tab unload where browser permits when a form is dirty; explain unsaved loss honestly. Clear only on explicit discard or confirmed success. Provide accessible labels/instructions/error summaries/field links/status announcements, keyboard order, focus to first error/stale summary and narrow/wide behavior.
