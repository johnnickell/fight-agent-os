# Run white-label account journeys from the shared React package

## Outcome

Fight Agent OS runs its existing human account journeys through one reusable, independently versioned npm
library, with supported branding and composition instead of copied application source. This is the first
concrete consumer for EPIC-00027 and normally one complete package/consumer PR.

## Scope

- Implement [TICKET-00142](../tickets/00142-TICKET.md)'s package and branding contracts under `packages/react/`;
  working name `@fight/react`. Supply focused public controls/account/style exports, compiled code/types,
  supported React peer dependencies, default CSS and documented theme overrides.
- Move existing shared controls, API/session/principal behavior and human account screens with their meaningful
  tests/stories. `client/` consumes the actual package; delete replaced implementations and private imports.
  Keep Agent OS navigation/product features in its host composition. No duplicate session coordinator/store.
- Product name, logo/accessible text, titles and semantic styling work across public/error/account/admin shells,
  light/dark and narrow/wide layouts. Preserve Bootstrap/React-Bootstrap conventions, CSP and local assets.
- Integrate packaging into actual owning build/install commands without duplicate dependency preparation or
  validation lanes. Qualify a packed artifact and public exports; a workspace symlink alone is insufficient.
  No package registry publication occurs in this TASK.
- Out of scope: unfinished administration features owned by TASK-00123/00128, tables owned by TASK-00597,
  Tailwind, new authentication features, dynamic theme management and Agent provisioning.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Use extracted account flows | Existing qualified server operations | Existing safe account/session reads | Existing events/invalidation | Same authority and recovery behavior through public library exports |
| Apply host branding | N/A | Trusted public brand/theme configuration | Local appearance only | Distinct product identity without a source fork |
| Compose a host business screen | Host-owned operations | Host-owned reads | Host-owned events | Shared controls work without Agent OS product modules |

## Validation and permissions

Preserve the server-authority, secret, CSRF, current-principal and failure contracts of the existing features.
Validate text/assets and fail clearly on unsupported public configuration. No arbitrary HTML, remote asset
loading, permissive transport overrides or client-side permission grants. Use the parent's public API and
styling boundaries; package ownership does not broaden access.

## Acceptance criteria

- [ ] Existing account journeys run in Agent OS through the shared package, with one session/principal owner.
- [ ] A distinct local brand covers public/error/account/admin shells, both themes and responsive states.
- [ ] Packed exports include usable JavaScript/types/CSS without host secrets, application internals, duplicate
  React, Tailwind or requirements to adopt Agent OS's router/build system.
- [ ] Replaced implementations/tests are removed or moved; current behavior remains meaningfully covered.
- [ ] Actual package/API compatibility, focused behavior/accessibility checks and normal build evidence are recorded.
