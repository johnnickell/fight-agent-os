# Make Land cleanup qualification and evidence preservation executable

## Outcome

Make the existing local Land cleanup contract reliable in actual Pi execution: remove only currently qualified
task resources, preserve required evidence before worktree deletion, and finish or resume cleanup with verified
results. Remove the concrete delivery blocker demonstrated by TASK-00519, where written rules were present
but a worker changed filesystem protections, another removed a container with unresolved ownership, and earlier
worktree removals lacked complete evidence-preservation manifests.

John authorized this bounded follow-up and an isolated worktree on 2026-10-26. This record plans the repair;
it does not implement or independently accept it. Preserve the existing Board priority and active-work ownership.

[TASK-00519](00519-TASK.md) delivered the fleet reconciliation changes and consumed
[TASK-00537](00537-TASK.md)'s qualified cleanup contract. Its PR #175 merged into `develop` on 2026-10-26.

## Scope

- Implement a bounded repository-owned cleanup operation used by local Land and Build's cleanup-only
  continuation. Keep [Landing Standards](../../docs/engineering/LANDING.md#cleanup-and-handoff) as the policy
  authority; make qualification, preservation, removal and postcondition checks executable instead of relying
  on ad hoc destructive shell sequences. Choose the smallest implementation that fits the existing workflow.
- Bind operations to the existing task handoff/receipt: canonical safe checkout, exact target worktree/ref/OID,
  publication or merge proof, exact Docker resources, current consumers, data disposition and prior results.
  Recheck mutable facts immediately before each removal; names, labels and historical receipts alone never qualify.
- Make held/unknown resources ineligible for removal. Unavailable inspection, changed identity, active consumers,
  shared endpoints, unresolved ownership or failed preservation produces a precise resource-specific hold.
- Preserve required ignored artifacts outside the candidate with explicit exclusions, old/new locators, verified
  file digests and private modes. Check source stability before removal; retain canonical reports unchanged.
- Carry the qualified Compose project, configuration/override/env-file locators and runtime identity into Land.
  Validate them against actual resources; do not print secrets or fall back to shared defaults/generic setup.
- Integrate finite interruption/resume and coordinator intake using existing receipts, not a new global registry.
  Completed effects are reobserved; only remaining qualified effects run, and success requires postconditions.
- Qualify the real installed Pi Land/Build path using disposable task-owned resources and the current supported
  runtime. Record the tested version/model/provider as evidence, never as a version equality requirement.
- Out of scope: a new sandbox, universal shell interceptor, tool-permission redesign, managed Workflow engine,
  background board synchronization, fleet-wide cleanup/adoption, billing repair, application features, automatic
  merge, remote-branch deletion, durable-data deletion, shared-runtime shutdown or another task's implementation.

The operation provides deterministic checks within its own execution path. An agent with unrestricted shell
access can bypass a helper; this TASK must not claim OS-level enforcement or universal protection against that
capability. A restricted destructive-operation capability is a separate architectural decision. Do not silently
expand this repair into that work or weaken existing native-tool ownership to obtain a stronger claim.

## Acceptance criteria

- [ ] Actual Land and Build cleanup-only callers use the bounded operation and existing exact-subject receipt;
  their normal execution contains no alternative ad hoc destructive cleanup path.
- [ ] Fresh ownership, publication/merge, consumer and data checks precede each removal. A resource explicitly
  held or unknown cannot be removed by the operation; stale IDs/OIDs, changed configuration, inspection errors
  and foreign network endpoints preserve the resource and produce a finite hold.
- [ ] A checkout cannot be retired through the operation until required ignored evidence/private state has a
  verified external copy, explicit exclusions, matching digests, preserved permissions and stable source inventory.
  Copy failure, mismatch or concurrent source changes retain the checkout and canonical report bytes.
- [ ] Permission-denial qualification leaves ACLs, modes, ownership and flags unchanged and records a hold.
  No force/sudo/global-prune or protection-changing recovery is used by the operation or observed Pi worker.
- [ ] The exact qualified runtime configuration reaches Land and is corroborated against current resources;
  missing or contradictory binding holds affected work without starting or stopping a shared/default stack.
- [ ] Real Pi execution proves normal cleanup, denial, unresolved ownership, active consumers, shared endpoints,
  unavailable inspection, preservation failure and interrupted resume on disposable fixtures. Record actual
  worker commands/results and independent before/after observations; instruction review alone is insufficient.
- [ ] Build observes the original worker's exit and finishes eligible checkout/ref cleanup from the safe
  canonical location. Resume handles already-absent and recreated resources without duplicate publication,
  repeated destructive effects, unbounded retries or erasing held resources.
- [ ] Completion separately reports removed, retained, held and failed resources with verified postconditions.
  Publication with a cleanup hold remains incomplete Land; independent coordinator intake verifies that claim.
- [ ] Document the helper's limited enforcement boundary and the live qualification coverage. Record fresh
  owning-tool checks and canonical `./bin/build`, followed by independent Review and applicable nonvisual QA.
