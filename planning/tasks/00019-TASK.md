# Reject invalid API input before dispatch

## Outcome

Post-routing, pre-Action API validation rejects malformed JSON, undeclared request shape, structural type errors, and declared `#[Validation]` constraints with deterministic dotted-field JSend failures before any command/query dispatch.

## Scope

- In scope: JSON parse/shape policy; request DTO/attribute discovery after routing; `#[Validation]` execution; nested/list dotted paths; message-list normalization; `400` JSend `fail` response; middleware ordering/composition; representative valid/invalid fixtures; proof that dispatch/events do not occur on invalid input.
- Out of scope: Domain exception mapping, authentication/authorization, endpoint-specific product validation, localization, arbitrary schema inference, OpenAPI, CORS, and client forms.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Accept valid transport input | Representative Action dispatches once | Representative query may dispatch once | Selected behavior owns any event | Parsed declared request reaches Action with expected values |
| Reject malformed JSON | No command | No query | No event | Sanitized `400` JSend `fail` identifies body failure without parser internals |
| Reject invalid shape/constraints | No command | No query | No event | Dotted field paths map to deterministic message lists |
| Leave Domain invariants intact | Later behavior may construct Domain values | N/A | Domain behavior owns events | Non-HTTP callers still receive Domain invariant enforcement |

## Validation and permissions

Middleware must execute after route selection and before Action invocation. Define deterministic behavior for absent body, empty body, invalid JSON, scalar/list/object top-level values, duplicate/undeclared fields, nested objects/lists, nullability, wrong primitive/container types, and declared transport constraints. Do not silently coerce unsafe types.

Use Fight Common's supported `#[Validation]` and validation contracts directly where suitable, closing application-specific middleware/mapping gaps without unreleased upstream work. Normalize failures to dotted paths and lists while excluding DTO class names, parser traces, raw payloads, arbitrary exception messages, secrets, SQL, and framework internals.

Transport validation does not replace Domain invariants. Invalid input cannot instantiate/dispatch the selected command/query or emit events. No user permission applies; middleware and fixtures are authorized, product endpoints are not.

## Acceptance criteria

- [ ] Validation runs after Slim routing identifies metadata and before the selected Action executes.
- [ ] Malformed JSON is distinguished safely from structurally/semantically invalid valid JSON.
- [ ] Explicit policy covers absent/empty/scalar/list/object bodies, undeclared fields, nullability, and unsafe type coercion.
- [ ] `#[Validation]` constraints execute for declared transport input.
- [ ] Nested and list violations produce deterministic dotted paths and message lists in a `400` JSend `fail` envelope.
- [ ] Responses expose no parser/framework/class/internal or sensitive details.
- [ ] Invalid requests dispatch no command/query and emit no domain event; representative valid input reaches the Action exactly once.
- [ ] Domain invariant tests remain independent of HTTP validation.
- [ ] Middleware ordering preserves versioned routing and successful Responder behavior.
- [ ] Focused middleware/functional checks and `./bin/build` pass with fresh evidence.
