# Reject invalid API input before dispatch

## Outcome

Post-routing, pre-Action API validation rejects invalid input on the real CSRF bootstrap before query dispatch and provides a declared `#[Validation]` path for later real request-body operations, without inventing a POST endpoint or DTO solely for testing.

## Scope

- In scope: JSON parse/shape policy for future real body-bearing operations; no-body CSRF GET and its bounded cookie/header input; request DTO/attribute discovery after routing; `#[Validation]` execution for declared DTOs; deterministic dotted-path/message-list normalization when actual fields exist; `400` JSend `fail`; middleware ordering; proof of no dispatch on rejected requests.
- Out of scope: Domain exception mapping, authentication/authorization, endpoint-specific product validation, localization, arbitrary schema inference, OpenAPI, CORS, and client forms.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Accept real CSRF bootstrap input | N/A — no mutation command | `GetCsrfProof` dispatches once | N/A — no domain event | A valid no-body GET reaches the Action with only the approved cookie value |
| Reject disallowed bootstrap body | No command | No query | No event | Sanitized `400` JSend `fail` rejects any GET body without echoing bytes or parser internals; future POSTs distinguish malformed JSON |
| Reject invalid declared input | No command | No query | No event | Declared cookie/header violations map to safe failures; future real POST DTOs prove dotted field message lists |
| Leave Domain invariants intact | Later behavior may construct Domain values | N/A | Domain behavior owns events | Non-HTTP callers still receive Domain invariant enforcement |

## Validation and permissions

Middleware must execute after route selection and before Action invocation. Define deterministic behavior for absent body, empty body, invalid JSON, scalar/list/object top-level values, duplicate/undeclared fields, nested objects/lists, nullability, wrong primitive/container types, and declared transport constraints. Do not silently coerce unsafe types.

Use Fight Common's supported `#[Validation]` and validation contracts directly where suitable, closing application-specific middleware/mapping gaps without unreleased upstream work. Do not create a fake body-bearing endpoint or DTO to demonstrate nested/list fields: the first real body-bearing action (activation or login) owns its concrete positive/negative DTO matrix. Middleware may reject malformed or forbidden body bytes sent to the no-body bootstrap, but cannot claim that such a negative test proves a production POST contract. Normalize actual failures to dotted paths and lists while excluding DTO class names, parser traces, raw payloads, arbitrary exception messages, secrets, SQL, and framework internals.

Transport validation does not replace Domain invariants. Invalid input cannot instantiate/dispatch the selected command/query or emit events. The CSRF bootstrap is the sole real endpoint in this slice; later protected request DTOs must pass through the same guard before Action dispatch. No user permission applies to bootstrap.

## Acceptance criteria

- [ ] Validation runs after Slim routing identifies metadata and before the selected Action executes.
- [ ] Malformed JSON is rejected safely where a body is accepted; bootstrap rejects any body. A real POST later proves malformed versus structurally/semantically invalid valid JSON.
- [ ] Explicit parser policy covers absent/empty/scalar/list/object bodies, undeclared fields, nullability and unsafe type coercion for future declared operations without treating bootstrap's no-body policy as a DTO test.
- [ ] `#[Validation]` constraints execute for declared transport input when a real DTO exists; do not manufacture a DTO to make this gate appear complete.
- [ ] The dotted-path/message-list mapper is available for actual nested/list violations; a later body-bearing interaction proves its complete contract with real fields.
- [ ] Responses expose no parser/framework/class/internal or sensitive details.
- [ ] Invalid CSRF bootstrap requests dispatch no query and emit no domain event; a valid no-body request reaches the Action exactly once.
- [ ] Domain invariant tests remain independent of HTTP validation.
- [ ] Middleware ordering preserves versioned routing and successful Responder behavior.
- [ ] Focused middleware/functional checks and `./bin/build` pass with fresh evidence.
