# Follow the active Compose stack with stack-wide logs and simple service filters

## Outcome

LOGS opens on all services of the verified main stack without a per-service source form, follows the verified
active Build/agent worktree stack, and lets the operator return to main or filter services. Deliver TICKET-00130's
simple live-log use case: the useful equivalent of `docker compose logs -f`, not another collector. John approved
this follow-on behavior on 2026-11-02. Independent Review and visual/behavioral QA accept candidate `9d9d952`;
publication and cleanup remain separate, with the accepted checkpoint and limits recorded below.

## Scope

- Default to bounded recent tail plus live output from all services in the verified main-checkout Compose stack
  when no eligible active worktree context is selected. Prefix records with service/container identity. Multiple
  services in one verified stack must not force a picker; genuine multiple-project ambiguity still needs a choice.
- Follow the verified active Build/selected-agent worktree stack, including automatic late-start discovery. Mere
  creation of an unrelated Git worktree cannot steal the display. An active worktree with no stack is visibly
  unavailable, not hidden main fallback; return to main at idle unless an explicit override is held.
- Provide only Follow active, Main (explicit main-stack pin) and Services (All or an inspected service subset)
  for source/filter interaction, plus ordinary display navigation/help. Returning to Follow releases Main; stack
  switches reset service filters to All and clear stale live/paused records. Preserve explicit Main intent.
- Extend existing verified log companions/readers. Verify the complete selected project/service/container set,
  including legitimately associated services without application source mounts, using actual owning runtime
  metadata. Qualify supported Docker capabilities; never weaken identity checks merely to fill the pane.
- Keep fixed bounded invocation without arbitrary shell/Compose-file evaluation, exact local source/generation
  verification, safe rendering and bounded source counts/readers/history/discovery. Reverify service-set and
  lifecycle changes and visibly disclose gaps/clipping/quiet/denied/unavailable states. Pane title is LOGS.
- Out of scope: repairing TASK-00544's missing/broken followers, changing its running scope, generic Docker/shell
  controls, runtime start/stop/restart, unrelated projects, transcript/model ingestion, unbounded retention,
  a new collector/registry, SDK stage cutover and agent browsing.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Open idle workspace | Existing workspace open | Verified main project and current service/container set | Existing output/source lifecycle | Bounded all-service tail/live follow without per-service prompt |
| Follow worktree activity | Display Follow mode; runtime startup separately authorized elsewhere | Verified active checkout and its actual running project | Existing context/runtime lifecycle | Correct source switch or honest unavailable state; no provisioning |
| Inspect main during active work | Display Main selection | Canonical main project/container identity | Display selection change | Clearly labelled main pin, no execution change |
| Filter services | Display Services: All or inspected subset | Services of current verified stack | Display filter change | Prefixed selected-service output; stack change resets All |

## Validation and permissions

Only existing operator-authorized workspace/display access permits local log reading. Pane controls do not grant
Docker execution authority to agents, provision containers, run arbitrary commands or expose the socket/credentials.
Reject unproved checkout/project/service/container association, foreign stacks, remote contexts and stale/replaced
source generations. Do not confuse display-selected worktree identity with proof that its stack exists.

Bind Main/Follow/filter intent to the actual selected stack/generation; reconcile old reader teardown and clear
stale output before admitting replacements. Unreaped readers block replacement, not hidden parallel following.
Verify legitimate metadata for non-source-mounted services rather than merely accepting matching names/labels.
Treat output as untrusted display content, preserve explicit close/cancel intent, and never ingest logs into model
context. HTTP/database grants, migrations and new Domain events are N/A: use existing local runtime/observation
contracts with their stated trusted-local limitations, not an OS isolation claim.

- [x] An unrelated worktree creation does not steal the stream. Eligible active Build/agent selection follows its
  own verified stack when available, including late startup; observation never provisions or restarts a runtime.
- [x] An active worktree without a stack has an explicit unavailable state, not silent main fallback. Idle returns
  to main unless an override is held; Main pin and return to Follow are predictable and clearly labelled.
- [x] Main/Follow/Services need no technical project IDs, shell commands or credential entry. All services and
  a selected subset work; service/container prefixes distinguish mixed output. Stack changes reset filters to All,
  preserve explicit Main intent and clear stale live/paused output before displaying a different source.
- [x] Stop/restart/replacement and service-set changes are freshly verified through bounded discovery. Docker
  denial, ambiguous projects, missing source identity and unreaped readers fail visibly without arbitrary fallback.
- [x] Source count/processes/record sizes/history/refresh remain bounded with honest gap/clipping notices. LOGS
  offers no shell, arbitrary Docker/lifecycle operations, transcript ingestion or unbounded archive.
- [x] Owning Harness checks and actual main plus two-worktree Docker/Herdr interaction prove mixed-service output,
