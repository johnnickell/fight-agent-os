# Browse live and completed agents in the Herdr AGENTS pane

## Outcome

The operator can open a readable agent list, inspect an eligible live/completed attempt's bounded output and
identity, then return without changing execution. Name the panes AGENTS and LOGS rather than verbose
observation disclaimers. Deliver TICKET-00130's browsing use case for existing upstream Agent launches before
the full Build cutover, and for correctly admitted stage agents afterward. John approved this slice and the
pane names on 2026-11-02; implementation remains unstarted.

## Scope

- Extend the existing Herdr activity companion, verified-child selection and bounded history rather than
  introducing a second registry. Provide keyboard list/detail/back navigation (for example Enter/Esc), existing
  pin/pause/paging and truthful assignment/model/attempt/lifecycle details.
- Keep verified retained completed SDK attempts browsable within existing eight-child/history bounds, preserving
  selected/pinned retention and explicit pressure/eviction behavior. This is an activity window, not a full transcript.
- Use AGENTS and LOGS as visible pane titles, including narrow/compact presentations. Remove `CHILD ACTIVITY`,
  `Runtime logs` and `human only` from titles; keep observation-only semantics in help/details and actual behavior.
- Preserve verified parent/custody, exact worktree context and existing runtime-log selection/revocation; do not
  infer parent membership or runtime authority from labels, filenames or a merely new Git worktree.
- Preserve active explicit selection despite concurrent output/arrivals, safe rendering, bounded history and
  honest missing/disconnected/completed states. Show gaps, clipping and evictions rather than inventing completeness.
- Out of scope: nested-agent tree, cross-session dashboard, pane execution/steer/cancel controls, unbounded
  transcripts, search/export/full tool-result collection, new log filters and the SDK stage execution cutover.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Browse eligible agents | Display list/select/back | Verified current-parent live and retained completed attempts | Existing observation/lifecycle updates | List/detail selection only |
| Inspect and hold output | Existing pin/pause/paging/details | Selected attempt identity and bounded activity | Existing safe activity updates | Frozen or pinned display; execution unaffected |
| Follow selected runtime context | Existing verified selection metadata | Actual selected/pinned checkout and source eligibility | Existing context/revocation updates | Correct existing log-context switch or visible refusal; no container changes |
| Open/close viewer | Existing workspace companion commands | Actual parent/companion lifetime | Existing reader lifecycle | Dispose/reopen display subscriptions only |

## Validation and permissions

Display choices never grant role/acceptance/publication authority or send commands to workers. Use the existing
verified parent/session/file/custody checks; foreign, nested, rootless, stale and replaced records remain refused.
Treat assistant text/logs as untrusted rendered content; do not ingest reasoning, raw transcripts or tool bodies.
Changing selection must clear stale/frozen output before showing another attempt and revoke lost log authority.
Closing/reopening only a reader leaves workers alone; upstream native shutdown/reload is distinct and may abort
agents. HTTP/database permissions, migrations and new product events are N/A to this local display change.

## Acceptance criteria

- [ ] Pane titles are AGENTS and LOGS, including compact/narrow presentations, with no `human only` suffixes.
  Help/details explain passive behavior without repeating disclaimers in pane titles.
- [ ] A readable list shows verified retained top-level agents with clear active/completed/failed states. Selecting
  an attempt opens bounded output/details; back returns to the list without losing intended selection.
- [ ] Concurrent output and new agents do not steal active explicit selection. Completed output stays browsable
  within eight-child/history bounds; selection/pin and eviction behavior are explicit under retention pressure.
- [ ] Narrow/wide layouts, scrolling and long identities are usable. Clipping/gaps/evictions are disclosed; no
  transcript completeness claim, incidental search/export or unbounded output storage is introduced.
- [ ] Switching agents updates or refuses existing verified runtime-log context and clears stale records. Lost,
  foreign and replaced sources cannot supply worktree/log authority.
- [ ] Viewer closure/reopening never launches, steers, resumes, cancels or accepts an agent. Parent runtime
  shutdown/reload remains truthfully distinct from passive reader disposal.
- [ ] Owning Harness checks and inspected real installed/native Pi/Herdr before/after captures cover live,
  concurrent and completed attempts, selection/pin/pause, retention pressure and source loss; normal full gate
  and independent Review/visual-behavioral QA are recorded.
