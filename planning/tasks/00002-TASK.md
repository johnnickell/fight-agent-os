# Establish and prove safe TASK execution

## Outcome

The repository has a concise project-local `work` skill and shared execution standards that safely turn one approved TASK into bounded, verified implementation work. A bounded bootstrap demonstration proves the workflow before production application work relies on it.

## Scope

- In scope: Add `.pi/skills/work/SKILL.md`; add the minimum shared engineering and execution standards it loads; cover approved-scope intake, checkout/worktree choice, `feature/*` branching from `develop`, architectural boundaries, testing, scope preservation, commits, verification, evidence, warnings, and implementation handoff; perform and record one bounded disposable or low-risk demonstration; obtain human bootstrap review.
- Out of scope: Independent review automation, landing, push, PR publication, merge, deployment, release claims, product-scope changes, planning creation/decomposition, multi-agent coordination, and imported Factory workflows.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Prepare approved work | N/A — repository workflow coordinates tools rather than application commands | Read TASK, parent TICKET, accepted decisions, repository instructions, branch/worktree state, and local status | N/A — no application domain event | User confirms main checkout or isolated worktree; authorized scope, branch, baseline, and unrelated work are explicit |
| Implement bounded work | N/A — direct authorized file and tool operations | Inspect only source, tests, and documentation required by approved scope | N/A — events belong to the implemented application use case | Testable changes and tests are made without overwriting unrelated work or exceeding planning authority |
| Verify and hand off | N/A — repository verification and Git operations | Read focused-check output, canonical-build output, final diff, status, and warnings | N/A — no workflow domain event | Authorized work is committed; fresh evidence and remaining uncertainty are recorded; control passes to independent review |
| Prove safe execution | N/A — bounded disposable or low-risk demonstration | Read demonstration inputs, decisions, outputs, and verification evidence | N/A — no application domain event | Proof exercises intake, placement, scope controls, checks, evidence, and handoff without production application changes |

## Validation and permissions

Reject or stop for missing approved TASK scope, ambiguous ownership, unauthorized branch or checkout changes, unexpected unrelated modifications, destructive operations without ownership evidence, secrets in evidence, missing required verification, or requests beyond implementation authority. Ask for main-checkout versus isolated-worktree choice before implementation unless already supplied. Place scratch beneath ignored `.runs/` paths and worktrees beneath `.runs/worktrees/`.

Preserve Domain/Application/Adapter, CQRS, Action–Domain–Responder, dependency-injection, naming, and documentation conventions through concise shared standards rather than duplicating repository instructions. For bugs, require reproduction and a failing regression test before repair where technically possible. Run focused checks during iteration and `./bin/build` as the canonical gate. Do not present warnings, skipped checks, inherited receipts, or incomplete verification as fresh success evidence.

No application permission model applies. Repository writes and an implementation commit are authorized only by the approved TASK. Push, PR publication, review acceptance, landing, merge, deployment, release, and creation or decomposition of planning records are not authorized.
