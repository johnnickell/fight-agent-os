# Investigate restored incidents in native Logs

## Outcome

An authorized requester can select older archive coverage, explicitly request restoration, follow truthful progress
and investigate exact restored content in the existing native Logs workspace. This approved slice C of
[TICKET-00115](../tickets/00115-TICKET.md) is the complete API-to-browser older-incident journey, not a second viewer
or a demonstration page with fixture-only ready scopes.

## Scope

- In scope: Native source/time/coverage selection, explicit request/status integration, isolated restored search/
  context/detail adapters and presentation, truthful failure/partial/expiry states, shared admission and accessible
  volatile browser interaction.
- Out of scope: New shell/theme/auth owner, raw logs in Dashboard/Activity, live tail in a restore, sharing/scope
  administration, export/download, automatic retries of mutations or scope lifetime renewal.

Use TASK-00470's protected coverage, TASK-00474's exact admission/status and TASK-00475's actual ready/verified-partial
scope. Show collection-time versus event-time basis, selection estimates/unknowns and known gaps before submission.
A bounded unknown estimate is not permission for fanout. Submit a stable explicit request identity; resolve an
uncertain original result before an explicit retry. Refresh/reconnect/back navigation cannot replay restore or
business mutations. Bounded status refreshes stop on retired context/terminal state; do not create an unbounded
polling/request backlog or mistake a live browser connection for verified readiness.

Reuse TASK-00463/00464 typed search/context/detail behavior with restored-scope authority, not live-window assumptions.
Search the entire selected eligible scope, all eight exact levels plus unknown, preserving DEBUG and tie-safe cursors.
Context can explicitly relax text/severity but never requester/source-generation/time/policy boundaries. Preserve
original bytes and fragment provenance in inert escaped/reversible detail; missing normalization fields stay missing.
No executable markup/ANSI, external resource loads, invented locals or silent truncation. No live-tail mixing.

Every status/search/context/detail fetch and private release rechecks current `READ_LOGS` + `RESTORE_LOG_ARCHIVES`,
requester ownership, actual readiness, policy/restriction and fixed expiry. Even another authorized Super Admin may
not inspect this requester's scope. Unknown authority withholds output. Denied/missing IDs do not reveal existence
or counts. Distinguish empty, busy, delayed, partial, corrupt, interrupted, purged, expired and unavailable only where
current authority permits knowledge; stale links alone do not prove purge or an empty successful result.

Use <=16-KiB requests (literal search <=4 KiB), 30-second reads, <=500 events/1-MiB pages and TASK-00463's two
installation-wide live/restored read-export slots, one/requester. Context <=50 observations/five minutes each side;
detail <=64-KiB raw fragments/1-MiB encoded with explicit continuation and one expanded detail. The view retains
<=2,000 observations/8 MiB including detail and renders <=200 rows. No separate restored query/cache pool or implicit
full-result fetch. Server and browser process fitness must be measured, not inferred from serialized caps.

Reuse the sole `/me` evaluator/authentication coordinator and generation fences. Refresh/logout/expiry/identity/
scope changes retire private state and late callbacks; reconnect or downloads/exports never extend fixed scope
lifetime. Safe typed route references are not grants; raw content/search text stays out of URLs/history/telemetry.
Keep labelled keyboard controls, stable focus, non-color severity, reduced motion, bounded announcements and readable
light/dark/narrow/zoom layouts. Required output/access denial is immediate, not delayed until background cleanup.

## Validation and permissions

Follow ADRs [0001](../adr/0001-application-ownership-and-orchestration.md),
[0003](../adr/0003-browser-authentication-security-profile.md) and
[0004](../adr/0004-client-authority-and-runtime-state.md): current server policy, same-origin Bearer/applicable CSRF,
no-store, volatile state and typed bounded operations. A cached request principal or client permission projection
is not fresh release authority. No object paths, backend tenant/query/flush endpoints or credentials reach callers.
Related entities/evidence retain separate permissions; restore does not certify Workflow evidence or grant export.
Already released bytes cannot be recalled.

## Acceptance criteria

- [ ] Actual native selection/request/status/search/context/detail works end to end against verified older archives,
  with honest clocks, coverage and partial/failure states, not synthetic production cards or live-window truncation.
- [ ] Cross-requester/guessed/stale scope access, current capability/session loss, purge/policy changes and expiry
  deny unsafe fetch/release; late callbacks cannot restore private state or renew scope lifetime.
- [ ] Whole-scope literal search, exact levels, tied records and malformed/binary/large detail preserve fidelity
  under shared server/browser budgets, inert rendering and no hidden query fanout.
- [ ] Submission uncertainty is resolved without automatic mutation replay; unavailable backend is not empty success,
  and no restored content enters live tail or sanitized Dashboard/Activity/evidence responses.
- [ ] Real keyboard/focus/reduced-motion/zoom/narrow/light-dark journeys, owned API/client/authority tests and full
  `./bin/build` pass with actual browser and provider integration evidence.
