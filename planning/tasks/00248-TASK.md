# Define the eight reviewed SDLC template specifications

## Outcome

Deliver the complete human-reviewed, versioned specifications for the eight managed SDLC templates as inputs
to the existing Harness template owner. Definitions explain requested behavior and capability; they do not create
Agents, grant Permissions, qualify models or claim working role journeys.

## Scope

- In scope: Project Manager, Explorer, Team Lead, Software Engineer, Senior Engineer, QA Engineer, Release Manager
  and Hotfix Engineer specifications, human-reviewed prompts, responsibilities, inputs/outputs, Skills, requested
  Permissions, model suitability, operating limits, handoffs, stable identity and historical alias provenance.
- Out of scope: Database seeding/storage, publication UI, automatic reconciliation, credentials, session launch,
  provider enrollment, Workflow implementation, runtime role acceptance or a ninth required Triage template.

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Review complete starting catalog | Human review of versioned template inputs, not a runtime command | Role responsibilities, requested resources/capabilities and source provenance | N/A — authoring definitions is not a business-state transition | Reviewed version-controlled inputs for TASK-00249 and TICKET-00075 |
| Follow a role assignment | N/A — bounded instruction walkthrough, no Agent launch | Assignment, governing rules, required outputs and next permitted handoff | N/A — walkthrough is not execution evidence | Traceable normal and failure-path review for each role |
| Resolve historical naming | N/A — define versioned alias mapping for the owning resolver | Stable logical identity, historical labels and revisions | N/A — no historical event rewrite | Explicit mappings without identity replacement or new authority |

## Validation and permissions

Use [Team roles](../../docs/engineering/TEAM.md) and the accepted WF-014/WF-015 boundaries as authorities.
Apply [Writing for Agents](../../.pi/skills/writing-for-agents/SKILL.md): define reader, trigger, required inputs,
observable completion, uncertainty/stop behavior and next permitted action; link shared rules instead of copying
whole checklists. Templates are not Access Control Roles. Prompts, names, Skills and `allowed-tools` grant nothing.

For each template, describe complete requested capability/Permission intent and referenced resources, distinguishing
existing definitions from dependencies not yet implemented. Do not invent usable Permission IDs or silently drop
missing requests. TASK-00249 resolves exact current IDs/revisions and denies unavailable profiles; accepting these
specifications alone does not establish runtime eligibility. Any new stable UUID identities use the owning factory
or UUID library once, preserving them thereafter; inspect existing identities before creating replacements.

Preserve Planner → Project Manager, Coordinator → Team Lead, Builder → Software Engineer, Reviewer → Senior
Engineer and Publisher → Release Manager through explicit versioned aliases, not history rewrites. Architect is
a Senior Engineer specialization, not another mandatory participant. Design/build contribution disqualifies that
Agent from independently reviewing the implementation. Review sessions are fresh; QA follows technical review and
precedes landing, with source repairs returned through the existing Engineer/review path.

Team Lead plans/delegates and escalates; PHP owns state, eligibility, grants and provisioning. Software Engineer
cannot accept its own work. Explorer cites evidence/uncertainty and prefers measured speed/cost suitability, never
a guessed model label or price. Define suitability requirements and identify unqualified choices honestly; no
provider is silently substituted. Release Manager's landing, merge, signing, release and deployment rights remain
separate. Hotfix retains bounded incident authority, isolation, regression evidence and independent review; a
specific skipped check needs the owning human exception, not a template-wide waiver.
