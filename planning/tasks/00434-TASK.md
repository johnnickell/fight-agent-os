# Request and recover bounded instruction suggestions

## Outcome

An authorized human can request help with one recognized instruction file, answer clarifying questions and recover
an attributed complete suggestion through a production API. The protected conversation retains the original input,
proposal and base without granting the Agent filesystem authority or requiring a completed editing/browser journey.

## Scope

- In scope: Selected-file request/disclosure composition, exact managed writing Skill, real named-Agent/provider
  integration, durable questions/answers and typed proposals, complete diff, original recovery and safe provenance.
- Out of scope: Browser form, filesystem Save/Delete, publication/sync, generic chat, Planning Apply, another Skill,
  provider/session/identity/accounting store, arbitrary file/tool/network access and automatic AI conflict repair.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Request selected-file help | Explicit bounded assistance intent through existing assignment/admission owners | Safe selected file/base/context, exact Skill, actual Agent/provider and remaining limits | Committed original input/admission/reservation facts | Protected generation after commit, never a filesystem effect |
| Clarify the requested change | Existing serialized turn with exact pending-question/answer identity | Original request, current scope and applicable bound context | Durable question/accepted-input facts | Bounded follow-up under the same owners, not new grants or scope |
| Retain complete suggestion | Existing original-outcome operation with validated typed payload | Exact base, proposed complete content, computed diff and provenance | Attributed proposal/usage facts | Durable protected proposal, no acceptance or file write |
| Inspect original result | N/A — current-authorized read | Original conversation/proposal/base and truthful freshness/availability | N/A | Same authorized history, no provider request or retry |
| Stop or reconcile interruption | Existing exact-request lifecycle/reconciliation operation | Original attempt/effects, current authority and consumed/reserved limits | Confirmed owning lifecycle/outcome facts | Safe original recovery or held uncertainty, no regeneration |
