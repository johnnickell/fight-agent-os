# Design the project-local security audit skill

## Outcome

A bounded `.pi/skills/security-audit/SKILL.md` assesses concrete security paths and trust boundaries without
repairing source or replacing independent TASK review.

## Scope

- In scope: Threat/asset/actor intake, actual entry-point and privilege tracing, source-backed findings,
  counterevidence, impact versus confidence, sampling limits and planning handoff. Include Agent tool inputs,
  instruction injection, filesystem/process/container/network boundaries, secrets, authenticated effects,
  resource exhaustion and dependency evidence where relevant. Use current primary security references.
- Out of scope: Live exploitation of external systems, automatic scanners/installations, remediation, publishing
  vulnerabilities, permission changes, unsupported compliance certification or repository-wide completeness claims.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Assess a named boundary | Authorized safe diagnostics only | Read code, policy, versions and evidence | N/A | Report and proposed scoped work only |

## Validation and permissions

Identify target, scope and safe evidence method. Never expose secrets or send private source to unapproved
services. Keep severity separate from confidence: a highly certain minor issue is not critical. Do not blanket
exclude internal endpoints or development tools; assess their actual reach and privileges. Skills do not grant
security-testing authority beyond the user's request.

## Acceptance criteria

- [x] Findings name an actual path, preconditions, impact, evidence/counterevidence and practical correction;
  distinguish unresolved questions and unseen coverage from confirmed defects.
- [x] Review sandbox/provisioner and credential boundaries using TEAM and isolated-startup contracts without
  declaring an unimplemented boundary proven safe.
- [x] Verify source provenance/license before adaptation; original instructions fit Pi and local review/audit scope.
- [x] Walk a safe bounded sample, validate metadata/links directly, planning views, diff and full build;
  no product-suite tests of instructions or deliberate vulnerable fixtures merely to test tools.

## Verification and evidence

Direct source/instruction walkthrough, current primary references, metadata/link checks, `./bin/planning-check`,
`git diff --check` and `./bin/build`. Record unavailable runtime evidence honestly.
