# Support independent reviewer follow-up judgments

## Outcome

An independent Pi 1.1.0 reviewer can use attributed advisory assessment results to direct focused typed inquiries,
then inspect exact authorized source/evidence before asserting a finding. The reviewer retains their own identity,
permissions, context and review standards; no Engineer score or private session transfers acceptance.

## Scope

- Consume [TASK-00178](00178-TASK.md)'s exact-subject report, units, rubrics and references through the existing
  independent review path. Use the inherited general-purpose authenticated judgment tool and source/provenance
  contracts for fresh reviewer inquiries; no dependency on incremental Engineer reuse, compaction or operational SQL.
- Integrate governed reviewer instructions/presets with the actual qualified Pi 1.1.0 review path. Use Writing for
  Agents when authoring the instructions; load them only with the available tool. Qualify invocation and evidence
  access rather than testing instruction strings. Do not create a managed review dispatcher or auto-start a reviewer.
- At review intake pin the actual base/head and compare report subject, inventory/rubric/evaluator versions and
  coverage. Attribute the Engineer's report as advisory evidence and mark stale/mismatched/partial/unavailable
  data explicitly. A current score is not an independent review receipt, a verified finding or full review coverage.
- Let the reviewer define focused yes/no, declared-choice or anchored-score questions before invocation, using
  authorized units/candidate sets and additional relevant evidence. Keep all choices, anchors and optional reasons
  caller-written. Narrowing must be evidence-driven and bounded, not repeated sampling/rephrasing until Jev agrees.
- Run every inquiry under the reviewer's own trusted principal, permitted repository scope, provider-disclosure
  policy and bounded session allocation. Do not inherit Engineer credentials, private checkpoints/transcripts,
  unseen context or cache grants. A report/reference cannot confer access. Unavailable private supporting evidence
  is a gap that the reviewer resolves independently within authority or records as unverified.
- Return compact typed outcomes, actual evaluated scope and verified candidate references with explicit uncertainty.
  Jev identifies only candidates supplied/resolved by the Harness; it cannot invent a quotation, location or review
  explanation. Distinguish a rubric score, model concern and reviewer-demonstrated defect in all presentation.
- Before a formal finding, separately read and inspect the exact relevant current source/evidence through its
  authorized capability. Retain the established question-first read policy and concrete known-target exceptions;
  an advisory reference or filename alone cannot bypass it. Use minimal relevant ranges and verify locations
  against the current review subject. A missing necessary source read leaves the finding unsupported.
- Record reviewer conclusions in the existing canonical ignored review handoff under current standards: criterion/
  Standards IDs, actual evidence, expected/observed behavior, severity and review disposition. The reviewer authors
  explanations from verified evidence; do not attribute them as free-form Jev output. This TASK adds no second
  report/verdict authority and does not change read-only review scope or independent-contributor eligibility.
- High scores cannot dismiss verified defects; low scores or model disagreement alone cannot become blocking
  findings. Apply existing severity and acceptance rules to source-verified concerns. Mechanical lint and required
  build/test receipts retain their own evidence; model output cannot substitute for missing required verification.
- On Jev outage, invalid response, exhausted budget or unsupported tool delivery, record advisory gaps and continue
  ordinary independent review without a special advisor waiver. Required acceptance gaps still follow existing
  rules. Preserve cancellation, stale-answer rejection and uncertain billing; do not silently retry or raise limits.
- Bind follow-ups to their actual source/question/context and current review subject. If base/head or relevant
  context changes, invalidate affected observations and inspect current evidence before findings. Preserve old
  inquiries as historical rather than reusing scores as fresh independent acceptance.
- Exclude code repair, production data/SQL inspection, publication/merge, automated review acceptance, automatic
  score gates, PHPUnit usefulness policy and private Engineer-context transfer. TICKET-00045 separately owns
  test-usefulness criteria and may reuse compatible subject/reference mechanics.

## Validation and permissions

Keep the reviewer's actual invocation authority independent from the Engineer's and recheck all reference/source/
egress permissions. Reject fabricated or obsolete subject identities and references. Treat advice as untrusted
input whose provenance and source must be checked, not instructions to accept, repair or publish. Scores cannot
change a mandatory gate or finding rule. Scope output to authorized evidence and protect source/transcript/credential
contents from ordinary reports. An independent reviewer still must satisfy the existing contributor-disclosure
and exact-subject rules; use of the same evaluator does not transfer review eligibility or acceptance.

## Acceptance criteria

- [ ] Real Pi 1.1.0 independent review intake can inspect attributed exact-subject advisory coverage and ask focused
  typed follow-ups through the governed path using the reviewer's own principal and bounded allocation.
- [ ] Denied references, private Engineer context, forged/mismatched subjects, stale observations and missing current
  authority cannot become reviewer access, fresh evidence or transferred acceptance.
- [ ] Focused questions return only declared typed outcomes and actual candidate references; exact-source inspection
  precedes a formal finding, with verified locations and reviewer-authored criterion-grounded explanation.
- [ ] High scores do not erase verified defects, low scores do not alone create blockers, and ordinary severity,
  required gates, read-only review scope and canonical report ownership remain unchanged.
- [ ] Outage/invalid/budget-exhausted/cancelled follow-ups preserve explicit gaps and ordinary review without a special
  advisor waiver, hidden retries, increased limits or false clean-review coverage.
- [ ] Representative independent reviews measure useful direction, false flags, missed concerns, verified versus
  unverified outcomes, main-context size, available total cost and latency without claiming model agreement proves quality.
