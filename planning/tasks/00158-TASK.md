# Render the client shell with Twig and self-host the selected fonts

## Outcome

The public application document and its safe unavailable state render through file-backed Twig templates under
project-root `templates/`, rather than HTML strings inside `ClientShellResponder`. The same document loads
self-hosted Ubuntu for headings and Open Sans for body text, with licensed, pinned assets and no runtime font
request to Google or another third party. This standalone chore carries the owner's typography amendment in
[TICKET-00018](../tickets/00018-TICKET.md); it does not reopen TASK-00035's historical design verdict or modify
the TASK-00050 PR. One independently reviewable implementation PR should deliver both document and font loading.

## Scope

- In scope: A project-root `templates/` directory with file-backed Twig shell and generic unavailable templates;
  replace PHP HTML assembly with injected Twig rendering in the existing web adapter; preserve safe asset handling,
  HTTP behavior and CSP-compatible theme prepaint; ship the two specified font families as versioned same-origin
  assets with appropriate licenses, subsets, fallbacks, static delivery and CSP; apply heading/body typography
  throughout the current public shell and production components/Storybook without importing the disposable
  prototype; focused behavioral, browser and build verification.
- Out of scope: Twig-rendering React pages or authentication/authority data server-side, changing API/error
  responders or unrelated templates, a general template abstraction/theme loader, runtime Google Fonts CDN
  requests, weakening CSP, remote tracking, arbitrary user font uploads, new account preference, and a general
  redesign of TASK-00035's accepted colors/layout. Later TASK-00051 owns the authenticated frame.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Serve the application document | N/A — GET `/app` via existing Action | Read the validated hashed manifest and file-backed Twig template | N/A — read-only presentation | Respond with escaped public config, prepaint before CSS/ESM, same headers/status and no private data |

| Render selected typography | N/A — browser resource loads | Load pinned same-origin Ubuntu and Open Sans font files with fallback | N/A — presentation only | Headings use actual Ubuntu, body/controls use actual Open Sans when available; no off-origin requests |

## Validation and permissions

The current public shell remains unauthenticated. Keep `ClientAssetManifest`'s exact hashed path/file checks;
pass only validated asset paths and the fixed public config to Twig. Use Twig autoescaping for HTML values and
JSON-in-script-safe encoding for inert runtime configuration; never pass a principal, credential, secret or raw
environment data. Do not mark unchecked data `raw`. Preserve `Content-Type`, no-store, nosniff, referrer and
restrictive CSP, and ensure missing/corrupt manifests or template/render failures fail closed without a path or
stack leak. Keep a generic safe 503 response when even the unavailable template cannot render (plain text is
acceptable; do not embed a second full HTML document in PHP). Avoid adding unrelated catch-all routes.

Select pinned font packages/files and record source URL, version, checksum, exact weights/subsets and
redistribution license/notice in tracked documentation and assets as required. Ubuntu headings should use
real Medium 500 rather than synthetic 600 where the design calls for it; Open Sans owns body, control and form
text at the weights actually shipped. Provide system sans-serif fallbacks and check glyph coverage, non-Latin
fallback and reflow. The owner chooses **self-hosting**, not a live Google Fonts stylesheet/CDN, under the
current same-origin CSP and TASK-00063's planned no-mutable-remote-resource envelope. If licensing, coverage
or actual font delivery cannot be qualified, stop and surface the obstacle rather than substituting remote
runtime fonts or falsely claiming that naming a font-family downloads it.
