# Persist identities and refresh sessions atomically

## Outcome

Production PostgreSQL adapters satisfy the complete stable `UserRepository` and `RefreshSessionRepository` contracts, including canonical identity constraints, role-reference fences, session credential lookup, and the indivisible authentication-authority/session operation.

## Scope

- In scope: User, role-assignment, email-reservation state required by the repository contract, and refresh-session migrations/mappings; complete User/RefreshSession adapters; production composition; exact entity reconstruction; pagination/ordering; authoritative constraints; expected-state updates; transaction-duration fences; safe conflict translation; contract, rollback, and controlled concurrency tests.
- Out of scope: Authentication HTTP behavior, credential generation/JWT/cookies, login throttle, product session policy, activation/reset grant adapters, external effects, UI, and deferred email-change journey delivery even though repository state must faithfully support the package contract.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Add and resolve identity | Existing package commands use `UserRepository` | Resolve by ID/email, list users, inspect role references | Package events remain package-owned | Exact user and assignments persist without canonical-email or reservation conflict |
| Replace user state | Package authentication, assignment, invitation, and lifecycle commands | Compare complete expected predecessor and required references | Events only continue from committed package outcomes | One valid transition advances exact revisions; stale/invalid updates write nothing |
| Create login authority atomically | `AuthenticationService` package behavior | Resolve expected user authority and new session ownership/version | Package login/session outcomes | Authority replacement and refresh-session insert both commit or both roll back |
| Resolve/rotate sessions | Package refresh/revoke commands | Resolve by ID/current or used credential, list active sessions | Package session lifecycle events | Expected session replacement wins once; used digests remain detectable as contracted |

## Validation and permissions

Database constraints must enforce stable identifiers, canonical-email uniqueness including live reservations, role and user references, session ownership, credential/digest uniqueness, and valid storage shapes. Persist only one-way refresh credential material supplied by package entities. Reconstruct exact package value objects/entities and honor pagination and promised ordering.

Implement every `UserRepository` method, including authentication authority, coupled authority/session insertion, role assignment/reference validation, reservation/confirmation, pending email correction, lifecycle replacement, and add/list/lookups. Implement every `RefreshSessionRepository` method, including active filtering, complete active scan, current/used credential lookup, and exact-revision replacement.

Use the same transaction-duration user-authority and role-reference fences across relevant methods. Controlled races must cover stale user/session writes, role removal/assignment, canonical/reserved email claims, reset versus login/session insertion, and credential rotation/reuse. Safe failures expose no SQL or existence information beyond contract.

No end-user permission is introduced. Persistence adapters and composition are authorized; package/feature policy and transport are not.

- [ ] Canonical email and live reservation conflicts are atomically rejected for add, correction, reservation, and confirmation.
- [ ] Role assignments cannot commit against removed/non-authoritative roles, including controlled races.
- [ ] Authentication-authority replacement obeys exact expected-state/revision rules and its transaction fence.
- [ ] `replaceAuthenticationAuthorityAndAddRefreshSession()` makes authority/session insertion indivisible and rejects mismatched ownership/version.
- [ ] Session queries honor ownership, active-at time, pagination/ordering, current credential, and historical used-digest semantics.
- [ ] Controlled reset/login and refresh replacement races allow only contract-valid outcomes; rollback leaves no partial state.
- [ ] Focused migration/repository/transaction/concurrency checks and `./bin/build` pass with fresh evidence.

## Completion notes

Implemented on `feature/task-00013-identity-session-persistence`. Migration `Version20261002000000` adds `users`,
`user_email_claims`, `user_role_assignments`, `refresh_sessions`, and `refresh_session_used_credentials` with
snake_case identifiers and named constraints (`pk_users`, `ck_users_state`, `ck_users_password_shape`,
`ck_users_revisions`, `ck_users_timestamps`, `uq_user_email_claims_email`, `uq_refresh_sessions_credential_digest`,
`uq_refresh_session_used_credentials_digest`, plus foreign keys and lifetime checks). One normalized
`user_email_claims` table enforces a single unique canonical value across canonical addresses and live
reservations.

Exact reconstruction uses adapter-private subclasses (`PersistedUser`, `PersistedRefreshSession`) that forward
authoritative stored state through the package's protected constructor. The locked `v0.3.0` package exposes no
public full-state factory and no getter for reserved session rotation timestamps or historical digests; hand
reflection and serialization remain prohibited. The package itself reconstitutes entities through this subclass
constructor pattern, and no lifecycle policy is duplicated: `refresh_session_used_credentials` is maintained
incrementally on rotation exactly as `RefreshSession::rotate()` appends the superseded digest, and `rotated_at` is
written on rotation and left unchanged on revocation.

`PostgresUserRepository` implements all eleven `UserRepository` methods with complete expected-state conditional
writes, a per-user `AuthenticationAuthorityFences` advisory lock for authority replacement and confirmation, the
shared `AuthorizationReferenceFences` for role assignment/reference validation, and an indivisible
`replaceAuthenticationAuthorityAndAddRefreshSession()` using a transaction-scoped savepoint. Canonical and
reservation claim conflicts throw `DuplicateEmailException` atomically; missing role references map to
`PersistenceConflict`. `PostgresRefreshSessionRepository` implements all six methods with `UPDATE ... WHERE
revision = ?` plus complete expected-state checks, current/used credential lookup, active-at filtering on both
expiry fields and revocation, and deterministic `created_at, id` ordering. `PostgresAtomicOperation` supplies
transaction-scoped savepoints so known conflicts roll back without partial state. Both repositories fail closed
outside an enclosing transaction. Composition binds `UserRepository` and `RefreshSessionRepository` on the shared
connection in `config/common/persistence.php`.

reported 2 executed, 0 unavailable, 0 new; the guarded PostgreSQL 17.11 suite passed 30 tests / 492 assertions on
