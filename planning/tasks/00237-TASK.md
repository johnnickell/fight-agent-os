# Deliver authorized lifecycle intent and safe original-operation status

## Outcome

Protected callers can retain authorized provision/rotation intent before invocation, resolve the original operation
truthfully after uncertainty, revoke current authority and read safe original status. Compose existing package
services; do not equate issuance with delivery, activation or use or expose a browser/raw-key lifecycle.

## Scope

- In scope: Current protected caller/target authorization, durable initiating key/request correlation, package
  provision/rotation/revocation/status composition, safe console/service handling of confirmed/indeterminate outcomes,
  retained-key retry and independently authorized revocation; reusable safe intent boundary for TICKET-00063.
- Out of scope: Browser Agent creation, Team/template ownership, delivery execution, activation, another credential
  queue, duplicated package transition policy, general retry/event platform or unteamed live product Agents.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Record and request provision or rotation | Retain exact key/request, then package `AgentProvisioningService::provision` or `AgentCredentialRotationService::rotate` | Current trusted caller/target/destination and original result | Unchanged package issuance events after confirmed commit; typed publication warning where specified | One correlated original issuance, protected material and audit; rotation cancels predecessor atomically |
| Resolve uncertain or lost result | Authorized same-key invocation only, never new-key fallback | `GetAgentOperation` through its actual handler and current read policy | No repeated success fact on retained-key resolution | Original issuance/status or truthful uncertainty without repeated generation/mutation/audit |
| Revoke an Agent credential | Guarded package `AgentCredentialLifecycleService::revoke` | Current caller/target and independently persisted authority after uncertain result | Existing revocation event/failure behavior, not issuance-warning semantics | Immediate atomic retirement/cancellation/audit, without key lookup or sink calls |

## Validation and permissions

Persist original package-generated operation ID, trusted originating scope and exact canonical request before
calling issuance. That initiating record is not another delivery queue or lifecycle authority. If retention fails,
do not call issuance. Server registration selects destination; UI or worker input cannot choose arbitrary scope,
URL, target grants or predecessor. Retry the original rotation predecessor even after it ceases to be current.
Authorize before key lookup on every attempt and original-target disclosure on status, including absence.

Use TASK-00234's real protected caller policy and TASK-00228–00230's canonical transaction/correlation contract.
Package services own the only business transaction; no outer transaction, hidden callback retry or audit-repository
policy. Agent OS orchestration is justified only for durable initiating intent/current caller policy crossing owners,
not an alias for a package service. Direct lifecycle paths require the same current target authorization; an actor
ID alone never grants revocation. A currently authorized maintainer can revoke after the originating grant or
historical destination access is gone; no key/sink access or new-work capacity may be needed for cancellation.

Committed issuance with publication failure stays confirmed with the package's typed warning. Revocation retains
its different post-commit rethrow behavior. Unconfirmed commit and absent status do not prove rollback; recompose a
closed Unit of Work and reconcile the exact retained key/state, never automatically rotate/provision or restore a
predecessor. Safe status distinguishes original issuance from current credential/delivery disposition and cannot
load material, start transactions, emit audit/events or disclose receipt/claim/key internals.

Live product Agent creation must pass TICKET-00063's Team/template/grant orchestration; this protected boundary is
not an alternate Team-free creation route. Component scenarios use explicitly isolated test identities only and
claim no real managed role journey. Full runtime remains unavailable pending complete composition qualification.

## Acceptance criteria

- [ ] Durable key/request retention precedes invocation and survives caller/process loss; conflicting requests
  reject, while identical authorized retries preserve original issuance without duplicate generation/audit/events.
- [ ] Actual PostgreSQL provision/rotation and capacity races are atomic, including cancellation rollback and
  same-key uniqueness losers. An ambiguous result remains indeterminate rather than becoming a new operation.
- [ ] Real encryption/persistence/audit faults and failed issuance publishers leave correct durable state and safe
  results; revocation publication failure is not incorrectly converted to an issuance warning or rollback claim.
- [ ] Protected revocation serializes through exact predecessor/correlation fences and removes delivery material
  without keys/sink; unauthorized direct calls deny. Current-use denial is separately integrated in TASK-00241.
- [ ] Safe original-operation status preserves historical identity and truthful dispositions, rechecks current
  visibility and cannot disclose material/claims/receipts or use absence to authorize issuance.
