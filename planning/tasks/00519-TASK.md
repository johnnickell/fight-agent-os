# Align and verify delivery handoffs across the ten projects

## Outcome

Align all ten approved projects with the shared Land/routing contract through minimal necessary changes or
evidenced no-change conclusions. Keep one central TASK responsible for complete coverage, without project-local
TASKs or duplicate planning queues. This delivers the complete requirement of
[TICKET-00120](../tickets/00120-TICKET.md).

The maintainer explicitly approved a multi-repository exception to the usual one-PR TASK boundary: each affected
project may have its own independently reviewable PR, while this central TASK owns aggregate acceptance and
records each project's delivery separately. This exception does not authorize publication or merge by itself.

## Scope

- Assess exactly `fight-agent-os`, `fight-common`, `fight-access-control`, `epic`, `fight-cms`, `project-slim`,
  `project-symfony`, `project-laravel`, `project-yii` and `project-codeigniter`.
- Resolve real checkout identities and inspect local instructions, planning tools, conventions, workflow
  bindings and current Board/Roadmap/README handoffs. Identify actual gaps against the qualified shared contract.
- Reuse TASK-00515–00518's completed shared guidance and Agent OS reference implementation. Verify its
  applicability and record the Agent OS disposition without duplicating completed implementation.
- Make only required script/documentation/current-handoff changes in isolated registered worktrees for affected
  projects. Keep already-compliant implementations with direct evidence supporting no change.
- Record per-project revisions, changes or no-change rationale, checks, warnings, independent acceptance,
  publication state and unresolved blockers. Preserve historical acceptance/checkpoint evidence.
- Resume incomplete work from retained ownership/evidence without repeating completed changes or publication.
- Out of scope: extra projects, broader framework adoption, application behavior, new managed Workflows,
  historical-evidence rewriting, unrelated cleanup, project-local TASKs, automatic approval/merge, release,
  deployment, archive or remote-branch deletion.
