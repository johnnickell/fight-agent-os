# Inspect current pending changes safely

## Outcome

An active authenticated owner can inspect a truthful read-only email-change state in Account/Security through
one authorized query/API. Its bounded projection and scope policy are reusable by later user administration,
without exposing package grant internals or mistaking credential delivery for completed account change.

## Scope

- In scope: Owned authorized status composition, coherent package User/reservation/grant/delivery observation,
  safe HTTP View and typed client service, real read-only account panel and accessibility/uncertainty states.
- Out of scope: Issuance, cancellation, expiry/repair on read, provider invocation, worker inspection API,
  cross-user administration UI, generic profile editor or a duplicate principal/state store.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Inspect own current change | N/A — read only | Authorized composed status over current User, exact grant/reservation and safe delivery facts | N/A | No-store bounded account projection; no business mutation |
| Deny unavailable or foreign scope | N/A | TASK-00278's current principal/target policy before protected observation | N/A | Safe denial or unavailable state, not a fabricated empty pending change |
| Refresh account panel | N/A | Same query under current client/server authority | Client presentation signals only | Current accessible state replaces only matching-generation volatile data |

## Validation and permissions

Derive the self target from the current active principal, never transport input. Apply TASK-00278's current
scope policy to the reusable query, including any trusted administrative consumer; only TASK-00282 adds its real
cross-user HTTP/UI journey. An ordinary `READ_USERS` grant or delivery ID does not authorize this private status.
Use TASK-00117's protected Action/Responder boundary and exact allowlisted response fields.

The inspected package `UserView` has no pending email-change fields, while `CredentialDeliveryStatusView` describes
only one delivery generation. Implement justified Agent OS read composition rather than aliasing a package query
or returning a grant/entity. Qualify a coherent observation of current User, reservation revision, exact latest
change and delivery facts. Do not combine unrelated reads into a falsely authoritative state; races or missing
required facts produce conflict/refetch or unavailable. Safe observation never decrypts or repairs state.

Distinguish no pending change, issued/awaiting confirmation, actual delivery outcome, retryable/permanent/uncertain
delivery, expired, cancelled and confirmed where evidence supports that exact disposition. Delivered does not
mean confirmed; expired authority may still await protected reservation cleanup. Do not infer cancellation from
absence, confirmation from email equality, or no work from outage. Use owning package lifecycle/time semantics,
not a parallel status algorithm. Expose only necessary canonical/pending address, safe actionability/expiry and
qualified context information; no credentials, hashes, ciphertext, grant objects, claim tokens, provider internals
or arbitrary worker/audit detail. Never accept a raw browser-supplied delivery ID as scope authority.

A status/context token, if needed for later confirmed intent, is non-authorizing and secret-free; reading it does
not reserve a generation or prove the package supports expected-generation cancellation. TASK-00281 retains that
contract hold. GET must not expire, cancel, send, create a notice, audit a business transition or reconcile state.
Show unavailable operations honestly until their actual owners are qualified, without fake records/buttons.

Use the existing `/me` owner, typed transport and frame under [ADR 0003](../adr/0003-browser-authentication-security-profile.md)
and [ADR 0004](../adr/0004-client-authority-and-runtime-state.md). Keep response data volatile/no-store, retire
late success/error on identity or authority change, and distinguish forbidden from anonymous and network failure.
Provide keyboard/focus/announcement, narrow/wide and light/dark states. No personal address or workflow state in
URLs, history, browser storage, telemetry or retained diagnostic captures.
