# Establish secret-safe credential provider adapters

## Outcome

Agent OS implements the qualified Fight Access Control provider-neutral credential-delivery capability with minimal
secret-safe inputs, typed outcomes, stable package delivery identity, deterministic network-free test adapters, and
fail-closed production composition when no required real provider is configured.

## Scope

- In scope: Adapter implementations of the locked package provider contract; invitation and password-reset provider mapping; stable package delivery-generation idempotency identity; invocation-lifetime credential handling; typed delivered/retryable/permanent outcomes; redacted diagnostics; null/in-memory test adapters; explicit test/development composition and production absence guard.
- Out of scope: Changes to package contracts/policy, production provider enrollment, SMTP/API clients, credential generation/cipher selection, durable discovery/claim/outcome logic, worker/runner, product email-change provider wiring, external audit publication, user-facing status, and provider-specific payload persistence.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Invoke a credential provider | Direct package handler calls its provider capability after committed claim | Read only package-approved invocation-lifetime destination/template/material and delivery ID | Package events remain package-owned | Adapter attempts one provider-neutral delivery and returns a typed outcome |
| Classify provider result | N/A — capability result | Inspect delivered/retryable/permanent outcome and bounded safe code | N/A | Package handler can persist its own retry or terminal transition without parsing arbitrary text |
| Repeat an at-least-once attempt | Same package generation is reclaimed after a crash or retry due time | Reuse immutable package delivery-generation ID | No duplicate business event is inferred | Every repeated provider attempt receives the same idempotency identity |
| Test effects deterministically | N/A — test adapter operation | Inspect redacted invocation records | N/A | Tests assert attempts/outcomes without network or retained credentials |

## Validation and permissions

Implement the exact locked package capability instead of creating an Agent OS alias. Inputs are accepted only for
the provider call lifetime. Raw credentials, hashes, ciphertext, tokens, provider secrets, credential-bearing URLs,
plaintext bodies, and arbitrary provider errors must not appear in stored adapter records, ordinary reads,
stringification, dumps, snapshots, logs, exceptions, audit context, or analytics.

Delivered, retryable, and permanent outcomes are typed by the package contract. Safe bounded reason codes may be
returned where allowed; arbitrary provider exceptions become the package-defined safe retryable path and cannot be
parsed into policy. The immutable delivery-generation ID passes unchanged on every attempt.

Null/in-memory adapters are deterministic, configurable, and network-free. They are registered only in explicit
test/development composition. Production-like composition fails closed when a required provider adapter is absent;
it cannot silently discard work. Email-change provider wiring remains deferred even though persistence follows the
same package lifecycle.

No end-user permission applies. Internal invocation occurs only through claimed package work; this TASK does not
authorize product delivery endpoints or provider credentials.
