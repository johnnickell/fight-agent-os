# Correct activation and password capabilities

## Outcome

Correct current invitation activation, password setting/change and password reset under cohesive capabilities,
without serializing credentials or copying Access Control transitions. This is slice E of
[TICKET-00135](../tickets/00135-TICKET.md), normally one complete PR. Preserve real password policy, one-time grant
and session effects while replacing ambiguous failure handling and incorrect ownership.

## Scope

- Replace AuthenticationService directly with supported synchronous UserAuthentication::activate() and
  PasswordManagement::changePassword()/resetPassword(), qualifying the actual release signatures. Update all live
  callers/fixtures and their failure handling together. Raw password/current-password/activation/reset credentials
  remain sensitive synchronous parameters, not Command fields. Retain genuine owned password-policy coordination,
  not a replacement authentication facade or old/new compatibility mode.
- Keep RequestPasswordReset dispatched through the configured bus. The public request retains its canonical-email
  handling, bounded admission and anti-enumeration behavior, with package-owned grant/delivery/audit transitions.
- Correct PasswordSetting/PasswordStructure/PasswordRejection, compromised-password checking, hash/validation
  adapters and activation/change/reset collaborators by meaningful capability and descriptive injected names.
  Keep Domain rules inward, provider/corpus/framework work in Adapter and required acceptance policy with its owner.
- Actual HTTP entries own credential/input mapping, trusted current user where required, purpose-specific origin/
  CSRF/admission/limiter checks and safe presentation. Preserve validation semantics and separate authenticated
  password change from public credential activation/reset; do not invent new permissions or protected endpoints.
- Consume actual package atomic activation, password replacement, authentication-version/session invalidation,
  one-time grant and audit behavior. No package-handler outer transaction, custom grant policy, artificial business
  aggregate, fake serializable command or copied authentication implementation.
- Remove generic LogicException-to-conflict activation classification in favor of intentional qualified failure
  contracts. Preserve policy rejection versus credential/business refusal, internal/availability failure and
  post-commit uncertainty without retaining raw secret-bearing causes or promising safe automatic replay.
- Preserve current session issuance/non-issuance semantics: activation creates its supported ordinary session;
  password change/reset do not invent replacement authority. Coordinate any real cookie/device outcome with the
  existing session owner rather than duplicating session mechanics.
- Reconcile affected Actions/Data/Responders, guards, validation capability/metadata adapters and existing validation
  discovery callers, composition, OpenAPI, necessary browser callers/docs and meaningful tests. Safe generic
  field/error projection belongs to TICKET-00136, not another classifier. Delete superseded types/tests after proof.

Excludes new authentication/password features, corpus-provider changes, email-change journeys, new permissions,
shared error-framework replacement and credential-worker/provider correction owned by TASK-00581. No implicit
credential/session history disposal, upstream mutation, application compatibility alias or new bus/result framework.
