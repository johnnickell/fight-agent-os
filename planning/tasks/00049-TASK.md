# Deliver the authoritative current-principal projection

## Outcome

`/api/v1/me` becomes the sole client authority projection by resolving each authenticated request through request-scoped `CurrentPrincipalProvider`, returning only safe identity and current role/permission names, and replacing the client's injected foundation loader with one typed production service whose session-scoped cache invalidates and refetches without persisting authority.

## Scope

- In scope: Request-scoped principal composition; safe current-user identity lookup/projection; authenticated `/api/v1/me` Action/View/route/OpenAPI; deterministic role/permission name mapping; no-store response policy; typed client feature service and runtime decoding; replacement of injected loader; principal-cache invalidation/refetch after login, refresh, logout, terminal failure, and authority-change signals; generation/stale-response protection; permission-catalog alignment; PostgreSQL/HTTP/client/cross-tab/redaction tests.
- Out of scope: Dashboard/frame/theme UI, token parsing changes, role/permission mutation, authority in JWT/HTML/runtime configuration, cross-tab projection broadcasts, persistent cache, session-management fields, user administration, and treating client checks as server enforcement.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Resolve current authority | N/A — read-only endpoint | `CurrentPrincipalProvider::getCurrentPrincipal()` and package-owned safe identity query | N/A — no domain event | One request-scoped authoritative snapshot becomes a safe no-store View |
| Load client principal | N/A — typed API read | `GET /api/v1/me` through shared API client | Client cache transition only | Sole principal cache enters authenticated state only after strict response decoding |
| Invalidate authority | N/A — client coordination | Observe login/refresh/logout/terminal/authority-change generation signal | Client invalidation/refetch signal | Cached projection clears; appropriate authenticated flow refetches; late result is ignored |
| Reject invalid authority | N/A — authentication middleware/provider | Resolve access claims, active user, session, version, roles, and permissions | N/A — no domain event | Sanitized correlated `401`; no partial identity or authority is returned |

## Validation and permissions

Require TASK-00044 Bearer authentication and use the request-scoped package `CurrentPrincipalProvider`; do not decode a second authority source or query roles/permissions independently in the Action. Resolve safe identity data through an Application-owned orchestration/query compatible with the accepted ownership ADR, compare identity to the principal, and fail closed on missing/mismatched/non-active state. `/me` requires authentication but not `VIEW_DASHBOARD`, because the client needs authority to distinguish authenticated forbidden routes from anonymous state.

Return an explicit View containing only stable user identity, canonical email needed for current-user presentation, deterministic unique role names, and deterministic unique permission names. Exclude refresh/session identifiers, authentication version, entity revisions/state internals, hashes, grants, credentials, pending destinations, audit/delivery data, timestamps, and repository objects. Validate every name against package value objects and the version-controlled managed catalog while permitting authoritative package behavior defined by accepted policy; never infer permission from role name.

Use versioned JSend and `Cache-Control: no-store` with truthful OpenAPI. Generic `401` covers invalid/missing/stale authentication; malformed or incomplete authoritative references fail closed without naming the failing record. Known transport failures follow centralized mappings and unknowns remain sanitized correlated `500`.

Replace TASK-00028's injected loader without creating a second cache/context. Strictly decode response shape, reject duplicate/malformed/unknownly shaped values according to typed contract, and preserve unknown/loading/anonymous/authenticated/stale/terminal semantics. Invalidate after login and every refresh before/refetch after accepted authentication state, clear on logout/terminal failure, and process authority-change/cross-tab signals as refetch instructions only. Never broadcast or persist the projection. Generation checks prevent an older response from restoring invalidated authority.

No role or permission grants access merely because it appears client-side. Exact shared permission evaluation controls presentation; each protected server operation remains independently authorized.
