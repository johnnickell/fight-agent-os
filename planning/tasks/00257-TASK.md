# Preview exact managed-Agent creation

## Outcome

A currently authorized administrator can inspect an exact proposed named Agent: reviewed template revision,
Team, permitted Repository scope, complete eligible desired direct Permissions and protected holder/destination
readiness. A coherent preview requests authority but grants nothing and is never a reusable admission token.

## Scope

- In scope: Protected read-only creation preview through owned Application/HTTP paths, complete template/Permission/
  scope resolution, exact provenance, bounded safe availability reasons and immutable intended selection.
- Out of scope: Template seeding/editing, creating an Agent or credential, registering holders, applying Permissions,
  arbitrary prompt/checkbox inputs, provider invocation, session launch or another template/trust registry.

## Validation and permissions

Require TASK-00256's current intent-specific creation and initial-assignment authority for a grant-bearing creation
preview, plus applicable target/scope read rights. Template-management authority alone grants no Agent access.
Server-resolve trusted identities; client names, roles, requested Permission arrays or supplied URLs cannot choose
a different template, grant, holder or credential destination. Normalize the intended friendly name through the
package name contract; it is not a unique identity or retry key.

Consume TASK-00249's exact database-backed Harness revision and complete reviewed resources/model constraints,
not source specifications as a runtime fallback. Show stable template identity and exact selected revision,
Team and allowed Repository scope, full desired current eligible `ADMIN_SAFE` Permission identities and safe
readiness. Missing/ineligible/retired references or unsupported resources must be explicit, never discarded to
manufacture a ready profile. Protected `SUPER_ADMIN_ONLY` rights remain ineligible even for a Super Admin caller.

Use actual current Team associations and registered Repository authority. Team/template membership or a preferred
Team grants no Repository access, Workflow delegation or launch power. A role can be creatable while a later
Workflow action is unavailable; distinguish that from incomplete/invalid required profile resources which block
creation. Resolve the intended distinct protected holder and fixed registered destination through their owner,
without exposing internal handles or offering operator enrollment in the browser.

Build one coherent selection, detecting competing template, Permission, Team/Repository and enrollment revisions.
The preview pins intended identity/content and records its observations; TASK-00258 revalidates exact confirmation
and live authority through supported transaction fences. Any required refreshed selection needs human review,
not automatic substitution. Preview is neither a reservation nor durable readiness proof.

Safe snake_case output excludes credential material, internal operation requests/keys, receipts, claims/leases,
provider configuration and another scope's protected template/Permission detail. Distinguish denied, unavailable,
invalid, missing and stale state within current disclosure authority; outages are not empty successful sets.
No audit/business mutation, issuance, registration, grant or provider egress occurs during this query.

## Acceptance criteria

- [ ] Authorized preview identifies the exact named selection, reviewed database revision, Team/Repository scope,
  complete eligible desired set and safe holder/destination readiness with no business mutation.
- [ ] Ineligible/protected/missing Permission definitions, incomplete resources, wrong scope and unavailable
  enrollment remain explicit and never produce a truncated set, substituted profile or arbitrary destination.

- [ ] Direct/API denial, malformed/unknown inputs and storage failures disclose no hidden target or protected
