# Deliver captured logs to private search with truthful receipts

## Outcome

Captured operational logs progress from durable pending work to the private search destination with truthful
acceptance, rejection and visibility state, including uncertain results and backend outages. This is approved
slice E of [TICKET-00112](../tickets/00112-TICKET.md), not a browser or Loki installation TASK.

## Scope

- In scope: Actual collector-to-private-search delivery binding, original-identity retry/reconciliation, bounded
  requests/admission/backoff, partial/rejected/uncertain responses, poison-data handling and independent status.
- Out of scope: Loki service/storage deployment, browser queries/tail, collector queue implementation, archive
  verification, new backend/admin proxy, changing original timestamps/content and invented exactly-once receipts.

Consume [WF-038](../wayfinder/tickets/WF-038-define-log-collection-and-failure-recovery.md),
[WF-040](../wayfinder/tickets/WF-040-select-the-log-search-backend.md) and
[TICKET-00113](../tickets/00113-TICKET.md)'s early exact ingestion/disposition contract. Preserve native original
observation/fragment/source identities and trusted collection clocks. Source persistence, HTTP acceptance, durable
backend storage, query visibility and independently verified archives remain separate facts.

Qualify actual partial batch completion, per-record rejection, metadata normalization, blocked-ingestion HTTP 260,
transport timeout and WAL faults. Generic 2xx, including a configured successful-looking ingestion block, cannot
settle all records as durable success. Preserve uncertain dispositions and replay original identities; retries may
produce duplicates and cannot erase legitimate repeated records. Do not rewrite event timestamps to satisfy limits.

Use the collection unit's shared maximum two delivery requests, <=1-MiB encoded batches including overhead,
3-second connection/10-second attempt deadlines and 1–60-second jittered retry backoff. No silent discard after a
retry count. Permanent schema/size/timestamp errors must not monopolize valid work; split/reduce only through the
qualified framing contract and retain rejected originals within TASK-00457's bounded holding/disposition rules.
Authentication/TLS/configuration failures block that destination, remain visible and do not disable verification.

Search unavailability must not intentionally block capture or archive progress. Queue pressure still obeys current
preservation/oldest-eligible rules; successful search alone is not verified archive or evidence-release authority.
Expose actual acceptance versus known query lag/unknown visibility through TASK-00456's status, not a guessed health
flag. TASK-00460 independently consumes its own route; neither delivery TASK is a whole-task prerequisite for the other.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Deliver pending records | Enrolled bounded private sink request | Original pending identity and precise sink result | Destination disposition, not Workflow/evidence completion | Accepted/rejected/uncertain work is retained or settled truthfully |
| Resume uncertain/partial delivery | Retry/reconcile original records within limits | Exact prior disposition and current destination capability | Recovery fact with multiplicity uncertainty | Surviving pending work progresses without changed identity/times |
| Handle poison or oversized input | Qualified split/rejected-data handling | Native rejection classification and holding capacity | Explicit rejection/loss uncertainty | Valid records retain fair progress without silent content deletion |
| Diagnose search outage | N/A — status inspection; automatic retries remain enrolled | Destination state, backlog and known visibility | Operational status only | Capture/archive can continue independently within their bounds |

## Validation and permissions

Use private scoped delivery credentials inside the enrolled Adapter/collector boundary, never browser/PHP request/
Agent Docker authority. Validate typed trusted source/framing identity and actual encoded sizes; producer fields
cannot select arbitrary tenants/endpoints. No TLS bypass or fallback public endpoint. Reuse current preservation
fences for copy release. Follow ADRs [0001](../adr/0001-application-ownership-and-orchestration.md) and
[0002](../adr/0002-postgresql-consistency-and-durable-effects.md); remote delivery is not an inline business transaction
or proof of a committed Workflow event. No pipeline redaction or backend credential in diagnostics.

## Acceptance criteria

- [ ] Actual private ingestion preserves accepted original identities/content/clocks through normal, partial and
  uncertain outcomes without claiming generic HTTP acceptance is durable/searchable/all-record success.
- [ ] HTTP 260, WAL uncertainty, lost acknowledgements, normalization, retry duplicates and per-record rejection have
  qualified dispositions; rejected/poison data cannot starve valid records or silently disappear.
- [ ] Actual sizes, shared concurrency, timeouts/backoff and bounded holding are enforced; authentication/TLS failure
  remains blocked without credential leakage or insecure fallback.
- [ ] Search outage leaves capture and the independent archive route's admission/backlog handling viable within their
  limits; the actual paired live-destination qualification is explicitly owned by TASK-00460 once both bindings exist.
- [ ] Owned disposition/recovery behavior and direct selected backend/transport qualification pass, with full
  `./bin/build` and explicit limits on observed crash/visibility/durability guarantees.
