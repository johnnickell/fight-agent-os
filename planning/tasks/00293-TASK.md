# Guard matched HTTP Actions with current Feature availability

## Outcome

Package-backed `FeatureFlagMiddleware` checks the final matched HTTP Action method after routing/authentication
and before Action construction or dispatch. OFF and ineligible PREVIEW deny with 404; a positive Feature result
never replaces ordinary authorization. Fresh repository reads, safe errors and the real Slim boundary are qualified.

## Scope

- In scope: Native method metadata, shared package availability composition, trusted request-principal integration,
  pre-Action HTTP enforcement, safe failures, authoritative-read behavior and actual dispatch integration.
- Out of scope: Another evaluator/authentication scheme, Agent-on-JWT exposure, scanner/provisioning on requests,
  Feature settings/UI/catalog, forced cancellation, deployment and a fabricated flagged product endpoint.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Enter a flagged Action | No command in the gate; owning Action dispatches only after admission | Matched method/native Attribute, trusted principal and package `FeatureAvailability` | No business event for the check | False denies before construction/dispatch; true continues under ordinary authorization |
| Enter an unflagged or explicitly public route | Only the original route's authorized operation | Existing route classification; Feature lookup only for a valid declaration | Owning operation's facts only | Unflagged behavior remains intact; public status is never inferred from ON |
| Observe a changed setting or invalid state | N/A — evaluation is read-only | Fresh Feature and bound Permission ID on every check | No success fact on rejection/error | Next check sees committed changes; broken/unknown/outage never silently allows or becomes OFF |

## Validation and permissions

Compose the selected package `FeatureAvailability` directly with the qualified Feature/Permission repositories,
not an owned forwarding alias or copied OFF/PREVIEW/ON policy. TASK-00292 supplies the qualified discovery/
persistence/preparation chain, including TASK-00290's canonical declaration surface. Preparation occurs through
protected operations before considering rollout, never inside a runtime check. Retain exact selected tag/source/
Composer lock evidence; existing storage or package in-memory scenarios are not consumer dispatch evidence.

Inspect Slim's selected route callable as the supported FQCN method without resolving the service/Action. The
inspected Slim callable resolver obtains or constructs the Action, so invoking it for metadata is too late.
Reuse TASK-00117's matched-Action boundary, native method resolution and supported metadata conventions; do not
build another route registry or eagerly instantiate unrelated Actions. Instantiate the actual package Attribute
with `newInstance()`, validating strict name, placement and nonrepeatability rather than reading arguments alone.
Malformed/conflicting/unsupported declarations must not quietly become unflagged. Preserve class-level ordinary
security metadata on its supported target rather than moving it to a method for visual consistency.

Place the Feature decision after routing and trusted authentication, before Action resolution/dispatch and
protected operation-specific validation/disclosure. Preserve outer bounded request protections and safe failure
handling; directly qualify Slim's last-in-first-out execution rather than infer ordering from configuration text.
Route/method misses keep their owning behavior. No valid Feature declaration means no Feature lookup or invented
flag requirement, while the ordinary security gate still applies.

Use only the immutable principal admitted by the route's existing qualified authentication scheme. TASK-00117
supplies current User authority and explicit public classification; use `null` only for an approved public route,
never after authentication failure, absent service, unknown worker identity or a caught provider exception. Do not
accept serialized principals, JWT Permission claims, `/me` output, role names or browser availability. This TASK
creates no Agent route or JWT/HMAC fallback; TASK-00294 qualifies actual Agent integration through TASK-00245.
An Agent principal is usable only where its owning authentication boundary already admits that route/request.

For an authenticated request that reaches this gate, OFF denies even privileged users, PREVIEW requires the
stored testing Permission ID in the captured principal, and ON permits continuation only. Preserve current
permission, owner/target, CSRF/Origin/rate and use-case checks. Authentication/ordinary authorization failures
retain their own safe semantics; a flag neither broadens a public exception nor disguises such failure as success.

The package reads the Feature and bound Permission on every invocation, including OFF and ON. Preserve missing
Feature, missing/mismatched binding, invalid state/name and storage-failure distinctions in sanitized internal
classification. Map legitimate false to fixed correlated 404; malformed configuration and operational errors
fail safely rather than becoming policy false or leaking exception messages. Use existing HTTP failure ownership,
not a second error middleware. No raw SQL, stored bytes, principal snapshots or credentials enter diagnostics.
Prevent shared/stale HTTP caching from reusing a per-principal admission or policy denial.

Qualify authoritative reads even with the same service instance, a second check in one request or another worker
job; no identity-map/result/negative cache may retain old settings. Binding uses original Permission ID, not a
renamed/recreated Permission name or configured default. Fresh Feature reads do not refresh the supplied principal:
reuse its package snapshot within the admitted request, and use the owning fresh provider on later requests/jobs.
Do not reauthenticate/consume a second Agent nonce merely to check a Feature. An admitted operation may finish;
there is no distributed check-and-effect transaction, scheduled recheck or retroactive cancellation guarantee.
