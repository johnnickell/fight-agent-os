# Expose authenticated typed judgments through MCP

## Outcome

A qualified Pi 1.1.0 caller can use the trusted first-party MCP judgment capability to ask typed questions about
bounded authorized evidence and receive compact answers with provenance. The usable path includes actual caller
authentication, current permission checks, source/disclosure admission and the shared evaluator; a local tool or
configured origin alone does not establish managed authority.

## Scope

- Reuse [TASK-00159](00159-TASK.md)'s evaluator/provider access, strict answer validation, budgets and receipts,
  and [TASK-00162](00162-TASK.md)'s contained source resolver and disclosure policy. Adapt the existing capability
  across the first-party boundary without a second provider client, privileged Jev identity or copied access policy.
- Own the minimum first-party MCP endpoint and Pi 1.1.0 caller integration required for this complete use case.
  Use the accepted first-party origin and real credential-holder/HMAC boundary from EPIC-00006; consume actual
  package-owned identity/permission contracts under ADR 0001. PHP retains authoritative application operations.
  An origin match, local operator session, model-supplied actor field or browser JWT does not substitute for the
  qualified MCP caller contract. Do not make browser Planning, full managed SDLC or downstream tool composition
  prerequisites merely to deliver this endpoint. Record any genuinely unavailable required contract as a blocker.
- Qualify the actual authenticated Pi caller path, credential isolation and identity/scope propagation through
  evaluator and source access. Support child/managed launch paths only after their real credential-holder and
  invocation context are qualified; do not invent Agent/assignment identities for unsupported local sessions.
- Expose a versioned request envelope: request identity, bounded evidence descriptors, inline typed questions or
  immutable preset reference, optional bounded context and requested limits. The server derives caller/session/
  repository authority from trusted invocation context, never from authoritative-looking request properties.
  Evidence descriptors distinguish supplied state, one permitted path and an existing authorized receipt with
  revision/digest and historical observation identity. Receipt inquiry never executes its original operation.
- Each question has a stable identity, prompt and answer kind: yes/no, declared choice or anchored score. Choices
  have caller-written identifiers/text; scores have declared bounds and anchors. Presets resolve immutable version
  and digest before evaluation, and cannot change tool permissions or operator settings. Any reason is another
  caller-written choice; Jev cannot generate a brief explanation that was never supplied.
- Return a versioned bounded envelope with request/evaluation identity, per-question typed answer or explicit
  unknown/not-applicable/incomplete/unavailable/invalid outcome, source coverage, authorized evidence references
  and evaluator/question/preset/policy/source provenance. Preserve distinct probability, confidence and score
  fields only when the qualified evaluator actually supplies them. There is no universal 0.70 threshold here.
  Denial, cancellation and transport failure retain distinct operation outcomes; none becomes a negative answer.
- References identify actual resolved evidence; locations may be returned only when deterministically verified
  against that source revision. Default results contain no full source, excerpts, query output, fabricated line
  numbers, hidden reasoning or free-form model explanation. Exact-source follow-up is a separate authorized read.
- Internal resolution does not recursively invoke Jev screening for its own evaluator inputs. Apply current
  containment, symlink, sensitive-source, access and independent provider-egress checks before every disclosure.
  Retain the 32 KiB regular-text file limit and reject or explicitly mark unsupported/binary/oversized evidence.
- Keep the shared 64 KiB serialized-input, eight-question, sixteen-choice, two-concurrent-request, fifteen-second,
  zero-automatic-retry ceilings and tighter applicable limits. Enforce protected per-request/session spending
  limits and conservative reservations across participating consumers; unsupported global budget scope is explicit.
  Bound response/provenance size and refuse unqualified request profiles rather than silently truncating evidence.
- Reject stale completion after stop/reload/context changes; preserve uncertain billing and provider failures.
  Start with fresh evaluation rather than introducing an unqualified general-purpose cache. TASK-00172 owns broad
  staged investigation, while TASK-00173 extends reusable answers after current evidence and authority checks.
- Deliver semantic-tool preference through governed instructions and available versioned presets, loaded only with
  the usable capability. Keep exact search/graph tools for symbols, dependency structure and precise evidence.
  Ad hoc questions cannot bypass guard, file-read, compaction, memory, triage or dispatch policies. Use Writing for
  Agents when authoring those instructions; qualify actual parent/child delivery rather than testing prompt text.
- Exclude new MCP sub-operations, live application/SQL analysis, memory ingestion, main-model routing, arbitrary
  command strings, generalized browser delivery and replacement of structural/graph tools.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Ask a typed question or preset | Submit a bounded evaluation request | Current authority, permitted evidence and validated typed answers | Judgment completed/rejected/failed observations | Authorized source reads, bounded provider usage and redacted receipts |
| Inspect an existing receipt | N/A: historical evidence inquiry | Authorized immutable receipt and declared typed questions | Judgment provenance identifies historical observation | No replay of the receipt's operation |
| Follow supporting evidence | Existing separately authorized exact-source read | Resolve current permitted reference and revision | Existing access observation where applicable | Only the needed permitted source enters caller context |
| Cancel or invalidate a request | Cancel owned work or invalidate obsolete invocation | Current request state and uncertain usage | Cancelled/obsolete observation | Stop dispatch/delivery; preserve possible charges |

## Validation and permissions

Authenticate before source lookup or provider dispatch, and use current package/application permission and repository
scope on each request. Source access and external disclosure are independent checks. Forged caller properties,
stale/revoked credentials and unauthorized references fail without revealing protected evidence metadata. Questions,
source text, presets and receipts are data, not a route to execute tools or alter endpoint/model/budget settings.

The first-party boundary is an implementation deliverable, not an already available guarantee. Name and keep an
unsupported required authentication/authority path blocked rather than replacing it with ambient service rights.
Local adapters preserve their documented same-user trust limits; neither a prompt nor file roots establish an OS
sandbox. Preserve current specialized consumers' thresholds and failure behavior independently of this tool.

## Acceptance criteria

- [ ] Actual Pi 1.1.0 invocation through the trusted first-party MCP endpoint proves authenticated caller identity,
  current scope/permission enforcement and protected evaluator access using the existing shared capability.
- [ ] Agent-authored yes/no, choice and anchored-score questions and versioned presets work over each supported
  bounded evidence form; invalid/missing/undeclared answers and explicit uncertainty cannot become ordinary answers.
- [ ] Results expose compact authorized references, honest coverage and reproducible provenance without fabricated
  locations, raw bodies or free-form reasons; a historical receipt never becomes fresh execution evidence.
- [ ] Forged identities, revoked authority, sensitive/escaped/symlink sources, denied disclosure and injected source
  instructions cannot expand access or cause execution. Authorization holds across every qualified entry path.
- [ ] Existing request/session ceilings, cancellation, obsolete completion and uncertain billing remain enforced;
  model/provider failure does not choose a replacement provider, relax policy or retry for a preferred answer.
- [ ] Governed semantic-tool preference is available with the qualified tool while exact evidence/search and
  specialized consumer policies remain usable; unsupported caller paths are explicitly identified.
- [ ] Representative classification, assumption and bounded diff-risk inquiries are compared with direct/structural/
  graph approaches for usefulness, missed evidence, unsupported claims, main-context size and available total cost/latency.
