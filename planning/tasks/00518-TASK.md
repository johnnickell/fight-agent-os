# Verify live handoffs and route corrections to Land

## Outcome

Provide bounded read-only live delivery verification in the Agent OS reference implementation and integrate it
with shared Land/routing guidance. Maintainers receive a verified current action, an exact Land correction
handoff or an evidence-recovery action, never an obsolete merge instruction or guessed state.

This completes [TICKET-00119](../tickets/00119-TICKET.md) using
[TASK-00517](00517-TASK.md)'s explicit identity and [TASK-00516](00516-TASK.md)'s ended-handoff correction path.

## Scope

- Qualify Common's explicit `./bin/planning-check --check-delivery` behavior and provide the supported bounded
  live-check interface for Agent OS. Document finite request/count limits, timeouts, identity checks and result
  semantics; do not infer compatibility from matching command names.
- Verify only relevant explicitly current delivery/merge handoffs through existing operator hosting access.
  Check exact subject/repository/PR identity and distinguish open, merged, closed-unmerged, mismatched,
  malformed/incomplete and unavailable evidence.
- Integrate mandatory relevant live verification into Land/routing handoff evaluation. Bind ended-handoff
  correction to the supported Land path without automatic invocation or tracked-file mutation by routing.
- Keep live verification separate from explicit write mode and ordinary offline validation/build behavior.
  Correctly reconciled historical references must stop generating live requests merely because they remain
  recorded as evidence.
- Provide exact next actions for verified states and evidence failures while preserving unrelated active/ready
  work and planning/decomposition ownership.
- Out of scope: automatic repairs, historical PR scans, background monitoring, CI-policy changes, fetch/push or
  merge from the checker, product APIs/events, managed Workflow implementation and ten-project rollout.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Verify a current handoff | Explicit supported live-delivery check | Bounded exact-PR identity and state reads using existing operator access | Observation evidence only | Read-only verified state or precise incomplete/error result |
| Route a verified open PR | Existing read-only routing entry point | Live result plus actual stage/acceptance evidence | N/A — recommendation only | Truthful current action; open alone does not prove readiness or acceptance |
| Route an ended handoff | Existing routing entry point | Verified merged or closed-unmerged result and owning record | N/A | Distinct observation and exact Land handback; no repeated merge instruction or automatic dispatch |
| Recover unavailable or mismatched evidence | Land/routing hold | CLI/authentication availability, response completeness and exact identity | Local diagnostic evidence only | Explicit unverified state and recovery action; no inferred merge/open state |

No application Command, Query, Domain event, permission or database change is introduced.

## Validation and permissions

Follow [lightweight routing](../CONVENTIONS.md#lightweight-work-routing),
[landing standards](../../docs/engineering/LANDING.md), [handoff rules](../../docs/engineering/HANDOFFS.md) and
[Writing for Agents](../../.pi/skills/writing-for-agents/SKILL.md). Use existing operator credentials without
printing secrets, requesting broader grants or changing hosting state. Document bounded observation scope and
failure recovery with the command interface.

Read-only means no edits, view refresh, fetch, publication, merge or automatic Land dispatch. Reject combining
live verification with mutation mode. A local planning pass is not live freshness; a verified open PR is not
acceptance, QA or required-CI success. Missing CLI/authentication, timeout, network/API error, partial response
or identity mismatch must never be converted into a fresh pass or assumed PR state.

Preserve existing Board ordering and planning handoffs. Verification uncertainty blocks the affected
recommendation without licensing unrelated history scans or mutations. Land retains the exclusive correction
path and its explicit subject, checkout and publication authority from TASK-00516.
