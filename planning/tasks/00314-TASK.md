# Prepare the exact publication candidate

## Outcome

A separately authorized Release Manager turns current independent acceptance and QA into a verified exact
publication candidate, with truthful database Planning closeout and no hidden implementation repair.

## Scope

- In scope: Release Manager admission, current acceptance/QA intake, intent-specific database closeout and
  eligible ancestor rollup, permitted administrative changes, final candidate manifest and fresh final checks.
- Out of scope: Repeating Review, repairing source, changing requirements/authority, push/PR effects, Markdown
  Planning writes after cutover, generic status setters, human approval/merge and release/deployment.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Admit Release Manager | Existing Workflow publication-preparation admission | Current Review/QA/bridge, Agent/session, authority, checks and Git state | Admission/hold facts | Separate bounded Release Manager session |
| Record accepted completion | Intent-specific acceptance/evidence/Planning closeout operations | Accepted candidate, criteria/evidence, expected Planning revisions and children | Completion and eligible ancestor facts through existing owner | PostgreSQL-authoritative completion and delivery-pending facts |
| Prepare and verify delivery candidate | Authorized bounded administrative closeout and final verification | Exact change manifest, current branch/base/remote and required-check policy | Candidate/verification or blocked facts | Exact verified candidate with fresh Release Manager receipts |

## Validation and permissions

Re-read Workflow, TASK/Planning, original Review, current technical acceptance, passing or justified N/A QA and
any TASK-00313 applicability bridge. Require a distinct authenticated Release Manager session with live direct
Permissions intersected with human/Workflow publication authority and Repository/context/resource restrictions.
It never inherits Team Lead/Engineer/reviewer credentials, repairs implementation or accepts its own substantive work.

PostgreSQL Planning is the sole authority after TASK-00104's approved verified cutover. Consume TASK-00092's
intent-specific lifecycle and same-operation eligible ancestor completion, with expected revisions and immutable
acceptance/evidence links; no generic writer or generated/frozen Markdown update. Terminal-first execution before
cutover remains an earlier milestone, not proof this later publication path is ready.

Keep accepted implementation A distinct from narrowly administrative delivery candidate B under the accepted
[closeout contract](../../docs/engineering/LANDING.md#acceptance-candidate-and-administrative-closeout). Only truthful
completion/publication metadata, approved evidence references, deterministic derived bookkeeping, provenance/links
and harmless corrections within EPIC-00008's envelope are permitted. Record every changed path and effect.
Requirements, implementation, tests, configuration, Permissions, authority and reviewed evidence cannot change
under that envelope. Material/ambiguous changes return to Review or human judgment; never silently amend policy.

Run the actual accepted required final checks on the exact candidate tree. Keep fresh check identities, outcomes,
warnings, missing evidence, tree/status and commit evidence attributable to Release Manager. Inherited or
Engineer-only receipts cannot become fresh final verification. Required literal-final-head delivery proof remains
blocking even when A is accepted and completion recorded. An incompatible literal-head completion requirement
needs its requirement owner's amendment, not a status-commit loop or an inferred waiver. No optional hosted check
is promoted to mandatory merely by repository configuration.

Persist candidate/closeout state and audit atomically under expected versions; external checks/Git effects occur
outside transactions with original-intent reconciliation. Failed/stale required checks hold delivery without
erasing valid A; demonstrated material defects use the acceptance/revision owners. Authority loss, unknown
liveness or uncertain effects never permit fresh blind retries or cleanup.
