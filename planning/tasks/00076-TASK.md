# Qualify supported local Planning operation

## Outcome

The maintainer directly exercises the complete local Planning installation journey on the reference Omarchy/Arch host and selected macOS version, and the repository records exact verified support, best-effort guidance, warnings, failures and recovery limits without converting implementation completion into deployment or universal platform certification.

## Scope

- In scope: Approved qualification plan; sanitized real-environment evidence for Omarchy/Arch and one named maintainer-tested macOS version; prerequisite/preflight comparison; explicit install/start/update/migration/HTTPS/approved-root/storage/diagnostic/stop/recovery exercise; guide and command corrections supported by findings; compatibility matrix and last-verified dates; unsupported/best-effort labels; cleanup and retained-resource accounting; final TICKET-00023 acceptance reconciliation.
- Out of scope: Automated platform certification, destructive host tests, arbitrary distro claims, production deployment, public DNS/certificates, broad backup disaster simulation, provider/Harness/Runner enrollment, repository registration, Planning migration, seeded-failure product tests, independent implementation review, merge, release and hiding substantive defects in qualification prose.

## Validation and permissions

Use an approved checklist naming exact host, OS/version/architecture, Docker/Compose, browser, Git/source-host tooling, filesystem, selected ports/hostnames, guide revision, application commit and owned resource names before any mutation. Preview every privileged, trust, network, mount, migration, update, stop, removal and cleanup effect. The human responds directly to operating-system prompts; no Agent receives sudo, administrator, keychain, secret-service, Docker Desktop or credential material.

Use only invented non-sensitive test content and explicitly approved project roots. Never paste credentials, private keys, tokens, passphrases, cookies, DSNs, raw environments, private logs or unnecessary personal paths into receipts. Sanitize screenshots and command output before preservation. Do not weaken platform security controls or use a complete-home mount to make qualification pass.

On both platforms, compare preflight output, owning-tool facts and Dashboard capability results. Exercise normal startup from the documented prerequisite state, explicit migrations, HTTPS/trust behavior, authentication needed to view the guide, approved-root add/change/remove and actual mount state, private Planning-storage persistence, diagnostics, bounded restart/update path, stop and documented recovery. Verify unrelated Docker projects, host files, credentials and source remain untouched.

Treat Omarchy/Arch and the named macOS release as verified only when the complete applicable path succeeds with recorded limitations. Keep `apt-get`, `dnf`, other Arch derivatives, other macOS versions, Docker alternatives and unsupported filesystems as best effort or unsupported unless direct equivalent evidence exists. One successful machine is not universal certification.

A substantive application, security, data-loss, migration, isolation or recovery defect blocks qualification and returns to the owning implementation TASK or a separately triaged bug; do not rewrite it as a warning. This TASK may correct bounded guide wording, commands and compatibility metadata directly supported by the run, then rerun affected evidence. Final status does not assert independent review, merge, release, deployment or production readiness.
