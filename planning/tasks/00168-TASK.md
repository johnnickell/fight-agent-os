# Enforce staged compaction at safe session boundaries

## Outcome

A participating local Pi 1.1.0 session can request early compaction, postpone recommendations within bounds and
compact at the request tier before new work begins. Deterministic accounting, quiet notices and verified fallback
remain available without Jev. Deliver timing and its real checkpoint integration together for
[TICKET-00041](../tickets/00041-TICKET.md).

## Scope

- Target **Pi 1.1.0**, using [TASK-00164](00164-TASK.md)'s protected checkpoint and validated resume contract.
  Qualify actual context-accounting, completed-turn, native-compaction, cancellation/reload and supported child
  hooks. A completed turn is an evaluation boundary, not proof that compaction is safe.
- Use initial notice/recommend/request targets of **180k/210k/240k tokens**. Resolve actual model/runtime settings,
  effective native trigger and available checkpoint/continuation reserve before activating a profile. The reported
  roughly 272k reference is an initial baseline to verify, never a hardcoded native guarantee.
- Scale tiers for other profiles from the verified effective trigger, preserving the accepted relative spacing.
  Define and record exact scaling/rounding and reserve calculations in versioned policy, qualify boundary cases
  on Pi 1.1.0, and reject overrides that break ordering or safety margins. Operator-owned settings cannot be
  enlarged by repository instructions or Agent assertions. Profile changes invalidate stale timing decisions;
  scaling never authorizes a model/provider switch.
- Maintain per-session current usage with provenance, freshness and measured/estimated/unavailable distinctions.
  Count context pressure rather than cumulative lifetime billing tokens. Do not infer safe capacity from unknown
  usage. If current usage or effective limits are unreliable, suspend custom tiers and use only qualified native
  fallback that satisfies TASK-00164; otherwise preserve/pause for intervention.
- From notice, allow explicit Agent-requested compaction at a safe point, including before large upcoming work,
  without any Jev verdict. From recommendation, actively recommend compaction and permit an attributable snooze
  with a reason. Snoozing never suspends accounting or later evaluation; it expires no later than request.
- At request, finish and reconcile already in-flight operations, then checkpoint/compact before the next work
  step. Do not start new calls to extend a work unit. Do not wait for Jev, require routine human/parent approval,
  or let a snooze veto the obligation. If safe compaction cannot fit the qualified limits, preserve and pause.
- Reuse TASK-00164's native baseline/fallback and resume validation, including actual model/cost prerequisites.
  Failure of optional selection or future timing judgment does not remove deterministic escalation. Missing
  required facts pause unless an independently available authorized repair capability satisfies the checkpoint
  contract; do not implement or duplicate TASK-00166's repair loop here.
- Persist enough protected timing/attempt state to recover after interruption without resetting an outstanding
  request-tier obligation or blindly repeating completed compaction. Reconcile actual checkpoint activation,
  in-flight effects, pending questions, current profile/usage and valid snooze scope. Honor explicit stops and
  cancellations; a reload does not restart stopped work or override governing instruction drift rules.
- Allow safe compaction while waiting for a human answer, preserving exact question identity/content/context and
  waiting status through the checkpoint contract; reconcile concurrent replies before dependent action. Unknown
  command/billing outcomes remain unknown and cannot be replayed as a recovery shortcut.
- Handle each supported Agent/sub-agent independently under its actual role/session authority and resources.
  Parent links carry authorized status only; review conversations stay independent. Qualify a real supported
  child path without inventing managed workflow identities or building an Agent launcher.
- Show quiet Agent/session notice, recommendation, snooze, fallback and compaction state. Deduplicate repeated
  unchanged notices independently of accounting; reserve direct human alerts for actual intervention. No new
  browser Dashboard dependency or claim of optimal intelligence follows from these notifications.
- Emit sanitized correlated lifecycle facts for profile/tier/request/snooze/cancel, checkpoint/compaction/resume,
  fallback and interruption/recovery. Include actual session/role/attempt/checkpoint identity, policy/runtime,
  bounded reason/actor/mode, protected references and available usage. Preserve WF-017 observation ownership.
- Exclude semantic timing evaluation (TASK-00169), history inspection/annotations (TASK-00170), new checkpoint
  storage, optional selection, memory promotion, retention cleanup, sandbox qualification and managed execution.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Activate timing policy | Select permitted profile/overrides | Effective context/native limits, reserve and usage | Profile/tier facts | Protected timing configuration/state and session presentation |
| Compact early or postpone | Request safe compaction; record bounded snooze or cancellation | Current tier, safe-point readiness and checkpoint availability | Request/recommend/defer/cancel facts | Authorized checkpoint/compaction or recorded deferral |
| Enforce request boundary | Initiate after existing operations reconcile | In-flight state and actual capacity | Request-tier/compaction/resume outcome | Compaction before new work, or preserved pause |
| Recover interruption/degradation | Reconcile timing state; use qualified native fallback | Actual activation, authority, question/effect and usage state | Recovered/fallback/blocked/intervention facts | Verified continuation; no reset obligation or effect replay |

## Validation and permissions

Reuse protected profile/storage controls from TASK-00164/TASK-00160; checks and model calls retain actual current
authority and disclosure limits. Overrides cannot remove reserve or permit unsupported execution routes. Quiet
UI state and telemetry are not approval, checkpoint authority or permission to resume. Local sessions do not
invent managed grants, claims or leases. Unknown limits, unsafe in-flight state or unavailable native recovery
must yield an explicit limitation, not guessed scaling or silently continuing beyond a request obligation.
Same-user process isolation remains the separate TASK-00138 boundary.

## Acceptance criteria

- [ ] Actual Pi 1.1.0 evidence establishes accounting freshness, effective native limits, scaled ordered thresholds,
  overrides and checkpoint/continuation reserves, with measured versus estimated facts stated explicitly.
- [ ] Agent-requested compaction from notice, recommendation and reasoned snooze behave as accepted; snooze expires
  by request. Quiet notices are deduplicated without suspending accounting.
- [ ] At request, already in-flight work completes/reconciles, then compaction or preserved pause occurs before new
  work. Concurrent/queued tool operations cannot slip past the qualified safe-point boundary.
- [ ] Unknown counts/limits, failed native summary, overflow and unavailable checkpoint facts produce qualified
  fallback or intervention. Missing Jev does not disable this deterministic capability.
- [ ] Reload/interruption, concurrent human replies, late completions and cancellation preserve question identity,
  valid authority and outstanding obligations without duplicate compaction, effect replay or resumed stopped work.
- [ ] Supported parent/child sessions operate independently with authorized status and private checkpoints; routine
  operation needs no parent approval. Unsupported lifecycle paths are identified rather than advertised.
- [ ] Correlated sanitized observations distinguish recommendation, saved checkpoint, compaction and validated
  continuation. Missing/duplicate telemetry neither proves nor authorizes recovery.
