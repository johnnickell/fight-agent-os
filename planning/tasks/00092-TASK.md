# Complete Planning lifecycle and archive operations

## Outcome

Authorized planners can use intent-specific EPIC/TICKET/TASK lifecycle, closeout, Won't Fix impact, reopen, archive and restore operations while parent readiness remains derived, judgment stays human-controlled and no status or relationship cascades silently.

## Scope

- In scope: Accepted EPIC/TICKET/TASK machine-status transition commands/events for needs-triage, needs-info, ready-for-agent, ready-for-human, in-progress, done and wontfix; explicit reasons/evidence; derived closeout readiness; TICKET/EPIC closeout previews and commands; completion-summary/progress revisions in closeout; mandatory human decisions; TASK Done semantics; Won't Fix direct/transitive dependent preflight and recoverable impact plan; reasoned reopen; archive/restore for all TICKET-owned Planning aggregate types where applicable; orthogonal archive state; parent restoration prerequisites; lifecycle/closeout/archive Views, Permissions, PostgreSQL constraints/concurrency and versioned API/OpenAPI.
- Out of scope: Generic status setter, automatic parent completion, review/PR/merge/release/deployment status, TASK priority/next eligibility, claims/execution, Markdown migration, browser UI, artifact automatic deletion, multi-person approval and purge policy beyond TASK-00087.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Transition lifecycle | Intent-specific ready/request-info/request-human/start/complete/decline/reopen command | Explain current transition prerequisites, criteria/evidence and blockers | Type-specific semantic lifecycle event | Only one valid reasoned transition appends; parents/children/edges remain unchanged |
| Close a TICKET | Explicit closeout command | Revalidate child outcomes, criteria/evidence, changed scope and unresolved work | Type-specific completion event plus semantic summary revision | Fully evidenced all-Done closeout may use authorized planning agent; judgment cases require human confirmation |
| Close an EPIC | Explicit closeout command | Revalidate destination, outcomes, child closeout, evidence, exclusions and unresolved work | Type-specific completion event plus semantic summary revision | Human-confirmed EPIC completion appends; no child action triggers it |
| Mark TASK Won't Fix | Explicit decline command with impact plan | Show direct/transitive active dependents and current edge versions | Type-specific declined event and persisted impact-plan state | Human-classified direct dependents are handled only through separately approved actions; no cascade/removal occurs |
| Archive/restore | Type-specific archive/restore command | Explain terminal/child/parent/link and artifact-hold prerequisites | Type-specific archived/restored event | Archive visibility changes independently; restore preserves prior lifecycle and may require parent restoration |

## Validation and permissions

Expose intent-specific commands only; no generic status setter. Validate type-specific transition matrices, required reason/evidence, expected stream/constraint versions and actor authority. Derived blocking/closeout readiness is never stored as another status. Child completion only changes its stream and may update a readiness projection; it never emits a parent lifecycle event.

TASK Done means implementation acceptance and required verification are complete. It does not mean independent review acceptance, PR publication, human approval, merge, release, deployment or certification. Those remain typed evidence/links. TICKET closeout revalidates intent, criteria, child outcomes, evidence, exclusions/scope and unresolved work. An authorized planning agent may close only a fully evidenced TICKET whose children are all Done; any Won't Fix child, changed scope, incomplete evidence or judgment requires exact human confirmation. A human always confirms EPIC completion.

TASK Won't Fix first creates/persists an expected-version impact plan after showing direct and transitive active dependents. A human classifies each direct dependent: safe explicit edge removal with rationale, retain edge and move dependent to Needs Info, separately process its own Won't Fix, or no change/cancel. Each resulting mutation uses its own command and current authorization/version. Never cascade statuses or remove dependencies automatically; interrupted execution leaves a recoverable unapplied/revalidated plan.

Archive is orthogonal and explicit. Active/non-terminal artifacts cannot archive. TASK requires Done/Won't Fix; TICKET/EPIC require terminal state and terminal children; Wayfinder records satisfy TASK-00086 closure; ResearchNote/Prototype follow their accepted final/retention rules. Archive does not delete events, evidence, artifacts or dependencies. Restore preserves prior lifecycle/history and may require explicit parent restoration first; reopening is separate.

Use independently justified view/lifecycle/closeout/Won't Fix/archive/restore Permissions. Mandatory human confirmations bind actor, exact aggregate/constraint versions, plan/impact and short expiry; agents do not impersonate humans. Event append, closeout summary/current projection, impact-plan or archive constraints and audit evidence commit atomically. Safe APIs expose actionable reasons without hidden child/dependent content.

## Acceptance criteria

- [ ] Every accepted lifecycle change has an intent-specific command/event and validated type-specific transition; no generic setter exists.
- [ ] Child completion never closes a parent; closeout readiness is derived and visible with complete inclusion/exclusion reasons.
- [ ] TASK Done records implementation acceptance/verification only and does not infer review, publication, merge, release or deployment.
- [ ] TICKET closeout revalidates all children/criteria/evidence/scope; any judgment case requires human confirmation.
- [ ] EPIC closeout always requires current human confirmation and revalidates destination/outcomes/children/evidence/exclusions.
- [ ] Won't Fix uses a recoverable current impact plan and separately authorized direct-dependent actions without cascade or automatic edge removal.
- [ ] Archive is explicit/orthogonal/terminal-only; restore preserves prior lifecycle/history and obeys parent/retention prerequisites.
- [ ] Expected-version/idempotent/concurrent closeout/impact/archive operations yield one exact semantic history and consistent constraints.
- [ ] Lifecycle/closeout/Won't Fix/archive/restore Permissions and confirmations are independently enforced.
- [ ] Focused behavior/PostgreSQL/concurrency/API tests and the canonical build pass.
