# Complete Planning lifecycle and archive operations

## Outcome

Authorized planners can use intent-specific EPIC/TICKET/TASK lifecycle, closeout, Won't Fix impact, reopen, archive and restore operations with automatic TICKET/EPIC completion when their children close and explicit authority for new decline, waiver, reopen and archive decisions.

## Scope

- In scope: Accepted EPIC/TICKET/TASK machine-status transition commands/events for needs-triage, needs-info, ready-for-agent, ready-for-human, in-progress, done and wontfix; explicit reasons/evidence; automatic ancestor completion in the originating child-closure operation; completion-summary/progress revisions derived from child outcomes; TASK Done semantics; Won't Fix direct/transitive dependent preflight and recoverable impact plan; reasoned reopen; archive/restore for all TICKET-owned Planning aggregate types where applicable; orthogonal archive state; parent restoration prerequisites; lifecycle/closeout/archive Views, Permissions, PostgreSQL constraints/concurrency and versioned API/OpenAPI.
- Out of scope: Generic status setter, separate parent-closeout approval, review/PR/merge/release/deployment status, TASK priority/next eligibility, claims/execution, Markdown migration, browser UI, artifact automatic deletion, multi-person approval and purge policy beyond TASK-00087.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Transition lifecycle | Intent-specific ready/request-info/request-human/start/complete/decline/reopen command | Explain current transition prerequisites, criteria/evidence and blockers | Type-specific semantic lifecycle event | One valid reasoned transition appends; terminal child outcomes also close eligible ancestors; child and dependency edges remain unchanged |
| Close a TICKET | Automatic continuation of child closure | Read all authoritative TASK outcomes, including archived children | Type-specific completion event plus child-outcome summary revision | Nonempty all-terminal child set closes the TICKET in the same operation without another review or confirmation |
| Close an EPIC | Automatic continuation of TICKET closure | Read all authoritative TICKET outcomes, including archived children | Type-specific completion event plus child-outcome summary revision | Nonempty all-terminal child set closes the EPIC in the same operation without another review or confirmation |
| Mark TASK Won't Fix | Explicit decline command with impact plan | Show direct/transitive active dependents and current edge versions | Type-specific declined event and persisted impact-plan state | Human-classified direct dependents are handled only through separately approved actions; no cascade/removal occurs |
| Archive/restore | Type-specific archive/restore command | Explain terminal/child/parent/link and artifact-hold prerequisites | Type-specific archived/restored event | Archive visibility changes independently; restore preserves prior lifecycle and may require parent restoration |

## Validation and permissions

Expose intent-specific commands only; no generic status setter. Validate type-specific transition matrices, required reason/evidence, expected stream/constraint versions and actor authority. Derived blocking is never stored as another status. Apply [automatic parent completion](../CONVENTIONS.md#automatic-parent-completion) bottom-up in the same operation as child closure. Child and resulting parent lifecycle events, summaries and current constraints commit atomically; retry on a stale hierarchy snapshot rather than leaving a separate user closeout step.

TASK Done means implementation acceptance and required verification are complete. It does not mean independent review acceptance, PR publication, human approval, merge, release, deployment or certification. Those remain typed evidence/links. TICKET and EPIC status follows the nonempty child set: all `wontfix` yields `wontfix`; otherwise all terminal yields `done`, preserving declined outcomes in the summary. Empty or unfinished child sets do not close. No parent-only review, QA or confirmation is required. Existing terminal/archived records are preserved.

TASK Won't Fix first creates/persists an expected-version impact plan after showing direct and transitive active dependents. A human classifies each direct dependent: safe explicit edge removal with rationale, retain edge and move dependent to Needs Info, separately process its own Won't Fix, or no change/cancel. Each resulting mutation uses its own command and current authorization/version. Never cascade dependent TASK statuses or remove dependencies automatically; interrupted execution leaves a recoverable unapplied/revalidated plan.

Archive is orthogonal and explicit. Active/non-terminal artifacts cannot archive. TASK requires Done/Won't Fix; TICKET/EPIC require terminal state and terminal children; Wayfinder records satisfy TASK-00086 closure; ResearchNote/Prototype follow their accepted final/retention rules. Archive does not delete events, evidence, artifacts or dependencies. Restore preserves prior lifecycle/history and may require explicit parent restoration first; reopening is separate.

Use independently justified view/lifecycle/Won't Fix/archive/restore Permissions. Authorized child closure includes its required ancestor rollup; do not require an extra parent permission ceremony. Human confirmations for new decline, waiver or archive decisions bind actor, exact aggregate/constraint versions, plan/impact and short expiry; agents do not impersonate humans. Event append, closeout summary/current projection, impact-plan or archive constraints and audit evidence commit atomically. Safe APIs expose actionable reasons without hidden child/dependent content.

## Acceptance criteria

- [ ] Every accepted lifecycle change has an intent-specific command/event and validated type-specific transition; no generic setter exists.
- [ ] Closing the final unfinished TASK automatically closes its TICKET and, when eligible, its EPIC in the same operation, with no additional invocation, review or confirmation.
- [ ] TASK Done records implementation acceptance/verification only and does not infer review, publication, merge, release or deployment.
- [ ] All live and archived children count; empty and unfinished child sets stay open. Mixed done/wontfix closes as done with exclusions retained; all-wontfix closes as wontfix.
- [ ] Repeated closure is idempotent; concurrent child/hierarchy changes cannot produce stale parent completion.
- [ ] Won't Fix uses a recoverable current impact plan and separately authorized direct-dependent actions without cascade or automatic edge removal.
- [ ] Archive is explicit/orthogonal/terminal-only; restore preserves prior lifecycle/history and obeys parent/retention prerequisites.
- [ ] Expected-version/idempotent/concurrent closeout/impact/archive operations yield one exact semantic history and consistent constraints.
- [ ] Lifecycle/Won't Fix/archive/restore authority is enforced; ancestor rollup follows authorized child closure without an additional parent-closeout gate.
- [ ] Focused behavior/PostgreSQL/concurrency/API tests and the canonical build pass.
