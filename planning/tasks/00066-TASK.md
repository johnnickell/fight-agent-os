# Prove critical browser continuity and close the foundation gate

## Outcome

The smallest pinned deterministic real-browser smoke suite proves only integration contracts unavailable below the browser boundary—trusted HTTPS/Secure cookies, credential-fragment history/referrer behavior, reload restoration, theme bootstrap, and multi-tab Web Locks/BroadcastChannel invalidation—then runs read-only inside `./bin/build` and records fresh complete foundation evidence without claiming review, release, deployment, or certification.

## Scope

- In scope: Select/pin containerized browser runner and browser version; isolated HTTPS application/PostgreSQL/catcher fixtures; deterministic seed/cleanup; minimal browser-only scenarios; controlled multi-tab synchronization; credential-safe artifact/failure policy; zero-hidden-retry/non-quarantine policy; focused repeatability proof; canonical-gate named phase integration; read-only/tracked-state proof; final TICKET/EPIC verification evidence and explicit warnings/exclusions/operational deferrals.
- Out of scope: Broad E2E/regression suite, duplicating lower-level journey/accessibility tests, multi-browser/device certification, visual-regression baseline, arbitrary sleeps/retries, production provider/deployment, formal penetration/accessibility/release certification, review/merge/landing, and fixing undisclosed blocking defects only in completion prose.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Run isolated browser smoke | N/A — repository test wrapper | Seed/query isolated app/database/catcher and inspect browser-visible outcomes | Existing application events only | Exact minimal scenarios pass or fail with sanitized deterministic diagnostics and full cleanup |
| Coordinate real browser tabs | Existing login/refresh/logout/revoke operations | Observe Web Locks/BroadcastChannel and authoritative server state | Existing client coordination/package outcomes | One bounded refresh leader and terminal/list/principal invalidations converge across pages |
| Prove credential-fragment boundary | Existing activation or reset journey | Inspect server request/referrer/history and transient browser state | Existing activation/reset event on chosen path | Fragment never reaches server/referrer/persistent storage and visible history is replaced before ordinary navigation |
| Run canonical foundation gate | `./bin/build` | Execute all prior canonical phases plus named browser-smoke phase | N/A — tooling only | Full read-only gate passes or attributes mandatory smoke failure clearly |

## Validation and permissions

Choose a pinned supported browser automation tool compatible with TASK-00032/00033's frontend lock/container policy. Pin browser binary/version/checksum through approved tooling; no floating download during product tests. Run headless by default against TASK-00063 trusted HTTPS using an isolated database, disposable mail catcher mailbox, synthetic identities, external test secrets, fixed locale/timezone/viewport and bounded deterministic clock/control hooks where application time matters.

Keep scenarios minimal and justified by browser platform boundaries. Required coverage includes: (1) Secure/HttpOnly cookie behavior through actual HTTPS plus one activation or reset link where fragment capture/history replacement/referrer cannot be proved below browser; (2) reload starts without access token, restores through HttpOnly refresh and authoritative `/me`, with prohibited storage empty; (3) two real pages/tabs use Web Locks/BroadcastChannel so one bounded refresh leader succeeds and logout/terminal invalidation reaches both; (4) another-session revocation or equivalent terminal authority proves server denial and applicable list/target convergence without cross-device claims; (5) system theme pre-render/OS-change and one critical focus behavior only where lower layers cannot establish browser rendering. Every scenario cites why lower-level evidence is insufficient.

Use deterministic API/database fixture setup rather than UI setup unrelated to the browser assertion, except when the critical journey itself is under test. Synchronize with explicit application/test events, network barriers, DOM state, lock hooks, database state or bounded polling; no arbitrary sleeps. Validate timeout bounds. Disable hidden retries and quarantine; one failure fails. Repeat focused suite enough to detect order/shared-state leakage and run scenarios independently.

Protect artifacts: use invented data; mark credentials sensitive; disable or sanitize traces, videos, screenshots, HAR, console/network dumps and HTML snapshots on credential-bearing steps. Failure reporting may include scenario/step/correlation/safe state only. If an artifact cannot be made secret-safe, do not collect it. Verify browser local/session storage, IndexedDB, Cache Storage, service workers, URL/history and generated outputs contain no prohibited credentials/authority. Always clean browser profiles, catcher mail, database, test secrets and scratch.

Add one clearly named mandatory browser-smoke phase to canonical `./bin/build` with deterministic startup/readiness, cleanup, and tracked-tree mutation checks. Keep generated browser/cache/report files ignored/disposable. It may not install dependencies, invoke source/planning writers, modify locks, access production/development data, or use external product network. Inspect and invoke the phase directly; do not seed a failure merely to test build attribution.

Final evidence reconciles TASK-00063 through TASK-00065 and TICKET-00014 through TICKET-00021 acceptance without recopying inherited receipts as fresh. Record actual commands/versions/counts/durations/warnings/exclusions/manual limits and unresolved production mail/TLS/deployment enrollment.
