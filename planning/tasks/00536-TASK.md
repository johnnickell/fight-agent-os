# Remove the legacy fight-terminal command

## Outcome

Permanently stop shipping the legacy `fight-terminal` command, leaving native `fight-workspace` usable and
unchanged. This is a new standalone chore, not a reopening of completed TASK-00512 or TASK-00535.
The owner directly approved permanent source removal and later owned cleanup/installation: “Can we do that?
Also, I'm ready to cleanup and install fight-workspace”. The isolated checkout choice remains in effect.

## Scope

- In scope: remove the obsolete package bin and sole-use direct retirement module; update directly affected
  dedicated checks and current installation/migration documentation; qualify packaging and owned upgrades.
- Out of scope: launcher behavior rewrites, RPC restoration/fallback, native authority or log-custody changes,
  automatic provisioning, unrelated refactors, global installation/settings changes in Work, and changes to
  historical acceptance records. Later global adoption requires independent acceptance and a separate receipt.

## Validation and permissions

Search actual consumers before deleting sole-use modules. Validate packaging/migration infrastructure with its
owning tools, not new product-suite tests of configuration or wrappers. Refuse unexpected package/bin ownership,
including dangling links; never force, use sudo, edit shell profiles or delete guessed paths. Only task-owned
isolated prefixes/settings/session fixtures may be changed during implementation qualification. No real global
installation/settings or operator sessions are changed. Preserve unrelated work, shared stacks and historical receipts.
