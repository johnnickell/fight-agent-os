# Follow existing Start and Pending start intents

## Outcome

Humans can follow their existing Ready-card/keyboard start or withdrawable Pending start into the real sessions
Dashboard and exact Workflow detail, without a duplicate form, second normal-work approval or false execution state.

## Scope

- In scope: Production navigation/status composition between existing TASK-00205/00265 interactions and sessions
  overview/detail, exact intent-to-Workflow correlation, accessible pending/withdrawn/admitted/uncertain continuity.
- Out of scope: New Start or pending engine, eligibility/Team/Triage policy, duplicated confirmations/withdrawal,
  automatic task selection, new queue, generic status mutation and operational lifecycle controls owned by TASK-00394.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Follow Ready-card/keyboard intent | Existing TASK-00205 operation only, never a second request from navigation | Exact original intent, current authoritative outcome and accepted Workflow | Existing committed Start facts only | Same accepted Workflow becomes navigable, not another claim |
| Follow or withdraw Pending start | Existing TASK-00265 interaction/operation only | Original bounded intent, consent/expiry, withdrawal/admission outcome | Existing pending/withdrawn/admitted facts | Same owning outcome; withdrawal cannot cancel started work |
| Reconnect or return to sessions | N/A — authorized status/detail reads | Current original intent/Workflow relation and durable result | Existing safe updates only | Honest pending/queued/preparing/working/held states without replay |

## Validation and permissions

Consume TASK-00391 real sessions navigation and TASK-00265's complete existing pending/selection integration,
including TASK-00205 pointer/keyboard Start transitively. Reuse those owners' current operations and exact consent,
expected-state, scope/identity and original-result semantics. Do not add another Start form, normal-route confirmation,
client eligibility algorithm or claim to bridge navigation. Any existing Planning database prerequisites remain
with those browser entry owners; they do not become new prerequisites of terminal Start or Markdown authority.

A Pending start is not a Workflow, claim, queued Runner or In Progress record. Link only an actually accepted original
Workflow identity verified by the owner. Distinguish pending, withdrawn, expired, held/uncertain, claimed/queued,
preparing and actually working. Triage recommendation, card movement, a response timeout or navigation success
proves none of these outcomes. Keep denied/unavailable references safe without leaking hidden TASK/Team facts.

Withdrawal uses the existing bounded intent operation; if admission wins, display/navigate to the actual Workflow
and never report withdrawn or silently cancel it. Changed/expired consent, current authority or source conflicts
return to the owner's required human action, not renewed consent by repeated clicks/read/restart. Current status
inspection does not schedule/reconsider pending work. Resolve original uncertainty before any further effect.

Retain ADR 0003/0004 sole authority/cache and generation fences across route, Repository, selected TASK and session
changes. Only allowlisted non-sensitive navigation values belong in URLs; confirmations, intents as business state,
grants, raw payloads and private drafts remain out of browser persistence/history/logs. Do not restore authority from
a carried route ID. Guard loaders/actions and retire late results, even after cancelled network requests. Refresh,
logout, tab close or reconnect never replays Start or withdraws/cancels work.

Provide pointer/keyboard-equivalent status, focus and announcements. A refusal restores/refetches authoritative Ready
placement through its existing owner; do not mutate Planning or Board order locally. Missing Dashboard access can
leave an honest existing start outcome without exposing protected detail or treating navigation failure as Start
failure. Existing accepted work is not repeated merely because its destination cannot be viewed.
