# Authorize and broker each bounded Agent use

## Outcome

Connect real current Agent authority to existing human/manual-session or Workflow grants, Team/Repository/context
and supported host constraints. The protected holder signs only the exact authorized bounded request, while all
relevant grant/revocation writers participate in shared fences. Raw credentials never enter Pi children.

## Scope

- In scope: Agent-specific current-use Application admission and protected signing integration with existing
  Harness/Runner broker owners; live direct Permissions, initiating-human/delegation, activation/holder, Team/Repository,
  context/profile/session/attempt and host limits; writer participation, safe denial and hold behavior.
- Out of scope: Another grant/Workflow engine, Team registry, provider client, sandbox/provisioner, general signing
  oracle, arbitrary endpoints or autonomous TASK selection; browser Planning/database cutover is not a manual-use gate.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Admit one bounded use | Owning tool/broker operation with trusted session or Workflow invocation context | Exact current credential/destination, activation, direct Permissions, initiating authority and scope | Existing owning use/effect fact only when established | One currently authorized request, never power inferred from authentication or a template |
| Sign through protected holder | Internal fixed-destination signing/dispatch under current bounded admission | Actual holder, canonical request, current grant/host and request limits | Safe invocation observation; no secret-bearing event | Real signed request dispatched through approved boundary, without exporting the key or providing arbitrary signatures |
| Revoke/narrow or hold use | Existing owner grant/session/Team/credential changes with integrated fences | Current expected revisions, authority epochs and actual process/session lineage | Existing owning revocation/change facts | Subsequent requests deny, stale/ambiguous contexts hold, historical snapshots remain unchanged |

## Validation and permissions

Reuse existing authority owners; do not recreate their records under authentication. Authentication and activation
are necessary but not sufficient. Intersect exact eligible direct Permissions with current initiating-human/manual
or Workflow delegation, one-Team membership and Repository association, designated checkout/context, pinned profile,
actual session/attempt and host/provider limits. Missing relevant authority denies; no synthetic Workflow for manual
use and no omission of Workflow grants when work actually belongs to one. Team/template names confer no rights.

Current use and applicable policy writers share cohort-first transaction-duration fences and monotonic epochs on
the canonical connection. Cover grant issuance/narrowing/revocation, human authority, Agent assignment/Permissions,
holder/destination, Team association/transfer and current session/attempt controls through their existing owners.
Package principal snapshots remain request-local; a subsequent invocation/request resolves fresh authority. Do not
promise retroactive cancellation of an already admitted effect. Preserve the owning broker's separately qualified
stream stop/cancellation behavior and disclose any residual in-flight window.

The signer remains within the protected holder boundary and selects only the exact currently authorized package/
destination tuple, even before the sink learns a replacement. Bind requested effect and method/authority/path/body
rather than accepting arbitrary request strings or caller-supplied account/role headers. Enforce allowed first-party
routing, limits and no unexpected redirects; keys/provider credentials/signing capability cannot enter child env,
models, files, transcripts or responses. No global-credential or unsigned/local-tool fallback after denial.

Trusted host/session evidence, not a prompt or local directory, establishes the supported boundary. Missing origin,
sandbox/provider qualification or stale context remains unavailable, with safe reasons. Component qualification
uses actual participants and cannot open the incomplete live cohort.

## Acceptance criteria

- [ ] Actual current-use/signing integration permits only the exact bounded operation under current Agent,
  initiating authority, Team/Repository/context and qualified session/host constraints, without exposing credentials.
- [ ] Revoked/changed credential, direct Permission, delegation, enrollment, Team association or context denies
  the next use despite an old snapshot/signature/receipt. Revoke/regrant does not restore an old admission epoch.
- [ ] Real grant/target writers and use admission serialize on PostgreSQL across direct, worker and broker paths;
  unsupported/unfenced paths cannot be enabled by a cached allow or metadata declaration.
- [ ] Wrong holder/session/host, forged context, arbitrary URL/request, scope expansion and provider fallback deny
  before effect/signing. Exact current selection rejects late predecessor material in either arrival order.
- [ ] Actual protected signing and downstream use are independently observed, including restart, hold and stale
  completion. Already-admitted behavior is bounded honestly rather than described as recalled by DB rollback.
