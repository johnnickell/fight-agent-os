# Explain usage and time in Workflow detail

## Outcome

Humans can explain the usage and timing values already shown in the sessions Dashboard through independently loaded
attribution and category breakdowns, without confusing incomplete measurements with zero or shared account balance.

## Scope

- In scope: Existing Workflow detail and Repository-summary drill-down integration, safe source/provenance and
  category breakdowns, independent load/failure states, typed queries and existing live/current-authority composition.
- Out of scope: Another Dashboard/shell, duplicate metrics/projection/accounting policy, provider refresh, quota
  sources, forecasting, raw tool/session inspection, billing and budget/limit mutation.

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Explain recorded usage | N/A — read-only | Existing bounded Workflow/Repository/phase usage and attribution | Existing committed projection notifications only | Inspectable source, identity, quantities and partial coverage |
| Explain known timing | N/A — read-only | Existing interval/category breakdown, gaps and as-of provenance | Existing committed projection notifications only | Distinct wall/active/queue/interruption/human-wait facts |
| Reconnect or change scope | N/A — authorized durable reload | Current exact target, generations and source/projection freshness | Existing safe live transport only | Truthful fresh/stale/unavailable detail without replay or effects |
