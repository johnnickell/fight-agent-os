# Browse effective instructions in the repository Dashboard

## Outcome

An authorized human can inspect the designated checkout's recognized root instructions from the existing repository
Dashboard: understand effective/shadowed state, open one exact file and inspect concise Git/provenance details.
Unavailable or unsafe access is explained without a repository tree, alternate checkout or implicit repair.

## Scope

- In scope: Production recognized-file list and single-file read-only viewer, exact typed query integration,
  readable effective/Git/availability/provenance details, authority fences and useful accessible states.
- Out of scope: New Dashboard/context resolver, general file browser/terminal/IDE, editor/diff/save/delete,
  browser assistance, publication, sync/fetch controls and persistent private browser storage.

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Enter instruction inspection | N/A — navigation/read | TASK-00430's current authorized metadata and availability | N/A — ordinary reads only | Recognized-root list and truthful effective/Git state |
| Open one recognized file | N/A — read-only | Exact current permitted content/digest/provenance from TASK-00430 | N/A | One inert bounded body with technical details, not a draft or provider input |
| Inspect an unavailable target | N/A — read-only | Safe denied/stale/unsafe/conflicting/offline reason and existing permitted next action | N/A | Actionable refusal without automatic relink, fetch or another checkout |

## Validation and permissions

Extend TASK-00107's existing repository selection/context workspace through TASK-00430, not a parallel page shell,
context authority or checkout selector. Reuse frame/theme/API/authority components; no demo-only endpoint or gallery.
Exactly five names are recognized: `AGENTS.override.md`, `AGENTS.md`, `AGENTS.MD`, `CLAUDE.md`, `CLAUDE.MD` at the
designated root. List recognized files only, represent safe missing/empty state, and open one file at a time. No
recursive tree, arbitrary path entry, parent/user instruction body, `.pi` resources or unrelated file navigation.

Render the server's qualified effective/override/unsupported explanations rather than recomputing Pi precedence
or inferring authority from prose. Ignored or untracked files can remain effective; explain publication limitations
without calling them generated or ineffective. Show observed branch/commit and synchronization freshness honestly.
No remote evidence means unknown/not checked, not up-to-date. Reads never start fetch/sync or an Agent session;
current discovery does not imply an existing session reloaded instructions.

Present concise status by default and bounded digest/encoding/size/context/Runner/provenance behind readable details.
Do not expose unnecessary identifiers, absolute personal paths, storage locators, credentials or raw errors. Render
source as inert text/Markdown without active HTML, remote resource loads, executable links or automatic tool/model
invocation. No source content enters URL/history, logs, analytics, retained debug snapshots or a disclosure request.

Use sole current `/api/v1/me` and the shared exact permission evaluator for guarded loaders/outlets and actions;
the server remains authoritative on every metadata/content request. View context is not View instructions. Viewing
instructions does not confer Update, AI-use, Publish or Sync. A safe denial must not reveal hidden Repository/file
existence or be converted into an authentication/refresh loop. Only normal existing owner controls may offer a
permitted next action; no relink/repair or path/branch substitution occurs from inspection.

Scope volatile decoded data and request generations to authentication, Workspace/Repository, current designated
Checkout/Worktree/context and selected filename. Switching file or scope retires the old body before showing the
new target. Fence late successes and errors after permission loss, restriction/context change, logout or newer
requests; abort alone is insufficient. No-store transport, private-cache invalidation and no persisted browser
business state apply to list metadata as well as content. Refresh/reconnect may obtain a new authorized observation,
not silently preserve old authority or rebind an existing context/session. Never replay a mutation.

Preserve distinct loading, empty/missing, failed, denied, stale, unsupported, unsafe, conflicting and unavailable
states. Clear private material when current authority ends; an offline/stale label does not authorize retaining
revoked content. Keep surrounding permitted Dashboard functionality usable when this section cannot load.
Keyboard selection, focused status/error recovery, clear headings and technical-details disclosure must work on
narrow/wide light/dark layouts, at reflow/zoom and with applicable reduced-motion preferences.
