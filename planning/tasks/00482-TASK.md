# Enroll isolated operational storage with enforced physical limits

## Outcome

Explicitly authorized installation operations provide private operational storage and enforced resource allocations
without consuming protected Artifact storage or silently overflowing the host. This approved slice B of
[TICKET-00117](../tickets/00117-TICKET.md) removes actual storage/isolation blockers, not a proof-only storage demo.

## Scope

- In scope: Existing private storage integration, isolated namespaces/credentials, collection/control/live/archive/
  temporary allocations, physical measurement/enforcement, bounded readiness/restart, exact version/security/license
  qualification and explicit storage-copy/backup limitations.
- Out of scope: Another storage stack, collector/queue design, archive format/verification, backend ingestion logic,
  autonomous retention, preservation/purge policy, unrestricted backup or service activation by preflight.

Consume TASK-00481's exact target/authority inputs and TASK-00374's installation-owned private SeaweedFS capability.
Extend that same installation, not a new Compose project or the completed TASK-00072 browser prerequisite chain.
Separate operational indexes/chunks, archives and Artifacts by actual credentials/namespaces/resource accounting.
Qualify supported S3/version/conditional-write and removal behavior against exact pinned versions and provenance/
security/license obligations; documentation or an ETag is not data-integrity evidence or operational acceptance.

Implement and directly verify physical allocation boundaries from
[WF-038](../wayfinder/tickets/WF-038-define-log-collection-and-failure-recovery.md) and
[WF-039](../wayfinder/tickets/WF-039-define-searchable-retention-and-verified-archives.md): runtime-source targets,
2-GiB destination queues/4-GiB combined, 5-GiB collection total including the 16-MiB control journal and 256-MiB rejected
material; archive 50-GiB admission/64-GiB physical including catalog, versions and compaction; temporary aggregate
4 GiB including staging/indexes/residuals. Live WAL/index/chunk/compaction and shared-service headroom need explicit
finite measured allocations. Native collector settings remain TASK-00455/00457/00458's responsibility; expose usable
storage enforcement without waiting for their completed collectors or the archive writer.

Logical bucket quotas, monitored scratch, read-only mounts or separate prefixes alone do not prove physical hard
isolation. Qualify actual supported mechanisms and shared fault limits. Count versions, delete markers, orphaned/
uncertain writes and delayed reclamation until owning tools establish disposition. Distinguish logical deletion from
physical freed space. Missing enforcement or provider guarantees block enrollment and return to the existing owner;
do not invent a bespoke queue/proxy or silently weaken retention/holds/DEBUG coverage.

Storage may be prepared before consumers are enrolled; missing consumers are not healthy or qualified. Preserve
existing named volumes/credentials/Artifact data and narrow secret mounts. Explicit start/update/restart/recovery
instructions identify owned resources and stop conditions. Expose bounded safe capacity facts to existing status
owners. Record supported versions/backups and unsupported erasure/restore routes: local-only storage cannot survive
host loss, and restoring bytes cannot reconstruct grants, holds or purge authority. Runtime state belongs under
ignored `var/`; `.runs/` remains scratch, not a service dependency.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Prepare private operational allocations | Explicit authorized installation/storage operation | Current target, ownership, capability and physical headroom | No invented Workflow event | Narrow isolated durable storage in the existing installation |
| Inspect pressure and residual bytes | Read-only owning tools/status inputs | Actual allocations, versions, physical use and unknown leftovers | Observation only | Honest bounded facts without object contents/credentials |
| Restart or recover owned storage | Explicit bounded owner operation | Original resources and actual storage outcome | Existing required installation facts only | Preserved qualified data or explicit unsupported/partial recovery |

## Validation and permissions

Consume existing storage/installation authority, never READ_LOGS or a bucket name as a grant. Keep all storage private;
no browser/Agent/PHP-request administration, public object redirect, raw environment dump or arbitrary path traversal.
Follow ADRs [0001](../adr/0001-application-ownership-and-orchestration.md) and
[0002](../adr/0002-postgresql-consistency-and-durable-effects.md); runtime/tooling observations do not mutate business
policy. Every privileged effect and destructive qualification needs separately bounded target/resource/cleanup authority.

## Acceptance criteria

- [ ] Actual private credentials/namespaces/physical allocations isolate operational roles and existing Artifacts;
  no second stack, public storage access or implicit privilege grant is introduced.
- [ ] Real storage tools establish enforced limits, safe failure at exhaustion and truthful residual/reclamation
  accounting including versions/compaction; logical caps alone cannot pass.
- [ ] Exact S3/storage/runtime identities and security/license/provenance evidence support intended consumers;
  unsupported native guarantees block activation rather than quietly changing the contract.
- [ ] Bounded authorized restart/recovery preserves qualified data and reports backup/local-loss limitations without
  reconstructing authority from stored bytes or claiming 50 GiB guarantees 90 days.
- [ ] Direct owning-tool qualification, relevant owned integration behavior and full `./bin/build` pass with actual
  resource/target receipts, warnings and unverified failure classes disclosed.

## Verification and evidence

Use approved isolated non-sensitive objects and owned allocations; inspect actual mounts, secrets exposure, volumes,
S3 operations, competing allocations, version residues and physical use. Exercise bounded restart, full storage and
removal only with explicit authority, never unrelated/global cleanup. Test owned application adapter behavior where
introduced; qualify storage/configuration/tooling directly, not product tests of vendor internals/migrations/wrappers.
Record exact images/platform, bytes before/after, shared fault boundaries and unsupported backup claims. Run focused
repository wrappers and full `./bin/build`; full retained-history fit belongs additionally to TASK-00487.
