# Operate Team and roster administration in the browser

## Outcome

A currently authorized Super Admin can manage real Repository-linked Teams, explicit defaults and named-Agent
rosters through accessible browser views and confirmed safe operations. The UI distinguishes no data, denied,
busy, stale, unavailable and uncertain results without granting authority or claiming Agent work occurred.

## Scope

- In scope: Team list/detail/create/name forms, Repository associations/default/alternatives, safe roster and
  current impact views, confirmed idle-transfer/unlink flows, expected revisions and current-authority handling;
  integration with actual named Agents from TICKET-00063 and existing client/API owners.
- Out of scope: Another Agent-creation or credential UI, raw secret/operation internals, template editor,
  selector/Workflow start, autonomous work, client-side grants, persistent browser drafts or runtime enablement.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Establish/manage a Team | TASK-00251/00252's existing protected create/name/link/default commands | Current authorized Team/Repository choices and revisions | Only server-owned committed facts | Confirmed Team/association/default changes, not a grant or start |
| Inspect roster and impact | N/A — read-only | TASK-00253/00254's safe roster, exact membership and commitment/impact facts | N/A | Truthful named-Agent membership and safe unavailable/hold reasons |
| Confirm idle transfer/unlink | TASK-00254's exact expected-state operation after explicit review | Fresh source/destination, affected references/default and safe impact | Existing server facts only after actual commit | One confirmed safe change or refusal; no local optimistic claim of transfer |
| Recover denial/conflict/uncertainty | Explicit refetch/original-outcome inspection, not automatic mutation retry | Current authority and authoritative original outcome | No success fact invented by presentation | Stale confirmation discarded; renewed human decision only after reconciliation |

## Validation and permissions

Use the actual authenticated frame and one current `/me` authority owner under ADR 0003/0004. Gate protected
routes, loaders, controls and action handlers by exact management Permissions, never role names or cached Team
membership. Every server operation still checks fresh authority, actor/target/scope and expected revisions. A
revoked Permission denies even if a control was visible. Retire private responses on auth/context invalidation;
late successes/errors cannot restore an older principal, roster, default or confirmation.

Forms hold only bounded volatile input. Do not store business drafts, roster/authority projections, confirmations
or operation state in browser storage, history, URLs, base HTML or telemetry. Classify safe navigation parameters
explicitly rather than putting forms into intended-route restoration. No raw credentials, sink/lease/claim/key
internals, protected holder handles, private tool inputs or transcripts appear in UI, diagnostics or evidence.
Use existing safe transport/validation errors and applicable no-store behavior; no new token or workflow cache.

Make initial Repository/default choice explicit. Show default versus alternatives without implying those Teams
have every required Agent or grant. Link to the existing named-Agent creation owner where authorized rather than
creating a second provisioning route. A Team can be inspected empty; an actual named Agent is required to qualify
the roster/transfer journey. Display membership independently of issued/delivered/activated/usable credential
states from their existing owner; do not equate an idle or listed Agent with current authorized tool use.

Transfer/removal confirmation names exact source/destination and safe impact. Refuse stale or busy/unknown results
without a force option. Waiting for PR review/merge alone is not a busy signal; use actual authoritative reasons.
Do not detach a retained Agent to zero Teams or silently replace a default. On uncertain mutation, preserve honest
feedback and inspect the original outcome before another attempt; disconnect, refresh or 401 recovery never
replays a business mutation automatically. Browser teardown loses draft input, not server-owned operation truth.

Use existing production components with semantic labels, focus management, keyboard interaction, error association
and readable narrow/wide/light/dark states. Color or animation alone cannot identify default, busy, denied or pending
status. Scope visual exploration to this journey if needed; no new design system or generic administrator console.

## Acceptance criteria

- [ ] Through real authenticated routes a currently authorized administrator creates a Team on a registered
  Repository, manages explicit associations/defaults and sees complete safe list/detail/roster information.
- [ ] Actual named Team-bound Agents from TICKET-00063 can be inspected and a genuinely idle eligible Agent can
  transfer through the protected server operation; unsafe unlink/removal and busy/unknown cases refuse honestly.
- [ ] Empty, loading, forbidden, invalid, stale, busy, unavailable, disconnect and uncertain outcomes are distinct;
  stale confirmation needs refresh/review and late responses or auth changes cannot restore protected UI state.
- [ ] Controls and direct requests both deny lost authority. No client grant, optimistic completed transfer,
  automatic mutation retry, secret disclosure or persisted business draft is introduced.
- [ ] Keyboard/focus/error and responsive visual evidence covers the real authorized and denial journeys, without
  claiming Workflow dispatch, live Explorer work or all-role operational acceptance.
