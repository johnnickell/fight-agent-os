# Guard custom-role permission delegation at every entry path

## Outcome

An installation operator with `MANAGE_ROLE_PERMISSIONS` can add or remove only eligible non-global permissions on a custom role: each actual entry adapter authenticates the actor and admits permission and target/scope, while the qualified package enforces custom-role and tier invariants. Configured bus dispatch and registered handler-owned persistence/audit preserve the business outcome without a second blanket Application gate.

## Scope

- In scope: `PUT`/`DELETE /api/v1/roles/{roleId}/permissions/{permissionId}` FQCN Actions; actor permission/target-scope admission at every actual entry adapter; qualified package custom-role/tier/reference checks through `GrantPermissionToCustomRole`/`RevokePermissionFromCustomRole`; confirmed/audited mutations, safe View/OpenAPI, stale/race and invalidation tests.
- Out of scope: Managed-role mutation, permission CRUD, custom/admin assignment to users, delegation of `SUPER_ADMIN_ONLY` or unknown/null-tier permissions, workspace-scoped rights without separate target policy, HTTP-only enforcement.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Grant permission | Package `GrantPermissionToCustomRole` through configured CommandBus after entry admission | Resolve actor/custom role/permission eligibility | Package grant event and safe audit | Only explicitly allowed `ADMIN_SAFE` membership commits |
| Revoke permission | Package `RevokePermissionFromCustomRole` through configured CommandBus after entry admission | Resolve actor/custom role/existing association | Package revoke event and safe audit | Eligible custom membership removed, managed role untouched |

## Validation and permissions

Require exact authoritative `SUPER_ADMIN_ONLY` `MANAGE_ROLE_PERMISSIONS`, authenticated caller and target/scope admission at every actual HTTP, Console or future Agent entry before configured bus dispatch. HTTP declares permission once on its Action. Follow the [canonical timing contract](../../docs/engineering/STANDARDS.md#entry-admission-and-authorization-timing): no duplicate blanket Application gate, exposed raw-bus entry or ordinary revocation/commit serialization. TASK-00126 must first prove the tagged package rejects managed target roles, `SUPER_ADMIN_ONLY` permissions, null/unmanaged tiers, missing references and concurrent policy drift. Delegate those intrinsic checks to the package rather than copying them into consumer handlers or adapters; never treat a stored tier label or absence of old handler permission checks as authorization. If the release does not guarantee safe eligibility, **do not register grant routes or permit calls**; return to human policy/owner review instead of relying on an HTTP-only fallback. Confirm the Role/Permission target and record outcome/actor without secrets. Required audit belongs in explicit registered-handler coordination with persistence on one shared generic transaction; qualify actual package support, not a consumer transaction decorator, nested transaction or post-commit audit subscriber. Future scoped admins require a separate scope model and are not implicitly global.
