# Guard custom-role permission delegation at every entry path

## Outcome

An installation operator with `MANAGE_ROLE_PERMISSIONS` can add or remove only eligible non-global permissions on a custom role: Agent OS Application authorizes actor and scope, while the qualified package enforces custom-role and tier invariants without duplicating old handler permission checks.

## Scope

- In scope: `PUT`/`DELETE /api/v1/roles/{roleId}/permissions/{permissionId}` FQCN Actions; shared Agent OS actor permission/scope checks for every entry adapter; qualified package custom-role/tier/reference checks through `GrantPermissionToCustomRole`/`RevokePermissionFromCustomRole`; confirmed/audited mutations, safe View/OpenAPI, stale/race and invalidation tests.
- Out of scope: Managed-role mutation, permission CRUD, custom/admin assignment to users, delegation of `SUPER_ADMIN_ONLY` or unknown/null-tier permissions, workspace-scoped rights without separate target policy, HTTP-only enforcement.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Grant permission | `GrantPermissionToCustomRole` through checked service | Resolve actor/custom role/permission eligibility | Package grant event and safe audit | Only explicitly allowed `ADMIN_SAFE` membership commits |
| Revoke permission | `RevokePermissionFromCustomRole` through checked service | Resolve actor/custom role/existing association | Package revoke event and safe audit | Eligible custom membership removed, managed role untouched |

## Validation and permissions

Require exact authoritative `SUPER_ADMIN_ONLY` `MANAGE_ROLE_PERMISSIONS` in the early route gate and shared Agent OS Application actor/scope service used by every HTTP, console or future Agent adapter. TASK-00126 must first prove the tagged package rejects managed target roles, `SUPER_ADMIN_ONLY` permissions, null/unmanaged tiers, missing references and concurrent policy drift. Delegate those intrinsic checks to the package rather than copying them into the Application service; never treat a stored tier label or absence of old handler permission checks as authorization. If the release does not guarantee safe eligibility, **do not register grant routes or permit calls**; return to human policy/owner review instead of relying on an HTTP-only fallback. Confirm and audit role/permission target, outcome and actor without secrets. Future scoped admins require a separate scope model and are not implicitly global.

## Acceptance criteria

- [ ] Shared Application actor/scope authorization and qualified package custom-role/`ADMIN_SAFE`/reference invariants jointly admit only eligible grants; unknown/global tiers and managed targets fail closed.
- [ ] Route attribute plus shared Agent OS Application actor/scope boundary protect every entry adapter; package-enforced intrinsic policy rejects forged role/tier state without duplicating handler permission rules.
- [ ] Concurrent grants/revokes/managed-policy changes preserve package reference/transaction rules and atomic audit/authority invalidation.
- [ ] Exact FQCN Actions/Views/OpenAPI remain safe and `./bin/build` plus focused PostgreSQL/HTTP/permission checks pass with warnings.
