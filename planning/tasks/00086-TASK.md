# Complete Wayfinder decisions and handoff readiness

## Outcome

Authorized planners can revise Wayfinder intent, record ordered stable decision points, synthesize ticket resolutions, author the recommended frontier and explicitly close tickets and maps only when the accepted evidence and handoff invariants are satisfied.

## Scope

- In scope: Map destination/done condition/notes/exclusions/linked ticket references/authored frontier revisions; WayfinderTicket question/boundary/preferences/decision-point/resolution revisions; stable ordered DecisionPoint children; semantic complete-value events; preview/readiness explanations; explicit close/reopen ticket and close/reopen map commands/events; unresolved/excluded/delegated fog; approved EPIC/TICKET/decision handoff links; expected versions/idempotency/audit provenance; detail/history/readiness/API/Permissions; PostgreSQL projection/constraint evidence.
- Out of scope: Generic status setters, automatic closure, ResearchNote/Prototype roots, general evidence/criteria model, archive/restore, dependency-edge mutation, EPIC/TICKET/TASK implementation, queue calculation, Markdown import, browser conversation history or AI planning.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Revise Wayfinder intent | Section/child-specific revise commands | Compare normalized current section/decision and expected version | Semantic section/child event | Complete normalized changed value appends without generic document or patch events |
| Accept/revise a decision point | Add/revise/retire/accept decision command | Preview ordering, required state, sources and downstream impact | `DecisionPointAdded`, `DecisionPointRevised`, `DecisionPointAccepted` or equivalent | Stable child identity/history and current projection advance atomically |
| Close a Wayfinder ticket | Explicit close command | Explain unresolved required decisions and resolution readiness | `WayfinderTicketClosed` | Synthesized resolution and closure append only when no required decision remains unresolved |
| Close a Wayfinder map | Explicit close command with human confirmation | Explain ticket outcomes, remaining fog, exclusions/delegations, frontier and handoff | `WayfinderMapClosed` | Map closes only with all tickets closed, no unresolved fog/frontier and approved handoff |
| Reopen closed Wayfinder work | Explicit reasoned reopen command | Preview retained decisions/resolution/handoff | Type-specific reopened event | Prior history remains and revisions may continue without erasing closure |

## Validation and permissions

Use intent-specific commands and semantic past-tense events carrying complete normalized section/child values. Never emit keystroke, Markdown-diff, JSON-Patch or `PlanningDocumentUpdated` events. Preserve stable DecisionPoint identities and explicit ordering; retirement/acceptance is historical, not deletion. Stale expected versions report safe intervening facts without merge.

Map frontier selection is authored, not inferred from calculated eligibility. A required decision needs explicit accepted/delegated/excluded disposition under the closed schema. A ticket cannot close without a synthesized resolution and no unresolved required decision. Closing does not delete its question, decisions or provenance and never closes the map automatically.

Map closeout transactionally revalidates every owned ticket, remaining fog disposition, exclusions/delegations, authored frontier absence and one approved handoff link. All tickets must be closed. Handoff identity must reference an authorized current Planning decision/record without granting authority to it. A human always confirms judgment-bearing map closure; confirmation is actor/scope/version/content-bound and short-lived. Reopen requires reason and permission, retains history and does not reopen children automatically.

Commands authenticate actor and enforce separate revision, decision, closure and reopen Permissions scoped to Repository. Agents may perform authorized revisions but never impersonate a user or satisfy mandatory human confirmation. Current constraints/readiness projection and stream append commit together. APIs use one Action per interaction and safe Views; no instruction content, conversation transcript, hidden Repository or raw payload leaks.

## Acceptance criteria

- [ ] Maps and tickets revise typed/narrative sections through section/child-specific commands and semantic complete-value events only.
- [ ] Decision points retain stable identity, explicit order, disposition, actor/reason/time and full revision history.
- [ ] Authored frontier remains distinct from calculated eligibility and cannot survive map closure.
- [ ] Ticket closure requires synthesized resolution and no unresolved required decision; child closure never closes its map.
- [ ] Map closure revalidates every ticket, fog disposition, exclusion/delegation, frontier and approved handoff atomically.
- [ ] Mandatory human confirmation cannot be replayed by an agent, different actor, stale map version or changed handoff.
- [ ] Reopen is reasoned and append-only and never rewrites closure or cascades to children.
- [ ] Stale/idempotent/concurrent commands preserve one semantic history and equivalent projections.
- [ ] Separate revision/decision/close/reopen Permissions and safe APIs are enforced server-side.
- [ ] Focused behavior/PostgreSQL/concurrency/API tests and the canonical build pass with fresh evidence.
