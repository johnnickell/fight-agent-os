# Deliver Project registration, selection, and context workspace

## Outcome

Authenticated users can enter a permission-aware Project-scoped Planning route, register/select/switch visible Projects, manage designated checkout links and inspect or revise permitted context configuration/conflict choices without carrying stale authority across URL scope or client state.

## Scope

- In scope: Production React route/layout/page/services/components from accepted handoff; visible Project list/search/empty state; target Project registration/source confirmation; URL-owned selection; registration/source/lifecycle/reconciliation summaries/actions where TICKET-00024 exposes them; designated Checkout/Worktree/Host selection/relink/availability; context summary/revision/mode/instruction provenance/conflicts/warnings/projection diagnostics; configuration history/preview/revise/restore and session-choice forms where permitted; typed API mapping; query cancellation/cache keys by scope/revision; permission-aware navigation/actions; responsive/state/component-catalog evidence.
- Out of scope: Filesystem browser beyond approved roots, raw instruction contents/editing, Planning hierarchy/artifact UI, browser Agent conversations, model/Pi sessions, migration import, local path guessing, client authorization, generic configuration JSON and automatic context refresh/fallback.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Register/select Project | Dispatch exact TICKET-00024 registration command when authorized; selection is navigation | List visible Projects and get registration/source/lifecycle | TICKET-00024 event only on registration | URL scope changes after server success; prior Project cache/context does not become current |
| Designate/relink checkout | Dispatch exact preview/confirm/designate/relink command | Query approved candidates/evidence/availability/current link | TICKET-00024 semantic event | Confirmed physical link changes; UI never invents identity from path/name |
| Inspect context | N/A — read-only interaction | Resolve safe context summary, provenance, conflicts, revision and availability | N/A — read emits no event | Current facts/warnings and permitted actions display without instruction contents/secrets |
| Revise/restore configuration | Dispatch exact TICKET-00025 semantic command | Preview validation/diff/impact/history/current revision | TICKET-00025 event | Accepted revision/rollback updates server state; stale proposals remain unapplied |
| Resolve session conflict | Dispatch exact narrowing choice where supported | Preview structured sources/recommendation/authority effect | TICKET-00025 event | Exact choice binds only accepted scope and never widens authority |

## Validation and permissions

Project scope is canonical URL state using stable safe route identifiers, not display name/path. On switch, cancel/ignore in-flight old-scope results, key API cache by authenticated principal/Workspace/Project/revisions, clear transient forms and refetch server-authoritative principal/scope/context. Never render previous Project data under a new URL or carry a context token implicitly.

Forms use typed TICKET-00024/25 API Views and exact commands/previews against expected revisions. Registration uses the target `RegisterProject` contract through the server entry's configured bus and
adapter-generated typed `ProjectId` in a void command. Successful acknowledgement can carry that known ID;
no identity-recovery fetch or result DTO is needed. On lost response, refresh/fresh authorized list/detail reveals
authoritative state; a new attempt may conflict on slug/source. Do not replay an immutable original response.
Physical link/relink keeps ADR 0005's separate exact-operation result/status and confirmation flow. Registration
grants neither access, physical linking, Planning cutover nor execution. Names here are target contracts, not
claims that today's Repository runtime/routes/permissions/markers have already changed. Checkout candidate evidence shows only safe relative/display facts; no free-form path becomes authority. Context UI records paths/digests/provenance safely but does not load complete instruction text or parse prose. Configuration is closed typed fields, not arbitrary JSON.

Client visibility/disabled copy reflects current principal Permissions but every query/command remains server-authorized. Distinguish view, register, source/lifecycle, checkout, context, configuration revise/restore and conflict-choice authority. Unknown principal/scope fails closed. Do not infer role names or show hidden Project existence.

Cover loading, no visible Projects, no selection, registration validation/conflict, missing/ambiguous/unavailable checkout, archived Project, stale revision, context conflict/stale/offline, denied/not-found/partial/service unavailable and success. Do not silently refresh authority-bearing context; changed context prompts the accepted new-binding flow. Offline/cached registered data is visibly stale/read-only and cannot enable actions.

Use existing shared API client/error/current-principal/routing/component/theme boundaries. Production pages coordinate; forms/components do not encode Domain policy. Warn before leaving dirty forms; no autosave/persisted drafts. Accessible status, dialog confirmation, focus restoration and narrow/wide layout follow accepted handoff.
