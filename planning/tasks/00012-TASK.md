# Establish guarded PostgreSQL persistence through managed authority

## Outcome

Agent OS has a guarded PostgreSQL migration and integration-test foundation on the canonical shared transactional connection, proven through complete production adapters for the Fight Access Control permission, role, and role-permission authority contracts.

## Scope

- In scope: PostgreSQL local/test service and repository wrappers; externalized configuration; Doctrine DBAL/ORM/Migrations wiring selected by the ADR; migration/status/reset workflow; hard test-target guards; deterministic isolation; authority schema; `PermissionRepository` and `RoleRepository` adapters; role-permission membership, managed catalog, pagination, expected-state replacement, reference fences, and PostgreSQL contract/concurrency tests.
- Out of scope: Users, refresh sessions, grants, audit/durable intent, feature policy reconciliation, HTTP/UI behavior, request-time migration, SQLite evidence, and the complete quality gate.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Migrate a database | N/A — migration tooling | Inspect configured database identity and migration status | N/A — no domain event | Approved target advances through versioned migrations outside requests |
| Persist managed authority | Package policy commands will use repositories later | Add/find/list managed permissions and roles and resolve memberships | Preserve package event ownership; no adapter event | Exact authority state persists with unique names/IDs and valid references |
| Replace or remove authority | Existing package behavior invokes repository replacement/removal | Compare expected revisions/state and assignment/reference fences | Package events only for successful package behavior | One valid change wins; stale or referenced removal fails safely |
| Reset integration state | N/A — guarded test tooling | Verify explicit test mode/database identity | N/A — no domain event | Only a known test database is reset and remigrated deterministically |

## Validation and permissions

Use snake_case tables/columns and database constraints for stable IDs, canonical names, managed identity, revisions, membership uniqueness, and references. Adapters implement package interfaces directly and reconstruct package entities rather than returning persistence records. Pagination and ordering must match package contracts.

Role and permission replace/remove operations must implement the ADR-selected transaction-duration fences and expected-state comparisons. Competing reconcile, replace, membership, and remove operations must produce controlled outcomes. Map known uniqueness/reference/stale conflicts without exposing SQL, credentials, or internal database identifiers.

All production and tests use the same connection under `DoctrineTransactionalUnitOfWork`. Integration tooling must require explicit test mode, allowlisted test naming/credentials, and refuse known development/production hosts or names before any destructive operation. No schema changes occur during requests.

No user-facing permission applies. Database/schema/tooling and authority adapters are authorized; feature policy, identities, and endpoints are not.
