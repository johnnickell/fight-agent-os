# Qualify supported atomic notice coordination

## Outcome

Qualify a supported public package contract that can commit each accepted email-change transition and its required
Agent OS old-mailbox notice intent atomically. Record the accepted ownership/transaction design and exact chosen
release, source and Composer lock before dependent implementation or exposure; a documented missing seam is a
hold, not completed qualification.

## Scope

- In scope: Current source/contract inspection; precise transition/recipient/attribution handoff; accepted ADR 0002
  supplement; any authorized consumer manifest/lock adoption and compatibility qualification.
- Out of scope: Upstream implementation or release without separate authority, vendor patches, notice persistence
  and sending, new email-change policy, product endpoints, provider enrollment or a generic outbox platform.

## Validation and permissions

Follow [ADR 0001](../adr/0001-application-ownership-and-orchestration.md) and
[ADR 0002](../adr/0002-postgresql-consistency-and-durable-effects.md). The currently inspected lock is Access
Control v0.5.0 at `46ffcf75f1e14dbc5b58a5049e05a600ce5cf8a0`, not a selection mandate for implementation.
`RequestEmailChangeHandler` and `AuthenticationService::confirmEmail()` each commit internally, then publish.
The request event carries the new destination; the confirmation event carries only User ID/time, not the old
recipient or exact generation. No supported atomic old-mailbox notice seam has been established from these APIs.

Inspect the actually selected public contract. Required package state, notice intent and audit use one canonical
`DoctrineTransactionalUnitOfWork` on the shared DBAL connection and roll back together. Identify exact in-transaction
facts, complete expected-state/locking requirements, invocation paths and failure/acknowledgement semantics.
After-commit subscribers, outer nested transactions, transaction-adapter tricks, audit/repository side effects,
reflection, copied handlers or provider calls inside the transaction cannot manufacture support. If unavailable,
stop for separately authorized owner amendment, tagged release and deliberate consumer lock update.

The package retains User/reservation/grant/session authority and its sole credential queue. Agent OS owns only
these two informational effects and demonstrated cross-boundary coordination. The supported boundary must cover
all enabled request/confirmation entry paths, not just one HTTP wrapper. No public standalone enqueue is allowed.
Bind separate stable notice identities to exact accepted change/stage, with immutable original-recipient and
attribution data. A later user-email lookup or time-only correlation is insufficient under successive changes.

Keep requester, target and later confirmation proof distinct. A bearer confirms possession of the purpose-bound
secret; do not infer that the original administrator confirmed or identify a natural person beyond package
proof. No credential/digest/ciphertext/link belongs in notice state or audit. Define minimum personal data,
retention dependencies, safe status and original-outcome recovery without claiming provider delivery or an
idempotent business command the package does not supply. Post-commit publication failure does not prove rollback.
