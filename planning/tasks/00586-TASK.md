# Retire Jev from the active Fight Pi harness

## Outcome

Ordinary Fight Pi and Build sessions start and work without Jev enrollment, screening prompts or a provider
preflight. The [Build child launcher](../../harness/pi/src/observation/run-stage.py) currently invokes a
screening preflight even when Jev is optional, and a failed preflight can block dispatch. Retiring that
dependency simplifies startup and reduces maintenance for everyday work.

## Scope

- Inventory actual callers of the Jev evaluator, file-screening extension, commands, agent-facing tools,
  prompt guidance and launch preflight. Verify a native parent and normal Build child with screening disabled.
  Trace any shared workflow role, session identity, worktree or observation behavior before removing its supplier.
- Remove Jev-only registrations, package wiring, provider setup and screening preflight. Remove superseded
  implementation, dependencies, tests and active guidance after verifying replacement paths. Use native Pi tools
  for file discovery and access, and preserve the independent deterministic tool policy and current role authority.
- Qualify fresh and previously enrolled installations and supported native and SDK child paths. An old enrollment
  must not gate startup or trigger provider traffic. Preserve existing sessions, transcripts, account settings,
  historical receipts, spend records and unresolved liabilities. Keep shared OpenRouter configuration intact.
- Record any proven live consumer that prevents a safe removal and resolve its native or existing supplier before
  removing that route. If a consumer still genuinely needs Jev, report the exact dependency and keep its scope
  separate from the verified removable paths.

## Acceptance criteria

- [ ] Ordinary Fight parent and representative Build child sessions start and perform authorized work without Jev
  credentials, enrollment, tooling or provider calls. Cover clean and previously enrolled local fixtures.
- [ ] Active instructions, tools and launch paths have no Jev-only requirements. Independent policy, workflow role
  binding, worktree selection, passive child observation and native file and shell behavior remain qualified.
- [ ] Retired code, dependency and documentation paths are removed once surviving callers are accounted for.
  Retained state and historical evidence stay protected. Active sessions and shared provider credentials are preserved.
- [ ] Verify normal entry points directly, run applicable Harness and canonical gates, and record supported
  runtime capabilities, tested version and separate Review/QA status.
