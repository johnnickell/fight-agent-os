# Compact the application header and standardize navigation controls

## Outcome

The delivered authenticated frame uses less vertical space and provides a familiar user-icon account menu,
compact icon-based appearance choices, and consistently named icon-supported navigation. Users can find account,
security and current-session sign-out controls without a large always-visible email/theme control area.

This is a bounded usability refinement of [TASK-00051](00051-TASK.md)'s existing frame and
[TASK-00050](00050-TASK.md)'s existing appearance controls, not a new account feature or design system.

## Scope

- In scope: Existing authenticated header/sidebar presentation; a user-outline icon dropdown; safe existing
  identity display and account/security/session links; existing current-session Sign Out action; Light/Dark/System
  icon choices; sidebar icons, Title Case labels and consistent wording; compact expand/collapse controls;
  accessible responsive interactions and production-backed visual evidence.
- Out of scope: Authentication/permission revalidation repair owned by [TASK-00505](00505-TASK.md); profile-photo
  upload, profile editing or new account/security/session operations; new permissions/routes, fake available
  operations, custom-theme installation, a replacement component library, or a broad application redesign.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Inspect account controls | N/A — local dropdown interaction | Existing sole principal's safe identity and route metadata | Local open/close/focus events only | User-icon menu reveals identity, account/security and independently permitted session links without a tall persistent header |
| Change appearance | Existing local theme selection | Existing preference/effective-mode store | Existing presentation preference and OS/storage notifications | Sun, moon and monitor choices select Light, Dark or System without affecting credentials or permissions |
| Sign out | Existing current-session logout via the coordinator | Existing logout result/state | Existing logout/invalidation signals | Same immediate local cleanup and truthful server-sign-out uncertainty; no new logout scope |
| Navigate or collapse the sidebar | N/A — navigation/presentation | Existing route manifest and shared permission evaluator | Existing navigation and local expansion signals | Icons supplement consistent labels; chevrons collapse/expand navigation with accessible names and focus behavior |

## Validation and permissions

Use a user-outline icon as the account-menu trigger, with an accessible name such as User Menu. Show the current
safe email/profile identity inside the menu, not as an always-expanded header item. Include Account & Security,
permitted Active Sessions navigation and Sign Out with appropriate icons. Only link to existing registered
routes; future operations retain their truthful unavailable presentation. No profile-photo upload or profile
editing is enabled by displaying identity.

Place appearance controls inside the account menu: sun for Light, moon for Dark and monitor for System, with a
clear selected state and accessible names. Show the selected preference, including System rather than pretending
that its effective light/dark result is a manual selection. Preserve OS-following, cross-tab appearance updates,
prepaint, storage-denial fallback and the existing appearance-only persistence policy. Retain the existing public
login/activation theme journey unless a shared selector change requires a compatible presentation adjustment.

Use consistent Title Case for frame/menu labels and corresponding shared route titles: Dashboard, Account &
Security, Change Password, Active Sessions, Users, Invite User, Invite Super Admin, Invitation Administration,
Light, Dark, System and Sign Out. Keep full Invitation Administration wording rather than mixing Administration
and Admin abbreviations. Render decorative icons next to the sidebar link text, never instead of that text.
Use double-left/double-right chevrons for collapse/expand rather than visible Close/Open words, while retaining
screen-reader names, expanded state and the established responsive drawer behavior.

Prefer the qualified React-Bootstrap dropdown/control mechanics and the existing semantic theme styles. Avoid
hover-only menus or a custom overlay framework. Keep icons self-contained and compatible with current CSP and
asset rules; no remote icon/font dependency. Preserve the sole principal cache and exact permission evaluator:
menu relocation does not create role-based bypasses or duplicate authority. The existing logout coordinator owns
cleanup, busy suppression and uncertain-server outcomes.

Aim for a single-row desktop utility header of roughly 56–64 CSS pixels at default text sizing, with the current
minimum 44-pixel control targets. Do not enforce a fixed height that clips enlarged text, long identity text,
focus rings or narrow-screen content. Move the account details and appearance choices out of the always-visible
row; do not achieve compactness merely by shrinking target sizes or hiding accessibility text.

## Acceptance criteria

- [ ] The authenticated header is visibly shorter than the baseline and normally one row on desktop, without
  clipping or horizontal overflow at narrow widths, zoom or enlarged text.
- [ ] A named user-outline icon opens an accessible menu containing the current safe identity, Account & Security,
  independently permitted session navigation and the existing current-session Sign Out action.
- [ ] Appearance uses compact sun/moon/monitor choices with readable/accessible Light/Dark/System names and an
  unambiguous selected preference; all existing theme lifecycle/fallback behavior remains intact.
- [ ] Every sidebar destination has an appropriate decorative icon alongside its label, and frame/account/sidebar
  labels and shared route titles use the accepted Title Case and consistent wording.
- [ ] Visible Open/Close words become compact directional chevrons with screen-reader names, expanded state,
  comfortable target sizes and correct wide-rail/narrow-drawer behavior.
- [ ] Menu and drawer controls support keyboard opening, traversal, selection, Escape, outside dismissal, focus
  return and visible unobscured focus; icons alone are not the only accessible indication of state or meaning.
- [ ] Permission variants, denied routes, missing/future account operations and uncertain logout remain truthful;
  no new authority source, endpoint, profile-photo capability or enabled unavailable action is introduced.
- [ ] Background session checks do not gain new dropdown/sidebar remount, route or scroll-reset behavior; preserve
  TASK-00505's accepted continuity contract when integrating after that repair.
- [ ] Production-backed component tests, narrow/wide light/dark/system and keyboard visual evidence, focused checks
  and `./bin/build` pass; independent Review and applicable QA accept the implementation separately.

decorative. If a behavioral defect is discovered, add its failing regression before repair. Do not add product
suite tests of Markdown, CSS source text, build configuration or tooling. Run focused client type/lint/tests,
production/catalog builds, browser/accessibility checks, planning validation, diff checks and `./bin/build`.
Record real browser/revision and Before/After evidence, automation limits and warnings; screenshots alone do not
constitute visual approval or universal screen-reader certification.
