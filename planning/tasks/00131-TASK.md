# Design the project-local audit skill

## Outcome

A project-local `audit` skill produces a bounded, evidence-backed assessment of owned code against accepted engineering standards, without replacing TASK review or making changes on the audited project's behalf.

## Scope

- In scope: Design `.pi/skills/audit/SKILL.md` from current Agent OS architecture, review and planning rules; compare the read-only Factory `skills/Fight-Audit-Skill.md` as a source rather than authority; specify scope intake, representative use-case tracing, counterevidence, sampling limits, severity, findings versus questions, and optional independently reviewable work-group recommendations. Update the [skill gap map](../../docs/engineering/SKILL_GAPS.md) for adopted/rejected choices.
- Out of scope: Production code changes, automatic planning records or PRs, PDF/Desktop output as a mandatory format, source repair, architecture acceptance, complete codebase certification, and Factory workflow imports.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Audit a selected boundary | N/A — read-only analysis | Inspect accepted standards, actual code and bounded tests/evidence | N/A | Deliver a traceable report with scope, findings, counterevidence, limits and proposed work groups, not new TASKs |

## Validation and permissions

Require an explicitly identified project and scope; distinguish observed behavior, incomplete inspection and suggested improvement. The skill cannot run destructive checks, alter another project or imply independent TASK approval. Proposed work routes through human-approved EPIC → TICKET → TASK planning or a standalone chore as appropriate. Keep source secrets and private data out of reports.

## Acceptance criteria

- [x] The skill states its intake, read-only authority, evidence format, stopping condition and handoff to existing planning, `architecture` and independent `review` without overlap.
- [x] Findings cite actual locations and violated local rules with practical consequences, counterevidence and feasible correction; unverified questions and sampling limits remain explicit.
- [x] Compare the Factory audit source and local standards with cited adopted/adapted/rejected decisions; do not copy Factory artifacts, commands or policy into Agent OS.
- [x] Directly validate references and a bounded sample audit walkthrough without adding product-suite tests of skills or tooling; refresh planning views and run `git diff --check` and `./bin/build`, reporting warnings and limits.

## Verification and evidence

Read current local standards/skills and the cited Factory source; walk one real scoped code path to demonstrate what is and is not a finding without modifying it. Check Markdown links and instructions directly, run planning validation, diff check and the canonical gate. Do not create an artificial failing product test of a skill.
