# Deliver guided Harness setup and diagnostics

## Outcome

A terminal-capable user can follow the existing versioned operator guide from exact Harness installation through
safe connection/profile setup, readiness, deliberate update/rollback and disconnection, with contextual Dashboard
help and read-only diagnostics that explain actual supported capabilities.

## Scope

- In scope: Harness extension of the existing authoritative operator-guide/read-only diagnostic journey,
  contextual Dashboard help links, safe copyable readiness/recovery results, supported Linux/macOS instructions,
  primary citations and last-verified platform/tool evidence integrated with actual preceding capabilities.
- Out of scope: Separate documentation/testing product, second guide/capability authority, automatic setup/repair,
  provider qualification or Agent creation, general shell training, browser Planning and database Planning cutover.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Check Harness setup | N/A — bounded read-only diagnostic | Actual package/mode, connection/origin, profile, protected-store and capability state | N/A — inspection creates no business mutation | Safe actionable ready/unavailable/unsupported/not-checkable results |
| Follow explicit setup/recovery | Existing exact install/connection/profile/lifecycle operations only when explicitly invoked | Guide revision, applicable platform/tool evidence, current original outcome | Existing owning facts only; reading guidance emits none | Human-authorized bounded mutation, never auto-enrollment or implicit repair |
| Find contextual help | N/A — authenticated bounded guide reads | Existing task-based guide sections and safe current capability Views | N/A | Dashboard links to one authoritative source with useful partial/offline states |
| Copy support diagnostics | N/A — deliberate safe representation/copy | Bounded current observations, source/revision and next action | N/A — no automatic upload | Secret-safe report with truthful freshness and limitations |

## Validation and permissions

Extend TASK-00075's single versioned guide and current capability presentation, using existing Harness and
credential owners' exact facts rather than duplicating a readiness registry. Explain each task's purpose, explicit
action, expected effects/result, read-only verification, original-outcome recovery/rollback limits and primary
vendor/distribution source. Include exact releases versus visibly mutable development, project trust, connection/
profile distinction, protected handles, live authority and linked switching without implying installed branding
is managed execution. Provider/login guidance links to its owner, not a new credential flow.

Read-only checks may inspect only declared bounded metadata/connectivity and supported store availability. They
never authenticate/enroll, install/update packages, start services, modify personal settings, retrieve secrets,
invoke sudo, scan a home directory, dump environments or upload reports. Distinguish missing setup, denied,
locked/unavailable store, mismatched installation, unsupported runtime, stale evidence, offline and not-checkable
states. Successful checks are observations, not grants or completed setup; optional probes cannot authorize use.

Support Linux/macOS according to actual evidence. Keep Omarchy/Arch reference, macOS maintainer installation run
and `pacman`/`apt-get`/`dnf` guidance independently labelled verified, best effort, unsupported or untested. Record
exact source/tool versions and last-verified evidence; historic TASK-00075/00076 or branding receipts cannot qualify
new Harness behavior. macOS Keychain/Linux Secret Service remain the only accepted interactive stores, with no
plaintext workaround when absent. Keep platform qualification inside actual setup, not a proof-only workload.

Private installation/capability details require existing current authenticated permissions on both guide-related
queries and diagnostics. Omit credentials, handles, provider authentication, raw exceptions, arbitrary logs,
private repository context and unnecessary machine paths. Browser visibility grants no setup authority. Keep
loading, denied, stale, offline, partial and unsupported states legible, with keyboard/focus/reflow and non-color-only
meaning through the existing accessible guide surface. Reconnect/viewing/copying never performs a setup effect.

Mutations remain explicit calls to the existing owners outside this read-only check. Unknown original package,
profile, credential or disconnection outcome is inspected/reconciled before retry, never replaced with a fresh
request to manufacture success. Preserve active snapshots and recoverable material; no automatic cleanup or
configuration changes follow from guidance. Underlying install/connection/profile primitives do not wait for the
completed browser guide or database Planning migration.

## Acceptance criteria

- [ ] One existing versioned guide covers the real Harness installation/configuration/readiness/update/rollback/
  disconnection journey with exact steps, expected effects, safe recovery, primary citations and qualification dates.
- [ ] Read-only checks report actual bounded safe facts and actionable unavailable states without installation,
  authentication, key access, service repair, personal configuration mutation or automatic upload.
- [ ] Actual supported Linux/macOS paths and store behavior are qualified through owners; unsupported/untested
  platform or package-manager guidance stays labelled and never becomes a positive managed-ready claim.
- [ ] Contextual Dashboard help and copyable diagnostics reuse existing source/capability authorities, current
  permissions and accessible partial/offline/error behavior without private-data leakage.
- [ ] The user completes the authorized setup/recovery journey through preceding capabilities; interruption and
  uncertain outcomes route to exact owning recovery, not automatic mutation or replacement issuance.
