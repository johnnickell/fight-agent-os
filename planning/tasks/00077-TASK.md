# Accept the repository identity and link-consistency ADR

## Outcome

An explicitly accepted ADR defines the stable Workspace/Repository/Host/Checkout/Worktree identity model, PostgreSQL transaction and uniqueness boundaries, conservative source/Git matching rules, and recoverable consistency protocol for database state plus the repository-local uncommitted Git marker before production registration changes begin.

## Scope

- In scope: Inspect accepted WF-008 semantics, ADR 0001/0002 boundaries, Fight Common COMB identity support, current PostgreSQL transaction capability, Git common-directory/config/worktree behavior and approved-root contract; decide aggregate ownership, current-state/event/audit persistence, identity generation, one initial Workspace/Host bootstrap, active slug/source uniqueness, source descriptor normalization/equivalence, matching evidence precedence, marker namespace/shape, preview/confirmation binding, database/marker ordering, idempotency, crash recovery, relink fencing, archive/restore conflicts, permission boundaries and downstream handoff.
- Out of scope: Production schema/code/API/UI, registering or linking a real repository, writing a durable Git marker, changing remotes/branches/source, Planning migration, Runner/Workflow authority, new-project creation, multi-workspace isolation, and implementing TICKET-00025 through TICKET-00029.

## Validation and permissions

Preserve WF-008: Agent OS mints COMB-backed typed identities; paths, names, slugs, remotes, provider IDs and markers are locators or evidence only. One Repository represents one intended collaboration in one Workspace. Checkout is one Git common directory on one Host; Worktrees sharing it retain distinct Worktree identities. A clone does not inherit Checkout identity, while a directory move may preserve an explicitly linked marker.

Define closed typed source descriptors with explicit normalization and equivalence semantics. Directory/slug similarity never matches. Existing durable links and shared common-directory evidence have priority; a unique source match only proposes the first link; fork/upstream, multiple, missing, changed, copied or conflicting evidence requires explicit confirmation or refusal. Provider-native immutable identifiers may strengthen evidence but never replace Repository identity.

Settle transactional uniqueness for active Workspace slugs and approved source identities, internally generated IDs, stale expected-state handling, audit attribution, and safe constraint translation. Reuse the one Doctrine/PostgreSQL connection and transaction authority from ADR 0002. Do not introduce reflection mapping, request-time schema mutation, client-selected normal IDs, a second identity authority, or filesystem policy in HTTP Actions.

PostgreSQL and `.git/config` cannot commit atomically. The ADR must enumerate every interruption point before/after confirmation, database mutation, marker observation/write and response; select an idempotent recoverable ordering with durable state/fencing where needed; define retry/reconciliation ownership; and prohibit silent rollback claims. Bind confirmation to actor, Repository, Host, exact canonical approved path, common-directory/marker/source observations, expected revisions and expiry. Changed evidence invalidates it.

Choose an Agent-OS-owned non-reserved Git configuration namespace and typed marker format. Inspect an existing value before writing. Never overwrite unknown/conflicting values, commit the marker, modify `.git/config` beyond the exact key, mutate branches/remotes/worktree files, or treat write success as database success. Define safe cleanup and operator escalation for every partial state.

Separate permissions for view, register, metadata/source change, link/relink, designate and archive/restore. Registration and linking do not grant Planning, Execution, Git publication or Agent authority. The future TICKET-00029 UI consumes commands/queries but owns no matching rule.

- [ ] Marker namespace, shape, inspection, write, conflict, cleanup and non-commit behavior are accepted and cannot alter branch, remote or working files.
- [ ] Archive/restore, source changes and relinks preserve identity/history and define active uniqueness conflicts without permanent deletion.

   explicit `github.com` profile. No general URL heuristics or silent fork/upstream/native-ID identity adoption.

   Conditional exact-key publication preserves unrelated config; unknown/multiple/worktree overrides refuse.
   Include-bearing mutation is unsupported initially. Supported-platform filesystem guarantees need qualification.
7. Commit pending database intent/reservations first, publish/re-read the marker outside a business transaction,
   then finalize state/audit/result. Pending reservations do not expire beneath a paused writer. Recovery,

   compensation is not rollback; no cross-resource atomicity or exactly-once event claim is made.

   Permissions, current Repository access and physical root capability are independent; linking grants no access,
