# Check and inspect designated-checkout update availability

## Outcome

An authorized human can inspect known synchronization state and explicitly request one bounded registered-remote
check through production APIs. Retained facts, remote observation/fetch and working-tree update remain distinct;
unknown freshness is never reported as up-to-date and viewing status never initiates network or Git effects.

## Scope

- In scope: Safe retained-status queries, explicit check admission, protected registered-default observation/fetch,
  original check recovery, bounded incoming-commit facts and early check/result/custody contracts for later sync.
- Out of scope: Branch/worktree update, browser presentation, scheduled dispatch, alternate checkouts, source or
  credential repair, another custody registry/provisioner, arbitrary remote access, publication and Agent execution.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Inspect known state | N/A — retained read only | Applicable last check/update, freshness, incoming commits and blocking reasons | N/A — no event per page view | Bounded authorized facts without fetch or update |
| Check registered remote | Explicit exact scoped check admission | Current source/default/checkout, authority and custody | Committed check intent and attributable observed outcome | Bounded protected observation/fetch; recorded reference effects, no worktree update |
| Reconcile interrupted check | Original-operation reconciliation and only proved-safe remaining delivery | Original intent, actual process/ref observations and current scope | Verified original outcome or uncertainty/hold | No blind re-fetch, takeover or false completion |
