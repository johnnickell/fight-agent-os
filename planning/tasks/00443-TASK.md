# Configure and run currently authorized scheduled synchronization

## Outcome

Authorized users configure bounded scheduled checks, enabled by default as policy, while actual scheduled checks
and eligible updates run only under a genuine current actor/delegation. Restarts and queued old work cannot revive
revoked authority or bypass the same safe fast-forward path used manually.

## Scope

- In scope: Expected-state schedule settings/API, attributable settings revisions, actual scheduled actor/delegation
  and revocation integration, bounded due-work admission/dispatch/recovery and direct real scheduler qualification.
- Out of scope: A general scheduler platform, new identity/permission engine, implicit administrator/Agent, copied
  credential-delivery queue, stronger background privilege, browser settings UI and automatic source/credential repair.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Inspect settings/readiness | N/A — protected read | Current settings revision, applicable actor/delegation and safe last outcome | N/A | Known enabled/disabled/blocked state, no enrollment or network effect |
| Configure checks | Expected-state configure/enable/disable operation | Current Configure authority, bounded policy and real delegation applicability | Committed settings/audit facts | Future scheduling policy changes, never a permanent effect grant |
| Admit due check/update | Bounded protected due-work admission through actual current actor/delegation | Current policy, authority, source/custody and exact target | Existing original check/update intents and outcomes | TASK-00441 check and only eligible TASK-00442 fast-forward |
| Recover after restart | Bounded original-operation reconciliation and due discovery | Current settings/authority, prior effect and next eligible work | Attributable original outcome/hold | No stale-work authority, duplicate update or hot retry loop |
