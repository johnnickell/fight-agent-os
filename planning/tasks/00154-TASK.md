# Serve configured permission-gated Swagger with shared credentials and themes

## Outcome

In an **explicitly allowed environment** (initial Agent OS set `["local"]`), a caller with current authoritative
managed `READ_SWAGGER` (`SUPER_ADMIN_ONLY`) can open a light/dark Swagger viewer, read the private generated
OpenAPI JSON and explicitly exercise supported same-origin operations using the application's existing
memory-only access token and session coordinator. Tag sections and operations start collapsed. An exact
configurable allowed-environments set may be empty or deliberately include staging, `test` or production;
current permission and each endpoint's actual authorization remain independent. Strictly parsed APP_DEBUG
controls only sanitized optional diagnostics, never Swagger, credentials or authority; true debug in exact
`APP_ENV=prod`/`production` fails startup.

## Scope

- In scope: Canonical local environment/configuration wiring; strict APP_DEBUG parsing; typed safe boot-config
  evolution; bounded debug-log convention/seam; protected viewer entry/bootstrap and document serving;
  qualified/pinned locally bundled Swagger UI; shared authenticated request/refresh/CSRF integration;
  collapsed tags/operations; existing system/light/dark theme integration; allowed/denied/expired/error states;
  exact environment allowlist and independent debug policy, permission/token/redaction/browser evidence and
  documentation.
- Out of scope: **Unconfigured** production/staging/test Swagger availability, role-name authorization,
  long-lived/static Swagger tokens, new login/refresh authority stores, token/secret HTML hydration,
  credential persistence,
  arbitrary external API explorers, automatic mutations/replays, broad environment refactoring, general
  observability/log collection, environment-update scripting, deployment and universal accessibility claims.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Configure documentation and safe diagnostics | Explicit operator environment settings | Read typed APP_ENV, exact Swagger allowlist and independent APP_DEBUG | None | Only opted-in environments are eligible; sanitized debug is independent and prohibited in prod/production |
| Open permitted Swagger | No business mutation | Server checks exact allowed environment/current READ_SWAGGER, serves viewer initialization and private spec | None | Authorized opted-in viewer renders in current theme; no public document bypass |
| Expand documentation | Local interaction only | Read tag/operation/schema details already authorized | Local UI signal | Initially collapsed sections expand only by deliberate interaction |
| Execute an API operation | Explicit user action invokes the real operation | Resolve current memory credentials, request protections and endpoint policy | Only the actual endpoint's existing events | Real effects occur only under that operation's server authorization; no synthetic success |
| Refresh/lose authority | Existing authentication coordinator only | Observe session/permission/context changes | Existing client invalidation signals | Requests/viewer data clear or pause; late work cannot restore revoked access |
| Emit safe debug output | No business command | Read validated independent app_debug flag | No domain event | Optional sanitized diagnostics only when explicitly enabled; prod/production with debug true refuses startup |

## Validation and permissions

### Allowed environments and public configuration

Implement [TICKET-00010's amended Swagger/debug contract](../tickets/00010-TICKET.md#local-environment-and-safe-debug-configuration)
and [ADR 0004's explicit later amendment](../adr/0004-client-authority-and-runtime-state.md#local-debug-and-documentation-availability-amendment).
`local` remains the canonical developer environment name, not an alias for every non-production value. Replace
the current Compose `APP_ENV: development` with deliberate local configuration support, document migration of
local operator files, and keep HTTP/TLS services consistent. Do not edit a user's ignored `.env` automatically.
The checked-in example already contains prospective APP_ENV/APP_DEBUG entries; add the explicit Swagger-allowed
set and remove pending-wiring caveats only after actual support is verified. Preserve stable section groups;
no updater script is in scope.

Read APP_DEBUG as a strict boolean, not language truthiness of strings such as `false`. Default to false when
absent; malformed configuration fails safely with a non-sensitive diagnostic. Effective optional browser debug
follows explicit APP_DEBUG=true in any named non-production environment. With exact APP_ENV=`prod` or
`production`, APP_DEBUG=true **fails startup**, not silently coerces debug false. Configure true for this
project's local environment and false for its staging/production environments; other deployments own their
choices subject to the hard production rule. APP_DEBUG does not enable Swagger, grant permissions, relax
origin/TLS/CSRF controls, or expose PHP stack/exception/configuration dumps.

Configure an exact Swagger allowed-environments set: this project's initial value is `["local"]`. An explicit
empty set disables the viewer/spec everywhere; a deliberate listed value may include `test`, staging, `prod`
or `production`. No wildcard/substring matching, malformed list, unset/invalid APP_ENV, or unlisted environment
may serve the viewer or spec; absence/invalid configuration fails closed with a non-sensitive diagnostic. The
list is only *environment eligibility*, never authority. Changing it requires explicit deployment configuration
and security qualification, not a browser toggle or APP_DEBUG setting. Test-mode enablement never alters the
guarded test database. Evaluate it independently on **both** viewer/bootstrap and direct spec reads, always
requiring current server-side READ_SWAGGER and the actual endpoint's authority for Try it out. Do not enable
other developer tools, broad debug logging or CORS by opting Swagger into production.

Use the existing inert escaped JSON boot block, not a second config endpoint or hidden/base64 environment dump.
Evolve its strict versioned schema and every producer/decoder/consumer atomically: add only `app_debug` and
`swagger_available` booleans alongside the existing API base/version. The former is the safe effective debug
state; the latter denotes configured environment eligibility, not a user grant. Publish neither the allowed
set nor APP_ENV, permission names, token or operator configuration as client runtime data. No principal,
token, CSRF value, cookie, role/permission set, signing key, provider config or submitted values belong in
HTML/config/assets. Base64 would only encode, not protect, such content. Preserve no-store, CSP-compatible
delivery, exact same-origin API base validation and generic boot failures. Missing/
malformed/unsupported schema never enables protected tools or diagnostics.

Permit intentional console diagnostics through a small shared guarded convention/seam, not unguarded console
calls distributed across forms. Suppress output when effective debugging is false. Even when explicitly enabled
outside local, log only safe event names/status/counts; never raw Authorization/Cookie headers, tokens,
CSRF/grants, passwords, form bodies, arbitrary response/error objects or personal data. A browser can modify
its public debug flag: this is a presentation/logging choice, never server enforcement or permission authority.

### Viewer and document authorization

Both viewer initialization and direct spec reads require **exact configured environment eligibility** and
current authoritative READ_SWAGGER on the server, through the existing authenticated principal/permission
boundaries. A client route check, role name, configured debug flag or previously downloaded schema cannot
authorize a new request. Keep viewer/spec unavailable in all **unlisted** environments (including `test`,
legacy `development`, staging and production under this project's starting `["local"]` set), and absent or
malformed configuration; explicit opt-in never overrides current Permission or endpoint policy. Test isolated
opted-in and denied application boots without relaxing the test-database guard.

Use an authenticated in-application entry that can obtain the guarded viewer/bootstrap and document via Bearer
fetches. Distinguish the generic public application shell from the protected Swagger viewer response: the shell
must not contain the spec, protected viewer payload or preauthorized configuration. Direct viewer/bootstrap and
document requests without current permission fail before disclosing them. Browser navigation does not attach
an arbitrary Authorization header automatically; prove the entry/reload/restoration sequence without inventing
a token URL, hidden input, temporary long-lived credential, or JavaScript-readable auth cookie.

Serve TASK-00153's complete generated artifact outside public static roots, with safe missing/corrupt outcomes,
no-store and no permissive CORS. No public `/openapi.json`, source-map/spec copy, web-server alias, download link
or `$ref` path may bypass the same permission/environment boundary. Use the current guard for each real
operation; READ_SWAGGER grants documentation access only, not authority to execute every documented operation.

### Shared request credentials and effects

Reuse the same narrow memory-token provider and completed TASK-00048/00049 authentication/principal lifecycle.
Use the latest token at send time, not a token captured when the viewer mounted. Keep the existing fifteen-minute
access lifetime and cookie-backed bounded refresh; do not issue a longer-lived token or persist credentials in
Swagger's authorization store. Do not prefill a token form, put tokens in base64/HTML/URLs/spec/examples/downloads,
copy them to storage or introduce another refresh loop. Reload restores through the application's normal flow;
logout, terminal failure, identity change or permission invalidation clears protected viewer data and retires
pending operations under the existing generation fences.

Qualify Swagger's supported request/response hooks or a bounded transport adapter against the real client
boundary. Constrain authenticated requests to approved same-origin API paths from the owned spec; reject
alternate servers, arbitrary URLs, remote refs, redirects and schemes before adding any credentials. Disable
remote validators/CDN dependencies and third-party requests. Apply the endpoint's actual CSRF/Origin/JSON/cookie
policy through existing services; the current foundation GET client alone does not prove safe POST transport.

The attached Authorization header is transient transport data, not Swagger form state, rendered request/curl
snippets, copied examples, logs, analytics or retained error snapshots. Keep `persistAuthorization` disabled and
verify actual library behavior rather than assuming that option prevents every leak. Strip sensitive display/
export material and clear transient request/response/form state on authority teardown. Document any operations
that cannot safely be executed in this viewer rather than creating a second credential-issuance/refresh flow.
Stop for a design decision if the selected library cannot honor these boundaries without a substantial fork.

Every Try it out/Execute is explicit and invokes real server behavior, not a harmless preview. Reads and mutations
retain all actual endpoint permission/target checks and confirmation requirements. No automatic request on page
load, theme change or expansion; no automatic business-mutation replay after refresh, 401, 403, cancellation or
uncertain failure. Refresh uses the one bounded coordinator; explicit user action retries an eligible operation.
A response received after local cancellation may still represent a committed server effect; never claim undo.

### Theme, grouping and interaction

Use TASK-00050's single system/light/dark preference and semantic styling owner. Both effective themes cover
tags, operation panels, parameters, inputs, code examples, response panes, buttons, status colors and visible
focus, with readable contrast and narrow reflow. No independent Swagger preference store or global style
leakage into normal application controls. Bundle pinned assets locally; any CSP exception must be narrow and
justified without weakening normal routes.

Initialize `docExpansion: "none"`: **tag groups and operations are collapsed by default** on initial load and
remount. Growing catalogs remain scannable; users can search and deliberately expand a section/operation.
Do not persist expansion state that reopens everything on subsequent visits. Expansion/search/theme actions
must not trigger API operations or alter credentials. Verify actual supported library behavior rather than
adding tests of configuration text.
