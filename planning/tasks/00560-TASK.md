# Execute a real Build Engineer stage through an upstream agent

## Outcome

An explicitly selected local Build journey runs its actual Engineer assignment through upstream SDK execution,
with trusted stage identity and visible Herdr activity, then hands committed implementation and verification to
the existing independent Review path. This is TICKET-00130's first usable execution transition, not an SDK demo.
John approved this bounded slice on 2026-11-02; implementation remains unstarted.

## Scope

- Qualify current supported upstream/Pi session creation, initialization and parent-root association against the
  installed layout. Implement the smallest session-specific Fight stage admission needed for a real Engineer.
  Use upstream execution directly rather than a copied engine, generic launch facade or new scheduler.
- Bind actual worker session to stage/TASK/checkout/attempt/permitted effects before execution. Preserve governing
  context, fresh independent request, exact pinned provider/model/thinking, selected checkout and one Compose
  runtime. Never grant authority by agent name, profile or prompt, or mutate shared `process.env` to impersonate
  session-local launcher identity. Do not inherit the coordinator's workflow role accidentally.
- Reuse verified native-parent custody and SDK observation so early/final assistant activity and tool names reach
  Herdr, with correct assigned TASK/stage instead of misleading `Unassigned` identity. Preserve exact verified
  worktree context for the existing log reader; observation remains passive and bounded.
- Preserve ordinary Work edits/checks/commits and evidence handoff, then existing fresh independent Review
  without Engineer dialogue. Keep non-Engineer process stages temporarily as demonstrated live callers;
  TASK-00561 owns full default cutover and replacement retirement. Do not switch an active journey silently.
- Qualify installed-layout package/profile discovery in disposable/private installations and document deliberate
  adoption at a safe session boundary. Do not automatically change everyday/global settings or reload parents.
- Out of scope: full Review/QA/Land SDK migration, managed Runner/server-side grants, new isolation claims,
  upstream scheduling/worktree cleanup, MCP dependency, pane browser, log UX, shared provisioning and publication.

## Validation and permissions

Only existing explicit Build authority permits Engineer effects. Fresh context and tool profiles are not OS
isolation or independent-stage authorization. Reject invalid task/checkout/role, duplicate attempts, unsupported
model/thinking and missing companion/session-init capability before unauthorized work. If supported upstream
initialization is missing, identify the exact hook needed and hold; prefer a small separately authorized upstream
contribution over monkey patches/forks. A mock-only proof or subordinate assistant cannot satisfy the stage contract.

Foreign, rootless, nested and replaced session records remain refused by observation; do not guess parenthood from
paths, labels or transcript names. Missing display must never trigger relaunch/substitution. Reconcile provider
failure, timeout, cancellation, parent shutdown/reload and uncertain liveness before another worker starts. Reader
closure leaves workers alone; parent runtime shutdown must not be advertised as passive. Keep private source,
credentials and raw reasoning out of display/evidence. Application HTTP/database changes and new Domain events
are N/A: this is local Harness integration using existing lifecycle events and trusted-local limitations.

## Acceptance criteria

- [ ] A real authorized Engineer assignment runs as one fresh upstream SDK session with correct trusted
  stage/TASK/checkout/attempt/effects, governing instructions and exact model/thinking; no parent transcript.
- [ ] Herdr shows early/final activity for that exact agent and verified selected worktree. Assigned identity is
  truthful; foreign/rootless/replaced-session rejection and passive reader behavior remain intact.
- [ ] Missing package/hook, invalid stage authorization/checkout/model and duplicate attempt fail safely before
  unauthorized work. A possibly-started SDK worker cannot trigger a silent Python fallback or duplicate launch.
- [ ] Timeout, provider error, abort, shutdown/reload and uncertain execution are reconciled without inventing
  success or durable survival. Display loss never substitutes the executor or changes the actual result.
- [ ] Committed Engineer implementation and verification reach the existing fresh independent Review route;
  Engineer dialogue is not copied and SDK terminal status is not acceptance.
- [ ] Owning Harness checks and real installed/native Pi/Herdr interaction establish the path and failures;
  normal full gate and independent Review/applicable QA are recorded with source/install/model evidence limits.
