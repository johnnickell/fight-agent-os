# Complete accessible managed-Agent administration

## Outcome

A currently authorized Super Admin uses one accessible browser journey to preview, confirm and create distinctly
named Team-bound Agents, inspect truthful current identity/authority/lifecycle status, rename and confirm rotation/
revocation. Qualify creation from all eight reviewed managed templates and incorporate the separately owned
Triage definition without treating provisioned identities as working roles.

## Scope

- In scope: Real directory/detail, complete template/Permission preview, exact named Team/Repository creation
  confirmation, current status and safe name/lifecycle forms through TASK-00256–00259; actual eight-template
  creation and Triage integration, authority invalidation, failure/recovery and responsive accessibility evidence.
- Out of scope: Another provisioning flow, template editor/AI publication, arbitrary Permission controls, drift
  repair, credential/sink/maintenance console, Team administration, session launcher, Workflow engine or role-use proof.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Review and confirm named creation | TASK-00258's exact reviewed creation intent | TASK-00257's current complete preview and safe readiness | Only existing server-owned committed facts | One distinctly named Team-bound Agent and truthful setup/delivery status, no launch |
| Inspect/manage an existing Agent | TASK-00256/00259's name/confirmed lifecycle operations | Current authorized directory/detail, desired/actual set and original-operation status | Existing owning facts, none invented by UI | Only the confirmed bounded mutation or explicit refusal/uncertainty |
| Recover stale or uncertain interaction | Explicit refetch/original-status resolution, not mutation replay | Current principal, original outcome and refreshed exact preview | No browser business event | Old confirmation discarded; renewed human choice only with authoritative state |

## Validation and permissions

Use TASK-00051's real authenticated frame and the single current `/me` authority owner under ADR 0003/0004.
Protect route rendering, loaders, controls and action handlers by exact intent-specific Permissions; role names,
template titles or a successful UI check grant nothing. Server operations still revalidate current authority,
target/scope and exact intent. Retire protected data on auth/context invalidation; late success and error responses
must not revive previous identities, previews, confirmations or lifecycle status.

Show the exact reviewed template revision, Team, registered Repository scope, normalized friendly name and full
eligible desired direct-Permission set before confirmation. Missing references/protected tiers are blockers, not
hidden omissions. Select protected holder/destination through the established server-owned boundary without
exposing handles or adding browser enrollment. A confirmation cannot silently adopt later template, Team, scope,
Permission or destination changes. Existing binding/history remains immutable; no checkbox overrides, arbitrary
browser prompt, current-template rebinding or existing-Agent Auto-sync is included.

Keep all business input, selection and confirmation state volatile and bounded. No credentials, operation requests/
keys, receipts, leases, provider secrets or private holder data reach browser forms, caches, URLs, base HTML,
telemetry or evidence. Classify safe navigation parameters explicitly; do not persist drafts or encode them in
intended-route restoration. Apply no-store/private-response rules and existing sanitized transport errors.

Display incomplete creation, issued, delivered, activated and bounded currently usable status separately using
TASK-00259's real observations. Initially unavailable role actions must be visibly unavailable, not mocked or
silently launched through an alternate path. An idle/listed Agent is not proof of a working role. Confirmation
of rotation/revocation names the exact safe target/effect; no force, activation override or implicit transfer.
After disconnect/401/refresh or uncertain commit, inspect original outcome before any new human-confirmed intent;
never automatically repeat a mutation. Browser teardown loses drafts, not durable server intent.

Use existing semantic production components with labels, keyboard/focus/error handling, readable narrow/wide and
light/dark states. Do not convey availability or errors by color alone. Show loading, empty, forbidden, invalid,
stale, unavailable, incomplete and uncertain states distinctly. Creation on each reviewed template uses the same
qualified shared boundary, not eight security-certification ceremonies or test-only seeded role labels.
