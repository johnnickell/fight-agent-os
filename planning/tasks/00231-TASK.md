# Fence every authority-changing writer

## Outcome

Every actual writer capable of changing Agent operation authority participates in the same cohort-first lock
order and advancing authority epochs. Direct writes, no-ops and revoke/regrant cannot bypass current state or
permit a stale delivery/cleanup acknowledgement. This closes cross-boundary participation, not live enablement.

## Scope

- In scope: TASK-00227's complete writer inventory; current Agent, Permission/Role/User, managed-policy,
  caller/target/delegation, destination ownership/binding and key write/reference participants; shared-connection
  admission, epochs, lock ordering and concrete HTTP/direct/CLI/worker enforcement; regression protection for
  existing human authority behavior.
- Out of scope: New grant policy or role-name authorization, independent queues, duplicate destination/key stores,
  provider effects, operational cohort switching, physical restoration, UI or assumed future writers.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Change caller/target/policy authority | Existing owning Permission/Role/User/Agent/delegation operations | Current expected authority and applicable cohort/epoch state | Existing owning facts only after commit | Policy and required epoch/reference changes share one transaction and fence |
| Change destination or key admission | Existing protected owner operations | Exact binding/ownership and key write/reference state | Existing protected operational facts, not a duplicate event | Reassignment, admission closure or regrant invalidates stale operation authority |
| Deny bypass or stale acknowledgement | Existing direct/worker paths under mandatory guards | Current operation/Agent/destination/key and bound authority epochs | Safe refusal, not a successful effect | No partial write, stale success, material resurrection or old allow restored by regrant |

## Validation and permissions

Preserve current caller/target/delegation policy and package ADMIN_SAFE/reference invariants. Actor strings and
signed requests are provenance/authentication, not authorization. All participating paths acquire cohort before
subordinate fences and retain them on the package Unit of Work connection through commit/rollback. Validate
desired-state no-ops too. Advance epochs whenever relevant authority changes, including revoke/regrant ABA;
unknown/restored epochs cannot count as current. Do not reset them to make a retry pass.

Integrate actual owner state rather than creating competing policy, destination or key authorities. Permission
tier promotion/removal and Role/User changes must serialize with the affected operation's authorization read;
a preflight check or outer nested transaction cannot establish this guarantee. No external effect executes inside
that business transaction. Detect gaps in direct repository and non-HTTP paths rather than assuming handler
registration covers them. Document precise participation without unnecessarily making unrelated existing human
operations depend on an unqualified Agent runtime; apply TASK-00227's accepted safe transition, not a permissive
Agent bypass or silent installation-wide lockout.

## Acceptance criteria

- [ ] Every actual relevant writer is traced to a tested mandatory fence/epoch path, including no-ops, direct
  repository/bus calls and worker/admin execution. Unsupported paths are disabled or explicitly block qualification.
- [ ] Independent PostgreSQL races between operation authorization/admission and each authority writer establish
  one committed order, including Permission promotion/removal, Role/User changes, delegation revoke/regrant,
  destination reassignment and key admission closure. Rollback releases locks without partial epochs or grants.
- [ ] Delayed completion cannot acknowledge under an old authority epoch after revoke/regrant or binding/key
  changes; expected-state checks remain exact even when visible values return to their earlier values.
- [ ] Existing human policy, last-admin and reference protections remain intact; no role-name bypass, duplicate
  authority store, nested transaction or incomplete positive Agent capability claim is introduced.
- [ ] Direct and normal-path failures are sanitized with no raw material or previous provider exception; actual
  participant and lock/epoch evidence supports every claimed coverage row.
