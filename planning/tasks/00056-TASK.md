# Deliver authenticated password change and terminal logout

## Outcome

The authenticated Account/Security journey derives ownership from the current principal, requires current-password proof, applies the shared policy to a replacement, invokes `AuthenticationService::changePassword()`, and after atomic authority advancement and all-session revocation clears current browser authority across tabs and requires fresh login.

## Scope

- In scope: Protected Change Password route/form; versioned Bearer-authenticated Action/validated sensitive DTO/safe View/OpenAPI; current-principal identity derivation; shared password/compromised checks; package change orchestration; generic current-password failure; current cookie expiry and memory/principal/cross-tab terminal invalidation; accepted success/policy/failure/loading/system states; PostgreSQL authority/session races; HTTP/component/accessibility/redaction tests.
- Out of scope: Password reset, email change, administrator assignment, changing another user, preserving current session, logout-everywhere as a standalone operation, password history/periodic expiry, external compromised-password APIs, storing form values through reauthentication, and broad browser automation.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Change known password | `AuthenticationService::changePassword(currentPrincipal.userId, current, new)` after owned policy | Resolve current principal, active user/hash, password policy, and all active sessions | `PasswordChanged` | Hash/authority replace and all-session revocation/audit commit atomically; terminal browser logout follows |
| Reject wrong current password | Same service call | Verify supplied current password against real/dummy safe path | Redacted package failure only | Generic rejection; valid session remains unless authority changed concurrently |
| Reject replacement password | N/A before package mutation | Apply structural policy and local compromised checker | N/A — no domain event | Safe requirement feedback; no user/session mutation and no secret retention |
| Complete terminal client transition | N/A — authentication coordination | Observe committed success, cookie deletion, and logout generation | Client logout/invalidation signal | Current and sibling tabs clear token/principal/form state and route to fresh Login |

## Validation and permissions

Require TASK-00044 Bearer authentication and request-scoped `CurrentPrincipalProvider`. Derive the user ID only from the principal; reject/ignore no body actor/user/role/session fields and never accept an administrative target. Self-service ownership is the authority; no role/managed permission applies. Stale/revoked/non-active principal fails before password mutation.

Accept bounded current password, new password, and confirmation only. Never trim/normalize silently. Confirmation mismatch is transport validation. Apply approved method/JSON/body/Origin controls for Bearer-authenticated same-origin mutation and endpoint rate limits without introducing ambient-cookie authority. Mark secrets sensitive and keep them out of serialized commands, logs, exceptions, audit, analytics, metrics, snapshots, browser persistence, route state, and reauthentication handoff.

Apply TASK-00039's exact server structural and local compromised-password policy to the new candidate before package service; client guidance is usability only. Password managers and paste remain supported. The current password is verified only inside `AuthenticationService::changePassword()` using package real/dummy safe behavior. Do not pre-read password hashes or duplicate comparison in the Action. The package does not require new password to differ unless its authoritative behavior changes; do not invent an unapproved history policy.

Use package service for active identity/current proof, Argon2id hash replacement, authentication-version and persistence-revision advancement, all-active-session revocation, safe audit evidence, transaction, and `PasswordChanged`. Successful change intentionally revokes the current session as part of all-session invalidation. Expire the current refresh cookie, clear access/principal/form memory, broadcast terminal logout, and navigate to Login with non-secret success guidance. No replacement token is issued.

Wrong current password and safe package rejection use one generic message without hash/state detail. Password-policy failures may explain candidate requirements. On failure before committed authority change, retain a still-valid current session and clear secret fields appropriately. If authority changed concurrently, normal terminal authentication handling wins; do not restore stale memory.

Recreate accepted Account/Security form and states with semantic components, labels/instructions, current/new/confirmation autocomplete semantics, show-password only as accepted, keyboard/focus, announcements, paste/Unicode/spaces, themes, reduced motion, narrow/wide layout, and explicit fresh-login result.
