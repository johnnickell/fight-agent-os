# Give Workspace bootstrap and reference generation explicit owners

## Outcome

Give the existing initial Workspace bootstrap and exceptional-reference entry their actual owners, rather than
hiding both inside RegistrationStore. Deliver the first complete cutover of
[TICKET-00134](../tickets/00134-TICKET.md), normally one PR: a coherent Workspace persistence/command/query path
and a bounded technical reference adapter, with current callers migrated. This removes the concrete mixed-store
prerequisite to Project delivery without inventing another operation framework.

## Scope

- Provide the initial Workspace aggregate, typed ID and collection-like WorkspaceRepository under the approved
  aggregate-owned organization. Keep the existing one-initial-Workspace meaning, attribution and stored identity;
  do not invent membership, multi-workspace management, Host enrollment or a giant cross-root aggregate.
- Make explicit bootstrap a Domain-owned ID-bearing command with a registered Application handler. Console
  generates the typed WorkspaceId before void bus dispatch; handler owns the generic transaction, aggregate
  persistence and separately explicit required audit. Repositories do not own completion or return HTTP payloads.
- Provide registered current-state Workspace reads and safe typed Views where needed. Queries/startup never create
  a Workspace. Known current identity, repeated explicit invocation and uncertain-response reconciliation use actual
  current state, not immutable original-response snapshots or a transparent replay journal. Preserve safe existing
  operator-facing outcomes, and state conflicts/uncertainty honestly if another caller wins the initial slot.
- Preserve explicit trusted-machine/operator Console admission and attribution, validation, safe output/exit status
  and bounded flags. An attribution UUID is not browser authentication or an access grant. Retain the one-initial-slot
  database invariant and atomic required audit, including real competing bootstrap behavior.
- Move exceptional-reference generation out of RegistrationStore and the forwarding Application service. It is an
  adapter-owned technical operation: current authentication, independent GENERATE_REFERENCE_IDS and Workspace scope
  admission, an atomic bounded limiter, and the owning UUID factory. It is not a write command/fake aggregate, and
  generates no reserved, persisted or predicted future aggregate identity or import authority.
- Preserve the existing ten-per-UTC-60-second actor budget, at most 10000 current buckets, safe exhaustion and
  Retry-After. Keep limiter metadata with the technical admission mechanism, not ProjectRepository or a business
  result journal. Generated IDs, private request data and credentials do not enter that storage or diagnostics.
- Migrate all existing initial-Workspace lookup/bootstrap/reference consumers to the real Workspace boundary or
  registered queries as appropriate, including current registration callers, composition, HTTP/Console presentation,
  meaningful tests, OpenAPI and runbook references. Move their owned Workspace types together without aliases.
- Remove extracted mixed-store methods and obsolete bootstrap/reference services/tests after replacement proof.
  Existing Project registration may retain its still-live original implementation until TASK-00575; add no temporary
  compatibility facade. Keep required audit independent from replay bookkeeping, preserving existing identities/history
  and remaining live consumers when changing shared evidence relationships. Use generated migrations if needed.

Excludes new Workspace/Host/access/import features, Project registration/read cutover, physical operations,
upstream source/releases, broad security refactoring, generic error frameworks and blanket ORM/DBAL replacement.
No new permission or disposal authority. Governing amendments belong to TASK-00564; full Project cutover follows.
