# Integrate the shared frontend candidate into the Symfony skeleton

## Outcome

The actual project-symfony skeleton installs the same packed frontend candidate as Agent OS, serves working
branded human account/administration journeys and can host a separate business page. This unblocks the chosen
foundation for nickell-financial and proves the library's real external integration before publication.

## Scope

- Qualify the package as built after TASK-00128, which carries TASK-00123/00121/00127 and TASK-00596/00597
  transitively. Use an identified packed dependency, not a source copy, deep import or symlink-only result.
- Implement the compatible backend/API/session/admission/persistence and local email setup in project-symfony
  using qualified canonical packages and the framework's own composition. npm installation is not backend work.
  Include qualified list pagination/ordering and matching totals from TASK-00597's documented contract.
  Keep search disabled for Access Control features. Document the shared optional search callback/URL integration
  for application-specific queries; do not implement an Access Control search projection.
- Use Symfony/Twig for the shell where appropriate and React/Bootstrap for the application UI. Demonstrate a
  different host brand and a useful host-owned landing page with shared controls; no Tailwind or Agent OS
  Planning/Workflow requirements. Do not invent product financial/home/social features for this integration.
- Repair demonstrated package portability gaps in the same candidate, remove replaced local frontend paths,
  document setup, release compatibility, public extension points and local-versus-production boundaries.
- Out of scope: registry publication, real-mail enrollment, production deployment, all other skeletons and later
  email-change/Agent/HMAC/managed-workflow features.

## Validation and permissions

Follow Symfony's instructions and independent checks. Verify server admission, current principal, CSRF/cookies,
separate self/admin sessions, managed/custom roles and permitted grants. Use independent local secrets and
captured mail. No copied production settings, broad public API/spec access or browser-only authorization.
