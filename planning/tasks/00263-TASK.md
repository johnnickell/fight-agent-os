# Bind Team selection at the authoritative start

## Outcome

Extend the existing authoritative Start operation to bind one currently eligible Team/Lead at intake. Revalidate
human consent and current facts, then commit the assignment, owning commitment, exclusive TASK claim, grant,
dispatch intent and fairness advancement consistently. Competing, stale and uncertain requests never double-book
an Agent or create another Workflow. The start owner remains TASK-00139, not this selector integration.

## Scope

- In scope: Team-specific admission inside existing Execution/Application ownership, current selection/consent
  revalidation, shared reference/commitment fencing, durable binding and fairness integration, original-command
  resolution and safe start status. Supported direct/terminal entry paths use the same operation.
- Out of scope: New Start/queue/claim/commitment authority, sandbox/provisioner or launcher, browser gestures,
  pending-intent UI, automatic retries, full Workflow execution, hotfix authorization or live cohort enablement.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Admit selected whole-TASK intake | Existing TASK-00139 Start with bounded human intent and Team selection | Fresh TASK-00261/00262 facts, exact consent, current claims/resources and original result | Existing owning Workflow/assignment/claim facts only after commit | One recorded Team/Lead, commitment, claim, grant and dispatch intent with one fairness advancement |
| Resolve duplicate or uncertainty | Existing original-command inspection/reconciliation | Original Workflow/claim/assignment and current authoritative outcome | No duplicated accepted-intake fact | Same result or honest unresolved hold, never another dispatch |
| Refuse changed eligibility | Existing Start returns safe refusal/hold | Current expected revisions, base inclusion, roster, credential and consent | No accepted/started fact for refusal | No partial assignment, grant, fairness movement or false progress |
