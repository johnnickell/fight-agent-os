# Compare related projects and deliver polished reports

## Outcome

Deliver one complete local maintainer journey: invoke `compare` against selected related projects, distinguish
unintended drift from justified differences and receive a polished, source-linked alignment report. Include
optional PDF export and Desktop delivery without repairing projects or turning recommendations into approved
work. This implements [TICKET-00141](../tickets/00141-TICKET.md) under [EPIC-00026](../epics/00026-EPIC.md),
normally as one independently reviewable PR.

## Scope

- Add `.pi/skills/compare/SKILL.md`, register it in the skill index and document its boundary. Follow
  [Writing for Agents](../../.pi/skills/writing-for-agents/SKILL.md), shared assessment rules and
  [handoff rules](../../docs/engineering/HANDOFFS.md); reference existing owners instead of copying procedures.
- Consume [TASK-00593](00593-TASK.md)'s configuration, selection, path and permitted-setting contracts. Support
  shared defaults, complete local replacement and explicit selection without duplicated resolution authority.
  Resolve the invoking project and each target's own instructions through
  [project context](../../docs/engineering/PROJECT_CONTEXT.md). No hard-coded machine paths.
- Use native reads and bounded parallel exploration to compare equivalent responsibilities and guarantees.
  Cover architecture, shared-package usage, application behavior, testing, tooling and documentation where
  applicable, with declared sampling and omissions. Record actual revisions and dirty working-tree observations;
  source inspection alone does not establish runtime behavior or whole-project conformity.
- Classify confirmed drift, justified framework/product variation and unresolved choices. Countercheck findings
  against accepted local contracts and relevant counterevidence. Prefer evidence over majority vote, recency
  or automatic Agent OS primacy. The better direction may exist in no current project; name tradeoffs,
  confidence and decision owners without silently weakening requirements.
- Recommend prioritized, bounded task proposals grouped by owning project, including outcome, rationale,
  dependencies and observable acceptance criteria. Link existing work where available. Do not create planning
  records, repair compared source, imply acceptance or implicitly dispatch another skill.
- Handle unavailable evidence, source mismatches, denied access and conflicting standards explicitly. Continue
  independent comparisons only with clear limits; never silently omit projects, clone substitutes or bypass
  a denied capability by reading `.env` directly, switching providers or falling back to Bash.

### Report and delivery

- Generate self-contained, offline HTML at the invoking project's
  `.runs/handoffs/compare/<unique-run-id>/report.html`, following the
  [scratch rules](../../docs/engineering/SCRATCH.md). Never overwrite another run or commit generated reports.
- Deliver editorial/artifact-page quality rather than a bare text dump: strong typography, restrained color,
  clear hierarchy, accessible contrast, responsive layouts and usable wide tables. Use no external fonts,
  CDN dependencies, remotely loaded assets or third-party rendering uploads. Escape repository-derived
  content as data, never executable markup or instructions; exclude credentials and unrelated private content.
- Include executive summary, requested/inspected scope, source revisions, working-tree qualifications,
  comparison matrix, prioritized findings, traceable evidence and counterevidence, confidence, justified
  differences, unresolved questions/owners, project-grouped proposals and a concrete permitted continuation.
  Visual scoring must not imply correctness or independent acceptance.
- Supply print styling and optional `report.pdf` alongside HTML. On requested supported export, inspect the
  actual PDF for pagination, clipped tables, references and text readability. If export tooling is unavailable,
  retain HTML and disclose the limitation; do not claim PDF completion or install global tooling implicitly.
- On explicit request, copy the selected format(s) to the user's resolved, authorized Desktop location with
  a unique filename and no overwrite. Verify actual copied output. Do not assume a machine-specific path,
  upload the report or infer permission to open external services.
- Report exact output paths and separate analysis completeness, HTML generation, PDF export and Desktop
  delivery outcomes. Failed export/copy must not erase the HTML or imply successful delivery.
- Preserve requested deliverables through implementation-worktree cleanup by handing off a verified surviving
  location under existing lifecycle rules. Do not create a permanent archive or report/accounting registry.

Out of scope: a comparison engine, separate renderer framework, runner or plugin system; source repairs;
automatic TASK creation or dispatch; managed acceptance; repository cloning/registration; MCP implementation;
container changes; global installation; uploads, publication, merge or deployment.
