# Deliver the guided Planning installation journey

## Outcome

A terminal-capable operator can run a read-only pre-application prerequisite check, and an appropriately authorized authenticated user can follow one accessible versioned task-based Dashboard guide linked to current installation capabilities, explicit human-run mutations, expected results, recovery and primary sources.

## Scope

- In scope: Versioned authoritative operator-guide source and revision/compatibility metadata; Linux/macOS task flow; Omarchy/Arch verified reference language and honestly labelled macOS/pacman/apt-get/dnf status; pre-application read-only host diagnostic; prerequisite/version/connectivity/credential-store checks; secret-safe copyable output; authenticated guide route/navigation; current/stale capability integration through TASK-00074; platform-qualified commands, expected results and recovery; loading/empty/stale/offline/unsupported/partial/denied/error states; accessibility and responsive behavior; direct documentation and command review.
- Out of scope: Silent installation, package-manager execution, `curl | sh`, credential creation/upload, sudo collection, certificate/DNS/mount/network/backup mutation, service repair, repository registration, Harness/Runner setup beyond clearly deferred guidance, browser AI explanations, automatic link checking, product tests of prose/scripts/configuration, and claiming unexercised platforms as verified.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Inspect prerequisites before startup | N/A — read-only host diagnostic | Inspect bounded OS, architecture, Git, source-host tooling, Docker/Compose, ports, DNS/TLS, storage and credential-store availability | N/A — host observation is not a Domain event | A copyable pass/warn/fail/not-checkable report is produced without installation or configuration mutation |
| Follow an operator task | N/A — guide view is read-only | Query guide revision, platform qualification and current installation capabilities | N/A — reads emit no Domain event | Dashboard presents purpose, explicit command/step, expected result, verification, recovery and primary source |
| Continue while offline or degraded | N/A — read-only view | Read visibly stale cached guide/capability state where available | N/A — reads emit no Domain event | Existing guidance remains visibly stale/read-only; live-dependent actions explain why they are unavailable |
| Copy diagnostics for support | N/A — representation only | Render bounded preflight/application facts | N/A — no automatic upload | User deliberately copies a secret-safe report with source revision and observation context |

## Validation and permissions

Keep one versioned repository guide source rendered in the Dashboard; do not create competing terminal and browser authorities. Organize it around tasks: identify platform and support level, check prerequisites, install missing prerequisites explicitly, configure/start/update/recover the Planning runtime, configure approved roots, and hand off to repository registration. Each step states why it exists, exact human action where applicable, expected result, read-only verification, recovery/rollback and primary vendor/distribution source.

The preflight runs before application availability and must be read-only. It may inspect only bounded prerequisite facts and declared connectivity. It must not install packages, authenticate, start Docker, pull images, edit files outside its owned disposable output, change ports/firewalls/DNS/trust/mounts, invoke sudo, read credential contents, dump the environment, scan the home directory, or upload anything. Return stable pass/warning/failure/unsupported/not-checkable outcomes and observed safe versions. Explain that a successful preflight is not installation success.

Support Linux and macOS honestly. Treat Omarchy/Arch as the first verified Linux path only after direct evidence and macOS as verified only after TASK-00076's maintainer run. Keep `pacman`, `apt-get` and `dnf` guidance independently labelled by actual evidence; best-effort text is not verified support. Cite primary Git, GitHub CLI, Docker, Pi, operating-system and selected runtime sources. Never expose or request passwords, sudo input, tokens, private keys, passphrases, credential-store contents or plaintext provider credentials.

Require authentication and the installation-information permission for current capability details and protected guide placement. Static public documentation, if any is deliberately selected, cannot expose private topology, paths or diagnostics. Installation settings and host mutations remain operator-controlled regardless of client visibility. Use TASK-00074 as the only live capability model.

Meet the completed application accessibility and responsive baseline: semantic headings/landmarks/lists/tables, labelled copy controls and command language, keyboard operation, visible focus, reflow, readable warnings without color-only meaning, appropriate announcements for refreshed status, and reduced-motion behavior. Present loading, empty, stale, unavailable, denied, partial and conflict-free recovery states honestly; never fabricate successful checks.
