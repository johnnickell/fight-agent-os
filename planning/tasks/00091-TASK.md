# Record stable Planning criteria and evidence

## Outcome

Authorized planners can manage stable-ID acceptance/outcome criteria and immutable evidence references through semantic history, explicit satisfaction, human waiver and correction by supersession without rewriting either aggregate intent or prior proof.

## Scope

- In scope: Ordered stable criterion children for TICKET/TASK and optional EPIC outcomes; closed criterion kind/text/disposition/provenance; add/revise/reorder/retire/satisfy/waive commands/events; evidence-reference children/links for commits, reviews, verification, managed artifacts, URLs and execution references; typed provenance/digests where owned; add/correct/supersede events; expected versions/idempotency; terminal reopen prerequisite; human waiver confirmation/reason; current criteria/evidence/closeout-input Views; separate criteria/evidence/waiver Permissions; PostgreSQL streams/projections/concurrency; versioned API/OpenAPI.
- Out of scope: Automatic evidence collection, trusting provider status, embedding artifact contents, prototype-specific storage lifecycle, lifecycle closeout/archive, emergency prohibited-content redaction, arbitrary URLs/plugin data, queue eligibility, Markdown import, browser forms and tests of GitHub/Git/test tools.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Manage a criterion | Add/revise/reorder/retire criterion command | Preview aggregate version, order, lifecycle and downstream closeout impact | Criterion semantic event | Stable child identity and complete normalized value/disposition append without deletion |
| Satisfy a criterion | `SatisfyCriterion` | Validate current criterion and typed immutable evidence links | `CriterionSatisfied` | Actor/time/rationale and exact evidence references append; aggregate projection advances |
| Waive a criterion | `WaiveCriterion` with human confirmation | Explain unmet intent, downstream impact and confirmation scope | `CriterionWaived` | Human-authorized reasoned disposition appends without pretending evidence exists |
| Record/correct evidence | Add or supersede evidence command | Validate kind, subject, digest/locator and provenance | Evidence-added/superseded event | New immutable reference links; correction supersedes but never rewrites prior evidence |
| Inspect proof | N/A — read-only interaction | Get criteria/evidence history and closeout inputs | N/A — reads emit no Domain event | Safe Views explain every current and superseded disposition/provenance |

## Validation and permissions

Criteria are stable-ID children of their owning Epic/Ticket/Task, never independent roots or generic checklist rows. Use closed typed kinds, bounded complete text, explicit order and active/retired/satisfied/waived disposition with actor/time/reason. Retirement preserves history. A terminal aggregate must be reopened before criterion intent/order changes; evidence correction may append under narrowly defined authority without falsifying terminal history.

Satisfaction requires one or more accepted immutable evidence references appropriate to the criterion. Evidence kinds are closed and safely normalized: commit, independent review, verification result, managed artifact, URL and later execution reference. Store stable identity/reference, digest/version, source, actor/time and safe provenance where available; do not infer provider truth, fetch arbitrary URLs during a transaction, embed files/logs, accept credentials or make a branch/PR status authoritative.

Corrections append a new evidence reference and explicit supersession link/reason; they never update/delete old event payloads. Superseded evidence remains visible in authorized history and is excluded from current satisfaction only according to explicit Domain rules. Missing/deleted external evidence yields a visible availability warning and never silently changes the historical disposition.

Waiver is a judgment-bearing operation requiring independent waiver Permission and a current short-lived human confirmation bound to actor, Repository, aggregate/criterion versions, impact and reason. Agents cannot satisfy that confirmation by impersonation. Waiver remains distinct from satisfaction and is revalidated during closeout.

Append semantic criterion/evidence event and update current projections transactionally under expected aggregate/constraint versions. Separate view, criteria revision, evidence and waiver Permissions. API Views redact private URLs/query strings, credentials, local paths, internal services, raw logs and hidden linked records.

- [ ] TICKET/TASK criteria and optional EPIC outcome criteria preserve owner, type, complete text, order, disposition and provenance through replay.
- [ ] Satisfaction requires accepted typed immutable evidence; no provider, branch, PR or artifact observation infers satisfaction automatically.

- [ ] Missing/unavailable external evidence remains historically visible with warning rather than silently changing disposition.
- [ ] Waiver requires reason, independent Permission and actor/version/impact-bound human confirmation and remains distinguishable from satisfaction.
- [ ] Terminal criterion intent changes require reopen; evidence correction preserves terminal history under explicit authority.
- [ ] Expected-version/idempotent/concurrent operations produce one exact event/projection history.
- [ ] Criteria/evidence/waiver Views and APIs are Repository-scoped and redact unsafe locator/content details.
- [ ] Focused behavior/PostgreSQL/concurrency/API tests and the canonical build pass.
