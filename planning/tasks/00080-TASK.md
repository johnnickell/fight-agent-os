# Complete repository reconciliation and lifecycle operations

## Outcome

Authorized users can explain and conservatively reconcile moved, copied, recloned or source-changed physical repositories, explicitly change source evidence, and archive or restore a registration while preserving every stable identity, link and history and deleting no local or Planning data.

## Scope

- In scope: Complete accepted matching decision table; `ExplainCheckoutMatch`; existing-link/shared-common-directory resolution; unique-source proposals; moved/unavailable/recloned/copied/conflicting-marker/fork/upstream/missing/changed-source outcomes; confirmed `RelinkCheckout`/`CheckoutRelinked`; marker reconciliation through accepted protocol; `ChangeRepositorySource`/`RepositorySourceChanged`; source-equivalence/fork relationship updates accepted by the model; `ArchiveRepository`/`RepositoryArchived`; `RestoreRepository`/`RepositoryRestored`; lifecycle/availability/history projections; active uniqueness and restore conflicts; downstream-reference/eligibility seams; independent permissions; versioned API/OpenAPI; PostgreSQL/concurrency and direct Git evidence.
- Out of scope: Permanent deletion, automatic relink, source-host mutation, remote edits, branch/worktree creation/removal, filesystem moves, Planning record/archive mutation, context resolution, Runner/Workflow execution, browser UI, new-project creation, migration/cutover and multi-workspace administration.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Explain physical matching | N/A — read-only interaction | `ExplainCheckoutMatch` | N/A — reads emit no Domain event | Safe evidence yields an automatic, confirmation-required or refusal outcome with exact reasons |
| Reconcile a moved or replacement checkout | `RelinkCheckout` | Preview current/history/candidate evidence and impact | `CheckoutRelinked` | Explicit confirmed link changes while Repository/Checkout history remains durable and marker state is recoverable |
| Change source descriptors | `ChangeRepositorySource` | Preview normalized source/equivalence and active conflicts | `RepositorySourceChanged` | Source evidence changes atomically without changing Repository identity or remote configuration |
| Archive or restore registration | `ArchiveRepository`, `RestoreRepository` | Query lifecycle, retained links, active conflicts and known downstream use | `RepositoryArchived`, `RepositoryRestored` | New repository-scoped work is disabled/restored; identity/history/files/Planning remain intact |
| Inspect unavailable registration | N/A — read-only interaction | `GetRepositoryRegistration`, `ListRepositoryCheckouts` | N/A — reads emit no Domain event | User sees lifecycle, designation, availability, evidence conflicts and next authorized action |

## Validation and permissions

Implement the accepted precedence exactly: an existing durable link resolves automatically; worktrees sharing its Git common directory resolve beneath that Checkout; a unique normalized primary/equivalent source can only propose a first/replacement link; fork/upstream, multiple, missing, changed or conflicting evidence requires explicit selection, confirmation or refusal. Directory/slug/name similarity never contributes authority.

Differentiate a moved linked checkout from a new clone, copied repository and linked worktree through Host, common-directory, accepted marker, source and durable history. A normal clone receives new Checkout/Worktree identities after confirmation. A copied or conflicting marker fails closed and cannot steal an existing Checkout. An unavailable path preserves its identity/history and designation record but is not operationally available. Never auto-relink because only one candidate exists.

Relink uses the TASK-00079 confirmation protections and TASK-00077 consistency/recovery protocol, bound to current and candidate evidence, expected revisions and explicit impact. Revalidate approved-root containment and all Git observations. Preserve old safe locators/history; do not rewrite identity. Never move files, change branches/remotes/index/worktrees, overwrite unknown markers or clean the old path.

Source changes use closed typed descriptors and transactionally recheck one-active-registration-per-source. Explicitly distinguish equivalent sources from fork/upstream relationships. Preserve source history and actor/reason; never call a source provider or mutate Git remotes as a hidden side effect. Changed source invalidates stale matching/link proposals.

Archive is a lifecycle transition, not deletion or completion. It disables new repository-scoped Planning/Execution operations through one authoritative active-state contract while preserving identity, sources, Checkout/Worktree links, designation, context/Planning/Execution history and local files. Existing downstream aggregates may remain inspectable according to their own permissions. Restore rechecks active slug/source conflicts and fails safely rather than renaming or merging. Until downstream TICKETs exist, expose the lifecycle/reference capability they must consume without fabricating Planning/Execution records or speculative wrappers.

Require separate server-side permissions for match explanation, relink, source change, archive and restore. Confirmation cannot substitute for permission. Safe responses redact credential-bearing remotes, marker internals, hidden registrations, unnecessary paths, filesystem contents and raw adapter errors. No operation grants Git publication, Planning migration or Agent authority.

## Acceptance criteria

- [ ] Matching produces the accepted automatic/confirmation/refusal outcome for existing link, shared common directory, unique source, fork/upstream, multiple, missing/changed source, move, reclone, unavailable path, copied marker and conflicting marker.
- [ ] Every outcome includes stable safe reasons/evidence and never uses directory, slug or display-name similarity as authority.
- [ ] Relink requires current permission and a fresh exact confirmation, revalidates approved-root/Git evidence, preserves identity/history and follows recoverable marker consistency.
- [ ] A normal clone receives new physical identities; moved links may preserve identity only through explicit valid evidence; copied/conflicting markers fail closed.
- [ ] Source changes preserve Repository identity/history, distinguish equivalence from fork/upstream, and enforce active uniqueness transactionally under competing requests.
- [ ] Archive/restore preserve Repository/Host/Checkout/Worktree identities, links, designation and history and never delete source or Planning data.
- [ ] Archived registrations reject new repository-scoped authority; restore rechecks slug/source conflicts and never silently renames, merges or displaces another registration.
- [ ] Independent permissions protect explanation, relink, source change, archive and restore; stale revisions/confirmations fail closed.
- [ ] API/query projections expose lifecycle, safe evidence, availability, ambiguity and next action without leaking secrets or persistence details.
- [ ] Focused Domain/Application/PostgreSQL/concurrency/API/redaction tests, real Git scenario checks and the canonical build pass.
