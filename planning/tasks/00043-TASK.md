# Deliver the public invitation activation journey

## Outcome

A canonical invitation link opens an accepted responsive React activation route that captures credential material transiently, removes it from visible history before ordinary rendering/navigation, submits a validated password to a versioned API, and atomically activates the pending identity, consumes the grant, and establishes an ordinary memory-token/HttpOnly-refresh session through `AuthenticationService::activate()`.

## Scope

- In scope: Canonical public activation route; pre-render fragment capture/history replacement; client transient credential owner; accessible password/confirmation form and policy guidance; typed activation feature service; versioned JSend Action/DTO/View; shared password/compromised checks; package activation orchestration; ordinary session token/cookie mapping; Origin/Fetch Metadata/JSON/request protections; production activation rate limit; generic invalid/used/expired/replaced recovery; accepted production components/tokens/states; OpenAPI; PostgreSQL race, HTTP/cookie, component/accessibility/redaction tests.
- Out of scope: Public registration, administrator-selected passwords, login/refresh/logout UI, remembered activation session unless separately approved, `/api/v1/me`/dashboard implementation, MFA/passkeys, server-rendering credentials, broad browser automation, and prototype code promotion.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Open activation link | N/A — client bootstrap/navigation | Read configured fragment fields once and validate safe route identity | Client-only history replacement | Credential is held transiently in memory and removed from address/history before normal UI behavior |
| Validate password form | N/A — client usability; server policy remains authoritative | Inspect password/confirmation and display approved guidance | N/A — no domain event | Accessible local feedback avoids submission errors without persisting/logging values |
| Activate pending identity | Explicit Action invokes `AuthenticationService::activate()` after owned policy checks | Resolve user/latest purpose-bound grant, password policy/checker, limiter, and session config | `UserActivated` | Grant consumed, Argon2id password/active authority/session commit atomically; access token/cookie returned safely |
| Recover invalid activation | N/A beyond rejected activation request | Classify only safe generic invalid/expired/used/replaced/throttled outcome | Redacted package failure only | No account state leaks; UI offers safe recovery/contact guidance and clears transient credential |

## Validation and permissions

Invitation URLs use TASK-00040's configured HTTPS origin and fragment placement so browsers do not send credential material in request lines/referrers. A minimal pre-render bootstrap reads only the expected bounded user/credential fields, validates shape, stores them only in an ephemeral in-memory owner, and immediately calls safe history replacement before analytics, remote resources, screenshots, or ordinary route rendering. Never write them to `localStorage`, `sessionStorage`, IndexedDB, Cache Storage, service worker, HTML, runtime config, client cache, error object, telemetry, or intended route.

The form permits paste/password managers/Unicode/spaces, has explicit labels/instructions, confirmation, show-password behavior only if accepted, visible focus, status/error announcements, and no composition-blocking client assumptions. Client checks are usability only. Server independently applies TASK-00039's exact structural and compromised-password policy before invoking package activation. Mark password/credential parameters sensitive and discard references after terminal outcome.

The public JSON endpoint accepts only explicit bounded user ID, activation credential, password, and allowed session option. Unless the accepted handoff explicitly requires otherwise, activation creates an ordinary non-remembered session. Apply accepted exact Origin, Fetch Metadata, content-type, CSRF/login-confusion controls appropriate to this credential-bearing public endpoint and an atomic production rate limit keyed through non-reversible bounded dimensions; never log raw network/email/credential/password keys.

Use `AuthenticationService::activate()` directly for package-owned validation, grant matching/consumption, password hash, authority revision, refresh session, token set, and `UserActivated`. The Action may orchestrate owned password policy before it but cannot duplicate activation invariants. Map access credential only to the shared memory-owned client token seam. Set rotating refresh credential only in the accepted Secure/HttpOnly/SameSite/path cookie; it never appears in JSON or JavaScript. Validate token/cookie lifetime as ordinary session policy and reuse this response boundary in TICKET-00017.

Invalid/malformed/unknown/used/expired/revoked/replaced grants and raced user/grant state return one generic recovery class without identity existence/lifecycle detail. Password policy feedback may identify unmet password requirements without confirming account state beyond possession flow. Clear transient credential on success or terminal failure.

Recreate TASK-00035's accepted design in production components; do not copy `.runs/prototypes/`. Include narrow/wide, system/light/dark, loading, policy validation, compromised password, generic failure, expired/recovery, conflict, throttled, and success states. No end-user permission beyond valid grant possession applies; server activation authority remains package-owned.
