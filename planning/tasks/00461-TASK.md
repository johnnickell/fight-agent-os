# Provide private Loki ingestion with truthful receipt contracts

## Outcome

The installation has a qualified private Loki persistence/ingestion boundary that supplies precise dispositions to
TASK-00459 without waiting for completed native Logs. This is approved slice A of [TICKET-00113](../tickets/00113-TICKET.md),
not proof that HTTP acceptance means durable search or verified archival.

## Scope

- In scope: Exact backend/image/storage/security/license adoption, private TSDB/persistent WAL integration, scoped
  credentials/accounting, native ingestion/identity/visibility contracts and existing-owner lifecycle hooks;
  qualification of partial/rejected/uncertain writes and actual storage/resource behavior.
- Out of scope: Collector/queue replacement, browser APIs/UI, independent archive/catalog implementation, a generic
  backend proxy, another hold authority, automatic service enrollment and a new experiment grant.

Consume [WF-040's accepted composition](../wayfinder/tickets/WF-040-select-the-log-search-backend.md#accepted-resolution--conditional-planning-selection)
and [the Loki reconciliation](../wayfinder/research/loki-integration-reconciliation.md). Conditional Loki OSS is a
planning selection: pin and qualify the actual supported release/image and private S3 integration. Reuse the existing
storage installation only where its exact contract succeeds; the old filesystem probe is not production approval.
Keep Loki chunks/indexes/WAL separate from verified operational archives and authoritative Artifacts by credentials,
namespace, lifecycle and measured physical accounting. Runtime files belong under ignored `var/`, not `.runs/`.

Consume TASK-00455's native framing/identity contract. Preserve exact emitted content/provenance in the qualified
envelope despite metadata normalization; retain original collection/event clocks and distinct same-time identities.
Provide TASK-00459 precise acceptance/partial/rejected/uncertain dispositions and actual visibility checks. Qualify
mixed-batch survivors, HTTP 260/other successful-looking ingestion blocks, lost responses, WAL ENOSPC and restart.
Generic 2xx is not all-record durability; expose remaining uncertainty and retry multiplicity without exactly-once
or content/timestamp deduplication claims. Larger records use qualified framing, never silent truncation.

Expose only internal owner-controlled lifecycle participation. Disable autonomous age TTL that could bypass holds;
zero backend age retention is not unlimited application retention. TICKET-00114 owns original-clock eligibility,
hold/grace/purge/late-ingest/policy fences throughout asynchronous deletion. Qualify this adapter's participation
and requested/processed/reclaimed distinctions with that owner, not a precheck or cancellation window masquerading
as protection. Unknown authority blocks unsafe cleanup, while finite admission still prevents unlimited growth.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Accept enrolled collection work | Private bounded backend ingestion only | Original identity/framing and precise native result | Destination observation, not Workflow or archive receipt | Persisted/accepted/rejected/uncertain work according to qualified evidence |
| Inspect actual query visibility | Internal bounded verification/read contract | Exact submitted identities and permitted scope | N/A | Visibility is distinguished from intake and durability |
| Recover backend storage | Existing authorized bounded recovery operation | Actual WAL/index/storage state and surviving records | Recovery/uncertainty observations only | Honest surviving coverage, not host-loss or infallible WAL claims |
| Participate in owner cleanup | Existing owner-authorized fenced deletion | Current owner operation/fence and actual reclamation | Existing lifecycle facts, no new hold authority | No autonomous expiry or protected sole-copy deletion |

## Validation and permissions

Backend credentials remain in private adapters/enrolled delivery, never browser or Agent configuration. No arbitrary
caller tenant, LogQL, push/delete/flush URL, object key or Docker capability is exposed. Bound actual requests and
resource use under WF-038 and the installed runtime profile. Preserve private transport and required cross-host TLS;
no authentication bypass as an outage fallback. Raw diagnostics remain private and are not pipeline-redacted.

Follow ADRs [0001](../adr/0001-application-ownership-and-orchestration.md) and
[0002](../adr/0002-postgresql-consistency-and-durable-effects.md): external backend effects are outside business
transactions and do not certify evidence/Workflow state. Existing preservation/storage owners remain authoritative.

## Acceptance criteria

- [ ] Exact images, licensing/security/provenance, supported private storage, credential isolation and enforced
  WAL/index/chunk/compaction resource limits are qualified in the existing installation boundary.
- [ ] Actual native ingestion preserves accepted content/identities/clocks; partial batches, HTTP 260, normalization,
  WAL faults and lost acknowledgements have truthful dispositions, never generic-success durability claims.
- [ ] Restart and visibility checks distinguish known surviving data from missing/uncertain coverage; old small-probe
  results are not substituted for this integration's fresh evidence.
- [ ] Actual backend lifecycle hooks participate in the existing owner's asynchronous hold/purge/late-ingest/policy
  fence, disable unsafe autonomous TTL and expose bounded admission and physical cleanup progress.
- [ ] TASK-00459 can consume this early interface without browser/whole-TICKET completion; direct provider/storage
  qualification, owned adapter behavior checks and full `./bin/build` pass with disclosed limits.

## Verification and evidence

Use manifested safe data with native levels, ties, equal legitimate records, malformed/binary/large fragments and
mixed valid/rejected batches. Directly qualify the selected provider/storage, restart, resource and asynchronous
cleanup mechanisms with owning tools; test owned adapter/disposition/fence integration, not configuration text or
vendor internals. Verify actual preserved bytes/identities and characterize acceptance versus visibility/durability.
Controlled failures require separately bounded targets/resources/effects and cleanup authority; never stop unrelated
services. Record versions, counts, uncertainty, measured physical use and warnings; run focused wrappers and full
`./bin/build`. Planning approval neither installs images nor authorizes live ingestion.
