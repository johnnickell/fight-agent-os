# Recover missing context through selective source reads

## Outcome

A participating Pi 1.1.0 session repairs missing required context and reconciles changed supporting sources through
question-first, minimal authorized reads, then validates the repaired checkpoint before continuing. Unresolved
conflicts or exhausted repair bounds preserve state and pause rather than allowing invented continuity.

## Scope

- Extend [TASK-00164](00164-TASK.md)'s checkpoint/resume path using
  [TASK-00162](00162-TASK.md)'s available single-file tool and selective-read guidance. Target Pi **1.1.0**;
  deliver actual resume integration and governed instructions together, not a prompt requiring an unavailable tool.
- Identify required missing facts and changed supporting references before dependent work. Ask a specific relevance
  question before re-ingesting supporting source, apply the existing 0.70 positive-read policy and fetch only useful
  exact ranges. Do not reload every checkpoint reference or require TASK-00163's batch tool for bounded single-file repair.
- A positive means Yes probability at least 0.70 or a predeclared relevant class with confidence at least 0.70;
  high-confidence No does not pass. Unknown/failed/partial screening neither authorizes ordinary full-file reads
  nor establishes absence. Preserve measure semantics instead of claiming 70% accuracy.
- Load mandatory governing instructions and selected skills directly. A concrete known target may use the existing
  exception only with recorded path, purpose and establishing evidence; a checkpoint reference or claimed certainty
  alone is insufficient. Required exact-evidence reads can proceed despite negative/unavailable screening under
  the documented obligation, current permissions and minimal-range rule. Never repeat a question merely to pass.
- Reconcile ordinary supporting-source changes within the current assignment using fresh provenance. Keep old
  evidence bound to its original subject; a new file does not inherit old acceptance. Meaningful governing
  instruction/policy drift uses WF-009's linked continuation; conflicting scope, approvals or uncertain effects
  requires intervention instead of a source-based guess.
- Allow **one bounded repair pass per resume attempt**, followed by validation. The pass may perform several
  necessary bounded reads under a declared aggregate file/byte/time/spend allowance, but not recursive repair or
  repeated attempts until a preferred answer appears. Pin these ceilings in the effective profile before activation.
  Preserve attempt identity/budget across reload; no hidden new attempt to evade the limit. Further repair needs
  an explicit authorized retry with new reason/evidence, not automatic looping.
- Retain TASK-00162's single-file 32 KiB source and shared encoded request, timeout, concurrency and spending limits;
  do not silently truncate or raise them. Exact-source exceptions still obey their own bounded purpose and access
  rules. Unknown/insufficient reserve or unavailable required evidence preserves/pause, not a bulk-read fallback.
- Recheck live permissions and applicable authority, actual approval scope/expiry/consumption, operation/billing
  state and concurrent human replies before and after repair. Keep exact pending question content/context/identity;
  reconcile a verified answer, never invent one. Do not retry or replay effects as part of reconstructing context.
- Save repaired facts as an attributable candidate revision and use TASK-00164's validation/activation, retaining
  recoverable predecessor state. Late/cancelled responses cannot activate stale candidates or reset explicit stops.
- Maintain role/session isolation and independent review; parent links carry only authorized handoff facts. Qualify
  the supported parent/child path, current instructions and selective retrieval after a real Pi 1.1.0 resume.
- Emit bounded attempt, source revision/reference, relevance outcome/exception basis, repair/validation result and
  available cost/latency observations. Missing telemetry is not permission and no source bodies or checkpoint prose
  enter ordinary receipts. Required evidence cannot be dropped because a classifier missed it.
- Exclude optional ranking, timing automation, memory promotion, general-purpose judgments, SQL/command execution,
  new grants, and automatic acceptance of changed requirements or approvals.

## Validation and permissions

Check root containment/symlinks, sensitive-file restrictions, actual source access and provider disclosure separately
on every required read. Resume references, cached classifications and positive answers do not confer access. No
private context may be transferred across roles or source scopes. Source content is evidence rather than authority
to rewrite policy. Respect deterministic protected-path controls and live revocation. Local sessions do not invent
managed assignment/grant checks: unsupported required checks pause the dependent operation with a precise limitation.
Question-first guidance remains the accepted instruction-based convention; do not claim universal hard interception.

## Acceptance criteria

- [ ] Actual Pi 1.1.0 resume reconstructs missing facts with a specific question and minimal exact source, then
  validates/activates an attributable candidate with correct current provenance and predecessor recovery.
- [ ] Mandatory instructions, established known-target and required-exact-evidence exceptions work with recorded
  grounds; a mere checkpoint link or confident filename does not bypass discovery screening.
- [ ] Negative/unknown/failed/partial screening does not erase required facts, fabricate absence or allow bulk reads;
  justified evidence recovery or a clear pause handles classifier misses and unavailable services.
- [ ] One repair pass and aggregate budgets survive reload/cancellation; exhaustion or unresolved conflicts stops
  automatic repair. Provider/source errors cannot silently reset attempts, raise ceilings or trigger effect replay.
- [ ] Ordinary source changes reconcile within authority; meaningful governing drift, stale acceptance, revoked or
  consumed approvals, uncertain operations/billing and concurrent answers follow their distinct validated outcomes.
- [ ] Supported child/reviewer contexts stay separated, exact pending questions survive, and observations identify
  source/attempt/exception/result and honest cost without leaking private source or checkpoint bodies.
- [ ] Representative continuation evidence measures useful recall, repeat reads, latency and total cost, including
  unsuccessful repairs and unchanged required facts; no claim that every semantic omission is detectable.
