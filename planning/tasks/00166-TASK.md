# Recover missing context through selective source reads

## Outcome

A resumed Fight Pi session can repair missing required facts and reconcile changed evidence through bounded
authorized reads. It validates the repaired state before dependent work continues.

## Scope

- Consume TASK-00164's resume contract on the installed supported Pi runtime. Identify the missing fact or
  changed evidence first. Use native structural search and minimal exact-source reads under current permissions.
  Load governing instructions and selected skills directly. Avoid bulk rereads or re-ingesting private context
  across roles. Repair has no Jev dependency.
- Reconcile ordinary source drift within the current assignment and bind fresh evidence to its actual revision.
  Material governing instruction or policy drift uses WF-009's linked continuation. Conflicting authority,
  pending replies and uncertain effects require reconciliation through their owners.
- Allow one bounded repair pass per resume attempt and then revalidate. Bound files, bytes and time. Preserve
  pending work and pause if required facts or authority remain unavailable. An explicit retry needs new grounds.

## Acceptance criteria

- [ ] Missing facts and changed supporting sources can be repaired using minimal native reads without Jev.
- [ ] Denied, corrupt, missing or conflicting evidence leaves a truthful held outcome. No retry loop, bulk
  reload, authority change or uncertain effect replay occurs.
- [ ] A repaired session continues with validated current evidence and exact pending questions. Reload cannot
  silently multiply the repair budget or restore obsolete approvals.

## Verification and evidence

Exercise the normal resume path with a recoverable missing fact, changed source, denied access and interrupted
repair. Qualify the installed runtime and record the bound and resulting read coverage. Keep protected evidence
under its existing access controls and run the applicable gates.
