# Adopt Common failures and cut HTTP error handling over end to end

## Outcome

Replace duplicate generic failures and HTTP error machinery with qualified canonical Common contracts across the
live application boundary and its actual clients. This is the complete cutover of
[TICKET-00136](../tickets/00136-TICKET.md), normally one PR: dependency qualification, throwing/catching consumers,
Slim integration, safe projections/diagnostics, direct failure responders, structured validation, client decoding,
OpenAPI/docs, verification and obsolete-path removal move together. Layer-only PRs would require dual formats or
competing classifiers. This is not a new generic error framework or a package-update-only prerequisite.

## Scope

- Qualify actual supported tagged Common Application failure and safe HTTP APIs, source/signatures, transitive
  requirements and real Agent OS composition. Deliberately update manifest/lock and record exact selected evidence.
  The inspected local v1.4.0 tag/source is a candidate, not distribution/runtime qualification. Current Access
  Control's ^1.3 Common constraint permits that minor; actual dependency resolution and compatibility still need proof.
- Inventory all current generic local failures and their throw/catch/presentation callers. Replace duplicated
  AuthenticationRequired, PermissionDenied, ResourceNotFound, StateConflict and RateLimited vocabulary directly with
  fitting Common categories, including RateLimitExceeded's validated retry hint. Reconcile other consumed shared
  absence/gone/precondition/input/rule/unavailable/server intents where real use requires them, not guessed codes.
- Retain a specific local failure only for a useful actual contract, such as typed partial-invitation information
  or a safe password-field projection. Keep Domain exceptions Domain-owned; translate known outcomes at their
  justified owner without Domain-to-Application imports. Wrong identity/result contracts, unknown storage faults
  and programmer failures must not be guessed into not-found/conflict/rule refusal.
- Compose SafeJSendErrorMiddleware and its qualified SafeHttpErrorPolicy, SafeHttpProjector and
  SafeHttpDiagnostics contracts as the one generic public HTTP error handling/reporting path. Replace
  ApiFailureMapper, MappedApiFailure and superseded ApiFailureMiddleware branches/tests after replacement proof;
  no copied policy, catch-all native exception-code mapper, legacy fallback classifier or compatibility alias.
- Qualify actual Slim last-in-first-out invocation, API scope and routing/admission/validation/Action coverage,
  including routing misses/method rejection. Keep only necessary adapter-only protocol translation from explicit
  supported native/package failure types. Document uncovered/non-API/startup/broken-factory boundaries honestly;
  an outer fallback must not become a second reporter or expose private diagnostics.
- Preserve independently validated correlation on successes/errors and no-store behavior, including safe fallbacks.
  Deliberately supply appropriate 401 authentication challenges, exact 405 Allow and validated 429/503 Retry-After.
  Publish only intentional protocol metadata, not arbitrary exception headers. Retry hints never authorize command
  replay, automatic mutation retry or a rollback claim.
- Use one redaction-aware diagnostics sink. Common offers each handled Throwable once; any expected-failure
  filtering happens inside this sink. Only allowlisted/validated bounded metadata reaches logger formatters, never
  the raw Throwable, request, credential, diagnostic message/cause/trace or private validator map. Reporting failure
  cannot be called successful reporting; use Common's nonrecursive safe fallback behavior.
- Public projections use independently authored messages/field data and accepted plain JSON values, not entities,
  arbitrary objects or JsonSerializable callbacks. Preserve structured safe field errors and declared public form
  allowlists; do not flatten them into a generic category or publish raw getErrors(). Distinguish actual malformed/
  unusable input from deliberate business/password-rule rejection under the agreed 400/422 contracts.
- Reconcile every affected response producer, including direct SessionLifecycleResponder, SessionRevocationResponder
  and Role mutation responses rather than only thrown exceptions. Preserve refresh/logout cookie clearing, terminal
  versus unavailable meaning, current-session guidance, partial/uncertain outcomes and ordinary success behavior.
  Do not silently drop these transport effects by moving response construction into generic middleware.
- Deliberately switch expected 4xx refusals to Common fail shapes and server/unavailable outcomes to error shapes.
  Preserve useful partial-invitation data under the agreed 503 error envelope. Replace top-level diagnostic-code
  coupling such as current-session code 5801 with an explicitly authored safe public intent contract; a private
  exception code is never a public discriminator.
- Update ApiClient/decodeResponse/ApiResult, relevant feature decoders/forms/pages/fixtures, API schemas/headers,
  generated OpenAPI/validation representations, actual callers and current docs together. Preserve strict envelope/
  status/data agreement, bounded safe field handling, client-owned display text and no automatic mutation retries.
  No permissive old/new response mode, arbitrary server-message display or wholesale frontend redesign.
- Keep Console parsing/redacted failure output/exit handling transport-appropriate through shared-category adoption;
  no HTTP Response/status objects inward. Remove superseded local exceptions/projectors/classifiers/middleware
  paths/tests once their real replacements work, retaining only genuinely owned transport/data contracts.

Excludes upstream implementation/releases, new endpoints or permissions, MCP/OAuth/HMAC qualification, whole-domain
exception replacement, new product journeys and the capability-specific query/use-case repairs owned by
TICKET-00134/00135. No business schema/data transition is expected; preserve needed history if actual consumer
changes reveal one. Error presentation does not mutate business state or establish that an earlier effect rolled back.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Existing operation intentionally refuses or reports required absence | Existing owning command/method; no new business intent | Existing required/optional read with its real contract | None invented by error handling | Canonical neutral intent, agreed safe HTTP shape/metadata and one diagnostic path |
| Internal/unknown Throwable reaches covered HTTP boundary | Existing invocation only | Existing invocation only | None | Safe server error and one redacted reporting attempt, never inferred rollback |
| Browser receives refusal/field/partial/current-session outcome | N/A; presentation/decoding | N/A; presentation/decoding | None | Safe consistent result/fields/guidance, correlation/cache/cookie semantics; no automatic retry |
| Diagnostics/projector/response creation fails | N/A; technical fallback | N/A | None | Common safe fallback, no recursive reporting; sanitized escape if factories cannot create a response |
| Console receives shared category or unknown failure | Existing Console intent only | Existing actual inspection if needed | None from presentation | Appropriate redacted output/exit behavior, not HTTP mapping |
