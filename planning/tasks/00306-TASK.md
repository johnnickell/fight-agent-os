# Add a local build coordinator through automatic PR publication

## Outcome

Remove the concrete local delivery blocker of manually relaying work/review/QA/land between agents. One `build`
invocation gives a Team Lead responsibility for one approved TASK through a human-reviewable open PR with
applicable screenshot evidence. This supports EPIC-00008 without claiming its managed Workflow is implemented.

## Scope

- In scope: Fresh project-local Pi skill, documented fresh-process dispatch using installed Pi CLI, one-TASK
  resolution from TASK/TICKET input, role/evidence gates, bounded repairs, automatic authorized land, usage docs
  and `next` defaulting executable implementation/repair recommendations to `build`.
- Out of scope: Imported Factory code, global setup, mandatory subagent extension, managed credentials/claims,
  Pi Durable adoption, browser coordinator UI, multi-TASK pipelines, merge/release/deployment and unrelated planning.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Start and delegate | `/skill:build TASK-NNNNN` or unambiguous TICKET input | Approved scope, readiness, checkout and Pi capabilities | Local ledger only | Fresh Engineer, Reviewer, QA and Release Manager processes |
| Repair or recover | Existing `work`/`review`/`qa` operations under Lead routing | Canonical current reports, exact source, process/effect state | Local finding dispositions | At most five shared repair cycles or explicit incomplete hold |
| Publish | Existing `land` within invocation authority | Accepted subject, QA, PR ownership, remote head and capture access | Existing local delivery receipts | Non-force push and one open PR with accessible applicable evidence |

## Validation and permissions

The maintainer selected the current worktree for this implementation and authorized separate commits. Do not use
TASK-00080, modify TICKET-00080's ongoing decomposition or publish the shared planning branch as a trial. Future
`build` invocations carry publication authority for their selected TASK; child roles cannot expand it. Team Lead
does not implement, accept its own work, turn missing evidence into PASS or merge. Local process separation is not
OS sandboxing, managed identity or deterministic enforcement. No extension is needed if Pi's fresh-process CLI
qualifies; document any missing coordination capability instead of installing a package implicitly.
