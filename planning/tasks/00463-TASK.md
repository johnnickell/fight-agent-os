# Search current logs in the native workspace

## Outcome

A currently authorized operator searches real captured operational logs through the native shell, with whole-window
literal matching, exact filters, tie-safe traversal and honest coverage. This is approved slice C of
[TICKET-00113](../tickets/00113-TICKET.md), the complete API-to-browser search path rather than a fixture-only screen.

## Scope

- In scope: Intent-specific private search/coverage queries, current authority/disclosure checks, typed provider
  translation, shared bounded read admission, protected Logs route/navigation, live result/filter/time presentation,
  volatile client state, safe errors and accessible bounded interaction.
- Out of scope: Context/raw continuation, tail, failure/run entry links, restore/export/download operations, another
  Dashboard, arbitrary LogQL/tenant/admin proxy, browser-to-Loki access, pipeline redaction or persisted searches.

Follow [WF-041](../wayfinder/tickets/WF-041-select-the-authorized-log-browser-integration.md). Application owns current
authorization, scope/retention eligibility and typed bounded queries; Adapter owns private credentials/provider
translation. Search the complete selected server-side scope, not loaded rows. Preserve exact eight Monolog levels
plus unknown; All includes DEBUG. Default to trusted collection time with labelled event time/precision; the initial
15-minute view cannot truncate the allowed 14-day window. Optional event-time filtering never bypasses collection-
clock eligibility. UI filtering changes neither capture nor original content.

Use stable observation/source identity and policy/scope/filter/time/direction-bound cursors. Same-time distinct and
identical legitimate messages remain discoverable; timestamp+1ns skipping or sorting only a truncated page cannot
claim complete traversal. Expose late/unstable coverage honestly. Missing complete bounded traversal is a delivery
blocker, not permission to ship silent omissions.

Bound requests to 16 KiB including 4 KiB UTF-8 literal search, operations to 30 seconds and pages to 500 events/1 MiB.
Enforce two active read/export operations installation-wide across live/restored scopes, one/requester, with no
unbounded queue. Count abandoned work until cancellation/completion is confirmed; per-process counters do not enforce
aggregate limits. Supply this shared admission/query/current-authority contract for later restore/extraction, without
implementing those operations now. TICKET-00116's approved split additionally places archive downloads in these
same two installation-wide slots and one/requester limit, not a separate pool. TASK-00478/00479 own transfer-specific
accounting and qualification; this early admission supplier does not depend on their completed extraction journeys.

The view retains at most 2,000 observations/8 MiB encoded including future details/paused backlog and renders at most
200 rows, with bounded accessible navigation. Show installation-wide log-access scope, source/generation, time basis,
freshness and known loss/unknown coverage. Distinguish loading/empty/denied/busy/partial/purged/unavailable only when
authorized to know the target; backend failure is not empty success. Reuse the frame/theme and one `/me` owner.

## Validation and permissions

Require current `READ_LOGS`, actor/session validity and applicable source/time/disclosure policy before fetch and
again before private release. Unknown authority withholds data. The existing API guard's cached request principal
is insufficient evidence of a fresh release check: reuse the owning authoritative resolver with real revalidation,
not a second permission store or repeated checks of the same snapshot. Participate in the current purge/disclosure
owner fence and distinguish already released/in-flight bytes, which cannot be recalled.

Follow ADRs [0001](../adr/0001-application-ownership-and-orchestration.md),
[0003](../adr/0003-browser-authentication-security-profile.md) and
[0004](../adr/0004-client-authority-and-runtime-state.md). Use authenticated same-origin/applicable-CSRF transport,
no-store and the sole volatile principal/cache/evaluator. Gate loaders and rendering; clear data on refresh/logout/
invalidation/expiry/identity/scope changes and reject late successes/errors. Client 60-second freshness is not server
authority caching. Put sensitive text in bounded bodies, not URLs/history/referrers/telemetry or logged query payloads;
producer activity logging selects safe metadata rather than pipeline-redacting search text after emission.

## Acceptance criteria

- [ ] Actual captured records reach protected native search through the real private query path; all exact levels,
  whole-window literal search, source/time/relationship filters and same-time traversal satisfy the contract.
- [ ] Every fetch/release validates current authority/policy; controlled permission/session/purge races and unavailable
  authority deny unsafe disclosure without existence/count leaks or role-name bypasses.
- [ ] Shared admission, encoded bounds, deadlines and cancellation accounting hold across concurrent processes and
  requesters; missing tie-safe traversal or unsupported backend scope cannot be labelled complete.
- [ ] Sensitive text/content stays out of URL/history/telemetry/logged payloads; no-store, volatile state and
  generation fences prevent stale private data returning after authority changes.
- [ ] Real keyboard/focus, non-color severity, reduced motion, bounded announcements, light/dark/zoom/narrow layouts
  work with measured browser/process resources; placeholders do not constitute production acceptance.
- [ ] Owned API/client/authorization/concurrency tests, direct backend/transport checks and full `./bin/build` pass;
  WF-042's healthy search objective is measured with counts, clock basis and volume rather than asserted.
