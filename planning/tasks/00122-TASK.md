# Authorize cross-user session inspection and revocation

## Outcome

An installation operator separately authorized to read or revoke another user's active sessions can do so only after current target-sensitive package authorization, without broadening self-service or exposing credentials.

## Scope

- In scope: `GET /api/v1/users/{userId}/sessions` with `READ_SESSIONS` and `DELETE /api/v1/users/{userId}/sessions/{sessionId}` with `DELETE_SESSIONS`, FQCN Actions, package `ListActiveSessions`/`RevokeSession`, actor/target callback, reasoned audited revoke, safe no-store Views/OpenAPI and session authority invalidation.
- Out of scope: Logout everywhere, self-service endpoint reuse as admin bypass, raw refresh credentials, editing session lifetimes, workspace/repository-scoped admins before an explicit target policy.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Inspect other user's sessions | None | `ListActiveSessions` with actor and explicit user after authorization | None | Bounded credential-free page for exactly one permitted target |
| Revoke other user's session | `RevokeSession` with actor/target/reason | Resolve package target/usable session state | Package revocation and durable safe audit | Only requested session revokes; target access fails closed immediately |

## Validation and permissions

Use the early route gate plus Agent OS Application exact `SUPER_ADMIN_ONLY` `READ_SESSIONS` or `DELETE_SESSIONS` on every entry. The package's retained `SessionAdministrationAuthorization` callback asks Agent OS whether this actor may act on this user/target; reject before or at the package boundary if target is out of scope. It is not a redundant handler permission check. Require nonempty bounded administrative reason for deletion and safe audit; do not accept actor/current session or authority from body. Nonexistent/cross-user/expired/revoked target outcomes must not leak another user's session data. Self-session `READ_OWN_SESSIONS`/`DELETE_OWN_SESSIONS` cannot access these paths, and current-session logout remains separate.

## Acceptance criteria

- [ ] Read and revoke require distinct current permissions plus package actor/target authorization; role names/JWT/client state alone grant nothing.
- [ ] Package query/revoke and confirmed reasoned audit expose only permitted target and credential-free Views; actor cannot be overridden by request.
- [ ] Self endpoints remain owner-only; stale/forbidden/unknown target and competing revocation return safe outcomes and no unauthorized dispatch.
- [ ] Target token/refresh authority fails immediately on committed revoke; full focused HTTP/PostgreSQL/race/redaction checks and `./bin/build` pass.

## Verification and evidence

Test self, other, unknown, expired/revoked and concurrently rotating sessions, separate permissions, missing/malicious reason, scoped-callback denial, stale authority and next-request token failure. Inspect no-store View, package callback invocation, durable audit and safe error class; run focused checks, `./bin/planning-check`, `git diff --check`, `./bin/build` and record fresh evidence/warnings.
