# Add clear-answer and simplification skills with consistent testing guidance

## Outcome

Make project assistance easier to understand and give maintainers a focused way to remove unnecessary code,
prose and tests. The maintainer approved this scope, isolated worktrees, independent review/QA, commits,
push and PR publication to project default branches on 2026-11-12. Human merge remains separate.

## Scope

- Add `what`, `ask`, `ci`, `handoff`, `learn` and `simplify` only to Agent OS `.pi/skills/`, and register their
  existing inspect/scratch effects with the Pi Harness.
- Apply plain-language output and test-quality guidance through existing owners. Require 100% Unit-only line
  coverage, useful assertions, testable DTO contracts, proportionate suite balance and focused mutation analysis.
- Preserve merged build-cache and validation-simplicity work. Keep current gate enforcement gaps explicit.
- Companion PRs align guidance in Common, Access Control, five framework starters and the existing future-test
  guidance in Financial, Home and Social. Omphalos is excluded by the maintainer.
- No application refactor, test deletion, coverage-engine change, new quality framework, dependency installation
  policy, global skill install, merge or deployment is part of this rollout.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Understand an answer or project | Pi `what`, `ask`, `learn` skills | Bounded current-source reads when needed | N/A | Chat answer; requested lesson artifact only |
| Diagnose CI | Pi `ci` skill | Selected job/log/revision reads | N/A | Diagnosis and existing Fix/Work handoff |
| Continue work | Pi `handoff` skill | Current session and evidence reads | N/A | Chat handoff; requested ignored artifact only |
| Simplify a selected boundary | Pi `simplify` skill | Scoped code/prose/test assessment | N/A | Findings; authorized edits retain Work ownership |

## Validation and permissions

Descriptions must distinguish these skills from next, architecture, fix, work and independent review/QA.
Rewriting preserves uncertainty and requirement strength. Unknown CI failures stay unresolved. No skill
implicitly installs tools, sends messages, creates tracking records or promotes source-write authority.
Target project instructions own gates and data boundaries. Application/API security changes are N/A.
