# Deliver independently authorized self-profile read and rename Tools

## Outcome

Expose the package's `agent.profile.read` and `agent.profile.update` through the real protected MCP boundary,
with separate explicitly granted managed Permissions and principal-only targets. Fresh minimal reads and
name-only updates never become credential/Permission management or access to another Agent.

## Scope

- In scope: Package `GetAgentProfileTool`, `UpdateAgentProfileTool`, query/rename handlers and safe failure mapping;
  stable managed `ADMIN_SAFE` profile Permission definitions/code references; current direct-path protection,
  request-bound composition, exact minimal response and package publication/failure semantics.
- Out of scope: Administrator Agent UI, automatic grants or template drift repair, new profile fields, direct
  Permission/credential changes, duplicated rename policy, generic self-service identity endpoint or new MCP server.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Read own profile | None beyond request authentication's separate nonce write | Package `GetAgentProfile` targeting only resolved principal ID | None for profile read | Fresh ACTIVE minimal `{agent_id, name}`; missing/revoked are equally unavailable |
| Rename own Agent | Package `UpdateAgent` through synchronous void dispatch, principal ID/typed initiator | No compensating read in the Tool | Existing `AgentNameChanged` after committed real change only | Name-only mutation or validated no-op; acknowledgement describes normalized requested name, not guaranteed latest state |
| Reconcile profile definitions | Existing complete managed-policy preview/reconciliation using fixed generated identities | Current complete policy and code references | Existing package policy facts only | Two managed `ADMIN_SAFE` definitions, no automatic Role/Agent assignment |

## Validation and permissions

Use package `AGENT_PROFILE_READ` and `AGENT_PROFILE_UPDATE` independently; neither implies the other. Generate two
distinct IDs once with the owning ID factory during authoring, fix them in version control and merge definitions
and code references into the complete policy without dropping existing Permissions/Roles. This approved extension
does not silently rewrite TASK-00036's historical exact catalog. Explicit grants use existing current authorized
assignment and tier fences; definitions, discovery and invocation never grant themselves.

Both Tools share the exact request-bound provider/request/correlation with TASK-00245 availability. Rebuild registry/
catalog when rebuilding these Tools; never reuse a catalog against a new registry. Enforce current scope as well
as exact direct Permission before schema validation, lookup, dispatch or progress. Protect generic query/rename
entry points and direct bus callers too; typed initiator is provenance, not authority.

Read accepts only an empty object; update accepts only string `name`. Reject caller Agent ID, initiator, credential,
Permission/lifecycle fields or any additional property. Package `AgentName` owns rename normalization/length rules;
do not substitute provisioning-name canonicalization. Query reads current ACTIVE storage, not principal name cache;
repository failure is not absence. Rename enforces current ACTIVE/cohort/correlation even for no-ops and preserves
all credential/Permission state. No-op and real-change acknowledgements are identical; only a change emits the event.

Expose exactly ID/name structured output and Common-derived text. Any dispatch failure prevents success output;
a post-commit publication failure does not imply rollback. Reconcile through a separately authorized fresh read,
not automatic replay/compensation. Use package exact-class safe failure mapping and sanitize real outer responders,
diagnostics and generic command-failure subscribers without original throwable text or material leakage.

## Acceptance criteria

- [ ] Stable generated Permission definitions/code references merge into the complete managed policy without
  changing unrelated authority or granting any Agent implicitly; explicit read/update grants remain independent.
- [ ] Real authenticated MCP read and rename target only the principal, reject extra authority fields and return
  exactly minimal ID/name; permission denial occurs before protected work and cannot reveal target existence.
- [ ] Reads observe fresh ACTIVE state; changed/unchanged renames obey package normalization, event and timestamp
  rules. Credential correlation/direct grants remain unchanged and alternate generic paths enforce current policy.
- [ ] Concurrent rename, revocation after admission, no-op on inactive state, rollback and committed-publication
  failure yield honest safe results; acknowledgement is not falsely presented as the latest stored name.
- [ ] Next-request revocation or Permission removal denies even with retained Tool metadata; request lifetimes,
  actual logging and command failure boundaries disclose no secret or private diagnostic state.
