# Establish event-sourced Wayfinder planning authority

## Outcome

Agent OS can create and inspect Project-owned Wayfinder maps and tickets through authoritative semantic event streams, transactionally current constraints and rebuildable read projections, establishing the shared Planning event, identity, reference and concurrency foundation without a generic document aggregate.

## Scope

- In scope: Fight Common event-store contract qualification/composition; Planning event envelopes and content payload/digest handling; adapter-generated typed COMB identities in void commands; Project-unique mutable map slugs; immutable atomic WF references; per-stream expected versions; command/causation provenance; required audit; transactional stream append, reference allocator, parent/slug constraint and required current projection; optional snapshots as cache only; rebuildable map/ticket detail, hierarchy and history Views; `CreateWayfinderMap`/`CreateWayfinderTicket` and typed creation events; authenticated actors/correlation; view/create Permissions; PostgreSQL migrations/repositories/concurrency; versioned API/OpenAPI.
- Out of scope: Generic document/update events, decision-point editing, synthesized resolution, dependency changes, closure/archive, ResearchNote/Prototype, EPIC/TICKET/TASK, queue/priority, migration/import, browser UI, asynchronous search infrastructure and full emergency-redaction operation.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Create a Wayfinder map | `CreateWayfinderMap` | Preview Project, slug uniqueness and initial destination/done condition | `WayfinderMapCreated` | One stream, internal identity, slug constraint and current projection commit atomically |
| Create a Wayfinder ticket | `CreateWayfinderTicket` | Preview active map, reference allocation and initial question/boundary | `WayfinderTicketCreated` | One immutable WF reference, child stream, parent/allocator constraints and projections commit atomically |
| Inspect current hierarchy | N/A — read-only interaction | Get map/ticket detail and Project map hierarchy | N/A — reads emit no Domain event | Authorized typed Views come only from rebuildable projections |
| Inspect history | N/A — read-only interaction | Get stream version, semantic events and safe provenance | N/A — reads emit no Domain event | Authorized history explains identity, actor, command and revisions without becoming authority |

## Validation and permissions

Use separate `WayfinderMap` and `WayfinderTicket` aggregates and streams. Do not implement a generic Planning artifact/document root or generic update event. Every stream event carries aggregate/event identity, stream version, timestamp, authenticated user/agent/system actor, command/causation identity, correlation/planning-session identity when present, event schema, and content payload reference/digest where applicable. Agents never impersonate users.

Creation entry adapters generate typed IDs through the owning COMB factories and put them into void commands;
aggregates accept them. Maps use a normalized Project-unique slug that may later change semantically and consume
no MAP sequence. Allocate immutable WF references atomically per Project/kind and never reuse allocated values,
including after archive or an abandoned competing create. Return the already known ID after successful dispatch;
fresh authorized queries provide reference/current state. Lost acknowledgement does not promise original-result
replay: another create may conflict; refresh/list/detail reveals authoritative state and identity.

Require an active Project from TICKET-00024. A ticket has exactly one active same-Project map parent. Reject cross-Project parentage, unknown/archived parents, slug/reference conflicts, unsupported schema, malformed bounded content and arbitrary untrusted client IDs/references. The registered aggregate-owned handler uses generic
`TransactionalUnitOfWork` to coordinate collection-like persistence, stream append, required audit, allocator,
parent/slug constraints and current projection on the exact shared connection. Success events dispatch after
commit; post-commit failure is uncertainty, not rollback. Optional display/search projections may lag, but
command-critical constraints may not. Follow the parent TICKET's entry admission and ownership contract.

Expected stream version guards changes where applicable. Stale commands return current version and safe intervening semantic facts without appending, merging or overwriting. Snapshot rows may optimize load only after replay equivalence is proved; event streams remain authority. Projection tables expose no write capability to Domain/Application callers.

Require independent authoritative Permissions to view Wayfinder data and create maps/tickets, admitted by each entry for Workspace/Project before configured bus dispatch. HTTP Actions map input and dispatch;
Responders map explicit safe Views to JSend `snake_case`; errors/OpenAPI follow the shared API boundary. Hide event payload internals, SQL, secrets, unnecessary identifiers and unauthorized Project existence.

## Acceptance criteria

- [ ] Separate WayfinderMap and WayfinderTicket roots use authoritative semantic streams with complete versioned envelopes and no generic Planning document/update aggregate.
- [ ] Internal COMB identities, mutable unique map slugs and immutable Project-local WF references obey their distinct contracts.
- [ ] ID-bearing void creates enforce uniqueness; lost responses reconcile with fresh authorized reads. No original-result
      receipt is required; stale expected versions fail without append or projection drift.
- [ ] Ticket parentage is active, same-Project and transactionally enforced with reference allocation.
- [ ] Stream append, command-critical constraints, required audit and current projection commit or roll back together on the canonical connection.
- [ ] Replaying accepted creation streams produces equivalent typed current Views; projections cannot append or modify streams.
- [ ] Actor, command, causation, correlation, timestamp, schema and content digest provenance survive persistence/replay safely.
- [ ] View/create authorization is entry-owned and Project-scoped; APIs expose only safe explicit Views and failures.
- [ ] Focused Domain/Application/PostgreSQL/concurrency/API/redaction tests and the canonical build pass with fresh evidence.
