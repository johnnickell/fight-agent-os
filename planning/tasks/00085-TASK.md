# Establish event-sourced Wayfinder planning authority

## Outcome

Agent OS can idempotently create and inspect repository-owned Wayfinder maps and tickets through authoritative semantic event streams, transactionally current constraints and rebuildable read projections, establishing the shared Planning event, identity, reference and concurrency foundation without a generic document aggregate.

## Scope

- In scope: Fight Common event-store contract qualification/composition; Planning event envelopes and content payload/digest handling; COMB internal identities; repository-unique mutable map slugs; immutable atomic WF references; per-stream expected versions; command identities/idempotent receipts; transactional stream append, reference allocator, parent/slug constraint and required current projection; optional snapshots as cache only; rebuildable map/ticket detail, hierarchy and history Views; `CreateWayfinderMap`/`CreateWayfinderTicket` and typed creation events; authenticated actors/correlation; view/create Permissions; PostgreSQL migrations/repositories/concurrency; versioned API/OpenAPI.
- Out of scope: Generic document/update events, decision-point editing, synthesized resolution, dependency changes, closure/archive, ResearchNote/Prototype, EPIC/TICKET/TASK, queue/priority, migration/import, browser UI, asynchronous search infrastructure and full emergency-redaction operation.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Create a Wayfinder map | `CreateWayfinderMap` | Preview Repository, slug uniqueness, initial destination/done condition and idempotency | `WayfinderMapCreated` | One stream, internal identity, slug constraint and current projection commit atomically |
| Create a Wayfinder ticket | `CreateWayfinderTicket` | Preview active map, reference allocation and initial question/boundary | `WayfinderTicketCreated` | One immutable WF reference, child stream, parent/allocator constraints and projections commit atomically |
| Inspect current hierarchy | N/A — read-only interaction | Get map/ticket detail and Repository map hierarchy | N/A — reads emit no Domain event | Authorized typed Views come only from rebuildable projections |
| Inspect history | N/A — read-only interaction | Get stream version, semantic events and safe provenance | N/A — reads emit no Domain event | Authorized history explains identity, actor, command and revisions without becoming authority |

## Validation and permissions

Use separate `WayfinderMap` and `WayfinderTicket` aggregates and streams. Do not implement a generic Planning artifact/document root or generic update event. Every stream event carries aggregate/event identity, stream version, timestamp, authenticated user/agent/system actor, command/causation identity, correlation/planning-session identity when present, event schema, and content payload reference/digest where applicable. Agents never impersonate users.

Generate internal identities through `Uuid::comb()` behind injected capabilities. Maps use a normalized repository-unique slug that may later change semantically; they do not consume a MAP sequence. Allocate immutable WF references atomically per Repository/kind and never reuse allocated values, including after archive or an abandoned competing create. Idempotent retry of the same command identity returns its first accepted identity/reference/result; command identity reuse with different intent fails.

Require an active authorized Repository from TICKET-00024. A ticket has exactly one active same-Repository map parent. Reject cross-Repository parentage, unknown/archived parents, slug/reference conflicts, unsupported schema, malformed bounded content and client-selected internal IDs/references. The command handler owns one canonical PostgreSQL transaction that appends the event and updates command-critical allocator, parent/slug constraints, idempotency result and current projection. Optional display/search projections may lag later, but creation results and constraints may not.

Expected stream version guards changes where applicable. Stale commands return current version and safe intervening semantic facts without appending, merging or overwriting. Snapshot rows may optimize load only after replay equivalence is proved; event streams remain authority. Projection tables expose no write capability to Domain/Application callers.

Require independent authoritative Permissions to view Wayfinder data and create maps/tickets, scoped to Workspace/Repository. HTTP Actions dispatch one command/query and map explicit safe Views to JSend `snake_case`; errors/OpenAPI follow the shared API boundary. Hide event payload internals, SQL, secrets, unnecessary identifiers and unauthorized Repository existence.

## Acceptance criteria

- [ ] Separate WayfinderMap and WayfinderTicket roots use authoritative semantic streams with complete versioned envelopes and no generic Planning document/update aggregate.
- [ ] Internal COMB identities, mutable unique map slugs and immutable repository-local WF references obey their distinct contracts.
- [ ] Idempotent retries return the original result; altered duplicate identities and stale stream versions fail without append or projection drift.
- [ ] Ticket parentage is active, same-Repository and transactionally enforced with reference allocation.
- [ ] Stream append, command-critical constraints, idempotency record and current projection commit or roll back together on the canonical connection.
- [ ] Replaying accepted creation streams produces equivalent typed current Views; projections cannot append or modify streams.
- [ ] Actor, command, causation, correlation, timestamp, schema and content digest provenance survive persistence/replay safely.
- [ ] View/create authorization is server-side and Repository-scoped; APIs expose only safe explicit Views and failures.
- [ ] Focused Domain/Application/PostgreSQL/concurrency/API/redaction tests and the canonical build pass with fresh evidence.
