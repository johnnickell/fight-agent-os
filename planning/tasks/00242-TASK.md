# Authenticate signed Agent requests with atomic replay protection

## Outcome

Resolve a real request-scoped package `AuthenticatedAgentPrincipal` using actual HMAC verification, authoritative
Agent/Permission state and atomic PostgreSQL replay protection. Authentication establishes identity evidence only;
activation, holder selection and current bounded use remain separately required.

## Scope

- In scope: Strict transport mapping to `SignedAgentRequest`, concrete `HmacSignedAgentRequestVerifier`,
  `AgentRequestNonceConsumer`, nonce persistence/retention and package `CurrentAgentPrincipalProvider` composition;
  bounded input/time checks, current authority races, neutral public failures and safe diagnostics.
- Out of scope: Browser JWT replacement, activation, broker launch, arbitrary secret retrieval, a new signing
  protocol, copied package principal-resolution policy or advertising a complete operational cohort.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Authenticate one signed request | Package provider resolves trusted transport input using actual verifier/decipher | Exact current credential, Agent state/revisions and complete direct Permission definitions | Safe authentication observation only, not a grant | One immutable request-local principal after confirmed nonce consumption and current-authority checks |
| Consume replay evidence | `AgentRequestNonceConsumer::consume` inside package-owned Unit of Work | Current exact Agent/credential/Permission-assignment revisions and nonce uniqueness | N/A — replay storage is not a product lifecycle event | Atomic globally unique consumption or denial, sharing current-authority fences |
| Reject malformed/replayed/obsolete request | No tool or activation command dispatched | Bounded header/body/URI/time validation and authoritative current state | Secret-free classified server diagnostic | Generic failure without material, signed body, nonce or provider disclosure |

## Validation and permissions

Compose the actual selected package provider rather than recreating it. Implement Common v1 HMAC semantics against
its selected source and actual signer, including normalized query, method, authority, path, canonical signed headers,
body digest and key representation. Do not infer the derived-key algorithm from prose alone: inspected Common docs
and implementation differ in their derivation description; source-bound interoperability evidence must settle the
selected contract, not a consumer-invented scheme. Missing public capability requires owner resolution, not vendor edits.

Strictly bound request/header/body sizes; reject duplicate/ambiguous credential/signature/timestamp headers, malformed
IDs, unsupported algorithms and proxy/authority ambiguity. Preserve signed bytes; do not reserialize input before
body verification. Use trusted configured origin/proxy facts, never untrusted forwarded identity. Preserve package
time semantics: no future timestamp, at most its accepted five-minute past window and exact empty/nonempty body
rules. Do not import browser JWT clock tolerance or accept Bearer credentials on the Agent route.

Verify cryptography before consuming a nonce. Nonce uniqueness is global to the contracted consumer store, not
per-process or narrowed to a caller/credential. Confirm current ACTIVE Agent, credential and Permission-assignment
revisions under cohort-first authority fences in the same transaction as consumption. No separate Common middleware
may independently consume the same nonce or accept nonce failure as success. Cleanup cannot reopen replay while any
request is acceptable; clock uncertainty/rollback must fail closed rather than permit premature evidence deletion.

Retain the provider only within this exact request; later requests/jobs must reconstruct it. Reuse one resolved
snapshot within the request without a second nonce transaction; failed/uncertain authentication never dispatches work.
Preserve the provider's post-consumption current-authority check and exact Permission resolution. No role/template
shortcut, stale replica or partial Permission result grants authority. Concrete secret parameters, callbacks and
actual exception/log adapters must redact material and signed input even with argument capture enabled.

## Acceptance criteria

- [ ] Actual Common-signed requests interoperate with the consumer verifier; altered canonical components, digest,
  algorithm, oversized/ambiguous input and timestamps outside package bounds deny before protected work.
- [ ] Concurrent identical nonce submissions across processes/credentials allow at most one consumption; current
  revision/state changes before/after consumption deny as required, with no extra nonce authority or nested transaction.
- [ ] Real restart and nonce retention preserve replay rejection; database/key/commit uncertainty cannot become
  authenticated success. Missing/malformed Permission definitions deny rather than yield a partial principal.
- [ ] Request-local reuse consumes once, while later requests resolve fresh current authority after grant changes,
  rotation/revocation and restart. Browser JWT and Agent HMAC paths remain distinct with no scheme fallback.
- [ ] Safe diagnostics/results and real argument-capturing traces expose no keys, nonces, bodies, ciphertext or
  provider details. Authentication alone cannot activate, sign for or launch an Agent.

## Verification and evidence
