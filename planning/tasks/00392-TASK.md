# Inspect immutable changes and retained evidence

## Outcome

Humans can inspect the exact submitted immutable changes and actual check/Artifact evidence through independently
loaded Changes and Evidence sections, without silently substituting current worktree content or exposing storage.

## Scope

- In scope: Complete bounded file discovery, lazy syntax-highlighted base…head bodies, protected evidence metadata/
  previews/downloads, provenance/limitations/sensitivity/hold/tombstone presentation and section-specific recovery.
- Out of scope: New evidence capture/store, arbitrary file browser, check execution, acceptance/Review verdict,
  code editor, active document renderer, public storage links and automatic refetch/repair of missing evidence.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Discover exact changes | N/A — read-only | TASK-00378 complete exact-subject manifest pages | Existing committed projection invalidations only | Every authorized file discoverable without loading every body |
| Inspect selected content | N/A — read-only | Exact immutable file body or protected bounded Artifact preview/download | N/A | Inert authorized bytes or explicit unavailable state |
| Inspect Evidence | N/A — read-only | Actual checks/Git/Artifact references, provenance, sensitivity, holds and tombstones | Existing safe invalidations | Attributed facts, never an inferred review or accepted check |

## Validation and permissions

Use TASK-00391's independent detail boundaries and current-authority/live owners, with TASK-00378/00380's protected
reads and lifecycle fences transitively through TASK-00389. Do not add duplicate APIs, read policy, evidence capture
or a second client cache. Validate exact Workflow/Repository/subject/base/head/manifest identity and current rights
on each manifest/body/reference request. A branch name, cached ID or public route is not authority.

Keep every changed file discoverable through stable bounded manifests; render only a bounded window and fetch bodies
lazily. Bind responses to exact subject, selection and current context/restriction generation. Escape all metadata,
paths, diff lines and parser output; syntax highlighting must remain inert and bounded by qualified byte/line/work
limits. Unsupported, oversized and binary bodies lead only to authorized Artifact routes, never omitted files,
unbounded parsing or active HTML/SVG. A malformed/incomplete subject is explicit, not silently repaired in the browser.

Show mutable worktree observations separately and never use them as fallback for absent retained bytes. Preserve
actual check invocation/subject/result/warnings/completeness and contribution/evidence lineage. Missing exit/status,
partial output or unavailable files do not become passing checks, independent Review or configured-base proof.
Later TICKET-00083 adds actual Review/QA criteria/verdicts to this surface; absent future capabilities stay unavailable.

Downloads/previews go through current-authorized application reads with no-store and safe media/name handling. No
presigned/public bucket URL, raw locator, secret-bearing diagnostic or automatic provider/Jev call follows human
inspection. Keep unsupported/restricted/corrupt/purged/held states distinct. Enforce current copy restrictions and
clear pending/visible data on invalidation; stale responses cannot resurrect retired content. Qualify disclosure
limits for already-delivered bytes without claiming recall. A failed Changes load never erases Evidence or Summary.

## Acceptance criteria

- [ ] Actual exact-subject changes remain fully discoverable beyond one page with lazy safe bodies; oversized/binary/
  unsupported content has explicit authorized handling and never falls back to a live checkout.
- [ ] Evidence shows actual checks/Git/Artifact provenance and limitations, distinguishing unknown/partial from
  success and later Review verdicts from presently unavailable capability.
- [ ] Malicious metadata/diffs, cross-scope requests, subject switches, redaction and late-response races cannot
  execute content or disclose retired evidence through previews, downloads or caches.
- [ ] Independent section states and real keyboard/focus/responsive/light-dark behavior keep exact work inspectable
  despite partial failure, purged content, long manifests or interrupted delivery.
