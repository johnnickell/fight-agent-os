# Inspect private memory under scoped oversight

## Outcome

A currently authorized Super Admin or specifically assigned audit Agent can inspect retained private Agent
memory through a bounded, attributed oversight operation, while an ordinary peer, Team Lead or independent
reviewer cannot acquire another Agent's private reasoning through normal work. This TASK owns the authoritative
private-read operation, managed Permission extension and safe access evidence; the basic human browser journey
belongs to TICKET-00050.

## Scope

- Add the exact managed `READ_PRIVATE_AGENT_MEMORIES` Permission through a deliberate extension of the qualified
  managed authority catalog from [TASK-00036](00036-TASK.md). It is **not** `SUPER_ADMIN_ONLY`; apply the
  accepted `ADMIN_SAFE` tier and initially assign it to managed `ROLE_SUPER_ADMIN`, without preventing future
  specifically authorized direct Agent grants or scoped role delegation. Use the installed Fight Access
  Control package's actual public policy/reconciliation contracts, not role-name bypasses or invented grants.
- Provide an Application query/use case for explicit private-content oversight with the authenticated actor,
  target Agent/memory, current effective Permission and target scope; preserve safe attribution of who accessed
  what and when. A Super Admin needs no extra audit TASK or purpose statement. An audit Agent must additionally
  have an explicit authorized audit TASK binding its purpose and target scope. Its direct Permission alone is
  insufficient outside that assignment. Humans and Agents never inherit another role's private session.
- Retain readable current private material for separately permitted oversight after its owner's Workflow or TASK
  completes, assignment changes or retirement; private correction does not imply retaining prior private text.
  Access to retained content remains guarded. Do not copy the private body into general search, a peer review
  handoff, a routine Project Manager view, logs, audit receipts or a silent self-learning feed.
- Deliver a bounded secure application/first-party access path that can be used by the later human presentation
  without duplicating authorization in the browser. Reuse TASK-00185's persistence and safe Views rather than
  inventing a second private memory store. TICKET-00050 owns visual inspection, exceptional safety removal and
  safe handling of any prohibited content already retained.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Read private content as an authorized Super Admin | Inspect private memory with attributed audit | Resolve current Permission, target access and exact memory content | Private access recorded only for a successful audited disclosure | Bounded private text returned to that principal, no approval or publication |
| Read as an assigned audit Agent | Inspect private memory with attributed audit | Resolve direct Permission, explicit current audit TASK and bound target | Private access recorded only for a successful audited disclosure | Permitted private content only for the TASK's authorized purpose and scope |
| Deny ordinary reviewer/peer | Rejected audited inspection | Resolve actor/target authority without disclosing content | Safe denial observation where policy requires | No private content, titles or excerpts enter ordinary review or logs |
