# Operate scheduled new-mailbox delivery and recovery

## Outcome

An approved production-like worker/schedule delivers actual committed email-change credentials to controlled
new mailboxes and recovers independently of the request process. Required key/provider access, separate expiry,
protected inspection and honest readiness are implemented and qualified, not inferred from storage or fixtures.

## Scope

- In scope: Bounded scheduled operation using existing runner/facilities and real shared provider; actual worker
  identity/key access, request-capture integration, process interruption/restart and recipient/uncertainty evidence.
- Out of scope: Public account/admin UI, confirmation page/submit/login, notice scheduler/retention, generic job
  platform, new credential queue, automatic deployment authority, unsupported key rotation or physical destruction.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Deliver accepted work after caller loss | Scheduled bounded runner dispatching package `DeliverEmailChange` | Package due work and exact safe generation state | Existing delivery/audit outcome after matching commit | Actual new-mailbox provider attempt under approved sender/worker scope |
| Recover independent of provider/key availability | Separately scheduled bounded `ExpireEmailChange`/existing cleanup commands | Package expired-work discovery and safe persisted progress | Package expiry facts on actual transitions | Exact expired authority/reservation/material cleanup without delivery key/provider |
| Inspect operation and gate readiness | Protected safe inspection/preflight, not a new business command | Actual schedule health, required access, current persisted work and bounded provider evidence | No fabricated success/business event | Honest qualified/unavailable/uncertain state for exposure owners and operators |
