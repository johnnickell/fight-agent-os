# Report which verification passes a change affects

## Outcome

Give local verification and GitHub the same answer about which checks a candidate needs and why.

## Scope

Provide a read-only selector that reports the comparison base, scope, and reason for each of PHP, Frontend, Pi Harness, and Planning. Account for changed, added, renamed, and deleted inputs as applicable to the candidate. Shared inputs may select several passes. Use conservative execution when history or classification is uncertain. Make browser smoke an explicit selection under Frontend, regardless of which side changed. Do not run checks, store receipts, or change repository settings in this TASK.

## Acceptance criteria

- [x] The command reports decisions and reasons for PHP-only, frontend-only, Harness-only, planning-only, and shared changes.
- [x] Backend-only and frontend-only changes that can affect the existing journeys select browser smoke. A combined change selects it once.
- [x] Unknown scope, missing history, or ambiguous shared inputs do not produce a successful skip. Local and hosted consumers can use the same policy without duplicating it.

## Verification and evidence

Record bounded candidate examples, selected bases, exact commands and results. Show behavior without changing sources or repository settings. Hand off to independent Review and applicable QA.

## Coordination

No prerequisite TASKs. Execution consumers are [TASK-00619](00619-TASK.md) and [TASK-00620](00620-TASK.md). Planning approval does not select a checkout or authorize implementation or publication.
