# Navigate from real failures and runs into diagnosis

## Outcome

An authorized operator reaches relevant real logs from a failed application operation or managed run, inspects exact
content/context and follows activity without another Dashboard or changed public errors. This is approved slice F
of [TICKET-00113](../tickets/00113-TICKET.md), additive navigation plus its real diagnosis journey, not proof-only work.

## Scope

- In scope: Permission-gated links from actual failure/correlation presentations and run Summary into native Logs;
  typed safe route parameters, current-authorized related navigation, missing/stale reference handling and real
  HTTP/worker/run diagnosis integration through search/detail/tail.
- Out of scope: Raw logs in Summary/Activity/history/evidence responses, new public error bodies, new Workflow state,
  synthesized relationships, transcript extraction, a second Dashboard, entity grants or completed archive/restore UI.

Use [WF-041's surface ownership](../wayfinder/tickets/WF-041-select-the-authorized-log-browser-integration.md#surface-and-navigation-ownership).
Reuse the existing frame/theme and native Logs navigation from TASK-00463. The typed API client already carries a
validated optional correlation reference; use that safe reference without changing HTTP status/envelope/message/
correlation/cache behavior or importing raw exceptions into user-facing errors. Link actual available Workflow/TASK/
run/process identities from their existing owner. Missing references stay unavailable/unknown, not invented joins
or broad cross-source searches labelled exact lineage.

Extend [TASK-00391](00391-TASK.md)'s real Summary surface, preserving independently loaded Summary, Changes, Activity
and Evidence. Navigation opens Logs rather than fetching raw diagnostics into sanitized section responses. Failure
or denial in Logs must not erase the dossier or alter Workflow execution/acceptance. A connected tail or found log
never certifies check evidence, publication, review or a Workflow transition.

Routes contain only reviewed non-secret typed IDs, time bounds, service and severity values. Free search text/raw
messages/exception text remain volatile bounded bodies, not URLs/history/referrers/analytics. Reuse ADR 0004's bounded
volatile intended route, rechecking current authority/target on restoration; no generic return URL or link-token grant.
Show selected scope/time and installation-wide log access rather than implying project membership confers access.

Related entity navigation checks that entity's current permission separately. `READ_LOGS` does not authorize another
entity's metadata, Artifacts, holds, purge or execution. Do not redact authorized original records to manufacture
entity-access separation; instead avoid unauthorized lookups/presentation when following their references.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Diagnose failed HTTP operation | Navigation only | Available validated correlation/time and current log authority | N/A | Existing public failure leads to actual scoped Logs without exposing raw error content in the response |
| Diagnose worker or managed run | Navigation only | Actual owner run/attempt references and current log authority | N/A | Real relevant observations/context/live activity, or explicit missing coverage/reference |
| Follow a related entity | Navigation only | That entity's separate current authority and typed reference | N/A | Authorized destination or safe denial; log access never supplies another grant |
| Reopen a stale/expired link | No automatic mutation | Current authority, target, time eligibility and coverage | Client navigation signal only | Honest denied/expired/unavailable state without hidden existence leaks or invented purge |

## Validation and permissions

Use TASK-00463/00464/00465's current server fetch/release and stream-batch checks plus the sole `/me` client evaluator.
Hide/deny unauthorized links/loaders/actions; UI permission checks are not enforcement. Typed IDs are references,
never authority. Follow ADRs [0003](../adr/0003-browser-authentication-security-profile.md) and
[0004](../adr/0004-client-authority-and-runtime-state.md): same-origin transport, no-store, bounded intended navigation,
volatile state and generation fencing across refresh/logout/expiry/scope changes. Already released bytes cannot be
recalled. Preserve existing secret-safe public response and sanitized Activity/evidence contracts.

## Acceptance criteria

- [ ] Actual failed HTTP, worker and managed-run paths expose useful permission-gated native Logs entry links using
  only available safe identities, with no fixture-only production records or fabricated lineage.
- [ ] Real records reached through those links support bounded search/context/exact detail and live follow under
  current authority, with known collection/visibility/browser gaps clearly distinguished.
- [ ] Public HTTP contracts and independently loaded Dashboard sections remain unchanged; raw diagnostics never enter
  sanitized Summary/Activity/history/evidence responses or confer execution/acceptance meaning.
- [ ] Related entity links perform independent current authorization; stale/missing/expired/denied references do not
  leak hidden metadata or bypass time/scope policy, and unknown lineage remains honest.
- [ ] Safe routes exclude sensitive search/raw content; late responses and restored navigation cannot revive old
  private state. Real keyboard/focus, responsive/light-dark/zoom/reduced-motion entry and return journeys work.
- [ ] Owned navigation/permission/integration tests, actual API/browser evidence and full `./bin/build` pass with
  exact producer/run references, fresh-versus-inherited evidence and incomplete coverage disclosed.

## Verification and evidence

Use real approved HTTP/worker/run operations with safe controlled failure inputs, retaining original identities and
current owner state. Exercise entry, search/context/detail/follow, back navigation, missing references, permission
loss and stale links through the actual shell and Summary. Do not add demonstration endpoints, synthetic production
Workflow cards or a new proof-only execution ceremony. Reuse ordinary authorized execution evidence where applicable.
Inspect URL/history/network/DOM behavior and independent section failure states; test owned navigation contracts,
not generated routes/configuration, library internals or wrappers. Run focused repository checks and full `./bin/build`,
recording actual source coverage, accessibility evidence, warnings and limits. No runtime operation is authorized
merely to obtain evidence by this planning approval.
