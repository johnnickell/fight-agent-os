# Integrate shared validation and field-error lifecycle with Formik

## Outcome

Production forms can consume the safe PHP-derived schema through one typed Formik integration, render multiple
client/server errors consistently, and immediately invalidate obsolete errors on edits without allowing late
responses to restore them. Existing form/control accessibility and authoritative server validation are preserved.

## Scope

- In scope: Deliberate Formik version/peer qualification and exact lock; typed public schema service/decoding;
  bounded safe metadata caching and cancellation; supported client rule functions; shared Formik adapter;
  safe server field-error contract extension and explicit field mapping; multiple-message presentation;
  value/dependency/submission generation tracking; reset/unmount/supersession semantics; existing production
  control/catalog integration and representative component/browser evidence; client conventions/documentation.
- Out of scope: Implementing authentication endpoints or product journeys, general form generation, arbitrary
  rule/code execution, client authorization, replacing React-Bootstrap, changing password policy, duplicating
  the API transport, persisting form secrets, broad E2E and wholesale third-party upgrades.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Load a named public schema | No business command | Typed read of TASK-00151's schema and revision | Client loading/result signal | Valid safe metadata available; explicit loading/failure/retry otherwise |
| Edit and locally validate a field | Local input only | Evaluate supported rules/dependent fields at current revisions | Input/validation signals | Old errors clear immediately; new-value results follow visibility policy |
| Present server rejection | Owning feature service's existing submission | Decode bounded safe message lists and known field mappings | Owning journey events only | Current server errors share accessible presentation with local errors |
| Discard stale results | None | Compare form/schema/submission/field/dependency generations | Local lifecycle signal | Superseded errors cannot overwrite current values or steal focus |
| Reset/finish/unmount | Owning journey lifecycle | Inspect outstanding owned validation/submission generations | Local cleanup signal | Errors and stale callbacks clear without retaining secrets or undoing server success |

## Validation and permissions

Implement [TICKET-00036's unified lifecycle](../tickets/00036-TICKET.md#unified-field-error-lifecycle) as the single
shared contract, not per-page error-reset patches. Keep generic validation independent of Formik where useful,
with a small Formik integration at its real public callback/state seams rather than an application-wide form
framework. Existing controls remain responsible for label/help/error association and focus, not rule policy.

Qualify a supported Formik version against the locked React/React DOM/TypeScript and existing control/catalog
stack through repository tooling. Do not force peer resolution, downgrade the stack or copy a reference project's
lock. Stop for a dependency decision if compatibility cannot be established. TASK-00149 excluded Formik only
from its prior control migration; this separately approved TASK owns adoption.

Decode TASK-00151's exact version/shape/rule/argument/message/revision contract as untrusted input. Unknown or
malformed rules do not pass validation or execute code. Cache only safe metadata in bounded revision-aware
memory; no credentials, form values or authorization snapshots. Resolve missing/unavailable/schema-changed
states explicitly, with bounded retry and no implicit valid result or unsafe submission fallback.

Extend TASK-00027's API failure contract deliberately: it currently recognizes validation envelopes but drops
field detail. Preserve existing transport/cancellation/authentication semantics while safely exposing bounded
contract-approved field/message lists. Explicitly map snake_case/dotted paths to registered client fields;
reject unsafe keys, unknown fields and payloads, never raw-set object paths or render HTML from server strings.
Generic authentication/system failures stay form-level; do not reveal which login credential/account failed.

Actual value changes via typing, paste, controlled updates or Formik APIs invalidate old client/server errors
immediately. A fresh failure for the new value may remain visible under defined touched/submission rules.
Unrelated current errors remain; comparison-dependent fields refresh. Track generations, not password/value
copies: edited-then-restored A → B → A still invalidates old responses. Multiple submissions, asynchronous
validation, reset, schema replacement and unmount must all reject obsolete callbacks. Cross-field server errors
need dependency provenance or conservative whole-response invalidation; do not guess validity from one unchanged
field. Preserve legitimate server-success handling in the owning journey even after cancellation or edits.

Provide semantic multiple-message rendering and clear help/error association. After rejected submission, focus
the first current invalid registered field; non-field-only failures use an accessible summary/status. Background
or discarded stale results do not move focus. Preserve busy/disabled, paste/password-manager, Unicode, visible
focus and narrow-layout contracts. Client enforcement never replaces server validation, grants or permissions.

## Verification and evidence

Exercise a rejected submission with several server messages, edits before/after response, programmatic changes,
unchanged neighboring fields, comparison dependencies, A → B → A, older/newer submissions, reset, schema revision
change and unmount. Prove forbidden late error/focus effects as well as success/recovery. Distinguish independent
field errors from cross-field/unknown dependency cases. Confirm a completed server mutation is not erased by
local error filtering and owning success handling remains intact.

Test declared rule semantics from PHP/public contracts, not by copying current JavaScript output. Fixtures are
safe schema/response data for owned client behavior, not test-only PHP Actions or tests of the exporter. Keep
API malformed-envelope/message/path and existing cancellation/authority regressions. Use synthetic values only;
inspect state/diagnostics for accidental credential copies and preserve safe response handling.

Run actual pinned dependency qualification and frontend tooling directly, never product tests of installers,
locks, lint/build or generated files. Run `./bin/client check`, focused affected API/HTTP tests and

`git diff --check`, then `./bin/build`. After technical acceptance, independent QA exercises real built catalog
rejection/correction/multiple messages, narrow keyboard focus and delayed/stale response behavior. Retain actual
inspected captures and state evidence; do not claim authentication E2E, universal accessibility or final design.
