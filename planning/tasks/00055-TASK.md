# Deliver one-time password-reset completion

## Outcome

A canonical public completion route captures password-reset authority transiently from a URL fragment, removes it from visible history before ordinary rendering, applies the shared password policy through a versioned API, and uses `AuthenticationService::resetPassword()` to consume one current grant, replace the Argon2id hash, advance authority, revoke every target-user session, and require fresh login.

## Scope

- In scope: Canonical public completion route; pre-render fragment capture/history replacement; transient credential owner/clearing; password/confirmation form and policy guidance; typed feature service; versioned Action/validated request values/generic View/OpenAPI; shared structural/compromised checks; package reset orchestration; request/rate controls; same-user memory/cookie/cross-tab invalidation after success; generic invalid/used/expired/replaced recovery; accepted production states; PostgreSQL race/session/HTTP/history/storage/accessibility/redaction tests.
- Out of scope: Issuing a new access/refresh session, remembered-session choice, administrator password assignment, reset request/delivery internals, authenticated password change, external password checker, periodic expiration/history, preserving password fields through navigation, and broad browser automation.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Open completion link | N/A — client bootstrap/navigation | Read expected fragment fields once and validate route identity | Client-only history replacement | Credential is held only in transient memory and removed before ordinary rendering/navigation |
| Complete reset | `AuthenticationService::resetPassword(userId, credential, password)` after owned policy | Resolve latest one-hour grant, active identity, password policy, sessions, and authority | `PasswordResetCompleted` | Grant consumed, Argon2id hash/authority replace, all target sessions revoke, audit commits atomically |
| Handle target session invalidation | N/A — client authentication coordination | Compare transient target ID to safe current principal and observe terminal server authority | Client logout/invalidation signal | Same-user tabs clear cookie/memory; every old server credential fails; unrelated current identity is not silently trusted for target |
| Reject invalid completion | N/A beyond rejected service | Resolve only generic malformed/unknown/used/expired/replaced/raced outcome | Redacted package failure only | No identity/grant state leaks; transient secret clears and safe request-new-link guidance appears |

TASK-00053 links carry only bounded user routing identity and reset credential in a URL fragment. The owner's
approved compatible routing clarification preserves that identity: TASK-00053 resolves only immutable UserId
through the package's secret-free exact-purpose/exact-generation status query inside invocation, never by email
or newest user grant. Advisory status is not a send fence; historical/stale mail races and package lifecycle
ownership remain unchanged. See [the approved supplier contract](00053-TASK.md#approved-invocation-routing-and-fragment-contract).

The exact fragment is `#user_id=<package UserId UUID string>&credential=<RFC3986-encoded opaque reset credential>`
in that order, exactly one occurrence of each field and no others. `user_id` is the canonical 36-character UUID;
`credential` decodes to 1–4096 bytes, unchanged and untrimmed. Validate bounds, duplicate/unknown fields and
encoding before capture; reject malformed encoding. Do not add email, generation ID, claim token or advisory
status/expiry. UserId routes the request but grants no authority without the matching current package credential.
This is a contract clarification only, not downstream implementation, acceptance, closure or reordering.

A minimal pre-render bootstrap reads expected fields once, validates shape/size, stores them in one ephemeral memory owner, and immediately replaces visible/history URL before analytics, remote resources, screenshots, or ordinary route rendering. Never persist in local/session storage, IndexedDB, Cache Storage, service worker, HTML, runtime config, API cache, intended route, error object, telemetry, or snapshot. Apply no-referrer policy and clear references on success/terminal failure/unmount.

The public JSON endpoint accepts only explicit bounded user ID, reset credential, password, and confirmation/transport fields justified by validation. Apply Origin, Fetch Metadata, HTTPS, JSON/body controls, accepted CSRF policy, and atomic secret-safe reset rate limits. Grant possession supplies reset authority; no authenticated role/permission applies and ambient refresh cookies are not authority for this operation.

Client password checks are usability only. Server independently applies TASK-00039's exact untrimmed Unicode structural policy and local compromised-password checker before invoking package service. Confirmation mismatch is transport validation. Mark all secret parameters sensitive; do not serialize CQRS password/credential messages or send candidates externally.

Call `AuthenticationService::resetPassword()` directly for current latest purpose-bound grant matching, active user, one-hour usability, credential verification, grant consumption, Argon2id hash replacement, authentication-version/revision advancement, all-session revocation, audit, transaction, and event. No new TokenSet is issued. Invalid/malformed/unknown/used/expired/revoked/replaced/mismatched/raced cases map to one generic request-new-link state without identity detail. Policy feedback can explain candidate requirements without proving grant/account state.

After success, require Login. Existing access JWTs fail on authoritative version checks and every refresh session is revoked. If the client currently represents the reset target, expire matching refresh cookie, clear access/principal state, and broadcast terminal logout; do not persist identity just to coordinate. An unrelated authenticated principal cannot authorize the reset and must not be accidentally mutated, but completion success still navigates safely without exposing target state.

Recreate accepted responsive form and loading/policy/common-password/generic-invalid/expired/throttled/success/system states. Permit paste/password managers/Unicode/spaces; support labels/instructions, confirmation, accepted show-password behavior, keyboard/focus, announcements, themes, reduced motion, and recovery links.
