# Bind and preflight authorized observability operations

## Outcome

An installation operator can inspect the exact prerequisites and authority for observability enrollment and invoke
only the narrow owning operations when their prerequisites hold. This approved slice A of
[TICKET-00117](../tickets/00117-TICKET.md) supplies real preflight and operator bindings, not another collector design,
a general administration proxy or a declaration that a named interface establishes authority.

## Scope

- In scope: Additive read-only preflight within TICKET-00023's existing operator-guide boundary; exact target/source/
  platform inventory, owned resource identifiers, supported privilege mechanisms and missing-capability reporting;
  actual narrow actor/operation bindings consumed by preservation, policy and recovery owners.
- Out of scope: Selecting the native collector, implementing preservation/purge/retention policy, full Dashboard
  guide, service enrollment, automatic repair, a second permission store or new Docker/hold/purge powers.

Reuse TASK-00446's normal trusted Console composition and the existing installation/preflight source, not a parallel
operator framework. Record exact declared OS/architecture, Docker/Compose/driver and service/storage identities,
source ownership and permitted mounts/networks/credential placement. Inspect only bounded declared targets; distinguish
pass, warning, unsupported, unavailable and not-checkable. Missing services may remain not configured; they must not
be started to make preflight pass. Read-only host inspection itself requires explicit bounded target authority.

Supply concrete installation inventory and permitted reader/physical-enforcement inputs to TASK-00455, leaving its
native candidate selection and privilege-security reconciliation there. Implement the actual capability-scoped
operator actor/attribution/invocation binding used by TASK-00467/00469/00473. Existing preservation/privacy owners
still decide current allowed action, scope, expected generation and required audit; an internal flag/operator UUID,
trusted shell or log capability does not create that business authority. Unknown or unavailable owner authority
refuses the affected operation. No generic arbitrary command, path, URL or provider invocation is exposed.

Keep privileged enrollment/credential/network/service changes explicit human-run operations with exact target,
prerequisites, expected effects, verification and stop/recovery conditions. Preflight may explain them but cannot
execute them. This TASK does not wait for the completed runtime/browser installation chain: extend the same guide/
composition boundary early; TASK-00486 later integrates the finished protected guide. Runtime state belongs in ignored
`var/`; execution evidence stays under ignored `.runs/`.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Inspect enrollment prerequisites | None; bounded operator preflight | Exact declared platform, source, resource and authority facts | No Domain event | Secret-safe copyable report without repair/startup |
| Resolve a lifecycle/operator invocation | Narrow existing owner operation only | Current actor/action/scope and expected-state prerequisites | Existing required owner audit only | Owner-authorized invocation or refusal, not new policy/grants |
| Encounter missing support or authority | No fallback mutation | Permitted missing/unsupported facts | None from inspection | Explicit owner handoff without inferred healthy/authorized state |

## Validation and permissions

Follow ADRs [0001](../adr/0001-application-ownership-and-orchestration.md) and
[0002](../adr/0002-postgresql-consistency-and-durable-effects.md). Preserve application-owned policy and canonical
state/audit/intent transactions; external effects never occur inside business transactions. No browser/Agent/PHP
request gets Docker or storage credentials. A read-only socket is not an API permission boundary; docker-gen's grant
is not transferable. Never read credential contents or dump environment, raw logs, private object names or arbitrary
home paths into reports. Preserve ordinary public HTTP and existing safe Console behavior.

## Acceptance criteria

- [ ] Actual additive preflight reports exact declared inventory/support/authority prerequisites with bounded work,
  no hidden mutation and truthful unknown/unsupported states across the explicitly verified platforms.
- [ ] Real narrow operator bindings preserve existing actor/action/scope/generation/audit rules and reject missing
  authority, forged targets and broad arbitrary invocation; no new preservation/installation powers are inferred.
- [ ] TASK-00455 receives actual installation inputs without reverse dependence on its chosen collector; downstream
  policy/recovery receives usable bindings without waiting for finished browser/runtime acceptance.
- [ ] Explicit enrollment instructions identify effects, verification and safe stop/recovery, without executing
  service/package/credential/DNS/mount changes or promoting best-effort guidance to verified support.
- [ ] Owned actor/invocation behavior tests, directly exercised preflight/guide checks and full `./bin/build` pass;
  remaining owner/security/platform gaps are recorded rather than hidden behind a green build.

## Verification and evidence
