# Make file-screening enrollment preview readable before confirmation

## Outcome

An operator can inspect the complete file-screening enrollment preview in a short terminal before deciding
whether to save standing authority. This removes the reported setup usability blocker in TASK-00309 without
changing its enrollment, disclosure, credential or accounting contracts.

## Scope

- In scope: A bounded scrollable read-only setup preview, visible navigation/cancellation controls, and a separate
  concise final confirmation tied to the same candidate. Preserve exact preview content and existing save behavior.
- Out of scope: Other operator commands, profile/budget policy changes, diagnosing the separately reported opaque
  setup error unless reproduced by this rendering path, live enrollment, provider requests, and runtime qualification expansion.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Inspect enrollment | `/file-screening setup` | Existing effective candidate and disclosure/budget/coverage details | N/A — local presentation only | Scroll and resize without changing candidate or stored state |
| Cancel preview or confirmation | Escape / decline | N/A | N/A | No save, credential resolution, provider call or accounting change |
| Confirm reviewed candidate | Existing operator setup confirmation | Exact previously displayed candidate | Existing saved notification | Existing profile save only after separate affirmative confirmation |

## Validation and permissions

Keep setup TUI-only and operator-owned. The preview cannot grant consent or save authority. Preserve preceding
source/command disclosure consent, exact-file exceptions, protected paths and all existing limits. Unsupported or
failed presentation must not fall through to saving. Do not use real credentials or enroll the operator during checks.

## Acceptance criteria

- [x] Full preview content is reachable with keyboard scrolling, including its last line, at ordinary and short/narrow terminal sizes.
- [x] Navigation/progress and cancellation remain visible; resize and long paths do not produce terminal-width overflow.
- [x] Continuing from the preview opens a concise separate confirmation; continuation alone never saves.
- [x] Cancelling either step leaves existing settings/accounting unchanged; affirmative confirmation saves the same reviewed candidate.
- [x] Focused owning-Harness/Pi checks and the canonical gate are recorded, including missing native visual evidence or warnings.
