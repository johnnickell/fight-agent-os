# Expose a safe authorized user detail

## Outcome

An authenticated operator with `READ_USERS` can inspect one installation user's package-backed state without exposing credentials or broadening the existing directory.

## Scope

- In scope: `GET /api/v1/users/{userId}` FQCN Action, validated ID, package `GetUserById`, exact safe role/lifecycle View, no-store JSend/OpenAPI and permission-aware detail entry in the existing directory.
- Out of scope: Any mutation, active email change, password/refresh-session/grant exposure or user-detail route usable through a self-service permission.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Inspect user | None | `GetUserById` plus safe role-reference projection | None | One no-store credential-free detail View |
| Reject forbidden/missing | None | Resolve actor/`READ_USERS` before target lookup | None | Safe 401/403/404 without dispatch on unauthorized request |

## Validation and permissions

Use TASK-00117's early route attribute and a fresh permission check explicitly in the HTTP Action on current authoritative `READ_USERS`, initially `SUPER_ADMIN_ONLY`, through the existing authoritative authentication and installation-policy capabilities; never infer from role/JWT. Dispatch public package user/role queries through injected QueryBus and delegate safe View mapping to the Responder without fetching there. Do not retain consumer read wrappers or copy generic identity behavior into Agent OS. This owner correction supersedes the earlier Application-entry requirement for the affected detail/directory reads; package invariants and other mutation/non-HTTP contracts remain intact. Bound the ID and returned fields, fail closed on missing role references and stale actor authority. Return only fields supported by TICKET-00021's directory plus safe detail necessary for later operations. No ownership fallback grants a directory read.

## Acceptance criteria

- [x] FQCN Action checks exact authoritative `READ_USERS` before package dispatch for valid and stale/anonymous/forbidden actors.
- [x] Valid target returns bounded safe JSend/View/OpenAPI with deterministic role state, no-store and no credentials or audit internals.
- [x] Invalid/unknown target, missing role reference, race and role-name spoof fail safely without enumeration of forbidden targets.
- [x] Focused package/HTTP/PostgreSQL/client/redaction checks and `./bin/build` pass with fresh counts and warnings.

## Verification and evidence

Exercise anonymous, permission combinations and managed/custom roles; inspect View/OpenAPI and direct-route behavior, no-dispatch, malformed IDs, pagination-to-detail transitions and redaction using real database users. Run focused checks, `./bin/planning-check`, `git diff --check` and `./bin/build`; record counts/warnings.
