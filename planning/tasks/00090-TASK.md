# Enforce Planning hierarchy and dependency revisions

## Outcome

Authorized planners can preview and explicitly revise valid same-Repository parent relationships and typed Wayfinder/TASK dependencies while transactionally current Workspace constraints prevent cycles, boundary violations and silent ownership/history rewrites.

## Scope

- In scope: Relationship-impact previews; revision-checked reasoned WayfinderTicket-to-map, Ticket-to-EPIC and Task-to-TICKET/unparented reparent operations; terminal reopen prerequisite; active execution/delivery-link human confirmation; typed WF-to-WF and TASK-to-TASK add/remove dependency commands/events; same-Repository WF dependencies; cross-Repository TASK dependencies within one Workspace; authoritative Workspace graph constraint projection and cycle detection; parent/dependency expected versions; cross-Repository move as explicit linked replacement/supersession workflow; independent relationship/cross-Repository Permissions; PostgreSQL concurrency/API/history/read projections.
- Out of scope: Generic arbitrary/cross-type blockers, cross-Workspace links, automatic status cascade, automatic dependency removal, task priority/eligibility, execution claims, lifecycle completion, Markdown import, physical repository movement, branch naming as identity and browser graph UI.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Preview reparenting | N/A — read-only validation | Explain source/target parent, lifecycle, active links and downstream impact | N/A — preview emits no Domain event | Caller receives current safe impact and confirmation requirements without mutation |
| Reparent within Repository | Type-specific reparent command with reason/expected versions | Revalidate child, old/new parent and current constraints | `PlanningArtifactReparented` or type-specific event | Owning stream and parent constraint projections update atomically; identity/Repository/reference remain unchanged |
| Add/remove dependency | Type-specific relationship command | Preview endpoint scope, lifecycle, complete graph cycles and downstream impact | `DependencyAdded` / `DependencyRemoved` | Owning stream and graph projection update atomically with reason/provenance |
| Move across Repository | Explicit create-linked-replacement command | Preview target authority, mapped content/relationships and retained source | Type-specific replacement/supersession events | New target-owned identity/reference is created; source ownership/history remains and gains explicit link evidence |

## Validation and permissions

Parent relationships remain typed: WayfinderTicket has one map, Ticket one EPIC, Task zero/one TICKET under standalone rules. Reparent only between active authorized records in the same Repository. Repository ownership and human reference never change. A terminal child must reopen before reparenting. Active execution/delivery links require current human confirmation bound to actor, versions, target and impact; agents cannot impersonate that human.

Dependencies remain typed: WayfinderTicket may depend only on WayfinderTicket in the same Repository; Task may depend only on Task in any registered active Repository within the same Workspace. Reject self edges, duplicate edges, cross-type edges, cross-Workspace edges, unknown/archived endpoints and cycles across the complete authoritative Workspace graph. A Won't Fix blocker remains an unsatisfied dependency until explicitly removed through an authorized reasoned command; no operation cascades or removes it automatically.

Use transactionally current rebuildable parent and graph constraint projections. Commands lock/check graph/endpoint versions in a deterministic bounded strategy without a repository-global planning version. Append the owning semantic event and update all command-critical relationship projections in one canonical transaction. Controlled concurrent edge/reparent operations must produce a valid acyclic final graph or safe stale/conflict result.

A cross-Repository move is never reparenting. It creates a new target-owned root through its normal create contract, maps only validated content/allowed relationships, allocates a new reference, and appends explicit supersession/link evidence to both authorized histories through one justified orchestration. If atomic cross-stream append cannot be guaranteed, use a recoverable staged intent that cannot expose the replacement as complete prematurely. Never rewrite source ownership/history.

Require separate relationship Permission and stronger authority over both repositories for cross-Repository TASK dependencies/replacements. Preview does not substitute execution authorization. Safe APIs omit unauthorized endpoint existence and full graph details not needed for the decision.
