# Deliver recoverable secret-safe invitation email

## Outcome

Qualified Fight Access Control package handlers claim package-owned invitation delivery state before Agent OS materializes a canonical HTTPS activation link only for provider invocation, delivers deterministic text/HTML mail to a loopback development catcher, and fails closed in production when no real provider is configured.

## Scope

- In scope: Invitation mapping for the exact locked package provider-neutral credential-delivery capability; protected credential handling at the invocation boundary; stable package delivery-generation idempotency; canonical activation URL builder; deterministic text/HTML template; security/privacy headers/content conventions; generic mail capability mapping; development mail-catcher service/config/wrappers; production provider absence guard; delivery/retry/crash/redaction/no-network tests; operator/developer documentation.
- Out of scope: Package discovery/claim/outcome policy or persistence, selecting/enrolling a production mail vendor, invitation HTTP/admin UI, public activation form, generic template engine, arbitrary persisted templates/endpoints/callables, analytics/tracking, scheduler enrollment, and any consumer outbox/queue.

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Process claimed invitation delivery | Exact locked package handler invokes its provider capability after claim commit | Receive only package-approved invocation-lifetime destination, credential material, and delivery-generation ID | Package delivery outcomes remain package-owned | Credential is materialized transiently, mail capability is invoked, and a typed outcome returns to the package handler |
| Recover invitation delivery | Existing TASK-00024 runner dispatches direct package handlers | Discover package-owned pending, due-retry, and expired-lease work | Original package event is optional | Package policy reclaims eligible work without consumer registration or a second queue |
| Inspect development mail | N/A — development tool | Read catcher mailbox through loopback UI/API | N/A — no domain event | Developer can retrieve intended invitation mail without console credential output |
| Reject unsafe composition | N/A — startup/composition | Validate key/base URL/provider/catcher mode | N/A — no domain event | Production-like boot fails when required secure delivery capability/configuration is absent |

## Validation and permissions

Implement the invitation mapping of the exact locked package provider-neutral capability from TASK-00022; do not implement the superseded `v0.2.0` in-transaction `InvitationDeliveryInvoker`, register consumer work, or add invitation intent persistence. Package-owned grant delivery state remains the sole queue and the immutable delivery-generation ID remains the provider idempotency identity. Templates, provider selection, endpoints, and callables are fixed by composition rather than persisted as dynamically resolvable work.

Credential material remains encrypted/protected in package-owned state and is decrypted by package-controlled processing only for the provider invocation lifetime. Do not retain plaintext in package status, retries, logs, exceptions, audit evidence, mail-adapter test records, dumps, metrics, or snapshots. Zeroization cannot be guaranteed by PHP; record that limitation honestly and minimize references/lifetime.

Build activation URLs from explicitly configured canonical HTTPS origin/path, never request `Host`, forwarded headers, or user input. Prefer a fragment carrying credential material so it is not sent in the HTTP request line/referrer; include only necessary safe identity routing data. Validate origin/path at startup and prohibit userinfo, non-HTTPS outside explicit test/development, and ambiguous host forms.

Templates are fixed/versioned, escape interpolated values, include expiry/recovery guidance, and have deterministic text and HTML alternatives. No remote images/fonts/scripts, tracking pixels, analytics parameters, or unnecessary private data. Development mail catcher binds to loopback or private development network only, uses disposable storage, and is never a production fallback. Its mailbox intentionally contains test activation links; scope/access/cleanup must be explicit.

Provider call occurs only after the originating and claim commits through the accepted direct package claim/invoke/outcome phases. The typed result returns to the package handler, which alone owns retry or terminal outcome persistence. Preserve at-least-once semantics and stable idempotency. No end-user permission applies to internal package delivery processing.
