# Run the existing PHP checks as a standalone pass

## Outcome

Let a human, agent, or GitHub runner verify PHP without preparing or running frontend checks. Keep the current verification strength and run each check only once in the existing build.

## Scope

- Provide a PHP entry point and a thin local Docker-backed host command for the existing PHP checks. Account for PHP syntax, style, static analysis, dependency rules, generated API contract freshness, and all PHPUnit suites, including PostgreSQL-backed tests.
- Reuse the same entry point in the existing build and demonstrate it directly on a native GitHub runner without containers or frontend setup. Do not duplicate application setup or keep a second permanent PHP check list.
- Preserve the current coverage policy and suite composition. Unit-only enforcement belongs to [TASK-00612](00612-TASK.md). Shared selection, pass receipts, and required-check cutover belong to [TICKET-00149](../tickets/00149-TICKET.md); browser smoke belongs to [TICKET-00147](../tickets/00147-TICKET.md).

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Verify PHP locally or on GitHub | Local Docker-backed command or direct PHP entry point | PHP source, generated API contracts, and test reports | N/A: verification | Reports and guarded test database setup and cleanup |
| Run the existing full build | `./bin/build` or its existing hosted route | Existing application and Planning inputs | Existing build result | Delegates to the PHP pass once; retains other checks |

## Validation and permissions

Preserve test database identity checks, cleanup and failure behavior, source stability, and explicit setup boundaries. Do not require host PHP or Composer for local use or change repository merge settings.

## Acceptance criteria

- [ ] The local pass and direct GitHub invocation complete without frontend setup. The direct hosted invocation starts no containers.
- [ ] Verification accounts for each existing PHP check and suite and preserves the current coverage gate and database safeguards.
- [ ] The existing build delegates to the PHP pass once and still runs its other checks without regressions. PHP failure does not produce successful build evidence.

## Verification and evidence

Record the old-to-new check inventory, exact local and hosted commands and results, and evidence of preserved database safeguards. Run the existing canonical build and report warnings, failures, and limits; use owning commands rather than product tests of check orchestration. Hand off to independent Review and applicable QA.
