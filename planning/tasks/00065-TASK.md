# Prove the integrated accessibility and responsive baseline

## Outcome

Production routes, components, and critical states receive deterministic automated accessibility checks plus explicitly recorded keyboard, focus, contrast, target, zoom/reflow, responsive, theme, and reduced-motion observations against the accepted WCAG 2.2 AA-oriented baseline, with evidence types and untested assistive-technology/browser limits kept honest.

## Scope

- In scope: Implemented route/state accessibility inventory; production-page automated semantic/accessibility checks; keyboard-only journey observations; focus order/visibility/obscuring/restoration; headings/landmarks/labels/instructions/autocomplete/error/status/table/link semantics; contrast/non-color/targets; long/Unicode content; zoom/narrow reflow/overflow; system/light/dark/reduced motion; representative browser rendering where component tests cannot prove behavior; defect regression/owner linkage; sanitized evidence summary.
- Out of scope: Universal/formal WCAG certification, exhaustive browser/assistive-technology matrix, prototype review repetition, broad visual-regression screenshots, subjective redesign, deferring journey-owned accessibility to this TASK, accepting blocking defects as limitations, RTL, and release approval.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Run automated accessibility checks | N/A — test/catalog/browser tooling | Inspect production DOM, names, roles, relationships, selected computed styles and states | N/A — no domain event | Deterministic violations fail focused/canonical checks with route/state attribution |
| Complete journey by keyboard | Existing journey interactions | Observe focus order, controls, dialogs, announcements and navigation | Client UI signals only | User can complete critical task without pointer or focus loss/trap |
| Inspect responsive/theme behavior | N/A — rendering observation | Inspect named viewport/zoom/mode/content/state combinations | N/A — no domain event | Content reflows, remains perceivable/operable, and avoids unsupported layout claims |
| Resolve accessibility defect | N/A — owner-linked regression workflow | Reproduce against accepted requirement and production component | N/A — no domain event | Failing regression precedes repair; focused matrix and canonical gate rerun |

## Validation and permissions

Build a route/state matrix covering Login, activation, reset request/completion, Dashboard, Account/Security, password change, active sessions, Users, ordinary/elevated invitation, invitation status/recovery, root restoration, loading/empty/validation/authentication failure/forbidden/not-found/expired/conflict/throttled/success/system error. Include permission variants, long/Unicode email/content, narrow/wide, system/light/dark and reduced motion. Use sanitized deterministic fixtures only.

Automated checks run against actual production components/pages and built Storybook/application, never copied prototypes. Configure supported axe-equivalent rules and project semantic tests without broad suppressions. A suppression requires exact rule/element/reason/evidence and cannot hide an accepted requirement. Automated output is a floor, not certification.

Record keyboard-only completion for critical forms/navigation/theme/menu/dialog/table-card/pagination/recovery/logout/session/invitation flows: tab order, reverse order, Enter/Space/Escape, focus entry/containment/return, route-change focus, validation focus, disabled/busy behavior, and no keyboard trap. Status/error/success/loading changes have appropriate announcements without duplicate/noisy output. Password managers/paste/autocomplete and accessible-authentication requirements remain intact.

Inspect semantic headings/landmarks, skip navigation, labels/descriptions/instructions, field/error association, link/button purpose, table headers/captions or equivalent list semantics, confirmation names, current/selected state, and non-color communication. Verify visible and unobscured focus, accepted contrast for text/components/focus/status across light/dark, and target size/spacing under WCAG 2.2-oriented policy.

Use named CSS viewport widths and browser zoom/reflow observations including accepted narrow baseline and 200%/400% scenarios where applicable; detect two-dimensional scrolling except justified data regions, clipping, overlap, offscreen dialogs, fixed-header focus obscuring, and long-content breakage. Verify system theme initialization/OS changes and no avoidable flash, explicit modes, reduced animation, and no motion-dependent understanding. Forced-colors/high-contrast observations are recorded where supported but untested areas remain explicit.

Separate automated results, computed/manual checks, screenshots, and subjective observations. Record browser/OS/tool/font/viewport/zoom/mode. Screenshots contain only fake data and no credentials. State untested screen-reader/mobile/forced-color combinations and do not claim universal WCAG conformance.

Any blocking defect receives reproduction and a failing regression test before repair and is linked to the owning journey/component. Small cross-cutting semantic/style repairs may occur here; material journey/design changes return to the owner and block completion until resolved/reverified.
