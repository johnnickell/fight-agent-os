# Support bounded authenticated log streaming and extraction

## Outcome

The existing authenticated application ingress/runtime supports finite private log streams and extraction without
unbounded workers, buffers or hidden spools. This approved slice E of [TICKET-00117](../tickets/00117-TICKET.md) removes
the concrete transport blocker for native tails and downloads, not a generic proxy or demonstration endpoint.

## Scope

- In scope: Actual shared/application ingress, worker/socket lifetime, authenticated fetch-stream response transport,
  finite buffering/backpressure/deadlines, cancellation/completion observation and aggregate resource binding.
- Out of scope: Tail/query/export content logic, another authority/admission store, raw Mercure topics, generic
  backend/storage proxy, public credential links, new persistent service by implication or shipping test endpoints.

Consume TASK-00483's actual supervised runtime and TASK-00072's shared HTTPS/application ingress. Unlike early
storage/capture suppliers, this TASK needs that concrete ingress foundation, not a substitute topology. Preserve
same-origin Bearer/applicable-CSRF/no-store contracts and current-authority release hooks. Browser/Agents never connect
directly to Loki or private storage; do not put credentials in URLs or broaden CSP/cross-origin access.

Qualify [WF-041](../wayfinder/tickets/WF-041-select-the-authorized-log-browser-integration.md)'s four-installation/
two-requester/one-view tails, <=30-second leases or credential remainder, <=64-KiB batches, <=1-MiB stream queues,
healthy flush <=1 second and <=5-second heartbeat without treating transport health as collection health. Reads and
exports/downloads share two installation-wide operations, one/requester. Transfers are <=30 seconds, export <=7 days/
16 MiB encoded and archive download <=16 MiB compressed; extraction batches <=64 KiB, queued output <=1 MiB/transfer.

Translate these contracts into actual finite PHP/application worker, proxy, socket, process heap and provider budgets.
A single serialized cap or server timeout does not bound all buffers, detached work or concurrent processes. Account
for browser save buffers/copies together with consumer qualification. No server spool or buffering-to-disk fallback;
unknown or abandoned work remains counted until cancellation/completion is established. Slow readers receive the
owning explicit interruption, never unlimited accumulation. Preserve transfer framing and completion signals; HTTP
success, proxy flush or EOF alone cannot establish complete content.

Provide real bounded cancellation/lifetime and output-hook behavior for TASK-00465/00478/00479. Those owners implement
fresh actor/session/capability/scope/disclosure checks before fetch and each output release, application admission,
content fidelity and browser generations. Do not replace their checks with a cached request principal, proxy token,
lease or another permission model. Transport must not release queued private data behind a failed output hook; already
released/in-flight bytes cannot be recalled. Validate where each buffer crosses that release boundary.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Carry an authorized bounded stream/transfer | Existing intent-specific owner request | Current owner output decision and finite runtime capacity | No Workflow event | Private bytes through existing authenticated ingress only |
| Apply backpressure or stop work | Bounded cancellation/lifetime operation | Actual buffered bytes, sockets, workers and provider state | Safe operational observations | Honest interruption and residual accounting, no hidden spool |
| Inspect unavailable transport | Read-only installation diagnostics | Actual support/limits/failure facts | None from reads | Explicit unsupported/degraded state without auto repair |

## Validation and permissions

Follow ADRs [0001](../adr/0001-application-ownership-and-orchestration.md),
[0003](../adr/0003-browser-authentication-security-profile.md) and
[0004](../adr/0004-client-authority-and-runtime-state.md). Preserve public HTTP failure/correlation/cache behavior;
private diagnostics and exceptions stay out of general errors/status. Narrow runtime configuration requires its
existing operator authority; no log permission grants ingress/service mutation. Qualification fixtures are disposable
bounded evidence, never a production arbitrary streaming route or a permanent product-suite infrastructure test.

## Acceptance criteria

- [ ] Actual existing ingress/application runtime carries bounded same-origin private streams/transfers without
  direct backend access, credential URLs, a new proxy product or unsafe cache/cross-origin behavior.
- [ ] Real buffering/backpressure, leases/deadlines, worker/socket/provider and aggregate memory limits hold under
  slow clients/disconnects; no hidden spool, detached unlimited work or premature resource release occurs.
- [ ] Output-hook and cancellation boundaries allow consuming owners to stop future private release; proxy flush,
  EOF and transport health cannot fabricate completion, current authority or collection coverage.
- [ ] Direct transport/runtime/resource qualification and any owned adapter/lifetime behavior tests pass, with exact
  unsupported mechanisms, warnings and full `./bin/build` recorded; consumer integration remains mandatory.

## Verification and evidence

Use owning proxy/runtime/network tools and explicitly authorized safe controlled transfer targets. Measure actual
buffers/heap/sockets/processes under concurrent tails, reads and transfers, stalls, deadline and cancellation faults;
inspect no-store, authenticated boundaries and disk writes. Record exact tested ingress/platform and release points.
Test owned behavior where introduced; do not product-test configuration/wrappers/migrations/vendor internals or seed
quality-tool failures. Run focused repository wrappers and full `./bin/build`; later consumers prove real content and
current-authority races on this qualified runtime, not on a substitute fake endpoint.
