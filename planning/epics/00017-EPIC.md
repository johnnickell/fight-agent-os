# Author versioned Agent templates with human-approved AI assistance

## Destination

Give the Super Admin a working browser journey to inspect, author, revise and publish database-authoritative,
versioned Agent profile templates. Start with the defined managed Agent templates as safe initial database
seeds; after that, the database retains approved changes to those templates and new templates, without a
code/seed-file edit for every revision. The editor can ask an Agent to propose a persona-based system prompt
and a desired direct-Permission set, but the human edits and approves **both** before publication. Neither
an AI suggestion nor a template revision creates an Agent, grants a Permission or installs a Workflow route.

New roles are not limited to the initial eight. A Super Admin may instantiate a distinct named, Team-assigned
Agent from a published eligible template and give it a small, real, manually initiated assignment using
already qualified Harness/tools, current direct Permissions and scope. This supports learning how a new role
works **before** committing to an existing or new Workflow; an absent Workflow remains visibly unavailable,
not faked by matching a name or prompt. Later custom Workspaces may use different conventions and role
catalogs, but this EPIC does not introduce Workspace-admin authority, custom Workflow design or automatic
TASK dispatch.

## Decisions and exclusions

- Consume the [AccessControl adoption map](../wayfinder/accesscontrol-consumer-adoption-map.md)'s
  [WF-033](../wayfinder/tickets/WF-033-define-agent-operation-adoption-boundary.md) separate template-editor
  handoff, [WF-014](../wayfinder/tickets/WF-014-define-skill-trust-and-harness-distribution.md)'s Harness
  resource/revision rules, [EPIC-00006](00006-EPIC.md)'s browser/AI/provider/Harness boundary, and
  [EPIC-00014](00014-EPIC.md)'s Team-assigned Agent creation, managed catalog and qualified AccessControl
  credential/use path. This EPIC supplies the **editor and template publication/integration**, not a duplicate
  Agent repository, credential issuance, Team administration, permission catalog, conversation platform or
  Workflow engine. No template authoring here blocks EPIC-00014's eight initially reviewed, working roles.
- The maintainer explicitly supersedes **only for Agent templates** WF-014/EPIC-00006's old assumption that a
  source-authored managed definition is repeatedly reconciled as the authoritative current revision. Seed the
  initially defined eight managed SDLC templates (and any separately approved Triage definition under its
  existing owner) once with stable identity and complete reviewed content; refuse collision/partial setup and
  never overwrite an existing database template/revision on later deploys or browser edits. The database then
  owns current managed and custom template versions, revisions, ancestry, scope and history. Approved browser
  edits append/select immutable revisions with expected-state protection. Preserve historical bytes, existing
  sessions' exact Harness snapshots and rollback-by-explicit-revision; no in-place rewrite or invisible
  session refresh. The old source reconciler must be **changed/retired safely** before browser publication so
  a subsequent deploy cannot clobber database authority. Retiring seed files after production experience is
  a separate verified decision; this EPIC does not delete them automatically or cut over Planning Markdown,
  change the authority of Skills, or reassign ownership of AccessControl Permission definitions.
- Offer safe browse/detail, version history/diff, scope/ancestry/managed-origin and impact views for the
  installed starting templates and authorized installation/Workspace-wide and registered-Repository-scoped
  custom templates under the existing Harness model. A published template carries its functional role/persona,
  human-reviewed system prompt, complete requested direct-Permission set, applicable resource/model/Repository
  constraints and versioned provenance. The editor permits human-only drafting as well as bounded AI assistance;
  the AI proposes only within the chosen scope, surfaces uncertainty and requested Permissions explicitly and
  never becomes the actor that approves/publishes. A suggestion is an editable draft, not a trusted
  instruction, a grant or an authoritative template. Exact form layout and proposal transport belong to
  TICKET/TASK design, but losing a browser connection must not silently publish an unfinished suggestion.
- Existing managed roles may be revised through the **authorized browser** without editing seed files. New
  role templates may be created and used for qualified manual work, without requiring a corresponding workflow
  first; a later workflow may explicitly recognize a stable role/template identity and an appropriate version
  under its own accepted ownership. The editor cannot invent a role's dispatch eligibility, use a model's
  claimed role name for selection, broaden Team/Repository scope or retroactively replace an active session's
  context. Custom template inheritance follows WF-014's explicit three-way proposal on ancestor changes:
  retain current custom version, publish a reviewed update for future Agents or separately review affected
  existing Agents; no silent permission promotion from managed ancestor drift.
- Super Admin-only applies to **administration of** User/Role/Permission/Agent entities in the UI, not to
  ordinary Users' existing self-service or Agents doing independently authorized assigned work. For this
  EPIC, template management/publication, Agent creation and any Agent direct-Permission assignment or
  reconciliation require separate current managed `SUPER_ADMIN_ONLY` **management** Permissions granted only
  through the authoritative managed Super Admin Role, checked on every HTTP and non-HTTP entry path with
  actor/target/scope/revision validation. Do not rely on a role-name shortcut, browser controls, a signed
  request or a model assertion. This tightens the earlier initially-Super-Admin-only administration intent;
  future `WORKSPACE_ADMIN`/`REPOSITORY_ADMIN` delegation needs separate policy and scoped target approval.
  Other existing administrative journeys remain with their own TICKET/EPIC owners, not reimplemented here.
  Users receive Permissions through managed/custom Role assignments under their existing owner; Agents have
  direct **eligible `ADMIN_SAFE`** Permissions, not Roles. The `SUPER_ADMIN_ONLY` *right to manage* must not be
  confused with assigning `SUPER_ADMIN_ONLY` Permissions **to** an Agent, which AccessControl forbids even for
  a Super Admin. A template's requested permissions never bypass package current-ID/tier/reference checks,
  owner-approved grant limits or independent Agent creation/use authority.
- Publishing any template revision changes **no existing Agent's** stored direct Permissions, bound template
  revision or live session snapshot. Show versioned, current drift for affected Agents: template desired set,
  actual direct set, additions, removals, invalid/ineligible items and uncertain state. Offer two separate
  **one-time Super Admin-confirmed** actions against current Agent/template/Permission state: **Add Missing
  Permissions** grants only explicitly reviewed eligible missing items and truthfully retains any remaining
  extras/drift; **Auto-sync Agent Permissions** replaces with the reviewed complete eligible desired set,
  showing and confirming additions **and removals**. Neither action persists an always-on auto-sync rule,
  silently widens another Agent's authority, changes an active session's immutable snapshot or mislabels a
  partial update as synchronized. Revalidate current actor/target, package tier, Team/Repository scope,
  grants, expected revisions and transaction/reference fences on every use, including no-ops, direct calls
  and races. Explain failure/uncertain commit and require refreshed preview/reconfirmation rather than blind
  retries; revocation applies immediately through existing current authority checks.
- Integrate with EPIC-00014's actual named Agent/Team creation rather than offering a seeded demo or a second
  credential path. A qualified template revision may be selected for a new Agent only when the Super Admin can
  preview and confirm its **complete eligible Permission set** and current Team/Repository scope. The Agent
  uses the shared holder-bound credential and authenticates for real bounded manual assignments through the
  supported Harness tools, with live delegated authority and host/sandbox controls. Do not claim a new custom
  role is dispatchable, production-workflow-ready or a working Agent merely because it was saved, seeded or
  given a credential. Run small actual assignments to learn and correct behavior; no disposable fake
  Workflow, proof-only test product or mandatory per-template certification ceremony. Workflow eligibility
  still requires an explicitly designed and authorized route under its own owner.
- Qualify actual browser and provider-assisted editing, authorization denials, safe prompt/permission review,
  idempotent initial seed, revision races, ancestry/drift and explicit grant/revoke results, ownership and
  redaction with owned tests plus `./bin/build`. The AI/provider path must work before claiming AI-assisted
  authoring is delivered; fallback human editing cannot be mislabeled as AI. Keep raw credentials, private
  source, unapproved cross-Repository content and unauthorized prompt/Permission details out of browser
  responses, model context, logs and ordinary history. The template's prompt, requested tools and AI output
  are never AccessControl or Workflow authority. Reuse EPIC-00006's qualified protected provider/Harness
  capabilities and human proposal patterns as appropriate; do not start a separate untrusted model endpoint.
- Exclude database cutover for Planning, global Skill authoring/editing, general repository-instruction editing,
  code-defined managed authority policy mutation, generic Role or Permission CRUD, direct User Permission
  grants, agent-originated management, new Workspace/Repository Admin Roles, universal automatic template
  reconciliation, automatic Workflow routing or creation, cross-Team delegation and unapproved Agent credential
  export. Defer exact schema, UI components, API routes, seed format, resource fields, model prompt, proposal
  persistence mechanism and implementation slices to TICKET/TASK planning; database authority after seed,
  Super Admin review and live Permission constraints are not deferred.

## Progress

Approved after the map's WF-033 handoff. The maintainer chose database-authoritative managed and custom Agent
profile templates following initial seeds, including browser changes to the original eight and new role
identities without seed-file edits. Existing Agents remain unchanged after template publication; Super Admin
may perform a one-time reviewed additions-only or complete-sync action. All User/Role/Permission/Agent
**management UI** remains Super Admin-only for now, without blocking ordinary self-service or qualified Agent
work. New templates may be tried on small real manual assignments before a Workflow recognizes them. The
existing managed-source reconciler assumption is explicitly superseded for Agent templates only. No seed,
Agent, Permission, browser editor, Workflow, provider call, TICKET or TASK was created in this grill.
