# Deliver the registered Planning workspace

## Destination

Deliver the first authoritative Planning workspace for the private Fight Agent OS installation. An authenticated
user can follow the local operating guidance, register an existing repository and designated checkout, resolve
its effective context, import its Markdown planning through an explicit verified authority cutover, and use the
Dashboard to operate PostgreSQL-authoritative Planning.

Use Fight Agent OS itself as the first real migrated repository. The result is the identity, context, Planning,
and browser foundation required by later Harness, browser Agent, and coordinated execution EPICs; it is not a
disposable proof or parallel planning system.

## Decisions and exclusions

- Consume the closed [Complete Fight Agent OS vision map](../wayfinder/complete-agent-os-vision-map.md) without
  reopening its product decisions. In particular, preserve [WF-008](../wayfinder/tickets/WF-008-establish-repository-identity-and-registration-boundaries.md)
  through [WF-012](../wayfinder/tickets/WF-012-define-browser-planning-and-conversation-ownership.md), the applicable
  onboarding boundary from [WF-020](../wayfinder/tickets/WF-020-define-developer-onboarding-and-operator-guidance.md),
  the local topology from [WF-023](../wayfinder/tickets/WF-023-define-local-runtime-and-shared-ingress-topology.md),
  and the sequencing handoff in [WF-019](../wayfinder/tickets/WF-019-select-end-to-end-proof-and-epic-handoff.md).
- Treat [EPIC-00003](00003-EPIC.md) and [EPIC-00004](00004-EPIC.md) as implementation prerequisites. Reuse their
  PostgreSQL, durable-effect, API, React, authentication, authorization, security, and quality foundations rather
  than creating an alternate stack. Reconcile and formally close the completed [EPIC-00002](00002-EPIC.md)
  records without duplicating their project-local Skill work.
- Support the accepted private-installation Linux and macOS scope with one versioned task-based Dashboard guide.
  Use read-only prerequisite and capability checks; keep installation, package-manager, privileged, credential,
  mount, network, and runtime mutations explicit. Label verified and best-effort platform guidance honestly.
- Run the capability in the accepted installation-owned Compose and shared-ingress topology. Deliver only the
  application, persistence, ingress, checkout access, and supporting runtime behavior required by this EPIC;
  do not pretend that later Agent execution, Artifact, or provider capabilities are usable before their EPICs.
- Begin with one explicit Workspace. Mint stable Agent OS Repository, Host, Checkout, and Worktree identities;
  treat paths, names, Git common-directory facts, source locators, and provider IDs as locators or matching
  evidence rather than identity.
- Let an authorized human register an existing repository, select its designated local checkout, and confirm the
  first durable checkout link. Configure only approved project roots, canonicalize and contain paths, reject
  ambiguity or symlink escape, and never infer identity from directory names or slugs.
- Keep registration, checkout linking, source changes, relinking, archive, and restore explicit and audited.
  Registration alone does not migrate Planning, change branches, rewrite instructions, grant Agent authority,
  or authorize commit, push, publication, or execution.
- Resolve one lean versioned `RepositoryContextSnapshot` for each session. Include registered identity, planning
  mode, branch/base guidance, named verification commands, recognized instruction paths and digests, restrictions,
  conflicts, and provenance without injecting secrets or duplicating whole context files into model prompts.
- Preserve Pi-native instruction discovery and the accepted precedence boundary. Application safety and live
  authorization are non-overridable; local instructions may narrow guidance but cannot grant application
  authority. Pause on recognized conflicts rather than guessing, and retain immutable session context when
  configuration or effective instructions later drift.
- Implement the accepted explicit planning-authority progression from unregistered/local through registered
  Markdown authority to registered database authority. Never switch modes automatically or let cached context
  expand authority while services are unavailable.
- Make PostgreSQL the sole Planning authority after cutover. Use typed event-sourced EPIC, TICKET, and TASK
  aggregates with COMB identities and readable references, explicit lifecycles, dependencies, revisions,
  acceptance, actor attribution, archive/restore, and reasoned eligibility.
- Enforce cross-aggregate invariants and the one workspace-wide next-executable-TASK query transactionally.
  Browser hierarchy, Roadmap, queue, and any existing terminal `next` capability must consume the same canonical
  eligibility rules and human-readable inclusion or exclusion reasons.
- Preserve EPIC → TICKET → TASK terminology and separate Wayfinder, grill, to-tickets, and to-tasks operations.
  Direct browser edits use intent-specific semantic commands against expected revisions rather than free-form
  document replacement or generic status setters.
- Rehearse a deterministic complete Markdown import against a clean target, report every mapped identity,
  relationship, lifecycle, dependency, revision, warning, and rejection, and require human approval of the clean
  rehearsal before the final switch.
- Perform the final authority change transactionally from one confirmed immutable source snapshot. Fail without
  partial authority on mismatch or error. Permit no dual writers, silent record repair, status inference, or
  deletion of source Markdown.
- After cutover, render Markdown on demand from database authority. Keep the original Markdown frozen and
  available until a later separately approved and human-merged retirement change; never archive or remove it
  automatically.
- Provide an authenticated repository-scoped Dashboard for context, hierarchy, Roadmap, canonical work queue,
  semantic Planning operations, archive/restore, and complete reasons for blocked or unavailable actions. Keep
  browser authorization server-enforced through Fight Access Control Permissions and fail closed on unknown or
  stale authority.
- Preserve optimistic concurrency and durable proposal semantics. Reject stale commands without discarding
  authoritative history; show conflicts and require a new reviewed proposal rather than silently merging or
  applying last-write-wins behavior.
- Present honest loading, empty, stale, unavailable-checkout, unavailable-service, denied, partial, and conflict
  states. Offline or cached projections are visibly stale and read-only; reconnecting never silently refreshes an
  authority-bearing session.
- Test important owned identity, Planning, authorization, migration, concurrency, cutover, and failure-boundary
  behavior. Manually migrate and operate Fight Agent OS as the first real consumer. Do not add ceremony tests for
  documentation, setup wrappers, configuration, package-manager behavior, browser mechanics, framework behavior,
  or the quality gate itself. Distinguish automated, manual, historical, and incomplete evidence honestly.
- Exclude browser AI Planning conversations, OpenRouter and local Codex Planning Agents, Harness distribution,
  custom Skills, Coordinator/Builder/Reviewer/Publisher execution, Workflow/session history, completion forecasts,
  starter-based project creation, browser instruction editing, multi-workspace isolation, and automatic Markdown
  retirement.
- Defer exact schemas, events, projections, APIs, routes, React components, permission identifiers, migration
  commands, runtime files, and implementation slices to TICKET and TASK decomposition. Do not create a disposable
  Planning database, duplicate authority, or temporary unauthenticated application path.
