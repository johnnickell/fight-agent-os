# Diagnose Agent OS operations and managed runs with live and archived logs

## Destination

A currently authorized Super Admin can open a failed Agent OS operation or managed run, find its relevant logs,
inspect useful emitted exceptions and stack traces, and follow surrounding activity and available relationships.
The same operator can investigate active activity and older incidents through native Logs and verified temporary
archive restoration, while distinguishing genuinely empty results from delayed, missing, unavailable, expired or
purged coverage. The complete live-and-archived journey is the release outcome; a backend installation or live-only
viewer is not completion.

This EPIC consumes the approved [operational observability map](../wayfinder/operational-observability-map.md)
and [WF-042 acceptance/handoff](../wayfinder/tickets/WF-042-bound-observability-delivery-and-acceptance.md#accepted-resolution-and-epic-handoff).
It does not change the terminal-first milestone, Board priority, existing Workflow authority or evidence ownership.
Incremental delivery is permitted; incomplete coverage or unverified archives must remain labelled partial.
`ready-for-agent` records an approved planning destination ready for requirement decomposition, not implementation
readiness, production qualification or an operational grant.

### Coverage, content and ownership

- Include all agreed application activity and Monolog records, not only failures. No ordinary sampling, null sink,
  threshold suppression or channel gaps. Supporting-service coverage follows the actual installation inventory,
  including ingress/PHP/PostgreSQL/Redis/Mercure/SeaweedFS where deployed. SQL statement logging is not required.
- Preserve emitted content without pipeline redaction. Producers avoid deliberate secret emission and do not add
  unrestricted request/response dumps, object snapshots, stack arguments or locals. Native exception normalization
  is not a whole-record byte bound or a guarantee of secret-free content. Exposure-response purge remains with its
  separately authorized owner; public responses never gain raw diagnostics.
- Observe command/query invocation and event dispatch across nested, worker and non-HTTP paths, including events
  without subscribers. Distinguish lifecycle/retry/replay facts; handler return is not proof of commit/publication.
  Reuse the shared service/bus pipeline, reset worker context and retain one error reporter per actual boundary.
- Operational logs are neither authoritative Workflow state nor immutable execution evidence. Sanitized history/
  Activity remains sanitized; available project/Workflow/TASK/run/correlation references are navigation, not grants
  or fabricated lineage. Preserve existing evidence, audit, privacy, hold and default post-terminal grace owners.
- Diagnostic failure should isolate damage and keep as much working as possible, with explicit degradation. Do not
  promise survival of arbitrary shared faults or weaken mandatory audit/evidence failure semantics.

### Storage and access

- Default to 14-day live search and independent 90-day ordinary local archives from trusted original collection
  time, with the configurability, holds/grace and finite limits defined by WF-039. Retry/import never re-ages data.
  Local-only protection accepts total host/storage loss; it is not off-machine backup.
- Archives are independent verified compressed records, not Loki chunks or a day-14 export. Intent, upload,
  readback/content verification and catalog publication are distinct. Queue persistence, sink acceptance, query
  visibility and verified archive receipt are distinct facts; a generic successful HTTP response is insufficient.
- Favor newer context at exhaustion through oldest-eligible queued-data eviction and independent persisted loss
  accounting. Never override holds, delete protected sole copies, prematurely evict verified archives or fall back
  to unlimited storage. Unknown preservation authority disables unsafe cleanup/publication; bounded admission
  policy remains necessary when safe cleanup cannot progress.
- Keep Loki private behind intent-specific Agent OS operations. Reuse qualified private storage infrastructure with
  isolated namespace/credentials/accounting for live indexes/chunks, operational archives and Artifacts. Exact image,
  storage, security, license and resource qualification is outstanding; the research versions are not installation
  authorization. No backend credential, Docker socket or generic query/object-path proxy reaches browser or Agents.
- Initially only managed Super Admins receive planned protected `READ_LOGS`, `EXPORT_LOGS`, `RESTORE_LOG_ARCHIVES`
  and `DOWNLOAD_LOG_ARCHIVES` capabilities under existing `SUPER_ADMIN_ONLY` invariants. Runtime checks use current
  capabilities, not Role-name shortcuts. No ordinary user/project member/custom role/direct Agent gains log access.
  Extraction powers remain separate from reading, although already visible/downloaded bytes cannot be recalled.
- Reuse browser authority/session/CSRF owners and volatile private state. Recheck current authority before fetching
  and releasing private content and at bounded stream/transfer output batches; unknown authority withholds output.
  Keep sensitive search text out of URLs/history/referrers/telemetry and avoid persistent private browser caches.

## Use cases and observable effects

| Journey | Authority and commands/queries | Events / side effects and acceptance |
|---|---|---|
| Diagnose a failed HTTP/worker operation | `READ_LOGS`; correlation/time/service search, context and raw detail | Read-only diagnosis finds expected/unexpected failure observations and useful emitted exception causes/frames; existing public response stays unchanged |
| Diagnose a failed managed run | `READ_LOGS`; follow existing Summary/run relationships and inspect check/process output | Available identities lead to relevant output without transcript reconstruction or another Workflow state store; related evidence retains its own permissions |
| Follow or investigate active activity | `READ_LOGS`; server-side literal search, exact severity/time/service filters, tail, pause/resume, context/detail | All includes DEBUG; tie-safe traversal, bounded inert rendering and explicit reconnect/paused gaps; no Workflow mutation from viewing |
| Explain absent records | Protected bounded coverage/status queries and independent local operator diagnostics | Capture, queue, search visibility and archive verification are separately reported; unavailable/unknown is never represented as complete empty success |
| Investigate an older incident | `READ_LOGS` + `RESTORE_LOG_ARCHIVES`; coverage query, explicit idempotent restore command, status/search/detail | Verified requester-owned temporary scope with bounded admission/import/expiry; real partial/corrupt/busy states, no live mixing, re-aging or business replay |
| Extract selected records/archives | `READ_LOGS` + `EXPORT_LOGS` or `DOWNLOAD_LOG_ARCHIVES`; restored export also needs current restore authority/scope | Bounded authorized output, private catalog access only as necessary, no arbitrary paths/hidden spool or false complete result |
| Recover or reclaim capacity | Existing operator/lifecycle authority, not powers conferred by log reading | Reconcile original identities/clocks and owner-fenced preservation/purge; distinguish deletion requested, processed and physically reclaimed |

Producer activity, archive/restore lifecycle observations and required security audit retain distinct meanings;
none creates a new authoritative Workflow event just because a log was emitted. Exact command/query/event contracts
belong to later requirement decomposition, not speculative APIs or implementation classes here.
