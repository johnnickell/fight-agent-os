# Edit repository instructions safely

## Destination

Deliver one focused Dashboard journey for inspecting and editing the Pi-native root instruction files in a
registered repository's designated local checkout. An authenticated authorized user can understand which
recognized file Pi loads, directly draft a change or request a browser Agent suggestion through the versioned
instruction-writing Skill, review the complete diff, and explicitly create, update, or delete one file through a
deterministic expected-digest write.

Saving changes remains separate from Git publication. A separately authorized confirmed operation creates an
owned branch, commits only the selected instruction-file change, pushes without force, creates a GitHub pull
request, and returns the designated checkout safely to its clean registered default branch. Manual and scheduled
synchronization can later apply only clean ownership-safe default-branch fast-forwards.

Exercise the complete production journey on a real Fight Agent OS instruction change. Keep the product narrowly
bounded to recognized repository instructions; it must not become a recursive file browser, source editor,
general-purpose IDE, autonomous AI writer, or destructive Git synchronization tool.

  immutable context snapshots, database-authoritative Planning, authentication, and the repository Dashboard.
  Depend on [EPIC-00006](00006-EPIC.md) for browser Agent conversations and the attributed versioned
  instruction-writing Skill. Reuse the deterministic eligible Runner capabilities from
  [EPIC-00007](00007-EPIC.md); do not require a coordinated coding Workflow, Senior Engineer, Release Manager, or EPIC-00008
  publication state machine for this human-confirmed repository operation.
- Recognize only these exact filenames at the designated checkout root in v1:

  - `AGENTS.override.md`;
  - `AGENTS.md`;
  - `AGENTS.MD`;
  - `CLAUDE.md`; and
  - `CLAUDE.MD`.

- Follow the installed supported Pi discovery contract to label which recognized existing file is loaded and why
  another is not, including same-directory `AGENTS.override.md` replacement behavior. Do not invent precedence,
  parse prose into application policy, or claim that an unrecognized convention affects Pi.
- Do not scan recursively. Nested context files, arbitrary Markdown/source files, `.pi/SYSTEM.md`,
  `.pi/APPEND_SYSTEM.md`, Skills, prompts, settings, Harness resources, parent directories, and user-global files
  are outside this editor. Bounded provenance may explain composition without exposing or editing parent/user
  content.
- List only recognized root files and open one at a time in a Markdown form. Label direct effective state such as
  **Loaded by Pi** or **Not loaded because AGENTS.override.md replaces it**. Show complete changed-file diff plus
  concise tracked, untracked, ignored, modified, branch, checkout-availability, and synchronization facts.
- Treat untracked or ignored recognized files truthfully: Pi may load them even though Git publication will not
  include them automatically. Never call a file ineffective solely because Git does not track it, and never infer
  that content is generated without authoritative evidence.
- Keep technical evidence—Repository, Host, Checkout, Worktree, Runner, context revision, commit, content digest,
  encoding, size, and provenance—available behind readable detail without exposing unnecessary internal IDs,
  absolute personal paths, storage URLs, or credentials.
- Reject symlinks, non-regular files, device/special files, binary content, unsupported encodings, excessive size,
  path ambiguity, traversal, case ambiguity, and content outside the exact allowlisted root names. Apply ordinary
  bounded text/Markdown safety without pretending instruction content is trusted application policy.
- Always use the repository's one designated local Worktree for ordinary Dashboard instruction operations. Do not
  ask the user to choose among clones/worktrees on every request and never substitute another clone, human
  checkout, or Workflow-owned worktree silently.
- Require the designated checkout to be online through an eligible Runner and still satisfy registered identity,
  approved-root containment, Git common-directory/marker, ownership, and availability checks. Refuse mutation when
  it is moved, unavailable, unsafe, ambiguous, outside approved mounts, or owned by a conflicting operation; show
  the exact blocking reason and allowed next action.
- Keep the Runner mechanical. It lists recognized names, reads bounded content, computes digests, performs an exact
  expected-digest/expected-absence atomic write or delete, and reports observed filesystem/Git results. It never
  invokes AI, chooses content, selects a checkout, interprets effective semantics, grants authority, resolves a
  conflict, commits, pushes, publishes, or synchronizes except through a separately authorized operation.
- Preserve distinct operation-aligned Fight Access Control capabilities for **View repository instructions**,
  **Update repository instructions**, **Use browser AI assistance**, **Publish repository changes**,
  **Synchronize the designated checkout**, and **Configure scheduled checkout synchronization**. Enforce each
  server-side on current identity/context; role names and client visibility never grant authority.
- Permit AI assistance without Update authority: an authorized user may request and inspect a suggestion but
  cannot submit it. Permit Update without publication. Publication and manual/scheduled synchronization always
  revalidate their own current authority and cannot inherit it from a read, conversation, draft, or save.
- Let the human select one recognized file and describe the desired change. The browser Agent may read only the
  authorized bounded file/context, discuss intent, ask clarifying questions, and use the exact versioned Harness
  instruction-writing Skill to place suggested complete content and diff into the same editable form.
- Preserve attribution and license compliance for the instruction-writing Skill adapted from Matt Pocock's
  MIT-licensed `writing-for-agents`. Record the Skill, Harness, provider/model, repository-context, file digest,
  conversation, initiating user, and acting Agent revisions used for a suggestion without copying credentials or
  hidden model context.
- Use the initiating user's protected OpenRouter environment connection/generation through TICKET-00089/00090
  for optional instruction assistance. No installation/family key or another user's connection is a fallback;
  replacement/disconnect cannot reset original usage or reassign a request. Connection self-service stays with
  its existing provider owner and direct editing remains model-independent.
- Keep the assistance conversation/proposal durable under EPIC-00006 ownership so disconnect or Agent interruption
  cannot turn a suggestion into a filesystem effect or lose an already durable proposal. The Agent cannot submit
  the form, call Save/Delete/Publish/Sync, choose another file, expand scope, or accept its own suggestion.
- Apply the accepted v1 direct-form behavior: unsaved human edits need not autosave, warn before leaving a dirty
  form, and do not support simultaneous co-editing. AI proposal durability does not imply that unsubmitted manual
  changes are authoritative.
- Use one **Save changes** operation for human-authored and Agent-assisted content. Before submission, show the
  complete file diff and effective-instruction consequence. Send only the allowlisted relative path, exact proposed
  complete content, expected current digest—or expected absence for a missing file—and current checkout/context
  evidence needed for safe validation.
- Revalidate live Permission, repository/designated-checkout identity, containment, regular-file safety, current
  branch/ownership, expected digest/absence, encoding/size, effective instruction result, and conflicting
  operations immediately before one atomic deterministic write. Return the observed new digest and Git status only
  after rereading the result.
- Reject Save when the file changed, appeared, disappeared, moved, became unsafe, or the checkout/context is stale.
  Preserve the durable AI proposal and return current safe content/diff beside the rejected draft so the human may
  reconcile manually or request a new suggestion. Never silently overwrite, last-write-win, auto-merge, or let AI
  resolve and apply a conflict.
- Provide a distinct **Delete file** operation for one existing recognized file. Show its complete deletion diff,
  tracked/ignored state, and which remaining recognized file Pi would load afterward; require explicit confirmation
  and expected current digest before deleting only that file.
- Keep create/update/delete as local filesystem facts. They do not stage, commit, push, open/update a PR, merge,
  reload Pi, update repository configuration, or start/continue an Agent session. Report dirty Git state and
  deliberate next actions without implying publication.
- Mark relevant `RepositoryContextSnapshot`s and Agent sessions stale only when the effective Pi instruction set
  changes. Preserve immutable historical snapshots and session lineages; never rewrite/reload them silently. A
  recognized but unloaded-file change updates repository evidence without staling sessions unless effective
  composition changes.
- Record accepted filesystem mutations and AI-assistance requests with initiating user, acting Agent when present,
  Skill/Harness/context revisions, file role/path, base/result digests, intent, outcome, stale consequence, and
  bounded safe evidence. Ordinary authorized reads use security/request logging rather than manufacturing one
  Domain event per page view.
- Make **Create pull request** the default separate publication action after a saved local change. Require a clean
  publication baseline except for the selected recognized instruction-file change; refuse unrelated staged,
  modified, untracked, ignored-sensitive, unpushed, divergent, conflicting, or operation-owned state rather than
  hiding, stashing, resetting, or including it.
- Preview the generated collision-safe branch, editable commit message, exact selected-file diff, registered remote
  and provider identity, and registered default base branch. Invalidate the preview when file digest, Git state,
  remote/base, checkout identity, live authority, or ownership changes.
- One explicit publication confirmation records durable intent and deterministically creates/switches the owned
  branch, stages only the selected recognized file, commits the exact previewed diff, pushes without force, and
  creates one GitHub PR against the registered default base. Browser AI receives neither publication authority nor
  GitHub credentials.
- Reconcile each effect and preserve truthful partial outcomes. A commit failure, uncertain push, successful push
  followed by PR failure, existing matching PR, provider outage, authorization change, or browser/Runner restart
  exposes exact safe retry/recovery; never duplicate commits/PRs or infer success from a disappeared process.
- After verified PR creation, return the designated checkout to its registered default branch only when the exact
  operation-owned transition is safe, then verify that branch is clean at its prior/default revision. Never leave
  proposal content applied to the default checkout, discard unrelated work, or claim cleanup success while an
  uncertain branch/process/provider effect remains.
- Show PR provider identity, number, title, source/target branches, exact pushed commit, publication/merge
  observation, warnings, retained local state, recovery actions, and an **Open pull request on GitHub** link that
  opens in a new tab. Proposal, save, commit, push, PR creation, merge, and synchronization remain distinct facts.
- Permit a repository policy to offer **Commit and push current branch** later only as a separate explicit preview
  and confirmation under the same safety boundaries. It is not the default and cannot be inferred from Save or
  Create pull request.
- Keep the designated Dashboard checkout on the registered default branch for ordinary operation. Provide explicit
  **Sync checkout** plus scheduled remote checks enabled by default and configurable only by an authorized
  repository administrator. Scheduling is a check authorization, not permission for destructive recovery.
- Before any automatic or manual update, verify that the checkout is online/eligible and identity-matched; on the
  registered default branch; clean in worktree/index; free of unpushed commits/divergence; unowned by Workflow or
  publication; bound to the registered upstream/source; and strictly behind in a fast-forward-only relationship.
- Fetch and apply only a verified default-branch fast-forward. Never auto-stash, reset, rebase, merge divergence,
  discard, switch a dirty checkout, resolve conflicts, delete branches, or override another operation. If any
  condition fails, make no mutation and show update availability, incoming commits when safe, and the blocking
  reason.
- Make manual synchronization preview incoming commits and recheck the same conditions; it has no destructive
  override. A scheduled synchronization that changes an instruction digest stales open forms and follows the same
  expected-digest rejection/context-drift paths instead of silently replacing browser state.
- Keep publication/synchronization as deterministic human-authorized repository operations, not coordinated
  Workflow review or Release Manager execution. Reuse safe Git/provider adapters when available without granting Software Engineer,
  Senior Engineer, support Agent, or instruction-writing Agent publication credentials.
- Exercise the complete production journey on a real Fight Agent OS instruction change: inspect effective files,
  request/review assistance where useful, save with expected digest, publish the selected-file PR, open the human
  handoff, merge only through normal human GitHub control, and safely synchronize the clean designated checkout.
  Preserve ordinary audit/recovery evidence rather than creating a proof-only endpoint or Workflow.
- Test important owned allowlist, path/regular-file safety, Pi-effective-state classification, authorization,
  expected-digest/absence concurrency, atomic write/delete, context-stale decision, publication intent/idempotency,
  unrelated-change refusal, uncertain-effect recovery, and synchronization predicates. Use focused real
  Git/Runner/GitHub boundaries and direct integrated verification without testing Pi, Git, GitHub, Markdown prose,
  browser/framework mechanics, scheduler configuration, or the quality gate merely to manufacture coverage.
- Exclude recursive/nested browsing, arbitrary Markdown/source/config editing, `.pi` resource editing, parent/user
  content exposure, general repository trees, browser Skill creation, Agent submission, automatic save/merge,
  save-time commit/push, force-push, PR approval/merge, dirty-tree mutation, destructive synchronization,
  auto-conflict resolution, remote branch cleanup, coordinated Review/Release Manager requirements, and a general IDE.
- Defer exact schemas, Commands/events, APIs, Permission identifiers, Runner transport, encoding/size limits,
  atomic-write mechanism, branch naming, Git/provider sequence, schedule/interval, provider/model choice, prompts,
  Skill text, UI components, and implementation slices to TICKET and TASK decomposition. Open a new Wayfinder
  decision only for a genuinely separate general repository editor, nested-working-directory model, or
