## Question

Which useful local infrastructure, homepage and engineering-entry capabilities must continue, and what verified
replacement and separate authorization would be needed before any ownership migration or retirement?

## Must decide

- Inventory a bounded set of existing Local Development, Omphalos, Ideaverse, `$aios` and `$fight` capabilities
  using the operator's named sources and targeted references. Distinguish documented intent, configured startup,
  actual implementation evidence and later live qualification; do not audit unrelated historical projects.
- Preserve Omphalos as John's browser homepage, its route/startup and useful workflows. Preserve other projects'
  routes, data and private operations even if Fight Agent OS eventually owns shared-infrastructure implementation.
- Separate four transitions: infrastructure ownership/lifecycle; route/data migration; engineering workflow entry
  points; retirement of routers/legacy apps. None automatically authorizes or proves another.
- For each useful capability, identify existing or proposed replacement owner, evidence gap, independent recovery,
  data/route implications and the exact later retirement decision. Mark missing replacement as preserve/hold,
  not an invitation to delete or build speculative replacements.
- Treat potential Ideaverse replacement by a future Nickell project as investigation, not accepted migration scope.
  `nickell.app` and `nickell.financial` are distinct applications and are not implemented by this map.
- Keep machine inventory, private paths, secrets and generated route state outside publishable research. Produce
  capability-level summaries with safe citations; retain historical evidence and source projects intact.
- Define later verification of route/startup/homepage continuity and replacement engineering commands. No live
  maintenance tests in this session. Any actual migration needs bounded effects, rollback/data recovery and
  separate approval; retirement requires verified replacements and explicit human authorization.

## Resolution boundary

Read-only bounded inventory and cited planning recommendations only. No ownership transfer, router/app deletion,
route/data migration, startup change, credentials, DNS/hosts change or source/planning-owner amendment. This branch
is independently selectable and has no launch dependency; explicitly defer uncertain replacements rather than
turn every legacy capability into a prerequisite for private production.

## Resolution

Closed as a **bounded source inventory and preservation/retirement handoff**, not live continuity acceptance.
[Research observed 2026-10-24](../research/WF-053-legacy-capabilities-and-retirement-boundaries.md) inventories the
named surfaces, distinguishes documentation/configuration from sampled implementation and untested runtime,
and records future replacement evidence without authorizing a transition.

### Inventory result

- **Local Development:** preserve shared ingress, route enrollment/removal, independent lifecycle/maintenance stop
  and recovery. The README and command-dispatch source support the operator contract; older hosts/startup
  observations are inherited, not fresh live evidence. WF-046/052's optional integration retains existing owners
  until separately authorized handover; no router implementation is moved now.
- **Omphalos:** preserve John's homepage and route plus its useful bookmarks/search/brief/daily-note, integration/
  worker-health and scheduling surfaces. The homepage component and authenticated brief action were inspected.
  Broader ingestion, credential, evidence/memory and operations capabilities are documented; the full behavior
  was not audited. Base Compose declares supporting services and durable/integrated state, not successful startup.
- **Ideaverse and `$aios`:** preserve the knowledge vault, personal workflows and canonical router/compatibility
  paths. Read catalog/documentation and the actual project/Codex adapters, not personal notes. Agent OS's engineering
  scope is not a substitute for capture, daily rhythm, knowledge work and other non-engineering workflows.
- **`$fight` and Factory:** preserve direct engineering routing independently of optional runtime/trace capabilities.
  Installed router/index distinguish these layers and the AIOS compatibility path. Agent OS's fresh project-local
  skills do not silently replace other projects' invocations, adopted rules, history, approvals or active runs.
- **Future emulation/Nickell applications:** not selected replacement suppliers or first-production prerequisites.
  Missing replacements mean preserve/hold, not an instruction to rebuild every legacy capability in Agent OS.

### Independent transition boundaries

Infrastructure ownership/lifecycle, application route/data migration, engineering entry-point replacement and
retirement remain four separately scoped transitions. Each later selected transition needs the exact affected
capability/target, current state and references, qualified replacement, continuity/recovery evidence and human
authority appropriate to its effects. Retirement specifically needs a verified replacement and explicit approval;
first production, map closure, a new domain screen or matching command names authorize none of it.

Later checks must establish actual route/TLS/startup/homepage behavior, retained data and jobs, correct target-
project workflow/permission/review semantics and recovery without dependence on the component being replaced.
These checks block only the selected transition, not unrelated Agent OS implementation, staging or first production.
No certification framework, speculative migration TASK or global legacy parity gate is proposed.
