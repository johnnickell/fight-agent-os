## Counterchecks, risk and allocation

[WF-033 — Define live Agent operation adoption and safe surfaces](../tickets/WF-033-define-agent-operation-adoption-boundary.md) approves a separate future Agent lifecycle/management EPIC, first real working Explorer with incremental Project Manager and additional Agent use, and a later separate AI-assisted template-authoring EPIC. Its protected operations and real-consumer qualification are part of product implementation, not an Explorer-only test harness. [WF-035 — Define project-linked Teams and available Agent selection](../tickets/WF-035-define-project-teams-and-agent-selection.md) owns the separate unresolved product Team/Workflow scheduling question; neither creates a present-tense Agent consumer.

- `config/routes/01-api-v1.php` registers **only** CSRF bootstrap and public-safe validation metadata. `config/routes/02-web.php` serves the non-product client shell; no credential/admin/Agent/Feature product route is live. `config/common/{command,query,persistence,security}.php` and `src/Application/CredentialDelivery/` show selective adapters/handlers, not every package use case. The implemented `PostgresAgentRepository::getOperationContract()` explicit denial and TASK-00126's owner-approved storage-only boundary prevent overclaiming. The Feature repository is not a Feature runtime.
- [EPIC-00004](../../epics/00004-EPIC.md) owns first web foundation and **explicitly defers email change and broad profile mutation**; its administrative extensions TICKET-00030/00031 do not silently remove those exclusions. [ADR 0001](../../adr/0001-application-ownership-and-orchestration.md) preserves package-owned messages/policy and Agent OS adapter/UI/necessary orchestration. [ADR 0002](../../adr/0002-postgresql-consistency-and-durable-effects.md) owns shared transaction/durable external effects and historically deferred Agents; any new scope requires an explicit successor/addendum, not silent restatement of v0.2.0 observations. [EPIC-00006](../../epics/00006-EPIC.md) owns Harness identities/resources; ask its owner whether to amend its destination or create a linked Agent credential EPIC. The [closed vision map](../complete-agent-os-vision-map.md) is navigation/settled guidance, not reopened authority.
- Suggested acceptance checks: real PostgreSQL CAS/isolation/fence races including direct and old-binary writers; same-key issuance/status after uncertain commit; real cipher/sink/idempotency and authority races; restart/restore and protected key maintenance; fresh Agent auth/delegation/MCP availability; real UI authorization, safe states and accessibility; production-like human delivery/expiry and Feature OFF/PREVIEW/ON checks; published *Agent OS evidence* bound to exact package/consumer revisions. Use package consumer-bindable suites only when bound to real Agent OS ports plus independent consumer observations; never substitute package in-memory fixture passes or storage-only tests for runtime qualification.
- **Sampling limit:** static repository/package inspection and existing TASK receipts only. No authenticated deployment, Agent issuance, sink, provider, old-binary exclusion, restoration, starter repo or live Feature was exercised here. No release or production-readiness assertion follows.
