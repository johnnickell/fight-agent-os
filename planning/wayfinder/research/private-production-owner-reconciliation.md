## Specific contract reconciliation

### Credentials and generation

Hosted generation consumes only the initiating user's authorized environment connection and exact generation;
no shared installation/family key, another user's connection, implicit account cycling or personal local token
reuse. Ordinary administration and conversation sharing do not grant another user's provider/account access.

Connection input may be deliberately entered once through a transient protected form; that is distinct from key
readback, browser persistence or client-side inference credentials. Server custody is encrypted with separate key
custody; raw secrets never enter models, children, profiles, snapshots, logs, transcripts or ordinary observations.
Provider connections are not Agent OS connection profiles or Fight Agent HMAC credentials.

Replacement/disconnect fences future use and late metadata but does not rebind old attempts or erase liabilities.
Local disconnect is not proof of upstream revocation. Preserve original accounting and required key versions
through cancellation, deployment and restore. Actual lifecycle/storage/current-use participants remain required.

### Models, defaults and continuation

Use provider-backed on-load/light-cache model discovery plus explicit Refresh models; exact supported metadata
routes are owned by TASK-00346, not a network call hidden inside TASK-00343. Scope authenticated cached results to
user/environment/connection generation, coalesce/rate-limit and expose time/staleness/unknown pricing. Public
nonsecret metadata may be shared where appropriate. There is no fixed model, mandatory TTL or benchmark project.

Discovery does not change defaults, start inference or refresh allowance. Set as default uses the current owning
profile writer and displayed authority; future conversations change, existing selections do not. Between-turn
OpenRouter model switches preview permitted carried context and any reduction, preserve prior history/accounting
and revalidate proposals through the existing confirmed linked continuation. No transferred approval or Apply.
Actual policy revocation still denies use; an unchanged reconnect needs no new ceremony.

### Usage and allowance

Conversation usage queries/rendering reuse normalized original attempts, preserving supported token categories,
requested/reported model, reported cost/currency versus estimate/source/time, and unknown/partial/stale/pending
coverage. Do not double-count cumulative, nested or linked activity, hide failed/stopped costs, mix units/currencies
or expose another user's private totals. Applicable budget views are permission-filtered and separate from
provider allowance; missing secondary displays do not change admission policy or disable unrelated reads.

The accepted allowance mapping is ordinary-key OpenRouter `/api/v1/key` through TASK-00346, not `/credits` through
management credentials. Key cap is not wallet balance or capacity, null is not unlimited, and multiple keys may
share account limits. Label actual scope/units/reset/freshness; do not infer balances by subtracting local usage.
Fight's approved connection/allowance resource direction returns recorded sanitized data; refresh is an explicit
separate operation. Catalog refresh, page rendering and reconnect are not allowance-refresh authority.

TASK-00399 retains its existing Workflow presentation dependency; its account-scoped contract can be reused without
pretending that the complete standalone connection-settings UI is already supplied. Missing allowance does not
block browser Planning. The later approved TASK-00521 now owns scope-specific settings composition after
TASK-00520 and TASK-00399; actual source/host qualification remains held.
